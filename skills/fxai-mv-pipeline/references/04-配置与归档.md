# 04 · 配置与归档（两级配置 · 项目目录 · 清理 · 加新歌 · 安装分发）

> 何时读：第一次装机/配环境、改 `config.json`、看项目目录结构、补归档、加一首新歌、打包分发。

## 配置化约定（工作区 config.json · 用户/UI 维护 · 必守）

**人物参考图、产出尺寸约定，全部外置到工作区配置文件，代码不写死。** 这样打包给别人用时，对方只需把默认参考图换成自己的形象、改一下 `ref_image`，不用碰代码；后续你做的 UI 也直接读写这个文件。

### 人物形象图（ref_image）：第一次怎么定义（用户视角 · 必守）
- **只存服务端**：写相对服务器端 `fxai/image/` 的路径，落在 `fxai/image/avatar/`（默认女主 `avatar/000.png`、男主 `avatar/001.png`，纯数字三位数补零，可换任意自定义相对路径）。路径格式与取值判据见 `fxai-standard/references/10-资源引用路径规范.md`；本机没有这个目录属正常，存在性走接口确认。
- 🔴 **缺图必须先问用户要图，拿到后再上传**（硬性）：
  1. 开工前用接口探测服务端 `avatar/` 下本项目要用的参考图在不在（`GET /fxai/down/file?url=image/avatar|<名字>`，200 = 存在；这条只用来确认文件存在，响应体本身不作产物下载用）。
  2. **探测不到 → 停下来问用户要图**，别往下跑：明确说「缺女主参考图，请发一张女主的正脸形象图给我」，男主同理一次性问齐。
  3. 拿到用户给的图（文件路径或图片文件）**之后**才 `upload_image(path, subdir="avatar", filename=<名字>, overwrite=True)` 传上去，并登记 `config.json` 的 `characters`。
  4. 参考图只认用户给的那一批：默认头像、上一首歌的产物、手上任何现成图都不作顶替；「默认图能跑」也不跳过这一步。传不上去 / 用户迟迟没给，就停下来问，等图到位再继续。
- **传上去叫什么**：女主落 `avatar/000.png`、男主落 `avatar/001.png`（用户另有指定时按指定来）；长得像不像由参考图本身决定，不看文件名。
- **面貌不进任何提示词**：`desc` 只作标记；长相由图锁，穿搭由当歌四视图锁（2026-11-12 起文字也不复述穿搭，见 02 册第 13 条 / 铁律 17）。
- **验证**：传完跑一次四视图/生图，返回 `queued` 即证明服务端读到该图。参考图没传到时**不会报错**，只表现为人物长相漂移，所以这一步必须真正问过。

> ⚠️ **配置存「相对路径」，不存物理绝对路径**：`ref_image` 一律写 `avatar/000.png` 这种相对服务器端 `fxai/image/` 的路径，与 workflow 传参一致；`resolve_ref()` 原样返回该相对路径，由 ComfyUI 服务器端 fxai-toolkit 解析。格式判据见 `fxai-standard/references/10-资源引用路径规范.md`。

### 文件位置（工作区级，整个 MV 空间一份）

```
<音乐工作区根>\config.json
```
- 这是「空间级」独立配置，跟具体哪首歌无关，整个音乐工作区共用。
- 加载器 `mv_config.py` 的搜索顺序：环境变量 `MV_CONFIG` → `{workspace}/config.json`；缺文件或字段不全时回退到内置默认值，进程照常启动（缺配置不崩）。
- 每首歌「用哪些人物 / 曲风 / 歌词」等**属于项目本身**的数据，不进这个配置——它们写在各歌的 `歌曲.md`（曲风/穿搭/歌词）与 `制作.json`（`characters`/`size`/`tags`）里。配置只放「资源库 + 默认尺寸」这类通用规则。

### 配置 schema

```json
{
  "version": 1,
  "characters": {
    "女主": { "id": "ref_woman", "role": "woman",
      "ref_image": "avatar/000.png",
      "type": "face",
      "desc": "面部特征参考图（仅标记，面貌以参考图为准，由图复刻五官）",
      "enabled": true },
    "男主": { "id": "ref_man", "role": "man",
      "ref_image": "avatar/001.png",
      "type": "face",
      "desc": "面部特征参考图（仅标记，面貌以参考图为准，由图复刻五官）", "enabled": true }
  },
  "defaults": {
    "landscape_width": 1920, "landscape_height": 1080,
    "mv_width": 1280, "mv_height": 768,
    "video_max_edge": 1300
  }
}
```
- `characters`：**人物花名册（资源库）**。键是「角色名」（女主/男主/任意你起的名），值含：
  - `ref_image`：参考图**相对**路径（相对服务器端 `fxai/image/`，如 `avatar/000.png`）；
  - `type`：`"face"` —— 标记该参考图是**头像/面部照**（裸肩头部像），**只用来锁「面貌五官特征」**，不是全身照、不含任何穿搭；
  - `desc`：**只作标记，不写任何具体五官/脸型**。直接写一句「面部特征参考图（以参考图为准，由图复刻五官）」即可——具体面貌由参考图本身复刻，**面貌靠图锁、不靠文字描述**，**`desc` 也不进提示词**（进了会污染多首歌的形象）。穿搭每首歌不同，写在该歌 `歌曲.md` 的「## 穿搭」段；
  - `role`（woman/man，仅标注用）、`enabled`。
  - 新增角色 = 加一项；换自己的参考图 = 把 `ref_image` 改成自己的相对路径（如 `avatar/001.png`）。
- `defaults`：横屏尺寸、MV 尺寸、视频边长封顶。这些是「尺寸约定」，一般不动；放这里是为了集中、可被 UI 调整。（音乐时长由工作流锁死 360s，本管线不配置、不传参。）

### 管线怎么读（produce_song.py）
1. `load_config(workspace)` 加载配置（合并默认值）。
2. 人物取「运行时覆盖 `RUN_OVERRIDES['characters']` > 项目 `制作.json` 的 `characters` > 配置首个启用人物」。
3. `get_character` + `resolve_ref` → 把相对 `ref_image` 解析成绝对路径，拿到人物 `desc`（仅作标记，不进提示词）。
4. **面貌由参考图锁、穿搭每歌写**（关键，这样多首歌的形象互不污染）：
   - **参考图（type=face）本身就是面部特征来源**，AI 直接复刻图上的五官，配置 `desc` 只作标记、不进提示词；
   - **四视图 `gen_char_view(..., ref=REF)` 只喂「当歌穿搭」**（`歌曲.md` 的「## 穿搭」）——参考图已锁面貌，符合「提示词职责划分」里"三/四视图只写穿搭"的规则；
   - **场景运镜 / MV 合成提示词也只写「当歌穿搭」**（`歌曲.md` 的「## 穿搭」），人物身份靠参考图锁定，文字无需重复面貌（更不会写死五官）。
   - 代码里 `CHAR_DESC = OUTFIT_DESC`（当歌穿搭），面貌不进任何提示词。
5. **`REF_WOMAN` 这类值全部来自配置**，代码里只留字段名。

> 🔧 **运行时临时覆盖（不落盘）**：对话中临时想改默认值或换人物（比如这回用男主、这次 MV 改 1080 宽），**改 `produce_song.py` 顶部的 `RUN_OVERRIDES`**，`config.json` 保持原样。例如 `RUN_OVERRIDES = {"defaults": {"mv_width": 1080}, "characters": ["男主"]}`。这只影响当次运行、存在内存里，不会写回配置文件；只有你明确要求「改配置」时才动 `config.json`。

### 与 fxai_global.json（全局部署配置）的职责划分（两种配置不同级，不混）
- **`<音乐工作区根>\config.json`（工作区根）** = 用户态 / 资源管理配置：人物参考图、尺寸约定。**随工作区走、UI 管**。
- **`~/.workbuddy\fxai_global.json`（用户级，机器共享）** = 部署 / 环境配置：ComfyUI 地址、软件安装目录与软件数据目录这两个「根目录」等本机环境项（ffmpeg / whisper 环境等派生路径由代码按这两个根目录自动推导，**不写入配置、不写死**）。**机器级、所有技能（fxai-mv-pipeline + fxai-lyric-subtitle 字幕）共享**，由安装流程确定 / `setup_env.py` 探测生成（固定目录名 `<盘>:\fxai` 与 `<盘>:\fxaitool`，自动命中，不必手跑），**不随技能包分发**。
- 读取优先级：`FXAI_GLOBAL_CONFIG` 环境变量 → 否则 `~/.workbuddy/fxai_global.json` → 否则代码内默认值（向后兼容）。脚本里所有本机路径一律来自这里，只留配置字段。
- **环境地址唯一来源（硬性）**：只认 `~/.workbuddy/fxai_global.json` 的两个字段——`comfy_url`（本机默认）+ `comfy_cloud_url`（线上）；本机探得通走本机，探不通自动切线上，不得改用别处地址。ComfyUI 基址（`COMFY` / `FILE_API_BASE`）、在线探活、任务提交、产物下载全部由它派生；**管线脚本、临时探测脚本、文档里的服务器地址一律来自这两个字段**，不写任何硬编码地址，`http://127.0.0.1:8188` 只是 `comfy_url` 缺失时的回退值。换机 / 换端口 / 换远端只改配置，代码不动。

### 全局部署配置 schema（fxai_global.json · 安装时生成，不随包发）

```json
{
  "software_install_dir": "<软件安装目录>",
  "software_data_dir": "<软件数据目录>",
  "comfy_url": "http://127.0.0.1:8188",
  "whisper_dir": "",
  "whisper_device": "cuda",
  "ollama_url": "http://127.0.0.1:11434"
}
```
- **打包只发 `fxai_global.example.json`**（模板，路径全空）。两个根目录由安装者在安装过程中确定，且**目录名固定**：软件安装目录 `<盘>:\fxai`、数据目录（同盘）`<盘>:\fxaitool`；代码按固定目录名自动命中，**正常使用不需要跑 setup_env.py**，只有装到非常规盘时才跑它（或由 UI 直接把两个根目录喂进配置）。用户路径各异，包里一律用占位符。
- **产物下载全部走 HTTP 接口**：① `POST /prompt` 提交工作流 → ② `POST /fxai/tasks/result` 拿 `url` 令牌（`image/sub|file.png`）→ ③ 经统一的 `GET /fxai/down/file?url=<令牌>` 端点 HTTP 下载到本地（`/fxai/down/file` 已固化进 fxai-toolkit 自定义节点包，随 ComfyUI 必存在，下载基址恒为 `comfy_url + /fxai/down/file`，不可配置）。
- **whisper 程序目录**（`whisper_dir`）：whisper 独立服务的安装位置（含 `whisper_server.py` 与 `model\`）。**模型选择已收回程序内部**（`whisper_server.py` 顶部 `MODEL_NAME`，当前 large-v3 满血版），全局配置只管程序在哪，模型不进全局配置；未探测到留空也不影响其它功能，首次用到 whisper 时再补。
- 字段含义：`software_install_dir`/`software_data_dir` 你软件的安装与数据目录（代码据此自动定位 ffmpeg 与 whisper 环境，这是真正需要你提供的两项）；`comfy_url` 是 ComfyUI 服务地址（也是下载基址，唯一必填）；**工作流 JSON 已随包内置在技能外的公共目录 `fxai-workflow/`（~/.workbuddy/skills/fxai-workflow/，与各技能包同级），正常无需在配置里填路径**（`workflow_dir`/`wf_mv_single` 仅自定义包外工作流时覆盖，`ui_wf_dir`）；`ffmpeg` / `whisper_*` 均可不填——代码按「软件安装目录 / 数据目录」自动定位 ffmpeg（带 libass）与 whisper 环境（专用 conda env）的 python；字幕对齐统一先使用该 conda 环境，不依赖本机其它 Python 版本；`ollama_url` 备用。

## 项目目录与产出物归档约定

**每首歌一个以「歌名」命名的项目文件夹**，放在音乐工作区（默认 `<音乐工作区根>\`）下。该文件夹是这首歌的**自包含资源归档**（资源管理用），与 ComfyUI 自身存储解耦——ComfyUI 仍按原有约定运行、产物先落到它自己的输出目录，我们**额外**把产出物下载/复制进这里做备份。

**唯一规则：单文件直接放项目根目录（用中文名），只有图片单独进 `图片\` 子文件夹。** 图片用「类型+阿拉伯数字序号」命名（人物1~N、场景1~N），与 ComfyUI 的 `000/001` 序号不会撞名。

```
<音乐工作区根>\{歌名}\
├── 歌曲.md ←【输入】「## 创作思路」+「## 曲风」(喂 Yue2 的 style) +「## 穿搭」+「## 歌词」
├── 场景素材.md ←【输入】创意素材池：`## 素材 N｜名称` + img/sdesc/cam/camf/act
├── 制作.json ←【输入】技术参数：characters / size(尺寸覆盖) / tags(输出子目录) / prop(道具参考图，可选)
├── 分镜剧本.md ←【输入/输出】★ 创作档：**分段数**条分镜（段落类型/段内人声/引用场景图/歌词意象/img/cam/camf/act）
├── 音乐.wav ← 生成的音乐成品（根目录，中文名）
├── 人声.wav ← ★ 交付的人声成品 = 分离后**再经 RNNoise 去噪**的那版（名称就叫「人声」）
├── 歌词时间轴.json ← 歌词对齐产物：每段「前奏/主歌/副歌/间奏/尾奏」+ 段内人声窗口 + 每句真实起止秒
├── 成片_{W}x{H}.mp4 ← 最终 MV（已烧录字幕），**带分辨率后缀**（如 成片_1280x768.mp4 / 成片_768x1280.mp4）
├── 字幕.ass ← 歌词字幕（ASS，烧录用）— 音乐阶段生成一次，成片直接烧，**不重复识别**
├── 字幕.srt ← 歌词字幕（SRT）— 同上
├── 合并_<W>x<H>.mp4 ← ★ ComfyUI 渲染的**合并成品**（干净无字幕），**原封不动下载进项目目录**（命名同成片：合并_1280x768.mp4 / 合并_768x1280.mp4），本身也是交付物
├── ComfyUI任务记录.md ← ★ 每次视频/音频生成的 ComfyUI 工作流任务 ID（prompt_id）登记
├── 运镜提示词.md ← 每个分段的 Ref2VA 六段式提示词（辅助，根目录；创作类文本一律 .md）
├── 场景提示词.md ← 每张场景图实际送入 ComfyUI 的生图提示词（辅助，根目录；与 运镜提示词.md 并列固定备份）
├── MV提交提示词.json ← ★ 实际提交给 ComfyUI 的 MV 提示词（lines_data 原始数据，含每段「人物参考图+场景图」绑定），事后回顾真实提交依据，纳入交付物与清理白名单
├── meta.json ← 本歌元数据（辅助，根目录）
└── 图片\ ← 唯一子文件夹：所有产出图备份
    ├── 人物1.png （人物四视图/参考图；多人物顺延 人物2…）
    ├── 场景1.png （场景图，按分镜顺序）
    ├── 场景2.png
    └── … 场景N.png
```
- **为什么图片单独成夹、且用「人物1/场景1」数字命名**：ComfyUI 原始输出里人物和场景都叫 `000.png/001.png…`，直接混装会互相覆盖；所以全部进 `图片\`，用「类型前缀 + **阿拉伯数字序号**」命名（人物1、场景1…场景N），既语义化又不会撞名。**序号一律阿拉伯数字**（人物1~N、场景1~N），无论多少张都一致。
- **★ 人物图文件名按数量动态生成**：人物数 = 配置里 `characters` 中 enabled 角色的数量；代码循环为每个角色生成四视图并归档为 `人物1.png`/`人物2.png`…`人物N.png`（场景图同理 `场景1~N.png`）。**支持 2 人、3 人等多人物**，文件名规则无需改动——`produce_song.py` 里没有写死的「人物1.png」字面量（归档用 `人物%d.png % idx` 动态拼），`resolve_existing_assets` 也返回 `char_rels` 列表以支撑 `--mv-only` 多人物复用。
- **歌曲文件 `歌曲.md`**：每首歌先定「曲风」（风格/节奏/编曲，即喂 Yue2 的 `style`），与歌词一起写入；`## 曲风` 记风格、`## 歌词` 记完整歌词（含 `[verse]` 等段落标记）。文件名固定「歌曲」，加新歌不改名。
- **音乐/成片/字幕**都是单文件，按上面的中文名直接放根目录。
- **一键生产 `produce_song.py`**（通用；**逐歌数据都在各自项目目录，脚本不含任何歌曲内容**）：从项目 `歌曲.md` 读曲风/穿搭/歌词、`场景素材.md` 读素材池、`制作.json` 读技术参数；跑完 音乐→四视图→N 张场景图→多参考 MV→字幕 全流程，并**自动按上述结构归档**（音乐→根、图片→`图片\`、成片/字幕→根）。用 `--song=<歌名>` 指定要生产哪首。
- 字幕时间轴来自 whisper 真实时间戳、文字用正确歌词替换（`fxai-lyric-subtitle` 技能）。

### 制作.json 的 prop 字段（道具参考图 · 多参考 MV 专用）
- **作用**：把某件**道具**（如《绝响》用到的古琴）单独生成一张参考图，作为 multiref 模式的**额外参考图**——接在「人物图 + 场景图」之后，对应 H3 的最后一个 `<Picture/Subject>` 编号。`build_multiref_lines` 把 `prop_rels` 追加到每行图片列表末尾，`build_segment_prompt` 同步声明 `<Subject>` 并强制「视频中该道具须严格参照此参考图的形制与质感」，锚定 H3 Ref2VA 偶发的道具漂移。
- **字段**（每项为一件道具）：
  - `name`：道具名（如 `古琴`），仅作缓存 key 与日志标识。
  - `prompt`：**只写道具本体描述**（是什么、材质、形态、关键特征如形制/材质/特殊结构）；背景/承托物/场景/人物由下面的生成规范统一追加。
  - `desc`：该道具在 MV 六段式 `<Subject>` 声明里用的描述（一般比 `prompt` 简，同样不含背景）。
  - `tag` / `subdir` / `num`：服务端落盘目录与固定文件名（`subdir/NNN.png`，同名覆盖，rel 固定不变，便于复用）。
  - `light_prop`（可选，默认 `false`）：`true` 表示道具本身是白色/浅色，需换对比背景（见规范例外）。
- 🔴 **道具参考图生成规范（硬规则，`produce_song.build_prop_render_prompt` 强制；勿在 per-song 提示词里另写背景/桌子）**：
  1. **纯白摄影棚背景 + 画面只有「道具本身」**：画面里只有道具，琴案/桌子/人物/场景/杂物一律不出现；背景纯白到边缘，无渐变、阴影、光斑。
  2. **唯一例外**：道具本身是白色或浅色（`light_prop=true`）时，背景改用**有对比度的纯色**（深灰/墨色），保证道具在图上看得见；此时「仅道具本身」同样要守住。
  3. 上述背景与「仅道具本身」两条由 `build_prop_render_prompt` 统一追加到 `prompt` 之后，作者在 `prompt` 里只写道具本体（写了背景/桌子也会被规范后缀覆盖语义）。
- **生成/复用**：`resolve_prop_rels()` 优先读 `_assets.json` 的 `prop_rels`（已生成则复用，不重渲），缺失才现生成并写回；`--mv-only` 直接复用，只出视频。

### 产出物归档 / 资源管理约定（必守）
1. **这是额外的「备份/归档层」，不改动 ComfyUI 任何生成参数**。ComfyUI 照常把产物落到它自己的输出目录；我们只在其后把需要的产出物**复制/下载**进 `{歌名}/`。
2. **产物一律经下载/复制进项目目录**：ComfyUI 可能部署在**另一台机器**上，本机无法直接操作其路径。本机部署时从 ComfyUI 的本地成品目录（`<技能目录>\fxai-mv-pipeline\output\`）**复制**进项目文件夹（等价于「从服务器下载」）；远端部署走 ComfyUI 的下载接口按返回的相对路径拉取。
3. **归哪些**：
   - 图片（四视图、场景图、人物参考图等）→ `图片\`（类型前缀+阿拉伯数字序号命名，如 人物1.png / 场景1.png）；
   - 最终音乐（wav）+ 最终 MV（mp4，带字幕）+ 字幕（ass/srt）→ 项目根目录（中文名）；
   - ★ **ComfyUI 合并成品（`合并_<W>x<H>.mp4`，干净无字幕）必须原封不动下载进项目根目录**——命名与成片同款（`合并_1280x768.mp4` / `合并_768x1280.mp4`），它本身也是交付物，与 `成片_{W}x{H}.mp4`（在它之上烧录字幕得到的）并存，**原始成品原样保留，另存文件名不覆盖**。
   - ★ **每次生成视频/音频，都要把 ComfyUI 工作流任务 ID（POST /prompt 返回的 `prompt_id`）登记到项目根 `ComfyUI任务记录.md`**；日后凭 ID 可 `POST /fxai/tasks/result {"prompt_ids": <id>}` 反查 url 令牌 → `GET /fxai/down/file?url=<令牌>` 补档缺失产物。任务记录至少记：类型（音乐/MV/四视图/场景图）、任务 ID、产物文件名、时间。
4. `produce_song.py` 已内置归档；历史歌曲/漏归档可跑 **`archive_song.py --song <歌名>`**（加 `--wait` 等产物就绪）。

### 🧹 生成完成后清理中间件/临时件
- **原则**：歌曲项目目录里**只保留约定交付物**；除交付物与 agent 自己的必要记录外，其余 `_` 开头的临时件/中间件全部删除。生成全流程跑完（`produce_song.py` 的 `main()` 收尾）**自动**调用 `cleanup_song_tmp(SONG_DIR)`，无需手动清。
- **保留清单（精确文件名白名单 + 带分辨率前缀 + 子目录）**：
  - 文档/元数据：`歌曲.md`、`场景素材.md`、`分镜剧本.md`、`运镜提示词.md`、`场景提示词.md`、`MV提交提示词.json`、`ComfyUI任务记录.md`、`制作.json`、`meta.json`、`歌词时间轴.json`；
  - 音频/字幕：`音乐.wav`、`字幕.ass`、`字幕.srt`；
  - 交付视频：`成片_<W>x<H>.mp4`、`合并_<W>x<H>.mp4`（前缀匹配，带分辨率后缀）；
  - 子目录：`图片/`（产出图归档，清理时整目录保留）、`.workbuddy/`（项目记忆，整目录保留）；
  - ⚠️ **例外保留** `_vocal_spans.json`：whisper 原始人声时间窗，**`--phase render --reuse-music` 重渲时跳过对齐，靠它给 `classify_segments` 判定分段人声**，故作为 agent 记录保留。
- **删除项（`cleanup_song_tmp` 只命中以下「显式临时模式」，未知文件/目录一律不动，安全）**：
  - 所有 `_` 开头临时文件：whisper 转录 `_transcript*.txt`、对齐报告 `_align_report.json` / `_align_verify.json`、各阶段日志 `_*_phase.log` / `_render_run*.log`、回收脚本 `_*_finish.py` / `*.log`、`_watch_retrieve*.log`、抽帧校验图 `_v*.png` 等；
  - `*.bak` 备份；`__pycache__/`、`.cache*`（缓存目录）。
- 实现位置：`mv_pipeline.cleanup_song_tmp(song_dir)`（删除策略见代码 `_SONG_KEEP_*` 常量），返回 `(removed, kept)` 供日志打印。若目录已是纯交付物则打印「无需清理」。
- ⚠️ **同一产物的收尾脚本（如下载+烧字幕）只用一个**，并发回收会破坏「先备份后覆盖」语义。

### 输出路径速查
- ComfyUI 中间产物：`<ComfyUI>/fxai/{image|audio|video}\<子目录>\`
- 本地成品（默认）：`<技能目录>\fxai-mv-pipeline\output\`（即归档约定里「从 ComfyUI 下载」的来源目录）
- 返回：本地绝对路径；失败抛 `RuntimeError`。

## 加一首新歌的标准动作
1. 建项目目录 `{WORKSPACE}/{歌名}/`。
2. 写 `歌曲.md`：至少 `## 曲风` + `## 穿搭` + `## 歌词`；建议再加 `## 创作思路`（这首歌表达什么、为什么做、意象体系、听觉设计）。
3. 写 `场景素材.md`：创意素材池，`## 素材 N｜名称` + `img/sdesc/cam/camf/act`（**只提供氛围与运镜，不决定张数**）。
4. 需要时写 `制作.json`：`characters`（如 `["女主"]`）、`size`（竖屏/横屏尺寸覆盖）、`tags`（ComfyUI 输出子目录，缺省自动派生）。
5. 确认 `config.json` 的 `characters` 里已配好该人物的 `ref_image`（相对路径）与 `desc`（**只作标记，如「面部特征参考图」，不写具体五官、不写穿搭**）。
6. 跑 `python produce_song.py --song={歌名} --phase music` → 逐条改写 `分镜剧本.md` → 再 `--phase render`。

### ★ 脚本不内嵌任何歌曲数据
- **逐歌创意内容一律留在项目目录**：歌词/曲风/穿搭/场景/创作思路等**逐歌创意内容**写在项目目录里，`produce_song.py`（及其它脚本）只放通用逻辑。
- 一切逐歌数据从**项目目录**读：`load_song_project()` 读 `歌曲.md`（创作思路/曲风/穿搭/歌词）+ `场景素材.md`（素材池）+ `制作.json`（characters/size/tags）。缺文件直接报错，不静默兜底。
- 脚本只保留**通用逻辑**：H3 分段公式、时间规则、运镜库/构图库、分镜生成与回读、下载与归档、字幕。
- 当前歌由 `--song=<名>` 或环境变量 `SONG` 指定（**不写死 `ACTIVE_SONG`**）。
- `RUN_OVERRIDES` 仅作对话期临时覆盖、保持 `{}`；项目级尺寸差异写进 `制作.json` 的 `size`。

## 工程相关经验

**4. MV 内部超时**：`run_workflow` 是脚本硬超时，长 MV（29 段多参考）常超 3h → 改 10800→21600（6h）让脚本自跑完；或后台运行 + watcher 兜底，服务端还在渲染时保持进程与队列原样（重跑会撞车浪费 GPU）。

**6. 生成后清理中间件**：`produce_song.py` 收尾自动 `cleanup_song_tmp`，删 `_` 前缀临时件/`*.bak`/`__pycache__`；保留约定交付物 + `_vocal_spans.json`（重渲复用）+ **`_music_ref.json`（复用音乐必需）**。⚠️ **`--reuse-music` 依赖 `_music_ref.json` 判定「可复用」**：若它被当临时件清理掉，`bool(_ref)` 为 False → 静默重新生成音乐、覆盖原 `音乐.wav`。已把 `_music_ref.json` 加入 `_SONG_KEEP_TEMP` 保留名单。多个收尾脚本禁用并发跑同一产物（会破坏「先备份后覆盖」语义）。

**9. 提示词固定备份**：三类「最终生产提示词」都落盘为项目根目录固定文件、纳入交付物与清理白名单，作为固定备份——
① `运镜提示词.md`（逐段 Ref2VA 六段式 MV 提示词，step 4/6 生成，人读版）；
② `场景提示词.md`（每张场景图**实际送入 ComfyUI** 的生图提示词，step 3/6 生成）；
③ **`MV提交提示词.json`**（multiref/single/multi 三种模式实际提交给 ComfyUI 的 `fxai_prompt`/lines_data 原始数据，含每段「人物参考图+场景图」绑定，`gen_mv` 提交时由 `prompt_out` 参数自动落盘）——这是事后回溯「真实提交了什么」的唯一原始依据，必须保留。
三者都属约定交付物，`cleanup_song_tmp` 不删；后续新歌自动产出，旧歌用脚本补。

**11. 🔴 `--mv-only` 找不到素材**：`resolve_existing_assets` 默认只扫 `_render_run.log`/`_produce_run.log`（带下划线前缀、且清理中间件会删），而实际保留的主日志叫 `render_run.log`（不带下划线）→ 永远返回「素材 0 张」→ 渲染在 2/6 直接退出。但 ComfyUI **仍保留**历史产物（从 `render_run.log` 提取 prompt_id 反查 `/fxai/tasks/result` 能拿回 `song_ref_scene/00N.png` 等引用）。**处置**：默认改为扫描目录下所有 `*.log` 并按修改时间倒序（最新优先），任何命名约定下都能复用。`--mv-only` 因此能复用已生成的 15 张场景图 + 人物图，跳过 2/6、3/6 生图，直接重跑 4/6 运镜→5/6 MV→6/6 字幕+清理。
