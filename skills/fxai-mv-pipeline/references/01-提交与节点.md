# 01 · 提交与节点（工作流提交 · 传值规范 · 节点映射 · 落盘 · 排错）

> 何时读：提交报错、改工作流 JSON、换工作流版本、查节点号与传值规范、落盘序号不对。

## ComfyUI 运行架构：CS 模式（HTTP 接口交互 · 用户拍板，硬性）
- 🚨 **我们调用的 ComfyUI 是「服务端/客户端（CS）架构」，全程走 HTTP 接口**：无论它装在本机还是远端，一律当**服务器**对待。所有交互都通过接口完成——提交工作流 `POST /prompt`、查队列 `GET /queue`、查任务结果 `POST /fxai/tasks/result`、下载产物 `GET /fxai/down/file`、中断 `POST /interrupt`、释放显存 `POST /free`。
- **本机进程管理一律不做**：判断 / 查 / 杀 ComfyUI 进程（无 PID / tasklist / kill）全交给保活方。进程存活由「凤希本地AI控制台」保活，杀进程会硬断渲染任务。**状态判断全靠接口返回，进程表不参与判断。**
- 🔴 **资源存在性确认 → 只走接口，以接口返回为准（硬性）**：确认 `avatar/000.png` 等参考图、或 `fxai/image/...` 任何资源是否存在时，资源目录的存在性由服务端回答——ComfyUI 是**服务器端模式**、很可能装在**另一台机器**上，本机磁盘 ≠ 服务端磁盘，本地扫到的「有/无」只作参考，服务端真实状态以接口返回为准。正确做法只有两种：① **直接提交工作流**，被服务端返回 `prompt_id` 并 `queued` 即最权威证明——服务端已成功读到该参考图，无需额外确认；② 主动探测走 `GET /fxai/down/file?url=<category/subdir|file>` 让服务端自己返回文件。**这条铁律的通用版见 `fxai-workflow` 客户端 SKILL.md，所有调 ComfyUI 的技能都必须遵守，换项目空间同样按此执行。**
- 🔄 **渲染中断 → 断点续跑（接口判定）**：周期性 `GET /queue` + 读 produce_song 日志里的 `] queued <prompt_id>` 判断跑到第几步（1/6~6/6）。若某步卡住 / 队列空但任务没完成，就从**该步继续**——仅 MV 挂→`--mv-only` 复用已生成图重渲；charview/场景图挂→整段 `--phase render --reuse-music` 重来。不无脑从头全重。
- ⚠️ 渲染「莫名停了」最常见原因：**队列被清空**（`POST /queue` 空 body 会报 `JSONDecodeError: Expecting value`，但任务已被清掉）。这是清空动作所致，**不是工作流提交格式错**——提交走 `POST /prompt`，成功必返回 `prompt_id`（日志 `queued <id>` 即为证）。

## 等任务

`run_workflow` / `submit_workflow` 内部等 `fxai:task_saved`（＝**合并/保存完毕**）才返回，返回即已过终态门。
| 阶段 | 规则 |
|---|---|
| 等待期·**正常** | ✅ 只查健康（服务器/进程还活着吗）<br>❌ 不做数据交互：不查 `/history`、不拉文件列表、不取结果、不下载、不反复 curl `/queue` |
| 等待期·**报错** | ✅ **这时才做数据交互**：取错误详情与日志，分析原因并解决。异常里带 `prompt_id`，用 `comfy_watch.py status <pid>` 查详情 |
| **终态门** | 日志出现 `✅ 合并成功，已保存：<url>` 之后，才做后续：取产物 → 烧字幕 → 归档 → 交付 |
- 要在对话里只在完成时播报一句 → `comfy_watch.py next <pid>`（只出终态，不刷过程）。
- 要全程看进度 → 双击 `fxai-comfyui-watcher/progress.html`（直连 WS，绕过对话，不耗 token）。

## 🚨 工作流提交前「格式自检」（防传值 / JSON 低级错误 · 用户拍板）

> **任何工作流提交 `POST /prompt` 之前，必须先按「该工作流的传值规范」做格式自检。** 不同工作流字段不同，规范各列于下；不通过就**立即点名报错**，在本地拦下脏 payload，再等难懂的节点错误就无从追溯。

### 实现（已在 mv_pipeline.py 落地）
- `run_workflow(wf, kind=..., tag=...)` 在 `json.dumps({"prompt": wf})` **之前**自动调用 `validate_workflow_payload(wf, kind, tag)`。
- 各 `gen_*` 已传入对应 `kind`：`gen_music→"music"`、`gen_char_view→"charview4/3"`、`gen_scene_image→"scene"`、`gen_mv→"single/multi/multiref"`。
- 自检四步：① 整体可 JSON 序列化（抓 Path/对象/bytes 混入）；② 每个节点结构合法（`class_type:str` + `inputs:dict`）；③ 按规范核对待填**字段齐全 + 类型正确**（重点抓 `_set` 静默跳过的漏填）；④ 多参考 `lines_data` 必为合法 JSON 且每行 `[int,str,str]`。
- 规范表（节点 id + 字段 + 期望类型）集中在 `mv_pipeline.WF_SPECS`，随工作流版本应同步维护；**某节点被改名会立刻报错提醒**，把「悄悄漏填→任务被吞」变成显式失败。

### 各工作流传值规范（提交前必过的字段清单）
| kind | 工作流 | 必填字段（节点 id · 字段 : 类型） |
|---|---|---|
| `music` | Yue2 音乐生成 | `42`·style/lyrics/mode:`str`；`45`·style/lyrics/mode:`str`、max_duration:`int/float`；`50`·seconds:`list`（保持对 45 的链接，由节点自己带出）；`55`·目录:`str` |
| `charview4` | 千问四视图 V2 | `147`·图片列表:`str`（有参考头像→参考图，无→空）；`170`·提示词:`str`；`205`·正向提示词:`str`（纯提示词支路主生成）；`210`·人脸特征锚脸（参考头像=147）；`117`·目录/文件名序号:`str`；`2`·seed:`int` |
| `charview3` | 千问三视图 | `147`·图片列表:`str`；`203`·正向提示词:`str`；`117`·目录:`str`；`2`·seed:`int` |
| `scene` | 千问图片处理（场景图） | `152`·正向提示词:`str`、宽度:`int`、高度:`int`；`141`·图片列表:`str`；`117`·目录:`str`；`2`·seed:`int` |

> ⚠️ **勿手动构造 `/prompt` 的 payload 绕过 `run_workflow`**——那样就跳过了自检。所有提交都走 `run_workflow`。

## 关键节点映射（供排查/二次开发）
- **Yue2 音乐**：`42`(ABC: style/lyrics/mode/seed)、`45`(生成: style/lyrics/mode/max_duration/seed)、`50`(秒数)、`55`(目录)。
- **千问三视图**：`203`(正向提示词/宽/高)、`147`(图片列表=参考图)、`117`(目录)、`2`(seed)。
- **千问图片处理**：复用 `fxai-comfyui-image-gen` 的 `generate_image`（role 控人物，w/h 控尺寸）。
- **MV 单场景**：`1105`(音频文件/分段)、`1005`(**人物+场景参考**：`图片列表`=`STRING` 逗号分隔、相对 `fxai/image/`，用 `gen_scene_image` 返回的 rel 路径；传列表会 400、硬编码错名会"没有图片")、`925`(帧率/**索引**，宽高由 `768` 驱动)、`768`(最大边长≤1300)、`1135`(保存目录)。
- **MV 多场景**：`989`(音频文件/分段)、`990`(**目录**=场景图片文件夹名，如 `mv_multi`；`758`/`889` 保持 LINK 到 `990`)、`925`(帧率/**索引**)、`768`(最大边长)、`1038`(保存目录)。
- **MV 多参考**：`989`(音频文件/分段)、`1039`(**FxAiScreenManager** 的 `lines_data` 图片列表 = `人物图1,人物图2,...,场景图`（顺序=H3 <Picture N>，人物在前场景在后；多人物时每人占一个 <Picture>）+ 对应 `<Subject N>` 外貌描述，由 `_set_multiref_screen` 注入；`1036`/`1042` 保持 LINK)、`925`(宽高/**索引**)、`1038`(保存目录 ⚠️ 见下)。

> 「长宽对齐基数」三个工作流都固定为 **32**，属固定值，**代码保持原样**。

### ⚠️ 索引铁律（用户规定）

三个 MV 工作流的 `925` 都设 **开始索引=`"0"`、结束索引=`"-1"`**（-1=跑完全部，不截断）。
**多场景、多参考导出默认的 `0/0` 会截断（单场景导出即为 `0/-1`）**，必须由代码强制覆盖为 `0/-1`。

### ⚠️ 生图落盘：固定序号 + 同名覆盖

服务端图片目录**只保留本次的 N 张**：
- 保存节点 `FxAiImageManagerV2`（`117` / 多场景 MV 的 `990`）的 **`启用文件名覆盖` 必须为 `True`** —— 四个工作流 JSON 均已设好（三视图/四视图/图片处理 `117`，多场景 `990`）。
- **覆盖开关 + 序号必须一起给**：`save_tensor_image` 仅在 `enable_overwrite` 且 `文件名序号` 为可用整数时采用序号，否则 `get_next_number()` 递增追加 → 只开覆盖开关仍会追加。
- 所以代码一律走 `_apply_img_overwrite(wf, node, num)`：覆盖开关 + 序号一起给。
  - 场景图：`num = 场景索引号（0 起）` → 第 i 张固定写 `00i.png`，重跑同名覆盖，目录里恒为 `n_total` 张。
  - 四视图：单人一次输出 `000–003.png`（`num=0`）；**多角色时按角色序号传 `num`**（第 n 个角色 `num=n-1`）→ 各角色 `000.png` / `001.png` 分列，重跑同名覆盖。
- **目录名只表语义，不带序号/时长后缀**：`song_charview` / `song_ref_scene`。
  - 目录 = 「这类资源放哪」，编号 = 「里面第几个」——**编号一律写在文件名上**（`fxai_filename_index`），不写进目录名。多角色靠不同 `num` 天然错开，不需要拆目录。
- `文件名序号` 在 INPUT_TYPES 里是 `forceInput`，但 **ComfyUI 服务端不校验 forceInput**（只影响 UI），API 传 int 常量合法；保险起见 `_run_img_workflow` 若遇「提交被拒」会自动移除该键重试（退回递增）。

### ⚠️ 多参考 `1038` 保存目录：由 gen_mv 自动补齐

`1038`(`FxAiMiniMaxVideoSaveV2`) 的「保存目录」缺失时，提交会报 `required_input_missing: 保存目录` **直接失败**。
gen_mv 主动补：`if "保存目录" not in wf["1038"]["inputs"]: ... = "mv_multiref"`。
> 注：部分输入是「连线(link)」而非值，已尽量覆盖值输入；若人物/场景未生效，需进一步把上游连线源节点改成目标图片（见 mv_pipeline.py 内 `_set`/`_set_multiref_screen` 注释）。

## 排错经验（提交相关）

**8. 占位符工作流**：所有 `gen_*` 走 `submit_workflow`（params 字典 → 占位符注入），分非字符串/JSON值/字符串三类替换；缺参回退 nodeconfig 默认（等价旧「不填=工作流默认」）。

**5（原）. 多行字符串占位符**：`submit_workflow` 字符串占位符必须用 `json.dumps(value, ensure_ascii=False)` 整体替换带引号占位符；只转义双引号会让多行歌词里的换行变成 JSON 非法控制字符（`Invalid control character`）。

**10. 🔴 multiref MV 提交 400 bad_linked_input**：`submit_workflow` 占位符替换若按「字符串内容是否像 JSON」判定，会把 multiref 的 `fxai_prompt`（一个 JSON 格式**字符串**，即 lines_data）误当原始 JSON 裸插成 list，同时 `fxai_segment_data` 默认 `[]` 也被裸插成 list → ComfyUI 的 `lines_data`(node 1039)/`关键帧JSON`(node 989) 都是 STRING 输入，收 list 即报 `bad_linked_input`。**处置**：`_to_replacement` 改按 Python 真实类型分类——`_NON_STRING` 占位符（数值/布尔）裸插；其余一律 `json.dumps(str(val))` 包成带引号字符串（传入 list/dict 则双层 dumps）。替换循环移除 `_is_json` 误判分支。验证：monkeypatch `run_workflow` 跑 `submit_workflow(WF_MV_MULTIREF, ...)`，`wf["1039"]["inputs"]["lines_data"]` 与 `wf["989"]["inputs"]["关键帧JSON"]` 必须都是 str。

**12. 🔴 换 multiref 工作流版本需核对服务端节点 INPUT_TYPES**：新工作流经 `submit_workflow` 替换占位符后，ComfyUI 服务端当前运行的自定义节点版本可能要求工作流**没填**的必填输入。`FxAiMiniMaxVideoSaveV2`(node 1038) 必填「保存目录」，漏填会被拒 `required_input_missing: 保存目录`。**做法**：`submit_workflow` 在 multiref 提交前按 `class_type=="FxAiMiniMaxVideoSaveV2"` 自动注入 `保存目录 = fxai_outputdir`（**不改工作流文件本身**，对以后换工作流也自动适配）；`WF_SPECS["multiref"]` 的 `("1038","保存目录",str)` 复原检查此项。
**同名替换 12.json 后必做**：
① dry-run 验证——monkeypatch `run_workflow` 跑一遍 `submit_workflow(WF_MV_MULTIREF, multiref_params)`，断言 JSON 合法、节点 1039 `lines_data`/989 `关键帧JSON` 均为 str、1038 已含「保存目录」；
② 对照 ComfyUI 服务端节点 INPUT_TYPES 核对所有必填输入是否齐全（不只是「保存目录」，可能还有别的）；
③ 确认 `WF_SPECS["multiref"]` 的节点号(989/1038/1039)与字段名仍匹配新工作流——不匹配会再报缺失/类型错。
当前 mv-minimax-multiref.json = MiniMax H3 `prism_dmad_pdmd_int8` + `H3人脸去油` 0.7 + `Motion_Repair` 0.45 + 双采版（含 Upscaler/音频解码/音视频分离节点）。
