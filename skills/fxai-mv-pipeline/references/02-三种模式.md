# 02 · 三种模式（single / multi / multiref · 用哪个就读哪一节）

> 何时读：**开工必读**。确定这次走哪种模式后，**只读该模式那一节**，其余两节不读。
> 角色视图规则与尺寸规范是三种模式共用，在本文前两节。

## 角色视图生成规则（硬性，务必遵守）
- **一律生成【四视图】**（`images=4`）：本地四视图工作流有无参考图都能生（无自有参考图时按提示词纯设定生成四视图）。
- **用到我们自己的角色（自有角色 000 / 001 等）→ 必须用我们自己的参考图生成四视图**，靠参考图锁脸锁身段；「这次没传参」也照样传 `ref=<自有参考图 rel>`，视图数恒为 4。
- **不是我们自己的角色**（客串角色、他人肖像、纯新角色）→ 没有自有参考图，就按提示词生成四视图。
- 显式写 `gen_char_view(prompt, ref=<自有参考图 rel>, views=4)`；无自有参考图时仍走四视图（若代码仍报「四视图必须提供 ref」，属技能代码尚未放开，先确认再跑，视图数保持 4）。
- 两个视图工作流的尺寸由工作流内置，**宽度/高度由工作流自己决定，代码不传覆盖值**。
  ⚠️ 注意：输出长边**并非固定值**，会随宽高比浮动，所以**按固定值推算视频尺寸会算错**，一律读实际图片长边。
- 参考图节点均为 `147`（FxAiCharacterImageSelector，「图片列表」= 相对 `fxai/image/` 的字符串，如 `avatar/000.png`）。
- 四视图 V2 工作流有两条生成支路：无参考头像 → `170` 提示词进 `205`（FxAiQwenImage21ThreeView）纯提示词出图；有参考头像 → 参考图进 `147` 再到 `210`（FxAiQwenFaceFeature）锚脸重生成，两条结果由 `197`（ImageStitch）拼成一张四视图，落在 `117`。⚠️ **`210` 的人脸特征流程与 `205` 的提示词输出都是工作流原样，代码勿覆盖**。

### ⚠️ 提示词职责划分（用户规定，容易写错）

写三/四视图提示词时，**只写「人」本身的内容 —— 发型、妆容、服装（穿搭）**。例如：

> 清冷疏离的年轻女子，利落短发，淡妆，过膝白色长风衣

**以下内容交给自定义节点内部默认，提示词里省掉**：
- ❌ 「完整全身人物，从头到脚完整入画」「人物比例标准」等**全身入画/构图**描述
- ❌ 「干净白底」「8k」「高清」「电影质感」等**画质/背景/镜头**描述

> 即：**三/四视图 = 只描述穿搭（发型/妆容/服装），其余交给节点默认**。
> 只有当某次生成确实需要特殊构图（比如要半身、要特定角度）时，才**按需**补写那句描述——「根据需要是否全身入画」是按当次生图需求现场决定的，不是默认必须写。

**图片处理（`gen_scene_image`，纯图片处理/场景图）** 则相反：需要**完整描述**（场景、光线、氛围、人物状态、穿搭都要写）。同样**不必默认写「全身入画」**，也是按当次需要再补。穿搭依旧要写全（参考图 000 是裸肩，靠提示词里的服装约束）。

## ⚠️ 尺寸规范：只按规范传参，不代劳判断

本机 fxai 自定义节点内部**已做好全部尺寸判断**（缩放、对齐、裁剪、校验）。Agent 的职责只有两条：
1. **图片**：按规范尺寸生成（竖屏 1080×1920 / 1440×1920，横屏宽高交换），不裁剪、不算图。
2. **视频**：最大边长按规范给 **1300**（`MAX_EDGE`），不读图、不预判。

> 代码里的 `safe_max_edge` / `_mv_limit` / `_img_long_edge` 等只是**排查工具**，
> 由开关 `AUTO_SIZE_GUARD` 控制，**默认已关闭（False）**——关闭时一律直接用 1300，不参与生成逻辑。
> 只有排查「放大被拦」这类异常时，才临时置 True 做事前拦截。
> 「长宽对齐基数」三个工作流固定 32，属固定值，代码不动它。

## 尺寸与约束（用户硬性规定）
- **图片（底图）**：长边可达 **1920**。竖屏 `portrait_9x16=(1080,1920)` / `portrait_3x4=(1440,1920)`；横屏宽高交换 `landscape_3x4=(1920,1440)`。内置 `IMG_SIZE`。
- **视频**：最大边长 **≤1300 且 ≤ 输入图长边**（自动取 `min(1300, 图长边)` 并按 32 对齐）。竖屏 `(731,1300)` / `(975,1300)`；横屏 `(1300,975)`。内置 `SIZE`、`MAX_EDGE=1300`、`_mv_limit()`、`safe_max_edge()`、`_fit_to_ratio()`。
- **循环分段默认 10 秒**（音频分段节点 `平均分段时长=10`），无需改。
- 默认人物由 **工作区配置 `config.json`** 决定（见 `04-配置与归档.md`）：在 `characters` 配人物参考图（相对路径如 `avatar/000.png`）；每首歌在项目的 `制作.json` 里用 `characters: ["女主"]` 指定用谁。`char_rel` 不传时取配置里的第一个启用人物。

## 模式一：single（单场景）

一个固定场景贯穿全曲。**人物直接生成在场景里**（参考图 = 女士头像，场景图由千问生成「人物+场景」）。
- 节点：`1105`(音频文件/分段)、`1005`(图片列表 = 逗号分隔 rel 路径，**传列表会 400**)、`925`(帧率/索引，宽高由 `768` 驱动)、`768`(最大边长≤1300)、`1135`(保存目录)。
- 单场景导出即 `0/-1`，与索引铁律一致。
- **提示词保持工作流默认**，原样提交。

## 模式二：multi（多场景）

按音乐段落切换多个场景。多个「人物+场景」图放进同一文件夹，按音频分段循环切换（**H3：FL2VA 首尾帧 + 音频参考，提示词保持工作流默认**）。
- 节点：`989`(音频文件/分段)、`990`(目录 = 场景图片文件夹名，如 `mv_multi`；`758`/`889` 保持 LINK 到 `990`)、`925`(帧率/索引)、`768`(最大边长)、`1038`(保存目录)。
- **提示词保持工作流默认**。
- 段间「上一段尾帧 → 下一段首帧」是 single/multi（FL2VA 双采版）的机制。

## 模式三：multiref（多参考）—— 默认走这条

要最稳的人物一致性。**链路：四视图 → N 张纯场景图 → 逐段 Ref2VA 六段式运镜 → MV → 字幕。**

### 🔴 场景图铁律：必须是空场景，不含任何人物

人物靠 `char_rel`（四视图参考图）+ 当歌穿搭在 MV 生成阶段注入（Ref2VA 的 `<Subject 1>`）。
场景图 img **只写环境**（场景/光线/氛围/构图），**人物描述留给分镜的 `act`**——在 img 里写"一位女子立于…/穿…"会让生出的场景图带人，与参考人物重复/冲突，MV 里出现双人或错位。

> 即：**场景图 img ≈ 该条素材的 `sdesc`（纯环境）**；人物动作写在分镜的 `act`，由 MV 提示词消费。
> 反例：`single` / `multi` 才是人物直接画进场景。混用会双人或错位。

### ★ 歌词感知场景图

有真实歌词的演唱段，场景图 img 末尾自动追加：
「画面环境呼应此段歌词意境：`<歌词>`，但只表现自然/环境意象（花田/光线/微风/天空/水面等），**保持空镜、不出现任何人物**」；
纯器乐段/无唱词段（歌词意象为空）不追加，保持素材池主题自由发挥。

实现：`build_storyboard` 在自动生成分镜时注入（仅 `scene_overrides` 为空时）；已生成的分镜剧本可用一次性脚本 `_enrich_lyric_scenes.py` 补注入（幂等，只命中真正歌词行）。

### ⚠️★ 多人物绑定铁律（按 H3 Ref2VA 规范 + 短剧已实现写法）

多参考图的「图片列表」顺序 = H3 的 `<Picture N>` 顺序，**人物图在前、场景图在后**：

```
<Picture 1>   = 人物1（四视图/角色图 人物1.png）
<Picture 2>   = 人物2（若有，人物2.png）
...
<Picture K+1> = 场景图
```

提示词里 `<Subject 1>` = `<Picture 1>` 中的人物（人物1）、`<Subject 2>` = `<Picture 2>`（人物2）… `<Subject K+1>` = `<Picture K+1>`（场景）。
代码里图片列表拼成 `"人物1,人物2,...,场景N"`，`build_segment_prompt` / `build_ref2va_prompt` 自动按人物数生成 `<Subject 1..K>` + `<Subject K+1>`。
**单人物时 K=1**，`<Picture 1>`=人物、`<Picture 2>`=场景。

### ★ 单次生成帧数：固定 10s 分段，不切 6 秒
- `FxAiMiniMaxImageToVideoV2`（1036）的 `帧数` 参数：`min 5 / max 3600 / step 17`，
  tooltip：**「自动对齐到 17k+5 网格（124≈5秒；训练范围约 124-362）」** → 训练有效区间约 **5.2s–15.1s**。
- 我们的 10s 分段 = **226 帧**，落在区间中部 → **单次生成即可，不切成 6 秒**：改 6 秒会贴近下限，且段数、场景图数、渲染排队时间都大幅增加。
- 段间「上一段尾帧 → 下一段首帧」是 **single/multi（FL2VA 双采版）** 的机制；
  **multiref（V2 双采版）的 1036 只接了「参考图片列表」，没接首帧/尾帧图片 → 每段独立生成**。
  首尾 1 秒安全区对 multiref 是「本段收束」用，对 single/multi 则能防止继承上一段的张嘴画面，两种模式都有价值。

## 调用方式（对话内首选 import）

> 视频生成已抽成公共件 `fxai-audio-video`（音频驱动 → 视频，数字人口播共用同一份实现）。
> 本模块 `gen_mv` / `build_ref2va_prompt` / `_build_multiref_lines` / `_build_multiline_prompt`
> 全部转调它，`kind` 固定 `"sing"`（演唱措辞）；口播那边传 `kind="speak"`。签名与行为不变。

```python
import sys
sys.path.insert(0, r"<技能目录>\fxai-mv-pipeline")
from mv_pipeline import gen_music, gen_char_view, gen_threeview, gen_scene_image, gen_mv, IMG_SIZE, SIZE
# 1) 音乐（短歌 60s；style/lyrics 遵循 fxai-yue2 技能规范）
audio, aud_rel = gen_music("中文，内敛女声，当代流行融合民谣，约78BPM，木吉他钢琴铺底，温柔疏离",
 "[Verse]\n半生的漂泊 早懒得数\n[Chorus]\n习惯了一个人的日子", duration=60)
# 2) 单/多场景：人物直接生成在场景里（图片 1920 长边，高清底图让视频更清晰）
# 图片处理=纯图片处理，需要完整描述（场景/光线/氛围/人物/穿搭）；「全身入画」按需再补
scene, scene_rel = gen_scene_image("中秋夜，都市高楼天台，一袭白衣女子独望明月，电影级光影",
 role="woman", w=IMG_SIZE["portrait_9x16"][0], h=IMG_SIZE["portrait_9x16"][1], tag="scene1")
# 3) 多参考：先【四视图】纯人物（有参考图→四视图，尺寸由工作流内置），再单独场景
# 三/四视图只写穿搭（发型/妆容/服装），别写全身入画/白底/8k——节点已默认
char, char_rel = gen_char_view("清冷疏离的年轻女子，利落短发，淡妆，过膝白色长风衣",
 ref="avatar/000.png", views=4, tag="mv_char", subdir="charview")
# 4) 生成 MV（三种模式；size 为「视频」尺寸，最大边长 ≤1300）
gen_mv("single", aud_rel, scene_rel=scene_rel, size=SIZE["portrait_9x16"])
gen_mv("multi", aud_rel, scene_rel="mv_multi", size=SIZE["landscape_3x4"])
gen_mv("multiref", aud_rel, char_rel=char_rel, scene_rel=scene_ref_rel, size=SIZE["portrait_3x4"])
```

> 提示词规范：
> - **三/四视图（纯人物）**：只写**穿搭**（发型/妆容/服装）；全身入画/白底/8k/镜头等由自定义节点默认，**不写**，除非当次生成确实需要再补。
> - **图片处理（场景图）**：**分模式**！
>   - **single / multi（单·多场景）**：人物直接画进场景，img 需**完整描述**（场景/光线/氛围/**人物/穿搭**）；「全身入画」按需再补。
>   - **multiref（多参考）**：img **只写环境（场景/光线/氛围/构图），人物由 char_rel 参考图在 MV 注入**。场景图 img ≈ 该素材的 sdesc（纯环境）。这条是铁律，img 写上人物时场景图会带人、与参考人物冲突。**有歌词的演唱段应让场景图贴近该段歌词的环境意象（纯环境、人物留给 MV），纯器乐/无词段按主题自由发挥**（见上方「★ 歌词感知场景图」）。
> - 一律**按传入内容原样使用，不追加任何后缀**。
> `gen_scene_image` / `gen_char_view` 返回 `(本地路径, rel路径)`，其中 **rel 路径就是 ComfyUI 侧相对 `fxai/image/` 的路径**（如 `mv_single_scene/003.png`），可直接喂给 MV 的 `scene_rel`/`char_rel`；**文件名用返回的 rel 路径**（实际落盘名是序号，可能与 tag 不同）。

**判定口径**：`config.json` 的 `desc` 永远是标记文案（「面部特征参考图（仅标记…）」），不可当穿搭用。`_char_desc = (_cc.get("char_desc") or OUTFIT_DESC)`，且含「仅标记/以参考图为准/复刻五官」字样即回退 OUTFIT_DESC。
**这条是 MV / 多参考共同遵守的全局铁律**——凡运动/六段式提示词要描述人物，一律「实际穿搭」，与生成四视图时那句提示词一致。

**14. 🔴 multiref 按段重渲（0 起索引，start=end）——「哪段不好就只重渲那段，不必整支重渲」**：multiref 工作流支持**只重生成其中某一段**，不重跑整支 MV，省 GPU、省时间。这是用户的硬性工作习惯，凡 multiref 模式必须遵守。
- **机制**：node `925` 的 `开始索引`/`结束索引`（占位符 `fxai_start_index`/`fxai_end_index`）限定渲染的段范围；只重单段 = 把起、止索引填成**同一个值**。
- **索引约定（0 起）**：故事板第 N 段 → 索引 **N−1**。例：重渲故事板第 12 段 → 索引 `11`（start=end=11）；第 14 段 → 索引 `13`。要重第 12、14 两段 = 提交两次独立任务（start=end=11 / start=end=13）。
- **代码已落地**：`gen_mv(..., start_index=..., end_index=...)` 在 multiref 分支把这两个值透传进 params（默认 `None` → 不传，节点默认渲染全部段）。`produce_song.py` 提供开关 **`--mv-segment=<N>`**（N 为 0 起索引）：隐含 `--mv-only`（复用已有图、不重生），只对第 N 段提交一次 multiref 任务。

- 🔴 **服务端自动合并成完整片**（所有视频生成环节的统一模式，见
  `fxai-standard/references/01-产出铁律.md`「视频生成的两种跑法」）：完整生成与单镜重渲都一样，
  服务端把「本次新段 + 已缓存的其他段」合并成一条完整视频返回；本地取到的即全长成片，
  直接进后续环节。
  - 逐段产物：`<ComfyUI>/fxai/video/<prefix>_multiref/<序号>.mp4`（`000.mp4` 起，0 起编号；MV `prefix=mv`）。
    服务端按项目缓存各段，同一时刻只有一个项目，重渲单段不影响其他段。
  - 合并产物：`fxai/video/merged/fxai_<时间戳>.mp4`——每次提交出一条完整成片。
  - **判据**：返回成片时长 = 全长。时长等于单段说明走的是单段下载路径（`--mv-segment` 取单段文件的场景）。
- **整支重做**走 `start_index=0` / `end_index=-1` 一次提交跑完；本节的单镜跑法用于某一镜返修。
- **断点续跑**走 `start_index=N` / `end_index=-1`（N 为 0 起索引）：从第 N+1 段渲到结尾，前面段命中缓存不动。
  断点位置用 `comfy_watch.py shots <pid> --dir <保存目录> --total <总段数>` 查（`--json` 取 `next_index`）。
- 单镜重渲带上该段原本的运镜 + 人物 + 场景绑定（`seg_prompts` 第 N 条），改提示词先改故事板对应条再重渲。
- **字幕**：全曲字幕在拿到服务端合并的完整片后**一次烧**（勿分段各烧，时间轴会错位）。

**15. 🔴 成片后抽帧质检（每段中点一帧 → 联络表，核对「人物在场 + 穿搭符合当歌设定」）**：MV 烧字幕出成片后**必须抽帧自检**，验收依据是抽帧画面，渲染日志的 success 只作参考。做法：对**未烧字幕的 `合并_{W}x{H}.mp4`** 按分段中点（`t=(N-1)*段长+段长/2`，避开头尾 1s 过渡区）逐段抽 1 帧，再拼成一张联络表（`-start_number 1 -i s%02d.png -vf "scale=320:-1,tile=6x5"`，本机 ffmpeg 不支持 `-pattern_type glob`，用 image2 序号）一眼扫全片，核对：① **每段人物都在场**（无「空镜无人」的段落）；② **人物穿搭 = 当歌设定**（歌曲.md `## 穿搭` 的发型/服装/配饰，而非基础头像或他歌形象）。
- **图必须看，日志只作参考**：渲染日志报 success 也看不出人物形象对不对（日志正确但四视图与成片人物都没穿上当歌穿搭是会真实发生的）。**成片与四视图都必须抽帧目测验收**，验收以画面为准。
