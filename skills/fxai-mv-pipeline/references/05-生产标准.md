# 05 · 生产标准（场景图数量 · 创作时序 · 逐段提示词 · 审美）

> 何时读：写分镜剧本、定场景图数量、写逐段提示词、把握审美要求。

## MV 生产标准（场景图数量 + 审美 · 必守）

### 场景图数量按音乐时长定
- **最底层铁律**：场景图数量**只由音频真实时长按时间规则算出**。除非用户明确要求生成多少张、或有其它特殊要求，否则手动指定 / 堆场景数一律不采用，`max(时间规则, SPEC场景数)` 之类悄悄覆盖时间的写法同样不采用。
- `场景素材.md` 只是**创意素材池**（场景氛围 + 各自运镜），**不是数量决定项**；池子不够就循环取用，循环条必须换运镜 + 换构图修饰，保证条条不同。
- 数量规则：
  - **短歌（≤2 分钟 / 120s）**：每个分段一张、**零重复**（`n = 分段数`）。
  - **长歌（>2 分钟）**：至少「**分段数 ÷ 2 + 1**」张，前面场景最多循环一次（来回重复会看腻）。
- 实现：`produce_song.py` 在音乐生成后按实际时长 `dur` 算 `min_scenes → n_total`（**纯时间规则**），再生成；图片按 `场景1.png … 场景N.png`（阿拉伯数字序号）命名。

> ⚠️ 时间规则只是**下限**，规划场景数优先——见本文末「经验 18」。

### ★★ 逐段提示词：演唱段 vs 器乐段必须分流
- **`lines_data` 行数 = 音频分段数**（`FxAiScreenLoadSimple` 取值是 `行索引 % 总行数`，行数=分段数即**一一对应**）
  → 每个分段都有自己独立的提示词；场景图仍只有 N 张，第 i 行循环引用 `scene_rels[i % N]`。
  **行数不得写成场景数**（那会让「前奏段」也套用演唱段的提示词）。
- **演唱段**：写明「第 X 秒开口演唱、唇形与 `<Audio 1>` 人声精准同步开合」。
- **器乐段（前奏/间奏/尾奏）**：只写**肢体表演 + 随拍律动**，演唱 / 歌声 / 对口型一律由代码的 `_SING_WORDS` 校验拦下并替换成器乐动作库
  （`INSTRUMENTAL_ACTS`：拨叶、闭眼感受风、拾叶、转身、缓步…让画面照样灵动）；
  🔴 动作库不写任何头部动作与眼神描写（无点头、仰头、低头、转头、回眸、目光、眼神），
  也不写「不点头 / 不歪头」这类负向禁令——负向词会把该动作喂给模型。
  音频描述也从「演唱音轨」改成「纯器乐伴奏音轨（没有人声）」。
- **首尾 1 秒安全区**：每个片段的实际生成时长不可能是理想的 9.41667s（音频分段器有过渡帧、尾段另有取舍），
  所以每段**开头 1s 与结尾 1s** 一律写「双唇闭合、安静、不做口型」，中间才是表演区 —— 就算切片漂几秒也不会出现「没声音却在张嘴」。

### ⚠️ 器乐段也要演得丰满

无人声段每拍都要有内容——只写「站着随节拍晃动」画面会呆板。
`INSTRUMENTAL_BEATS` 把器乐段拆成**【起 / 承 / 合】三拍**，每拍都写：
**动作 + 表情 + 神态 + 与环境的互动**（风、光、水、落叶），让 9.4 秒里有层次与情绪变化。
前提不变：**全程闭唇、自然合口、无演唱口型**。

### 审美总要求（每支 MV 的生产目标）
- **赏心悦目**：穿搭、场景、运镜、色调要统一成一套好看的整体，让人看完觉得「漂亮」。
- **场景贴合歌词意境**：每个场景图的内容/氛围要对应歌词写到的画面（如歌词写到的桂花树/老巷/茶桌/旧邮筒/天台/湖畔），不是随便堆景。写 `场景素材.md` 时，逐段对照歌词意象来设计 `img`（纯场景图提示词）与 `act`（人物在该景的动作）。
- **每首歌不同穿搭、不同场景**：穿搭写在该歌 `歌曲.md` 的「## 穿搭」（每歌不同），场景素材写在 `场景素材.md`（每歌不同），参考图只锁面貌——三者配合，保证每支 MV 都有独立辨识度。

### ★ 创作时序铁律

**音乐出来、拿到真实时长、算出 N 之后，才开始写提示词**——不是先写死一堆场景再循环凑数：

```
1) 生成音乐 → 拿到「真实音频时长」
2) 【歌词先行对齐】whisper 出真实时间轴 + 与歌词强制对齐
   → 字幕.srt/.ass（成片直接烧录，只做这一次）+ 歌词时间轴.json
3) H3 精确公式算「分段数」→ 用真实分段时长与字幕时间严格交集
   → 判定每段「有没有人在唱、段内第几秒唱到第几秒」→ 前奏/主歌/副歌/间奏/尾奏
   → 时间规则算出「场景图数 N」
4) 【这时才】逐段写（第 i 条分镜 ↔ 第 i 个音频分段，一一对应）：
   - img : 场景图提示词（只有前 N 条要生图，其余标「复用场景X」）
   - cam / camf / act : 该段的动态与运镜
     演唱段 → 写清切点时刻开口（`At 00:03.500, …`）、唇形同步
     器乐段 → 不演唱、不开口，改肢体表演与随拍律动
     并对照「该段真实唱到的歌词」写 → 落盘 分镜剧本.md
5) 最后才：生成 N 张场景图 → 逐段构建运镜提示词 → 渲染 MV → 烧字幕（复用第 2 步的字幕）
```
- 剧本条数 = **分段数**（不是场景数）；若已有按场景数创作的剧本，会自动备份为 `分镜剧本_按场景N条_备份.md`，并把已创作的 img/cam/camf 继承给对应的场景图，不浪费创作。
- 两段式命令：
  - `python produce_song.py --phase music` → 只出音乐 + 歌词对齐 + 分镜剧本草稿，**停下等逐条创作**；
  - 改完剧本后 `python produce_song.py --phase render` → 出图 + MV + 烧字幕（字幕复用，不重跑 whisper）。
- 常用组合开关：
  - `--reuse-music`：不重新生成音乐（**只要重生成音乐，时长一变段数/景数/剧本条数就全变**，务必复用）。
  - `--mv-only`：不重新生图，复用已生成好的素材只渲 MV（改提示词后重渲用它，省掉 20 分钟生图）。
  - `--mv-segment=<N>`（**0 起索引**）：**只重渲第 N 段**，不重跑整支 MV（哪段不好就只渲那段，省 GPU）。隐含 `--mv-only`，下载该段裸片为 `成片_段N_{W}x{H}.mp4` 并跳过全曲字幕烧录，归位按「模式相关经验 14」拼回。例：重渲故事板第 12 段（索引 11）= `--mv-segment=11`；第 14 段（索引 13）= `--mv-segment=13`。
  - `--regen-subtitle`：人工发现字幕偏移/错字时才加，重跑识别并重合成。
  - 例（改完提示词只重渲）：`--phase render --reuse-music --mv-only`
  - 例（只重渲第 12 段）：`--phase render --reuse-music --mv-segment=11`
- **render 阶段必须复用已有音乐**（不得重新生成）：Yue2 非确定性，一旦时长变了，N 就和已写好的剧本对不上。
- 兜底去重：即使不改剧本直接跑，也有运镜库（12 套）+ 构图修饰（7 种），循环取用时换运镜 + 换构图修饰，`cam`/`img` **条条不重样**。

### ★ 创作类文本一律 `.md`
- 给人看的创作文本**全部用 Markdown**：`歌曲.md`、`分镜剧本.md`、`运镜提示词.md`。
- `分镜剧本.md` 是**唯一创作档**，脚本直接回读解析（`load_storyboard()`），字段不全的条目视为未写完 → 按时间规则重建，半截剧本不静默沿用。
- 过程性临时文件（`_*.log`、`_tmp/` 等）不在此列。

### ★ 成片 / 字幕命名
- `成片_{W}x{H}.mp4` —— **成片带分辨率后缀**（横屏 `成片_1280x768.mp4`、竖屏 `成片_768x1280.mp4`）。
  同一首歌用不同分辨率重跑时不会互相覆盖；不同尺寸的素材（参考图/场景图）本就可能不同，按尺寸规格管理才对。
- `字幕.ass` / `字幕.srt` —— **不带分辨率后缀**，单一文件、跨尺寸复用。
  理由：音频相同 → whisper 识别结果一致，字幕没必要每尺寸重烧。
- MV 分辨率由 `gen_mv(size=(W,H))` 注入到工作流「生成控制器」节点的 `宽度/高度`（**仅内存覆盖，不写回 JSON 模板**）。

## 与 fxai-short-drama 共享的通用规范（同源 H3 经验）

`fxai-short-drama` 是针对"动物/对白短剧"的姊妹技能，以下 H3 经验**同样适用本 MV 技能**，做场景/镜头提示词时一并遵守：
- **场景参与者要动起来**（动态描述）：H3 不会自动给背景编动作，提示词只写静态场景 + 单一主角时，其余人物/动物像贴图。在摘要与详细描述里显式写"其他人在做什么动态事"（走/唱/挥手/互动），详见 `fxai-short-drama` SKILL.md「三之二」。
- **单段/单镜头重生成**：只有某一幕/某分段出问题时，用 `single_shot` / 单分段重提，比整曲重提省时间（H3 合并架构下需手动拼回完整片，详见 `fxai-short-drama` SKILL.md「单镜头重生成」）。

## 生产相关经验

**1. 歌词感知场景图**：场景图提示词必须按对应片段歌词走——有真实歌词→在 img 末尾注入「画面环境呼应此段歌词意境：`<歌词>`，只表现自然/环境意象，保持空镜、不出现人物」；纯器乐/无词段→保持素材池主题自由发挥。**多参考场景图永远空镜**（人物靠 char_rel 在 MV 注入）。代码 `build_storyboard` 自动做，已生成的分镜可用 `_enrich_lyric_scenes.py` 补注入（幂等，只命中真正歌词行）。

**7. 调试纪律**：单一音频上不连续迭代调参；换字幕样式只改 ASS 头（restyle），whisper 沿用已验证的那版结果（识别波动会破坏已验证时间轴）。

**18. 🔴 场景图数量：时间规则只是「下限」，规划场景数优先**：公式只是下限；`场景素材.md` 里实际规划了 N 个场景就**按 N 张生成**，不严格遵循公式。
- **实现**：`produce_song.py` 的 `n_total = max(min_scenes, len(SCENES_SRC))`——`min_scenes` 是时间规则下限（≤120s 每分段一张；>120s 至少 分段数//2+1），`len(SCENES_SRC)` 是 `场景素材.md` 实际写的场景条数；取较大者。
- **取 max 的理由**：公式是地板值，`场景素材.md` 规划的场景本就想全用上；若被压到下限，分镜 `scene_ref` 是按 `%(n_total)` 铺的，少生成＝那几张图根本不进 MV。
- **配套：分镜 `scene_ref` 必须按当前 n_total 重算**：改 n_total 后要整份重铺，只补生差的那几张会漏——旧 `分镜剧本.md` 的 `scene_ref` 是按旧数量铺的（如 `%(11)`），会漏掉新场景。做法：重跑 `--phase music`（复用音乐+字幕、只重算分镜）让 `build_storyboard` 用新 n_total 重铺 scene_ref 1…N，再 `--phase render --reuse-music`。
- **⚠️ `--reuse-music` 必带**：`--phase music` 不带 `--reuse-music` 会**重新生成音乐**（Yue2 每次随机、时长不同），连带字幕/分镜全重对齐；中途改场景数这类「只想调画面」的操作，music 阶段必须 `--reuse-music`（或确认接受新音频）再 render，否则音乐又被换一版。
