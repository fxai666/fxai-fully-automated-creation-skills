# 03 · 分段与字幕（音频分段公式 · 人声判定 · 歌词对齐 · 烧录）

> 何时读：处理音乐时长、人声判定、歌词对齐、whisper、字幕时间轴、烧录。

## ★★★ 音频分段「精确公式」——MiniMax / H3 的 17k+5 网格

**公式本体在公共件 `fxai-audio-video/audio_video.py`（MV / 数字人口播 / 短剧共用同一份）**：

```python
import audio_video as av
secs, bounds = av.h3_segments(歌曲时长)   # 每段秒数 + 每段 (start, end)
n         = av.h3_segment_count(歌曲时长) # 只要段数
```

`produce_song.py` 里的 `h3_align_down` / `h3_segments` / `h3_segment_count` 是转发封装，行为一致。

**为什么必须按这个算**：MiniMax（H3）只接受满足「**17k+5 帧**」的时长（`H3_FPS = 24`）。
工作流里传 `平均分段时长 = 10`，服务端并不是真的切 10 秒——它先**向下对齐**到网格：

```
h3_align_down(frames) = 17 * ((frames - 5) // 17) + 5   # 最大的 17k+5 ≤ frames
frames_per_seg = h3_align_down(round(10 * 24)) = h3_align_down(240) = 226
实际每段 = 226 / 24 = 9.41667 s   ← 这就是「传 10 秒、实际 9.4 秒多点」
```

完整分段（与 `FxAiAudioSegmenterV2.select_segment(目标模型="MiniMax")` 逐行同构）：

```
total_frames   = round(音频总时长 * 24)
frames_per_seg = h3_align_down(round(平均分段时长 * 24))   # 平均分段时长=0 时取 226
num_full = total_frames // frames_per_seg
tail     = total_frames - num_full * frames_per_seg
min_thr  = int((5.0 if 平均分段时长 > 10.0 else 3.0) * 24)  # 10s 分段 → 3s → 72 帧
if 0 < tail < min_thr and num_full > 0:   # 尾段太短 → 并回上一段
    num_full -= 1
    tail += frames_per_seg
分段数 = num_full + (1 if tail > 0 else 0)
```

**⚠️ 勿用 `ceil(时长 / 10)` 估算**——两者经常差 1 段（120 秒：公式 13 段、`ceil` 给 12），
场景数、时间窗、歌词对位会全错。
- 实现：公共件 `fxai-audio-video/audio_video.py` 的 `h3_align_down()` / `h3_segments()` / `h3_segment_count()`；`produce_song.py` 转发封装（**只读参考，ComfyUI 节点源码 `<某ComfyUI本机路径>/custom_nodes/fxai-toolkit/fxai_audio_segments_v2.py` 保持原样**）。
- 分镜剧本的时间窗也用它：分镜 i 的窗口 = **第 i 个音频分段**的真实 `[start, end)`，取代 `时长/N` 均分；并记录 `覆盖分段`（i、i+N、i+2N…）供创作时参考。

## ⚠️ 人声判定：必须用 whisper 原始时间轴

**判定"这段有没有人在唱"，用 whisper 原始段做交集，歌词强制对齐结果只作参考不作依据。**

（唱歌识别错字极多，字幕脚本 `gen_lyric_subtitle._filter_hallucination` 的「与全部歌词相似度 <0.18 就丢」规则会把真歌词段当幻觉删掉，导致时间轴漂移。）实现在 `lyrics_align.py`：
1. `filter_vocal_segments()`：只丢**真幻觉**——台标/署名关键词（`詞曲|李宗盛|独播剧场|Television…`）、≤2 字、超出音频时长、**重复 ≥3 次且 sim<0.35**。
   ⚠️ 重复次数**必须配相似度条件**：副歌重复是正常演唱（`把心事交给远去的帆和郎`唱 4 次，sim=0.909），只按重复数删会把真演唱删掉。
2. `classify_segments(vocal_spans=...)`：段内人声窗口 = whisper 段 ∩ 分段，输出**相对该段起点**的秒。
3. `align_lyrics_monotonic()`：歌词↔段映射用 **DP（相似度 + 时长约束 + 单调）**；高相似度句（副歌）精确锁定，错字多的句子靠「该行时长 ≈ 按字数应得时长」兜底。纯字数比例会累积错位，弃用。
4. `write_subtitles()` 自己写 `字幕.srt/.ass`，覆盖共享脚本的错位结果。

判定规则（`lyrics_align.classify_segments`）：
- 分段与「歌词区间并集」的重叠占比 **≥ 0.15** → **演唱段**（type 取歌词里的 `[主歌]/[副歌]/[桥段]` 标记，英文标记自动转中文）；
- 否则 → **无人声段**：第一个演唱段之前 = 前奏，最后一个之后 = 尾奏，中间 = 间奏；
- `vocal_windows` = 段内相对秒的人声窗口 → 转成切点写进提示词：首档不写时刻，其后每档 `At 00:03.500, …`。

## ⚠️ VAD 段内能量交叉验证（音频静音片 ↔ 识别结果 多方验证）

人声判定要两方交叉：单看 whisper 会漏——它会把片尾署名（字幕志愿者/独播剧场/请不吝点赞）幻觉到前奏区，生成「伪人声窗」，使前奏被误判成有人声。`lyrics_align.py` 用「音频参考 + 识别参考」两方交叉兜底（零依赖：标准库 wave+array，numpy 优先加速）：
1. **逐段判断**：用 H3 精确分段 `bounds` 对 `人声.wav`（去噪纯人声）逐段算段内 RMS 能量，与「全曲被标有人声段的 RMS 均值（演唱基准 ref）」比较——**不是全局阈值**。前奏/尾奏的器乐残留（远低于 ref）判静音、真唱（≈ref）判有声；短的/弱的残留被段级 RMS 聚合自然消化，算静音。
2. **与文本识别交叉**：`classify_segments` 按 whisper 窗判段内有无演唱；`cross_validate_segments_with_vad(seg_info, 人声.wav, auto_fix=True)` 用段内能量复核——段标「有人声」但段内 RMS<ref×10% 且段长>4s → **自动降级为无人声**（从根上防住伪人声窗）；<ref×30% → 警告；段标「无人声」但 RMS>ref×50% → 警告（可能漏判）。
3. **句级交叉**：`verify_alignment(..., vad_wav=人声.wav)` 某句时间窗内段内能量<ref×20% → ERROR。

触发：`produce_song --phase music`（align 分支）与 `lyrics_align.py --mode verify` 自动跑；
`_vocal_vad.json`（VAD 报告）落盘备查，旧 `_vocal_spans.json`（whisper 原始窗）仍保留。

## ★★★ 歌词先行对齐（Lyric-First）：音乐一出来就 whisper 对齐

**为什么**：过去分镜靠「歌词大概唱到哪」估算 → ① 前奏/间奏（纯器乐）也被写成「演唱、对口型」，人物嘴巴跟着音乐乱动、穿帮；② 场景意境与实际唱词错位（以为唱 A 句其实在唱 B 句）。

**做法**：音乐生成后**先做人声分离 + 神经网络去噪**，再跑 whisper，拿真实时间轴并与我们的歌词强制对齐，再用**真实分段时长**与字幕时间做**严格交集**：

```
音乐.wav --服务端模型工作流--> 人声 --ffmpeg arnndn(RNNoise)--> 去噪人声
    --whisper--> 分段文本 --强制对齐--> 每句歌词的真实起止秒
    → 字幕.srt / 字幕.ass （最终烧录用）
    → 歌词时间轴.json （分段表：段落类型 + 段内人声窗口 + 命中歌词）
```

**★ 识别前必须先把人声弄干净（管线步骤 1.4/6）**：
- 链路：`separate_vocals()` 分离 → 下载 `人声.wav` → `denoise_audio()` 用 ffmpeg `arnndn`（RNNoise）去噪 → 喂给 `run_align`。去噪后开唱起点不会被前奏器乐误判成人声。
- 产物落在歌曲目录 `_人声.wav` / `_人声_去噪.wav`（`_` 开头 = 中间件，收尾自动清理）。**时间轴不受影响**：去噪不改变时长。
- 开关：`fxai_global.json` 的 `vocal_separation`（默认 **true**）。技能未装 / ComfyUI 离线 / 分离失败时**自动回退用原音乐**，不阻断主流程。

**★ 字幕只识别一次**：成片阶段直接烧录这里的 `字幕.ass`，**whisper 只跑一次**（音频没变，时间戳必然一致）。
只有人工检查发现字幕偏移/错字时，才加 `--regen-subtitle` 重跑识别并重合成。
实现：`lyrics_align.py`（`run_align` / `classify_segments` / `write_timeline` / `burn_subtitle`）。

### ★ 对齐算法铁律
- whisper 识别错字极多（"雾从林梢醒"→"武松林 烧信"）属正常，**时间刻度才是真值**：对齐只看「哪段在唱 + 唱了多久」，文字换成我们的正确歌词。
- **副歌重复句按演唱处理**："把心事交给远去的帆和浪" 在副歌会被唱 4 次（whisper 识别 4 段），`filter_vocal_segments` 只在「重复≥3 次 **且** 与任何歌词相似度<0.35」时才丢；带相似度条件是关键，缺了这条真演唱会被删 → 时间轴整体漂移。
- **逐段对齐前先合并相邻相似段**（`_merge_repeated_segs`，sim≥0.72）：副歌重复演唱同一句会产生多余段，不合并会把多余段错误塞进相邻歌词行，第 6/14 这类句时间窗即漂移。
- 主对齐用**「相似度 + 时长约束」单调 DP**：识别准的句子（副歌）精确锁定，错字多的句子靠「该行时长≈按字数应得时长」兜底，严格单调不回退；DP 失败才 fallback 到「按字数比例吸附段边界」。
- 新歌务必做**逐句相似度自检**：把每句对齐窗口内的 whisper 文本与歌词比 sim，低相似若因错字但时间窗真实则 OK；若窗口内是**上一句/下一句内容**（sim≈0）即判定错位，必须修对齐再烧录。

### ★ 通用自检 `verify_alignment` + 多版交叉 `cross_check_whisper`
- `run_align` 默认自动跑 `verify_alignment` 逐条核对（零长度窗口 / 空识别漏识 / 内容相对时间段过长即密度异常 / 副歌重复漂移即窗内是邻句内容 / 相邻重叠 / 间隙含人声断裂）。无错=PASS，有错=报错，全部落 `_align_verify.json`。
- 难对齐的歌可 `--multi-pass 3` 让 whisper 再跑几版（预设：词级·硬切9s / 词级·硬切11s / 词级·beam3·无上文 + 1 版句级 sanity check），`cross_check_whisper` 比各版人声窗一致度；**低一致区标红人工复核**。注：这是**可选仲裁**，主链路默认只跑 9s/11s 两版（见下）。
- **词级一致度必须带容忍带算**（`_WORD_TOL=0.75s`）：whisper 词级时间戳各版天然有 ±0.3~0.7s 边界抖动，严格逐 0.5s 网格比较会把纯抖动全算成不一致；MV 用途 ±1s 无感，容忍带口径才合理。词级共识窗用**多数票**（不是全交集），单版漏词不会把窗打碎；剩余分歧集中在「前奏→第一句开唱」边界。
- **★★ 演唱顺序 ≠ 纸面歌词顺序**：AI 生成歌曲会压缩、跳句、加衬词（"呀""不是我…"）、和声串词，纸面顺序对齐会把某行硬塞进前面的时间、之后全部错位。**做法：两版不同分段的 whisper 各自顺序对齐 + 行级表决**，两版都同意的行才可信，分歧行报告点名（见下「双分段双版」）。
- **人工钉定 `_line_pins.json`**（项目目录，{"行号":[start,end]}）：和声串词区两引擎打架、DP 不敢认的句子，听歌后手工钉定（run_align 自动合并进时间轴）。
- **字幕配色预设 `STYLE_PRESETS`**（`ass_header(w,h,style=...)`，run_align/style 透传）：white 经典白 / cream 奶油暖黄 / mint 薄荷青 / gold 香槟金 / sakura 樱粉 / ice 冰蓝；微软雅黑加粗+柔投影+字距0.8+淡入淡出；横屏字号大一档（短边 0.050 vs 0.042）。
- **质量指标看「词级两版一致度」**（`cross_check_whisper` 的 word_agreement，带 `_WORD_TOL=0.75s` 容忍带算）：一致度高=时间轴稳；剩余分歧集中在「前奏→第一句开唱」边界，属正常。
- **词级窗精修**：句级 whisper 容易把「器乐间奏 + 下一句演唱」合并成一长段。`multi_pass` 启用时，自动用词级人声窗裁剪/前移句级窗口，让时间轴更贴近真实演唱。
- 命令行：
  - 跑对齐+自检：`python lyrics_align.py --audio 音乐.wav --lyrics 歌词.txt --out-dir <项目> --multi-pass 2`
  - ⚠️ **CLI（`main`）不传 `video_size`**，ASS 会落到默认横屏 `1280x768`——**竖屏歌曲照此 CLI 跑会 PlayRes 错、烧录错位**。竖屏（如 `768x1280`）必须**直接调 `run_align(audio, lyrics, out_dir, video_size=(W,H))`**（`produce_song.py` 已按 MV 尺寸传入）；只有横屏 `1280x768` 才能直接用 CLI。
  - **只自检已有项目（不重跑 whisper、不重新生成视频）**：`python lyrics_align.py --mode verify --out-dir <项目> [--audio 音乐.wav --multi-pass 2]`
- 产物：`_align_verify.json`（自检报告）、`_xcheck.json`（多版交叉报告）、`_vocal_spans.json`（最终采用的人声窗）。

### ★ whisper 双分段双版对齐
- 用**同一模型、不同分段长度**跑多版 whisper 词级（默认 9s / 11s / 13s，切点间距 2s 增强边界容错，常量 `DEFAULT_SEG_LENS`）。分段是**硬切**（接口参数 `clip_seg` → faster-whisper `clip_timestamps`），**不是 VAD**。切点不同 → 边界效应/漏词的暴露点不同，各版互为校验。多版统一用 `transcribe_passes`：**音频只上传一次**，服务端连跑。
- ⚠️ **硬切必须关 `condition_on_previous_text`**：cond 开时上一片段的幻觉文本会成为下一片段的提示、自我强化成幻觉链（同一音频 cond 开＝162 词 / 幻觉字占比 **48.8%**，cond 关＝256 词 / **8.5%**）。接口传 `condition=False`。
- ⚠️ **幻觉过滤必须词级连字剔除**（`_strip_halluc_words`）：whisper 幻觉常被拆成单字词（中/文/字/幕/志/愿/者/李/宗/盛），逐词匹配抓不到；若直接让「短语含关键词就丢整条」跑，会把同短语里的真唱词一起删掉。先摘幻觉**词**，再拼短语、再跑短语级保守过滤。
- ⚠️ **VAD 分段对歌曲无效**：silero 把歌切成 <9s 的短块，`max_speech_duration_s=9/10` 不触发 → 两版转写 md5 相同；开 VAD 还会丢真唱。所以 `--max-speech` 保留但**勿用**，分段一律走 `--clip-seg`。
- 每版链路（勿省步）：词 → 短语（gap 0.6s 合并）→ **短语级幻觉过滤**（台标/署名/≤2字/重复且不像歌词）→ 两阶段顺序对齐 `_align_lines_words`（行→短语单调分配 DP + 短语内按字数权重切词，短语内全是唱词时间所以切分可靠）→ 歌词文字一律换成正确歌词。**两版都不做「用模型文字决定唱的是哪句」**，只比时间刻度。
- **行级表决 `merge_line_passes`（通用，与歌无关）**：两版**起点和终点都**落在容忍带 ≤1.5s 内 → 取中位数（`_src=both`，高可信）；否则视为分歧，取「窗内识别文本与本行歌词最像」的版本（`_src=conflict`，报告点名建议人工复核）。★ **终点必须一起判**：只比起点会把某版明显过长的行（把下一句的时间也吞进来）误判成「一致」，结果整段歌词各晚数秒、末句被挤没；终点不一致就按窗内文本择版（`_sim_chars` 是 SequenceMatcher 比值，过长的窗天然被惩罚）。只有一版有 → 采用（另一版多半漏识，`_src=single`）；两版都没有 → 该行不上屏并在报告点名。
- 报告 `_align_report.json`：both/single/conflict 计数 + 分歧行逐条候选 + 未匹配行号；两版原始转写 `_transcript_9s.txt`/`_transcript_11s.txt`（`_transcript.txt` = 主版 9s 的副本，供下游/复跑复用）。
- 重叠行去重 `_dedupe_overlaps`：两版合并后相邻行重叠时**按中点切开保留两句**（过短才丢）——整句丢弃会让歌词凭空消失。人工钉定 `_apply_pins` 为最后一步：覆盖同号行，并**裁剪**与钉定窗冲突的邻行（裁完 <0.4s 才丢），使字幕两行压在一起的情况消失。
- ★ **未认领短语回收 `_absorb_orphan_phrases`**：`_align_lines_words` 的 DP 让每行只绑**一个**短语，但一行歌词常被唱成两截（中间换气 >0.6s 就被切成两个短语）→ 后半截短语无人认领，**字幕留白而歌声还在继续**。规则：凡无任何行覆盖的高置信短语（非幻觉、时长 ≥0.4s），若与某行间隙 ≤2.5s 就并入间隙最小的那行（尾接延 end / 头接提前 start），并夹住邻行边界使前后行不重叠。⚠ **文本相似度门槛一律不加**——whisper 唱中文歌常输出繁体（爭/響/樣），与简体歌词逐字比对相似度极低，加了门槛会把该补的真唱又挡回去。
- 词级直接喂 DP 是**错误做法**（唱歌文本相似度被逐字稀释 → 整段漂移、单句被压成 0.4s）；短语内切分才是稳的。
- 硬约束 `_clamp_items`：时间轴一律钳制在音频时长内；自检把「超出音频时长」列为错误。
- ★ 换字幕样式只改 ASS 头（restyle），**whisper 沿用已验证的那一版时间轴**：识别有随机波动，重跑会把已验证的时间轴打乱。

### ★ 字幕输出三条硬规则
1. **ASS 的 `PlayResX/Y` 必须 = 视频真实分辨率**（横屏 `1280x768`、竖屏 `768x1280`），写死任一值都会让 libass 按错误画布算坐标 → 字幕位置与字号全错。`ass_header(w,h)` 按视频尺寸生成，字号 ∝ 短边、MarginV ∝ 高；`run_align(video_size=(MV_W, MV_H))` 一路传下去。
2. **超长句切两拍**：单句 > 10.5s 按空格（最靠近中点）或字数中点拆成两条、按字数加权分时长，解决「一行字幕挂 13~14 秒」（拖腔长句常见）。歌词文本不变，只是分两行显示。
3. **起唱前窗口必须跳过零长情形**：人声从段首就起唱时跳过「起唱前」这一拍，输出里只留正长窗口（不产生 `1.00s–1.00s`）。

## 字幕规范（生成期抑制 + 后期 whisper 真实时间轴 + 正确歌词替换）

MV 字幕采用与 `fxai-short-drama` 一致的稳定方案：**生成阶段画面上不出字幕，字幕条全部后期叠加**；后期字幕的**时间轴来自 whisper 真实时间戳，文字一律用正确歌词替换**（ASR 识别文字只作时间参考）。`produce_song_full.py` 第 6 步已串好这条流水线，新项目直接复用即可。

### 一、生成阶段：抑制画面字幕
- MiniMax H3 有时会在画面里自己画出字幕/歌词，且不准（同音错字、乱码）。MV 是**音频参考**模式，歌词靠音频对齐驱动，**提示词里只写画面与动作，不写"画面显示字幕/歌词"这类要求**。
- 若需显式抑制，可在每条镜头提示词末尾追加 `negative_constraints` 段（写法见 `fxai-short-drama` SKILL.md「二、生成阶段抑制画面字幕」），抑制范围写成"自动对白/歌词字幕条 + 乱码文字"，**有意文字要保留**（片尾 slogan、招牌、横幅等），把"任何可见文字"一刀切掉会误伤这些。

### 二、后期字幕：whisper 只取时间，文字用正确歌词
- 抽音轨 → 用 `fxai-lyric-subtitle` 技能（`scripts/gen_lyric_subtitle.py`）跑 whisper：**推荐词级**（`write_transcript(audio, out, words=True, vad=True)`，全走 whisper 服务接口；词级比句级更准，能把每句字幕卡到"第一个字出口"的时刻，消除句间静音带来的字幕提前）。MV 唱歌常有长静音/间奏，句级边界会把静音算进区间、让字幕提前冒出，故**优先词级**。
- whisper 对**唱歌**识别常错（同音字），且**时间轴才是它最有价值的部分**。因此：
  - **时间轴**：采用 whisper 的 `[start->end]`（词级则取该句首词开始/末词结束）；
  - **文字**：用我们的**正确歌词**按行序一一替换 ASR 文本（`gen_lyric_subtitle.py --lyrics 歌词.txt` 即此逻辑）。
- 丢弃前奏/间奏无词段（whisper 会幻觉成"作曲 XXX"之类），只保留有词段。
- ⚠️ **确定性时间轴漂移陷阱**：H3 系统生成语音/歌声实际起音、句间停顿 ≠ 提示词声明的时间轴，越往后累积延迟越大 → 若按"提示词 0–3s/3–6s 硬排"字幕会越往后越提前。**一律改用 whisper 真实时间轴对齐（优先词级）**（详见 `fxai-short-drama` SKILL.md「四、字幕规范·确定性时间轴的漂移陷阱」）。

### 三、烧录
- 用本机带 libass 的 ffmpeg（凤希AI伴侣自带）：`ffmpeg -i in.mp4 -vf "subtitles=filename=xxx.ass" -c:a copy out_sub.mp4`（`cwd` 切到字幕同目录；ASS 用 UTF-8 无 BOM；字体 `Microsoft YaHei`）。
- 中文渲染异常（豆腐块）= ffmpeg 缺 libass，换伴侣自带的带 libass ffmpeg（详见 `fxai-lyric-subtitle` SKILL.md「前置与关键坑」）。

> **跨技能复用脚本**：`fxai-short-drama/gen_subtitle_aligned.py` 是"whisper 只取时间 + 正确文本替换"的纯函数实现（歌词/台词通用），音乐/MV/短剧都能用；MV 本项目走 `fxai-lyric-subtitle` 的 `gen_lyric_subtitle.py --lyrics`。

## 配套能力
- **H3 视频提示词写作** → 技能 `fxai-h3-video-prompt`（`<技能目录>\fxai-h3-video-prompt`）：我们三个 MV 工作流**全部带音频参考**，所以只用到两条 H3 分支——
  - 单场景 / 多场景 = **FL2VA（首尾帧）+ 音频参考**，提示词由工作流默认内置、保持默认；
  - 多参考 = **Ref2VA（全参考）+ 音频参考**，`gen_mv("multiref", ..., char_desc=..., scene_desc=...)` 会把 `1039` 节点的 `lines_data` 按 H3 六段式规范重建（音频固定为「原音频 / fully_copy」，不另行设计音轨）。需要对 H3 做更精细的镜头/运镜/动作/VFX 控制时查它。

## 字幕相关经验

**16. 🔴 字幕两坑：①器乐占位符上屏 ②时间轴漂移**：用户看成片发现「开头显示了乐器那个玩意儿」+「45 秒附近字幕没对上、该出的没出」。拆开是两件事，**根因不同、修法不同**：
- **坑① 器乐占位符被烧进成片**：`歌曲.md` 歌词里的 `[前奏]/[尾奏]` 标记会被 `build_storyboard` 落成「（器乐，无词）」「（器乐渐弱，风声与鸟鸣）」之类的占位文本（这些文本不是歌词），会被 `write_subtitles()` 当普通歌词原样上屏 → 开头/结尾烧出一行「乐器那个玩意儿」。`_is_inst_placeholder(txt)`（齐括号包裹 + 含「器乐/无词/间奏/渐弱/风声/纯音乐/music」才算占位，正常带括号歌词如「哈哈（开心）」照常上屏）在 `write_subtitles()` 入口 `continue` 跳过。
- **坑② 时间轴漂移（非缺字/错字）**：字幕文字对得上、时间却偏（屏上还在唱 A 句、字幕已切走）→ 判时间轴错位，不是词错了。修法：对全曲跑 whisper **逐词时间戳**（`full_words.txt`），与现字幕逐句 `difflib` 强制对齐比对，漂移 **> ±1.2s** 的句才修（±1.2s 内视为正常对齐误差，不碰）；用逐词硬证据重算每句真实起止，重写 `字幕.srt / 字幕.ass / 歌词时间轴.json`，再从**干净无字幕的 `合并_{W}x{H}.mp4`** 重烧 `成片_{W}x{H}.mp4`。
- **诊断铁律**：① 缺字/错字 vs 时间错位要分开判断——先看 whisper 逐词证据，**词对得上只是时间偏**就只调时间轴、whisper 沿用原结果（见调试纪律：重跑识别有波动会破坏已验证时间轴）；② 换字幕样式只改 ASS 头（restyle），whisper 沿用原结果。③ 模型看不到图，时间轴对不对**必须靠逐词时间戳硬证据**判定，抽帧目测只能确认「这句内容有没有出现」，确认不了精确时间。

**17. 🔴 字幕校正：三版硬切 + 多数簇表决**：三版间距恒为 **Δ=2s**（`DEFAULT_SEG_LENS=(9.0,11.0,13.0)`），这是唯一跨歌「全零错误 + 零丢行」且平均 conflict 最低的配置——Δ=3 必丢行/报错，Δ=4 在部分歌上反而最差。
- **配置**：`lyrics_align.py` 的 `whisper_word_passes` 按各 seg 自动跑一版（每版 `clip_timestamps` 硬切、关 `condition`、连字幻觉剔除）。
- **核心算法 `merge_line_passes` 为「多数簇表决」**（新增 `_largest_cluster`，N≤3 精确）：各候选版本两两比「起点&终点都 ≤`_LINE_TOL`(1.5s)」→ 取最大一致簇、簇内取中位数；
- **2 版一致 + 1 版离群 = `majority`**：取那 2 版的中位（离群版不参与取值）——这是三版相比两版的关键收益；
- 全一致 = `all`；全不接近 = `conflict`（取「窗内识别文本与本行歌词最像」的版本，主版同分优先）；仅 1 版有 = `single`；都无→不上屏并点名。
- ⚠️ 标签语义：`all`=**全部 N 版**都成簇（3/3）；`majority`=成簇数 ≥2 但 <N（`len(cluster)==len(passes)`）。
- **多数票的作用**：单版在某切点的边界误判（把整段误判成间奏→时间压缩→下游漂移）会被「多数票」中和——2 版同意即高可信，无需第 3 版也同意。
- **验证**：合成单测覆盖 all/majority/single/conflict + `_largest_cluster` 五例全 PASS；真实轻量跑某首歌前 25s 三版均正常产出转录、幻觉连字剔除(15/7/5 词)、合并出 35 句共识、无崩溃。报告键 `all/majority/single/conflict`，落 `_align_report.json`。
- **cross_check 预设**同步为 `词级·硬切9s/11s/13s`，与主链路三版硬切一致（另保留 beam3/句级 差异版扩搜）。
