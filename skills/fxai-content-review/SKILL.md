# fxai-content-review

SQLite 是唯一真相源，`经验库.md` 是它的只读投影。做：诊断落库、累加次数标顽疾、登记素材台账与标签、从复盘长出缺口。

## 本技能文件清单（先读这里，再决定读哪几册）

| 文件 | 什么时候读 |
|---|---|
| `SKILL.md` | 本文件：铁律/领域隔离/沉淀通路/复盘流程 |
| `references/判据表.md` | 做两层诊断时（五维度判据 + 复盘六步） |
| `references/计数口径与台账字段.md` | 入库前对指纹、受控词表、台账字段与硬约束 |
| `references/命令与导出格式.md` | 敲命令、导出经验库、确认消费侧 |
| `scripts/db.py` | 台账后端（SQLite），按命令用，无需通读 |
| `已沉淀规则.md` | exp promote 写 |
| `经验库_{领域}.md` | 导出到 {data_dir} |

**确定本次要做什么之后，只读对应的那一两册，其余一律不读。**

## 铁律（不看分册也要守）

1. **数据只用用户给的**：缺的字段标"未提供"并回问缺哪个。
2. **结论必须落到"下次具体怎么做"**；只指毛病不给动作的不入库。
3. **只基于内容本身**，不套"爆款模板""一般规律"；判断能指到具体某句。
4. **标签先在受控词表登记**（代码强制，写不进未登记标签）；**一条经验只属于一个领域**：跨岗位通用的才用「通用」，否则落到具体岗位（混算污染计数）。

## 领域（岗位）隔离

领域即岗位，取值受控（见参数），各对一个岗位技能（见消费侧）。`指纹 = 领域|分类|关键词`，**只在本领域内计数**（文章与口播的"开头没给利益"各算各的）。导出按领域拆成 `经验库_文章.md` 等，**岗位技能只读自己那份**；查素材自动带「通用」。

## 经验 → 规则（沉淀通路）

`exp add` 记一笔 → 反复命中变顽疾 → `exp promote` 升规则 → 写进对应技能。`exp pending` 列出**该沉淀还没沉淀**的（命中 ≥2+已确认+未晋升）；`exp promote --id N` 把条目（规则/反例/落点技能）追加进 `已沉淀规则.md`（落点看 `SCOPE_SKILL`）。

## 复盘流程

1. **对齐内容**：确认**领域**（哪个岗位）/ 标题/主题/类型（人设型·信任型·变现型）/ 文案原文；**领域问出来才入库**（落错污染该岗位计数）。
2. **两层诊断**。内容层（零外部数据，现在就能做），每条能指到具体哪一句，五个维度：开头钩子（第 1 句靠悬念/冲突/利益/反差/共鸣留人，够不够利）、中间结构（推进顺不顺、哪里讲糊涂）、卖点呈现（卖点用哪几句说的、击不击中人）、结尾引导（引导什么、自然不自然）、口播可读性（句子长短、顺口吗）。数据层给了播放/完播/互动/转化才分析，**没给就列出要导字段**。
3. **一条一入库**：每问题单独成条，带全 `分类+关键词+结论+证据+下次动作`；分类从受控表选（选错被拒）。`指纹 = 分类|关键词`，命中已有条目**计数 +1**不新增；满 2 次即顽疾。
4. **登记素材缺口**：发现"这类内容缺素材"就记进缺口表（不建空目录），积累后按表补。
5. **导出**：`exp export` 按领域生成 `经验库_{领域}.md`。
6. **沉淀（可选）**：命中 ≥2 且已确认的经验跑 `exp promote` 升规则写进技能。

## 硬约束

1. **只登记本地最终产物**：ComfyUI 服务端的参考图、四视图、中间帧属生产过程，不入库。
2. **只存路径不存文件本体**：本地文件不存在则 `verified=0`，仍可入库但复用前复查；传未登记标签会报错（先 `tag add`）。
3. **经验去重靠指纹不靠语义相似度**：算同类用同一 `领域|分类|关键词`。
4. **库目录解析顺序**：`FXAI_DATA_DIR` > `fxai_global.json.data_dir` > `工作目录/_fxai_data`。
5. `经验库_{领域}.md` 是导出产物**只读**。

## 消费侧

开工前只读**自己领域**那份，把"下次动作"带进本轮：`fxai-weixin-gzh-publisher`→`{data_dir}/经验库_文章.md`、`fxai-voiceover-script`→`经验库_口播.md`、`fxai-video-editing`→`经验库_视频.md`、`fxai-scene-gen`→`经验库_素材.md`、`fxai-novel-writing`→`{data_dir}/经验库_小说.md`（番茄驳回原因、章节完读、签约评估不通过的理由都记这个领域）。
