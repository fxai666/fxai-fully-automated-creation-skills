# 03 · 参数与调用

> **何时读**：程序化调用、多段顺序、接视频下游、处理 wav 格式时。

## CLI 参数

`python voice_gen.py --help` 查全部。

## 多段顺序

串行提交一个一个来，文件名零填充序号；交付认序号不认接口返回先后。
输出已存在默认复用，哪段失败单独重跑那一段。

## 程序化调用

```python
import tts_client as tc          # 同目录 import 即可
meta = tc.synthesize(
    text="用四川话自然口语的语气说<|endofprompt|>。大家好，今天这期讲三件事。",  # 标签+正文一起送
    ref_audio="voices/ref.wav",
    mode="cross_lingual",
    speed=1.0,
    out_path="<输出目录>/01.wav")
# meta = {ok, path, duration, sample_rate, mode, speed, url, text}
```

接口回的是 IEEE float（fmt=3）wav，标准库 `wave` 读不了；用模块内 `_parse_wav` / `_write_wav`，
拼接用 `join_wavs`。

## 语速（speed）

`speed` 是**浮点参数，取值自由**，按优先级取：

1. `--speed <浮点>`（命令行最高优先，覆盖其余）
2. 音色库条目的 `speed` 字段（`tts.speakers[].speed`）
3. 全局配置 `tts.default_speed`（缺省 `1.0`）

`1.0` = 模型原生节奏，**完全不处理**（本地引擎也不写标记）。跨引擎安全范围 `0.5~2.0`
（CosyVoice3 接口限制 `ge=0.5, le=2.0`）；本地 ffmpeg 引擎超出范围会自动串联 `atempo`，仍精确生效。

语速由谁做按引擎定，读 `tts.engines.<名>.speed_mode`（`tts_client.engine_speed_mode()`）：

| speed_mode | 引擎 | 谁做 | 客户端行为 |
|---|---|---|---|
| `server` | CosyVoice3 | 模型管线内部（`CosyVoice3Model.token2wav()` 对 mel 做 `F.interpolate(mode='linear')`，再进 HiFT 声码器） | `speed` 原样透传，不碰波形 |
| `local` | 千问 Qwen3-TTS | 客户端 | 向服务端只送 `speed=1.0`（要模型原生节奏），拿到音频后 `apply_speed_local()` 用 ffmpeg `atempo` 原地变速 |

千问的 `generate_voice_clone` / `generate_custom_voice` **没有语速入口**，服务端也**不做**变速（收到即忽略），
所以只能在客户端补。变速后会写 `<名>.wav.speed` 标记（记生效语速）；`applied_speed()` 读它，
复用判定要连语速一起核 —— 改了语速就得重合成。

⛔ 本地变速**只用 ffmpeg `atempo`**。librosa `time_stretch` 是波形域相位声码器，会在每个音节后留拖尾（回音）。

## 配套视频生成

音频出来后接 `fxai-digital-human-video`：

```bash
python dh_video.py --project <项目名> --script <项目名>/口播文案_标签.md --concat
```

单条音频也能直接喂：`--audio 任意.wav`。
