# 02 · 扩展解析

> **何时读**：理解通用解析路径、追加专用解析器、写解析契约、扩展路由时。

## 抽象层级（新增能力前先读）

本技能描述的是**步骤**，不是**站点**。判断一个页面能否取出素材，只问「网页要把媒体交给浏览器，必然经过哪些动作」，不问「这是哪个站、它的接口长什么样」。

| 层次 | 描述对象 | 本包里的形态 |
|------|----------|--------------|
| 能力层 | 一次采集必然经过的步骤 | 预热会话 → 重取页面 → 扫描响应 → 派生候选 → 排序下载 → 校验落地 |
| 实例层 | 某类响应里地址长什么样 | 通用特征：扩展名、路径词、内嵌 JSON 字段、水印标记、清晰度参数 |

站点差异只落在实例层，且一律用通用特征吸收，不按名称分支。代码与文档都不描述具体站点，因此同一套步骤对任何链接成立：链接本身就是全部输入，域名、落地页、Referer、素材 ID 全由它推导。

**成立前提**：媒体地址出现在首次 HTTP 响应中且可被枚举。掉出这个前提的形态：

| 形态 | 破法（补能力，不改路径） |
|------|--------------------------|
| 地址由客户端签名接口动态取回 | 注入会话后重放取数请求，或转外部下载器 |
| 分片流 / 加密流 | 取清单并合并，或转外部下载器 |
| 需登录、需交互校验 | 注入 cookie / 换出口，再走同一步骤 |

新增解析器 = 在这条路径的某一步换实现，不是为某个站另写一条路径。步骤顺序、素材落点、验收判据在任何解析器下不变。

## 使用层全局配置（技能包外）

技能包只提供「查档 → 复用 → 首次分析 → 回写」这套机制，不内置任何站点记录。
站点专属的有效链路在**运行时**沉淀到用户级配置目录，跨项目复用，省去重复的链路分析。

**技能包与发布包只提供通用能力，不预置任何具体站点、域名或专属链路**：分册由使用者本机运行时生成，
只存用户级目录；`sites/`、域名式分册、`CONFIG.md` 默认不进发布包，带分册参数块的文本命中即拒绝出包。

| 项 | 判据 |
|----|------|
| 唯一根 | 固定用户级 `~/.workbuddy/fxai-material-collect/`；`CONFIG.md` 总纲 + `sites/` 分册；换工作目录依旧命中同一份档 |
| 分册 | 每站一份 Markdown；头部 `---` 参数块供脚本直读，正文为有效链路 / 产物基线 / 人工笔记 |
| 入口别名 | 短链等入口只写 `alias` 指针，不复制正文，保证一站一份事实源 |
| 内容边界 | 只记「这次怎么跑通的」与基线；不复写本册通用步骤、铁律与验收判据 |

**运行时流程**：按链接域名查分册 → 命中且状态正常就按档内 `form` 首轮直取、按 `bootstrap` 省掉多余预热 → 未命中 / `review` / `--refresh` 走完整链路 → 跑通后自动回写主分册（`form` / `bootstrap` / `baseline` / `verified` / `hits`）→ 命中却失败累计 `fails`，连续两次标 `review`，下次自动重新分析。

| 参数 | 用途 |
|------|------|
| `--list-profiles` | 列出已有分册与复用状态 |
| `--refresh` | 忽略旧档重新分析，成功后覆盖 |
| `--no-profile` | 本次不读不写 |

- 分册里允许出现具体站点名，它属于**用法记录**而非能力描述，且只存在于使用者本机；技能包与发布包内仍按铁律 9 保持零站点名、零分册。
- `<!-- auto:end -->` 之后是人工笔记区，自动回写不覆盖。
- 规范只改技能包那一处；新形态先用通用特征吸收，确需专门处理才追加解析器。
- 字段定义与维护细则写在用户级 `CONFIG.md`，本册不复写；工作区记忆只留指针。

## 解析器契约

模块放 `scripts/sources/<解析器>.py`，入口用 `pkgutil` 自动发现，路由表由代码生成。

| 名称 | 类型 | 判据 |
|------|------|------|
| `NAME` | str | 解析器标识，与模块名一致 |
| `LABEL` | str | 日志里的解析模式名 |
| `HOSTS` | tuple[str] | 链接特征串；`match` 命中即路由到本模块；通用兜底给空元组 |
| `BOOTSTRAP` | tuple[str] | 会话预热入口；给空元组时由入口按目标链接推导 |
| `PRIORITY` | int | 升序匹配，数值小的优先；通用兜底取 100 |
| `match(url)` | bool | 只按链接判定，不发起请求 |
| `collect(url, raw, opts)` | dict | 返回资源描述 |
| `selftest_adapter()` | bool | 用本地数据校验解析函数，不联网 |

资源描述字段：

| 字段 | 类型 | 判据 |
|------|------|------|
| `site` | str | 取 `NAME` |
| `id` | str | 素材 ID，用作文件名前缀 |
| `title` | str | 素材标题，无标题给空串 |
| `urls` | list[str] | 候选媒体地址，按可用性降序；入口按序重试 |
| `images` | list[str] | 图集地址；`urls` 为空且本项非空时逐张保存 |
| `source_url` | str | 原始链接，供外部下载器兜底 |
| `final_url` | str | 落地页地址，用于推导 Referer |

- 取数失败时返回 `{"site": NAME, "error": "<判据说明>"}`，入口打 `[fail]` 并计为未完成。
- HTTP、cookie、下载、文件名、外部下载器一律调 `core`，解析器内禁重复实现。
- 下划线开头的模块由入口跳过；`scripts/sources/_template.py` 是接入骨架，复制后填位。
- 解析器内禁写具体平台名称、域名与专属接口路径；页面特征从传入的链接推导。

## 通用解析口径

`scripts/sources/webpage.py` 覆盖任意 http(s) 链接，流程如下：

| 步 | 动作 |
|----|------|
| 1 | 入口按目标链接做一次桌面 UA 预热，记录落地页地址 |
| 2 | 入口按落地页根地址再预热一次，补齐会话 cookie |
| 3 | 解析器按三种请求形态重取页面：移动 / 桌面 UA × 链接与落地页两种 Referer |
| 4 | 扫描页面内嵌 JSON 块与标签属性，收集媒体地址与图集地址 |
| 5 | 由水印标记、附加参数与清晰度参数派生候选并排序 |
| 6 | 入口按序下载，校验文件头与体积 |

- 任一轮解出媒体地址即停；最多三轮，三轮均不可达返回失败。
- 内嵌数据块按 `window.*` 赋值、`application/json` 脚本、`DATA` 标记脚本、流式 push 四类解析。
- 资源地址按通用特征分类：视频取 `mp4` / `m3u8` / `mpd` / `play` / `media` / `stream`，图片取常见图片扩展名与图片路径特征，静态资源与统计脚本剔除。
- 候选派生：去水印标记、去附加展示参数、按清晰度参数生成高清变体；无标记直连排前，高清变体兜底。
- 标题取内嵌数据里的描述字段，回退到页面 `title` 与 `og:title`。
- 素材 ID 取落地页路径中的长数字段；无数字段时取链接摘要前 12 位。

## 接入步骤

1. 复制 `scripts/sources/_template.py` 为 `<解析器>.py`。
2. 填 `NAME` / `LABEL` / `HOSTS` / `PRIORITY`。
3. 实现 `match` 与 `collect`，登录态取 `opts.cookie`，代理取 `opts.proxy`。
4. 补 `selftest_adapter`，用本地数据覆盖解析分支。
5. 跑 `--list-sites` 与 `--selftest`。
6. 用一条真实链接跑 `--info`，再跑完整下载并过 01 册验收判据。

## 扩展验收

| 项 | 判据 |
|----|------|
| 路由 | `--list-sites` 列出新解析器；目标链接日志出现对应 `[模式]` |
| 自检 | `--selftest` 全绿且全程无网络请求 |
| 改动范围 | `collect.py` 与 `core.py` 零改动 |
| 下载 | 文件头含 `ftyp`，ffprobe 读出尺寸与时长 |
| 兜底 | `--engine ytdlp` 对新解析器生效 |
