# 07 · 触发词挂载规范（Combat V2 + Camera Motion）

> 何时读：**写任何 H3 提示词之前**——尤其打斗镜。本册是「哪条提示词该挂哪个触发词」的**唯一权威来源**。
> 与 06 册的分工：06 册给 Camera Motion LoRA 的**运镜词表与强度**；本册管**触发词挂在哪、挂几个、按什么顺序**。

## 一、为什么单开一册（触发词不是可选项）

触发词是**生造词**，正常中文里不会自然出现，模型只在**看到它**时才激活对应 LoRA 的能力。
**漏挂 = 该 LoRA 完全不起作用**，而提示词文本本身看不出任何异常——这是最隐蔽的一类失败。

所以：**触发词不是「写得好才加」，是「写就必挂」。**

## 二、我们有两类 LoRA、两个触发词族

| LoRA | 触发词 | 管什么 | 词条出处 |
|---|---|---|---|
| **Combat V2** | `prfight1` / `prfin1` / `prslow1` | 打斗**动作**怎么表现 | `fxai-combat-design/references/08-招式术语字典.md` |
| **Camera Motion** | `camera motion` | **运镜**怎么动 | 本技能 `06-运镜LoRA与运镜写法.md` |

两者**互不冲突、可叠加**：一个管动作、一个管运镜。

## 三、镜型 → 触发词 对照表（照抄即可）

| 镜型 | 触发词行（`detailed_description` 第一行） |
|---|---|
| **文戏镜**（无交手、无运镜诉求） | **整行不写**（一个都不留） |
| **普通镜**（只要运镜，不打斗） | `camera motion` |
| **打斗镜**（普通交手） | `camera motion, prfight1` |
| **打斗终结镜**（这一镜走完终结技） | `camera motion, prfight1, prfin1` |
| **打斗慢镜终结**（终结技要慢放） | `camera motion, prfight1, prfin1, prslow1` |

**三条硬规则**：

1. `camera motion` **永远排最前**——它是运镜总开关。
2. `prfight1` 是**打斗镜的基础词**：只要这一镜有武术动作 / 兵器交手就挂，不管是不是终结镜。
3. `prfin1` / `prslow1` **只在终结镜加**，且**必须与 `prfight1` 同时出现**（不单独用）。

## 四、位置：固定写在 `detailed_description` 第一行

```text
detailed_description:
camera motion, prfight1, prfin1          ← 就是这一行（独占一行）
雪后阴天，灰白冷调，肃杀利落的近身兵器对决氛围。   ← 风格句
[Shot 1] 中景镜头，……                            ← 正文时间轴
```

> **章节标题中英两套，位置规则完全相同**：短剧管线（`fxai-short-drama`）的六段式用**中文章节名**，触发词落在 **`详细描述`** 的下一行；MV / 口播管线（`fxai-audio-video`）用**英文章节名**，落在 **`detailed_description:`** 的下一行。两者都是「描述画面的那一段」的第一行。

- 触发词行的落点只有「描述画面的那一段」，`subject_definitions` / `summary` / `retention_analysis` 三段保持各自原有内容。
- 正文时间轴（`[Shot 1] …` 那句）保持纯画面描述，`prfight1` 这类词混进去会被当成画面内容。
- 触发词行**独占一行**、全小写、逗号分隔、不加引号、不加句号。

> **为什么不是「整条 prompt 的最开头」**：Ref2VA 是**六段结构化**格式，第一段必须是 `subject_definitions:`。
> 真正描述画面的那一段是 `detailed_description`，所以触发词落在它的第一行——
> 这是本技能格式下最接近 06 册「放 prompt 开头」的落点。

## 五、完整可复制骨架

**打斗终结镜**：

```text
detailed_description:
camera motion, prfight1, prfin1
<风格句：题材 + 光色 + 氛围>
[Shot 1] <景别与机位>，镜头以<运镜类型>（<英文运镜短语>）跟拍 <Subject 1> (S1)，幅度<小/中>、速度<慢/中>。<时间轴正文…>
```

**纯文戏镜**（触发词行**整行删掉**）：

```text
detailed_description:
<风格句：题材 + 光色 + 氛围>
[Shot 1] ……
```

## 六、与 06 册运镜写法的配合

挂上 `camera motion` 只是**打开开关**；具体怎么动仍要在正文里写全「类型 + 幅度 + 速度 + 跟拍对象」，
运镜词只从 06 册 9 类词表里挑**一条**（`slow push-in` / `slow pull-back` / `slow tracking shot` / `handheld tracking shot` …）。

## 七、⚠️ 当前落盘现状（务必知道）

**触发词写了 ≠ LoRA 生效。** 触发词只在**对应 LoRA 真的加载了**时才起作用。

现状（已核对全部 H3 工作流的 `FxAiLoraLoader` 节点，节点号 `1177`）：**每个工作流都挂两条 LoRA**——

| LoRA | 强度 | `trigger_words` | 作用 |
|---|---|---|---|
| `H3人脸去油.safetensors` | 0.7 | 空 | 压人脸油光/塑料感 |
| `Motion_Repair.safetensors` | 0.45 | 空 | 修动作发飘 |

换人链 `h3-char-swap-api.json` 是另一套两条：`h3_character_swap` 1.0 + `Motion_Repair` 0.45（不带人脸去油）。
`minimax_h3_ref2v_turbo_8step_768p_bf16`（8 步加速）已从全部工作流删除——PRISM 底座自带 8 步蒸馏，挂着只抹细节。
`H3电影感`(0.3) 只在 V1.4 期间挂过，**现行任何工作流都不含这条**。

🔴 **人脸去油常开**：所有 H3 工作流恒为 `enabled: true` + 0.7，不分底座；
短剧管线 `_adapt_loras_to_base()` 在模板被关时自动补开。

覆盖：`mv-minimax-multi`、`mv-minimax-multi-api`、`mv-minimax-multiref`、`mv-minimax-multiref-api`、
`mv-minimax-single`、`shortdrama-minimax-filmdrama-api`；`mv-minimax-single-api` 的 `lora_data` 走接口注入。

🔴 **表里三条 LoRA 的 `trigger_words` 都是空的**，所以 **`camera motion`、`prfight1`、`prfin1` 现在写了也不会触发任何东西**。
要用运镜/打斗 LoRA，得把 `lora_data` 里再加一条对应的 LoRA（并填它的触发词），
或者改成占位符以支持按镜切换。

**写提示词时照本册照挂**——提示词侧该写的写全，LoRA 挂载由工作流侧解决，两边不互相等。

## 八、常见误用

- ❌ **打斗镜忘挂 `prfight1`** → 打斗动作不增强，成片软。
- ❌ **文戏镜挂着 `prfight1` 没删** → 模型可能把「打斗」当画面内容，文戏镜莫名多出动作。
- ❌ **`camera motion` 没放最前** → 运镜控制不激活（同 06 册）。
- ❌ **只挂 `prfin1` 不挂 `prfight1`** → 终结词是叠加在基础词上的，单独用无意义。
- ❌ **把触发词写进 `summary` 或正文** → 被当成画面内容，污染提示词。
- ❌ **以为「挂了触发词就一定生效」** → 见第七节，还要 LoRA 真的加载。
- ❌ **手工再抄一遍** → 短剧管线已自动挂（见第九节），手抄不会重复，但没必要。

## 九、代码层：短剧管线自动挂载（v0.6.0 起）

「必挂」这件事不靠人记——短剧管线的组装函数会**自动**做：

```python
# fxai-short-drama/drama_pipeline.py
build_lines_data(shots, ..., auto_triggers=True)   # 默认开
#   → resolve_trigger_words(shot)   判定本镜该挂哪些
#   → inject_trigger_words(prompt, words)   插到「详细描述」第一行（独占一行）
```

**判定优先级**（高 → 低）：

| 级别 | 写法 | 说明 |
|---|---|---|
| 1 | `shot["trigger_words"] = "camera motion, prfight1"` | 显式指定（str 逗号分隔或 list）；`""` / `[]` = **明确不挂** |
| 2 | `shot["is_fight"]` / `["finisher"]` / `["slow"]` | 显式布尔开关；`is_fight=False` = 文戏镜 |
| 3 | 关键词启发式 | 扫「详细描述」段正文：命中打斗强信号 → `camera motion, prfight1`；命中终结词 → 加 `prfin1`；命中慢镜词 → 加 `prslow1`（并补 `prfin1`） |

- 启发式**只认强信号**（招式 / 兵器 / 身体对抗词：劈砍、格挡、弓步、剑锋、缠斗…），「端起酒杯」这类日常动作**不会**被误判——误挂 `prfight1` 会让文戏镜凭空多出打斗动作。
- 提示词里**已经有**触发词行时 → **就地合并**（补齐缺的词、去重、按标准顺序重排），不会出现两行。
- 关闭：`build_workflow(..., auto_triggers=False)`。
- MV / 口播管线不做自动判定：`fxai-audio-video.build_ref2va_prompt(..., trigger_words=…)` 由调用方显式传。

**交付文档同步**：`export_shot_prompts.py` 导出的 `镜头六段式提示词.md` 会按同一规则把触发词行补出来，保证「交付物 = 实际提交给 H3 的提示词」。
