# 发布机制与主页可见性（被问「为什么看不到」「占不占次数」时读）

## 发布 ≠ 群发：次数与可见性

**占用群发次数的，是【群发通知】这个开关，跟发的是图文还是贴图无关。** 官方客服《公众号群发消息方法》逐字：

> 「编辑消息时会提供【群发】或者【发布】两种选择，若是进行【群发】消息，粉丝可在微信端收到公众号群发的消息，**会占用公众号的群发次数**。若【发布】消息，粉丝不会收到消息。**发布不占用群发次数，一天可多次发布。**」

三个常被混为一谈的事实：
| 事实 | 官方口径 |
|---|---|
| 次数从哪来 | 后台（2023-09 起）把「群发」「发布」两个按钮合并成一个「发表」，靠**【群发通知】开关**区分。勾了＝群发（推送粉丝、占次数）；不勾＝发布（不推、不占次数、**一天可多次**） |
| 扫码是什么 | 【群发通知】的安全验证（公众平台安全助手扫码确认）。**它是勾了通知才弹出的，不是内容类型决定的** |
| 贴图/图文差别 | 只有形态和字段，**在次数这件事上完全对等** |

**发起来的东西到底在哪儿：官方客服《公众号/服务号的群发规则》逐字——**

> 「无论文章发表时是否开启群发通知，微信用户都可以**在公众号主页看到文章发表记录**。」

于是「粉丝看不到」这个疑问的准确答案是两个不同的地方，别混：
- **公众号主页（资料页 → 【全部】【贴图】【文章】【视频号】【服务】五个 tab）**：只有**后台手动「发表」／群发**的内容才进这里；接口发的不进（见下一节，官方口径）。
- **粉丝微信客户端顶部的消息列表（订阅号消息／服务号会话）**：只有**勾了【群发通知】**的才会出现在这里；没勾的通知一次都不进。

**`freepublish/submit` 没有「群发通知」开关**（接口参数只有 `media_id`），接口只能发「发布」这一档：免费、不限次、只进发表记录。想让粉丝在客户端消息列表里看到，只有两条路：
1. **后台手动发表时勾【群发通知】并扫码**（不勾不占次数；勾了就跟图文一样占次数）。
2. **`mass/sendall` 群发**，传**草稿的 media_id**（不是已发表 article_id），微信按 media_id 自己识别类型：news 走 mpnews、贴图走贴图群发。占群发次数（认证订阅号 1 次/天、服务号 4 次/月）、**不可逆** → 执行前必须复述剩余次数并拿到用户确认。
 - `freepublish/submit` 发布后草稿不在 `freepublish/draftlist` 里了，要群发得**重新建一次草稿**拿 media_id。

## 接口发布 ≠ 后台手动发表：主页进不进，看的是通道不是开关

官方开放社区答复（`developers.weixin.qq.com/community/develop/doc/0006ce2c8303d04ce5051750769409`）逐条原文：

> ① 通过 `freepublish/submit` 发布的文章**不会进入公众号主页，这是产品预期设计**。
> ② MP 后台「**不开启群发通知但仍在主页展示**」功能对应的就是发布接口本身。
> ③ 自 2026-04-21 起观察到的 API 发布内容不显示主页现象**属于官方预期行为，产品逻辑始终保持一致**。发布接口**不保证内容展示在主页**。
> ④ 调用公众号 API 同步文章**需要非个人主体微信认证**。
| 通道 | 不勾群发通知时，主页（【文章】/【贴图】tab）可见？ |
|---|---|
| mp 后台手动「发表」 | **可见**（官方第 ② 条讲的就是这个场景） |
| API `freepublish/submit` | **不可见**（官方第 ①③ 条，属预期行为，不是故障、不是配置错） |

→ 「接口发出去了、发表记录里也显示「已发表」、主页却什么都看不到」＝ 正常。
→ 用户问「API 发的文章/贴图在主页找不到」时，**先按这条结论解释，别去翻权限配置**。
→ 想让用户看见：走 **接口建草稿 → 后台手动点发表**（`draft-add` / `draft-add-newspic` 建稿，走草稿链路而不是 `publish`）。
→ 经由中转代发时，主页仍看不到，**优先查第三方授权链路，而不是查接口权限**。

**诊断顺序：先确认内容在不在「发表记录」里。**
- `freepublish/publishlist` 查得到（有 `article_id`、有 `mp.weixin.qq.com` 链接）→ 接口侧**发布成功**，进了「发表记录 · 未通知」
 —— 但**这不等于主页可见**（上面官方口径），去主页看不到是预期，要走后台手动发表才进主页。
- 查不到 → 才是真失败，回 `05-自检与目录规范.md` 排查。
- 草稿只在箱子里、还没发表：用 `draft-list` 能看到，`article_type=newspic` + `image_info.image_list` 齐全即正常。

**想自己核实某篇是「已通知」还是「仅发表」**：后台「发表记录」里鼠标悬浮「已发表」看小浮窗；或标题左侧下拉箭头看显示「已开启通知」还是「未开启群发通知」。


- 接口 `freepublish/submit` 发的文章**不进公众号主页文章列表**，能上主页又不占群发额度的唯一路径是「接口建草稿 → 后台手动点发表」。
- 交付时明确写出：草稿 media_id、去后台哪个入口能找到它、这一步之后还有没有别的动作。

## 两种发表形态对照

| | 图文消息（news） | 贴图消息（newspic） |
|---|---|---|
| 后台形态 | 文章，进文章列表可点开阅读 | 贴图 / 图片消息（图集），**一条消息里多图，读者左右滑动** |
| 接口识别字段 | `article_type:"news"`（不填即默认） | **`article_type:"newspic"`** |
| 图怎么进接口 | 正文 `<img>`（自动上传换成 mmbiz URL） | **`image_info.image_list[]`，传永久 media_id，最多 20 张** |
| 正文 `content` | **HTML**（支持标签） | **纯文本**，HTML / `<img>` 收不进去 |
| 封面 | `thumb_media_id` 必填（永久 MediaID） | **首张图即封面，`thumb_media_id` 与 `cover_info` 都不传** |
| 技能子命令 | `draft-add` | **`draft-add-newspic`** |
| 发表链路 | `draft/add` → `freepublish/submit` | 同左（完全共用） |
| 额度 | `freepublish` 不占群发额度、不推送粉丝 | 同左 |

**怎么选**
- **文字是主角、配几张图**（教程、说明、观点、复盘）→ **图文消息**，进 `01-图文消息news.md`。
- **图是主角、文字只当图注或一句说明**（写真、穿搭、摄影、作品集、图集）→ **贴图消息**，进 `02-贴图消息newspic.md`。
- 用户嘴里的「纯贴图 / 纯图集 / 建图集 / 贴图文章」，指的都是 **贴图消息**。
