# 文章结构模板与排版

命中即读：搭文章骨架、调正文排版、决定图插在哪、控字数与分段时。结构模板给骨架，模板库见四节，配图与排版按本册执行；封面尺寸走 01 册，标题与开头走 10 册。

## 一、通用结构骨架（四段式，可长可短）

| 段落 | 作用 | 字数占比 | 排版要求 |
|---|---|---|---|
| 钩子 | 首屏给继续读的理由 | 5% | 首行即钩子，短段落，忌铺垫（10 册） |
| 展开 | 场景 / 数据 / 冲突具体化 | 25% | 一节配一图，节内短句成段 |
| 主干 | 3~5 个小节递进，每节一个判断 | 50% | 小节之间用小标题隔开，节末落一句实话 |
| 收束 | 回到开头，给结论或下判断 | 20% | 硬广最多在最后一节出现一次；署名行按 SKILL.md -3 节 |

干货方法文把「主干」换成「步骤 1/2/3」；亲历叙事把「主干」换成「时间线」；观点文把「主干」换成「论点 + 反例」。骨架不变，换的是中段组织方式。

## 二、常用结构变体

- **教程文**：钩子（我能解决什么）→ 前置条件（需要什么）→ 步骤（每步一段一图）→ 常见问题 → 收束。
- **复盘文**：钩子（结果先给）→ 背景（为什么做）→ 过程（做了什么）→ 失误（哪些没做对）→ 下次怎么改。
- **观点文**：钩子（反常识判断）→ 现象（大家都这么说）→ 拆解（为什么站不住）→ 我的结论 → 收束。
- **经验分享型 · 软落点**：入门经验 / 避坑 / 省钱思路，末尾带自家落点 → 走第三节专用模板（**有硬口径，不可按普通干货文写**）。

## 三、经验分享型 · 软落点模板（2026-11-11 定）

**定位**：这不是推销文，是「给大伙儿准备了一套思路，也准备了这套玩法」。读者先拿到能用的方法，最后才知道有个现成的落点可选。

**适用**：面向初学者 / 潜在用户的入门经验、避坑、省钱思路、阶段化方法论；文末要带自家镜像 / 工具 / 地址 / 收费口径。
**不适用**：纯教程（本来就不带落点）、自家工具实测文（走 04 册真跑掐表）、纯观点文（走观点变体）。

### 骨架（6 段；前四段＝方法阶段，一个「我们」都不许有）

| 段 | 作用 | 能不能提自家 |
|---|---|---|
| 钩子 | 点破痛点（钱花了没做出东西 / 走弯路），给继续读的理由 | ❌ |
| 分阶段 | 把学习过程切成阶段，说明每阶段目标与花法不同 | ❌ |
| 通用方法一 | 可执行的筛选 / 判断标准（如「24G 能跑、镜像费低、作者可靠」三条） | ❌ |
| 通用方法二 | 更省的操作方式或趋势判断（如智能体 + 技能包 + 算力），写成行业通用走法，**不写成「我们主推」** | ❌ |
| 提供线路（收束段①） | **承上启下**：亮作者身份（既是镜像作者 / 开发者，也是深度使用者）+「说说我能给大伙儿提供点什么」→ 把备好的一条线路讲清楚 → 地址 | ✅ |
| 怎么挣钱（收束段②） | **单独一节**，按下面「钱这一节怎么写」四步：朋友问「要收费吗」→ 先答**免费** + 开源精神 → **不预收、觉得值心甘情愿再支持** → 列收入来源几块 → 感谢关心 → 收尾 | ✅ |

🔴 **收束段可以是 1 节，也可以是 2 节**：内容一多就拆开——**线路归倒数第二节、钱归最后一节**。
别把「代码全开源」直接甩在收束段开头，也别把钱插在线路中间。

**通用方法二别只讲趋势**：得给一句明确建议（对应用层的人，直接用「智能体 + 技能包 + 算力」这套组合，
上手最快），再把「快在哪儿」拆成 2~3 条「不用关注 X」——工作流 / 节点画布、环境、发布与提示词这些零碎痛点，
收一句「一句话说清目标，过程机器跑完；人管目标和验收」。只写「这是未来主流」不给理由，读者不知道下一步该干嘛。
效果若给量级判断（如「省一半以上」），必须标明是**个人经验判断**并限定范围（「按我自个儿这一路的经验 / 光入门这一段」），
别写成掐表实测或对所有人的承诺（04 册数字纪律、07 册不夸大）。

**收束段别硬拐**：开头不能直接甩「代码全开源 / 那要不要钱」，读者会被硬拽进广告。
先亮身份（既是云上给大伙儿做镜像的作者 / 开发者，也是天天在用这套东西的深度使用者）、
再一句「说说我能给大伙儿提供点什么」，把前四节的通用经验与自家落点接上，先讲线路和地址，钱单独放最后一节。

### 三条硬口径（用户 2026-11-11 明确）

1. 🔴 **收束段之前，零「我们 / 咱们 / 凤希AI / 我们这套东西 / 我们主推 / 我们自己也做…」**。
   可以用第一人称「我」讲亲历与判断，不能用「我们」讲产品、讲团队、讲自家镜像。
   自检：按收束段第一节标题切开，前半篇搜这几个词，命中数必须为 0。
2. 🔴 **语气是「顺带备了」，不是「推荐使用」**：不比较、不贬低别家、不写「一步到位」「最好用」。
   必须明写「按同样标准挑别家做的一样能练」，把选择权留给读者。
3. 🔴 **落点只在收束段出现一次**：地址 / 入口 / 收费口径 / 软引导全在收束段，前面不埋钩子、不反复吆喝；
   地址原样贴、不做可点外链（07 册红线）。

### 收束段句式（可直接套用）

> 前面写的都是通用路子，跟用谁家的东西没关系。写到这儿，也该交代一下我自己站在哪儿：
> 我既是在云上给大伙儿做镜像的作者和开发者，也是天天拿这套东西干活的深度 AI 使用者。
> ……所以我照着这套思路，给大伙儿备了一条能直接照着走的线路：智能体 / 技能包 / 算力三层，
> 从 24G 那一档起步把第一条活跑通。觉得这个走法靠谱、自己用得上，就可以从下面这个开始；
> 按那三条去挑别家做的，一样能练。
> （钱单独起一节，按下面「钱这一节怎么写」四步走：免费 → 不预收 → 列收入来源 → 感谢关心。）

### 钱这一节怎么写（2026-11-11 用户明确，四步）

| 步 | 写法 | 口径 |
|---|---|---|
| 1 问 | 「有朋友问：那这个要收费吗」 | 用朋友提问接住，别直接甩「代码全开源」 |
| 2 答 | **把「免费」两个字先说出来** +「本着开源的精神，这套技术免费让大伙儿用」 | 🔴 别用「本身不收钱」「知识共享」绕着答；读者要的是一个是 / 否 |
| 3 不预收 | 「不会无缘无故先收你一笔费用」→「用着觉得确实值，心甘情愿地付一点支持我们」 | 🔴 先给价值再谈钱；不预收、不催、不捆着卖 |
| 4 列来源 | 「收入来源于哪几块儿？下面列出来」→ 红包或软件会员 / 用我们的镜像 / 帮忙部署或一对一的带你实操教学才另收服务费 | 🔴 列的是**收入来源**，不是「会发生的费用」 |

**六条硬口径**：

1. 🔴 **云的费用不能混进收入清单**：云按小时收的算力费是付给云平台的，不进作者口袋。
   单独一句诚实交代，否则「免费」会被读成「连云也不花钱」，前面的省钱逻辑就塌了。
2. 🔴 **服务费只挂在具体劳动上**：代部署、一对一的带你实操教学这类实际替人干活的，才「这个时候另外收一次服务费」。
   不写「软件本身提供的一些服务」这种含糊收费项。
   🔴 措辞就用「**一对一的带你实操教学**」（用户 2026-11-11 03:36 明确），别写成「给你讲解怎么用 / 一对一讲解」。
3. 🔴 **支持路径写全三条**：红包或软件会员 / 用我们的镜像（在相关云上，费用按页面标的走）/ 购买服务。
   「用我们的镜像就行」本身就是一种支持，别让读者以为非掏钱不可。
   🔴 「零元 / 相对低」是**方法阶段挑别家镜像的通用筛选标准**，不是自家镜像的属性；
   自家镜像有相应费用，写「按页面标的走」，别写「零元那份也照样能用」。
4. **语气是感谢，不是辩解**：收一句「也谢谢大伙儿的关心」+「有效果、你觉得有效果，再付」；
   「不卖课、不割韭菜」一句带过即可，别铺陈成自我表白。
5. **免费的延伸内容也要写进来**：会录制使用视频、不定时开直播，大伙儿都能来，
   **现阶段一律免费分享**。放在「免费」那一步之后当补充，别塞进收入清单，也别写成「以后可能收费」的钩子。
6. 🔴 **不写「打赏」二字**（用户 2026-11-11 明确）：写「一个红包支持一下，或者一个软件会员支持一下」；
   「软件会员」四个字别省成「会员」，别含糊成「支持一下」。

**别说车轱辘话**：「不预收」和「有效果再付」是同一层意思，前者放在清单前当承诺、
后者放在清单后当收束，各出现一次，别在中间再重复一遍。

### 反例（本轮真踩过的坑）

- 「我们这套东西，24G 那一档就能跑起来」→ 第一节就自报家门；改成中性的「24G 那一档，就够把第一条活从头跑到尾」。
- 「我们自己也做镜像，给大伙准备的那几个本来就是照这三条设的」→ 把通用标准变成自夸；改成「三条都对得上就可以开工，别只认一个名字、也别只认一个作者」。
- 「我们现在主推的创作模式是……」→ 把行业趋势写成自家产品；改成「有个更顺的走法……这不是谁家独门的东西，往后大家用 AI 做东西多半就是这么个用法」。
- 🔴 「我是从应用层上来的，不是做开发、做技术的那一类」→ **把作者身份写反了**：我们本身做开发。
  经验谈要写成假设句，且用「我」不用「我们」：「像我这种做技术开发的，工作流、环境本来就得自己倒腾；
  如果你只是想用 AI 做出个东西（应用层普通用户），这四样压根不该你操心」。
  别把作者写成用户，也别让「应用层用户」听着像低配角色。
- 「机时其实好算」→ 生造词费解；改成大白话「云上这笔钱其实好算：按小时计费，开多久算多久」。
  通用原则：**讲钱讲流程都用大白话，别自造缩略词**，读者看不懂就等于没写。
- 🔴 收束段开头直接甩「**代码全开源 / 那要不要钱**」→ 没承上启下、读着突兀，读者被硬拽进广告；
  先亮身份 +「说说我能给大伙儿提供点什么」，把线路讲清楚，钱单独放最后一节。
- 🔴 把「线路」和「怎么挣钱」挤在同一节 → 前一句还在讲能给你什么，后一句就谈收费，读着别扭；
  内容一多就拆成两节（倒数第二节线路、末节钱）。
- 🔴 问「要不要钱」却答「代码全开源，这套东西本身不收钱」→ 绕着答，没把「免费」说出口；
  改成干脆的「**免费。** 本着开源的精神，这套技术免费让大伙儿用」。
- 🔴 把「会发生的费用」当收入来源列，还把「云那边的进项费用」混进去 → 读者分不清到底谁收了钱；
  改成只列红包或软件会员 / 用镜像 / 服务费三块，云费用单独一句说明「是付给云平台的，不进我的口袋」。
- 🔴 一上来先讲收费项、不提「不会无缘无故先收费用」→ 读着像先谈钱再给东西；
  先写「东西先拿去用，觉得确实值、心甘情愿再支持」，再列来源。

## 四、模板库索引与扩充纪律

按「内容类型」选模板，别每篇从零起；以后每写一类新内容，先在这里登记骨架与硬口径，逐步把自家不同风格、不同内容的模板补全。

| 内容类型 | 用哪个模板 | 出处 |
|---|---|---|
| 教程 / 步骤 | 教程文变体 | 本册二节 |
| 复盘（结果 + 失误） | 复盘文变体 | 本册二节 |
| 观点 / 反常识 | 观点文变体 | 本册二节 |
| 自家工具实测（带可复现数字） | 真跑掐表文 | 04 册 |
| **入门经验 / 避坑 / 省钱思路（末尾带自家落点）** | **经验分享型 · 软落点** | **本册三节** |

新模板登记三件套：**适用 / 不适用、骨架表、硬口径 + 反例**。只写一句风格描述不算模板。

## 五、字数与分段

- 幽默随笔正文 **1200~1800 字为下限**（SKILL.md -3 节），干货方法文按需要上浮，深度文可到 3000 字。
- 段落控制在 **2~4 行**（移动端一屏约 8~10 行）；单句成段是本账号常用手法，一节里不超过 3 次。
- 每一节收一句扎心实话，节与节之间不写「接下来我们讲……」这类过场。
- 不用「首先 / 其次 / 最后」堆砌逻辑，用小标题和小节自然分段。

## 六、配图粒度（铁律）

- 配图粒度是**小节**，不是自然段：正文里用空行或小标题分开的大块，通常 4~6 节，每节至少一张。
- 每节的图落在**最需图示处**，图意与本节内容一致；一段一图属于凑数。
- 图必须真跑出来（自家工具的图走 04 册真跑流程），交付记录来源。
- 图注：居中 + 灰色小字，一句话说明图在讲什么。
- 收束段拆成两节时，**每节仍至少一张图**；优先把已有的链路图 / 账本图挪过来配文，改 `.md` 图占位与图注即可，不必新出图。

## 七、正文排版规范

- 段落之间空一行；小标题用 `##` 层级，最多两层，第三层用加粗句首代替。
- 强调用**加粗**，一段最多一处；连续加粗等于没有强调。
- 引用块用于金句 / 数据来源，一篇不超过 2 处。
- 列表用于并列信息，每项一行，控制在 7 项内；有序列表用于步骤。
- 链接走超链接文字，不裸奔长 URL（正文外链规则见 07 册）。
- 代码、命令、路径、参数用行内代码，参数名与值区分清楚。
- 全文字号层级不超过三级，行长控制在每行 20~28 个汉字，窄屏不挤。

## 八、图文 vs 贴图的形态选择

判断与字段、接口链路走 01 册（图文 news）与 02 册（贴图 newspic）。排版上贴图消息的字当图注：每张图一句说明，正文纯文本、顺序即阅读顺序。
