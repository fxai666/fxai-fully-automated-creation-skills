# 自检、配置与目录规范（发布后自检 / 装机配置 / 建项目目录时读）

## 发表与自检（两种形态共用）

**发布后自检（必做）**
1. `publish-status --publish-id <id>`：发布是异步的，2~5 分钟后查（内部端点 `freepublish/publishget`，
 返回 `publish_status:0` 且 `article_detail.fail_idx` 为空才算成）。**贴图类还要顺着回包核对 `image_count`**。
2. `freepublish/publishlist` 回看：正文图张数、正文字数、留言开关。
3. 取正文要**往下钻三层**：`item["content"]["news_item"][0]["content"]` 才是 HTML 字符串。
4. 自检正则**同时匹配 `mmbiz.qpic.cn` 与 `mmecoa.qpic.cn`**（后者含 `mmecoa_jpg/` 与 `sz_mmecoa_jpg/` 两种前缀）。
5. 判本地路径残留的正则加 `(?<![a-zA-Z])` 前缀。

**草稿箱 vs 已发表（别拿错 ID）**
| | 端点 | 返回的 ID | 用途 |
|---|---|---|---|
| 草稿箱 | `freepublish/draftlist` | `item[].media_id` | 删草稿、发布用 |
| 已发表 | `freepublish/publishlist` | `item[].article_id` | 删除已发布文章用（不用 `media_id`） |

`draftlist` 认的参数名是 `curpage/pagesize/no_content`（不是 `offset/count`）。

**首尾空白一律掐掉**：签名与发送必须是同一份值。脚本已在这三处统一掐掉首尾空白（空格、换行、制表、全角空格），正文中间的换行原样保留：
1. `relay_call()` 入口（`_norm_param`）：**所有端点的所有参数**统一掐首尾，签的是它、发的也是它，自己写调用别绕过它；
2. `read_content()` / `read_plain()`：正文文件读进来先 `strip()`（并用 `utf-8-sig` 吃掉 BOM），HTML 文件末尾的 `\n` 由脚本统一清掉，手工 rstrip 可省；
3. `draft-update`：articles 是 JSON 字符串整体当参数发，`relay_call` 掐不到里面字段，脚本对 `title/author/digest/content` 及 `--ext` 递归掐（`_norm_json_strings`）。

## 前置条件与配置
1. **所有接口都走中转（凤希AI伴侣 → 公众号运营）**。先跑 `python scripts/wx_api.py precheck`：没配置会返回完整引导（含下载方式）并退出码 1；配好返回 `ok:true` 与公众号清单。
2. 服务号必须已微信认证（未认证无发布权限，报 48001）。
3. 凭据来源分两处，**一律由技能自己取**：
   - **公众号凭据**（`host` / 每个号各自的 `configid`+`appsecret`）→ `~/.workbuddy/fxai_global.json` 的 `weixin_gzh` 字段，由「凤希AI伴侣 → 首页 → 公众号运营 → 复制智能体配置口令」导出后写入。**口令里不含登录态**。
   - **登录身份**（tokenmyid / usertoken）→ 本机客户端安装目录下的 `userinfo.json`：先读 `~/.workbuddy/fxai_global.json` 的 `software_install_dir`，再读 `<software_install_dir>/userinfo.json` 的 `myid` / `usertoken`。客户端每次登录成功都会整份重写该文件，所以换账号自动跟着换、不会出现过期快照。老配置里残留的 `weixin_gzh.login` 只作为兜底。
4. **IP 白名单官方强制无法关闭**，token 寿命 2 小时，链路依赖固定 IP 服务器中转。
5. 装完（或换机器、重新导出后）立刻跑 `python scripts/wx_api.py secure` 收紧 `~/.workbuddy/fxai_global.json` 权限——它存着 AppSecret + corpid。`precheck` 的返回里会打印登录身份来自哪个文件（只报路径、不打印 token）。
6. **发布默认值**（可选）：技能目录下 `config.json` 可写 `default_author` / `need_open_comment` / `only_fans_can_comment` / `content_source_url`；全局 `weixin_gzh.publish` 的同名键作兜底，本地值优先。照 `config.example.json` 复制成 `config.json` 再改。

**可用中继端点**：`freepublish/*`（uploadcover / uploadimage / draftadd / **draftaddnewspic** / draftget / draftdelete / **draftlist** / **publishlist**（已发表列表）/ publish / publishget / publishdelete）、`mass/*`（sendall / getstatus）、`material/add`（image / voice / video 永久素材）。
⚠️ `draftlist`（草稿箱，命令 `draft-list`）与 `publishlist`（已发表，命令 `publish-list`）是两个不同端点，别混用。

🔴 **`draftupdate` 不在可用端点里**（2026-11-12 实测）：`wx_api.py` 有 `draft-update` 命令，但中转侧没实现该端点 —— 实调返回的是「请求参数原样回显 + `rsscode:200`」（HTTP 200，`relay_call` 见 rsscode 即判 -1），`draft-get` 回读确认草稿**一个字都没变**。**改草稿只能 `draft-add` 重建 + `draft-delete` 删旧**，别在 `draft-update` 上反复试。顺序要「先建新、核过再删旧」，保证任何时刻草稿箱里至少有一份完整稿。

**正文排版闸门也是硬约束**：`draft-add` / `draft-update`(news) / `publish`(无 media_id) 三条路都会先过 `scripts/html_guard.py`，`<pre>` 换行、CSS 引号、`break-all` 自动修（回包 `html_fixed`），修不掉的直接拒绝提交。规则与写法见 01 册 1.4b，自查命令 `check-html --content <文件>`（`ok:false` 退出码 1）。

**选号铁律**：只有一个号直接用；用户指定了账号就带 `--account "公众号名"` 或环境变量 `WX_ACCOUNT`；多个号且用户没说，**必须先问清楚再动手**。

**已发文章想改内容**：`publish-delete` 删掉再重发（微信不支持编辑已发布正文）。

## 自定义菜单命令（后台入口，官方 7 端点全家桶）

菜单改动即时生效、**不占群发次数**，也不影响主页可见性（03 册口径）。脚本提供 7 个命令，全部走 `relay_call` 中转，提交前先过本地结构校验。

| 命令 | 中转端点 | 作用 |
|---|---|---|
| `menu-create --file 菜单.json` | `menu/create` | 建/覆盖默认菜单（**整体替换**，重建即清掉旧的默认菜单） |
| `menu-get` | `menu/get` | 读默认菜单，回包含 `conditionalmenu` 个性化菜单列表 |
| `menu-delete` | `menu/delete` | 清空全部菜单：默认菜单 + 所有个性化菜单 |
| `menu-addconditional --file 个性化.json` | `menu/addconditional` | 建个性化菜单（按人群分组），返回 `menuid` |
| `menu-delconditional --menuid <id>` | `menu/delconditional` | 按 `menuid` 删个性化菜单 |
| `menu-trymatch --user-id <openid或微信号>` | `menu/trymatch` | 试算某个粉丝实际命中哪个菜单 |
| `menu-selfinfo` | `get_current_selfmenu_info` | 本账号当前生效的默认菜单 |

菜单定义用 `--file` 传 JSON 文件或 `--json` 直接给字符串，官方字段名是 `button`（`buttons` 写法脚本也收）。骨架：

```json
{"button": [
  {"type": "view", "name": "自动化干货", "url": "https://www.fxai.site/auto",
   "sub_button": [{"type": "click", "name": "入门", "key": "JR_01"}]},
  {"type": "click", "name": "联系我", "key": "CONTACT_ME"}
]}
```

个性化菜单在同一份 JSON 里加 `matchrule`：

```json
{"button": [{"type": "click", "name": "创业者专属", "key": "ENT_01"}],
 "matchrule": {"tag_id": 2}}
```

**官方最新约束（写 JSON 前逐条对照）**
- `matchrule` 只收 `tag_id` 与 `client_platform_type`（1=iOS / 2=Android / 3=Others），且至少填一项；**性别 / 地区 / 语言字段官方已废除**，带上直接被拒（`errcode 65320`），脚本本地就会拦下。
- 个性化菜单**没有编辑接口**：改它＝`menu-delconditional` 删掉再整体重发。
- 多个个性化菜单按创建时间**从后往前**优先匹配。
- 图文入口的 `media_id` / `view_limited` 已弃用，改用 `article_id` / `article_view_limited`。
- 字节上限（中文 1 字 3 字节）：一级菜单名 16 / 二级菜单名 60 / key 128 / url 1024；一级菜单 ≤3 个、每个一级下二级 ≤5 个。
- 带 `sub_button` 的一级项可省 `type`（它是容器）；叶子项必须给合法 `type`。
- 7 个端点都要**认证账号**，未认证报 48001。

**端点可用性**：`menu/create|get|delete|addconditional|delconditional|trymatch` 与 `get_current_selfmenu_info` 需中转侧实现对应端点后才能真跑，报端点未实现即停在该步提示用户。客户端侧的结构校验在提交前本地完成，不通过不发出。菜单排布与自动回复文案按 14 册第三、四节配。

## 产出物目录规范（按项目隔离，一份就是备份）

**一篇公众号内容 = 一个项目目录**。发布前先按项目名建独立文件夹，全部产出物往里放；它同时就是备份，发布完留着别清。

⚠️ **项目目录直接落在工作区根下，`out/` 这层省掉**。

```
<工作区>/<项目名>/
 ├─ article/ 正文 HTML、标题文案（.md）
 ├─ image/ 配图（png 母版 + jpg 发布版）
 ├─ music/ 原创歌 / 音频
 ├─ video/ MV / 视频
 ├─ doc/ 词曲原文、提示词、脚本（文本 .md）
 └─ _tmp/ 临时中间产物（下划线开头，不算交付）
```

项目根优先级：环境变量 `FXAI_PROJECTS_ROOT` → 工作区级 `<工作区>/_fxai_global.json` 的 `projects_root` → **当前工作目录**。在哪个工作区干活就是 `<工作区>/<项目名>/`，不写死盘符，也没有全局路径配置。

**五道铁律（发布前逐条过）**
1. **产物一律接口下载**：图/音/视频在 ComfyUI 生成后走 `comfy_client` 的 `GET /fxai/down/file?url=<令牌>` 拿字节。
2. **落进对应子目录**：图 `image/`、歌 `music/`、片 `video/`、词曲提示词 `doc/`、正文 `article/`。
3. **同名走自动换名**：目标已存在自动换名 `_1` / `_2`，跑两遍要留两版。
4. **任何源都不删**：删了只能重新排队生成。
5. **所有文本一律 `.md`**：文案、标题、歌词、提示词、大纲、报告、转写稿一律存 `.md`，**不用 `.txt`**。
   正文仍是 `.html`（微信要 HTML），`.srt` / `.ass` / `.json` 等结构化格式照旧。

**发布前自检**
- [ ] 项目目录在 `<工作区>/<项目名>/`，路径里没有多余 `out/` 这层
- [ ] 6 个子目录都在（空的也算）
- [ ] 所有媒体都是接口下载来的，没有从 ComfyUI 本机目录拷的
- [ ] 同名文件没被覆盖
- [ ] 文本产物（文案/歌词/提示词/报告）都是 `.md`，没有 `.txt`
- [ ] 临时脚本都在 `_tmp/`，没混进交付目录
- [ ] 发出去的这版 = 项目目录里的这版
- [ ] 项目目录留着没清

## 工作流约定（AI 执行时）
1. **先定项目目录，再生成内容**：按上面建好 `<工作区>/<项目名>/{article,image,music,video,doc,_tmp}`，所有图音视频一律接口下载落进对应子目录。
2. **先判断发哪种形态**：文字主角 → 图文 `draft-add`；图主角 → 贴图 `draft-add-newspic`。
3. 封面图 JPG 发布版 `quality≥95 + subsample=0 + optimize=True`，<1.5MB；PNG 母版保留。
4. 建完草稿核对 `images_uploaded`（图文）/ 回包张数（贴图），**为 0 就别发布**。
5. `need_open_comment` 一律传 1。
6. 发布后 2~5 分钟 `publish-status` 确认，并做发布后自检，再把结果告诉用户。
7. **群发不可撤销**：执行前必须拿到用户明确确认。
8. 多公众号时用户没点名，先问「给哪个号发？」。

## 铁律速查（常驻，发布前逐条过）

1. **写自家工具的文章先真跑、再掐表、最后写数字**，数字一律来自实跑（04 册）。
2. **接口发布 ≠ 后台手动发表**：`freepublish/submit` 的内容**不进公众号主页**；想让用户看见走「接口建草稿 → 后台手动发表」。
3. **发布后自检**：2~5 分钟后 `publish-status`，再看 `image_count` 是否等于传入张数。
4. **`--images` 一个标志带多个路径**（`--images a.jpg b.jpg`）；写成每图一个标志时只认到 1 张。
5. **建完草稿核对 `images_uploaded`（图文）/ 回包 `image_count`（贴图）**，为 0 就不发布。
6. **`need_open_comment` 一律传 1**。
7. **封面/正文图发布版一律走脚本**：`make_cover.py`（封面 1152×512）/ `export_figures.py`（正文图 1152 宽），内部固定 `quality=95` + `subsample=0`（4:4:4）+ `optimize=True`，单张 <1.5MB；PNG 母版留在 `image/`。**别手写 PIL 转换、别去历史项目量尺寸**（见 01 册 1.3）。
8. **判接口成败只看 `errcode`/`errmsg`**；回包 `hint` 是通用托底文案，别信。
9. **产物一律接口下载**（`GET /fxai/down/file?url=...`），本机 ComfyUI 输出目录只当服务端看。
10. **所有文本一律 `.md`**（正文仍 `.html`）；同名走自动换名 `_1`/`_2`，两版都留着。
11. **项目目录直接落在工作区根下**，外面不套一层 `out/`。
12. **装完/换机器立刻跑 `secure`** 收紧 `~/.workbuddy/fxai_global.json` 权限（公众号凭据集中在它的 `weixin_gzh` 字段，含 AppSecret + corpid）。**登录态不在这个文件里**，脚本每次从 `<software_install_dir>/userinfo.json` 现读。
13. **多公众号且用户没点名，先问清楚**再动手。
14. **提交前首尾空白由脚本统一清掉**（标题 / 摘要 / 作者 / 正文 HTML 文件末尾的换行都算）；签名与发送必须同源。写新端点时参数一律过 `relay_call()`，别自己拼请求绕过。
15. **正文排版必须过闸门**（2026-11-12 起）：代码块 / 提示词 / 台词例子一行一个 `<section>`，禁用 `<pre>`、`white-space:pre`、`word-break:break-all` 与 CSS 值里的引号。`draft-add` / `draft-update`(news) / `publish` 提交前走 `scripts/html_guard.py`，能修的自动修（回包 `html_fixed`），修不掉的**直接拒绝提交**并给 `violations[]`。写法见 01 册 1.4b，自查 `check-html --content <文件>`。
16. **改草稿别用 `draft-update`**：中转侧没这个端点，只回显请求、草稿不变（见本册「可用中继端点」）。只能 `draft-add` 重建 + `draft-delete` 删旧，先建新、核过再删旧。
