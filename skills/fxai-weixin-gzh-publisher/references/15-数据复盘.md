# 数据复盘

命中即读：发布后带回后台数据、要定「下一篇写什么」、要判断某个动作有没有用时。复盘结论回写《公众号运营档案》并交给 `fxai-content-review` 沉淀经验；搜索与推荐口径见 12 册，指标口径见本册。

## 一、指标口径（先统一，再比较）

| 指标 | 口径 | 看什么 |
|---|---|---|
| 阅读人数 / 阅读次数 | 后台「内容分析」 | 规模 |
| 打开率（送达后打开比） | 会话列表打开 / 送达 | 标题与封面第一关 |
| 读完率 | 读完人数 / 阅读人数 | 结构与长度是否拖人 |
| 分享率 / 在看率 | 分享或在看人数 / 阅读人数 | 值不值得转发（推荐侧关键） |
| 涨粉数 | 关注数增量 / 阅读人数 | 内容与账号的匹配度 |
| 搜一搜来源 | 搜索来源阅读 / 阅读总数 | 长尾流量与关键词覆盖（12 册） |
| 菜单点击 / 自动回复触发 | 后台对应统计 | 私域入口是否有人走（14 册） |

取数窗口统一：**发布后 7 天**（长尾文可到 14 天），同一账号所有文章用同一窗口，跨窗口的数字没有可比性。

## 二、复盘节奏

| 周期 | 动作 | 产出 |
|---|---|---|
| 发布后 48 小时 | 看打开率与读完率 | 早期判断：这篇的标题/结构是否成立 |
| 发布后 7 天 | 完整取数 + 定下一篇选题 | 回写运营档案「待复盘文章」→ 结案 |
| 每月首个工作日 | 汇总上月 4~8 篇，找共性 | 栏目 / 选题 / 排版的三条结论 |
| 每季度 | 回头看定位与栏目（08 册） | 定位是否要重做、栏目是否增减 |

## 三、单篇复盘四问

1. **这篇的目标是什么**（涨粉 / 私域 / 品牌 / 互动，按 08 册主目标轮换）？达成了吗？
2. **哪个环节最弱**：打开率低 → 标题封面（10 册）；读完率低 → 结构开头（11 册）；分享低 → 观点密度；搜索来源低 → 关键词（12 册）。
3. **哪个动作有效**：可复用的写进经验库，不可复用的写清原因（时机 / 选题 / 平台规则变化）。
4. **下一篇改哪一处**：只改一处，方便归因。

## 四、找共性（月度）

- 拉近 8 篇数据，按打开率排序，看**头部 2 篇和尾部 2 篇**差在哪（标题句式、选题类型、长度、配图数、发布时间）。
- 只在**同类选题**之间比：拿爆款教程文和爆款观点文比没有意义。
- 连续 3 篇同一类选题明显跑赢 → 把它升级成栏目（08 册第四节）。
- 连续 3 篇明显跑输 → 暂停该选题类型，写清暂停原因再重启。

## 五、归因纪律（让结论站得住）

- **单篇波动不等于趋势**：一篇异常先看发布时机、是否有外部转发、是否撞上平台活动。
- **变量一次只动一个**：标题、封面、长度、排期一次只动一个，否则无法归因。
- **数字来源统一后台**：不混用第三方统计与后台口径。
- **不追单篇爆款**：把可复制的动作找出来，比复制一次爆款更有价值。

## 六、经验沉淀（与内容复盘技能衔接）

- 复盘结论按 fxai-content-review 的台账格式落进 SQLite，同类问题在**本领域内累加「第几次出现」**。
- 反复命中的经验按技能规则晋升为领域经验；开工前读 `{data_dir}/经验库_文章.md`（SKILL.md -0 节）。
- 每条经验写成「下次该怎么改」，不写「以后注意」这种没法执行的句子。

## 七、运营档案回写

复盘完成后回写《公众号运营档案》：已发文章登记（标题、发布日期、数据窗口、关键指标）、待复盘文章出结论结案、选题池按数据结果增删（09 册）。
档案与本册的关系：档案记「这个账号发生了什么」，本册记「怎么复盘」；两者都留在工作区，技能里只留方法。
