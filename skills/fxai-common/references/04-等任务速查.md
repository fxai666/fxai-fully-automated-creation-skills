# 等任务速查：等法对照、task_id 三态与云端冷却期

**何时读**：派后台任务、开机等 GPU 之前查等法对照表与故障处置时

| 等待对象 | 等法 | 常见错法（照左列的等法改） |
|---|---|---|
| **ComfyUI 任务** | `fxai-comfyui-watcher` 的 `wait <pid>`（自己连WS 守着 `fxai:task_saved`＝合并/保存完毕才退出） | `sleep` + 反复 curl `/history` / `/queue` / `/fxai/tasks/result` |
| **本机后台 Bash**（`run_in_background`） | 任务完成会**自动推 `<task-notification>`**；同时做别的去 | 反复 `TaskOutput(block=true)` 空等 |
| **云端实例开机** | `xgy_guard.ensure_online()` 轮询 booting→running 直到就绪 | 平台限流期反复 boot（见下方冷却） |

- **task_id 三态，别混用**：
  - 本机后台 Bash → `task_id` 是命令回显里的 **shell id**（形如 `iTJj7I`），`TaskOutput` 能读；
  - 子代理 → agent id（形如 `xxx@_auto_xxx`）**不是** shell id，喂给 `TaskOutput` 报 `No task found`；
    要子代理结果等 `<task-notification>`；
  - `TaskOutput` 报 `No task found` 时**先核对 id 来源**；换个 id 接着阻塞等仍是空等。

## 判据：界面没动静 ≠ 任务卡住

出现「看起来卡住」时，**先分清三种情况再决定动作**（「再等久一点」会掩盖判断缺失）：
1. 任务本身慢（生图/渲染确实要几分钟到几小时）→ 继续干别的，等通知；
2. 我自己阻塞在等待调用上 → 立即退出等待，改做别的；
3. id 传错 / 任务压根没起来 → 核对 id 与启动日志。

## 云端实例释放 GPU 后有冷却期

`stop --release-gpu` 关机后**立刻** `boot` 会被平台拒（`code=1000 该实例暂时无法进行操作`）。
**正确顺序**：等实例状态真正回到 `shutdown`（`xgy_guard.py list` 可看）再开机，手动验证要留足冷却。
