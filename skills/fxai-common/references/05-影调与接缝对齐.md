# 影调与接缝对齐（`video_tone.py`）

**何时读**：分段生成后要拼成一条、段间亮度或色温对不上；或者画面「发灰」「像蒙了一层雾」要查原因。

**一句话**：拼段之前过两道工序 —— ① 影调对齐（乘法增益，把每段拉回参考色阶）
② 接缝对齐（加法平移，把本段首帧贴到上一段末帧）。**顺序不得颠倒。**

---

## 一、为什么分段一定会跳色

H3 每一段都是从噪声独立跑出来的，模型对「整屏曝光 / 色温」**没有跨段记忆**。

实测（608×1056 / 216 帧 / 两段）：接缝处整屏亮度掉 **1.6~2.0 灰阶**，
而全片正常的帧间亮度变化 95 分位只有 **0.6~0.7** —— 接缝处是正常变化的近 3 倍。
帧差指标（PSNR/SSIM）看不出来，因为被大量本来就在微动的像素稀释了，但眼睛一眼就看见。

**提示词管不了这件事**：正向写 `bright/evenly lit` 四角一个灰阶没动，
负向写 `no darkening` 反而更暗。曝光只能在画面上后处理。

---

## 二、两道工序各自解决什么

| | ① 影调对齐 | ② 接缝对齐 |
|---|---|---|
| 数学 | **乘法**（整段 × 增益） | **加法**（整段 + 逐通道偏移） |
| 修什么 | 亮度 + **对比度**（「发闷」的正解） | 只修亮度/色温的**绝对差**，对比度绝对不变 |
| 参考 | 参考片（源片）或第一段 | 上一段的**末帧** |
| 上限 | 增益卡 `[0.7, 1.4]` + 最大调整 20 灰阶 | 单通道 12 灰阶 |
| 越界行为 | **跳过**（像素一点不动） | 截断到上限；差超 30 灰阶判定换场、**不接** |
| 靠什么 | 背景区采样 + 剔离群块 | 首帧/末帧逐通道均值 |

**为什么必须 ① 在 ② 前面**：影调先把每段拉回参考，接缝再消残余跳变。
反过来的话，影调的增益会把接缝刚做好的平移又乘一遍，越修越偏。

---

## 三、影调为什么会算出「灾难值」，怎么拦的

暗背景段子上，背景四块采样会全是噪声级的小数（实测生成 70/3/6/11，源片 29/1/5/2），
四个比值 0.411 / 0.335 / 0.923 / 0.173 剔掉最离群的一块后平均成 **0.2986** ——
整段亮度砍到 30%，对比度从 44.3 塌到 13.6，画面像蒙了一层灰雾。

前两段没事，是因为每段都有一块 84 左右的亮区被当离群值剔掉了；
这一段四块全暗，没有离群值可剔，四个噪声级的小比值直接平均成了灾难。

**所以卡死 `[0.7, 1.4]`**：实测正常漂移只有 12%（比值 0.87），±40% 已远超正常范围。
超出去就判定采样不可靠 → 本段跳过、像素一点不动，交给接缝按上一段末帧平移，段间照样不跳。

> 试过更复杂的「总量比」方案（拿整段总亮度当裁判），离线回放显示三段全被跳过
> —— 包括原本正常的第 1、2 段。**只留范围检查这一条**。

## 四、采样区怎么选

| 采样区 | 取哪 | 什么时候用 |
|---|---|---|
| **八方位**（默认） | 3×3 网格去掉正中那块，8 块一起估 | 默认。中间一定是人物，采进来会被服装主导；八方位能扛住 4~5 块被侵占 |
| 四角 | 4 个角块 | 能扛住 1~2 个角被人物侵占 |
| 上部 | 只有上两角 | 及地长裙 / 阔腿裤挡满下半幅时最稳 |
| 边缘带 | 上下左右四条边带 | 人物占满左右的镜头 |
| 全图 | 整帧 | 只在空镜用，有人物时会被服装带偏 |

聚合方式是「**剔掉最离群的一块再平均**」，不是中位数：
中位数会让暗角占更大权重，算出的增益偏大（黑蕾丝那版从 +0.26 恶化到 +2.17）；
纯平均又会被伸进画面的长裙拉高，真正的背景角欠校正 5~7 个灰阶。

**背景全黑**（舞台、夜景）时四角/八方位都会采到噪声 → 换「上部」，或者干脆让范围检查拦掉。

## 五、接缝的两个保险

1. **单通道偏移卡 12 灰阶**：万一参考帧本身是闪白/黑场，也带不跑整段。
   正常段间差只有 10 灰阶左右，够用；不够就把 `--seam` 调到 20~24。
2. **跳变超 30 灰阶判定换场、不接**：口播/幻灯片这类同一场景的分段，段间差只有十几灰阶；
   剪辑类技能拼的是不同镜头，硬接会把两个场景拉成同一色阶，画面反而变味。

另外：**第一段没有上一段**，参考为空，原样透传 —— 这是设计好的，不是漏了。

## 六、用法

```bash
# 先看量再动手（推荐：先 --dry-run 确认每段校正量合不合理）
python video_tone.py --in s1.mp4 s2.mp4 s3.mp4 --dry-run

# 真跑，校正后的段落到 outdir，文件名带序号，顺序与入参一致
python video_tone.py --in s1.mp4 s2.mp4 s3.mp4 --outdir tmp/tone

# 有源片就把源片当参考（效果等同节点接「参考序列」）
python video_tone.py --in s1.mp4 s2.mp4 --ref 源片.mp4 --outdir tmp/tone
```

```python
import video_tone
fixed = video_tone.align(["s1.mp4", "s2.mp4", "s3.mp4"], outdir="tmp/tone")
# fixed 与原列表等长同序；没动的段返回原路径，直接拼即可
```

**校正量小于半个灰阶的段不重编码**，原路径直接返回 —— 分段多的时候省一大截时间，
也省掉无谓的二次压缩损失。

## 七、实测（3 段合成片，每段背景亮度不同、第三段还偏了色温）

```
背景亮度（八方位均值，灰阶）    原片 → 校正后
  第1段                          178.3 → 178.3（锚点，不动）
  第2段                          159.3 → 176.8
  第3段                          149.0 → 176.5

接缝跳变（上一段末帧 → 本段首帧）
  段1→2    原 −17.7 灰阶  →  校正后 −1.4 灰阶
  段2→3    原 −11.2 灰阶  →  校正后 +0.7 灰阶
```

剩 1 灰阶左右是 8 bit 取整 + 最大调整 20 灰阶钳制的余量，肉眼不可见。

## 八、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志「比值 ×N 超出 0.7~1.4，跳过」 | 背景太暗/闪白/构图突变，采样不可靠 | **正常行为**，画面不动；需要修就换 `--region 上部` 再试 |
| 日志「跳变 N 灰阶，判定换场，不接」 | 段间差超 30 灰阶，判定是不同镜头 | 是同一场景就调大 `--seam-cut`；是剪辑类拼接就别接 |
| 段头明显偏亮/偏暗 | 接缝按**原始**首帧算了，没算影调的增益 | 用 `align()` / 命令行（内部已按影调校正后的值算）；自己调 `plan_seam` 时必须传 `tone` |
| 整片发灰 | 增益被算成远小于 1 | 已由 `[0.7,1.4]` 拦掉；还发灰就 `--mode 不启用` 排除本模块嫌疑 |
| 拼接后音画不同步 | 重编码丢了音频 | 本模块 `-c:a copy` 保留音频；上游若已无音轨，先补再拼 |
