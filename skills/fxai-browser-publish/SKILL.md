# fxai-browser-publish · 自动发布

本技能定义的是**一套实现自动发布的规范与技术路线**，不是某个站点的投稿脚本。包内不预置任何站点、账号、凭据、选择器与本机路径；站点差异全部由使用方在**实例目录**里按本规范创建，命中即复用。照 01 / 02 / 03 册即可从零接入任意站点。

## 直接开跑

```bash
python -B scripts/init_hub.py --hub "<发布目录>"      # 幂等生成骨架
python -B scripts/resolve_hub.py --check             # 自检指针来源
cd "<发布目录>" && python cli.py check               # 实例侧命令，见 01 册
```

实例目录的 `cli.py` 与 `core/` 由使用方按 01 册落地；本包只给规范、骨架与校验脚本，**不携带实例实现与站点记录**。

## 初始化之后先做这件事

初始化会生成 `config/接入清单.md`。**接任何站点之前先读它**：接入单位是「**站点 × 内容类型**」这一格，不是站点——站点层记登录与通用文案，类型层各记一份发布页地址、入口动作、字段与视口指纹（见 02 / 03 / 10 册）。只为确实支持的类型建键，建键即承诺支持；地址为空保持 `unverified`；同一站点不同类型是两个地址，各验各的。每接完一格用 `goto <站点> --type <类型>` 判命中并复跑一次确认零写盘，跑通即把动作序列、手法与坑回写该格 `path_log`（见 09 / 11 册）。**接站时同时定文案档位 `copy_profile`，未标注按大众向（见 13 册）**。

## 铁律速查（常驻）

1. 🔴 **技能包零站点**：包内不得出现平台名称、域名、接口路径、选择器、按钮文案、字数上限；站点一律抽象为「站点」。
2. 🔴 **站点记录只落实例目录**：站点条目、账号、登录态、选择器、按钮文案只由运行时写进实例目录；跑通即回写，包内零记录。
3. 🔴 **四层不混放**：L0 本包＝规范；L1 全局配置＝实例目录指针；L2 实例目录＝站点与账号；L3 项目目录＝成片 / 物料 / 回执。
4. 🔴 **两种交付模式**：默认直接发，`--draft` 存草稿，`--dry` 只调试；执行前过发布单「授权模式」行，票据缺失即拒绝。见 08 册。
5. 🔴 **只从项目目录拿成片**：只读输入，不重剪、不转码；发布物料与回执写回同一项目目录。
6. 🔴 **凭据零外泄**：profile、cookie、二维码、账号注册表只留实例目录，不得进技能包、发布包、版本库，不得打印内容。
7. 🔴 **多账号按账号隔离**：一个浏览器持久化目录只装「一个站点 × 一个账号」；任务队列带账号字段。
8. 🔴 **AI 生成必须标识**：任务一律标 AI，页面有声明入口就勾，文案内需有显式标识；平台选项不等于合规完成。
9. 🔴 **结果页 URL ≠ 作品链接**：回执区分「已提交 / 审核中 / 已发布 / 被拒 / 发布未验证」。
10. 🔴 **页面改版只改实例配置**：选择器全在实例目录站点条目里，用 probe 导出 DOM 校准。
11. 🔴 **项目清单与记忆只由脚本写**：`fxai_project.py init <项目目录>` 建档、`stage --publish` 登记、`memory --add` 记决策；不得手写 JSON。
12. 🔴 **浏览器运行时走公共件**：Chrome 检测与补装统一调 `fxai-standard/scripts/ensure_chrome.py`，不自造一份。
13. 🔴 **运行一律带 `-B`**：技能目录内不得写入缓存、字节码、素材或产物。
14. 🔴 **地址直达、只分析一次**：发布页地址记在站点条目 `types.<类型>.upload_url`，召唤时一步打开；命中即复用、零分析零写盘，失效才重校准。见 09 册。
15. 🔴 **按内容类型选渠道**：视频 / 图文 / 文章各走各的地址与字段，`--platform all` 展开到所有支持该类型的站点。见 10 册。
16. 🔴 **扫码走不通就手动登**：只有短信验证码的站点开有头窗口由用户亲手登，不代填手机号、不代收验证码；登完自动接管落盘。见 10 册。
17. 🔴 **原创声明与来源台账分离**：声明按实际沿用比例判断，全场景替换可按原创；素材来源与授权凭证一律保留并记台账，发布单必列授权核查项。与 AI 声明二选一时优先 AI 生成。见 07 册第九节。
18. 🔴 **动作台账按格回写**：打通一格即把动作序列、有效手法与坑写进 `types.<类型>.path_log`；下次照台账执行，只校选择器。见 11 册。
19. 🔴 **文案按档位分写**：`tech` 技术名词前置、可写实现；`mass` 娱乐化钩子，不得写技术名词与制作过程，按正常作品发布；两档均保留 AI 显式标识。档位取实例目录 `copy_profile`（类型层可覆盖），未标注一律 `mass`。见 13 册。
