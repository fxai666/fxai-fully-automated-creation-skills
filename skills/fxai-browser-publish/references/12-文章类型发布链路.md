# 12 · 文章类型发布链路

文章与视频不是同一套流程：视频要等上传、要选封面截帧、要等转码；文章是富文本编辑器，正文靠注入。
这一册定文章类（`article`）从「正文已定稿」到「四站全上线」的完整口径。

## 一、口径：确认即直发，只有公众号走草稿

| 站点类型 | 默认动作 | 理由 |
|---|---|---|
| 一般内容平台 | **直接发布** | 绕开「先存草稿再去草稿箱点发布」的两段流程，少一次跳转、少一次等待、少一轮 token |
| 微信公众号 | **进草稿箱** | 群发不可撤回，且图文必须先在公众号后台成稿再群发 |

- 文章定稿、物料齐备、发布单已确认后，走全域发布链路一次发完，**不做「存草稿 → 人工确认 → 再发布」的中转**。
- 起草阶段需要看排版的，用 `run --dry`（只填不发）或 `run --draft`（落草稿箱），这是调试手段，不是正式链路。
- 授权模式仍只认发布单的 `授权模式：publish` / `draft` 行；写 `publish` 就是直发。

## 二、配置优先级：类型层压站点层

文章页与视频页的按钮、封面控件、字段常常完全不同，取配置时**一律类型层优先**：

```
entry（types.article）有该键 → 用它
否则回落 pconf（站点级）
```

实现是一个函数，不准各处手写 `entry.get(...) or pconf.get(...)`：

```python
def _cfg(entry, pconf, key, default=None):
    v = entry.get(key)
    return v if v is not None else pconf.get(key, default)
```

站点级 `extra_post` 是视频流程的收尾动作（封面截帧弹窗、创作声明），文章流程**只跑 `entry.extra_post`**；
混用会让文章流程空等视频元素直到超时。

## 三、正文注入四选一

| 方式 | 配置 | 适用 | 判据 |
|---|---|---|---|
| 导入文档 | `body_mode: import_md` + `media_inputs` | 平台支持直接吃 .md / .docx | 导入后编辑器字数 > 300 |
| 剪贴板粘贴 | `body_mode: paste_html` + `clipboard_first` | Draft.js / ProseMirror / Lexical 受控编辑器 | 平台自带的字数统计会变 |
| 插入 HTML | `body_mode: paste_html` | UEditor 或自研非受控编辑器 | 回读 innerText 与原文长度相当 |
| 纯文本兜底 | 自动 | 前三种都失败 | 内容在、格式丢，仅保证不空 |

- **受控编辑器必须走 paste 事件**：直接改 DOM（`insertHTML`、`innerHTML`）不进编辑器内部状态，页面看着有字，保存下来是空的。
- 剪贴板首选的站点直接配 `clipboard_first: true`，勿让它先试 `insertHTML` 白白丢一次。
- 判「注入成功」用回读长度对比原文长度的比例，无需完全相等——平台的字数统计口径与原文不同（去标点、去空白、按中文计字）。

## 四、标题的两个坑

| 现象 | 处置 | 配置 |
|---|---|---|
| 标题平时是「显示态」文本，点一下才变成 input | 先点显示态再填 | `fields.title_display` |
| 导入文档后标题被文件名覆盖 | 正文注入完再重填一次 | `title_last: true` |

标题超站点上限时先截断再填（`limits.title`），勿等提交时被平台打回。

## 五、封面：三种结构

| 结构 | 判据 | 配置 |
|---|---|---|
| 页面上直接有 file input | 一个 `input[type=file][accept*=image]` | `cover_inputs` |
| 先点开弹窗，弹窗里再上传 | 封面是必填项，不设就打回 | `cover_flow` |
| 默认关闭的开关 + 虚线占位框 | 「自定义封面」是个 switch，关着时不显示上传位 | `cover_flow` + `click_js_near` |

`cover_flow` 是一串动作，文件路径用占位符 `@cover`，运行期由任务里的封面替换：

```json
"cover_flow": [
  {"action": "click_selector", "selectors": ["…打开弹窗的元素…"], "label": "打开封面弹窗"},
  {"action": "wait", "ms": 3000},
  {"action": "set_files", "accept": "image/*", "value": "@cover", "label": "上传封面"},
  {"action": "wait", "ms": 3500},
  {"action": "click_js_text", "texts": ["确定"], "prefix": true, "label": "确认封面"}
]
```

五个要点：

1. **按 accept 筛文件输入**：同一页面常同时存在 `video/*` 与 `image/*` 两个隐藏 input，按 class 猜必错。
2. **系统文件对话框不可靠**：`filechooser` 事件能拦到、`set_files` 也执行了，但页面没读到文件；直接对 `input[type=file]` 赋值才生效。
3. **确认按钮带计数**：弹窗里是「确定 (1)」，精确文本匹配必然落空，用 `prefix: true` 前缀匹配。
4. **先导后传的弹窗要再确认一轮**：CSDN 上传后弹「图片编辑」，必须点「确认上传」才落图；不点则弹窗一直盖着，后面的标签选择全被挡住。
5. **开关型封面不得点文字**：B 站「自定义封面」是 `label` + `vui_switch` 两件套，点 label 只弹提示。用 `click_js_near`（给文字、给控件选择器，在同一表单行内找控件再点）：

```json
{"action": "click_js_near", "texts": ["自定义封面"],
 "selectors": ["div.vui_switch--switch"], "label": "打开自定义封面开关"}
```

`click_js_near` 自带幂等：控件 `aria-checked` 已是 true 就返回 `already-on`、跳过点击，防止把开关点关。

### 编辑器在 iframe 内时

`cover_flow` / `submit_confirm` 会自动套用正文作用域：B 站整套编辑器（发布设置、开关、上传控件）都在 `york/read-editor` iframe 里，用主文档 locator 一个也找不到。动作里凡是 locator / evaluate 都跑在作用域上，`click_point` 与 `page.mouse` 仍走主文档坐标系——iframe 内勿配坐标点击。

## 六、提交按钮与后续确认

| 情形 | 配置 |
|---|---|
| 提交按钮在 iframe 内 | `submit_selector`，按 正文作用域 → 标题作用域 → 主页面 依次找 |
| 点了提交还要再确认一轮（选标签、填分类） | `submit_confirm`，一串动作 |
| 提交后不跳转，只在弹窗里给「点击查看」 | `success_link_texts`，顺着点进去取真实作品地址 |

- `submit_selector` 用 Playwright 精确文本写法 `text="发布"`；`button:text-is("发布")`、`text-is("发布")` 都无效。
- 同一词在页面出现多次（工具栏一次、弹窗一次）用 `click_js_text`：按可见性 + 文字取最后一个，比坐标稳，也不怕弹窗位移。
- 成功判定不是「URL 变了」就算成：很多站点提交后就地弹窗。必须配 `success_hints`，命中弹窗文案才判 `published`。
- 提交成功后的回执优先取作品页地址；只有后台页面地址时，按标题去内容管理列表定位公开链接，再回填。

## 七、四个站的实际手法

| 站点 | 正文 | 标题 | 封面 | 提交 | 坑 |
|---|---|---|---|---|---|
| CSDN | 导入 .md | 显示态点开 + 正文后重填 | 发布弹窗内「添加封面 → 从本地上传」 | 弹窗内选标签后点「发布文章」 | 标签必填；上传后要再点「确认上传」；`**文字。**` 句号在加粗内不渲染 |
| 百家号 | 剪贴板 HTML | 直接填 | **弹窗 + 必填** | 底部「发布」 | 不设封面点发布会静默失败，只弹 700ms 的「请添加封面」 |
| 知乎 | 剪贴板 HTML | textarea | 可不设 | 直接发布 | Draft.js 受控，`insertHTML` 后字数统计仍是 0；无存草稿按钮，编辑即自动保存 |
| B 站 | 剪贴板 HTML | iframe 内 textarea | **「自定义封面」开关默认关闭** | iframe 内「发布」 | 不打开开关就没有标题图，平台自动抓正文文字当封面；提交成功后弹「你的专栏已提交成功」但不跳转 |

| 站点 | 封面步骤 |
|---|---|
| CSDN | 点「发布文章」→ `input.el-upload__input` 塞图 → 弹「图片编辑」→ 点「确认上传」→ 再选标签 → 发布 |
| 百家号 | 点封面槽位 → 弹「正文/本地上传」→ `input[type=file][accept*=image]` 塞图 → 点「确定 (1)」 |
| B 站 | 展开发布设置 → 打开「自定义封面」开关 → 点 `.select-cover` → 塞图（`accept=.png`）→ 弹「选择封面的截取位置」→ 点「确定」 |

B 站封面校验不得看 `.select-cover` 在不在：上传成功后它就没了（换成预览图）。改判「同一 form-item 内有 `img`」或出现「重新上传」。

标题长度上限各不相同（知乎/CSDN 宽、B 站 40、百家号 64），按 `limits.title` 截断，勿一套标题硬套。

## 八、跑完必须核的四件事

1. 四站任务状态是否都落到 `published`，`result_url` 是否是可打开的公开地址。
2. 公开地址能否 200（CSDN、知乎会拦无头流量返回 403/404，改用浏览器打开核对标题）。
3. 提交后无跳转的站点，是否已在平台内容管理里确认「已发布 / 审核中」。
4. 公众号是否只落草稿、未群发。
