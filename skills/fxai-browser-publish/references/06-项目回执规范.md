# 06 · 项目回执规范（脚本登记 + 独立 MD）

> **何时读**：发布后把站点、账号、地址、状态写回项目目录时。

## 一、数据落点

| 落点 | 内容 | 由谁写 |
|---|---|---|
| `_fxai_project.json` | `stages.publish` 阶段状态（0 未开始 / 1 部分 / 2 完成） | **只能** `fxai_project.py stage` |
| `_fxai_memory.md` | 一条发布决策 / 风险记忆 | **只能** `fxai_project.py memory --add` |
| `发布材料清单.md` | 成片规格、封面、逐站文案、物料状态、关联发布单 | 发布能力生成 / 更新 |
| `发布信息.md` | 站点、账号、标题、地址、状态、备注（人读账本） | 发布能力生成 / 追加 |
| `交付清单.json` | 交付物清单 | 由既有项目流程维护，发布能力不直接改 |

硬规则：**绝不手写或字符串替换 `_fxai_project.json` 与 `交付清单.json`**。要改就调脚本，脚本自己写时间戳、自己维护结构。

## 二、脚本命令

```text
# 项目目录建档（产物目录建好即执行）
python fxai_project.py init "<项目目录>"

# 点亮 / 更新 publish 阶段
python fxai_project.py stage "<项目目录>" --publish 2

# 记一条发布决策（--tag 可选 约定/决策/待办/风险）
python fxai_project.py memory "<项目目录>" --add "<日期 首发站点与账号>" --tag 决策

# 仅当项目本来就有分集结构时，登记该集发布物料
python fxai_project.py deliver "<项目目录>" --no 1 --publish "发布信息.md"
```

`deliver` 必须给集号，且会给无集项目新建一条 episode。单集项目没有 `episodes` 时，勿为登记而硬造一集，用 `stage --publish` + `发布信息.md` 即可。

阶段词表含 `publish`（`script / image / audio / video / publish`），无需改全局标准。首次发布确认后再点亮，勿在「发布单待确认」阶段就写成 2。

## 三、发布信息.md 结构

用 `templates/发布信息.md`。每次发布后**追加**一行记录，不覆盖历史：

```text
| 日期 | 站点 | 账号 | 标题 | 作品链接 | 状态 | 备注 |
```

状态只用状态机里的词：`待确认 / 已提交 / 审核中 / 已发布 / 被拒 / 发布未验证`。

## 四、状态机与链接要求

```text
待确认 → 已提交 → 审核中 → 已发布
                    ↘ 被拒
                    ↘ 发布未验证（published_unverified，需人工看结果截图）
```

- 确认发布后返回的 `result_url` 是**投稿结果页 URL，不等于公开作品链接**。
- 刚提交时状态写「已提交」，链接栏写「待补公开链接」，备注里记结果截图路径。
- 拿到平台公开链接后再把同一行改成「已发布」，链接填真实作品地址。
- `published_unverified` 不许美化成「已发布」。

## 五、回写流程

```text
1. 确认发布单 → 建任务 → 预览 → 确认发布
2. 读任务队列里该任务的 platform / account / title / status / result_url / preview_path
3. 追加一行到项目目录 发布信息.md
4. python fxai_project.py stage "<项目目录>" --publish 2   （仅全部确认发布完成后）
5. python fxai_project.py memory "<项目目录>" --add "<日期 首发站点与账号>" --tag 决策
6. 更新 发布材料清单.md 的状态字段；发布单状态改为 已执行
7. 页面显示审核中时，状态保持「审核中」，后续人工复查再更新
```

## 六、项目管理可读性

`_fxai_project.json` 的 `stages.publish` 供项目页展示逐阶段进度；`发布信息.md` 供人查看「发到哪些站点、地址在哪里」；两者互补，不互相替代。实例目录的任务队列是运行台账，**不是**项目回执，勿把数据库路径当成项目发布信息。
