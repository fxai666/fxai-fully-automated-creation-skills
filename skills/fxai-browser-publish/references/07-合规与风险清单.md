# 07 · 合规与风险清单

> **何时读**：发布前逐条过一遍；任何一条没结论，就写进发布单的「待确认 / 风险」栏，不得略过。

## 1. AI 生成合成内容标识（法律硬要求）

- 《人工智能生成合成内容标识办法》自 2025-09-01 施行，AI 生成的视频需**显式**与**隐式**标识。
- 显式：画面 / 文案可感知，加平台声明入口。声明入口找不到时只告警，需人工确认。
- 隐式：文件元数据中的生成合成信息。未落地实现时列为已知缺口，不得宣称合规完成。
- 任务一律带 AI 标记；平台没有该选项时，文案里的显式标识仍须保留。

## 2. 分类 / 专辑 / 分区

- 用户口语里的「其他专辑」须拆成三件不同的事：项目类别、站点分区、站点合集 / 专辑。
- 未登录看到真实下拉项前不得拍板，不得新建专辑，不得误选近似分区。
- 各站点术语不同，逐站 probe 记录真实可选项。

## 3. 回执闭环

- `result_url` 记的是投稿结果页，不是公开作品链接。
- 状态机区分 `待确认 / 已提交 / 审核中 / 已发布 / 被拒 / 发布未验证`；`published_unverified` 不许伪装成已发布。
- 需补齐：审核状态回查、公开链接抓取、按项目汇总。

## 4. 风控与重复搬运

- 同一时刻全量群发同一条成片、文案一字不差，易触发平台审核限流与重复内容判定。
- 措施：错峰定时、逐站文案差异化、标签按站点调整、先发 1–2 站观察审核结果。
- 页面改版只改实例目录站点条目，用 probe 导出 DOM 校准，代码零改动。

## 5. 成片质量

- 成片规格用 `ffprobe` 实测后写进发布单；低分辨率经平台二次压缩后可能更糊。
- 是否先超分 / 增强属用户决策，发布能力不擅自改片，可在发布单里列为建议项。
- 封面若用平台自动截帧，可能命中黑场或糊帧；优先挑清晰帧，设计封面走 `fxai-poster` 与 `qc.py` 门禁。
- **全场景替换类作品可按原创声明**：人物与场景全部重绘、成片无原片可辨主材时可按「原创」声明；素材来源与授权凭证仍须保留并记入台账。见第九节。
- 非全场景替换（局部替换、仅换脸、保留原片背景与构图）按实际沿用比例核清素材授权与声明口径。

## 6. 登录态与账号

- 发布前逐站 `check`，登录态可能过期。
- 未登录或未校准的站点，发布单须如实写「通道待打通」。
- 持久化目录、cookie、storage_state、二维码属凭据，不进技能包、发布包、版本库，不打印内容。
- 多账号必须显式传账号参数，批量发布勿依赖默认账号。

## 7. 外发确认

- 真实发布属外发动作：先出发布单 → 用户明确确认 → 才加确认参数。
- 不带确认参数的 `run` 只预览；带媒体 `probe` 只上传到投稿页、绝不点提交，但会留下未发布草稿，校准前须让用户知情并单独授权。
- 群发、删文、充值、销毁实例等外发动作同样需明确确认。

## 8. 公共包与体系边界

- 本技能属 `fxai-*` 体系，可被打包分享。改完 `SKILL.md` / `references` / `scripts` 后跑 `fxai-standard/scripts/check_standard.py`，ERROR 与 WARN 清零再收工。
- 出包前核查：包内零站点名、零域名、零专属接口路径、零站点分册参数块、零凭据、零本机绝对路径。
- 跨技能改动先问用户；一条规则只在归属技能写全，别处只留一行指针。
- 项目清单与记忆只由 `fxai_project.py` 写，发布能力不手写 JSON。

## 9. 通用能力缺口检查表

发布单里按实际情况勾选，未落地即列为待办风险：

| 项 | 判据 |
|---|---|
| 隐式 AI 标识 | 成片元数据里含生成合成信息 |
| 公开链接回查 | 能从平台取回作品地址并区分审核状态 |
| 封面质检 | 设计封面已过 `qc.py pre\|prompt\|post` |
| 字段校准 | 所有目标站点的字段候选均取自真实表单页 DOM |
| 分类确认 | 目标站点的分区 / 合集真实下拉项已记录 |
| 原创口径 | 声明按实际沿用比例判断；素材来源与授权台账逐项留存 |

## 九、原创声明与素材来源台账

**声明口径**面向平台，**来源台账**面向权利凭证；两者互不替代，原创声明不免除素材授权记录义务。

| 情形 | 判据 | 声明口径 | 素材来源与授权 |
|---|---|---|---|
| 全场景替换 | 人物与场景全部重绘，原片无一处可辨主材（背景、建筑、植被、地面材质全换） | 可按**原创** | 仍须记录并取得授权 |
| 局部替换 | 只换人物或只换背景，原片构图 / 背景 / 音轨大量沿用 | 按实际沿用比例判断，必要时标二创 | 须核清 |
| 仅换脸 | 画面除面部外基本不变 | 二创 | 须核清 |

**声明冲突时的优先级**：不同站点的声明入口形态不一样，按下面三档处理：

| 站点形态 | 处理 |
|---|---|
| 原创与 AI 是两个独立开关 / 独立入口 | 两个都选 |
| 同一个单选项里既可选原创又可选 AI | **选 AI 生成**，原创让位 |
| 只有原创、没有 AI 入口 | 选原创，并在文案里写显式 AI 标识补足 |

AI 标识是法定要求，原创是平台权益；两者撞车时先保合规。

全场景替换的可辨主材由生成模型重新产生，与素材源没有同一画面，故可按原创声明；但素材的取得与使用仍以授权为前提。固定动作：

1. 发布单**必列**素材授权核查项，逐项写明原片出处、授权凭证位置与台账文件；未核清的写入风险栏。
2. 每个交付物填随包《字体与素材授权台账.md》，字体名与协议一并记录（通用规范 06 册）。
3. 站点若有原创声明入口（标签、单选、声明弹层等形态），按上表选原创，不摘除平台默认加的原创标签。
4. 不为「稳妥」把原创改成转载或自制以外的选项——错误声明同样是合规问题。
5. 成片里仍能一眼认出原片场景或原片人物时，回到上表第二、三行处理。
