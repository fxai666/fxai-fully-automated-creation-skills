# 03 · 接入新站点的技术路线

> **何时读**：接入一个尚未配置的站点、校准选择器、页面改版时。
> 本册回答「**遇到一个没见过的站点，怎么把它接进来**」。技能包不认识任何具体站点，只给这条推导路径。

## 一、站点＝一条数据记录

站点标识由使用方在实例目录里自定义，取值统一小写、字母数字与 `_` / `-`。它只是一个键，代码里不得出现按名称分支。

一个站点条目覆盖该站点投稿所需的全部页面知识。能力层（01 册）的步骤顺序、落点、验收判据在任何站点下不变；新增站点＝在 `config/sites/` 下新建该站自己的一个文件，`cli.py` 与 `core/` 零改动。

**顶层键两种形态**：新建实例用 `sites`；既有实例沿用 `platforms` 时，`resolve_hub.py` 两种键都识别。接入新站点按该实例既有键落记录，同一份台账只保留一个顶层集合。

**成立前提**：该站点提供网页投稿入口，登录态可持久化，上传控件可由自动化库驱动。前提不成立时按 01 册第一节补能力，不得为单个站点改写主流程。

## 二、站点条目字段契约

| 字段 | 类型 | 判据 |
|---|---|---|
| `enabled` | bool | 是否参与任务调度 |
| `label` | str | 日志与发布单里的展示名 |
| `login_url` | str | 登录页入口 |
| `login_mode` | str | `qr`（默认，抓码给用户扫）/ `manual`（开有头窗口由用户亲手登，登完自动接管） |
| `types` | dict | **内容类型 → 发布页条目**，见下节；地址、入口动作、命中状态都挂在这一层 |
| `login_cookies` | list[str] | 判定登录态的 cookie 名集合，命中任一即视为已登录 |
| `qr_selectors` | list[str] | 二维码容器候选，按序探测 |
| `qr_refresh_texts` / `qr_expired_texts` | list[str] | 换码控件文案 / 过期提示文案 |
| `video_inputs` / `cover_inputs` | list[str] | 成片 / 封面上传控件候选，按媒体类型精确匹配优先 |
| `fields` | dict[str, list[str]] | `title` / `descr` / `tags` / `cover` 各自的候选 |
| `ai_declaration_texts` | list[str] | AI 生成声明入口的可见文案 |
| `submit_texts` | list[str] | 投稿 / 发布按钮的可见文案 |
| `success_hints` | list[str] | 提交成功提示文案 |
| `login_pre` | list[dict] | 登录页入口动作（点「登录」/切「扫码」），首次登录时记录一次 |
| `extra_pre` / `extra_post` | list[dict] | 上传前 / 填表后附加动作，由动作解释器执行 |
| `notes` | str | 人工笔记，记录该站点的特殊形态 |

字段值一律由 probe 从真实页面导出后填写，不得凭印象编写。字段缺失时留空数组并在 `notes` 里记为「未校准」，该站点不得进入正式任务。

### 内容类型条目 `types.<类型>`

| 字段 | 类型 | 判据 |
|---|---|---|
| `label` | str | 该类型在日志里的展示名，如「视频」「图文」「文章」 |
| `upload_url` | str | 该类型发布页地址；空串表示支持但地址未记录，不算失效 |
| `entry_pre` | list[dict] | 进入该类型发布页的入口动作，与地址一起复用 |
| `media_inputs` | list[str] | 该类型的上传控件候选；缺省回落到站点级 `video_inputs` |
| `arrive_checks` | list[str] | 到达判据候选。纯文字类型没有上传控件，改判标题 / 正文输入框 |
| `arrive_frame` | str | 编辑器在 iframe 里时填 frame URL 片段，到达判据改在该 frame 内匹配 |
| `entry_state` | dict | 视口指纹 / `verified_at` / `hits` / `fails` / `state` |
| `path_log` | list[dict] | **该格的动作台账**：目的 / 动作 / 手法 / 定位 / 坑 / 校验 / 验证时间；跑通即回写，见 11 册 |

只为**确实支持**的类型建键；建了键就等于承诺支持，路由会把它算进渠道。不支持的组合不建键。

### 站点级补充开关（只在该站确实需要时加）

| 字段 | 作用 |
|---|---|
| `tags_in_desc` | 站点没有独立标签框，话题以 `#话题` 写进正文 |
| `tags_in_title` | 站点既没有独立标签框、也没有正文框，只有标题框时，把标签拼在标题末尾；配 `limits.title` 按标题上限裁，放不下就少放一个标签 |
| `title_in_desc` | 站点没有独立标题框，标题就是正文首行，与正文合并一次填完 |
| `title_last` | 上传完成瞬间会用文件名回填标题，需在所有附加动作之后重填收尾 |
| `cover_mode` | 置 `auto` 时不上传封面，用平台自动截帧 / 推荐 |
| `post_cover` | 封面注入之后要做的动作：注入只是把图交给平台的裁剪 / 确认层，还要再点一次确认才生效 |
| `footer_in_desc` | 置 `false` 时公共页脚不参与拼接，用于没有正文框的站（省得日志刷「未找到简介输入框」） |
| `ai_declaration_actions` | AI 声明是「点开 → 单选 → 确定」弹窗时，改用动作序列提交 |
| `limits` | 该站标题 / 正文的字数上限；正文超限时标题与标签整段保住，只从正文尾部按标点收尾 |
| `title_override` | 站点级短标题：上限极小的站用短标题，给标签和正文腾出配额；不影响其他站用的原标题。**写 `auto:N` 表示由本条作品标题自动截取 N 字（默认 10），换作品自动适配**——写死一句短标题的代价是换作品必忘改，会把上一部的标题带进新作品 |
| `tags_before_desc` | 标签排在正文之前；上限小的站必须开，否则按字数截断时先被切掉的是标签 |
| `part_sep` | 段落分隔符，默认两个换行；上限小的站用单换行，分隔符本身也吃字数配额 |
| `common_block` | 置 `false` 时不追加公共文案块（外链受限的站点用） |
| `submit_selector` / `submit_ratio_x` | 提交按钮优先按选择器直取（底部按钮常带稳定的数据属性或固定类名）；只有整个操作栏是一个自定义元素、文字取不到时，才配 `submit_ratio_x` 按栏内横向比例点 |
| `submit_confirm` | 点完提交才弹的二次确认（声明原创 / 分成计划 / 二次确认发布）的动作序列 |
| `submit_probe_s` | 点完提交后轮询成功提示的窗口，默认 15 秒；成功提示常是只闪一两秒的浮层，必须点完立刻轮询才能抓到 |
| `manual_check` | 登记「什么信号才代表这次真的需要人工」：`texts` 校验提示文案、`hint` 给人看的操作说明、`wait_s` 等待上限。命中才把窗口挪回屏幕内等人，没命中就一路走到底——一次性校验按一次性处理，跑通几次后收紧为只在真出现时等 |
| `manual_hint` | 人工接手时横幅上显示的操作说明，写到动作级 |
| `draft_texts` | 存草稿按钮文案候选 |
| `upload_wait_ms` | 该站上传完成的等待时长，视频越大给得越长，等上传完再点发布 |
| `tags_max` | 该站标签数量上限；超限按上限裁，公共标签整组保住 |
| `submit_wait_ready_s` | 轮询等提交按钮从禁用变可点，可点了立刻提交，超时才放弃 |
| `post_upload` | 上传完成、填表之前要做的动作：关掉封面截取等自动弹窗，否则它挡住后面所有点击 |
| `descr_type` | 置 `keyboard` 时描述框改为点进去再键盘输入，用于画布型编辑器；输入前会先全选删除，清掉平台预填的文件名 |
| `wait_click_text`（动作） | 平台自弹的东西（引导气泡、封面截取框、升级提示）出现时间不可预测，用这个动作等它出现再点；配 `wait_s` 等待预算、`times` 最多点几次、`optional` 超时是否跳过 |

## 三、从页面推导候选的通用特征

按页面必然具有的结构特征推导，不按站点名称记忆：

| 目标 | 通用特征 | 排序判据 |
|---|---|---|
| 成片上传控件 | 文件输入控件的 `accept` 含目标媒体扩展名 | 精确扩展名优先 → 媒体大类 → 通配文件输入；同页多个文件输入框时按 `accept` 排除其他用途 |
| 封面上传控件 | 文件输入控件 `accept` 含图片扩展名，或位于封面区域内 | 图片类优先，按容器文案辅助判定 |
| 二维码容器 | 登录页内含画布 / 图片且尺寸接近方形的容器类名 | 候选按序探测，原图放大后交给用户 |
| 标题 / 简介 | 输入框 `placeholder`、`name`、`contenteditable`、富文本编辑器容器 | 优先语义化属性，其次 DOM 层级 |
| 标签 | 输入后可生成词条块的输入框 | 与标题输入框区分，按容器结构判定 |
| 分类 / 分区 / 合集 | 下拉控件与选项列表 | 选项文本来自真实页面，不新建、不臆造 |
| AI 声明入口 | 复选框或开关旁的可见文案 | 文案候选按序匹配 |
| 投稿按钮 | 按钮或可点击元素的可见文本 | 与「保存草稿」「预览」等相邻按钮区分 |
| 成功提示 | 提交后的页面文案或 URL 特征 | 未命中即记 `published_unverified` |

## 四、接入步骤

1. **建条目**：在 `config/sites/` 下新建 `<站点标识>.json`，字段先留空，`enabled` 置 false；一站一文件，各站互不影响。
2. **登记账号**：在 `config/accounts.json` 为该站点建账号注册表与默认账号。
3. **扫码登录**：把二维码大图交给用户手机扫，确认后校验 `login_cookies` 命中，登录态按账号落盘。
4. **只读 probe**：导出投稿页 DOM、截图、文件输入框清单、字段清单、按钮文本，填 `qr_selectors` 以外的上传前字段。
5. **判断页面形态**：若上传前页缺少标题 / 简介 / 标签，判为两阶段投稿页，配置 `form_wait_ms` 并启用轮询等待。
6. **带媒体 probe**：如需拿到上传后表单页，须单独取得用户授权（该动作会上传成片并在平台留下未发布草稿，绝不点提交），导出表单页 DOM 后填 `fields`、`ai_declaration_texts`、`submit_texts`、`success_hints`。
7. **真实下拉项**：记录分类 / 分区 / 合集的可选项，回填发布物料里的分类口径。
8. **置 enabled**：条目字段齐备且用真实表单页验证后，把 `enabled` 置 true，`notes` 记「已校准」与校准日期。
9. **跑通闸门**：先用 `--dry` 出预览截图核对表单，再由发布单确认后按默认模式提交。
10. **回写经验**：把「这次怎么跑通的」写进该站点条目的 `notes` 与实例目录的人工笔记区，命中即复用。

## 五、复用与刷新

| 状态 | 判据 | 动作 |
|---|---|---|
| 已校准 | `notes` 标记已校准、登录态有效、最近一次提交成功 | 直接复用条目 |
| 待复核 | 登录态失效、连续两次提交失败、或页面结构探测命中数骤降 | 重新 probe，覆盖字段候选 |
| 未校准 | 字段留空或未用真实表单页验证 | 停在闸门外，不建正式任务 |
| 页面改版 | 候选全部落空 | 只改该站自己的 `config/sites/<站点标识>.json`，其他站点与代码零改动 |

站点经验只由运行时沉淀到实例目录，跨项目复用；技能包与发布包内保持零站点记录。人工笔记区与自动回写区分离，自动回写不得覆盖人工批注。

## 六、接入验收判据

| 项 | 判据 |
|---|---|
| 改动范围 | 新增站点只改实例配置，`cli.py` 与 `core/` 零改动 |
| 登录 | 扫码后 `login_cookies` 命中，重开会话免扫码 |
| 上传 | 成片上传控件按 `accept` 精确命中，未误选同页其他文件输入框 |
| 表单 | 两阶段页面由字段可见性判定就绪，无固定时长休眠 |
| 闸门 | `--dry` 只出预览截图，平台无新投稿 |
| 校准 | `ai_declaration_texts` / `submit_texts` / `success_hints` 均取自真实表单页 DOM |
| 凭据 | 新增站点的登录态文件落在「站点 × 账号」独立目录，与既有账号零重叠 |
| 合规 | 技能包内搜不到新增站点的名称、域名与选择器值 |
