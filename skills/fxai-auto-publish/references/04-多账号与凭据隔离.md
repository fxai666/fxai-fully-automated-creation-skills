# 04 · 多账号与凭据隔离

> **何时读**：加账号、切默认账号、扫码登录、排查串号或登录态丢失时。

## 一、隔离判据

一个浏览器持久化用户目录只承载「一个站点 × 一个账号」。共用目录时，后登录的会话会顶掉先登录的 cookie，任务队列仍判定旧账号在线，提交即串号。隔离粒度必须同时覆盖持久化目录、登录态备份、二维码图、日志、预览截图与任务记录。

## 二、目录结构（实例目录内）

```text
profiles/<站点>/<账号>/          浏览器持久化用户目录，登录态真正落盘处
cookies/<站点>__<账号>.json      storage_state 备份，供诊断与迁移
logs/qr/<站点>__<账号>*.png     扫码图，按账号区分
logs/<站点>/<账号>/             预览图、失败截图、DOM 快照、任务日志
config/accounts.json            账号注册表：别名 / 备注 / 默认账号
config/platforms.json           全局默认规则（与账号无关）
config/sites/<站点标识>.json    站点条目（与账号无关，一站一文件）
tasks.db                        任务队列，含 account 字段
```

## 三、账号别名硬规则

- 只允许字母、数字、`_` / `-`，长度 1–32，统一小写。
- 禁用浏览器内建目录名与系统保留名。浏览器持久化目录自带 `Default/` 子目录，Windows 大小写不敏感，别名取 `default` 会被误判成「账号目录已存在」，迁移逻辑随即跳过整个目录。默认账号取 `main`。
- 禁用中文、空格、`..` 等，防路径穿越。
- 注册表只存别名、备注、默认账号；凭据一律不进注册表。

## 四、命令形态（实例侧）

```text
accounts list                        列出全部站点的账号、默认账号、登录态有无
accounts add <站点> <账号> --note ""  登记账号
accounts default <站点> <账号>       切默认账号
login <站点> --account <账号>        抓二维码交给用户扫
check <站点> --account <账号>        校验登录态
probe <站点> --account <账号>        用该账号打开投稿页
add --platform <站点> --account <账号> ...
run --account <账号>                 只跑该账号的任务（默认直接发，--draft 存草稿）
```

缺省账号取注册表里的默认账号。批量发布须显式传账号，勿依赖默认值。

## 五、扫码流程

1. 打开登录页，截取二维码原图，放大 4 倍后即时交给用户。
2. 用户在手机端扫码并点确认。
3. 周期检测登录态；仅当页面出现过期提示或达到兜底时长才换码，周期检测时只刷新主图。
4. 命中 `login_cookies` 强标识即判成功，写持久化目录与 `storage_state` 备份。
5. 超时则旧码作废，重跑命令出新码。等待时长给到用户能从容完成扫码的量级。

### 登录判据必须只认「登录后才有的」cookie

抓码前先看清这个 cookie 是**登录后才下发**，还是**匿名访客也会下发**。后者当判据会造成假阳性：
一进登录页就被判「已有登录态」，实际没登，后续发布全部失败在登录页重定向。

| 类型 | 判据 | 处理 |
|---|---|---|
| 会话凭据（登录后才有） | 会话 id、令牌、票据 | 收进 `login_cookies`，命中任一即已登录 |
| 匿名标识（访客也有） | 设备指纹、访客 id、埋点 id、地区标记 | 不得单独作为判据；与别的凭据同时命中时也不加分 |
| 镜像副本 | 同一凭据的 `_BFESS` 之类镜像 | 只作参考，不与原凭据并列当两条判据 |

自查方法：清空该站点持久化目录 → 打开登录页但不登录 → 读 cookie 名。此时出现的名字一律**不得**写进
`login_cookies`。判据宁少不滥：一条真凭据足够，两条假凭据会毁掉整条通道。

### 判成功的顺序：先看是不是还在登录页

任何「已登录」判断都先做一步：当前 URL 是否仍是登录页（路径含 `login` / `passport` / `signin` /
`sso` / `auth`）。**只要还在登录页，cookie 旁证、地址旁证、会话 cookie 统统不算成功。**

原因很直接：地址提示写成裸域名（如「包含站点域名」）时，登录页 URL 自己就含该域名，会被判成「已进入站内」。
手动登录模式下这个误判最致命——窗口刚打开就报「已有登录态」，用户根本没机会登录。

手动登录的成功判据按此顺序，逐条短路过：

1. 命中 `login_cookies` 里的真凭据 → 成功。
2. 仍在登录页 → 未成功，继续等。
3. 已离开登录页且命中 `logged_in_url_hints` → 成功。
4. 已离开登录页且出现会话类 cookie → 成功。
5. 其余 → 未成功。

`logged_in_url_hints` 只写「登录后才可能出现的具体路径」，裸域名不写。

## 六、老单账号迁移

早期结构把 `profiles/<站点>/` 直接当持久化目录、登录态备份为 `cookies/<站点>.json`。入口处统一做幂等迁移：

```text
profiles/<站点>/          → profiles/<站点>/main/
cookies/<站点>.json       → cookies/<站点>__main.json
tasks.account 补列        → 历史任务归 main
```

搬的是**整个目录**，内容零改动，登录态不丢。迁移过程按站点增量检查，全局布尔标记会漏掉后接入的站点。中间态文件与旧的默认别名由迁移逻辑收拢到 `main`。目录占用时先关掉使用该目录的浏览器进程，勿强删。

## 七、凭据边界

| 允许 | 禁用 |
|---|---|
| 规则里描述账号「别名 / 备注 / 默认账号」这类字段 | 技能包内放 cookie 值、token、密码、storage_state |
| 实例目录本机保存持久化目录与登录态备份 | 把这些文件复制进技能包、发布包、版本库、聊天记录 |
| 打印「登录态有效 / 命中哪些 cookie 名」 | 打印 cookie 的 value、浏览器 `Local State` 内容 |
| 注册表存别名 | 注册表存任何凭据 |

实例目录 `.gitignore` 覆盖 `profiles/`、`cookies/`、`logs/qr/`、`config/accounts.json`、`tasks.db`。

## 八、排查串号

| 现象 | 判据与处置 |
|---|---|
| 某账号登录过，`check` 判未登录 | 核对 `--account` 取值；排查是否有别的账号复用了同一持久化目录 |
| 账号目录被埋进旧持久化目录 | 迁移应在所有子命令入口之前统一执行；单站点登记处也需兜底检查 |
| 迁移报「暂存目录已存在」 | 上次迁移中断，人工核对暂存目录内容后放回目标账号目录再重试 |
| 迁移报浏览器占用 | 关掉占用该目录的浏览器进程，勿强删 |
