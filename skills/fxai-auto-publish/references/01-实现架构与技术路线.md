# 01 · 实现架构与技术路线

> **何时读**：从零实现一套自动发布能力、判断通道选型、定状态机与闸门时。
> 本册回答「**这套东西该怎么搭**」，不回答「某个站点怎么点」。站点差异一律按 03 册落到实例目录。

## 一、抽象层级（先建立这个概念）

| 层 | 描述对象 | 形态 |
|---|---|---|
| 能力层 | 一次发布必然经过的步骤 | 定位实例目录 → 校验账号登录态 → 打开投稿页 → 上传成片 → 等待表单 → 填物料 → 预览 → 人工确认 → 提交 → 回写回执 |
| 实例层 | 某个站点的页面控件长什么样 | 站点条目：登录 URL、投稿 URL、二维码容器、上传控件、字段候选、AI 声明文案、投稿按钮文案、成功提示 |

站点差异只落在实例层，由**数据**吸收，不按名称分支。代码与规范都不描述具体站点，因此同一套步骤对任何站点成立：站点条目本身就是全部输入。新增站点＝往实例层加一条记录，能力层零改动。

成立前提：目标站点提供可自动化的网页投稿入口，且登录态可持久化。掉出这个前提的形态与破法：

| 形态 | 破法（补能力，不改路径） |
|---|---|
| 投稿入口有设备风控或强人机校验 | 保持有头浏览器与真实用户目录，降低自动化特征；必要时转人工 |
| 登录只能短信 / 设备扫码且会话极短 | 缩短复用窗口，登录后即时执行，登录态失效即停 |
| 表单由异步脚本分片渲染 | 轮询等待目标字段出现，按字段可见性判定 |
| 媒体地址或上传接口签名化 | 走页面原生上传控件，由页面自己完成签名 |

## 二、通道选型判据

| 判据 | 取值 | 适用条件 |
|---|---|---|
| 官方开放接口 | 优先 | 站点提供公开的视频发布接口、使用方具备应用资质与审核通过、可持有 OAuth 授权与令牌续期 |
| 本机浏览器自动化 | 默认 | 无公开接口、接口门槛高于收益、或需要同时覆盖多个形态不同的站点 |
| 移动端模拟器 / 设备群控 | 排除 | 设备指纹风控、维护成本、登录态迁移成本均高于浏览器通道 |

选定浏览器通道后，全局只保留这一条主通道。官方接口作为后续升级路径：接口就绪时替换「提交」一步，其余（登录态、任务队列、闸门、物料、回执）保持同源，不重写整套实现。

## 三、运行时骨架

- 本机浏览器 + 自动化库，用**持久化用户目录**（persistent context）启动，一个目录只装一个「站点 × 账号」的会话。
- 启动参数固定：浏览器 channel、区域语言、视口、关闭首次运行提示、关闭默认浏览器检查、抑制自动化特征标记。
- 浏览器可执行文件的检测与缺失自动安装统一走 `fxai-standard/scripts/ensure_chrome.py`；实例侧只消费其返回路径，不得自造一套探测逻辑。
- 每次会话结束时导出 `storage_state` 作为登录态备份；持久化用户目录是主登录态，备份文件用于诊断与迁移。
- 会话全程可截图、可导出 DOM；日志按「站点 / 账号 / 任务号」分目录，多账号并行排查时互不覆盖。

## 四、登录态与扫码

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 打开登录页，定位二维码容器 | 命中站点条目里的二维码候选 |
| 2 | 截取二维码原图并放大，交给用户手机扫 | 原图偏小，放大倍数取 4，缩放用最近邻保持可识别 |
| 3 | 用户手机确认后，按周期检测登录态 cookie | 命中站点条目 `login_cookies` 即成功 |
| 4 | 写回持久化目录与 `storage_state` | 后续会话免扫码 |

二维码刷新判据：仅当页面出现过期提示文案，或达到兜底时长，才更换新码；周期检测时只刷新主图、**不换码**。找不到刷新控件时重载登录页重新出码。等待时长给到用户能从容完成扫码的量级，二维码大图须即时送达。

## 五、多账号隔离

- 账号别名统一小写，只允许字母、数字、`_`、`-`；禁用浏览器内建目录名与系统保留名，Windows 大小写不敏感下尤其要避开与浏览器内建 `Default/` 撞名的别名。
- 路径按「站点 × 账号」隔离：持久化用户目录、登录态文件、二维码图、任务日志、预览截图各带账号段。
- 账号注册表只存别名、备注、默认账号；凭据一律不进注册表。
- 任务队列带账号字段；切账号必须显式传账号参数，缺省取该站点默认账号。
- 老单账号结构迁移到多账号结构时做成幂等：整体搬迁持久化目录，登录态文件改名，历史任务的账号字段归到默认账号。

## 六、任务队列与状态机

| 字段 | 用途 |
|---|---|
| `id` / `platform` / `account` | 任务标识与「站点 × 账号」定位 |
| `video` / `title` / `descr` / `tags` / `cover` | 发布物料 |
| `ai_generated` | AI 声明标记 |
| `schedule_at` | 错峰定时 |
| `status` / `attempts` | 状态与重试计数 |
| `result_url` / `preview_path` / `error` | 结果、预览截图、错误信息 |
| `created_at` / `updated_at` | 时间戳 |

状态词表固定为：`pending / running / failed / cancelled / published / published_unverified`。存草稿 / 调试成功后任务回到 `pending` 并只写 `preview_path`。平台「审核中 / 被拒」由人工回查后写进项目回执，代码不自动判定。

队列用单文件关系型数据库，表结构升级走平滑加列；索引覆盖「站点 + 账号 + 状态」与「状态 + 定时」。命令层提供增、列、重试、取消、按状态过滤。

## 七、发布闸门（四道）

1. **发布单**：发布前生成待确认工单，列站点、账号、逐站物料、封面、AI 声明、分类、风险、执行方案，交用户过目。
2. **三种执行模式**：`run` 默认直接发布；`--draft` 填完点存草稿；`--dry` 只填表出截图、不点任何按钮。三者都以发布单的「授权模式」行为前置闸门。
3. **人工确认**：发布单状态改为已确认，且授权范围逐项写明（上传留草稿、真实发布分开授权）。
4. **逐站放行**：优先单站点逐条提交，首发一站观察审核结果，再推其余站点。

含糊的「可以发」不等于同意「上传成片并在平台留下未发布草稿」。两类外发动作分别要授权，授权项写进发布单。

## 八、定位引擎

- 站点条目里每个控件给**多个候选**，按序探测，命中第一个可见且可用者。理由：页面 A/B 改版时只换候选顺序，不动代码。
- 语义化定位分两类：按选择器找控件、按可见文本找按钮 / 声明入口。
- 动作解释器由数据驱动：站点条目里的 `extra_pre` / `extra_post` 描述附加点击与勾选，代码只解释动作类型，不内嵌站点判断。
- 页面改版一律改实例目录的站点条目，用 probe 导出 DOM 校准，代码零改动。

## 九、两阶段投稿页

部分站点把投稿流程拆成「上传前页」与「上传后表单页」：标题、简介、标签、投稿按钮要等媒体上传完成后才渲染。

判据：上传完成后**轮询等待**目标字段出现，超时上限由实例配置的 `form_wait_ms` 控制；用字段可见性判定就绪。固定时长的休眠会随网络与文件体积失效，禁用。上传控件候选按媒体类型精确匹配，避开同一页面里其他用途的文件输入框。

## 十、probe 校准

| 模式 | 动作 | 外发属性 |
|---|---|---|
| 只读 probe | 导出投稿页 DOM、截图、枚举文件输入框、字段、按钮文本 | 纯本地读取 |
| 带媒体 probe | 上传一条成片后导出表单页 DOM，绝不点提交 | **外发**：会在平台留下未发布草稿，须单独授权 |

校准产物用于填写站点条目的字段候选、AI 声明文案、投稿按钮文案、成功提示。未用真实表单页验证的条目，状态记为「未校准」，不得进入正式任务。

## 十一、回执闭环

`run` 直接发布返回的 `result_url` 是投稿结果页 URL，**不等于公开作品链接**。刚提交时项目回执写「已提交」、链接栏写「待补公开链接」并附结果截图路径；拿到平台公开链接后再把同一行改成「已发布」。没匹配到平台成功文案时返回 `published_unverified`，保留该状态并附截图人工核对，不得美化成已发布。

## 十二、失败取证与重试

- 任一环节失败：截图 + 导出 DOM + 写按账号分目录的日志，然后停下。
- 部分站点已提交时，禁用整批重跑；用「按站点放行」只补未发那一站，否则已成功的站点会重复投稿。
- 明确失败的单条任务走 `retry`；确认不发的走 `cancel`。
- 已提交状态的任务先人工到平台核一遍有无草稿或已发布，再决定重试。

## 十三、使用方需要落地的模块清单

技能包只给规范、骨架与校验脚本。照下表实现实例目录里的可执行部分：

| 模块 | 职责 |
|---|---|
| `cli.py` | 命令入口：环境自检、列出站点、账号维护、扫码登录、登录态校验、probe、加任务、列队、试跑、确认发布、重试、取消 |
| `core/accounts.py` | 账号注册表读写、别名校验、按账号生成路径、老结构幂等迁移 |
| `core/browser.py` | 浏览器可执行文件解析、站点配置加载、持久化会话、截图与 DOM 导出、登录态备份 |
| `core/store.py` | 任务表建表与平滑升级、增删查改、按账号与状态过滤 |
| `core/login.py` | 二维码抓取与放大、过期判据、登录态轮询、按账号落盘 |
| `core/engine.py` | 多候选定位、文本定位、动作解释、表单轮询等待、成功文案判定、失败取证 |
| `core/publish.py` | 单任务全流程：校验登录态 → 上传 → 等表单 → 填物料 → 预览 → 确认 → 提交 → 返回状态与结果 |
| `config/platforms.json` | 全局默认规则（视口、等待、超时），由 `templates/实例骨架.json` 初始化 |
| `config/sites/<站点标识>.json` | 每站一个文件：该站的地址、字段候选、开关、动作台账 |
| `config/accounts.json` | 账号注册表，由初始化脚本生成 |
| `tasks.db` / `.gitignore` / `发布单/` | 运行台账、凭据排除清单、审批票据目录 |

## 十四、最小验收判据

| 项 | 判据 |
|---|---|
| 定位 | 不设临时环境变量时，指针解析器返回 `source=global_config` 且自检通过 |
| 骨架 | 初始化脚本重复执行两次，第二次不覆盖任何已存在文件 |
| 隔离 | 两个账号的持久化目录、登录态文件、二维码图路径互不重叠 |
| 闸门 | `run` 不带确认参数时任务数增加、状态仍为 `pending`、平台无新投稿 |
| 状态 | 未匹配成功文案时返回 `published_unverified`，回执里不出现「已发布」 |
| 扩展 | 新增一个站点只改实例配置，`cli.py` 与 `core/` 零改动 |
| 合规 | 技能包内搜不到站点名、域名、盘符、账号别名、凭据值 |
