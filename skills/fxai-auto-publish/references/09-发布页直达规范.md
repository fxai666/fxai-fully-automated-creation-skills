# 09 · 发布页直达规范

> **何时读**：首次打通一个站点、要记录发布页地址、判断已记录地址是否失效时。

## 一、一条地址，只分析一次

自动发布的最短线路只有一步：**按已记录的发布页地址直接打开**。地址即坐标，不存像素坐标、不存点击剧本。

| 阶段 | 动作 | 分析成本 |
|---|---|---|
| 首次（含扫码登录） | 打开候选入口 → 确认最终落地地址 → 记到达判据 → 写入实例目录 | 一次 |
| 之后每次 | 读地址 → 一步打开 → 判到达 → 开干 | 零 |
| 地址失效 | 导出截图与 DOM → 重新确认地址 → 回写 | 一次 |

地址的唯一来源是实例目录站点条目的 `types.<内容类型>.upload_url`。人读清单 `config/发布页直达清单.md` 只作记录，不参与运行，零双源漂移。

**地址的归属是「站点 × 内容类型」，不是站点本身**：同一站点的视频页与图文页往往不同地址，
各记各的、各验各的（见 10 册）。一个类型验证通过不影响另一个类型的状态。

## 二、首次记录判据

1. 登录态已就绪：站点条目的登录态 cookie 命中，且落地 URL 不含登录页特征。
2. 落地地址可直达：从空白页直接打开该地址即可进入投稿页，不依赖首页或创作中心导航。
3. 到达判据可命中：站点条目的上传控件候选里至少一个在超时内出现。
4. 视口指纹一致：记录时写入当前固定视口指纹，复用前比对。
5. 地址不含会话令牌、一次性参数、账号标识。
6. 地址归属到具体内容类型：记录的是「站点 + 类型」这一格，不写成站点级公共地址。

四条同时成立才把状态置 `verified` 并写 `verified_at`；任一条不成立保持 `unverified`，按第三节分析。

## 三、失效判据与重新分析

命中任一即判失效，状态置 `stale` 并累计 `fails`：

| 判据 | 含义 |
|---|---|
| 落地 URL 含登录页特征 | 登录态过期，先重新扫码 |
| 上传控件候选全部超时 | 页面改版或地址变更 |
| 视口指纹与记录不一致 | 分辨率漂移，记录与当前视口不对位 |
| 该类型的 `upload_url` 为空 | 地址还没走到过，先 probe 再记录，不算失效 |
| 落地地址与记录地址不同且带临时参数 | 直达链路被替换 |
| 被重定向回后台首页 | 平台已关闭发布页地址直达；改成「直达后台首页 + 点入口按钮」两级进入，`entry_pre` 记那一下点击 |

失效时才导出截图与 DOM，确认新的落地地址与到达判据后回写；未失效时零截图、零 DOM 导出、零选择器枚举。

「重定向回后台首页」是最常见的一种：地址没错，但平台把直接访问掐掉了，落回工作台。判据是**落地路径退化成后台根路径**（而不是记录里那段发布页路径），此时把 `upload_url` 改成后台首页、把「进发布页」那一下写进 `entry_pre`，比反复猜新地址更快。

## 四、入口动作

有的站点直接打开发布页会被重定向回工作台，必须先点一次入口按钮。把这一步记进站点条目的 `entry_pre`，与地址一起复用。

| 动作 | 字段 | 判据 |
|---|---|---|
| `click_frame` | `frame` + `texts` 或 `selector` | 入口在 iframe 内：按 frame URL 片段定位，只认文字完全相等的 `button` / `a` |
| `click_text` / `click_selector` | `texts` / `selectors` | 入口在主文档内 |
| `click_point` | `x` / `y` | 入口无稳定选择器时按固定视口坐标点击 |

执行顺序固定：打开地址 → 跑 `entry_pre` → 判到达。命中后整条入口动作与地址一起复用，不做二次分析；入口找不到才判失效。

`click_frame` 按 URL 片段找 frame 并轮询等入口渲染；文字判据用去空白后完全相等，只命中按钮本身，不命中说明段落。

## 五、固定视口

| 项 | 取值 | 判据 |
|---|---|---|
| 视口 | `1440 × 900` | 主流创作后台在 1366 以上布局稳定；1440 覆盖笔记本与外接屏，避开响应式折叠 |
| 设备像素比 | `1` | 截图尺寸恒定，跨机器可比对 |
| 截图 | 视口截图、PNG、非整页 | 尺寸恒为 1440×900 |
| 锁定 | 站点条目与默认项都不得在运行时改写视口 | 视口是记录的一部分，漂移即失效 |

视口指纹格式 `宽x高@像素比`，写入站点条目的 `entry_state.viewport`；复用前比对，不一致按第三节处理。

## 六、命令契约

```bash
python -B cli.py goto <站点>            # 一步直达；命中即复用，零写盘零分析
python -B cli.py goto <站点> --verify   # 强制回写状态并刷新直达清单
python -B cli.py goto --all             # 批量预检；无登录态站点本地跳过，不开浏览器
python -B cli.py goto <站点> --force    # 无登录态也打开（会跳登录页，仅用于确认地址）
python -B cli.py probe <站点>           # 仅在失效后使用，导出 DOM 与截图校准
```

输出判据：`ENTRY_OK` 为命中，`ENTRY_FAIL` 为失效，`SKIP` 为本地预检无登录态。

## 七、验收判据

| 项 | 判据 |
|---|---|
| 一次分析 | 站点状态为 `verified` 后，再次直达不产生截图与 DOM 文件 |
| 零写盘复用 | 连续两次直达，配置文件修改时间不变 |
| 单一来源 | 地址只存在于站点条目的 `upload_url`，清单文件不反向写入 |
| 视口固定 | 连续两次截图字节尺寸一致，均为 1440×900 |
| 失效可查 | 状态 `stale` 时必有 `entry_fail` 截图与 DOM，且 `fails` 递增 |
| 省资源 | 批量预检对无登录态站点零浏览器启动 |
| 入口复用 | `entry_pre` 命中后再次直达，入口动作按记录执行，不重新推导 |
| 入口精确 | iframe 内点击只认完全相等的按钮文字，不命中说明段落或父容器 |
