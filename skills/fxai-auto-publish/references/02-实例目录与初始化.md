# 02 · 实例目录与初始化

> **何时读**：指定发布目录、生成或复用骨架、配全局指针、判断「这份数据该放哪」时。
> 本册落实「**没有就创建，有的话就复用**」与四层资料归属。

## 一、四层归属

| 层 | 位置 | 放什么 | 谁共享 |
|---|---|---|---|
| **L0 技能包** | 用户级 skills 目录 `fxai-auto-publish/` | 全局实现规范、架构、技术路线、模板、查找规则 | 所有账号、客户端、项目 |
| **L1 全局配置** | `~/.workbuddy/fxai_global.json` 的 `publish_hub` 段 | **只放一个指针** `hub_dir`（+ 技能名与说明） | 本机所有账号 / 客户端，落盘不随会话丢 |
| **L2 实例目录** | `hub_dir` 指向的目录 | 站点条目、账号注册表、任务队列、登录态凭据、审批票据 | 所有项目共用，按「站点 × 账号」隔离 |
| **L3 项目目录** | 每个项目自己的目录 | 最终成片、发布材料清单、封面、逐站文案、`发布信息.md` | 只属于该项目 |

**一句话**：技能包是「怎么搭、怎么点」的说明书，全局配置是「去哪找工具箱」的指针，实例目录是「有哪些站点和账号、各自怎么点」的台账，项目目录是「这次发什么、发到哪了」的账本。

## 二、L1 全局配置：只放指针

```json
"publish_hub": {
  "hub_dir": "<发布目录绝对路径>",
  "skill": "fxai-auto-publish",
  "note": "实例目录指针：站点条目与账号信息都在 hub_dir 内，不在本文件、不在技能包"
}
```

规则：

- 按能力分一个顶层段，**只增不改**其他段。
- 该段里绝不写站点标识、账号别名、cookie、token、选择器、项目路径。
- 全局配置文件里另有其他能力的敏感字段。指针解析器**只反序列化后取 `publish_hub` 一段**，不枚举、不打印其他字段。
- 改全局配置前先备份；写入后校验「原有顶层字段一个没变」。
- 临时环境变量 `FXAI_PUBLISH_HUB` 只用于本次进程覆盖，不落盘、不改全局配置。它属于会话级，换账号、重开客户端即失效，**不得**当默认来源。

读取优先级：

```text
FXAI_PUBLISH_HUB（临时覆盖）
  > ~/.workbuddy/fxai_global.json 的 publish_hub.hub_dir（默认，跨账号共享）
  > 都没有 → 报错并给出配置指引，绝不猜路径、绝不扫盘
```

## 三、初始化：没有就创建，有的话就复用

```bash
python -B scripts/init_hub.py --hub "<发布目录>"
python -B scripts/init_hub.py --hub "<发布目录>" --check-only
python -B scripts/resolve_hub.py --check
```

幂等判据：目标文件已存在即跳过，绝不覆盖、绝不截断、绝不改写使用者手填的内容。重复执行的输出里，创建项为空、复用项全列出。

初始化动作按顺序：

| 步 | 动作 | 已存在时 |
|---|---|---|
| 1 | 建实例目录与 `config/`、`公共/`、`发布单/`、`logs/`、`cookies/`、`profiles/` | 跳过 |
| 2 | 复制 `templates/实例骨架.json` 为 `config/platforms.json`（全局规则），并建空目录 `config/sites/` | 跳过 |
| 3 | 生成 `config/接入清单.md` 固定检查表（无任何站点，只有「接进来要填什么」） | 跳过 |
| 3.1 | 生成 `config/accounts.json` 空注册表 | 跳过 |
| 3.2 | 生成 `公共/公共文案块.json` 空模板（页脚与通用标签的落点） | 跳过 |
| 4 | 生成 `.gitignore`，排除凭据与运行产物 | 跳过 |
| 5 | 建 `tasks.db` 空表结构 | 跳过 |
| 6 | 备份全局配置后，只增 / 只改 `publish_hub` 段 | 已有指针时只核对，不覆盖别的段 |
| 7 | 输出自检：来源、目录、关键文件、站点数 | 每次都跑 |

站点数为 0 属正常初始状态：站点条目按 03 册逐条接入，技能包不预置任何站点。

### 初始化之后，智能体必须做的第一件事

**读 `config/接入清单.md`，再动手接站点。** 这张表把「一个站点 × 一个内容类型要填到什么程度才算打通」
固定下来，接入时照表逐格填、逐格验：

1. 先定这个站点支持哪几类内容（视频 / 图文 / 文章），只为确实支持的类型建键。
2. 每类内容各记一份发布页地址、入口动作、上传控件、字段候选、命中状态。
3. 同一站点的视频页与图文页是**两个地址**，不许拿一个地址当全站通用。
4. 每接完一个「站点 × 类型」，跑一次 `goto <站点> --type <类型>` 判命中；再跑一次确认零写盘。
5. 地址为空的类型保持 `unverified`，表示「支持但还没走到过」，不是不支持。

初始化产物与接入清单的分工：

| 文件 | 谁生成 | 内容 | 会不会过期 |
|---|---|---|---|
| `config/接入清单.md` | 初始化脚本 | 固定检查表，无站点 | 不会，是规范 |
| `config/platforms.json` | 初始化给空骨架，只放全局默认规则 | 视口、等待、超时等默认值 | 基本不变 |
| `config/sites/<站点标识>.json` | 接入某站点时新建该站自己的文件 | 该站地址、字段、开关、动作台账 | 会，随该站接入更新 |
| `config/发布页直达清单.md` | 运行时 `goto` 生成 | 每个「站点 × 类型」的地址与状态 | 会，每次刷新 |

## 四、实例目录结构

| 路径 | 内容 | 是否含凭据 |
|---|---|---|
| `cli.py`、`core/` | 按 01 册落地的实例实现 | 否 |
| `config/platforms.json` | 全局默认规则（视口、等待、超时），不含任何站点 | 否 |
| `config/sites/<站点标识>.json` | 每站一个文件：该站 `types.<内容类型>` 的地址与命中状态、字段候选、开关、动作台账 | 否 |
| `config/接入清单.md` | 接入固定检查表（无站点），初始化生成 | 否 |
| `config/发布页直达清单.md` | 每个「站点 × 内容类型」的地址与命中状态，运行时生成，只作记录 | 否 |
| `config/accounts.json` | 站点有哪些账号、默认账号、备注 | 否 |
| `公共/公共文案块.json` | 所有站点共用的简介页脚与通用标签；发布时自动追加，改内容只改这一个文件 | 否 |
| `profiles/<站点>/<账号>/` | 浏览器持久化用户目录 | **是** |
| `cookies/<站点>__<账号>.json` | 登录态备份 | **是** |
| `logs/<站点>/<账号>/`、`logs/qr/` | 任务日志、二维码大图、预览与失败截图 | **是**（二维码属登录会话） |
| `tasks.db` | 运行台账（含 `account`、`content_type`），不是项目回执 | 否 |
| `发布单/` | 发布前的待确认工单，运行侧审批票据 | 否 |
| `.gitignore` | 凭据与运行产物排除清单 | 否 |

实例目录里不放成片、封面、逐站文案、项目回执；项目目录里不放凭据、选择器、规范副本。

## 五、凭据边界

- 持久化用户目录、登录态文件、二维码图、账号注册表一律只留本机实例目录。
- 不得进技能包、不得进发布包、不得进版本库、不得在日志里打印内容。
- 账号命令只列别名、备注、默认账号与「有 / 无登录态」，不输出任何 cookie 值。
- 换机器时只迁移使用者自己明确指定的凭据文件，其余由重新扫码生成。

## 六、换账号 / 换客户端 / 换机器

```text
换账号登录 / 换客户端
  → L0 技能包仍在用户级 skills 目录（跨账号共享，不带用户 id）
  → L1 全局配置仍在（落盘）
  → resolve_hub.py 读 publish_hub.hub_dir
  → L2 拿到站点条目 + 账号注册表 + tasks.db
  → 按 L0 的规范继续操作，无需重新教一遍
```

- 换数据根：只需在新机器的全局配置里改 `hub_dir` 一个字段，技能包与全部规范零改动。
- 前提：技能包放在用户级 skills 目录、全局配置放在 `~/.workbuddy/`。若换成另一个系统用户或另一台机器，需重新放置技能包并配置一次 `hub_dir`。
- 换账号后第一次召唤，先跑 `python -B scripts/resolve_hub.py --check`，确认 `source=global_config`。

## 七、防串数据检查清单

- [ ] 技能包里搜不到盘符、项目名、成片路径、真实账号数据、选择器值、cookie 值。
- [ ] 全局配置 `publish_hub` 段里只有一个指针，没有站点或账号数据。
- [ ] 站点条目一律从实例目录 `config/sites/` 下该站自己的文件读，不在对话里凭记忆写死。
- [ ] 账号一律从实例目录 `config/accounts.json` 读。
- [ ] 发布材料从项目目录读，`发布信息.md` 写回同一项目目录。
- [ ] 初始化脚本重复执行后，`config/platforms.json` 与 `config/sites/` 下站点文件的修改时间都不变。

## 八、三张票的分工

| 票据 | 归属层 | 作用 | 状态由谁改 |
|---|---|---|---|
| `发布单/<日期>_<项目>.md` | L2 | 审批票据：这次确认了什么、授权了哪些外发动作 | 出单助手生成；用户确认后改「已确认」 |
| `tasks.db` | L2 | 运行台账：每「站点 × 账号」一条任务与状态 | 只由实例 `cli.py` 写，人不手改 |
| `发布材料清单.md`、`发布信息.md` | L3 | 项目资产台账与人读回执 | 发布能力生成 / 追加 |

三者只互相引用（一行「关联发布单」「关联回执」），不复制正文。
