# 11 · 站点操作路径台账

一格（站点 × 内容类型）跑通之后，把「从打开地址到填完全部字段」的**动作序列、实际有效的手法、踩过的坑**全部写回这一格。下次照台账执行，只核对选择器是否仍命中，不重新分析页面。

台账是**资产**，不是日志。日志记「这次发生了什么」，台账记「下次怎么做才对」。

## 一、存在哪

| 形态 | 落点 | 谁写 |
|---|---|---|
| 机器读 | `types.<内容类型>.path_log`（列表，一步一条） | 运行时脚本 |
| 人读 | `config/操作路径/<站点>_<类型>.md` | 由 `path_log` 生成，不手写 |

`path_log` 挂在**内容类型层**，与 `upload_url`、`entry_pre` 同级：同一站点的视频页与文章页，动作序列本来就是两套。

## 二、一步记什么

| 字段 | 含义 | 例 |
|---|---|---|
| `seq` | 执行顺序，从 1 开始 | `3` |
| `goal` | 这一步要达成什么 | `选择声明项` |
| `action` | 动作类型与参数，与运行时动作同名 | `{"action":"click_text","texts":["请选择…"]}` |
| `method` | 实际有效的手法 | `真实鼠标` / `键盘键入` / `文件注入` / `上溯祖先点击` / `强制点击` |
| `target` | 选择器或文本 | `label:has-text("…")` |
| `pitfall` | 不做会怎样 | `点内部 span 被外层 label 拦截` |
| `check` | 怎么确认成功 | `回读输入框值` / `出现某文案` / `截图位` |
| `verified_at` | 验证时间 | `2026-11-07 05:52` |

`method` 字段是台账的核心价值：**同一个动作，手法错了就是失败**。写「点了下拉」没有意义，写「真实鼠标点选项节点」下次才能一次成。

## 三、点击手法优先级（按这个顺序选，不许跳级）

| 级别 | 手法 | 何时用 | 说明 |
|---|---|---|---|
| 1 | **元素级真实鼠标点击** | 默认手法 | 运行时算元素中心坐标再派发 mousedown/mouseup，事件可信、布局变化不失效 |
| 2 | **坐标点击** | 元素被透明层遮挡、定位器拿不到唯一节点时 | 最"物理"，但坐标随布局与缩放漂移，只作兜底 |
| 3 | **键盘操作** | 下拉可用方向键、输入框需回车确认时 | 对自绘组件同样可信 |
| 4 | **强制点击** | 元素稳定可见但被兄弟节点拦截 | 绕过可点击性检查，仍派发真实鼠标事件 |
| 5 | ~~JS 合成点击~~ | **禁用** | `element.click()`、`dispatchEvent` 产生不可信事件，组件库直接忽略 |

判断依据只有一条：**事件是否可信**。可信事件由浏览器自己产生，页面无从分辨是人是机；合成事件带 `isTrusted=false`，前端组件库、风控脚本都能识别。

**手法对了，时机错了照样失败。** 平台自己弹的东西（新手引导气泡、封面截取框、升级提示、活动横幅）出现时间不可预测：有的在上传完成的瞬间弹，有的要等转码几秒后才弹。排成固定顺序的点击必然扑空，日志只会留下「未出现，跳过」，让人误以为是选择器写错了。

这类目标一律用**等出现再点**的动作（`wait_click_text`）：给一个等待预算，每 1～2 秒轮询一次，出现即点、点完继续，超时按可选跳过、不阻断流程。同一个弹窗可能连弹两次（横屏封面一次、竖屏封面一次），用 `times` 指定最多点几次。台账的 `method` 写「等出现再点」，`pitfall` 写清它比哪一步晚。

## 四、必须记下来的十七类坑

接入时遇到下面任一情形，除了改配置，还要在 `pitfall` 里写清现象与解法。

1. **组件库下拉不吃合成点击**：`dispatchEvent`、`el.click()` 对自绘下拉无效。手法写「真实鼠标点选项节点」——先点触发器展开，再按选项文字精确匹配后点击。
2. **文字节点被外层容器拦截**：文字在 `span` 里、外面套一层 `label` / `role` 容器时，点内部节点报「被拦截」。手法写「上溯最近的可点击祖先再点，仍拦截则强制点击」。
3. **上传完成瞬间回填标题**：有的站点在上传结束那刻用文件名覆盖标题。手法写「所有附加动作之后重填标题」，并用 `title_last` 标记；配套 `input_value()` 回读校验。
4. **表单异步渲染**：上传完成后表单不是立刻就有，等「标题框出现」这个信号，不写固定长睡眠。
5. **编辑器在 iframe 里**：文章类站点常见。手法写 `arrive_frame` 指定 frame 片段，在 frame 内定位，不在主文档里找。
6. **平台默认值陷阱**：默认分区、默认标签、默认可见范围与内容无关。手法写「显式选中目标项」，并把平台默认值原样记进 `pitfall`，提醒下次别以为已经对。
7. **没有独立标签框**：话题只能写进正文。手法写 `tags_in_desc`，以 `#话题` 形式拼进正文一次填入。
8. **AI 声明在弹窗里**：不是勾选框，而是「点开 → 单选 → 确定」。手法写 `ai_declaration_actions` 动作序列，收尾必须点确定。
9. **字数上限**：标题与正文各有上限，超了静默截断。手法写 `limits`，填之前先比对长度。
10. **标签数量上限**：有的站点只收固定条数，多写的直接导致提交被挡。手法写 `tags_max`，按上限裁剪并保证公共标签整组留下。
11. **只读输入框点开才弹层**：声明、分区、合集这类字段，控件本身是 `<input readonly placeholder="请选择…">`，直接往里 `fill` 只会改显示值、不触发业务逻辑，提交时仍是「未选择」。手法写「点这个输入框打开弹层 → 点选项文字 → 点弹层确定」，三步齐全才算选上。
12. **富文本编辑器预填了内容**：有的编辑器在上传完成后拿视频文件名 / 标题预填一段，直接 `type` 是往后追加，字数对不上还夹着无关字样。手法写「点进可编辑区 → 全选删除 → 再键盘输入」，并在 `pitfall` 记下预填来源。
13. **编辑器外层容器不是编辑区**：`div[class*='编辑器前缀']` 这类选择器命中的往往是最外层容器，点它聚焦不到光标，打出来的字落不到正文里。手法写「取内部带 `contenteditable` / `data-lexical-editor` 的节点」，回读 `innerText` 校验字数。
14. **字数上限把标签吃掉**：上限极小的站（几十字），标题加标签就占满配额，正文一写就把标签挤掉；更隐蔽的是分隔符和空格也计入字数。手法写「标签前置（`tags_before_desc`）+ 站点级短标题（`title_override`）+ 单换行分隔（`part_sep`）」，让标题与标签整段保住，只从正文尾部按标点收尾。日志里「标签处理完成 N 个」只代表内存里算过，平台没有标签框时它一个都不会收到，别据此以为加上了。
15. **封面注入不等于封面设好**：注入图片只是把图交给平台的裁剪 / 确认层，接着会弹一个浮层，底部通常有「重选」和「确认」两个按钮，**只点确认那一个才生效**，直接往下走等于没设。手法写站点级 `post_cover` 动作位（等确认按钮出现再点，配 `wait_click_text`）。另外封面常按手机竖版预览，横版图会被裁掉两边，备图时按目标站要求的比例出一份。
16. **提交后地址不变**：提交发生在页面浮层里的站（不是独立投稿页），成功后只是关掉浮层、地址一个字都不变。手法写「成功判据以浮层文案为主，URL 变化只作辅助」，并把该站的成功浮层文案记进 `success_hints`。
17. **逐字输入被联想吃掉**：正文里带 `#话题`、`@用户` 这类触发符号时，键盘**逐字**敲会触发平台的联想自动补全——它把后面的字吞掉、把符号插到错位置，最终写进去的东西跟目标完全不同，字数还对得上，光看计数器发现不了。手法写「一次性插入（`insert_text`）而不是逐字敲」，并**写完回读一次**做比对，不符就换剪贴板粘贴重写。同理，提交时平台若弹「存在未匹配的话题 / 提及」这类内容校验框，选**保留原文**那一项（站点级 `submit_confirm`），让自动改写别碰我们的文案。

## 五、提交与判成功：六条硬规矩

这三条都是「看着像发了、其实没发」换来的，接入时直接照做。

### 1. 提交按钮只从底部操作栏取，不扫全屏

页面顶部常有一个同名的「发布 / 新建」按钮，点下去只是展开一个下拉菜单（上传视频 / 上传图文 / 写长文）。按全屏文字匹配时，它排在前面，于是每次都点中它，页面纹丝不动，日志却写着「已点击发布」。

做法：先把提交按钮限定在**底部操作栏**范围内再取点。配置里写 `submit_selector` 指向那条栏（或它的容器），配合 `submit_ratio_x` 在栏内横向定位；只有在拿不到选择器时才退回文字匹配，且文字匹配必须精确。

### 2. 文字取不到就按坐标点，坐标与 frame / shadow 无关

底部操作栏常是自定义元素（形如 `<xxx-publish-btn>`），里面的按钮文字在 shadow DOM 里，`get_by_text` 一律取不到，DOM 里也查不到这个文字节点。

做法：用 `ratio_x` 按元素盒子内部横向比例取点，派发真实鼠标事件。**鼠标坐标是视口级的**，元素在不在 iframe、文字在不在 shadow root，都不影响点击落点。这是坐标点击最有价值的场景。

要点：坐标点击不会自动滚动，先 `scroll_into_view_if_needed` 再取盒子，否则拿到的 y 在视口之外，点了个空。

### 3. 文件一律注入，系统选文件窗口全局拦掉

上传成片、上传封面都走 `set_input_files` 直接把路径塞进隐藏 input，这是唯一注入路径，快且稳。

风险在于：点击动作一旦落到包着 file input 的 `label` 上，浏览器会弹出系统级选文件窗口，把人挡住、把流程卡死。做法是在拿到页面时挂一个 `filechooser` 监听，收到就取消——注入已经完成，这个窗口没有存在意义。

### 4. 提交前确认上传真的完成

视频上传是异步的，没传完时提交按钮是浅色 / 不可点，点了等于没点，日志却写着「已点击提交」。判断方式：

- 按钮颜色或 `disabled` 状态变化，是最直观的信号；
- 拿不到状态时，按站点给一个足够长的上传等待（`upload_wait_ms`），视频越大给得越长。

这一条和「判成功」是两回事：没传完就提交，结果一定是停在发布页。

### 5. 判成功三条路，缺一条就会误判

| 判据 | 说明 |
|---|---|
| 成功文案 | 文案必须只在该站提交后出现。**导航项一律剔除**：侧边栏里内容管理、草稿箱、数据看板这类常驻入口永远在页面上，写进成功文案就是永久假阳性 |
| 地址整体变化 | 比**完整 URL 含查询参数**，不只比路径。有的站发完只是把 `?published=true` 挂上去，路径一个字没变 |
| 地址成功标记 | `published=true` / `success=1` / `result=success` 这类标记单独认 |

三条都不成立时，**按未发布处理**：任务回队列、状态留在 `pending`，不写 `published_unverified` 冒充。宁可让人再看一眼，也如实记成未发布。

### 6. 判成功要抢在 toast 消失之前

成功提示常常是个**只闪一两秒的浮层**（toast / 轻提示），不是页面上的常驻区块。点完提交先等固定秒数再去找，找到的是空气——于是明明发出去了，却被判成未发布、任务退回队列，白跑一遍还可能重复发布。

正确做法：**点完立刻开始轮询**，间隔 400ms 左右，命中就记下，最多轮询十几秒；页面地址同时盯着，变了也算。等固定时长只在轮询结束之后做，用于让页面稳定、好截图。

配套要点：

- 轮询窗口用站点级开关 `submit_probe_s` 调，默认 15 秒；转码慢的站可以放长。
- 提交后弹二次确认的站，**先处理确认再轮询**，否则确认框挡着、轮询空转。
- 人工接手结束后要**补判一次**，人可能已经点完确认、页面也跳走了。
- 有的站发布成功后**地址一个字都不变**（提交发生在页面浮层里，成功后只是关掉浮层）。这类站的成功判据只看浮层文案，URL 变化只作辅助。

## 六、执行纪律

- **先读台账再动手**：召唤发布时按 `path_log` 顺序执行，选择器仍命中就不改任何东西。
- **只有失效才重校准**：被重定向登录页、控件全超时、视口指纹变化，才算失效；失效才 `probe` 导 DOM，校准后**回写台账**并更新 `verified_at`。
- **空台账等于没跑通**：`path_log` 为空表示这一格从未跑通过，按 03 册首次接入流程走，别假装能跑。
- **台账只记动作**：账号、cookie、二维码、本机路径一律留在凭据层；台账随实例目录一起备份，保持可分享。

## 七、验收判据

- 连续执行两次：第二次日志里每一步都显示命中，且**零写盘、零分析**。
- 台账步骤数与实际执行日志的步骤数对得上，不多不少。
- 台账里每条 `pitfall` 都能对应到一个具体动作参数；只有现象没有解法的条目，视为没写完。
- 台账里不出现 JS 合成点击；确有必要用坐标点击的，`pitfall` 里写清为什么元素级点击不可用。
