# 10 · 内容类型路由与登录兜底

发布不是「一个站点一个地址」，而是「一个站点 × 一个内容类型一个地址」。这一册定两件事：
按内容类型选渠道，以及扫码走不通时怎么把登录态拿下来。

## 一、三种内容类型

| 值 | 中文 | 判据 | 媒体形态 |
|---|---|---|---|
| `video` | 视频 | 单个视频文件 | 一个 mp4 |
| `image_text` | 图文 | 多图 + 短文案，标题可选 | 一个图片目录或若干图片 |
| `article` | 文章 | 长正文，有标题、有排版 | 文档或 Markdown 源 |

类型是**路由键**，不是标签：它同时决定去哪几个站点、去每个站点的哪个地址、填哪些字段。

## 二、地址归属：站点 × 内容类型

同一站点的视频页与图文页**通常不是同一个地址**（常见的差异是查询参数 `?target=video` / `?target=image`，
或路径里的 `upload/video` 与 `upload/text`）。因此地址、入口动作、命中状态三者一起挂在内容类型下：

```json
"types": {
  "video":      {"label": "视频", "upload_url": "…", "entry_pre": [], "entry_state": {}},
  "image_text": {"label": "图文", "upload_url": "", "entry_pre": [], "entry_state": {"state": "unverified"}}
}
```

规则：

1. `upload_url` 为空表示「该站点支持这类内容，但发布页地址还没走到过」，不是不支持。
2. 不支持的组合**不建键**；建了键就是承诺支持，路由会把它算进渠道。
3. 一个类型的地址验证通过，不影响另一个类型的状态，两者分别记 `entry_state`。
4. 地址仍然只分析一次、命中即复用；类型只是把「一次」变成「每个类型各一次」。

## 三、到达判据随类型变

判「是否已到发布页」按类型取判据：文章类页面往往一个文件输入都没有，一律找上传控件必然误判为未到达。

| 内容类型 | 到达判据 | 说明 |
|---|---|---|
| 视频 / 图文 | 上传控件候选（`media_inputs`） | 文件输入只要在 DOM 里就算到位，可见与否都算 |
| 文章 | 标题输入框 + 正文编辑区（`arrive_checks`） | 富文本 / Markdown 编辑器各有特征 |
| 任意 | 编辑器在 iframe 内时，用 `arrive_frame` 指定 frame | 判据改在该 frame 内匹配，不在主文档找 |

三者可叠加：先按 `arrive_frame` 定位 frame，再在 frame 内按 `arrive_checks` 或 `media_inputs` 匹配。
命中即 `verified`；只记了地址但判据没命中，状态保持 `unverified`，不冒充打通。

## 四、按类型选渠道

```bash
python -B cli.py platforms --type article     # 看谁能发文章
python -B cli.py add --type article --platform all --media <文档> --title "…" --ai
python -B cli.py run --type article           # 只跑文章任务；默认直接发，--draft 存草稿，--dry 只预览
```

`--platform all` 是**路由展开**：取所有 `types` 里含该类型的站点，逐站建任务，账号各按各站默认账号。
一条内容要发多个站点时用 `all`，只发某站时写站点 key。

## 五、登录方式与兜底

站点条目的 `login_mode` 决定 `login` 的默认走法：

| 值 | 走法 | 适用 |
|---|---|---|
| `qr`（默认） | 抓二维码图片交用户扫，轮询登录态 | 有扫码入口的平台 |
| `manual` | 开有头窗口，用户自己登，登完自动接管 | 只有短信验证码 / 图形验证码 / 密码的站点 |

`python -B cli.py login <站点> --manual` 可对任意站点临时强制手动模式。

手动模式的边界（硬约束）：

1. **只开窗、不代填**：不代填手机号、不代收验证码、不代输密码，全部由用户在窗口里亲手完成。
2. **成功判据三层**：站点配了 `login_cookies` 就精确判 cookie；否则判 `logged_in_url_hints`；
   再否则判「地址已离开登录页且出现会话类 cookie」。宁可多等，不误判成功。
3. **登录态只落本机**：成功后写进 `profiles/<站点>/<账号>/`，并按需备份 `cookies/<站点>__<账号>.json`；
   二维码、验证码、cookie 值一律不进技能包、不进版本库、不打印。
4. **接管在登完之后**：登录成功后同一进程内即可继续 `goto` / `probe`；换进程也无需重登。

## 六、验收判据

- `platforms --type <类型>` 列出的站点，等于该类型所有渠道，不多不少。
- 每个已打通的「站点 × 类型」在直达清单里各占一行，地址互不覆盖。
- 地址为空的行状态为 `unverified`，`goto` 对该行输出 SKIP 并提示先 probe，不打开浏览器。
- `login --manual` 在用户登完后输出 `LOGIN_OK`，且随后 `check` 显示登录态有效。
