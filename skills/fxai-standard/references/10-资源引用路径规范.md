# 10 · 资源引用路径规范（图片 / 音频 / 视频同一套）

> **何时读**：往服务端提交任务、填参考图 / 参考音频 / 视频输入、上传本机素材、
> 把生成产物接到下一环节时。调 ComfyUI 的技能一律适用，三类资源同一套格式。

## 总则

- 🔴 **一条格式，三类通用**：图片、音频、视频的 rel 都是 `<子目录>/<文件名>`，
  差别只在基准目录——图片 `fxai/image/`、音频 `fxai/audio/`、视频 `fxai/video/`。

| 类别 | 服务端基准目录 | rel 长相 | 从哪取 |
|---|---|---|---|
| 图片 | `fxai/image/` | `avatar/000.png`、`shortdrama_xjz/003.png` | `upload_image` 返回、生图返回值、常量 |
| 音频 | `fxai/audio/` | `<歌名>_vocalsep/000_audio.wav` | `upload_audio` 返回、人声分离产物令牌 |
| 视频 | `fxai/video/` | `merged/fxai_<时间戳>.mp4`、`<prefix>_multiref/000.mp4` | `upload_video` 返回、渲染产物令牌 |

- 🔴 **同一条资源三种路径，各归其位**：本机路径只用于本地读写，节点输入只收服务端相对路径，
  服务端绝对路径不进任何参数。提交被拒先查是不是三者串了位。

| 路径形态 | 长相 | 用在哪 | 谁解析 |
|---|---|---|---|
| 本机路径 | `<盘符>:/…/xxx.png`、`assets/…` | 上传源、ffmpeg 入参、下载落点、读像素 | 本机 Python / ffmpeg |
| 服务端相对路径 rel | `<子目录>/<文件名>` | 节点输入（图片列表 / 参考图 / 音频文件 / 视频）、配置里的 `ref_image` | 服务端 fxai-toolkit |
| 服务端绝对路径 | `/root/…`、`<comfy_root>/fxai/image/…` | 只在服务端排障口径里出现 | 不参与提交 |

## rel 怎么写（三类同一条）

- **基准不进串**：rel 从基准下第一层起写——`avatar/000.png`，不写 `fxai/image/avatar/000.png`；
  音频写 `<子目录>/<文件名>`，不写 `fxai/audio/…`；视频写 `merged/x.mp4`，不写 `fxai/video/merged/x.mp4`。
- **分隔符只用正斜杠**：反斜杠、盘符冒号、`./`、`../`、连续斜杠一律不出现。
- **必带子目录**：`shortdrama_xjz/000.png`、`merged/fxai_xxx.mp4`。
  裸文件名只在文件确实落在基准根下时才写。
- **子目录单层**：上传接口按单层目录落盘，`a/b` 会被剥成 `ab`；一个系列 / 一个用途占一个目录。
- **文件名**：保留原扩展名、小写、ASCII 无空格；上传时用 `filename=` 指定目标名。
- **多图 = 一个字符串**：逗号分隔、逗号后不空格，如 `avatar/001.png,avatar/000.png`；
  传 list 或 JSON 数组会被节点拒（`bad_linked_input` / 400）。音频、视频按节点输入类型给单值。
- **顺序即编号**：串里第 1 张 = 提示词里的 `<image1>`、第 2 张 = `<image2>`，两边顺序对齐。

## 取值出口（rel 只从这几处取）

| 场景 | 入口 | 取哪个 |
|---|---|---|
| 本机图片上传 | `comfy_client.upload_image(local, subdir=…, filename=…, overwrite=True)` | 返回的服务端文件名 → rel = `<subdir>/<文件名>` |
| 本机音频上传 | `comfy_client.upload_audio(local, subdir=…)` | 直接返回 `<subdir>/<文件名>`，可直填「音频文件」 |
| 本机视频上传 | `comfy_client.upload_video(local, subdir=…)` | 直接返回 `<subdir>/<文件名>`，可直填视频输入 |
| 生图 / 四视图 / 场景图 | `generate_image` / `gen_char_view` / `gen_scene_image` | 返回 `(本机路径, rel)`，下一环节用 rel |
| 音频产物（人声分离等） | `/fxai/tasks/result` 的 url 令牌 | 令牌 `audio|<子目录>|<文件名>`，节点填 `<子目录>/<文件名>` |
| 视频产物（渲染成片 / 分镜） | `/fxai/tasks/result` 的 url 令牌 | 令牌 `video|<子目录>/<文件名>`，节点填 `<子目录>/<文件名>` |
| 服务端已有资源 | 常量 `C.REF_WOMAN` / `C.REF_MAN`、配置字段 | 原样填，不重复上传 |
| 列目录核对 | `GET /fxai/files/list?dir=fxai&subdir=<类别>/<子目录>` | 返回项即 `<子目录>/<文件名>`，类别取 `image` / `audio` / `video` |

- 🔴 **rel 与令牌不是一回事**：令牌（`image|…`、`audio|…|…`、`video|…`）只回传给
  `/fxai/down/file` 与 `/fxai/tasks/result`；节点输入只填去掉类别前缀的 rel。
  令牌一律用接口返回的原串，不手工拼接、不手工与 rel 互转。
- 🔴 **不按文件名猜、不按本地目录拼**：rel 只从上面几处取，猜出来的串提交上去就是「读不到文件」。
- **上传成功即服务端已落盘**：`upload_image` / `upload_audio` 返回成功就代表服务端有这份资源，
  不必再回本机核对。
- **覆盖同一 rel**：`upload_image` / `upload_video` 传 `overwrite=True` + `filename=<目标名>`
  直接覆盖该名、不递增；`upload_audio` 按目录内已有数量编号（`<NNN>_<原名>`）。
  rel 末段一律用返回值，不按原文件名推。
- **覆盖生效判据**：返回名必须等于 `filename`（扩展名沿用上传文件）；不等即服务端未加载覆盖接口，
  按返回的错误停在该步。
- **本机视频上服务端**：`upload_video(local, subdir=…)` 落到 `fxai/video/<subdir>/`，rel 用返回串。
- **角色底图不搬运**：`avatar/000.png`（女）/ `avatar/001.png`（男）本来就在服务端，只传路径，
  不上传、不另存到项目目录再当参考图。
- role 关键字（`woman` / `man` / `both` / 空值）到 rel 的映射表见
  `fxai-common/references/03-ref路径速查.md`，本册不重复。

## 提交被拒时的定位表

| 现象 | 命中的写法 | 改法 |
|---|---|---|
| 节点报没有图片 / 读不到参考图 | 图片 rel 填成本机路径或裸文件名 | 换 `<子目录>/<文件名>` |
| 音频节点找不到音频 / 出来的片子静音 | 音频填了本机 wav 路径 | 先 `upload_audio`，填返回的 `<子目录>/<文件名>` |
| 视频节点读不到输入 | 视频填了本机 mp4，或整串令牌 | 先 `upload_video`，填返回的 `<子目录>/<文件名>` |
| `400` 或 `bad_linked_input` | 图片列表传了 list | 换逗号分隔的单个字符串 |
| 上传后名字变成 `000.png` | 没带 `filename=` | 带 `filename=<目标名>` + `overwrite=True` |
| 文件落在别的目录 / 目录名粘在一起 | `subdir` 带斜杠或盘符 | 单层目录名 |
| 提交 `queued` 但画面没有参考 | 串顺序与 `<imageN>` 编号错位 | 按串顺序重排提示词编号 |

## 判据

- 提交前扫工作流 JSON 的 `inputs`：出现盘符冒号或反斜杠即路径写错。
- `inputs` 出现 `|` 即令牌混进了 rel（图片 / 音频 / 视频都按这条查）。
- rel 首段等于基准目录名（`image` / `audio` / `video`）即基准进了串，删掉该段。
- 节点里填的 rel 末段 = 接口返回的文件名；不一致即覆盖命名没生效。
- 服务端有没有这份资源只由接口回答（`/fxai/files/list`、`/fxai/down/file`、提交被 `queued`），
  本机目录不作依据（见 07 册）。
