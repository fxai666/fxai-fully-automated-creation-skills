# 12 · 交付视频编码规格

> **何时读**：任何技能写出最终交付 MP4（成片 / 最终成片 / 样片）前、改编码参数时、交付前验收码率时。
> **口径修正 2026-11-15**：2000 kbps 是**最高上限**，不是必须凑到的目标值。
> 2000 以内（含明显更低的码率）都合规，不重制、不回压、不为了对齐数值二次压缩。

## 适用范围

- 适用：写入项目根目录、交给发布环节的**最终成片**，时长 ≥30 秒。
- 不适用：中间片段、拼段、封面段、对比片、验收抽帧、超分中间产物、`_tmp/` 内临时转码。
- 覆盖动作：烧字幕、拼封面、叠卡、拼接、单镜返修拼回。**最后一次重编码即交付编码**；中间环节仍按各自技能的画质档走。

## 规格（数值唯一出处）

| 项 | 值 |
|---|---|
| 容器 | MP4，`-movflags +faststart` |
| 视频 | H.264 / libx264，`-preset medium`，`-pix_fmt yuv420p` |
| 音频 | AAC 192 kbps；源音轨已是 AAC 时 `-c:a copy`，不二次编码 |
| **总比特率** | **上限 2000 kbps**，低于上限即合规，**无下界** |
| 编码目标 | 1900 kbps（视频 1708 kbps + 音频 192 kbps），留 100 kbps 封装 / VBV 余量 |
| 单遍实现 | `-b:v 1708k -maxrate 2000k -bufsize 3600k` |
| 两遍实现（推荐） | `-pass 1` / `-pass 2`，`-b:v 1708322` |
| 验收判据 | ffprobe `format.bit_rate` **≤ 2000 kbps 即通过**；只判上界，不设容差带、不设下界 |

## 执行规则

1. 码率数值只写在 `fxai-common/video_encode.py`；产线不得各自写 `-b:v` / `-crf` / `-cq` 作为最终成片的质量档。
2. 最终编码一律调 `delivery_venc()` 取参数列表，或调 `encode_delivery_2pass()` 一步成型（后者自带验收）。
3. 允许走 CRF 等画质档产出**低码率**成片（例如静态录屏、教程演示），只要实测总码率 ≤ 2000 kbps 就放行；但为防失控，仍须用统一出口的 `-maxrate 2000k` 封顶，不得既无 `-b:v` 又无 `-maxrate`。
4. NVENC 分支同样按码率封顶；`-cq` 配 `-b:v 0` 只可用于中间片段。
5. 从**最高质量的源一次成型**：带字幕的成片从无字幕原片烧录并一次成型；不得拿已压缩的成片二次压缩，烧录字幕的文字边缘会糊。
6. 交付前调 `assert_delivery_bitrate(成片)`，超过 2000 kbps 才停在交付前、不进发布环节；低于 2000 一律直接放行。
7. 发布单 / `发布材料.json` 记 ffprobe **实测**总码率与体积，不把上限值当实测值。
8. 换画幅 / 帧率 / 编码器都不改 2000 kbps 这个上限；要改只改本册与 `video_encode.py`，且两处同步。
9. **不得为了「凑到 2000」给低码率成片灌码率**：低码率是更省流量的好事，重编码只会损失画质。

## ★ 贴封面交付一次成型（MV 最省流程，2026-11-27 立）

> 何时读：MV / 任何「干净合并片 → 贴封面 + 烧字幕 → 交付成片」的场景。

**问题**：把「贴封面」和「烧字幕」拆成两步，中间会落一个高码率片，再全片重编码一次到 2000k ——
两次全片重编码、多一个几百 MB 的中间文件、字幕边缘被压两遍（实测：合并片 7232k →
贴封面后 5932k/172MB → 成片 1910k，中间那一次编码完全是白做的）。

**做法**：把「拼封面段 + 烧字幕 + 2000k 交付编码」合成**一次 filter_complex 编码**，
从干净合并片一次成型到成片；只编码一遍，字幕只被处理一次。

- 代码出口：`fxai-poster/poster.py` 的 `finish_with_cover(png, video, ass, out, frames=10, fps)`。
  内部走 `fxai-common/video_encode.py` 的 `delivery_venc()`，不写死 `-b:v`/`-crf`。
- **字幕必须挂在 concat 之前的正片分支**（`[1:v]...subtitles=...→[v1]`），用**原始
  `字幕.ass`，不平移**：拼上封面段后正片整体后移，字幕自动对齐。若挂在 concat 之后的
  `[v]` 上才需要平移封面段时长 —— 别走那条路，会多造一份平移版字幕。
- 音轨：MV 正片音轨就是配乐，封面段用 25Hz 垫音；**不需要再混 BGM**
  （「BGM 最后混」是短剧/幻灯片场景，MV 不适用）。
- 封面段仍按 `fxai-poster/references/04` 的 10 帧 / `trim=end_frame` / 垫次声正弦 / faststart 规范，
  一次 filter_complex 拼接（禁 `concat -c copy`）。
- 验收：同第 6/7 条，`assert_delivery_bitrate()` ≤ 2000 即放行；另抽首帧确认封面、抽歌词点确认字幕未错位。

**旧流程不是错误、只是不省**：已按两步法产出且验收通过的成片（如《风过长椅》
`成片_731x1300.mp4`，1910k）**不因本节重做**；本节只约束此后的新交付。

## 判据

- `python -B scripts/video_bitrate.py <成片.mp4>` 退出码 0，打印实测 kbps ≤ 2000。
- `check_standard.py --skills-root <技能根>` 的「交付编码契约」零 ERROR：产出最终成片的脚本必须调用统一出口。
- 成片时长、帧数、音轨与压缩前一致；`ffmpeg -v error -i 成片 -f null -` 全片解码零报错。

## 指针

- 公共实现：`fxai-common/video_encode.py`；验收脚本：`scripts/video_bitrate.py`。
- 静态判据：`references/04-规范体检.md`「交付编码契约」。
- 发布侧只读取、不转码：发布物料与发布单口径归各自发布技能。
