# 12 · 交付视频编码规格

> **何时读**：任何技能写出最终交付 MP4（成片 / 最终成片 / 样片）前、改编码参数时、交付前验收码率时。

## 适用范围

- 适用：写入项目根目录、交给发布环节的**最终成片**，时长 ≥30 秒。
- 不适用：中间片段、拼段、封面段、对比片、验收抽帧、超分中间产物、`_tmp/` 内临时转码。
- 覆盖动作：烧字幕、拼封面、叠卡、拼接、单镜返修拼回。**最后一次重编码即交付编码**，必须走本节；中间环节仍按各自技能的画质档走。

## 规格（数值唯一出处）

| 项 | 值 |
|---|---|
| 容器 | MP4，`-movflags +faststart` |
| 视频 | H.264 / libx264，`-preset medium`，`-pix_fmt yuv420p` |
| 音频 | AAC 192 kbps；源音轨已是 AAC 时 `-c:a copy`，不二次编码 |
| **总比特率** | **2000 kbps**（视频 1808 kbps + 音频 192 kbps） |
| 单遍实现 | `-b:v 1808k -maxrate 2200k -bufsize 3600k` |
| 两遍实现（推荐） | `-pass 1` / `-pass 2`，`-b:v 1808322`，实测偏差最小 |
| 验收容差 | ffprobe `format.bit_rate` 落在 1800～2200 kbps |

## 执行规则

1. 码率数值只写在 `fxai-common/video_encode.py`；产线不得各自写 `-b:v` / `-crf` / `-cq` 作为最终成片的质量档。
2. 最终编码一律调 `delivery_venc()` 取参数列表，或调 `encode_delivery_2pass()` 一步成型（后者自带验收）。
3. 不得用无 `-b:v` 的默认编码（ffmpeg 缺省 CRF 23 会让交付码率完全失控），不得只设 `-maxrate` 而不设 `-b:v`。
4. NVENC 分支同样按 `-b:v` 定码率；`-cq` 配 `-b:v 0` 只可用于中间片段。
5. 从**最高质量的源一次成型**：带字幕的成片从无字幕原片烧录并一次压到目标码率；不得拿已压缩的成片二次压缩，烧录字幕的文字边缘会糊。
6. 交付前调 `assert_delivery_bitrate(成片)`，不过即停在交付前，不进发布环节。
7. 发布单 / `发布材料.json` 记 ffprobe **实测**总码率与体积，不把目标值当实测值。
8. 换画幅 / 帧率 / 编码器都不改 2000 kbps；要改只改本册与 `video_encode.py`，且两处同步。

## 判据

- `python -B scripts/video_bitrate.py <成片.mp4>` 退出码 0，打印实测 kbps 在容差内。
- `check_standard.py --skills-root <技能根>` 的「交付编码契约」零 ERROR：产出最终成片的脚本必须调用统一出口。
- 成片时长、帧数、音轨与压缩前一致；`ffmpeg -v error -i 成片 -f null -` 全片解码零报错。

## 指针

- 公共实现：`fxai-common/video_encode.py`；验收脚本：`scripts/video_bitrate.py`。
- 静态判据：`references/04-规范体检.md`「交付编码契约」。
- 发布侧只读取、不转码：发布物料与发布单口径归各自发布技能。
