# 07 · 本地环境边界

> **何时读**：开工前确认「这台机器能干什么」、想查模型 / 节点 / 配置 / 安装目录、
> 或判断某个能力是否存在时。**默认开工即适用，不需要额外触发。**

## 总则

- 🔴 **能力只从技能包取**：本机有什么能力，一律以技能包（`SKILL.md` / `references/` /
  工作流 JSON / 脚本入口）已声明的入口为准。
- 🔴 **不得勘察本地环境**：未经用户明确允许，模型清单、节点清单、配置文件、
  安装目录、权重文件、数据目录一律不读、不列举、不扫描。
- 🔴 **存在性判定走服务端接口**：资源 / 能力有没有，由服务接口回答（提交后被 `queued`
  即证明服务端已读到），不以本机磁盘扫描结果为准。
- **唯一放行条件**：用户明说「去看一下 XX 配置 / 列一下 XX 模型」才动，且只动他点名的那一样。

## 越界判据（命中任一条即越界）

| 动作 | 例子 |
|---|---|
| 拉服务端能力清单当能力目录读 | `GET /object_info` 全量拉回再筛节点名、`GET /models/...` 列权重文件 |
| 扫本机磁盘找模型 / 目录 | `ls` / `find` / `Glob` 模型目录、`ComfyUI/models/**` |
| 读本机或服务端配置文件判定能力 | 读 `extra_model_paths.yaml`、`config.json`、`fxai_global.json` 探地址与模型 |
| 用系统信息接口反推能力 | 拉 `system_stats` 的 `comfy_package_versions` / VRAM 判断该跑哪个模型 |
| 直接翻安装目录看装了什么 | 列 `site-packages` / 自定义节点目录判断有无某能力 |

**非越界**（正向路径，照做即可）：探活接口确认服务在不在（`system_stats` 只取存活信号）、
提交任务后看是否返回 `prompt_id` + `queued`、按技能包文档调用已声明的入口。

需要读客户端安装目录 / 登录身份 / 用户账号库时，按 08 册四步判定取值：只读全局配置里
写明的两个目录字段，不枚举目录内容，本册边界仍然适用。

## 正向路径：需要某个能力时这么做

1. **先查技能包声明**：该能力在不在，看技能自己的 SKILL.md 与 references 写了没。
   技能包没写的，视为不存在，不去本机/服务端现场挖。
2. **存在性交给接口**：提交工作流 / 调接口，被接收即存在，报错即不存在。
3. **确认不了就问用户**：技能包没声明、接口也答不了的能力需求，停下问人，
   不自行勘察推断。

## 为什么这条是硬边界

本地环境是用户自己的资产与隐私边界：模型、配置、目录结构属于环境清单而非技能能力清单。
智能体逐项勘察等于把用户家底盘一遍，且勘察结论会反过来诱导越权改动（改配置、换模型、
起服务）。技能包声明什么就用什么，能力缺口用「问用户」补，不用「翻机器」补。
