# 09 · 会话记忆

> **何时读**：开工读记忆、收工写记忆、整理 `.workbuddy/memory/` 与用户级 `MEMORY.md` 时。

## 两份文件，分工固定

| 文件 | 装什么 | 判据 |
|---|---|---|
| `MEMORY.md`（项目级 / 用户级） | **现行有效的口径**：铁律、数值、路径、约定 | 读它就能开工，无需翻日志 |
| `YYYY-MM-DD.md` | **变更台账**：哪天哪个口径变成了什么 | 只用来追溯「什么时候定的」 |

口径归 `MEMORY.md`，日志只留变更痕迹。日志里出现一条长期有效的规则，
同一条同时上提到 `MEMORY.md`，日志那行压成一句「X 已上提」。

## 分册

口径攒到装不下（`MEMORY.md` 超 3KB，或出现三个以上互不相干的主题）就按**什么时候读**拆册：
`NN-主题.md` 与 `YYYY-MM-DD.md` 同目录，`MEMORY.md` 退成「索引 + 横切铁律 + 现行标准」。
判据：一条口径只在一册写全，别处只留指针（同 03 册「册与册不重复」）。

## 日志四条写法

1. 🔴 **一条口径只留一条**：旧结论被推翻时就地改写为现行口径，或标注它被哪条取代；
   同一关键词全文搜下去只命中一处。
2. 🔴 **标题只写最终口径**：不写时间戳、不写「用户拍板 / 我改了」，写「闸门 = 9KB」这类陈述。
   同一件事只有一个标题，后续修订改这个标题下的正文。
3. **加粗只给数字与禁行项**：全文控制在 10 处以内。
4. **表格只给 3 项以上并列**：两行结论写成一句话，单句不套表格。

## 禁入项

| 禁入 | 原因 |
|---|---|
| 过程叙述（谁问的、试了几次、改了几轮） | 未来会话拿不到上下文，用不上 |
| 已作废的中间方案 | 与现行口径并列时会被误读成有效 |
| 情绪化原话 | 只留它推导出的口径 |
| 操作流水（跑了什么命令、输出什么） | 需要时可复跑，不必存 |

一句话判据：**这条内容，未来的我能直接照着执行吗？** 答不上来就压成口径，或删。

## 五个记忆层

| 层 | 落点 | 随什么走 |
|---|---|---|
| 项目 | `B/_fxai_memory.md` | 随项目 |
| 技能 | `skills/<技能>/references/` | 随技能出包 |
| 标准 | `fxai-standard/references/` | 随包 |
| 工作区 | `<A>/.workbuddy/memory/` | 随 Agent 空间 |
| 用户级 | `~/.workbuddy/MEMORY.md` | 随用户 |

落点判据与逐层例子见 01 册「记忆分层与归属」；本册只管**怎么写**（口径 vs 台账、四条写法、禁入项），
不管**写到哪一层**。

🔴 **归属跟着被操作对象，不跟操作方**：在 A 工作区操作 B 项目，该项目口径写 `B/_fxai_memory.md`；
改的是某技能的模板或判据，写该技能 `references/`；A 的记忆空间只留跨项目通用口径。

## 写入时机

- **开工**：读 `MEMORY.md`；日志按日期倒序翻最近一两份即可，不全读。
- **收工**：有实质产出才写。实质产出 = 建改文件、定口径、修缺陷、换技术方案。
  纯问答、查资料、打招呼不写。
- **跨项目偏好**（个人习惯、行业口径、硬边界）写用户级 `MEMORY.md`，不写项目日志。
