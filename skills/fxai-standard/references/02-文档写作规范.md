# 02 · 文档写作规范

> **何时读**：写或改任何 SKILL.md / references / 脚本注释/docstring 时。本册是
> 写作侧的执行规则；体检判据见 04 册。

## 总则

- 🔴 **只写最终执行规则与判据**：读文档的人能照做照查；过程与原因不进文档。
- 🔴 **规则条目不附现成句子**：要说明一条规则，写判据（什么样算命中、什么样不算），
  不附可直接照抄的成句——成句会被当模板逐条套，是文案机械化的根源。
  可执行判据：`check_standard.py` 的 `DEMO_MARK`（见 04 册判据表），行内命中即 ERROR。
  字段级文档只给格式占位（括号里写该填什么类型），不给填好的值。

## 过程叙述禁入

判定词表（行内命中即 ERROR，语境豁免与标记豁免见下）：

| 族 | 判定词 |
|---|---|
| 修复/问题类 | 已修、踩坑、试错、症状、复测 <!-- std:allow --> |
| 数据/成果类 | 实测数据、演示产物、成果演示、上一版 <!-- std:allow --> |
| 时间/变更类 | 以前、原来、原来怎么样、不再、导致、后来我们、后来发现、改成现在这样 <!-- std:allow --> |
| 用户/反馈类 | 用户发现、用户点名、用户反馈 <!-- std:allow --> |
| 示例类 | 示例、样例、范例、示范、范句 <!-- std:allow --> |
| 心得类 | 心得 <!-- std:allow --> |

**边界口径（用户澄清定稿）**：判定词禁的是「记录我方操作过程」，不是「这些字出现在
内容里」——平台推荐用词、话题标签、违禁词表、判据词表、措辞清单、功能名、接口名、
对观众的话术，撞词正常保留。

### 两级豁免

1. **语境豁免（EXEMPT_CTX）**：行内（或紧邻的上文标题行）出现 用词 / 词表 / 措辞 /
   标签 / 话题 / 可选 / 枚举 / 话术 / 提示语 / 感受词 / 关键词 / 违禁 / 判据 / 命中 /
   功能名 / 接口名 / 叙述 / 规则 时，该行不判过程叙述。
2. **标记豁免（ALLOW_MARKS）**：行尾加隐藏标记，显式放过：
   - Markdown：`<!-- std:allow -->`
   - 脚本：`# std:allow`
   用于规则正文不得不引用判定词本身的场合（如本册的词表说明、技能里引「试错/踩坑」
   作为内容要求）。

## 句式规范

- 🔴 **只写「怎么做」的最终执行规则，不写禁令清单**：禁令清单不落盘；把「不许做 X」
   改写成「做 Y 达成同一目的」。
- 🔴 **表禁用一律「不得 / 禁用 / 勿」**；弱化措辞过不了检（否定式词表见 04 册）。
- **因果句改正面规则**：「只认 A 会数成 0 张」→「正则须同时匹配 A 与 B」。
- **删后果括号**：「（发表后无法补开）」「会报 47001」类整删。
- **删原因从句**：「保证第一帧…」「杜绝产物分裂」类目的从句整删，留规则本身。
- **过程叙述段落整删**：开工前置、经验库、变更历史类章节合并成一行指针或删。

## 域例外：白名单为主 + 精简黑名单（提示词 / 约束类规则）

🔴 **本例外覆盖上节「禁令清单不落盘」**——仅限**提示词与生成约束类**规则，且须同时满足：

- 主体仍是**白名单**（写「要怎么写 / 要怎么构图」），黑名单只作兜底。
- 黑名单**只列已被确认会出穿帮的具体坏写法**（具体短语），不泛化、不堆泛禁令、
  不写成「不许做 X」式的通用禁令清单。
- 每条黑名单项须能对应到代码/护栏里同一个具体的防错点（文档与代码双保险）。

适用场景：生成式 AI 提示词规则——已确认某具体写法会出穿帮（如数字人口播场景图
的「前景遮挡 / 低机位仰拍 / 过肩 / 物件特写注入人物」、会重算背景的「平移 / 抬升 /
环绕」），白名单管「应写什么」兜不住这些被验证的坏话术，才用精简黑名单钉死。
落地形态：`fxai-digital-human-video/references/02-人物动作与场景图.md`
「人物落位区无前景遮挡」「背景稳住」两节（❌ 禁用写法 / ✅ 白名单写法 + `_SCENE_GUARD` 护栏）。
