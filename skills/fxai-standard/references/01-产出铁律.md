# 01 · 产出铁律

> **何时读**：开工定标准、定产物落点、写交付清单、定配置读写规则、清理项目目录时。

## 标准唯一来源（开工第一条）

🔴 **执行标准只从技能库取**：字号、镜长、语速、样式、命名、验收判据，一律读
`skills/fxai-*/references/` 与 `SKILL.md`。**标准只取技能库**：既有成片与既有项目脚本用来对素材、对进度，
参数一律回技能查；既有项目里的参数只是那一次的取值，作参考不作依据。

| 需求 | 唯一来源 |
|---|---|
| 字幕字号 / 单条上限 / 样式 | `fxai-lyric-subtitle/SKILL.md` + 本项目技能的 `references/` |
| 提示词写法 / 六段结构 | 对应技能 `references/NN-*.md` |
| 产物落点 / 记忆 / 渲染跑法 | 本册（01） |
| 参考图 / 音频 / 视频的路径格式与 rel 取值 | 本技能 10 册 |
| 脚本入口与参数 | 技能 `SKILL.md` + 脚本自身参数 |

- **开工动作**：先定本项目用哪几个技能 → 读它们的 `references/` 相关册 → 再动手。顺序是先读标准、后写参数，不是先照抄旧项目。
- 🔴 **技能库里查不到标准时，补进技能库，不回退到"上次的做法"**：按 03 册写进对应技能
  `references/`（技能自己的判据）或本册（跨技能通用），下一集直接用。
- 🔴 **旧项目只作两用**：① 素材来源（角色图、场景图、参考文案）；② 对比样本（对进度、对时长）。
  不得作为参数依据与写法依据。
- 🔴 **新旧冲突以技能为准**：旧项目里的取值与技能 `references/` 不一致时，按技能执行，
  并就地修正旧项目的那处取值；不得因"旧项目那样跑通了"而沿用。
- **同一件事只留一个事实源**：标准写在技能里，项目记忆与工作区记忆只写「本项目取值」和指针，
  不复写标准正文（复写即制造第二处事实源，改一处漏一处）。

## 产物落点

- 🔴 **产物只落当前工作区** `<工作区>/<项目名>/`：工作区 = 当前工作目录（在哪个工作区跑就建在哪）。
- 🔴 **无全局 projects_root 层**：优先级 = `FXAI_PROJECTS_ROOT` 环境变量 > 工作区级
  `<工作区>/_fxai_global.json` 的 `projects_root` > 当前工作目录；不读用户个人目录的
  全局配置文件，不往上跳 `.workbuddy` 找。
- **用户个人目录只作素材来源**：引用别处的素材 ≠ 把产物写到别处。
- **目录扁平**：交付物一律放项目根目录，不建 `video/` `music/` `doc/` 分层；
  图片多才单独放 `image/`。
- 🔴 **中间产物只落 `_tmp/`**：草稿、抽帧、试听片段、调试文本、临时转码一律写
  `<项目>/_tmp/`。项目根与交付目录里出现下列任一项即视为不合规：
  `__pycache__` / `*.pyc` / `node_modules` / `.git` / `.ipynb_checkpoints` /
  `Thumbs.db` / `desktop.ini` / `~$*` / `*.tmp` / `*.part`。
- **Python 不落字节码**：跑技能脚本加 `-B`，或设 `PYTHONDONTWRITEBYTECODE=1`；
  脚本内首行 `sys.dont_write_bytecode = True`。项目目录里的 `__pycache__` 一律由此产生。
- **收尾清 `_` 前缀临时件**：交付后 `_tmp/` 内文件按需清空，目录本身可留。
- 文本类交付物用 Markdown（`.md`）；仅机器清单用 `.json`。

## 工程纪律（跨技能共用）

- 🔴 **删除走 `send2trash`**（进回收站）；PowerShell 的 `Add-Type` / COM 与 bash 调 powershell 会被安全层拦。
- 🔴 **历史残留只 move 不 delete**：移到项目 `_tmp/` 或工作区 `_归档/`。
- 写文件统一 `encoding='utf-8'` + `newline=''`，行尾 LF。
- 中文文件名会破坏 ffmpeg 滤镜路径解析：烧字幕等操作先复制成 ASCII 名
  （`src.mp4` / `sub.ass` / `out.mp4`）再跑，跑完按需改名。

## 对比视频画幅（跨技能共用）

- 🔴 **拼接方向由源片画幅决定**：源片宽 ≥ 高（横屏 / 方形）→ `原片对比.mp4` 用 `vstack` 上下堆叠，上格原片、下格成片；源片宽 < 高（竖屏）→ 用 `hstack` 左右并排，左格原片、右格成片。
- **判据取且只取源片** `<项目>/<原片>.mp4` 的 ffprobe `width` / `height`；成片与既有对比片的画幅只作尺寸参照。
- 两路输入先统一到同一 `W×H` 再拼：横屏输出 `W×2H`，竖屏输出 `2W×H`。帧率、帧数、音轨与成片一致，音轨取成片。
- 标签方位随拼接方向改：上下堆叠按上 / 下格对齐，左右并排按左 / 右格对齐。
- 生成命令、锁帧与 `交付清单.json` 字段 → `fxai-face-edit/references/07`；宣传贴片消费走内部自用贴片技能，不随公开包分发。

## 视频帧数验收（跨技能共用）

- 🔴 **规格判据取解码实测帧数**：`ffprobe -count_frames` 的 `stream.nb_read_frames` 是唯一判据，容器 `nb_frames` 元数据只作参照。成片、对比片、验收抽帧的目标帧号，一律以解码实测值与期望值相等为放行条件。
- **规整滤镜用 `fps=N` 滤镜 + `-r N` 输出**：`setpts=N/(N*TB)` 配 `-fps_mode passthrough` 会写出「容器帧数报满、末帧无法解码」的产物；本机实测一条 6.033 秒 30fps 片，容器标 181 帧而实际只解码出 180 帧。
- **抽帧产物逐一校验存在且非空**：ffmpeg 遇到不可解码的目标帧会返回 0 并跳过写文件，缺图直到拼验收网格时才暴露。抽帧调用后当场校验，缺失即报错。
- **共用实现**：`fxai-standard/scripts/video_frames.py` 提供 `decoded_frames()` 与 `assert_frames()`，一处实现多处调用；`fxai-face-edit/scripts/make_compare.py` 生成对比片后接 `assert_frames()`。门禁判据见 `references/04-规范体检.md`「视频帧数验收契约」。

## 成片品牌标识（跨技能共用）

- 🔴 **AI 标识必须加，文案固定为品牌位**：所有成片画面右下角常驻一枚半透明圆角角标，文案取全局配置 `~/.workbuddy/fxai_global.json` 的 `brand.ai_mark_text`（当前值 `凤希AI生成`）。**这是品牌植入位**：不得改写成「AI 生成」「AI」等通用文案，不得省略，也不得只写进简介文案而不上画面。
- **位置与样式**：右下角，距右 / 下边各 24px；深色半透明底（RGBA 12,14,20,175）、圆角 12、白色文字；角标宽度按文案实测宽度自适应（`textlength` + 左右各 22px 内边距），不挤压、不截字。
- 🔴 **文案唯一来源是全局配置**：脚本不得硬编码品牌名；配置缺失或读取失败时，兜底值也必须同为 `凤希AI生成`，不得回退成通用文案。
- **交付清单同步**：`最终交付.AI标识` 写实际角标文案（`画面右下角「凤希AI生成」角标`），不写「AI 生成」。
- 本机角色替换链的角标生成实现 → `fxai-face-edit/references/07`「成片品牌角标」；法律层面的显式 / 隐式标识与平台声明入口 → 发布侧规范。本节只管画面这一枚角标的文案与位置。

## 项目清单

项目根 `_fxai_project.json` 是技能与页面之间唯一的数据契约：技能写它，页面读它显示类型、
标题、逐集进度。页面不解析别的文件，缺它只能靠目录结构猜（短剧与番剧结构相同，必猜错）。

结构（`schema: 2`）：

```json
{
  "schema": 2,
  "title": "云上清楼",
  "category": "drama",
  "skill": "fxai-short-drama",
  "summary": "古风复仇短剧，20 集",
  "stages": { "script": 2, "image": 2, "audio": 1, "video": 0, "publish": 0 },
  "episodes": [
    {
      "no": 1, "name": "风尘花魁", "dir": "1、风尘花魁",
      "stages": { "script": 2, "image": 2, "audio": 1 },
      "deliver": { "video": "1、风尘花魁\\成片_ep1.mp4", "script": "1、风尘花魁\\六段式提示词.md" }
    }
  ],
  "updated": "2026-10-18 16:41:12"
}
```

- `category` 取 `drama / anime / mv / music / image / voiceover / ad / novel / wechat / remake / other`
  （取值以 `categories.json` 为准，本行只是摘要）。
  （`wechat`＝公众号：选题文案、配图、发布物料都归它，页面类型栏与五段进度条同款显示。
  `ad`＝广告：立项、创意、脚本分镜、成片、投放物料都归它，走 `fxai-ad-video`。
  `remake`＝复刻：角色复刻 / 整片场景复刻，走 `fxai-face-edit`；磁盘上叫「替换 / 换脸 / 角色替换」的老目录也归它。）
- 五段固定词表：`script` 剧本·文案·分镜 · `image` 画面 · `audio` 音频 · `video` 成片 ·
  `publish` 发布物料（封面/标题/简介/字幕）。用不到的段不写，页面不画。- 阶段取值 `0` 未开始 / `1` 部分 / `2` 完成。
- `episodes[].dir` 必须是项目根下真实目录名（含序号），页面靠它对上集；
  `deliver` 里的路径相对项目根。
- **交付清单随产物走**：清单里记录字体名与协议（见 06 册）、模型与引擎、关键参数，
  写在 `extra` 字段里，脚本原样保留。

### 类别表：一处定义，多处生成

类别定义在 `fxai-standard/categories.json`（唯一事实源）：`order` 定展示顺序，`items` 每类记
`name / icon / color / words / stages / skill / comment`。本册与各脚本都只引用这一份取值。

| 谁用它 | 怎么用 |
|---|---|
| `scripts/catkit.py` | 读表并对外给出 `CATEGORIES` / `stages_of()` / `skill_of()`，其余脚本只调它 |
| `scripts/fxai_project.py` | `init` 与 `check` 的合法取值来自 `catkit.CATEGORIES` |
| `scripts/check_project_clean.py` | 同上，`CATEGORIES = set(catkit.CATEGORIES)` |
| `scripts/check_standard.py` | `PRODUCERS` 里的类别须落在表内，越界即 ERROR；默认技能与表不符报 WARN |
| 客户端项目页 | 由 `scripts/sync_categories.py` 从表生成，不手改 |

**加类别三步**：

1. 在 `categories.json` 的 `order` 与 `items` 里各加一处；
2. `python scripts/sync_categories.py --site <站点根> --write` —— 重写客户端
   `tool/project/js/projectkit.js` 的 `CATEGORIES` / `CATEGORY_ORDER` / `TYPE_STAGES`、
   `tool/project/detail.js` 的 `SKILL_OF`，并把 `index.html` / `detail.html` 里对应
   `<script src="...?v=xx">` 的版本号各加一；
3. 该类有专属生产技能时，在 `check_standard.py` 的 `PRODUCERS` 登记一行。

- 核对：`python scripts/sync_categories.py --site <站点根>`（不带 `--write`）只比对两侧，不一致退出码 1。
- 删类别：从 `categories.json` 删掉 → 跑一次 sync → 用 `fxai_project.py check` 扫存量项目有无残值。
- 站点根 = 含 `tool/project/` 的那一层目录（客户端站点源目录，按本机实际填）。



调用 `scripts/fxai_project.py`，不手写 JSON（它管 `updated`、原子写入、坏文件不覆盖）：

```bash
python scripts/fxai_project.py init    <项目目录> --title 云上清楼 --category drama --skill fxai-short-drama
python scripts/fxai_project.py episode <项目目录> --no 1 --name 风尘花魁 --dir "1、风尘花魁" --script 2 --image 2
python scripts/fxai_project.py deliver <项目目录> --no 1 --video "1、风尘花魁\成片_ep1.mp4"
python scripts/fxai_project.py stage   <项目目录> --script 2 --image 1     # 无集结构的项目
python scripts/fxai_project.py check   <项目目录>                          # 校验结构
```

- **每完成一段即登记**，收尾不补；页面据此显示实时进度。
- 有 `episodes` 时项目级 `stages` 按集自动汇总，不必手设。
- 无集结构的项目（单篇生图 / 小说 / 单条口播）用 `stage` 设项目级阶段，不建 `episodes`。
- **未建清单的老项目不追溯**；新建项目一律建档。

## 项目记忆

每个项目在项目根自带一份记忆 `_fxai_memory.md`：随项目走，跨会话续做靠它接上口径与未决项。

- 🔴 **建档即带记忆**：`fxai_project.py init` 写出骨架；记忆文件由脚本建，不手写。
- 🔴 **不走 init 的项目一样必建**：手工搭的项目（自写 `project_def.json`、直接建目录）在
  第一次开工时补 `fxai_project.py memory <项目目录>` 生成骨架，再逐条 `--add`。
  **没有 `_fxai_memory.md` 的项目视为未建档**，不得在项目外另找地方记它的事。
- 🔴 **工作区记忆不代替项目记忆**：`<工作区>/.workbuddy/memory/` 只装跨项目的口径与踩过的坑，
  某一部剧 / 某一集的约定、决策、待办、风险必须落该项目 `_fxai_memory.md`。
  项目口径写进工作区记忆属错层，同一条要搬回项目并在工作区压成通用判据。
- 🔴 **开工先读记忆**：定位到项目后先读它，取稳定约定与未决项；读完按本节追加本次结论。
- 🔴 **只记约定、决策、待办**：稳定口径（人设 / 风格 / 参数 / 素材来源 / 角色库指针）、
  已定决策（带日期与判据）、待办与未决属记忆内容；操作流水、临时覆盖、调试数据不进记忆。
- **追加写，不改写**：新条目追加到所属段末尾，一行一条，已写条目只增不改。
- **同一口径第二次出现即上提**：流水里重复出现的口径提炼进「稳定约定」段，流水行保留。
- **单文件 ≤ 4000 字符**：超限把已闭环的流水条目压成一行结论，「稳定约定」段不动。
- 加工作业同此：定位到项目后按本节追加一条，不另建记忆文件。

```bash
python scripts/fxai_project.py memory <项目目录> --add "女主音色定温柔青年音" --tag 约定
python scripts/fxai_project.py memory <项目目录>                                  # 打印全文
```

- `--tag` 取 `约定 / 决策 / 待办 / 风险`，省略按 `决策` 记。
- 段落归属：`约定` 进「稳定约定」，`待办` 进「待办与未决」，`决策` 与 `风险` 进「决策与流水」。
- `--add` 一次一条，一条一件事；记忆缺失时子命令先补骨架再追加。

### 记忆分层与归属

每条记录先判层，再写；同一口径只在一层写全，别层只留指针。

| 层 | 落点 | 装什么 | 随什么走 |
|---|---|---|---|
| 项目 | `B/_fxai_memory.md` | 该项目的约定 / 决策 / 待办 / 风险 | 随项目 |
| 技能 | `skills/<技能>/references/NN-*.md` | 该技能自己的判据、提示词模板口径、验收规则 | 随技能出包 |
| 标准 | `fxai-standard/references/*.md` | 跨技能的通用规范（产物落点、体积闸门、记忆写法） | 随包 |
| 工作区 | `<A>/.workbuddy/memory/` | 本工作区跨项目口径（工具用法、环境边界、通用缺陷） | 随 Agent 空间 |
| 用户级 | `~/.workbuddy/MEMORY.md` | 跨项目个人偏好、硬边界、全局约定 | 随用户 |

🔴 **归层判据**：自上而下，第一条命中即写那一层。

1. 只在某一个项目成立 → **项目层**。
2. 某技能的提示词模板、输出规则、验收判据变了 → **技能层**。
3. 多个技能都受约束 → **标准层**。
4. 本工作区怎么做事的习惯 → **工作区层**。
5. 换机器、换项目都成立 → **用户级**。

🔴 **技能层的改动不进用户级、不进项目**：写进用户级出包时不带，别人拿到包就少这条判据；
写进项目只对那个项目生效，换个项目又踩一遍。

🔴 **记忆跟着被操作对象走，不跟操作方走**：在 A 空间操作 B 项目，B 的约定 / 决策 /
待办 / 风险写 `B/_fxai_memory.md`，操作方只留提炼后的通用判据。

🔴 **操作方记忆里的口径主语不得是项目专有名**（角色名、剧名、曲名、客户名、某次发布的版本号）。
命中即说明该条目归项目，须搬回该项目 `_fxai_memory.md`。

- 技能根出现 `MEMORY.md` 属错位件：口径并入 `references/` 对应册后删除，不在技能根另立记忆。
- 项目 vs 会话的分工与写法见 09 册；本节的「层」是落点判据，09 册是内容判据。

## 加工作业的项目归属

对已有素材做二次加工的作业（剪辑成片、加字幕、标题卡、人声分离、转码、排版导出），
同样归入项目体系，区别只在它是「更新者」而非「建档者」。开工第一步定位项目：

```bash
python scripts/fxai_project.py context "<输入文件或目录>" [--workspace <工作区>] [--json]
```

- `found: true` → 加工产物写回该项目目录，按加工内容更新对应段：成片剪辑 → `video`，
  字幕 / 封面 / 标题 / 简介 → `publish`，配乐 / 人声 / 配音 → `audio`。
  集归属取返回的 `episode`；`episode` 为 `null` 时按项目级 `stage` 登记。
- `found: false` → 按返回的 `suggest_mode` 建档：
  - `init_here`（输入是已组织好的目录）→ 就地 `init`，目录结构保持原样，`category` 取 `other`
    或按产物判定；
  - `new_project`（输入是散落的素材文件）→ 在 `suggest_root`（工作区下按素材名）建目录后 `init`。
  加工产物落项目根，中间文件进 `_tmp/`。
- `--require` 用于必须在既有项目内完成的作业：未定位到项目返回退出码 3，停在该步询问用户。
- 项目根一律由 `context` 给出，技能不自拼路径、不按目录名猜项目。

**交付前自检**：`python scripts/check_project_clean.py <项目目录> --strict` 返回 0 才收工。
它同时查垃圾文件、`_` 前缀过程目录、散落的过程文件、旧分层目录（`video/` `music/` `doc/`）
与项目清单完整性；返回 1 时按报告把过程文件移进 `_tmp/` 或删除，清单用 `fxai_project.py` 补。

## 渲染中查进度（视频类通用）

视频类任务（短剧 / MV / 数字人 / 幻灯片视频）提交后，问「到第几个分镜了 / 还要多久」
一律查，不得以「等终态」代替回答。

- 🔴 **唯一入口** `fxai-workflow/shot_query.py`（库调用 `shot_query.query(pid)`）：
  只给 prompt_id，保存目录、总镜数、任务起点自动定位，输出
  「已生成 N/M 镜 · 还剩 K 镜 · 约 X 分钟 · 下一镜第 N 镜」。
- **任务串行排队**：想知道「此刻跑到第几镜」用 `shot_query.py now`——它取 `/queue` 里 running
  的那个 pid 再按同一套口径算，不必记 prompt_id；逐镜重渲连排时尤其省事。
- **`/fxai/tasks/result` 只在任务结束后写一条结果**：排队中与生成中返回空。实时镜号走
  `fxai:progress` 广播（带 current/total，需监听进程），没监听时走「本任务起点之后的落盘文件」。
- **判定口径**：保存目录里**不在 `merged/` 下**的视频文件即分镜，文件名序号＝分镜序号
  （`000.mp4` = 第 1 镜）；`merged/` 里的合并片是成片，不计入分镜。
- **总镜数**取提交快照 `lines_data` 的行数（一镜一行）；结束索引写 `-1` 表示整集，
  不按索引推总镜数。
- **单镜重渲任务单独口径**：工作流里「开始索引 == 结束索引」即只跑那一镜，总镜数与
  「还剩几镜 / 续跑参数」全部跳过，输出「单镜重渲（只跑第 N 镜）」＋该镜落没落盘；
  同一目录连排多个单镜任务时，只认自己那一镜的镜号。
- **保存目录按任务反查，不写死**：取该任务自己工作流里的「保存目录」字段（`/history` 或提交快照）；
  短剧管线默认 `sucai`，MV / 数字人 / 幻灯片各用自己的目录，互不相同。查询侧不得假定固定目录。
- 🔴 **目录被多个任务共用时必须按任务窗口过滤**：只数本任务起点之后落盘的文件，
  起点取提交快照的 `time`（台账 / `/history` 都取不到时仍可用）。
- **断点续跑** `shot_query.py resume <pid>`（= `comfy_client.resume_task()`）：取回原工作流 →
  「开始索引」改到 `next_index`、「结束索引」置 `-1` → 重新提交；`lines_data` 保留全部镜头，
  合并节点照旧合并整集，已生成镜头命中节点缓存直接复用。不得整集重投。
- **机器读** `--json`：`shot_count` / `scene_total` / `remaining` / `eta_seconds` /
  `avg_shot_seconds` / `next_index`；断点续跑直接拿 `next_index` 作 `start_index`。

```bash
python ~/.workbuddy/skills/fxai-workflow/shot_query.py <prompt_id>          # 查：第几镜 / 还剩几镜 / 约多久
python ~/.workbuddy/skills/fxai-workflow/shot_query.py resume <prompt_id>   # 续：从下一镜接着跑完
```

接口优先级、快照字段与兜底顺序见 `fxai-workflow/SKILL.md`「渲染中看第几镜」。

## 视频生成的两种跑法（短剧 / MV / 数字人 / 幻灯片视频通用）

多镜控制器工作流（含「开始索引 / 结束索引」节点）按场景二选一：

| 场景 | 跑法 | 索引 |
|---|---|---|
| 整片重做 | 一次提交跑完全部镜 | `start_index=0`、`end_index=-1` |
| 某一镜不合格要返修 | 只重渲那一镜 | `start_index=end_index=N`（N 为 0 起索引） |

- **整片重做一次提交跑完**（`0 → -1`）：每次提交都要重跑前置（如角色四视图），
  逐镜循环提交会按镜数成倍重跑。
- 🔴 **服务端自动合并成完整片**：完整生成与单镜重渲都一样，服务端把
  「本次新段 + 已缓存的其他段」合并成一条完整视频返回；本地取到的即全长成片，
  直接进烧字幕 / 后续环节。
  - 逐段产物：`<ComfyUI>/fxai/video/<prefix>_multiref/<序号>.mp4`（`000.mp4` 起，0 起编号）。
    服务端按项目缓存各段，同一时刻只有一个项目，重渲单段不影响其他段。
  - 合并产物：`fxai/video/merged/fxai_<时间戳>.mp4`——每次提交出一条完整成片。
  - **判据**：返回成片时长 = 全长。时长等于单段说明走的是单段下载路径。
- 🔴 **每张场景图配一段自己的文字描述**：多段用 `|` 分隔传给 `--scene-desc`，
  描述随各段提示词下发，各镜才按时段切到自己的场景；只有图没有描述时各镜背景会雷同。
- **字幕在服务端合并的完整片上一次烧完**，时间轴才对齐。

## GPU 提交前门禁：探测优先、按需回收与 500 自愈

🔴 **提交 prompt 前先探测当前显存实况**：残留低于阈值即视为模型已卸载，跳过回收直接提交；超阈值才调同步硬回收接口卸载全部模型，卸载后立刻验证一次，达标即走，未达标才进入下一轮。门禁挂在提交公共层 `fxai-workflow/comfy_client.py` 的 `POST /prompt` 之前，唯一实现为 `fxai-standard/scripts/check_gpu_gate.py`；技能脚本只留指针，一处实现多处调用，各自复制判据属第二处事实源。

| 步骤 | 动作 | 判据 |
|---|---|---|
| 探活 | `GET /system_stats` | 返回正常即在线；HTTP 5xx 或无响应＝服务不健康，启动方式交回给人，启停权在人；5xx 且命中显存类时先走一次自愈再复查 |
| 队列 | `GET /queue` | running / pending 任一非 0 即排队等它结束，不打断、不抢占、不重投 |
| 探测 | `GET /fxai/guard/status` + 本机物理卡实况 | 接口给出显存硬件实况、模型装载数、staged 记账与错误日志摘要；残留显存 ≤ 阈值、空闲占比达标、`pinned_gb` 归零即放行，**回收次数 0** |
| 回收 | 同步硬回收接口 `POST /fxai/guard/recover` | 仅探测超阈值时执行；全部步骤 `ok=true`，任一步失败＝CUDA 上下文已脏，停手请人重启 |
| 验证 | 每轮回收后立刻采样一次 | 判据同「探测」；达标即提交，未达标才进入下一轮，轮数上限由参数定，固定多轮回收属无效开销 |
| 自愈 | 500 / 显存类错误 → `self_heal()` | 按显存实况与错误日志判因；命中才卸载一次并验证，回落即自动重投一轮，额度 1 次 |

- **残留显存**＝物理卡实况占用，或进程内占用减去空载固有开销。CUDA 上下文与推理运行时保留的固有占用不属模型残留；阈值按设备容量由环境变量或命令行调整，判据不写死某台机器的读数。缺省 1 GiB 为「跳过回收」阈值。
- **接口返回硬件实况**：`GET /fxai/guard/status` 须给出物理卡占用 / 总量 / 利用率、进程内显存、模型装载数、`pinned_gb`、回收次数、`last_error` / `last_error_kind` / `error_log`；判因取这些值，接口返回 200 不等于模型已卸载。
- 同步硬回收接口由本机显存守卫节点提供；`installed=false` 时门禁拦下提交，交回人补环境。
- 内置 `POST /free` 只置 `unload_models` / `free_memory` 标记，实际卸载在 `prompt_worker` 循环里由下个 prompt 消费，既不立即也不彻底；队列线程终止后标记无人消费。卸载验收以同步硬回收接口为准。
- 工作流自有权重块与缓存不进 ComfyUI 的模型管理表，`unload_all_models()` 与 `free_memory()` 都碰不到。判据须取**设备级空闲显存实测值**，以「模型列表已空」代替验收属放行残留。
- **500 自愈的边界**：显存实况正常且错误日志无显存特征 → 判为服务不健康，停手把重启交回给人；卸载步骤失败或验证未回落 → 停手请人重启；自愈成功只重投一轮，额度用完仍失败按原错误抛出。全程不代启、不自行重启、不无限重试。
- 门禁未过一律停在提交前并给出非零退出码；验收记录写项目临时目录，供交付清单回溯。判据的静态受检方式见 04 册「判据与分级」。

### 三类动作的分工

| 动作 | 处置 |
|---|---|
| 提交前门禁 | 探活 → 队列 → 显存探测 → 按需回收 → 一次验证即走 → 提交 |
| 主动放弃一个仍在跑的任务 | `POST /interrupt`（空 body）→ `POST /queue` body `{"clear":true}` |
| 500 / 显存类错误 | `self_heal()` 判因 → 卸载一次 → 验证回落 → 立即重投一轮；判为服务不健康、卸载失败或验证未过时停手，把重启交回给人，重启后按提交前门禁验收通过再降显存重试 |

## 中断渲染任务：一律走接口

ComfyUI 是服务端模式，进程管理归「凤希本地AI控制台」，调用方只按地址发 HTTP。
中断或放弃一个已提交的渲染任务，按顺序调这两个接口：

1. `POST /interrupt`（空 body）——断 running，不动进程、不清队列
2. `POST /queue` body `{"clear":true}` ——清排队中的残留

- 卸载全部模型与显存验收属**提交前门禁**，按上一节先探测再按需回收；内置 `POST /free` 只置标记，不列入中断步骤。
- 中断步骤仅适用于仍在跑的任务；任务已因 GPU OOM 失败时按上一节「500 / 显存类错误」走自愈，自愈判为服务不健康才停手交回人重启。
- 本地那条提交命令（后台 shell）保持不动，任务被接口中断后自行返回。
- 状态判定只走接口：`GET /queue`（running / pending）、`POST /fxai/tasks/result`。
- 资源有无只由服务端回答：本机磁盘 ≠ 服务端磁盘，判定不用本机 `find` / `ls`。

## 不落盘内容（写进技能文档与注释的禁入项）

| 禁入项 | 落点规则 |
|---|---|
| 过程叙述（判定词见 02 册词表） | 只写最终执行规则与判据 |
| 现成句子（示例族判定词见 02 册） | 规则条目不附现成句子，要说明写判据 |

> 措辞清单、功能名、对观众的话术，撞词正常保留（豁免见 02 / 04 册）。
