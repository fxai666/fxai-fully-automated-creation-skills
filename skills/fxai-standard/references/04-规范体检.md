# 04 · 规范体检（check_standard.py / check_project_clean.py）

> **何时读**：跑规范体检、查判据口径、用豁免标记时。

## 两个工具的分工

| 工具 | 查什么 | 何时跑 |
|---|---|---|
| `check_standard.py <技能目录>` | 技能包自身：文档判据、SKILL.md 体积、路由三要素、项目清单契约、垃圾文件 | 改完 SKILL.md / references / scripts |
| `check_project_clean.py <项目目录>` | 项目交付目录：过程文件残留、是否建了 `_tmp/`、清单与记忆是否合规 | 每个项目交付前 |

## check_standard.py

```bash
python scripts/check_standard.py <技能目录> [--junk] [--fix]
python scripts/check_standard.py --skills-root <技能根目录> [--junk] [--fix]
```

- 扫描 `<技能目录>` 下 `.md / .py / .json / .js / .sh`，逐文件逐行判定。
- `--junk`：加查垃圾文件与孤儿目录（`__pycache__` / `.pyc` / 备份副本等）。
- `--skills-root`：批量扫该目录下全部 `fxai-*` 技能，逐行汇总 ERROR 数。
- `--fix`：给产出型技能自动补项目清单指针段（幂等，已含即跳过；补后超 9KB 报 ERROR 且不写盘）。
- 退出码：有 ERROR 返回 1，否则 0；收工标准 = ERROR 0 / WARN 0。
- 整改任何技能后跑一遍；全量治理用 `--skills-root` 一条命令覆盖全包。
- **GPU 提交前门禁按代码判**：`fxai-standard` 的 `scripts/check_gpu_gate.py` 须提供 `gate()` 与同步硬回收；`fxai-workflow` 的 `comfy_client.py` 须在 `POST /prompt` 之前调用 `gpu_gate()`。缺席、实现不完整或接线位置在后即 ERROR。判据落在真正提交的东西上，查文档措辞不算数；规则正文见 01 册「GPU 提交前门禁」。
- **500 / 显存自愈按代码判**：同一实现须提供 `self_heal()` 与探测短路；提交公共层须在 5xx 与执行期错误两处接上自愈重投。缺席、实现不完整或接线错位即 ERROR，见下节。
- **视频帧数验收按代码判**：`fxai-standard` 的 `scripts/video_frames.py` 须提供 `decoded_frames()` 与 `-count_frames` 实测；`fxai-face-edit` 的 `scripts/make_compare.py` 须在生成对比片之后调用 `assert_frames()`。缺席、实现不完整或接线位置在前即 ERROR。规则正文见 01 册「视频帧数验收」。

## GPU 门禁与 500 自愈契约（写进代码的强制项）

规则正文见 01 册「GPU 提交前门禁」；体检查的是实现与接线，实现与接线两处同查，单查一边挡不住「写了没接」。

| 判据 | 受检文件 | 判据值 |
|---|---|---|
| 探测优先 / 短路跳过 | `scripts/check_gpu_gate.py` | 含 `释放前探测`、`跳过（释放前探测已低于阈值）`、`recover_calls`；短路分支出现在卸载调用之前 |
| 阈值可调 | 同上 | 含 `SKIP_RECOVER_GIB`，取值来自环境变量 |
| 硬件实况与错误日志判因 | 同上 | 含 `/fxai/guard/status`、`"hardware": hw`、`"error_log": st.get("error_log")`、`models_loaded`，且 `self_heal()` 消费错误日志做显存类判定 |
| 卸载后一次验证 | 同上 | 含 `def is_clean(`、`def residual_gib(`、`def self_heal(` |
| 提交点门禁 | `fxai-workflow/comfy_client.py` | `gpu_gate(url=url` 出现在 `+ "/prompt"` 之前 |
| 5xx 自愈接线 | 同上 | 含 `def gpu_self_heal(`、`G.self_heal(`、`heal_used`，且 `if gpu_self_heal(url=url` 落在 5xx 分支与计网络重试次数之间 |
| 执行期错误自愈接线 | 同上 | 含 `def _heal_and_retry(`、`heal_rounds`，且 `_heal_and_retry(wf, timeout` 落在错误终态分支近旁 |

- `check_gpu_gate_contract()` 管提交点门禁位置，`check_gpu_self_heal_contract()` 管探测优先与自愈接线，两者均在 `audit()` 内调用。
- 判据带正反测：对真实实现报 0 项；删掉 `self_heal()`、删掉短路标记、抹掉硬件实况采样、去掉自愈接线、改写 5xx 分支调用，任一种都须报 ERROR。判据落在具体代码串与相对位置上，只查函数名会被同名残留骗过。
- 每条判据都有翻车依据：固定多轮回收拖慢每次提交；接口 200 当成已卸载会放行残留；5xx 一律停手会把可自愈的显存堆积交回人；自愈无限重试会把坏 CUDA 上下文越堆越满。

### 8. 规则文档不许出现成句示范：写了就等于给了照抄源 <!-- std:allow -->

用户口径：**「我们为什么这里面还有示范呢？标准规范里是不允许出现这些的。」** <!-- std:allow -->

02 册总则写着「规则条目不附现成句子」，但只有文字约束时没人执行 ——
数字人分镜册里一直有一张「正确写法」表，照抄进分镜，出片就是模板化的动作。 <!-- std:allow -->
成句示范不是参考，是**默认答案**：读的人会把句子搬进产物，判据反而没人看。 <!-- std:allow -->

落到程序：`check_standard.py` 的 `DEMO_MARK`（正确写法 / 错误写法 / 写法示例 / <!-- std:allow -->
正确示例 / 错误示例 / 照抄以下 / 照此写）行内命中即 ERROR。 <!-- std:allow -->

| 该写 | 不该写 |
|---|---|
| 判据：什么样算命中、什么样算不命中 | 一句写好的动作描述 |
| 词级白名单 / 黑名单短语（域例外允许） | 用引号包起来的完整句子 |
| 枚举表的可用性标记（运镜 / 机位能否用） | 用可用性标记包装的成句 |

配套：字段级文档（`storyboard.json` 之类）只给**格式占位**——
括号里写该填什么类型、按哪条判据填，不给填好的样例值。

## check_project_clean.py

```bash
python scripts/check_project_clean.py <项目目录> [--json] [--strict]
```

- 只读：不删、不移、不改，只出报告与退出码。
- 退出码：0 = 干净；1 = 有不合规项；2 = 目录不存在。`--strict` 把下列「提示级」项一并计入失败。
- 六类判据（与 `tool/project/js/projectkit.js` 的 `SKIP_DIRS` / `SKIP_FILES` / `PROCESS_FILE_RE` 同源）：

| 类别 | 判据 | 非 strict | strict |
|---|---|---|---|
| 垃圾（junk） | `__pycache__` / `*.pyc` / `node_modules` / `.git` / `.ipynb_checkpoints` / `Thumbs.db` / `desktop.ini` / `~$*` / `*.tmp` / `*.part` | 失败 | 失败 |
| 过程目录（stray） | `_` 前缀目录，白名单 `_base` 除外；整目录报一次，不下钻 | 提示 | 失败 |
| 过程文件（process） | 代码 / 日志 / 进程号 / 中间态 / 自检帧 / 备份副本（正则在脚本顶部 `PROCESS_FILE_RE`） | 提示 | 失败 |
| 分层目录（layer） | `video` / `music` / `doc` / `audio` / `output` / `成片` 等旧布局；`image/` 属允许项 | 提示 | 失败 |
| 项目清单 | `_fxai_project.json` 缺失 / 解析失败 / `category` 不在白名单 / 缺 `title` | 提示 | 失败 |
| 项目记忆 | `_fxai_memory.md` 缺失 / 读取失败 / 内容为空 | 提示 | 失败 |

- 中间产物目录 `_tmp/` `_work/` `_cache/` `_logs/` `_debug/` 允许存在，内容不计交付物。
- 记忆缺失用 `fxai_project.py memory <项目目录>` 补骨架；清单与记忆同属项目根契约。
- `--json` 输出 `junk / work_dirs / stray_dirs / process_files / layer_dirs / manifest / memory` 七段，供脚本消费。
- 改判据时两处同步：本脚本顶部常量 与 `projectkit.js` 的 `SKIP_DIRS` / `SKIP_FILES` / `PROCESS_FILE_RE` / `PROCESS_DIR_ALLOW`。

## 两级豁免

1. **语境豁免（EXEMPT_CTX）**：行内出现 用词 / 词表 / 措辞 / 标签 / 话题 / 可选 /
   枚举 / 话术 / 提示语 / 感受词 / 关键词 / 违禁 / 判据 / 命中 / 功能名 / 接口名 /
   叙述 / 规则 时，该行不判过程叙述——平台用词对照、违禁词表、判据说明、功能名
   描述天然带这些词，属合法规则表述。
2. **标记豁免（ALLOW_MARKS）**：行尾加隐藏标记显式放过：
   - Markdown：`<!-- std:allow -->`
   - 脚本：`# std:allow`
   用于规则正文不得不引用判定词本身的场合。

## 边界口径

判定词禁的是「记录我方操作过程」，不是「这些字出现在内容里」：平台推荐用词、话题
标签、违禁词表、判据词表、措辞清单、功能名、对观众的话术，撞词正常保留；确有合法
用法用豁免标记放过，不改词表。

## 自查纪律

- 本技能自身同样受检：改完 SKILL.md / references / scripts 先跑本工具，0/0 再收工。
- 词表扩充属跨技能改动：加词前问用户（第零法则 2），加完对全包复检，误伤合法表述
  的词撤回。

## 门禁判据怎么选：白名单 / 黑名单

做交付门禁（提交前、出片前、发布前）时，**两层各用各的，缺一不可**：

| 层 | 判据形态 | 管什么 | 为什么必须这样 |
|---|---|---|---|
| **结构** | **白名单**：枚举 + 必填 + 格式 | 字段取值、类型、数量、时间码连续性、必填字段 | 黑名单永远列不全「新编出来一个没见过的值」；白名单直接挡住 |
| **语言** | **黑名单**：禁写词表 | 自然语言描述（分镜动作、提示词、文案、话术） | 自然语言是开放集合，白名单列不出「所有可能的写法」 |

反过来用会失效：用黑名单管结构 → 漏一个新值就放行；用白名单管语言 → 表达全被限死。

### 判据落点：查「真正提交的东西」，不查中间表

校验脚本必须**真跑一遍组装函数**，拿它产出的文本/文件来查。
中间表合规不等于产物合规 —— 典型失效：分镜表写了动作、代码却没把该字段拼进提示词，
出片照样错，而查分镜表的脚本全绿。这类「查了但没查对」比不查更危险。

### 门禁挂两道

- **生成前**：结构 + 提示词审计，白烧算力之前就拦住（一条长片重跑可能是小时级）。
- **交付前**：交付清单 + 上面两层判据，任一不过就非零退出，不允许「看着还行」放行。

### 每条判据要有真实翻车

判据不是形式主义：每条都要能说清「不这么判会发生什么」。没有真实案例的条目不加，
加了会让门禁变噪声、最后被人整体跳过。

## 返修门禁：能只重做一段，就不许整片重跑（2026-10-21）

用户口径：**某一段生成错了，就走单段重生成。所有视频生成技能共同遵守，不只数字人。**

这条只写在规范里不够 —— 写在规范里等于「读到了才会守」，21 号的事故就是没读到。
必须做成程序行为，三个落点：

### 1. 判定只有一份：`fxai-common/rework.py`

| 函数 | 用途 |
|---|---|
| `is_rework(start, end)` | 是否单段返修（显式索引且非整片 `(0,-1)`）。**所有「已有产物→跳过」之前必须调它** |
| `shot_no_of(秒数)` | 用户说「62 秒那里不对」→ 直接算出第 7 镜 |
| `shot_timecode(n)` | 第 n 镜 → 时间码区间（定位、抽帧复验都用它） |
| `changed_shots(proj, sb)` | 比对上次渲染的分镜签名 → **这次改了哪几镜** |
| `splice_segment(成片, 裸片, n)` | 单段裸片按时间码替换回完整成片（短剧 / MV / 幻灯共用） |

各技能**不许**自己再写一份 `SEG_SECONDS`、自己算时间码、自己判断返修。

### 2. 「参数被跳过逻辑吃掉」是这一类事故的固定形态

数字人踩过：`--start-index 6 --end-index 6` 传了，主流程发现 `合并_*.mp4` 已存在，
直接「已有产物，跳过」，成片一个字节没变。**规范写了单段返修，代码却是整片跳过**——
规范与实现不一致，比没规范更坏。

所以统一判据：**只要显式给了索引且不是 `(0,-1)`，一律视为返修，必须真渲**，
并在日志打 `[rework] 返修模式：只重渲第 N 段`。看到这行才算真在返修。

### 3. 整片重跑请求要自动降级

`dh_video.py` 已接：整片模式 + 成片已存在 + `changed_shots` 只有 1~3 镜
→ **自动改为逐镜单段返修**，日志打 `[rework] 只改了第 N 镜 → 自动降级为单镜返修`。
真要整片重来必须显式 `--force`。

理由：让人（和 Agent）在「整片还是单段」上做选择，本身就是事故源。
**能算出来的事不该让人选。**

### 4. 单段返修的时间账（为什么值得做成门禁）

| 形态 | 整片重跑 | 单段重跑 |
|---|---|---|
| 数字人口播 88 s / 10 镜 | ≈ 70 min | ≈ 8~10 min（四视图命中缓存后 2~3 min） |
| MV 一曲 / 十几段 | 几十分钟 | 几分钟 |
| 短剧一集 / 十几镜 | 几十分钟 | 几分钟 |
| 幻灯口播 / 十几段 | 十几分钟 | 几十秒 |

**判据**：返修日志里必须同时出现「返修模式」「复用缓存」两行；只看到
「完整音频一次性生成」+ 一路渲下去，说明又在整片重跑，立刻停。

### 5. 质检只报「不过」不够，必须给出返修入口

用户口径：**「你检查过后，某一段有问题，要能够命中返修这个规范。」**

所以质检脚本的输出里必须自带三样，缺一样就算不合格：

| 必须输出 | 数字人里的落点 |
|---|---|
| 未过项落在**哪几镜** | `preflight.py` 从每条未过项的 detail 里抽「第 N 镜 / 第 N 段」，收成 `bad_shots` |
| 每镜的**时间码** | `rework.shot_timecode(n)` → `56.50~65.92 s`，方便抽帧复验 |
| **现成命令** | `python scripts/refix.py --project <项目> --shots 3,7,9` |

同时落盘 `doc/_preflight.json`（`ok / failed / rework_shots / refix`），
下游 `check_delivery.py` 直接读它把返修入口抄进交付门禁输出 ——
不靠人去翻 stdout，也不靠人记得「还有返修这个选项」。

判据：任何一个「不过」的输出里，看不到 `refix.py --shots` 这行，就是质检没写完。

### 6. 多段返修：串行提交 + 全部渲完才继续

用户口径：**「如果三段都有问题，就三段都提交返修；这三段返修完了再去做后面的事。」**

这条的前提是服务端合并规则（技能里一直有记录）：**每渲完一段，服务端都会拿其它段的
缓存拼回一条完整成片**。推论有三条，都是硬的：

1. **必须串行**。并行提交会互相覆盖对方刚生成的段，成片里总有几镜是旧的。
2. **只认最后一段渲完那一次**。中途那几次成片都是半成品。
3. **全部渲完才能烧字幕 / 做封面 / 交付**。烧在半成品上等于白烧一遍。

程序落点：`fxai-common/rework.py` 的 `parse_shots()` / `plan_batch()` / `MERGE_NOTE`，
数字人侧由 `scripts/refix.py --shots 3,7,9` 实现（一镜渲完才提交下一镜，
全部返回 0 才退出 0，中途失败立刻停并打印「已完成 / 未完成」）。

`plan_batch()` 还会打印时间账（每镜约 9 分钟、多镜串行累加），
让「整片 vs 单段」的选择在**看到数字之后**做，而不是拍脑袋。

### 7. 返修完成后必须回环验收

返修不是终点。`refix.py` 结束时会打印固定三步：

1. 重跑 `preflight.py`，必须全绿
2. 看 `_tmp/refix_shotN/` 的抽帧，确认问题真的消失
3. 才做字幕 / 封面 / S5 交付自检

而且 `refix.py` 在渲染**之前**会先逐镜体检，分镜还有硬伤直接拦下（`--allow-bad` 才强渲）——
没改分镜就重渲，等于拿同样的输入再烧一遍 GPU。

### 8. 黑名单为什么会漏检：词表覆盖率 = 质检上限（2026-10-21 第二次事故）

事故形态：用户看片说「还有一些镜头还是有点头」，而 `preflight.py` 全绿。

原因不是质检没跑，是**质检查的词不是模型听的词**：

| 环节 | 实际情况 |
|---|---|
| 词表 | `HEAD_ACT = [点头, 抬头, 低头, …]` —— 只认字面写着"头"的写法 |
| 分镜 | `motion = "重心前移到前脚，右侧肩头略收，上身轻轻前压一点"` |
| 质检 | 词表里没有"上身前压"→ **放行** |
| 模型 | 「上身前压一点」在腰以上构图里 = **点头** |
| 用户 | 看到的还是点头 |

**这就是黑名单模式的固有缺陷：它只能拦住"你已经想到的写法"。**
凡是换个部位、换个动词的表达（肩膀一沉 / 胸口一挺 / 脖颈松一下 / 上半身略低），
全部放行。事故是随机的，名单是滞后的。

同一次事故里还有第二种漏检 —— **强度不足**而不是字面命中：

- 走位镜模板当时只写「嘴唇与 <Audio 1> 精准同步开合」，字面合规（有唇、有同步），
  但强度等于"对齐一下"，模型渲出来几乎不动嘴。质检查的是**词在不在**，不是**够不够**。

### 修法：能枚举"写什么"的，就别枚举"禁什么"

| 判据类型 | 用什么 | 例子 |
|---|---|---|
| 开放自然语言（动作描述） | **部位白名单** | `motion` 只准出现 脚/腿/重心/手/臂/掌/指；肩/胸/背/腰/颈/脖/上身/躯干 一律不许出现（第 28 项） |
| 强度类要求 | **必须命中白名单短语** | 每段提示词必须含「持续讲话 + 嘴部全程保持明显开合 + 口型逐字跟随」（★9），只写"开口讲述"不算 |
| 封闭枚举（景别/运镜/索引） | 白名单 | `kind ∈ {move, gesture}`、`size` 六档 |
| 确实无法枚举的少量词 | 黑名单兜底 | 头部动作字面词、面部节拍词 |

**判据：一条规则如果只能靠"想到了才加进黑名单"，它就一定会漏。**
写完一条黑名单就要问一句：**这个动作还能用哪些别的部位/动词表达？**
答得出来，就该改成部位白名单。

配套：白名单要留**误伤例外表**（`TORSO_OK`），否则「朝镜头方向」里的"头"、
「手抬到胸口高度」里的"胸"会把合规写法拦掉 —— 误伤比漏检更糟，人会开始绕过门禁。
