# 05 · 人脸精修 ComfyUI 链（本机整片精修）

> **何时读**：要把一整条视频逐段修脸、走本机 ComfyUI 时；要调精修强度、排查「提交了没反应」时。

链路：**源视频 → 分段 → 逐段精修（全脸）→ 合并 → 保存成片**。
跑的是 `fxai-workflow/face-restore-lite.json`（源自作者存档《人脸精修轻量链V1》），
注册表任务名 `facerestore`、模型 `lite`。入口脚本 `scripts/face_restore.py`，
提交/轮询/下载全走公共层 `comfy_client`。

## 与云端链路的分工

| | 本机精修链 | 云端 FaceFusion |
|---|---|---|
| 入口 | `face_restore.py` | `face_edit.py` |
| 适合 | 整片视频、逐段精修、长片 | 换脸、对嘴、单张图、抠像 |
| 计费 | 本机 GPU，不计费 | 云端按小时 |
| 待机要求 | ComfyUI 8188 在线 | 云端实例已开机 |

片子几十秒、只想修一两张脸 → 云端更快；整条片子从头到尾都要修 → 本机这条，按段跑完自动合并。

## 一、工作流结构（13 个节点）

```
108 视频分段器 ──┬─→ 111 生成控制器（分段时长 / 结束索引 -1）
                 └─→ 113 视频分段加载 ──→ 105 人脸精修（全脸）──→ 5 保存成片
                                              ↑
                                    104 角色资源图片选择器（参考脸）
109/110/117 循环（计数，逐段推进）
114 视频合并（把各段拼回整片）─┬─→ 121 PreviewAny（把合并成片路径写进 history）
                              └─→ 120 自动关机（GameOver，默认不触发）
119 释放资源（收尾卸模型、清显存）
```

关键节点 `FxAiFaceRestoreLiteV2`（标题「② 人脸精修 · 轻量链 V2（全脸）」），超分引擎是**自研超分 VOSR2**。

> 与作者原档的两处差异：① 多了 **121 PreviewAny**，接的是 **114 合并节点**的「视频本地路径」——
> **交付物永远是合并后的整片**，不是某一段的中间产物；② `结束索引` 直接写成 `-1`。原因见第七节。
> **121 这个节点别删。**

## 二、占位符（提交时注入）

工作流里 14 个占位符，`face_restore.py` 全部显式传值，不靠 nodeconfig 默认值。

| 占位符 | 落在哪个输入 | 传什么 |
|---|---|---|
| `fxai_videoinput` | 108 视频分段器 · 视频文件 | 源视频路径，**服务端可读的绝对路径**（相对路径按服务端根目录解析，必报「找不到视频文件」） |
| `fxai_imageinput` | 104 角色资源图片选择器 · 图片列表 | 参考脸，逗号分隔的服务端相对路径，默认 `avatar/000.png,avatar/001.png` |
| `fxai_outputdir` | 5 保存成片 · 保存目录 | 服务端保存子目录，默认 `face_restore` |
| `fxai_seed` | 105 人脸精修 · 随机种子 | 默认 42（作者存档值）；<1 即随机。固定种子逐段更稳，不易闪 |
| `fxai_width` / `fxai_height` | 111 生成控制器 · 宽度 / 高度 | **必须跟源视频一致**。占位符默认 960×544，竖屏素材不传就被拉横；脚本自动 ffprobe 源尺寸 |
| `fxai_duration` | 108 视频分段器 · 平均分段时长 | **固定 10 秒，全片统一口径，不调**（FLOAT，必须裸插数字，不得带引号） |
| `fxai_average_segment` | 108 · 是否平均分段 | 固定 `true` |
| `fxai_skip_initial` | 108 · 跳过初始段 | 固定 `true` |
| `fxai_include_tail` | 108 · 包含尾部段 | `false`（实测 25 秒素材照样出 24.96 秒、599 帧，尾段没丢，这个开关不是「舍尾」） |
| `fxai_segment_data` | 108 · 关键帧JSON | 固定 `"[]"`（不用手填关键帧） |
| `fxai_start_index` | 111 · 开始索引 | 固定 `0` |
| — | 111 · 结束索引 | **工作流里写死 `-1`**（＝跑完全部段）。传 `0` 只跑第一段，25 秒素材会只剩 10 秒 |
| `fxai_auto_shutdown` | 111 · 自动关机 | **默认 `false`**。本机跑关自己没意义；云端跑完想省机时费才 `--auto-shutdown` |

> ⚠️ `fxai_duration` 曾被漏在 `non_string_placeholders` 外，被包成字符串 `"10"`，
> 而节点要 FLOAT，提交直接 `custom_validation_failed`。已在 `nodeconfig.json` 补进该表。

## 三、精修参数（105 节点，按字面含义理解）

| 参数 | 现值 | 作用 |
|---|---|---|
| 超分引擎 | 自研超分 (VOSR2) | 超分走哪套引擎 |
| 超分倍数 | 4 | 放大倍数，越大越清晰、越慢、越吃显存 |
| 处理脸宽上限 | 96 | 单张脸处理尺寸上限，小脸放大修 |
| 换脸脸宽上限 | 96 | 同一链里带换脸时的脸宽上限 |
| 遮罩比例 | 0.7 | 精修覆盖范围，越大越往外扩 |
| 羽化半径 | 0.045 | 边缘过渡，抑制「一块补丁」感 |
| 身份相似度阈值 | 0.1 | 认脸门槛，调高更容易漏认 |
| 换脸强度 | 1 | 换脸时融合强度 |
| 肤色回拉 | 0.6 | 修完把肤色往原片拉回，防「假白」 |
| 纹理保留 | 0.9 | 保留原片皮肤纹理，防「塑料脸」 |
| 批大小 | 4 | 一次处理多少帧，吃显存 |
| 裁切框边长 | 0 | 0 = 按检测框自动 |

**改参数只有一个原则：先保纹理与肤色，再谈清晰。** 把纹理保留拉满、肤色回拉给足，宁可少锐一点，也别修成一张塑料脸——脸一假，整片就废了。

## 四、调用

```bash
R=~/.workbuddy/skills/fxai-face-edit/scripts/face_restore.py

python "$R" 源视频.mp4 --out-dir .                        # 默认：自有角色参考脸、种子 42、尺寸随源
python "$R" 源视频.mp4 --ref avatar/001.png --seed 42     # 指定男角色底图、固定种子
python "$R" 源视频.mp4 --width 768 --height 1280          # 手动指定输出尺寸（默认按源视频取）
python "$R" 源视频.mp4 --auto-shutdown                    # 云端跑完自动关机（默认关）
python "$R" 源视频.mp4 --dry-run                          # 不提交，只看注入后的参数
```

返回本机成片绝对路径，同时打印耗时与体积。成片落点默认当前工作目录。
**分段时长固定 10 秒，不开放调节**——整条视频生成规范统一这个口径。

## 五、耗时口径

工作流按 **10 秒一段**切（`平均分段时长`），每段单独跑一次精修再合并。所以：

- 耗时 ≈ 段数 × 单段耗时，**随片长线性增长**，不是一次推理跑完；
- 实测（本机 8188，2026-10-26，768×1280）：3 秒 / 1 段 **6 秒**；25 秒 / 3 段 **113 秒**；21 秒 / 2 段 **109 秒**；
- 分段口径（服务端已实现，`face_restore.py` 用 `plan_segments()` 在本地算一遍做对照）：
  每段 10 秒；**最后一段不足 3 秒就并进倒数第二段**，不留碎尾。
  实测 21 秒 → 10 + 10.96 秒两段；25 秒 → 10+10+5 三段；12 秒 → 整条一段（10+2 并成一段）；
- 段与段之间是硬拼（没有交叉淡化），段越多边界越可能看到跳变，人脸滞回也会在边界重置；
- 显存紧张时把 `批大小` 从 4 调小，慢一点但不容易挂；
- 开工前把预估时间告诉用户，别让人干等；`--timeout` 默认 7200 秒，超长片自行加大。

## 六、排障

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `找不到视频文件：xxx` | 传了相对路径 | 传绝对路径；脚本对「本机存在的相对路径」会自动转绝对 |
| `custom_validation_failed`（节点 108） | 分段参数类型不对 | 确认 `fxai_duration` 是裸插数字，见第二节警示 |
| `required_input_missing`「输入」 | `FxAiReleaseResources` 缺必填输入 | 本版工作流已带 `输入`；旧导出件由公共层自动补（`kind="facerestore"` 分支） |
| 提交返回 `queued` 但很快失败 | 视频路径服务端读不到 | 确认传的是 ComfyUI 那台机器上的路径 |
| 某一段报错整条链停 | 该段检测不到脸 | 正常现象：没脸的段会跳过；连续报错再看参考图是否有效 |
| 成片没声音 | 合并节点没接上音轨 | 工作流里 114 的 `音频` 输入接的是 108 输出；缺音轨时确认源片本身有声 |
| 脸修完发白 / 发假 | 纹理保留太低、肤色回拉不足 | 调高 `纹理保留`、`肤色回拉`，降低 `超分倍数` |
| 画面被拉横 / 变形 | 宽高占位符吃了默认 960×544 | 让脚本 ffprobe 源尺寸，或显式 `--width/--height` |
| **成片只有第一段（秒数 ≈ 10）** | `结束索引` 传了 `0`，循环只跑一段 | 工作流已写死 `-1`；若手动改过，改回 `-1`（＝跑完全部段） |
| **成片比源片少 1 帧** | `_start_seconds()` 的 `+0.0001` 让每段丢首帧，见第八节 | 节点侧 `fxai_video_utils.py` 用半帧偏置，**重启 ComfyUI 生效** |
| 下载回来体积过小 | 半片 | 脚本已按 ftyp 校验并抛错；重跑该任务 |
| 8188 探不通 | 本机 ComfyUI 没启动 | 由「凤希本地AI控制台」启动，**不由 AI 自己起** |

## 七、产物归属与取回

**交付物只认合并后的整片**：`FxAiVideoMerger`（114）把各段按顺序拼成一条，那条才是成片。
分段保存节点（5）写的是每段的过程文件，**不得当交付物**——多段任务下它只是其中一段。

成片经 HTTP 接口下载到本机（`--out-dir`），**服务端 `output/`、`face_restore/` 只当过程目录**。
完整性校验：MP4 查 `ftyp` 且体积过小判坏片，不通过直接抛错。

下载令牌是 `类别/子目录|文件名`（如 `video/merged|fxai_20261026_193101.mp4`），类别只认 image / audio / video。

**取令牌的三条路，公共层 `submit_workflow` 按顺序自动尝试：**

| 顺序 | 来源 | 说明 |
|---|---|---|
| ① | `fxai:task_saved` 广播 | 事件自带 url，最直接 |
| ② | `/fxai/tasks/result` | 按 prompt_id 查结果表 |
| ③ | `/history` 的 `outputs` | 收尾节点 `output_node=False` 时唯一的出路 |

⚠️ `FxAiVideoMerger` 与 `FxAiVideoSaveV1` 的 `output_node` 都是 `False`，只往服务端磁盘写文件，
既不发广播也不登记结果表。所以末端挂了 **121 PreviewAny，接 114 合并节点的「视频本地路径」**，
路径以文本落进 `history.outputs`，③ 从那里读出来转下载令牌。**接 114 而不是接 5**——接 5 拿到的是
单段过程文件，多段任务会漏掉后面的段。

> 实测（本机 8188，2026-10-26）：
> - 3 秒 / 1 段 → 6 秒完成，令牌 `video/merged|…`，成片 71 帧 / 768×1280，与旧版产物**像素完全一致**；
> - 25 秒 / 3 段 → 113 秒完成（帧数损耗修复前的实测）；
> - 同一条 25 秒素材把 `结束索引` 传成 `0` 时，只产出 10 秒 / 240 帧——**这就是「只拿到第一段」的坑**。

**因此：把工作流复制去别处时，节点 121（PreviewAny）别删**——删了这条链就只能手动去
服务端 output 目录捞片子。

## 八、分段解码定位（帧数零损耗）

分段算法 `build_frame_segments()` 本身正确：0 → total 首尾相接，尾段不足 3 秒并入上一段。
帧数损耗出在解码定位 `fxai_video_utils._start_seconds()`：旧写法 `start/fps + 0.0001`
会让 ffmpeg 输入侧 `-ss` 把目标帧判成「早于定位点」丢掉，每段少首帧，末段无帧可补。

定位点算法：

```python
def _start_seconds(start_frame, fps):
    start = int(start_frame)
    if start <= 0:
        return 0.0
    return max(0.0, (start - 0.5) / fps)
```

判据：定位点取目标帧与前一帧的正中间，目标帧（`start/fps`）一定大于定位点不被丢，
前一帧（`(start-1)/fps`）一定小于定位点不被多带。`start=0` 直接归 0，不加偏置。
改完须重启 ComfyUI 生效（节点模块在进程启动时加载）。
