# 07 · 交付清单存储规范

> **何时读**：角色替换任务完成或建档时，需要组织项目目录、写交付清单、整理产物落点时。

## 目录结构

每个角色替换任务以**项目名**为顶层目录。目录层级**最多两层**：

- **单个文件直接放项目根目录**——只有一个原片、只有一个成片，不套子目录。
- **多同类才建子目录**——有多个版本实验时才建第二层目录分开。
- **临时文件单独放**——过程中的中间产物放 `临时文件/`，与正式产物分开，方便定期清理。

### 典型结构（多版本调参场景）


### 简单场景（单版本，不调参）

只有一个版本、没有多轮调参实验时，全部文件直接放项目根目录，**不需要任何子目录**：

```
<工作区>/
├── 吃猪蹄/
│   ├── 吃猪蹄.mp4          ← 原片
│   ├── 参考图.jpg          ← 参考图
│   ├── 替换结果.mp4        ← 生成结果
│   ├── 最终成片.mp4        ← 定稿
│   ├── 原片对比.mp4        ← 对比视频
│   └── 交付清单.json
```

### 关键规则

1. 🔴 **最多两层目录**：项目根目录为第一层，类别子目录为第二层，不得再套第三层。
2. 🔴 **单个直接放根目录**：只有一份原片、一份成片、一张参考图时，直接放项目根目录，不建子目录。
3. 🔴 **多同类才分目录**：多个版本实验 → 建 `调参实验/`；多段裁剪片段 → 建 `裁剪片段/`。
4. 🔴 **临时文件单独放**：过程中产生的中间产物（裁剪片段、试片视频、调试抽帧）放 `临时文件/`，与正式产物分开。项目定稿后可定期清理。
5. 🔴 **全中文命名**：目录名、文件名统一用中文，一看就懂。
6. 🔴 **交付清单.json 随项目走**：每个项目根目录一份。
7. 🔴 **原片只读**：放入后不修改、不覆盖，保证可溯源。
8. 🔴 **与标准产出铁律的关系**：标准层的 `_tmp/` 对应本册的 `临时文件/`；标准层的 `_fxai_project.json` 管页面进度，本册的 `交付清单.json` 管角色替换链路的全链路信息，两者并存不冲突。

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `项目名` | string | 是 | 项目名，与目录名一致 |
| `创建时间` | ISO 8601 | 是 | 项目创建时间 |
| `状态` | string | 是 | `草稿` / `进行中` / `已完成` |
| `原始素材` | object | 是 | 原片路径、参考图路径及元数据 |
| `生成链路` | object | 是 | 脚本、后端、参数、提示词版本 |
| `版本记录[]` | array | 是 | 所有版本记录，含状态（`已淘汰`/`定稿`/`实验中`） |
| `最终交付` | object | 是 | 最终交付物路径及技术参数 |
| `耗时统计` | object | 否 | 耗时统计，便于后续估时 |
| `备注` | string | 否 | 关键经验/注意事项 |

## 成片品牌角标

通则见 `fxai-standard/references/01`「成片品牌标识」。本机角色替换链的实现：

- 🔴 **文案取全局配置** `~/.workbuddy/fxai_global.json` 的 `brand.ai_mark_text`（当前 `凤希AI生成`），脚本不硬编码品牌名；读失败兜底同为 `凤希AI生成`。
- 角标 PNG 用 PIL 现生成：字号 26（`C:/Windows/Fonts/msyh.ttc`），宽 = `textlength(文案) + 44`、高 56，圆角 12，底色 RGBA `(12,14,20,175)`，白字居中。
- 合成时 `overlay=W-w-24:H-h-24`，叠在**规整后的成片**上，与配乐、帧率规整在同一次 ffmpeg 里完成；对比片直接继承成片，不重复叠。
- `交付清单.json` 的 `最终交付.AI标识` 写 `画面右下角「凤希AI生成」角标`。

## 对比视频画幅（按源片横竖选拼接方向）

跨技能通则见 `fxai-standard/references/01`「对比视频画幅」。本节定本机角色替换链的实现。

| 源片（ffprobe） | 拼接方向 | 格位 | 输出尺寸 |
|---|---|---|---|
| `width >= height`（横屏 / 方形） | `vstack` 上下堆叠 | 上＝原片，下＝成片 | `W×2H` |
| `width < height`（竖屏） | `hstack` 左右并排 | 左＝原片，右＝成片 | `2W×H` |

- 判据取源片 `<项目>/<原片>.mp4` 的 `width` / `height`；成片与既有对比片只作单格尺寸参照。
- 两路先统一到同一 `W×H`（取成片宽高，横屏项目常为 `960×512`），再拼接；`setsar=1` + `fps=<帧率>` + `setpts` 锁两路同步。
- 帧率、帧数、音轨与成片一致：音轨取成片，`-frames:v <总帧数>` 锁帧。
- 标签方位随拼接方向改：上下堆叠按上 / 下格对齐，左右并排按左 / 右格对齐；验收抽帧按同样格位判。
- 一键生成：`python -B scripts/make_compare.py --source <原片> --result <成片> --out <项目>/原片对比.mp4`。

横屏命令模板（`W×H` 为单格尺寸）：

```bash
ffmpeg -y -v error -i 原片.mp4 -i 最终成片.mp4 \
  -filter_complex "[0:v]scale=W:H,setsar=1,fps=FPS[a];[1:v]scale=W:H,setsar=1,fps=FPS[b];[a][b]vstack=inputs=2[outv]" \
  -map "[outv]" -map 1:a -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p \
  -c:a aac -b:a 192k -r FPS -frames:v N 原片对比.mp4
```

竖屏把 `[a][b]vstack` 换成 `[a][b]hstack`，输出 `2W×H`。

`交付清单.json` → `最终交付` 增记：

| 字段 | 类型 | 填什么 |
|---|---|---|
| `对比视频` | string | `原片对比.mp4` |
| `源片画幅` | string | `横屏` / `竖屏`，与判定一致 |
| `对比视频布局` | string | `上下堆叠` / `左右并排` |
| `对比视频分辨率` | string | 拼接后的 `宽x高` |

## 命名规范

全中文命名，文件名见名知义：

| 文件类型 | 命名格式 | 例 |
|---|---|---|
| 原片 | 保留原名或 `{项目名}.mp4` | `黑老大驾到.mp4` |
| 参考图 | `参考图.jpg` 或保留原名 | `参考图.jpg` |
| 裁剪片段 | `片段_{起}-{止}秒.mp4` | `片段_0-10秒.mp4` |
| 版本目录 | `v{序号}_{中文简述}/` | `v4_去头饰/` |
| 版本成片 | `替换结果.mp4`（目录内统一名） | `调参实验/v4_去头饰/替换结果.mp4` |
| 抽帧对比 | `{版本}_{时间}秒.jpg` | `v4_0.5秒.jpg` |
| 最终成片 | `最终成片.mp4` | 项目根目录 |
| 对比视频 | `原片对比.mp4` | 项目根目录 |
| 提示词 | `提示词.txt`（目录内统一名） | `调参实验/v4_去头饰/提示词.txt` |
| 交付清单 | `交付清单.json` | 项目根目录 |
| 临时文件目录 | `临时文件/` | 项目根目录下第二层 |
| 试片视频 | `test{时长}s_{版本}.mp4` 或保留原名 | `临时文件/test4s_v4.mp4` |
| 调试抽帧 | 保留原名或 `调试_{描述}.jpg` | `临时文件/调试抽帧/frame_0.jpg` |

## 什么算临时文件

过程中产生的中间产物，不属于正式版本产物：

| 类型 | 举例 | 生命周期 |
|---|---|---|
| 裁剪片段 | ffmpeg 裁出的测试片段 `片段_0-10秒.mp4` | 试片用完即可清 |
| 试片视频 | 验证提示词的短试片 `test4s_v4.mp4` | 确认效果后可清 |
| 调试抽帧 | 过程中抽的对比帧 `frame_0.jpg`、`chk_sbs.jpg` | 项目定稿后可清 |
| 哈希命名文件 | 下载临时素材 `4eefb8fdc3ba01cedce2dd8fd5a8409b.mp4` | 确认归属后归入或清理 |

项目定稿后 `临时文件/` 可整体清理，不影响交付完整性。
