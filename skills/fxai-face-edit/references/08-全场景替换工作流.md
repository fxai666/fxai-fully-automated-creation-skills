# 08 · 全场景替换工作流

> **何时读**：用户说「全场景替换」，或要求参考原片动作、机位与事件但把场景、家具、道具整套换掉时；
> 要给这类任务定交付范围、写提示词、拆镜头、做配乐、验收时。

## 一、模式定义

**全场景替换**是角色替换的一个具名工作流模式，触发词为「全场景替换」「换全部场景」「场景道具都换掉」「按原片动作复刻并换景」。模式注册表与以后新增模式的命名口径见 SKILL.md「替换工作流模式」。

一句话口径：**参考原片做的事，换成自己的人、自己的场景、自己的道具、自己的配乐。**

| 维度 | 执行 | 判据 |
|---|---|---|
| 人物 | 全片出镜人体整体换成参考角色，含远景人物、人体局部（手、手指、前臂、腿）、镜面与地面反射里的人 | 抽帧逐格比对，任何一格残留原人物皮肤、原服装袖口即命中 |
| 场景 | 地面、墙面、帘、家具、台面、容器、手持之外的道具，材质与款式整套换成另一套 | 任一镜头里场景主材或家具款式与源片一致即命中 |
| 事件 | 每个镜头各自的姿态、动作节奏、握持方式、同框人数、机位、景别、构图、光线方向、事件顺序逐帧保留 | 按帧号并排抽帧，构图与动作同步 |
| 片长 | 成片帧数、帧率、时长与源片一致 | `ffprobe` 三项对齐 |
| 配乐 | 成片音轨唯一来源为本次生成的纯器乐 wav | 源片音轨在成片中零引用 |

**模式边界**：用户明确指定「只换人、场景不动」时走 `references/06` 的保留场景写法，并在交付清单记录该口径；该任务不属于全场景替换。

## 二、端到端流程

按步序执行，每步的产出是下一步的输入。

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 建档 | 产物目录建好即 `fxai_project.py init` 建档，需求里写清场景风格短语与逐帧保留项 | 项目根有 `_fxai_project.json` |
| 2 拆片 | 读源片帧数/帧率/时长；`ffmpeg -vf "select='gt(scene,0.30)',showinfo"` 测切点，按帧号精确裁成单镜头片段 | 各段帧数之和＝源片总帧数 |
| 3 分类 | 按「画面里是否有人体」给每个单镜头片段分组，人体含手、前臂、腿、远景小人、反射里的人 | 判定依据为原尺寸单帧；缩略接触表只用于定位 |
| 4 配提示词 | 按分组选 `assets/` 模板，填入本项目场景风格短语 | 场景段与源片主材不同、可一眼分辨 |
| 5 生成 | 每个单镜头片段独立提交 `char_swap.py`，逐段落盘并 `ffprobe` 核对帧数 | 段结果帧数与源片段一致；长批量可断点续跑 |
| 6 配乐 | 生成纯器乐 wav、裁到片长、配平响度 | caption 含 `Vocal Details`；人声验收达标 |
| 7 拼接 | 各段 `concat=n=N:v=1:a=0`，成片音轨 wav 作唯一音频输入，`-r <fps> -frames:v <总帧数>` 锁帧 | 三者帧数一致 |
| 8 验收交付 | 按第六节逐项验收，出对比片与验收图，写交付清单 | 全部判据通过，清单字段齐 |

## 三、提示词

H3 六段式，`retention_analysis` 必写，`<Audio 1>` 用裸标签。模板两份，按镜头内容选：

| 模板 | 适用 | 关键差异 |
|---|---|---|
| `assets/全场景替换提示词-默认.txt` | 镜头里有完整人物或人物身体，含远景小人 | `retention_analysis` 只给人物与表演/构图 `fully_preserved`；场景改写正向明写在 `summary` 与 `detailed_description` |
| `assets/全场景替换提示词-人体局部.txt` | 镜头里只有手、手指与前臂，无人物出镜 | 主体定义只取参考图的手与前臂；整条可见小臂换到画面边缘；模板内不出现任何固定装置类别名称 |

填写与改写判据：

| 位置 | 填什么 | 判据 |
|---|---|---|
| `summary` 与 `detailed_description` 的场景段 | 本项目材质/风格级短语（地面材质、墙面材质、帘与家具主材、光色） | 与源片主材不同；不写具体固定装置名称 |
| `detailed_description` 手持物件段 | 动作依赖的物件类别、颜色、握持方式 | 抽样帧里该物件逐帧可见、位置与用途一致 |
| 负向 | 材质/风格级排除项 | 命中域例外：只列已确认会穿帮的具体写法，用「不得／禁用／勿」表述 |

规则：

1. 提示词里写固定装置类别名称（台盆、龙头、水槽一类）会把该物件带进别的镜头。判据：某个不含该物件的镜头里出现该物件即命中，改用人体局部模板。
2. 动作依赖的手持物件在该镜头专用提示词里点名保住。点名手持物件类别串场景的概率低，点名固定装置类别会串。镜头里无手持物件时删掉该段。
3. 多镜头源片在 `detailed_description` 写逐帧编辑定性与跨镜头独立性声明，判据见 `references/06`。
4. 某一镜头特有的物件写进该镜头专用提示词，全局描述只写贯穿全片的通则。
5. `detailed_description` 明写画面里原本没有的东西不得新增、原本有的东西不得移除。

## 四、镜头拆分与分类

1. 4 秒分段内出现多个切点时，按切点拆开各自生成再拼回。整片直跑会把多个镜头平滑成同一场景，并在无人镜头里补出人物。
2. 分类按内容派模板：

| 画面内容 | 处理 |
|---|---|
| 有完整人物或人物身体，含远景小人 | 默认模板 |
| 只有手/前臂，且动作依赖手持物件 | 人体局部模板 + 手持物件保留段 |
| 只有手/前臂，无手持物件 | 人体局部模板，删手持物件段 |
| 无任何人体 | 保留画面，做统一暖调校色 |

3. 相邻镜头的场景材质跨镜头连贯。判据：并排抽帧里家具与地面主材一致；某个镜头换景、相邻镜头保留源片主材即命中。
4. 长批量逐段落盘、每段核对帧数后进入下一段；等待型脚本靠上一段产物帧数正确串行排队。并发提交同一后端会互相抢队列，多个生成任务之间用产物帧数握手。
5. 试片挑镜头切换最密、内容最特殊的那一段；只跑开头段测不出跨镜头漂移。

## 五、纯器乐配乐（默认必做）

1. 生成入口 `fxai-slide-video/sv_bgm.py`，参数 `--model minimax3 --vocal none --duration <片长+10> --seed 42`。生成实现归 `fxai-slide-video`，本册只定入口与验收口径。
2. caption 用完整三段式 `Global Metadata` / `Vocal Details` / `Arrangement`。判据：caption 含 `Vocal Details` 时脚本原样采用；仅传风格串时脚本把它追加在内置基调之后，生成结果带电子流行底色即命中。`Vocal Details` 写清无演唱、无哼唱、无和声、无呼吸声、无念白、无口哨、无人声采样、无合唱垫音。
3. 三档 caption 在 `assets/纯器乐配乐caption-*.txt`：轻柔、紧凑、耐听。用户未指定时取轻柔叠加耐听的编制。三档共同判据：中频留白、低频收敛、无鼓组、无电子节拍、无合成器主奏、无刺耳高频，情绪舒服、可长时间听。
4. 原始 wav 时长须覆盖片长加淡出余量。短于片长时重新生成；循环补足会听出重复。
5. 后处理：`atrim` 裁到片长、淡入 0.15 秒、淡出 0.7 秒、`loudnorm=I=-16:TP=-1.5:LRA=11`，按唯一音轨电平配平。垫底 BGM 的 −32 dBFS 侧链口径不适用。
6. 挂音轨两种方式：换音轨时 `-map 0:v -map 1:a -c:v copy`，画面流 MD5 不变；多段重拼时把成片音轨 wav 作 `concat` 之外的唯一音频输入。
7. 无人声验收走 `fxai-vocal-separate` 分离成片音轨。判据：人声轨 mean ≤ −40 dBFS、语音频段（300~3400Hz）比主音轨低 ≥ 20 dB、静默时长占全片 ≥ 95%。出现短瞬态时定位到具体乐器再判定，并把结论写进交付清单。
8. 交付物落在 `<项目>/配乐/`：原始 wav 与成片音轨 wav 各一份。

## 六、画面验收

| 检查 | 做法 | 判据 |
|---|---|---|
| 帧数 | 各段帧数求和；成片与对比片用 `-r <fps> -frames:v <总帧数>` 锁帧 | 合计、成片、对比片三者一致 |
| 分段边界 | 跨 4 秒的片段抽边界前后连帧 | 无跳色、无回到源片帧、无黑帧 |
| 人体 | 每 20 帧均匀采样 + 原片/成片上下并排 | 无真人肤色、无只换手掌留下的真人小臂、无远景真人 |
| 道具 | 逐格清点源片物件 | 物件都在、位置用途一致、款式已换 |
| 全片 | 每个镜头一个中点帧做 N 格并排 | 无串镜、无凭空加人、无黑帧、各格构图独立 |
| 指定区间 | 用户给出时间区间时按秒抽帧扫描 | 区间内每格满足人体与场景判据 |

## 九、返修四坑（2026-11-07 实测，开工前自查）

`牵牛田间` v1 被用户一次打回四条，逐条对应判据与做法。四条都是**静默失败**——脚本不报错、帧数也对，但成片不能用。

| 坑 | 表现 | 根因 | 必做 |
|---|---|---|---|
| 场景没换 | 并排看背景跟原片几乎一样 | 场景风格短语写成了原片本身 | 同类不同套，见 §9.1 |
| 模糊 | 成片比原片软、背景糊 | `max-side` 小于源片长边，静默缩分辨率 | 见 §9.2 |
| 脸忽大忽小 | 逐帧头部占比在跳 | 提示词没锁面部尺寸 | 见 §9.3 |
| 段间不一致 | 段边界跳、动作节奏一顿一顿 | 分多次独立提交 + VFR 手动拼接 | 见 §9.4 |

### 9.1 场景短语必须「同类不同套」

先列出原片主材五项：**地面材质 / 植被种类 / 树木形态 / 建筑款式 / 色调与光质**。新场景至少换掉其中四项，并在负向里把原片主材逐项点名排除。

判据：原片帧与成片帧左右并排，一眼能分辨不是同一个地方。**绝不能把「古风青绿田园」用在本身就是竹林＋荷塘＋水田＋黄墙黛瓦的源片上**——那等于把同一套景重绘一遍，不叫换景。用户说「风格取类似的」指田园/乡野这个大类保持，不是主材照搬。

### 9.2 `max-side` 按显存档位，不追源片长边

**默认值由显存决定**（`comfy_client.default_max_side()`）：本机 **≤16G 卡 960**、本机 **≥24G 卡 1280**、**线上实例 1280**；显式 `--max-side` 优先。

档位低于源片长边是**既定取舍，不是故障**：16G 卡硬上 1280 会 OOM，把长边压到 960 是稳定性与可用性的平衡；成片比原片软属于这个取舍的一部分。

| 源片 | 设 960 | 设 1280 |
|---|---|---|
| 720x1280 | 输出 512x960（糊） | 输出 704x1280 |

工作流按 64 倍数对齐，长边小于源片就会被缩。**只有明确要更高分辨率、且卡够（≥24G 或线上）时才显式抬高**；不传就走显存默认，不要按源片长边自动抬。生成后 `ffprobe` 核对成片长边是否等于所选档位（对齐误差 ±64 内正常），差一档即判错档、回查脚本有没有被写死旧默认值。低步数采样本身会软化背景，另在 `detailed_description` 补「画面锐利清晰、高细节」段，`负向` 补「不要模糊、软焦、涂抹感、低分辨率糊片、背景糊成一团」。

### 9.3 面部尺寸恒定单列最高优先级段

原片推镜会让人脸一大一小，但替换后的角色必须全程一致。在 `detailed_description` 单列一段并标 🔴：

> S1 的头部尺寸、脸部大小、五官间距与比例、面部在画面中的占比全程恒定，每一帧完全一致；不随镜头推进把脸放大、不随帧波动忽大忽小。头部高度占画面高度的比例、双肩宽度、头身比、机体分节尺寸在全片每一帧保持不变。五官形状、发型轮廓、机体接缝形状也逐帧一致。

负向再重复一遍「不要脸部尺寸忽大忽小、不要在近景把脸放大、不要让头部占比逐帧变化」。验收取帧 0 与尾帧并排量头部占比。

### 9.4 整片一次提交 + VFR 规整

1. **整片一次提交**（`--start-index 0 --end-index -1`），让工作流内部循环分段。只有内部循环时 `11→14` 的接缝首帧锚定（`value1`）与 28 接缝色彩对齐才生效；**拆成多次单段提交等于把这两道保险关掉**，段边界必然跳。
2. **VFR 源片先规整**：`avg_frame_rate` 与 `r_frame_rate` 不一致、帧间隔混杂（如 0.067/0.133/0.2s）时，先转均匀时间戳：
   ```bash
   FPS=$(python -c "print(161/15.066667)")   # FPS = 总帧数 / 时长
   ffmpeg -i 源片.mp4 -vf "setpts=N/(${FPS}*TB)" -fps_mode passthrough \
          -c:v libx264 -crf 16 -c:a aac 原片_CFR.mp4
   ```
   🔴 **必须保留音轨**：`-an` 会让提示词里的 `<Audio 1>` 报「提示词引用的素材不足：音频需要 1 个，实际只有 0 个」。
3. **工作流输出帧率常与输入不同**（如输入 10.686fps、输出 11fps、161 帧只有 14.64s）。用同一 `setpts=N/(FPS*TB) + -fps_mode passthrough` 把时长还原，帧数不变。**不要用 `-r`、`fps` 滤镜或 `-fps_mode cfr`**，它们会重采样丢帧（实测 161→116/44）。
4. **挂音轨别加 `-shortest`**：音轨比视频短 0.0002s 就会裁掉最后一帧（161→160）。
5. **对比片**：两边统一 `fps=<真实fps>` 帧网格后再 `hstack`，末尾加 `-frames:v <总帧数>` 锁帧；否则时间戳网格不一致会补帧到 300+ 帧。
