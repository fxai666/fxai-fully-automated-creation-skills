# 04 · 等结果与排障

> **何时读**：提交之后。查任务状态、等结果、产物不对劲时。

## 状态取值

| status | 含义 | 下一步 |
|---|---|---|
| `queued` | 排队中 | 继续等；`health` 看 `queue` / `running` 判断前面排了几个 |
| `running` | 处理中 | 看 `progress` 与 `message` |
| `succeeded` | 完成 | `download` 取产物 |
| `failed` | 失败 | 看 `log` 尾部定位 |
| `cancelled` | 已取消 | 重提或改参数 |
| `interrupted` | 服务重启等打断 | 重提 |

服务端单 worker 串行处理，`queued` 堆积属正常，不是卡死。

## 等法

```bash
P=~/.workbuddy/skills/fxai-face-edit/scripts/face_edit.py

python "$P" submit --target 目标.mp4 --processors 换脸 --no-wait   # 只拿任务号
python "$P" status <任务号>                                        # 随时查，带日志尾部
python "$P" cancel <任务号>                                        # 不想等了
python "$P" delete <任务号>                                        # 连产物一起删
```

`submit` / `run` 默认一直等到终态（默认上限 1800 秒，`--timeout` 可调）。
超时抛错时任务仍在服务端跑，接着用 `status` 看进度；此时重提会多占一个 worker。

- 🔴 收到「仍在运行 / 你会被自动通知」这类提示后立刻停止查询，`block=true` 长等一律改用 `status` 单次查。
- 查进度用 `status`，一次查一次；连续轮询空耗。

## 排障表

| 现象 | 判据 | 处置 |
|---|---|---|
| 连不上服务 | `health` 抛「连不上」 | 交给用户开机，见 01 册 |
| 上传被拒 | 接口返 413 | 单个请求上限 4 GB，切短或压码率后再传 |
| 提交被拒：需要头像 | 处理器含换脸类 | 补 `--source` |
| 提交被拒：唇形同步 | 目标不是视频 | 换视频目标 |
| `faces` 返回 `count` 为 0 | 这一帧没人脸 | 换帧号重测，见 03 册 |
| `failed` | 看 `status` 的 `log` | 日志尾部有服务端原始报错 |
| 产物视频没声音 | 音轨丢了 | `--option output_audio_encoder=aac`，改 flac 会丢音轨 |
| 产物视频异常小 | 校验抛「仅 N 字节，判为坏片」 | 重提；持续如此查服务端 ffmpeg 版本 |
| PNG 缺 IEND / JPEG 头不对 | 下载校验抛错 | 重下或重提 |
| 排队过久 | `health` 的 `queue` 持续不降 | 用 `jobs` 看是不是有别人的任务占着 worker |

## 产物落点与校验

产物下载到 `--out-dir`（缺省当前工作目录），文件名取服务端 `output_name`。
下载后自动过完整性校验：PNG 查 IEND、JPEG 查文件头、MP4 查 ftyp 且小于 10 KB 判坏片。
校验不过直接抛错，不返回路径。
