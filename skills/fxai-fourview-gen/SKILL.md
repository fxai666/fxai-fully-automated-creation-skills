## 🚨 ComfyUI 服务端模式铁律（硬）

ComfyUI 是**服务器端模式**运行，服务器很可能装在**另一台机器**上，**本机磁盘 ≠ 服务端磁盘**。
- 🔴 确认 `avatar/000.png` 等参考图或任何 `fxai/image/...` 资源是否存在时，**只走接口判定**：本机用 `find`/`ls` 扫 ComfyUI 资源目录得到的「有/无」不可信、不代表服务端真实状态。
- ✅ 确认方式只走接口：① 直接提交工作流，被服务端 `queued` 即最权威证明服务端已读到参考图；② 或 `GET /fxai/down/file?url=<category/subdir|file>` 探测。**通用铁律见 `fxai-workflow` 技能。**
- 🔴 **开工前读 `fxai-workflow/SKILL.md` 的「🚨 ComfyUI 服务端模式铁律」全文**（本技能只摘了上面两条，铁律原文在被依赖件里，不在 `comfy_client.py`）。
- 🔴🔴 **服务与技能解耦（API 模式）**：ComfyUI 由「凤希本地AI控制台」／启动器启停，本技能只按地址发 HTTP；本机 8188 探不通 → 走云或提示人启动。

## 何时调用本技能

- MV 多参考（multiref）模式：需要把人物四视图作为 `<Picture 1>` 注入 Ref2VA 提示词。
- 短剧 / 数字人口播 / 动画：首次缺角色三视图时建档，存项目 `角色三视图/`。
- 任何"要保持同一人物跨镜头/跨场景外观一致"的场景。

## 规则（用户硬性规定）

- **短剧/MV 多参考链路（Ref2VA / multiref）里，角色视图一律走【四视图】**：本地四视图工作流两种输入都出四视图。
- **用得到我们自己角色的地方，必须用我们自己的参考图生成四视图**（锁脸锁身段），走纯提示词生成会丢一致性；自有参考图 = 全局头像库 `avatar/000.png` / `avatar/001.png`，只传路径不重传；只有非自有角色才按提示词生成。
- 三视图是另一套独立工作流（`img-qwen21-threeview.json`），只在明确要三视图时调；默认路径是四视图。
- 默认 `gen_char_view(prompt, ref="avatar/000.png")`；没自有参考图就 `gen_char_view(prompt)`（ref 留空，仍然四视图）。
- **三视图输出 1280×1080**（工作流节点 203 写死，代码不覆盖、不传参）。
- **四视图 V2 输出 = 「参考锚脸特写 + 四视图」横向拼接图**（节点 `210` 出锚脸特写、节点 `205` 出四视图，节点 `197` ImageStitch 拼成一张），输出 **2168×1280**，不是 1280×1080——别按固定尺寸推算下游。四视图支路的宽高由节点 199 `FxAiPhotoSizeConfigV2` 给出（已固化 1280×1080，锚脸支路取宽度÷2 由节点 204 `FxAiMathInt` 自动算），`反转` 参数是「宽↔高互换」必须保持 `false`。
- 人物须为**自有角色**（000/001）；他人肖像有侵权风险。

## 等任务

四视图/三视图走共享客户端的 `submit_workflow`，内部等 `fxai:task_saved`（＝**已保存**）才返回，返回即已过终态门。

| 阶段 | 规则 |
|---|---|
| 等待期·**正常** | ✅ 只查健康（服务器/进程还活着吗）<br>❌ 不做数据交互：不查 `/history`、不拉文件列表、不取结果、不下载、不反复 curl `/queue` |
| 等待期·**报错** | ✅ **这时才做数据交互**：取错误详情与日志，分析原因并解决。异常里带 `prompt_id`，用 `comfy_watch.py status <pid>` 查详情 |
| **终态门** | 日志出现 `✅ 合并成功，已保存：<url>` 之后，才做后续：取产物 → 归档 → 交付 |

- 要在对话里只在完成时播报一句 → `comfy_watch.py next <pid>`（只出终态，不刷过程）。
- 要全程看进度 → 双击 `fxai-comfyui-watcher/progress.html`（直连 WS，绕过对话，不耗 token）。
