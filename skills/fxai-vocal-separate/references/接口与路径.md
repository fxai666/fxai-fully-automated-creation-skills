# 接口与路径（提交前 / 排查时照查）

## 工作流登记（位置与配置处）

- **文件位置（配置目录）**：公共工作流目录 `fxai-workflow/`（与各 `fxai-*` 技能同级），命名 `<类别>-<模型>-<用途>[_api].json` →
  - **`vc-melband-vocalsep-api.json`**（当前实际使用）：Mel-Band RoFormer，服务端节点 `FxAiMelRoformerLoader` + `FxAiMelRoformerSampler`（凤希AI 封装，来自 `custom_nodes.fxai-toolkit`），模型 `MelBandRoformer_fp32.safetensors`。
  - `vc-uvr-vocalsep-api.json`：备用占位模板（换其它分离模型时用它改）。
- **登记处**：`fxai-workflow/comfy_client.py` 的 `WORKFLOWS` 注册表 —— `"vocalsep": {"melband": "vc-melband-vocalsep-api.json", "uvr": "vc-uvr-vocalsep-api.json"}`，默认模型 = 第一项（`melband`）。代码一律走 `cc.resolve_wf("vocalsep", model)`，文件名由注册表提供。
- **提交前格式自检**：`comfy_client.WF_SPECS["vocalsep"]` 校验节点 `815`（音频文件，str）与 `816`（目录，str）；换工作流后节点 id 变了需同步这里。

## 工作流内节点结构（服务端导出，id 固定）

- `821` FxAiMelRoformerLoader → `模型文件`（下拉选 `MelBandRoformer_fp32.safetensors`），输出 MELROFORMERMODEL
- `820` FxAiMelRoformerSampler → 入 `模型`[821,0] + `音频`[815,0]，输出 0 = 人声、1 = 伴奏
- `815` FxAiAudioSelector → `音频文件` = 占位符 `fxai_audioinput`
- `816` FxAiAudioManager → `目录` = 占位符 `fxai_outputdir`，音频接 `[820, 0]`（人声）
- `819` FxAiClearCache（收尾清缓存）

⚠️ **`816` 的「目录」必须留占位符 `fxai_outputdir`**：ComfyUI 导出时常把它写成硬编码目录名，一旦写死，服务端产物全挤进同一个目录、编号持续递增且 `out_sub` 传参失效。

## 占位符（与全局一致，勿改写成 fxai_audio）

- `fxai_audioinput` → 输入音频的服务端相对路径（提交时替换为 `audio_rel`）。
- `fxai_outputdir` → 服务端输出子目录（默认按 audio_rel 派生，如 `<歌名>_vocalsep`；产物落在服务端 `fxai/audio/<该目录>/`）。
- 提交：`comfy_client.submit_workflow(wf, {"fxai_audioinput":..., "fxai_outputdir":...}, kind="vocalsep")` → 轮询 `/fxai/tasks/result` → 下载。

## 服务端状态确认（查接口）

- 服务端在线时，`FxAiMelRoformerSampler` / `FxAiMelRoformerLoader` / `FxAiAudioSelector` 均已注册（属 `custom_nodes.fxai-toolkit`），模型 `MelBandRoformer_fp32.safetensors` 在 `模型文件` 可选列表里。
- 资源状态一律查接口，节点源码的 requirements 只作参考：
  - `GET /object_info/FxAiMelRoformerSampler` 有返回 = 节点已注册（fxai-toolkit 已装好）；
  - `GET /object_info/FxAiMelRoformerLoader` 的 `模型文件` 列表 = 服务端可见的分离模型。
- 真缺依赖时：`pip install rotary_embedding_torch einops` 装进 **ComfyUI 运行环境（conda）** 并重启 ComfyUI。

## 等任务

人声分离走共享客户端 `submit_workflow`，内部等 `fxai:task_saved`（＝**已保存**）才返回，返回即已过终态门。

| 阶段 | 规则 |
|---|---|
| 等待期·**正常** | ✅ 只查健康（服务器/进程还活着吗）<br>❌ 不做数据交互：不查 `/history`、不拉文件列表、不取结果、不下载、不反复 curl `/queue` |
| 等待期·**报错** | ✅ **这时才做数据交互**：取错误详情与日志，分析原因并解决。异常里带 `prompt_id`，用 `comfy_watch.py status <pid>` 查详情 |
| **终态门** | 日志出现 `✅ 合并成功，已保存：<url>` 之后，才做后续：取产物 → 归档 → 交付 |

- 要在对话里只在完成时播报一句 → `comfy_watch.py next <pid>`（只出终态，不刷过程）。
- 要全程看进度 → 双击 `fxai-comfyui-watcher/progress.html`（直连 WS，绕过对话，不耗 token）。
