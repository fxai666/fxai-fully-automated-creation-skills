# 03 · 选图与出图接口

> 何时读：选人/选服装/选姿势、调工作流、路径传参、素材传到服务端时。

## 三选一流程

1. **人物**：走 `fxai-role-management` 角色库（`scripts/role_mgr.py list / get`），取角色头像路径，作为图1。本技能不生成人物。
2. **服装/套装**：`select.py pick/find --类型 服装` → 得到 `图片` 相对路径，作为图2。
3. **姿势**：`select.py pick/find --类型 姿势` → 得到 `图片` 相对路径，作为图3。
   `pick` 逐层过滤：一级 → 二级 → 三级 → 名称；多一层目录就多问一层（接口不变，只多一次筛选）。

## 素材目录（服务端，纯壳）

服务端素材根目录 = ComfyUI 的 `fxai/image/`（见 `fxai-toolkit/fxai_character_image_selector.py` 的 `get_image_path`：`base_dir = "fxai/image"`）。

目录采用**英文目录名 + 中文显示名**映射：定义在 `fxai-toolkit/js/fxai_category_config.js` 的 `CATEGORY_CONFIG`，图片选择器按英文名列图（`/fxai/image/v2/list?subdir=<英文名>`），界面显示中文。系统既有映射（本技能只用到前两个落点，其余供参考）：

| 界面显示 | 实际目录名 | 磁盘形态 |
|---|---|---|
| **姿势** | `pose` | 软链 → 图库仓库 `img/`，脚本里写 `pose/<文件名>` |
| **套装** | `clothes` | 软链 → 图库仓库 `img/costume/`，脚本里写 `clothes/<文件名>` |
| 角色 | `avatar` | 实体 |
| 视图 | `views` | 实体 |
| 素材 | `sucai` | 实体 |
| 场景 | `scene` | 实体 |
| 上衣 / 裙子 / 裤子 / 鞋袜 | `tops` / `skirts` / `pants` / `shoessocks` | 实体 |
| 首饰 / 胸罩 / 内裤 / 装备 / 家具 / 宠物 / 座驾 / 产品 | `jewelry` / `bra` / `underpants` / `equipment` / `furniture` / `pet` / `vehicle` / `products` | 实体 |
| 其他 | `other` | 实体 |

使用者可直接在 `image/pose/`（姿势）或 `image/clothes/`（套装）里放图，也可在这两个目录下自建任意子文件夹（按风格、题材、偏好等任意维度），放什么由使用者决定，本技能不判定内容。`registry.py scan <素材根目录>` 会按真实子目录层级索引；`图片` 列存相对路径，选完原样交给出图客户端。

## 路径传参（接口不变）

- 登记表 `图片` 列存相对路径（基准 = 数据目录或 `FXAI_CHARACTER_STYLING_DATA`）。
- `select.py path <id>` 原样输出该路径；`--resolve` 才转绝对路径。
- 三图按「**图1人物 / 图2服装 / 图3姿势**」顺序拼进 `fxai_imageinput`（逗号分隔），与提示词的图序严格对齐。

## 出图（本技能 API 客户端）

- 入口：`scripts/styling_api.py generate_styling(...)` 或 `python styling_api.py --人物 ... --服装 ... --姿势 ...`。
- 链路：三图各自 `upload_image` → 服务端相对路径 → 拼 `fxai_imageinput` → `submit_workflow` → 下载。提交/轮询/下载全委托 `fxai-workflow/comfy_client.py`。
- 工作流：`fxai-workflow` 注册表 `charstyling` → `qwen21` → `charstyling-qwen21-api.json`（UI/API 版在 ComfyUI `凤希AI/角色造型合成V1*.json`）。
- 提示词：必须由 `prompt_builder.build_recipe_prompt()` 生成，零穿搭文字（服装名称只在括号辅助）。
- 尺寸：本机默认 960 档，不自行抬档（用户硬规则）。
- 本机 8188 探不通 → 报错让人启动，不自行拉起 ComfyUI。
- `--dry-run` 只构建提示词与参数，不提交；去掉它才真提交。
- `compose.py` 仍是纯编排（只组织、不内嵌生图）；真出图走 `styling_api.py`。

## 产物落点

生成图按项目方式落 `<项目空间>/图片/<项目名>/`；中间与草稿只进 `_tmp/`。
