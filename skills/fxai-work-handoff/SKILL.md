# fxai-work-handoff · 工作交接清单

交接文档落在**实际工作项目的文件夹根目录**：`<项目根>/工作交接清单.md`，与该项目的成片、素材、`_fxai_project.json` 同级。
不写进工作区根、不写进 `.workbuddy/memory/`、不写进技能目录。目标：接手方读完不需要再问，直接开工。

## 本技能文件清单（先读这里，再决定读哪册）

| 文件 | 什么时候读 |
|---|---|
| `references/01-交接清单写法.md` | 写或改清单、逐节填内容、判「够不够细」时 |
| `references/02-接手开工.md` | 你是接手方，读完清单要开工；或清单与实际不符时 |
| `scripts/handoff.py` | 生成骨架 / 体检 / 打印；改判定规则才读 |

**确定本次要做什么之后，只读对应的那一册，其余一律不读。**

## 直接开跑

```bash
S=~/.workbuddy/skills/fxai-work-handoff/scripts

python -B $S/handoff.py init  <项目目录> [--to "<接手人>"]   # 建骨架，自动填客观事实
python -B $S/handoff.py check <项目目录>                     # 体检：缺节 / 未填 / 死链
python -B $S/handoff.py show  <项目目录>                     # 打印节标题与待填项
```

- `init` 已有清单时不覆盖（退出码 3），`--force` 才重建，旧清单改名进 `<项目根>/_tmp/`。
- `check` 退出码：0 通过 / 3 待补（缺节、`<待填` 残留、死链）/ 1 出错。
- 死链范围：二节引用路径、六节文件地图首列、三/四/五/十一节写的绝对路径；相对路径不校验（十一节技能册指针相对技能根）。
- 项目根优先由 `_fxai_project.json` 定位（`fxai_project.py context <任意路径>`），无清单时取传入目录。

## 铁律速查

1. 🔴 落点固定 `<项目根>/工作交接清单.md`，与项目产物同级；项目根按 `_fxai_project.json` 认定。
2. 🔴 全篇写「接手方要执行的动作」：每条给 在哪做、怎么做、做完判据；自己做到哪只作背景。
3. 🔴 已完成项列产物绝对路径 + 判据；同一交付物只列最终版。
4. 🔴 待办逐条编号，写依赖与卡点；卡在外部时写明找谁、给什么。
5. 🔴 硬约束写本项目取值（时长、尺寸、档位、模型、文案口径、编码、命名），标准只给指针。
6. 🔴 清单里每个路径都真实存在，或在同一行标「尚未生成」；`check` 报失效即改。
7. 🔴 交接只读现状 + 写这一份文档：不改产物、不跑生成、不动项目代码。
8. 🔴 项目有 `_fxai_memory.md` / `_fxai_project.json` 时在清单里指路，进度不另写一份。
9. 🔴 密钥、token、密码不进清单，只写取值位置。
10. 🔴 交完在项目记忆追加一条：交接时间、接手人、清单路径。

## 指针

- 产物落点、`_tmp`、交付版本口径：`fxai-standard/references/01-产出铁律.md`。
- 项目建档与记忆：`fxai_project.py`（`init` / `stage` / `memory`）；记忆写法：`fxai-standard/references/09-会话记忆.md`。
- 接手方要用的技能册由清单「记忆与标准指针」一节列明，不复制正文。
