# 02 · 接手开工

> **何时读**：你是接手方，项目根有 `工作交接清单.md` 要读；或清单与实际不符需要定处理口径时。

## 开工五步

1. **读三节即可判断是否可开工**：一、一句话现状 → 三、接手第一件事 → 十二、验收标准。
2. **核对现状**：按第六节文件地图逐个 `ls`，按第七节跑法确认服务在不在；有出入先记下来，不先动手。
3. **确认卡点**：第五节里有卡在外部的事项，先向交接方或用户确认，不自行假设已解决。
4. **按第三节第一条动作开工**：一条做完、验收过，再进下一条；同时把结果写回项目记忆。
5. **回报**：做完一节或遇到阻塞，回一条「做了什么 / 产物路径 / 卡在哪」，不写流水账。

## 清单与实际不符

| 情况 | 处理 |
|---|---|
| 产物路径不存在 | 先全目录搜同名文件；找到就改清单，找不到按「未完成」处理，进待办 |
| 清单说已完成、实际只做了一半 | 以实物为准，把它移回待办并写明缺口 |
| 清单缺关键信息（模型、参数、文案口径） | 回技能册查；技能册也没有，停下问用户，不自行取值 |
| 清单与实际冲突且都有道理 | 以用户当次确认为准，改清单并记入项目记忆 |

- 改动清单时**只改事实部分**，不删交接方写的硬约束与遗留问题；硬约束要改，先问用户。
- 每次修正清单后跑 `handoff.py check <项目目录>`，保持退出码 0。

## 禁区

- 不重跑清单里标了「已完成、勿重做」的步骤。
- 不把历史版 / 变体产物重新放回交付目录。
- 不因为「上次那样跑通了」就跳过技能册口径。
- 不在项目根建 `video/` `music/` `doc/` 分层，产物仍放项目根，中间件进 `_tmp/`。

## 干完的收尾

1. 清 `_tmp/` 与过程件，跑 `check_project_clean.py <项目目录>`。
2. 更新 `_fxai_project.json` 阶段（`fxai_project.py stage` / `episode`）与 `_fxai_memory.md`。
3. 清单第十三节「交接自查」重勾一遍；下一步若还要交人，就地改写第一、三、五节。
