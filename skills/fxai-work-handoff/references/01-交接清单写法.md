# 01 · 交接清单写法

> **何时读**：写或改 `工作交接清单.md`、逐节填内容、判「够不够细」时。

## 总判据

一句话：**接手方拿着这份清单，不问你任何问题就能继续干，且干完知道什么算干完。**

三处硬判据：

1. 每条动作都能直接执行——有位置（文件 / 目录）、有做法（命令或操作）、有完成判据。
2. 每个路径都真实存在，或在同一行标「尚未生成」。
3. 同一件事只有一个事实源：标准写法指到技能册，进度指到 `_fxai_memory.md`，清单不复制正文。

## 十三节逐节要求

| 节 | 必须写到的内容 | 不达标的形态 |
|---|---|---|
| 一、一句话现状 | 项目在做什么、停在哪一步、还差什么 | 只写「进行中」「已完成一半」 |
| 二、交接卡 | 项目名、项目根绝对路径、分类、当前阶段、交接时间、交接给谁、当前交付物 | 路径写成相对路径 |
| 三、接手第一件事 | 编号动作 1~3 条，每条含 在哪做 / 怎么做 / 做完判据 | 写「继续做视频」这类无法执行的动作 |
| 四、已完成 | 每项给产物绝对路径 + 判据 + 哪部分勿重做 | 只有一句「已完成大部分」 |
| 五、待办与下一步 | 表格：编号 / 任务 / 依赖 / 产物 / 验收判据 / 卡点 | 待办无验收判据，或卡点写「待定」 |
| 六、关键文件地图 | 表格：路径 / 是什么 / 改动方式 | 只列目录不列文件，或漏掉入口脚本 |
| 七、跑法与环境 | 所需服务、端口、启动命令、账号取值位置 | 只写「环境已配好」 |
| 八、硬约束 | 本项目取值：时长、尺寸、档位、模型、文案口径、编码、命名 | 复制技能标准正文 |
| 九、坑与绕法 | 现象 → 处理，一条一行 | 写「有问题再说」 |
| 十、素材与授权 | 素材来源、可商用范围、授权台账位置 | 只写「素材已备」 |
| 十一、记忆与标准指针 | `_fxai_memory.md`、`_fxai_project.json`、工作区记忆、该读的技能册清单 | 只写「看记忆」 |
| 十二、验收标准 | 什么算这条活干完，逐条可判 | 写「做好看一点」 |
| 十三、交接自查 | 勾选项：各项已填、路径已验、产物未动、记忆已更新 | 空表或全勾但未填上文 |

## 三、接手第一件事的写法

- 只写**下一个动作**，最多三条；后面的放进第五节，不在这里铺开。
- 每条三段式：`在哪做`（文件 / 目录绝对路径）→ `怎么做`（命令或界面操作）→ `判据`（跑完看什么算过）。
- 需要用户拍板的动作排在第一条，写清要回答什么；其他动作排后面。
- 依赖外部服务的动作写「服务没起时找谁、给什么」，不写「先自己拉起服务」。

## 八、硬约束的取值来源

- 本项目固化下来的取值（分辨率档位、模型名、时长、文案口径、编码、命名规则）逐条列出，写数字不写形容词。
- 取值来自技能册的，写「取值 + 出处册名」，正文不转述规则。
- 该项目的禁区（不许改的文件、不许动的素材、不许替换的模型）单列在这一节末尾。

## 九、坑与绕法的写法

- 一行一条：`现象 → 处理`。现象写可观测的报错或画面，不写猜测的原因。
- 已解决与未解决的分别标 `已绕开` / `仍卡住`；仍卡住的进第五节待办，不在此重复。

## 十一、记忆与标准指针

按层写路径，不复制内容：

| 层 | 指向 |
|---|---|
| 项目记忆 | `<项目根>/_fxai_memory.md`（无则写「尚未生成」） |
| 项目清单 | `<项目根>/_fxai_project.json` 的 `summary` / `stages` |
| 工作区记忆 | `<工作区>/.workbuddy/memory/` 的 `MEMORY.md` 与最近日志 |
| 用户级 | 跨项目铁律在用户级 `MEMORY.md` |
| 技能册 | 本项目用到哪几个技能，逐个列名 + 该读的册 |

## 交接前自查

1. 跑 `handoff.py check <项目目录>`，退出码 0。
2. 手动点一遍第一节到第三节：只看这三节能否开工。
3. 确认产物没被本次交接改动（`git status` 或文件时间）。
4. 项目记忆已追加交接记录。
