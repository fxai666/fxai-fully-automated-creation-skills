# 01 · 环境与路由

> **何时读**：开工第一步。查服务地址从哪来、全局配置怎么填、服务没起怎么办、显存什么时候释放。

## 服务形态

| 项 | 值 |
|---|---|
| 形态 | 常驻 HTTP 服务，独立进程，监听 `0.0.0.0:8187` |
| 名称 | `fxai-svc`（`fxai.json` 里 `name: rvc`） |
| 鉴权 | 无。跨机访问由网络层隔离 |
| 启停 | 由人启停。技能只发 HTTP，不代管开关机 |
| 网页 | `http://127.0.0.1:8187`（工作台）/ `/train`（训练）/ `/library`（作品库） |

## 全局配置（复制即用）

写进 `~/.workbuddy/fxai_global.json`。**只填这一块**，路径与解释器都按约定自动解析：

```json
"rvc": {
  "local_url": "http://127.0.0.1:8187",
  "cloud_url": "",
  "prefer_local": true,
  "idle_timeout": 90,
  "sep_backend": "melband",
  "timeout": 900,
  "train_epochs": 250,
  "train_batch": 8,
  "train_sr": 40000,
  "sep_model": "MelBandRoformer_fp32.safetensors"
}
```

| 键 | 作用 | 取值判据 |
|---|---|---|
| `local_url` | 本机服务地址 | 缺省 `http://127.0.0.1:8187` |
| `cloud_url` | 线上地址 | 留空 = 只走本机 |
| `prefer_local` | 本机优先 | `true`：本机探得通就用本机；探不通转 `cloud_url` |
| `idle_timeout` | 空闲卸载秒数 | 服务启动时读它；`0` = 模型常驻 |
| `sep_backend` | 默认分离后端 | `melband`（内置）/ `skill`（外部 ComfyUI） |
| `timeout` | 客户端等终态上限 | 秒。3 分钟歌约 45 秒，给 900 足够 |
| `train_epochs` / `train_batch` / `train_sr` | 训练默认参数 | 与现役音色同规格：250 / 8 / 40000 |
| `sep_model` | 分离模型文件名 | 与 `models/separator` 下的实际文件名一致 |

服务自身只读 `idle_timeout` 与 `sep_backend`；其余键给调用方（技能 / 客户端）用。

**换机器只改 `rvc` 这一块**，不动其他服务的段；同一个服务换地址也只改 `local_url`。

### 不想手填就抄客户端的

客户端「设置 → 私有AI服务地址」里加一条**类型 `RVC音色转换`、端口 `8187`** 的服务，再进
「设置 → 技能运行环境」选它，点「复制智能体安装口令」——口令里的 `rvc_url` 就是
`rvc.local_url`，其余键按本册默认补。装技能时连目录一起带过去，不用逐台手抄。

## 地址解析优先级

```
--url  >  环境变量 FXAI_RVC_URL  >  rvc.prefer_local 决定 local_url / cloud_url 的先后  >  缺省本机
```

探活口径：`GET /health` 2 秒超时，返回 200 即在线。首选地址探不通才轮到下一个；都不通按首选地址发请求，报错里带地址原文。

## 解释器与项目目录

启动服务需要 GPU 环境，技能只负责把命令交给人执行：

```bash
P=<软件数据目录>/conda/env/rvc/python.exe
"$P" "<项目目录>/fxsvc_server.py" --host 0.0.0.0 --port 8187
```

| 场景 | 动作 |
|---|---|
| Windows 桌面 | 双击项目根的 `start_fxai_svc.bat` |
| Linux / macOS / Git Bash | `bash start_fxai_svc.sh` |
| 由启动器拉起 | 启动器按 `fxai.json` 的 `app` 调 `fxsvc_server.py` |

| 路径 | 解析 |
|---|---|
| 软件数据目录 | 全局配置顶层 `software_data_dir` |
| 项目目录 | 工作区下的 `fxai-svc`（随工作区走） |
| 解释器 | `FXSVC_PYTHON` → `<项目>/env/python.exe` → `<software_data_dir>/conda/env/rvc/python.exe` → `PATH` |

## 探不通怎么办

1. 先看进程在不在：`curl -s -m 3 http://127.0.0.1:8187/health`。
2. 不在 → 把上面的启动命令打回给人执行，等 `health` 返回 `healthy` 再继续。
3. 在但不健康 → 看 `<项目>/logs/web.log` 尾部；`separator.ready=false` 说明分离模型缺失或参数不匹配。
4. `comfy.up=false` 只影响 `sep_backend=skill`，内置 `melband` 不受影响，照常跑。

## 显存与空闲卸载

| 环节 | 显存 |
|---|---|
| 换声模型 | 约 1.4GB |
| 分离模型 | 约 885MB |
| 装载后常驻 | 转换结束起算 `idle_timeout` 秒 |

- 有在途任务时不卸载；到点前来了新任务会重排定时器。
- `POST /unload` 立即释放，转换进行中返回 `409`。
- `POST /load?voice=<音色>` 预热，返回完整状态体。
- 状态判读只看接口：`model_loaded` / `loaded_voice` / `vram_mb`。

## 与外部 ComfyUI 的关系

`sep_backend=melband`（默认）走进程内 Mel-Band RoFormer，**整条链路自包含，不需要 ComfyUI**。
`sep_backend=skill` 才走外部 ComfyUI 的分离工作流，需要 `comfy_url` 可达；该值从全局配置顶层 `comfy_url` 读，缺省 `http://127.0.0.1:8188`。部署环境默认用 `melband`。
