# 04 · 音色训练

> **何时读**：要给某人练新音色、问「练多久」「素材要多少」「训完在哪儿」时。

## 训练流程

```
① 切片 ──▶ ② 特征 ──▶ ③ 训练 ──▶ ④ 检索索引 ──▶ ⑤ 入库
去静音、3.7s 切段     contentvec + rmvpe     RVC v2 40k         faiss        复制进 models/voices
重采样 40k            f0 音高                默认 250 epoch     同名 .index  写 _meta.json 显示名
```

产物规格与现役音色一致：40k / v2 / 带 f0。训完自动进音色库，工作台下拉里第一个就是它。

## 素材判据

| 项 | 判据 |
|---|---|
| 内容 | 只要人声：清唱、干声、播客、口播。带伴奏会让音色学糊，整首歌先用工作台分离出人声轨 |
| 时长 | **10~30 分钟最划算**。1 分钟能跑但音色不稳；超 40 分钟训练时长翻倍、音色提升很小 |
| 表现力 | 语速、情绪、音高都要有变化。整段平读会训出很僵的音色 |
| 素材类型 | wav / mp3 / flac / m4a 均可，可一次传多个文件，服务端统一重采样到 40k |
| 排除项 | 现场演唱会（混响 + 尖叫）、电话录音、KTV 自带混响、多人对唱 |

## 参数

| 字段 | 默认 | 说明 |
|---|---|---|
| `name` | 必填 | 音色显示名，可为中文 |
| `epochs` | `250` | **可填 20~600**（越界由服务端夹取）。推荐 200~300：想快点用 200，想更好用 300；低于 100 音色不稳，高于 400 收益很小 |
| `batch` | `8` | 16G 显存可到 12，约省三成时间 |
| `sr` | `40000` | 与现役音色保持一致，勿改 |

网页 `/train` 上 epoch 是「下拉 + 自定义输入」：下拉给 120 / 200 / 250 / 300 四档，
选「自定义」可以手填 20~600，旁边实时显示按当前素材估算的耗时。

## 耗时参考（RTX 5060 Ti 16G）

训练量 ≈ 切片数 × epoch。`Automatic` 切片下每分钟素材约切 20~24 段，batch=8 时每段一步、约 0.25 秒/步：

| 素材时长 | 切片数 | epoch | 全流程耗时 |
|---|---|---|---|
| 6 分钟 | 140 段 | 40 | 约 4 分 40 秒 |
| 6 分钟 | 140 段 | 250 | 约 21 分钟 |
| 10 分钟 | 约 230 段 | 250 | 约 30 分钟 |
| 20 分钟 | 约 460 段 | 250 | 约 60 分钟 |

估算口径：`切片数 × epoch × 0.25 / 60` 分钟，再加切片与特征阶段的 1~3 分钟。
接口里 `minutes`（素材时长）、`slices`（切片数）、`eta`（剩余秒数）三个字段可直接回答「还要多久」。

## 三个硬约束

1. **训练独占显卡**：开训练前先卸换声模型；训练期间提交的换声任务保持 `queued`，
   `stage_text` 显示「等待训练结束（显卡被训练占用）」，训练结束自动开跑。
   转换进行中提交训练返回 `409`。
2. **训练跑在独立子进程**：服务只读 `train/<job_id>/state.json`，训练卡住或崩掉不影响 HTTP，
   页面照常刷新、照常取消。
3. **磁盘音色文件名必须 ASCII**：faiss 在 Windows 下用窄字符开文件，中文 `.index` 会静默失效，
   音色听起来「不像」。内部统一 `voice_MMDD_HHMM`，中文名只存 `_meta.json`。

## 底模

训练需要 `engine/rvc/models/pretraineds/hifi-gan/f0G40k.pth` 与 `f0D40k.pth`。

```bash
python rvc_client.py pretrained              # ready / missing
python rvc_client.py pretrained --download   # 开始下载（hf-mirror 优先）
```

`download.running` / `done` / `total` 看进度；`ready=true` 才能开训练。

## 命令

```bash
P=<技能目录>/scripts/rvc_client.py
python "$P" train <素材1.wav> <素材2.mp3> --name <显示名> --epochs 250 --batch 8
python "$P" train <素材目录>/*.wav --name <显示名> --no-wait     # 只建任务
python "$P" train-job <train_id>            # 单次查
python "$P" train-job <train_id> --wait     # 跟随到终态
python "$P" train-cancel <train_id>         # 取消，子进程在检查点退出
python "$P" train-jobs                      # 全部任务 + 底模状态
```

命令行等价入口（不经过 HTTP，直接跑训练器）：`python -m fxsvc.trainer --name <显示名> --audio <素材...>`。

## 训练素材库（素材必须先归库）

素材传一次就留在服务端 `train_sets/<set_id>/`，可以命名、标归属、在库之间移动、反复取用。
**一套素材训 5 次只占一份盘**：开训时硬链接进 `train/<job_id>/raw/`，不复制。

**没有"裸文件"这回事**：`POST /api/train` 要么给 `set_id`，要么给文件 + `set_name`，
服务端不接受游离素材。第一次访问 `/api/train/sets` 会自动建「默认素材库」兜底，
所以「临时上传」这个说法不成立 —— 上传就是入库。

| 做法 | 命令 |
|---|---|
| 列全部素材库 | `python "$P" sets` |
| 看某个库的文件清单 | `python "$P" set-detail <set_id>` |
| 建空库 | `python "$P" set-new "小北-普通话" --owner 小北` |
| 往库里追加素材 | `python "$P" set-add <set_id> <音频...>` |
| 跨库移动（序号 1 起算） | `python "$P" set-move <from_id> <to_id> --items 1,3,5` |
| 用素材库开训（**不传文件**） | `python "$P" train --set <set_id> --name <音色名> --epochs 250` |
| 传新文件并归库再训 | `python "$P" train <音频...> --name <音色名> --set-name "小北-普通话" --set-owner 小北` |
| 把已跑过的训练素材收编成库 | `python "$P" set-adopt` |

网页分工：

- `/train`：顶部是**素材库下拉（必选）**，拖文件进来就直接存进当前库，然后开训。
  训练中进度卡里有「取消训练」（`POST /api/train/job/<id>/cancel`）：已跑轮次丢弃、
  不会产出音色，素材还在库里可以重训。
- 训完的提示里带「去工作台用它换声 →」：点了会把这个音色写成服务端当前音色
  （`POST /api/prefs` 的 `convert.voice`）再跳 `/`，落地就是选中状态，不用在下拉里翻。
- 训练跑在服务端，关页面不会中断；前端在 `running/queued` 时挂 `beforeunload` 拦一下，
  提醒「进度会看不到」。
- `/sets`：独立的素材库管理页。左边库列表，右边文件表格，勾选后可「移动到…」
  另一个库、批量删；也能建库、改名、标归属、试听、看训练历史。

移动的语义是 `move` 不是复制：源库那份移走，不另占空间；目标库已有同内容会跳过、
留在原库并回报 `skipped`。移动不影响已经硬链接进某次训练的 `raw/`。

**删整库是连文件一起删**（`rmtree` 整个 `train_sets/<set_id>/`，不可恢复）：
只想删一部分，先勾选要留的文件「移动到…」别的库，再回来删这个空库。
删库不影响已训好的音色和 `trainings` 里的记录。返回值 `freed_mb` 是真的腾出来的容量，
`shared_mb` / `shared_count` 是仍被 `train/<job_id>/raw/` 硬链接引用的部分 ——
那部分要等训练中间文件清理才真正释放，别当成「删了没效果」。

每个库都带训练历史 `trainings`（`job_id` / 音色名 / epoch / 时间），
所以「这套素材 + 250 epoch 出过什么音色」查得到，换参数时不用凭记忆试。

判据：

- 一套素材 = 一次可复现的训练。不同批次的素材**另建一个库**，别往里混，混了就复现不了任何一次。
- 归属 `owner` 填音色名或角色名，方便同名库区分。
- 训练素材库和作品库的原曲素材（`input/library/`，换声用）是两套东西，别互相替代。
- 删库前先问一句「这套是否还要继续训练」：要留就先移走文件，库删了文件就没了。

## 产物落点

| 内容 | 位置 |
|---|---|
| 任务状态与日志 | `<项目>/train/<train_id>/`（`state.json` / `train.log` / `raw/`） |
| 训练素材库 | `<项目>/train_sets/<set_id>/` + `_index.json`（名称、归属、时长、训练历史） |
| 中间产物 | `<项目>/engine/logs/<slug>/`（切片、特征、checkpoint） |
| 音色模型 | `<项目>/models/voices/<slug>.pth` + 同名 `.index` |
| 显示名 | `<项目>/models/voices/_meta.json` |

确认音色好用后，`engine/logs/<slug>/` 可以整目录删掉省空间 —— **这个是占盘大头**
（G / D checkpoint 一份 400~800MB，一轮训练 1~2GB），素材库本身只有几十 MB，不用急着删。

## 清理训练中间文件

训练收尾时 pth 与 index 已复制进 `models/voices/`，`engine/logs/<slug>/` 此后无任何环节读取：
**删掉不影响换声、试听、导出，也不影响训练记录**（记录在素材库的 `trainings` 里）。
唯一会用到它的是"从某个 checkpoint 接着练"，本项目每次从头切片训练，没有续训通道。

| 做法 | 入口 |
|---|---|
| 看有哪些、占多少 | 网页 `/train` 右栏「训练中间文件」卡片 / `python "$P" ws` |
| 勾选清理 | 卡片里勾选 → 清理选中（二次确认，显示将释放多少） |
| 命令行清理 | `python "$P" ws-clean <slug> [<slug>...]` |
| 接口 | `GET /api/train/workspaces`、`POST /api/train/workspaces/clean` `{slugs:[...]}` |
| 训练成功自动清 | 卡片里的开关，或 `POST /api/train/prefs` `{auto_clean:true}`；**默认关** |

判据与边界：

- **训练一结束就提醒用户清**，别让它默默堆到几十 G；删不删由用户自己点。
- 只列出「音色库里有记录」或「`train` 任务记录里出现过」的 slug。
  引擎内置的 `mute` / `mute_spin` / `mute_spin-v2` / `reference` 是训练与推理自己要用的
  采样基准和评估参考，**永不列出、永不删除**（删了会让换声出问题）。
- 正在训练（`running` / `queued`）的工作区锁住，接口直接拒；不得绕过这个锁去删目录。
- 排查「换声没声音 / 音色不对」时，先看 `models/voices/` 里的 pth 与 index 是否完整，
  勿从 `engine/logs/` 找原因 —— 那里面只是过程文件。
