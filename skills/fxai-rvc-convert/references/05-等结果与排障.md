# 05 · 等结果与排障

> **何时读**：任务提交后要等多久、卡住了、失败了、显存不放、结果对不上时。

## 等待纪律

- 🔴 **按状态轮询，不按固定时长死等**：`GET /api/job/<id>` 每 2 秒一次（训练 5 秒一次），
  只在 `stage` / `progress` 变化时上屏，防止刷屏。
- 等待上限用 `rvc.timeout`（900s）；训练按 `6 小时`。超时只报「仍在运行 + 当前进度」，
  任务本身继续跑，稍后 `job <id>` 接着查。
- 一次提交只等一条，多首素材分次提交；队列串行，堆在一起看不到单条进度。

## 状态判读

| `status` | `stage_text` | 含义与动作 |
|---|---|---|
| `queued` | 排队中 | 前面有任务；看 `queued_ahead` |
| `queued` | 等待训练结束（显卡被训练占用） | 等训练终态，自动开跑 |
| `running` | 分离人声 / 伴奏 | 6%→44% 推进，可取消 |
| `running` | 音色转换（<音色>） | 45%，首次装载模型较慢 |
| `running` | 等响混音 | 82% |
| `done` | 完成 | 取 `result_url` 下载 |
| `error` | 失败 | 读 `error` 字段，对照下表 |
| `canceled` | 已取消 | 任务目录已清理，重提一条 |

`GET /health` 的 `state` 是全局态：`idle` / `loading` / `converting` / `training`。
判「服务忙不忙」看 `busy`、`in_flight`、`queued` 三个数。

## 取消

| 阶段 | 行为 |
|---|---|
| 排队中 | 立即出队，`status=canceled` |
| 运行中 | 响应 `canceling`，当前阶段收尾时中断；分离阶段按块检查，中断最快 |
| 已终态 | 直接回 `done` / `error` / `canceled`，不重复处理 |

取消后任务目录清掉中间文件，成品目录若已生成则保留。取消不是删除：要删作品走 `delete`。

## 故障处置

| 现象 | 判据 | 处置 |
|---|---|---|
| 连不上 | `URLError` / 拒绝连接 | 服务没起；按 `01` 册把启动命令交给人，等 `healthy` |
| `音色不存在` | 404 | `voices` 取 `id`；中文名查不到时改用 ASCII id |
| 一直 `queued` | `training.active=true` | 训练占卡，等训练终态 |
| `正在转换中…` 409 | `busy=true` | 等终态再开训练或卸载 |
| `模型装载失败` | 500 + `加载失败：` | 看 `logs/web.log`；`.pth` 损坏或缺 `.index` 同级依赖 |
| 分离阶段报错 | `separator.ready=false` | 查 `models/separator/` 文件名与 `rvc.sep_model`、结构参数 |
| 成品没人声 / 全静音 | `sep=skip` 但素材带伴奏 | 去掉 `vocal_only`，让它走①分离 |
| 成品比原曲短 | `duration` 与成品时长差 >1s | 素材是视频片段或采样率异常；先转 44.1k/48k WAV 重提 |
| 咬字糊 | — | `protect` 上调到 `0.4~0.5` |
| 听起来不像 | `index` 为空，或 `index_rate` 被手动调低 | 补 `.index`（训练第④步自动建）；有索引就保持默认 `index_rate=1`（最像） |
| 显存不释放 | `vram_mb` 长期高 | `unload`；或等 `idle_timeout` |

## 日志与现场

| 内容 | 位置 |
|---|---|
| 服务日志 | `<项目>/logs/web.log`（超 10MB 轮转 `web.log.1`），转换管线以 `[pipeline]` 前缀并入 |
| 单任务成品与元信息 | `<项目>/output/<job_id>/`（`meta.json` 记参数与耗时） |
| 训练日志 | `<项目>/train/<train_id>/train.log` |

## 服务重启的影响

| 场景 | 结果 |
|---|---|
| 重启时在跑的任务 | 丢失，`JOBS` 是内存态；重提一条 |
| 已完成且 `save=1` | `meta.json` 在盘上，`/api/jobs` 照常列出 |
| 已完成但 `save=0` | 12 小时内可下载，启动时清理超期项 |
| 模型 | 重启后回到未装载，首次转换重新装载（约 2s + 1.4GB 显存） |

## 交付前核对

1. `job <id>` 的 `status=done`，`elapsed` 与 `duration` 合理（约 0.3~0.5 倍时长）。
2. 成品落在目标目录，能被播放器读出时长（不是 0 字节、不是半截文件）。
3. 需要留档的成品 `saved=true`，交付说明里带 `job_id` 便于回溯。
4. 只用过一次的临时成品清掉，或 `delete` 掉不进交付的条目。
