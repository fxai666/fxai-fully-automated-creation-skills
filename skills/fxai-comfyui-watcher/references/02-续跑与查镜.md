# 02 · 续跑与查镜

> **何时读**：任务中断 / 超时 / 服务器重启后要接着跑，或要核对「已生成到第几镜」时。
> 日常等待与查询走 SKILL.md 的快捷命令。

## 断了怎么续跑：一条命令（生成视频通用：短剧 / MV / 数字人 / 幻灯片视频）

中断 / 超时被掐 / 服务器挂了之后，**不用重新准备分镜数据**，一条命令接着跑：

```bash
$WATCH resume <prompt_id>            # 查到第几镜 → 自动重投（返回新的 prompt_id）
$WATCH resume <pid> --dry-run        # 只算不提交，先看它会从第几镜开始
$WATCH resume <pid> --wait           # 提交后就地等到终态（不用再起一条 wait）
```

**原理**：`/history/<pid>` 里存着上次提交时的**完整工作流**（每行提示词/时长/参考图、尺寸、帧率、音频模式、保存目录全在里面）→ 查已生成到第几镜 → 把「开始索引」改到下一镜、`结束索引` 置 -1 → 重新 `POST /prompt`。`lines_data` 保留全部镜头，合并节点照旧合并整集（已生成的镜头命中节点缓存会直接复用，不重复烧 GPU）。

**⚠️ `/history` 是内存态**：只留最近约 10 条、都是 0.4 天内的任务，服务端输出目录里的分镜可能存了 23 天（那些任务的原始工作流已查不回来）。**ComfyUI 一重启，老任务的 history 就没了**。

所以提交那一刻就顺手落一份**工作流快照**到 `~/.workbuddy/runtime/comfy_ws/snapshots/<pid>.json`（`comfy_client.run_workflow` 与短剧 `submit_workflow` 都已内置）。resume 取工作流的顺序：服务端 `/history` → `--wf <文件>` → 本地快照，三处都没有才报 `blocked`。

**取不到工作流时**：三处都拿不到（服务重启 + 本机快照也丢了，比如换电脑）→ 用 `--wf <工作流json>` 指定，或按原脚本重投并显式给 `start_index`；工作流里没有「开始索引/结束索引」字段（非多镜控制器）→ 整条重跑。命令会明确告诉你属于哪种。

⚠️ **保存目录别混用**：文件号按目录内已有数量递增，多个任务共用一个目录时分镜归属会混乱。真混了会直接报 `blocked` 并给出两条安全做法（换专用目录 / 人工核后再给 `--total`），不会瞎猜。

## 查「已生成到第几个分镜」——先查再决定（生成视频通用）

多段循环生成中途断了（超时、关机、报错、换机器）时，**先查再续**：

```bash
$WATCH shots <prompt_id>                      # 自动定位保存目录
$WATCH shots <pid> --dir sucai --total 30     # 目录/总镜数已知时最准
$WATCH shots <pid> --files                    # 连文件清单一起打（带大小/时间）
$WATCH shots <pid> --json                     # 机器读（流水线取 next_index）
$WATCH shots <pid> --resume                   # 只出一行：<pid>\t<start_index>\t<已生成镜数>
```

**判定口径（全技能统一）**：视频文件**只要不在合并目录（`merged`）里**，文件名上带的文件号**就是分镜序号**（`000.mp4` = 第 1 镜，`007.mp4` = 第 8 镜）；`video/merged/xxx.mp4` 是整条成片，**不算分镜**。

**🔴 服务端逐段产物 + 自动合并（多镜控制器通用）**：工作流含「开始索引 / 结束索引」节点时，提交**只重渲指定段**，**服务端把「本次新段 + 已缓存的其他段」自动合并成一条完整视频返回**。

- 逐段产物：`<ComfyUI 输出根>/fxai/video/<prefix>_multiref/<序号>.mp4`（`000.mp4` 起，0 起编号）。数字人 `prefix=dh`，MV `prefix=mv`。服务端按项目缓存各段，重渲单段不覆盖其他段。
- 合并产物：`fxai/video/merged/fxai_<时间戳>.mp4`——每次提交都新出一条完整成片。
- 「哪一镜不合格就只重渲哪一镜」，逐镜跑完服务端自然是完整片，本地只取回成片；MV 侧 `produce_song.py --mv-segment` 取的是单段文件，属另一条路径。
- 判据：返回成片时长 = **全长**；拿到单段时长说明走的是单段下载路径。
- 查各段状态：看服务端逐段目录的 mtime（新渲过的段 mtime 会更新），或 `shots <pid> --files`。

数据源（**全部走接口，不读本机磁盘**：ComfyUI 可能在另一台机器上，本机磁盘 ≠ 服务端磁盘）：台账 → `/fxai/tasks/result` → `/history/<pid>` 的 prompt（反查节点「保存目录」）→ `/fxai/files/list`（目录内视频清单，带 size/mtime）。台账没了也查得出；加 `--debug` 把每次真实 HTTP 请求打到 stderr，可逐条核对。

输出关键项：`已生成 N 镜`、`缺失第 X 镜`、`下一镜 第 N 镜`、`续跑参数 start_index=N`。续跑：`build_workflow(..., start_index=r["next_index"])`；库里直接 `comfy_client.shot_progress(pid)` 拿同一份字典。实现见 `fxai-workflow/shot_query.py`。

## 三种看进度的方式（都不需要问 Agent）

**浏览器面板（首选）** 双击 `progress.html`（浏览器直连 WS，零 token、不经过对话，换服务器在面板顶部改地址）；**Agent 播报** `next <pid>`；**过程留档** `next/wait <pid> --log`（事后查 `status`/`top` 时才落盘）。`comfy_client.BROADCAST_VERBOSE` 与 `drama_pipeline.WAIT_VERBOSE` 默认 `False`，实时看置 `True`。
