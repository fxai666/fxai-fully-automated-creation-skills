# 封面多尺寸与平台规格（本册为唯一出处）

> **尺寸只有一个真源**：本技能根目录 `cover_sizes.json`。站点台账只准写 key，不许写像素。
> **能统一就统一**：竖屏一律 `vert_9x16`、横版一律 `horiz_16x9`，**两张覆盖全部 13 站**。

其它技能（发布、MV 产线、短剧）要用封面规格，一律写指针指向本册，**不许复制尺寸表**。

---

## 一、四层归属（谁都不许越界）

```
能力层  本技能 fxai-poster
        ├─ cover_sizes.json      ← 尺寸 + 各站规格，唯一真源
        ├─ cover_styles.py       ← 版式定义（STYLES / render / render_matrix）
        ├─ cover_prompt.py       ← 版式 → 生图提示词（六段骨架，第三段写足排版）
        ├─ cover_side.py         ← 按底图留白自动判文字侧
        └─ cover_batch.py        ← 薄 CLI：读项目配置 → 选路线 → 出图
                 ↑ 只引用 key
站点层  发布技能实例 <hub>/sites/<site>.json
        └─ "cover": {"key": "vert_9x16", "source_of_truth": "fxai-poster/cover_sizes.json"}
                 ↑ 实例化
项目层  <作品目录>/封面.json      ← 底图 + 文案 + 要出哪几个 key
```

| 层 | 存什么 | 不许存什么 |
|---|---|---|
| 能力层 | 像素尺寸、比例、裁切锚点、每站最小尺寸、版式 CSS | 站点**操作坐标**、账号、凭据 |
| 站点层 | 只存 key 与「本站能否裁」 | 不许再写 `1080×1920` |
| 项目层 | 底图路径、标题文案、样式、key 清单 | 不许按站点分别配尺寸 |

**边界**：封面尺寸是平台公开的设计要求（等同「抖音要求 9:16」），不是操作坐标，可以预置进技能包；
但站点按钮坐标、账号一律不进本技能。

---

## 二、统一优先：最小出图集只要两张

| 集合 | 内容 | 用在哪 |
|---|---|---|
| **最小集（默认）** | `vert_9x16` 1080×1920 + `horiz_16x9` 1920×1080 | 覆盖 13 站，够用即可 |
| 历史备选（默认不生成） | `vert_3x4` / `square_1x1` / `wechat_235` | 仅用户明确指定时才出；项目 `sizes` 默认只列最小集两张 |

🔴 **平台上传框比例 ≠ 出图比例**：抖音封面向导竖 3:4 / 横 4:3（用户 2026-11-09 实测，
已记进 `cover_sizes.json` 的 `upload_frame`），那是平台给的裁切框；
主出图仍只有 9:16 + 16:9 两张，由平台裁切，**不另出第三张**。
代价是必须把竖排文字安排进 3:4 安全区，别让裁切切掉字。

三个判据，满足就**不许**多出一张：
1. 站点标了 `crop: true`（允许平台裁切）
2. 站点最小尺寸 ≤ 我们给的尺寸
3. 比例在站点 `ratio_ok` 列表里

> 唯一硬例外是 CSDN：`crop: false`，裁剪下限 960×540，竖版裁完 614×346 被拒，横版是硬要求。

## 三、五个尺寸 key

| key | 尺寸 | 比例 | 版式 | 锚点 | 主要落点 |
|---|---|---|---|---|---|
| `vert_9x16` | 1080×1920 | 9:16 | portrait | top | **竖屏统一**：抖音/快手/视频号/TikTok/贴吧/小红书/知乎/微博 |
| `vert_3x4` | 1080×1440 | 3:4 | portrait | top | 可选：图文社区专门首图位 |
| `square_1x1` | 1080×1080 | 1:1 | portrait | top | 可选：方图位 |
| `horiz_16x9` | 1920×1080 | 16:9 | landscape | center | **横版统一**：B站/百家号/头条/CSDN/YouTube |
| `wechat_235` | 900×383 | 2.35:1 | landscape | center | 公众号首图（专用比例，必须单独出） |

查站点规格：`python cover_batch.py --sites`
查尺寸注册表：`python cover_batch.py --list-sizes`

产物实测核对（2026-11-09，读 PNG 头）：1080×1920 = 9:16（**高是宽的 1.78 倍，
看起来「很高」是比例本身决定的，不是尺寸写错**）、1920×1080 = 16:9；
另外 1080×1440 / 1080×1080 / 900×383 三张是历史备选，不参与发布。

## 四、版式规则（`vert_title` 竖排贴边样式）

为什么是竖排：照片类封面把大字横排压顶部，人物居中构图时字正好落在额头到下巴，等于给脸打码。
竖排只占画面一侧的一条窄带，人物完整露出，从 9:16 到 2.35:1 都不会把标题裁断。
**贴左还是贴右由第七节的留白判定决定**，`side` 参数会让文字锚点、遮罩方向、横版主体位置一起翻。
同一套版式语义有两个出口：HTML 叠加层（`cover_styles.py`）与生图提示词（`cover_prompt.py`），
改版式时两处一起改，不许只改一边。

### 竖版（H ≥ W，`_vert_title`）
```
底图 object-position: 50% 0%   ← 顶部对齐先保头顶，1:1/3:4 裁下半身
veilL 左侧 64% 宽：0%→.93 / 21%→.89 / 44%→.50 / 68%→.14 / 86%→0
veilT 顶部 15% .66→0；veilB 底部 26% .95→0
自上而下：kicker → en → 竖排主标题 → 底部副标题 / 品牌
```
- 主标题 `writing-mode: vertical-rl`，字号 `H×0.0646`，左边界 `W×0.05`
- **0~21% 遮罩必须压到 .88 以上**：人物穿浅色衣服（本作米白长裙）时，低了白字糊成一片

### 横版（W > H，`_vert_title_land`）
```
bgblur 同图 50% 8% / cover，inset -32%，blur H×0.057，brightness .52  ← 只取上部天空，避免人像重影
hero   原图高度 122%，left 62%，上下出血，左右 mask 渐隐            ← 放大出血才有体量
tint   左 .90 → 30% .80 → 48% .30 → 64% .16 → 82% .55 → 右 .90
文字全走左侧空区：kicker / 竖排标题 / en / 副标题 / 品牌
```

### 小尺寸（H < 520）
只留 kicker + 竖排标题，删英文行、副标题、页脚——多一行就糊。

## 五、生成与验收

```bash
python cover_batch.py --project <项目目录> --gen-cover             # 首选：生图直接带字
python cover_batch.py --project <项目目录>                         # 已有底图 → 多尺寸叠加层
python cover_batch.py --project <项目目录> --only vert_9x16,horiz_16x9
python cover_batch.py --project <项目目录> --outdir <其它目录>      # 不改正式产物
```

项目 `<项目目录>/封面.json`：
```json
{
  "base_image": "…/封面/_base.jpg",
  "style": "vert_title",
  "title": "潮汐来信", "title_en": "TIDE LETTERS", "kicker": "ORIGINAL SONG",
  "subtitle": "…", "footer": "凤希AI · …",
  "theme": {"gold": "#d8c39a", "paper": "#f7f2e9"},
  "sizes": ["vert_9x16", "horiz_16x9"]
}
```

产物：`<项目>/封面/封面_<标题>_<W>x<H>.png`

出图后**逐张看图**，五项必看：
1. 头顶有没有被裁 2. 标题有没有压脸 3. 白字下面是不是浅色衣服
4. 底部文字有没有被裁或叠 5. 横版有没有人像重影 / 竖直接缝

## 六、已知缺陷与对策（改模板前先看）

| 现象 | 根因 | 修法 |
|---|---|---|
| 标题横排压住整张脸 | 四个字落在额头到下巴之间 | 改竖排贴左 |
| 1:1 / 3:4 头顶被切 | `object-fit:cover` 默认居中裁 | `object-position: 50% 0%` |
| 竖排标题糊在浅色裙上 | 遮罩只压到 .82 且衰减快 | 0~21% 压到 .89 |
| 横版右下角半个模糊人影 | 模糊底图 `center` 取到人物 | 取 `50% 8%` 上部天空 + inset -32% |
| 横版人物太窄像贴纸 | 满高只有 607px 宽 | hero 放大 122% 出血 |
| 900×383 底部三行糊成一团 | 字号等比缩到 8px | H<520 走 compact |
| CSDN 拒收封面 | 竖版裁完 614×346 | 一律 `horiz_16x9` |
| 尺寸改一处没全跟随 | 站点各自写死像素 | 站点只存 key，改 `cover_sizes.json` 一处 |
| 文字写死贴左、和主体挤一边 | 没看底图主体站在哪侧 | `cover_side.py` 三段投票判空余最多的一边 |
| 生图封面没有字，还得后期叠 | 把「画面无任何文字」当成通用生图口径 | 只对叠加层路线成立；主路径走 `--gen-cover`，排版说明写进提示词第三段 |
| 生图把字写歪、漏字、层级消失 | 提示词只写「有标题」，没写位置/字号/字色/字体/容器 | `cover_prompt.py` 按版式逐条写，过 `qc.py prompt` 门再出图 |
| 底部冒出一串乱码英文字母 | 提示词写了「装饰字母」却没给逐字引号，模型自造文本 | 要上画面的文案一律进双引号；竖版不生成装饰英文行（`cover_prompt.py` 已去掉） |
| 改了提示词却还是出旧图 | `scene-gen` 按 tag 缓存，tag 不变直接复用 | tag 带提示词指纹（`cover_prompt.prompt_tag()`）；急用可 `--force` |

## 七、文字贴哪一侧：贴空余最多的一边

🔴 **不许写死贴左**。先看底图主体在哪边，文字贴**反侧**（空余最多的一边），主体尽量留在另一边。

本作实测：主体亮部重心 `x=29.3%`（人物明显偏左），左带 0~24% 空度 0.60 /
右带 76~100% 空度 0.94 → **右侧才是空余最多的一边**，文字该贴右。

判据在 `cover_side.py`（只用 PIL，不调模型、不依赖 numpy）：

1. 灰度缩到 120×200，取上 75%（避开底部暗部与烧录字幕带）
2. 比较左带 0~24% 与右带 76~100% 的 `empty = 1 - 亮像素占比 - 边缘能量/255`
   （亮像素多＝有浅色主体，边缘能量高＝轮廓纹理多，都说明「不空」）
3. 上段 / 中段 / 全段**三段都判同一侧**才自动翻边，不一致就保守用左
4. 两侧空度差 `< 0.05`（都很空、差不足以定案）时，改按**主体重心反侧**兜底：重心偏左 → 文字贴右
5. 判定结果打印成一行人话，含主体重心、两侧空度、是否走了兜底

侧一旦定了，**竖版与横版联动**：文字锚点、遮罩渐变方向、横版主体位置（62% ↔ 38%）一起翻，
不是只把字挪过去。项目 `封面.json` 写 `"text_side": "auto" | "left" | "right"` 覆盖，
CLI `--side left|right|auto` 临时覆盖；`--bg <路径>` 可直接换底图调版式而不重新生图。

## 八、画面与文字来源：优先自家生图技能，文字直接生在图上

🔴 **封面的画面优先由自家生图技能生成**；🔴 **封面上的文字默认由千问2.1 直接渲染在画面上**。
`10` 册第一句写得很清楚：文字渲染是千问2.1 的强项，**该写文字就大胆写进去，靠叠加层补字是次优解**。
`03` 册第 18 行、`05` 册「底图与文字层二选一」都是同一口径。

| 优先级 | 画面来源 | 说明 |
|---|---|---|
| 1 | 自家生图技能（`fxai-scene-gen` / `fxai-comfyui-image-gen`） | 本地 GPU 与云端容器**都走同一个 HTTP 接口**；寻址、探活、切换由 `fxai-workflow` 全权负责，本技能不写服务地址 |
| 2 | 成片剧照 | 仅「已有人物成片且要贴剧」时的例外，四步法见 `03` 册 |
| 3 | 纯排版 `web` | 信息图、大段文字、要对齐的表格清单才用 |

### 两条路线，A 是默认

| 路线 | 命令 | 文字怎么落 | 什么时候用 |
|---|---|---|---|
| **A 首选** | `--gen-cover` | **提示词第三段写足排版说明，生图直接把字画在画面上**，出完即成品，不叠第二层字 | 绝大多数封面：文案固定、要一次成型、文字与光影自然融合 |
| B 例外 | `--gen-base` → `render_matrix()` | 生图出**无字底图** → HTML 叠加层按 key 重排 | 一次出多尺寸、后续要改字、要像素级精确控字 |

🔴 **「画面无任何文字」只属于路线 B**，因为叠加层会在同一位置再落一层字，两层字会打架。
**绝不能把它写成通用生图口径**——那等于把主路径降级成次优解。路线 B 的提示词由
`cover_prompt.py --no-text` 生成，不要手写。

### 版式模板怎么进提示词

`cover_prompt.py` 把 `cover_styles.py` 的 8 种版式翻译成六段骨架的**第三段「文字区块」**：
逐条写清「引号文案 + 位置 + 字号层级 + 颜色 + 字体风格 + 排版容器」，
文案进双引号、四条封顶、单条 ≤14 字、主标 ≤7 字；并按 `side` 把人物安排到文字的反侧。
写完过 `qc.py` 的提示词门（`--skip-qc` 可强出，不推荐），出图后**逐字核对文案**。
🔴 生图 tag 必须带**提示词指纹**：`scene-gen` 按 tag 缓存图片，改了提示词却不换 tag 会复用旧图，表现为「改了没生效」。用 `cover_prompt.prompt_tag()` 生成 tag，`--force` 可强制重出。

画面内容由项目 `封面.json` 的 `gen_brief`（texture / composition / subject / scene / light）
与 `gen_text`（生图专用短文案）提供，**技能包不写死任何作品内容**；生图尺寸取 `10` 册的
32 倍数表，出图后按 `cover_sizes.json` 的 key 尺寸缩放落盘。

```bash
# 路线 A（默认首选）：版式排版说明自动写进提示词 → 生图直接带字
python cover_batch.py --project <项目> --gen-cover \
  --gen-size vert_9x16 --gen-role <作品角色图相对路径> --side right

# 只预览/改提示词，不出图
python cover_prompt.py --project <项目> --size vert_9x16 --side right --role <角色图>

# 路线 B（例外）：无字底图 → 多尺寸叠加层
python cover_batch.py --project <项目> --gen-base --gen-role <作品角色图相对路径>
python cover_batch.py --project <项目> --only vert_9x16,horiz_16x9
```

🔴 人物一律挂**作品自己的角色参考图**（规避他人肖像）；出字前按
`fxai-standard/references/06-字体与素材授权.md` 过字体白名单。
生图服务探不通就报错让人启动或切云地址，**本机 DOWN ≠ 由我来起**。
