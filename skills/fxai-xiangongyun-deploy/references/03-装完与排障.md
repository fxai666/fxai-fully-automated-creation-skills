# 装完之后与排障（装完配置 / 重启 / 升级 / 报错时读）

## 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 401 / 镜像没收录 | 平台没同步这个仓库 | **找仙宫云客服收录**；非要开备用源：`XGY_SRC_ORDER="mirror,ms,hf" python deploy.py run --only <id>` |
| 速度只有 ~11 MB/s | 魔搭单连接速度 | 加 `--parallel 3`；或挂数据盘 |
| 下下来 145 字节、开头是 `{"Code":10990101007...}` | 不存在的仓库也返 200 | 脚本已自动识别；若出现，检查 `repo` / `ms_repo` 配的仓库名 |
| 文件体积越下越小 | 源不支持 Range，`curl -C -` 把目标文件从 0 截断重写 | 所有 URL 都由 `probe_sources.py` 提前验过返 206；换源前必须重跑探测 |
| 磁盘不够 | 全量 79.5 GB | `--group img`（21 GB）；或「关机释放GPU → 开机」免费扩容；或挂数据盘后 `--set-dir <id>=<子目录>` |
| 节点报错「找不到模型」 | 凤希自研节点读盘目录和常规约定不同 | 脚本末尾自动 grep `fxai_minimax_upscaler*.py` 打出真实目录名，按那个改 `--set-dir` |
| 🚨 提交任务返回「模型不存在 / 找不到模型」，服务端连候选都没有 | **V1.9 换了模型与工作流，连的是 V1.9 之前创建的实例** | **必须用同一个镜像 ID 重新创建一台新实例**（内容已覆盖为 V1.9；仙宫云同样必须重建）；重下模型 / 改模型名 / 重启都补不齐。见下节 |
| 装完节点不生效 | ComfyUI 没重启 | 重启 ComfyUI 进程/容器；`python deploy.py verify -H ...` 复查 |
| pip 装依赖失败 | 镜像源慢 | 不致命，重启看日志再补；或手动 `$PY -m pip install -r <节点>/requirements.txt`（`$PY` 是脚本日志里的解释器） |
| GitHub 克隆 `gnutls_handshake() failed` | 仙宫云到 GitHub 的 TLS 常被掐 | 已加 3 次重试（间隔 3 秒）。仍失败手动 `git clone --depth 1 <repo> <目标>` |
| 装完仍报缺节点 | ComfyUI 版本 < 0.30.0 | `--upgrade-comfy` 升级 |

## 🔴 打开就是指定工作流（镜像内置，不依赖浏览器）

**目标**：镜像重新部署后，任何浏览器、任何新域名、零 localStorage，裸地址打开 ComfyUI
就直接打开我们指定的工作流（可以**多条**），**永不出官方内置的「基础文生图」默认图**，
而且**不新建任何文件夹、不多出任何多余标签**。

### 分工（2026-11-13 用户定稿，两层 + 一层自愈）

| 层 | 载体 | 职责 |
|---|---|---|
| 主力：打开哪几条 | `custom_nodes/fxai-toolkit/js/fxai_default_workflow.js` 的 `TARGETS` 数组 | 打开的是**真实持久化工作流**：标签名=文件名、能直接保存回原文件、侧栏高亮正常 |
| 兜底：不出官方图 | `assets/default-workflow/fxai_default_workflow.py` + `99-fxai-default-wf.sh` | 把前端 bundle 里硬编码的官方图换成我们的工作流；扩展没加载时也不会露官方图 |
| 自愈：扩展别丢 | `99-fxai-default-wf.sh` 第 ① 段 | 开机检查扩展文件；被节点重装/误删就从 `/root/xgyscripts/fxai_default_workflow.js` 复制回来 |

改「默认打开哪几条」只改 `TARGETS` 一处，**不要**去建目录、不要去写 `.index.json`。

### 各类升级的影响面（实测口径）

| 升级动作 | 扩展（TARGETS） | 兜底内置图 | 处理 |
|---|---|---|---|
| 升级 ComfyUI 本体（git pull / 换版本） | 不受影响（在 `custom_nodes` 里，被 `WEB_DIRECTORY` 自动加载） | 不受影响 | 重启即可 |
| 升级 `comfyui-frontend-package` | 不受影响（前端包在 `site-packages`，扩展在节点包） | **会被覆盖**，变回官方基础文生图 | 跑一次 `fxai_default_workflow.py`（或重启触发开机脚本）；bundle 的 `var K` 锚点若变，脚本会 `SKIP` 并提示 |
| 更新/重装 `fxai-toolkit` 节点 | 随仓库走（`git pull` 保留文件）；**整目录重装会丢** | 不受影响 | 开机脚本自愈；或重跑 99 脚本 |
| 云端重新部署（换实例，镜像里） | 随镜像（节点包 + `/root/xgyscripts` 备份） | 随镜像（`/scripts/start.d`） | 开机自动执行 |

🔴 **唯一需要留意的一类**：前端大版本把 `app.extensionManager.workflow` 的
`openWorkflow` / `openWorkflowsInBackground` / `closeWorkflow` 改名。那时扩展会静默失败
（控制台只有 `[fxai-default]` 一行日志），画面退回「兜底内置图」——
内容仍是我们的工作流，但标签名会是 `Unsaved Workflow`。判断方法：全新浏览器打开后，
`openWorkflows[*].temporary` 若为 `true` 就是这个情况，去查前端 API 改名即可。

🔴 **新增 js 文件必须重启 ComfyUI** 才会进入 `/extensions` 列表；只改已有 js 的内容不用重启，
浏览器强刷就生效。开机脚本恢复回来的文件，如果启动时本来缺失，也要重启才会被注册。

### 🔴 为什么不能靠 `?workflows=` 参数（重要，别再走回头路）

前端 1.59.1 的 `useFolderWorkflowsUrlLoader()`：

```js
function isFolderName(e){ return typeof e=="string" && e!=="" && !e.includes("/") && !e.includes("\\") && !e.includes("..") && !e.includes(",") }
async function openInFront(folder){ let t=workflowsIn(folder); return t.length===0||!await openWorkflow(t[0])?false:(openWorkflowsInBackground({right:t.map(e=>e.path)}),true) }
```

- 参数值只能是**单层目录名**，`isFolderName` 直接拒绝带 `/` 的值 → **传不了文件名**。
- 它会打开该目录下**全部** `.json`：第一条进前台，其余全部塞成后台标签。
- 所以「用 URL 指定某一条」这条路不存在；早期为了绕开它而新建 `workflows/默认/` 软链目录 +
  `.index.json` favorites + `index.html` 首访跳转，**已全部废弃并清理**（用户明确不要多出来的
  文件夹和标签，而且以后删了那条工作流就全坏）。

### 扩展的行为边界（保守，不抢用户操作）

`fxai_default_workflow.js` 在 `setup()` 后每 400ms 检查一次、最多 20 秒，只在**全部**满足时动手：

- 当前只有一个工作流标签，且 `activeWorkflow.isTemporary === true`（刚启动的临时图）
- `isModified !== true`（用户没改过画布）
- `openWorkflows.length === 1`（用户没开别的）
- 画布已有节点（`app.graph._nodes.length > 0`，说明初始化完成）

命中后：`openWorkflow(TARGETS[0])` → 其余 `openWorkflowsInBackground({right:[...]})` →
关掉临时标签 → 清掉 URL 参数。已经有真实工作流（上次恢复的）或用户改过 → **完全不动**。

### 兜底脚本（前端包升级后重打）

```bash
PY=/root/miniconda3/envs/comfyui/bin/python
$PY /root/xgyscripts/fxai_default_workflow.py --check     # 只检查不写
$PY /root/xgyscripts/fxai_default_workflow.py             # 应用（幂等，顺带清理历史遗留）
$PY /root/xgyscripts/fxai_default_workflow.py --revert    # 还原官方默认图
bash /scripts/start.d/99-fxai-default-wf.sh              # 开机脚本实跑
```

脚本同时会**清理旧版本的遗留**（幂等）：删 `workflows/默认/`（只删软链和空目录，真文件一律保留）、
从 `.index.json` 移除 `workflows/默认/` 收藏（空了就把文件也删）、从 `index.html` 移除
`<!--FXAI_DF_START-->…<!--FXAI_DF_END-->` 注入段。

### 验收（缺一不可）

- `curl -s 127.0.0.1:8188/ | grep -c FXAI_DF_START` → **0**（首页注入已清空）；
  `grep -c FxAiQwenImage21Edit <static>/assets/workflowStore-*.js` → 1（兜底图仍在）。
- `curl -s 127.0.0.1:8188/extensions | grep fxai_default_workflow` → 有输出（扩展开关已注册）。
- **全新浏览器 profile**（Playwright `launch_persistent_context` 到新目录）打开裸地址：
  `app.extensionManager.workflow.openWorkflows` 应等于 `TARGETS` 列的那几条，
  **每条 `temporary:false`、`path` 以 `workflows/` 开头**；
  `document.title` = 第一条的名字；节点类型不含 `CLIPTextEncode`/`SaveImage` 官方图特征。
- 浏览器控制台出现 `[fxai-default] 打开默认工作流 → workflows/xxx.json, workflows/yyy.json`。

### 踩过的坑

- 旧开机脚本 `ls -d ... | head -1` 挑中的是 `python3.1` 那份，而 ComfyUI 实际跑
  **`python3.12`**；现脚本用 glob 遍历**所有** `static` 目录（这两份其实是同一 inode，
  写一次两处都变，但仍要全遍历防以后分家）。
- `pip install -U comfyui-frontend-package` 会**覆盖** `index.html` 和 `workflowStore-*.js`，
  且新 bundle 的 hash 文件名会变 → 脚本用 `workflowStore-*.js` 通配 + 哈希标记幂等重打，
  升级后必须重跑一次（开机脚本会自动做）。**扩展本身在前端包之外，不受升级影响。**
- 只改 bundle 的 K 段，标签名会是 `Unsaved Workflow`：前端启动时是
  `createTemporary(i18n('Unsaved Workflow'), K)`，名字由调用方给，K 里的字段改不动它。
  **要名字正确、能保存回原文件，必须靠扩展打开真实路径。**
- 工作流 JSON 改了内容：脚本按 `sha1` 标记判断，不一致就只换 K 段，不会重复叠加。
- 新增 `js/*.js` 扩展后必须**重启 ComfyUI**（`/extensions` 列表启动时扫描），
  只改已有 js 的内容不用重启，浏览器强刷即可。

## 🔴 V1.9 · 提交报「模型没有了」→ 重新创建新实例

**判据**：提交工作流后服务端返回「模型不存在 / 找不到模型 / `value_not_in_list` 且连可替换的候选都没有」，
而工作流用的是 V1.9 的新模型（PRISM / RelayVSR / `H3人脸去油.safetensors` 等）。
这说明**连着的是 V1.9 之前用旧镜像创建的实例** —— 模型装在实例系统盘，技能包升级改不到它。

**以下动作无效**：在旧实例上补下模型、改工作流里的模型名、重启 ComfyUI、`--upgrade-comfy`、
或反复重提任务。这些都补不齐整套新模型，只会白烧 GPU 时间。

**要做的**：提示用户**用同一个镜像 ID 重新创建一台新实例**（ID 不变、镜像内容已覆盖为 V1.9；用仙宫云时同样必须重建），
并给出 `deploy-image 9463d4ca-2f86-45cf-b0a3-a81ba6f3b27c` 的演练请求体；**用户明确确认后才加 `--yes` 真建**（实时扣费，不自动创建）。
建完按 `01-实例管理API.md` 的顺序：`comfy-url <新ID>` 拿地址 → `xgy_guard.py use <新ID>` 写全局配置
→ `comfy_url` 指向新实例 → 再出片。旧实例按需 `release-gpu` 停机保留，不销毁。

客户端侧已经自动提示：`fxai-workflow/comfy_client.py` 的 `_fmt_model_fix()` 在模型找不到对应项时
会打印「必须新建实例（镜像 ID 不变）」的完整指引与镜像 ID，运行期不用靠人翻这一册。

## fxai-toolkit 报「节点不存在 / IMPORT FAILED」

**通常不是没装节点**，而是缺 Python 依赖，整个包 import 失败（comfyui.log 留痕
`fxai_audio_utils.py line N → ModuleNotFoundError: No module named 'soundfile'`）。
必须先装依赖再重启，否则所有 `FxAi*` 节点都不会注册。

```bash
PY=$(readlink -f /proc/$(pgrep -f "main.py --enable-cors-header" | head -1)/exe)
$PY -m pip install soundfile        # 目前唯一缺的依赖；toolkit 无 requirements.txt
# 装完必须重启 ComfyUI，日志出现「凤希AI - 角色资源管理器」横幅即成功
```

**别在 ComfyUI 进程外用裸 import 验证 fxai-toolkit**：会误报
`PromptServer has no attribute 'instance'`。只能在重启后看 `/object_info` 里有没有 `FxAi*` 节点。

（密码 eem3…）**已经连不上了**（SSH banner 直接 Reset）。凭据一律从


### 步骤
1. **先看落后多少**（非 shallow 仓库才能算出来）：
   `git rev-list --left-right --count HEAD...@{u}`，或用 `git fetch origin --quiet` +
   `git log --oneline HEAD...origin/HEAD`。
2. **确认依赖变没变**：`git log --name-only --pretty=format: HEAD..origin/master | grep -E "requirements|pyproject"`。
   没输出就**一个包都不用装**；有输出才 `python -m pip install -U -r requirements.txt`
   （注意别顺手升 requirements 里的 `comfyui-frontend-package` 等钉死版本，
    `system_stats` 里 installed 必须等于 required）。
3. **升本体**：`git pull --ff-only origin master`。工作区有已跟踪文件被删也能拉，
   前提是要拉的那批 commit 没碰它们（`git log --name-only` 先核一遍）。
4. **升自定义节点**：git 装的 `git pull --ff-only`；**zip 装的目录没有 .git，
   只能删了重拉**（`git clone --depth 1` 覆盖前把旧目录 `mv` 成 `.bak.<ts>` 可回滚）。
   解压前先 `rm -rf` 旧 `__pycache__`（残留 pyc 会让节点看起来加载了其实没换代码）。
5. **重启**：`bash /root/xgyscripts/xgy_restart_comfy.sh`（sleep 55 后日志才打完）。
6. **验收**：`/fxai/health` + `/system_stats` 必须 200；`object_info` 节点数
   **不该比升级前少**（升级前先记一次基线）。当前基线：`object_info` **1549** 个，
   其中 `FxAi*` **102** 个、`*KJ` **37** 个。日志里 `Import times` 段要能看见每个节点的加载秒数。

| 目标 | 结果 |
|---|---|
