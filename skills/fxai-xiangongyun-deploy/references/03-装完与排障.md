# 装完之后与排障（装完配置 / 重启 / 升级 / 报错时读）

## 常见问题
| 现象 | 原因 | 处理 |
|---|---|---|
| 401 / 镜像没收录 | 平台没同步这个仓库 | **找仙宫云客服收录**；非要开备用源：`XGY_SRC_ORDER="mirror,ms,hf" python deploy.py run --only <id>` |
| 速度只有 ~11 MB/s | 魔搭单连接速度 | 加 `--parallel 3`；或挂数据盘 |
| 下下来 145 字节、开头是 `{"Code":10990101007...}` | 不存在的仓库也返 200 | 脚本已自动识别；若出现，检查 `repo` / `ms_repo` 配的仓库名 |
| 文件体积越下越小 | 源不支持 Range，`curl -C -` 把目标文件从 0 截断重写 | 所有 URL 都由 `probe_sources.py` 提前验过返 206；换源前必须重跑探测 |
| 磁盘不够 | 全量 79.5 GB | `--group img`（21 GB）；或「关机释放GPU → 开机」免费扩容；或挂数据盘后 `--set-dir <id>=<子目录>` |
| 节点报错「找不到模型」 | 凤希自研节点读盘目录和常规约定不同 | 脚本末尾自动 grep `fxai_minimax_upscaler*.py` 打出真实目录名，按那个改 `--set-dir` |
| 🚨 提交任务返回「模型不存在 / 找不到模型」，服务端连候选都没有 | **V1.9 换了模型与工作流，连的是旧镜像创建的实例** | **必须用 V1.9 对应的新镜像重新创建一台新实例**（仙宫云同样必须重建）；重下模型 / 改模型名 / 重启都补不齐。见下节 |
| 装完节点不生效 | ComfyUI 没重启 | 重启 ComfyUI 进程/容器；`python deploy.py verify -H ...` 复查 |
| pip 装依赖失败 | 镜像源慢 | 不致命，重启看日志再补；或手动 `$PY -m pip install -r <节点>/requirements.txt`（`$PY` 是脚本日志里的解释器） |
| GitHub 克隆 `gnutls_handshake() failed` | 仙宫云到 GitHub 的 TLS 常被掐 | 已加 3 次重试（间隔 3 秒）。仍失败手动 `git clone --depth 1 <repo> <目标>` |
| 装完仍报缺节点 | ComfyUI 版本 < 0.30.0 | `--upgrade-comfy` 升级 |

## 🔴 打开就是自定义默认工作流（镜像内置，不依赖浏览器）

**目标**：镜像重新部署后，任何浏览器、任何新域名、零 localStorage，裸地址打开 ComfyUI
都直接显示我们自己的工作流，**永不出官方内置的「基础文生图」默认图**。

**为什么必须改前端包**：前端 1.59.1 把官方默认图**硬编码**在
`assets/workflowStore-*.js` 的 `var K={...},_e=JSON.stringify(K)` 里，`Load Default Workflow`
命令与无状态启动都读它。官方**没有**服务端「默认工作流」设置项；`.index.json` 的 favorites
只管侧栏书签，标签状态在浏览器 localStorage（`Comfy.Workflow.OpenPaths:*` 按 clientId 索引）。
所以「存镜像前在自己浏览器里打开一次」这种办法，换机/换域名就失效。

**三层固化，只用一份脚本**：`assets/default-workflow/fxai_default_workflow.py`
（部署到云端 `/root/xgyscripts/fxai_default_workflow.py`），配
`assets/default-workflow/99-fxai-default-wf.sh`（放到 `/scripts/start.d/`，开机自动执行、幂等）。

1. **替换内置默认图**：把 `var K={...}` 整段换成自定义工作流的单行 ASCII JSON
   （`ensure_ascii=True`，避免中文 / U+2028 破坏 JS 字面量）。`_e` 与
   `window.comfyAPI.defaultGraph.defaultGraph` 都由 K 派生，一处替换全链路生效。
   原始 K 段 base64 存进同文件注释，`--revert` 可精确还原。
2. **首页首访重定向**：`index.html` 的 `<head>` 注入脚本，无 URL 参数且无历史标签时
   → `/?workflows=默认`。这样打开的是**持久化工作流**（能保存、标签名正常、书签常驻），
   而不是临时草稿。前端原生支持该参数：打开目录下所有 json、第一个置前、随后抹掉参数。
   🔴 参数值只能是**纯目录名**，含 `.` `/` `..` `,` 会被 `isFolderName` 拒绝 → 不能传文件名。
3. **目录与书签**：`workflows/默认/` 里只留一条指向源文件的**软链**（不复制副本），
   `.index.json` 写 `{"favorites":["workflows/默认/<文件名>.json"]}`。

```bash
# 云端执行（校验 / 应用 / 回滚）
PY=/root/miniconda3/envs/comfyui/bin/python
$PY /root/xgyscripts/fxai_default_workflow.py --check     # 只检查不写
$PY /root/xgyscripts/fxai_default_workflow.py             # 应用（幂等）
$PY /root/xgyscripts/fxai_default_workflow.py --revert    # 还原官方默认图 + 移除注入
bash /scripts/start.d/99-fxai-default-wf.sh              # 开机脚本实跑
```

**验收（缺一不可）**：
- `curl -s 127.0.0.1:8188/ | grep -c FXAI_DF_START` → 1；
  `grep -c FxAiQwenImage21Edit <static>/assets/workflowStore-*.js` → 1。
- **全新浏览器 profile**（Playwright `launch_persistent_context` 到新目录）打开裸地址：
  最终 URL 带 `?workflows=%E9%BB%98%E8%AE%A4`，`document.title` 为
  `千问2.1图片处理 - ComfyUI`，`app.graph._nodes` 的 type 集合与源工作流一致，
  且**不含** `CLIPTextEncode` / `SaveImage` 那套官方图节点。
- 演练一遍「补丁丢了」：`--revert` → 跑开机脚本 → 再查上面两项恢复为 1。

**踩过的坑**：
- 旧开机脚本 `ls -d ... | head -1` 挑中的是 `python3.1` 那份，而 ComfyUI 实际跑
  **`python3.12`**；现脚本用 glob 遍历**所有** `static` 目录（这两份其实是同一 inode，
  写一次两处都变，但仍要全遍历防以后分家）。
- `pip install -U comfyui-frontend-package` 会**覆盖** `index.html` 和 `workflowStore-*.js`，
  且新 bundle 的 hash 文件名会变 → 脚本用 `workflowStore-*.js` 通配 + 哈希标记幂等重打，
  升级后必须重跑一次（开机脚本会自动做）。
- 工作流 JSON 改了内容：脚本按 `sha1` 标记判断，不一致就只换 K 段，不会重复叠加。
- 只写 `?workflows=默认` 这个 URL 给别人不行 —— 那是浏览器侧行为，URL 参数会被抹掉、
  下次打开还是回官方默认图。**必须改服务端前端包**。

## 🔴 V1.9 · 提交报「模型没有了」→ 重新创建新实例

**判据**：提交工作流后服务端返回「模型不存在 / 找不到模型 / `value_not_in_list` 且连可替换的候选都没有」，
而工作流用的是 V1.9 的新模型（PRISM / RelayVSR / `H3人脸去油.safetensors` 等）。
这说明**连着的是 V1.9 之前用旧镜像创建的实例** —— 模型装在实例系统盘，技能包升级改不到它。

**以下动作无效**：在旧实例上补下模型、改工作流里的模型名、重启 ComfyUI、`--upgrade-comfy`、
或反复重提任务。这些都补不齐整套新模型，只会白烧 GPU 时间。

**要做的**：提示用户**用 V1.9 对应的新镜像重新创建一台新实例**（用仙宫云时同样必须重建），
并给出 `deploy-image <新镜像ID>` 的演练请求体；**用户明确确认后才加 `--yes` 真建**（实时扣费，不自动创建）。
建完按 `01-实例管理API.md` 的顺序：`comfy-url <新ID>` 拿地址 → `xgy_guard.py use <新ID>` 写全局配置
→ `comfy_url` 指向新实例 → 再出片。旧实例按需 `release-gpu` 停机保留，不销毁。

客户端侧已经自动提示：`fxai-workflow/comfy_client.py` 的 `_fmt_model_fix()` 在模型找不到对应项时
会打印「必须用 V1.9 新镜像重新创建实例」的完整指引，运行期不用靠人翻这一册。

## 工作流改了要同步清单

改了工作流（新增/换模型）之后**必须**跑一次对账，否则装完才发现少东西：

```bash
python scan_workflows.py
```

它扫工作流目录里所有 `*.json`，正则捞出模型文件名、汇总所有 `class_type`，
跟 `assets/models.json` / `assets/nodes.json` 对账，报告哪些模型没被清单覆盖、哪些节点类型没有对应节点包。

## 装完之后
1. 重启云端 ComfyUI（装在 screen `sd` 会话里，见下）。
2. 本机 `~/.workbuddy/fxai_global.json` 把 `comfy_url` 指向 ComfyUI 公网地址：
   **`http://<实例ID>-8188.container.x-gpu.com`**（端口写在**主机名里**，不是 `:8188` 后缀）。
   地址用 `python xgy_api.py comfy-url <id>` 拿，别自己拼。
   本机跑客户端前要 `export NO_PROXY=".x-gpu.com,127.0.0.1,localhost"`（本机有代理会拦）。
3. 角色参考图传到 **`<comfy_root>/fxai/image/avatar/`**（不是 `input/avatar/`），
   否则运行时报 `没有图片，请选择图片文件`。参考图从本机 `本机 ComfyUI 的 input 目录\0NN_*.png` 取。
4. 按 `fxai-workflow` 铁律：确认资源只走接口（提交任务返回 `queued` 即证明服务端读到了），
   本机侧以接口返回为准。

## 重启云端 ComfyUI

装在 screen 会话 `sd` 里（`/tmp/sd.log` 为日志），conda env `comfyui`：

```bash
bash /root/xgyscripts/xgy_restart_comfy.sh
```

脚本内容（现成，别手敲）：`screen -S sd -X quit` → kill 残留 → `rm -f /tmp/sd.log` → 重新拉起 → sleep 45 后打日志尾部。
启动参数：`python main.py --enable-cors-header --enable-manager --listen 0.0.0.0 --mmap-torch-files --disable-pinned-memory`
（`--enable-manager` 别改，不然前端 focusMode 之外还会少 Manager 入口）。

脚本只 sleep 45 秒，脚本内不一定打完「All startup tasks have been completed」，要额外 sleep 20–25 再查。

## fxai-toolkit 报「节点不存在 / IMPORT FAILED」

**通常不是没装节点**，而是缺 Python 依赖，整个包 import 失败（comfyui.log 留痕
`fxai_audio_utils.py line N → ModuleNotFoundError: No module named 'soundfile'`）。
必须先装依赖再重启，否则所有 `FxAi*` 节点都不会注册。

```bash
PY=$(readlink -f /proc/$(pgrep -f "main.py --enable-cors-header" | head -1)/exe)
$PY -m pip install soundfile        # 目前唯一缺的依赖；toolkit 无 requirements.txt
# 装完必须重启 ComfyUI，日志出现「凤希AI - 角色资源管理器」横幅即成功
```

**别在 ComfyUI 进程外用裸 import 验证 fxai-toolkit**：会误报
`PromptServer has no attribute 'instance'`。只能在重启后看 `/object_info` 里有没有 `FxAi*` 节点。

## 更新 ComfyUI / 自定义节点（在实例上直接升）

```bash

```

### 步骤
1. **先看落后多少**（非 shallow 仓库才能算出来）：
   `git rev-list --left-right --count HEAD...@{u}`，或用 `git fetch origin --quiet` +
   `git log --oneline HEAD...origin/HEAD`。
2. **确认依赖变没变**：`git log --name-only --pretty=format: HEAD..origin/master | grep -E "requirements|pyproject"`。
   没输出就**一个包都不用装**；有输出才 `python -m pip install -U -r requirements.txt`
   （注意别顺手升 requirements 里的 `comfyui-frontend-package` 等钉死版本，
    `system_stats` 里 installed 必须等于 required）。
3. **升本体**：`git pull --ff-only origin master`。工作区有已跟踪文件被删也能拉，
   前提是要拉的那批 commit 没碰它们（`git log --name-only` 先核一遍）。
4. **升自定义节点**：git 装的 `git pull --ff-only`；**zip 装的目录没有 .git，
   只能删了重拉**（`git clone --depth 1` 覆盖前把旧目录 `mv` 成 `.bak.<ts>` 可回滚）。
   解压前先 `rm -rf` 旧 `__pycache__`（残留 pyc 会让节点看起来加载了其实没换代码）。
5. **重启**：`bash /root/xgyscripts/xgy_restart_comfy.sh`（sleep 55 后日志才打完）。
6. **验收**：`/fxai/health` + `/system_stats` 必须 200；`object_info` 节点数
   **不该比升级前少**（升级前先记一次基线）。当前基线：`object_info` **1549** 个，
   其中 `FxAi*` **102** 个、`*KJ` **37** 个。日志里 `Import times` 段要能看见每个节点的加载秒数。

### 本机到云端的下载/网络现状
| 目标 | 结果 |
|---|---|
| `codeload.github.com/.../zip/refs/heads/master` | ❌ 返回 `404: Not Found`（只有 14 字节） |
| `git clone --depth 1 https://github.com/...` | ✅ 通，但**会随机 `gnutls_handshake() failed`**，`for i in 1 2 3 4; do git clone … && break; sleep 4; done` 重试即可 |
| `raw.githubusercontent.com`（Manager 拉清单） | ❌ 现在连不上（日志报 `Failed to perform initial fetching extension-node-map.json`），Manager 退到 local mode，**不影响装/升级节点** |
| `comfyregistry.org` | ❌ 仍不通 |

`/api/kernels/terminals/websocket/<n>` 和 `/api/terminals/websocket/<n>` **全 404**。
