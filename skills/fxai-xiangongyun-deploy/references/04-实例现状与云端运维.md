## 本机复用工具（`<工作目录>\仙宫云\`）

**推工作流**：`push-workflows.py`
```bash
python push-workflows.py
# 只推指定几个：--map 16.json=千问2.1图片处理.json 19.json=Yue2音乐生成.json
```

**SSH 执行器**：`xgy_ssh.py`（paramiko，已装在该 venv）
```bash
python xgy_ssh.py "<远程命令>"
python xgy_ssh.py --upload <本地> <远端>
python xgy_ssh.py --pull  <远端> <本地>
```

容器里**没有 `python` 只有 `python3`**；跑 ComfyUI 依赖必须先
`source /root/miniconda3/etc/profile.d/conda.sh && conda activate comfyui`
（前台命令用 `/root/miniconda3/envs/comfyui/bin/python`）。

**升级包**（启动日志会主动点名要升的这 4 个 frontend 相关，升完那段 WARNING 整块消失）：
```bash
conda activate comfyui
pip install -U comfyui-frontend-package==1.53.10 comfyui-workflow-templates==0.11.74 \
             comfyui-embedded-docs==0.5.13 comfy-kitchen==0.2.36
```
ComfyUI 本体无需升级：`git -C /root/ComfyUI rev-list HEAD..@{u} --count` = 0。

**长命令拆开发**：`xgy_ssh.py` 的 `cmd = " ".join(args)`，一条命令里嵌套太多层引号会让远端返回
exit 127。重启这类长命令拆成 2~3 次调用。`Git Bash` 下双引号包壳会让变量变字面量
（报 `integer expression expected`），纯 grep/echo/for 的命令外层改用单引号。

## 本地自定义节点推上实例的标准流程
1. **`pack-node.py [源目录] [输出zip]`** —— 打包本地节点，自动排除 `.git / __pycache__ / node_modules / venv`。
   zip 内**根就是节点目录名**，解包 `extractall(custom_nodes)` 即得 `custom_nodes/<节点名>/`，不会多套一层。
2. **`upload-node.py [本地zip] [节点目录名]`** —— 上传 + 解包 + 清理 zip；
   同名目录已存在会先 `mv` 成 `.bak.<ts>`（可回滚）。
3. 依赖：`pip install` 必须进 **`/root/miniconda3/envs/comfyui/bin/pip`**（不是系统 pip，也不是 conda base）。
4. 重启 + 快照看 Import times 里有没有 `[INFO]   x.x seconds: /root/ComfyUI/custom_nodes/<节点名>`；
   再用 `check-nodes-exist.py <节点名...>` 验是否真注册进 `object_info`。

依赖别靠猜：逐个 `envs/comfyui/bin/python -c "import X"` 验
（matplotlib/cv2/PIL 常已带，mss / color-matcher 常缺）。
验收指标：`object_info` 返回类型总数会变大（KJNodes 装完基线 **1548**）。

## ComfyUI-Manager：已内置

启动命令自带 `--enable-manager`，Manager 后端是核心内置包 `site-packages/comfyui_manager`，
**不在** `custom_nodes` 目录里 —— 那里没有 `ComfyUI-Manager` 是正常现象。

配置：`/root/ComfyUI/user/__manager/config.ini`。清单缓存在 `/root/ComfyUI/user/__manager/cache/`。

**验证 Manager 活着用 `/v2/manager/*` 前缀**（内置版本 4.2.2，REST 已迁到 v2，`/manager/*` 全 404）：
```bash
curl -s 127.0.0.1:8188/v2/manager/version              # -> V4.2.2
curl -s 127.0.0.1:8188/v2/manager/is_legacy_manager_ui # false=新版UI；加了 legacy 参数为 true
curl -s 127.0.0.1:8188/v2/customnode/installed         # 已装节点及 enabled 状态
curl -s 127.0.0.1:8188/v2/manager/queue/status         # 队列状态
```
`/v2/customnode/getmappings` 会 500（无关紧要）。

**启用 legacy 版**（`custom_nodes/ComfyUI-Manager`，v3.42）两步：
① 目录改名 `ComfyUI-Manager` → **`ComfyUI_Manager`**（下划线），
因为 `should_be_disabled()` 是纯目录名匹配（`comfyui-manager`）；
② 启动参数加 **`--enable-manager-legacy-ui`**，否则前端走 v4 UI。
**改 `/root/xgyscripts/xgy_restart_comfy.sh` 里 `python main.py` 那行**，别只改命令行，
这样做镜像时参数跟着走。改回新版则把目录名和参数一起还原。

不想要 legacy 那份：目录改回 `ComfyUI-Manager`（会被策略挡掉变死包），并去掉脚本里的
`--enable-manager-legacy-ui`。

**「看不到 Manager 按钮」= 开了 focusMode（专注模式），不是没装。**
前端 `GraphView-*.js` 里 focusMode 为真时顶栏 `top-menu-actionbars` 整块 `inert + max-h-0`，
「🧩 管理扩展」按钮不渲染；legacy 菜单模式（`Comfy.UseNewMenu=Disabled`）下 focusMode 还会把
`menuContainer` 整个 `display:none`。
- **一键修**（只删这 2 个 key，其它设置保留）：F12 Console 跑
  `localStorage.removeItem('Comfy.UseNewMenu'); localStorage.removeItem('Comfy.FocusMode'); location.reload()`
- 诊断：`localStorage.getItem('Comfy.UseNewMenu')` / `'Comfy.FocusMode'`；
  手动找路径是 ☰ → `Toggle Focus Mode`（category=`view-controls`），或 ☰ → Manager 项
  （`Comfy.Manager.Menu.ToggleVisibility`，不受 focusMode 影响）。
- **镜像分发要固化两处**：① 服务端默认设置
  `/root/ComfyUI/user/default/comfy.settings.json` 写 `Comfy.FocusMode:false`、`Comfy.UseNewMenu:"Top"`
  （改它不用重启）；② 前端 bundle 打补丁（`<工作目录>\仙宫云\patch-ui-btn.py`，原文件自动备份 `.bak`）：
  把 `GraphView-*.js` 里 actionbar 的折叠写死关掉
  （`inert:a.value,"aria-hidden":a.value` → `inert:!1,"aria-hidden":!1`；
  `` `...ease-in-out`,a.value&&`max-h-0 translate-x-8 opacity-0` `` → `` `...ease-in-out`,`ease-in-out` ``）。
  ⚠️ 升级 `comfyui-frontend-package` 会覆盖补丁，需重跑 `patch-ui-btn.py`，
  文件名_hash 变了（脚本按当时的文件名硬编码，报错再改 TARGET）。
  补丁串要用 `BT = chr(96)` 现拼反引号；`ease-in-out` 后跟的是反引号不是双引号。
- 挖前端代码用 `diag-ui-btn.py`（在 `<工作目录>\仙宫云\`）：探测脚本写进远端 /tmp 再执行，
  绕开多层引号转义；远端脚本模板用 `.replace()` 注入，避开 `%` 格式化（minify 代码里全是 `%`）。

**前端资源在 `site-packages/comfyui_frontend_package/static/assets/`**，
`/root/ComfyUI/web` 不存在；要判断「前端有没有某个 UI」grep 上面那个 assets 目录。
排障前先看是不是新 bundle：`curl -s 127.0.0.1:8188/` 看 `index-*.js` 哈希，并让用户强刷 Ctrl+Shift+R。

**「是不是没装前端？」的硬证据两条**：① assets 目录下 `index-*.js` 存在；
② grep 到 Manager 专属字符串 `menu.manageExtensions`。
Manager 是否装上以 grep 到专属字符串 `menu.manageExtensions` 为准（grep manager 数量会被 three.js 的 RecordingManager/CameraManager 大量命中）。

`comfyregistry.org` 在本实例返回 000（不通），Manager 面板的「官方推荐 / 缺失节点」区加载不出来，
**但不影响安装节点**（安装走 github clone），日志里那句 `Cannot connect to comfyregistry.` 可忽略。

`commands.json` / `extensions/index.json` 在新版 Manager main 分支已拆成
`custom-node-list.json` + `extension-node-map.json`，拿旧文件名 curl 会 404。

**命令行装节点**（Manager 同一套代码，UI 点不动时用）：
```bash
source /root/miniconda3/etc/profile.d/conda.sh && conda activate comfyui
export COMFYUI_PATH=/root/ComfyUI
git clone --depth 1 https://github.com/ltdrdata/ComfyUI-Manager /tmp/cm   # cm-cli 需要
cd /tmp/cm && PYTHONPATH=/tmp/cm python cm-cli.py install <节点github地址>
# 子命令：install / uninstall / update / disable / enable / fix / show / save-snapshot / restore-snapshot
```

## 该实例外网连通性
| 地址 | 结果 |
|---|---|
| `https://github.com`（git clone） | 通 |
| `raw.githubusercontent.com` | ⚠️ 会掉（Manager 拉清单报 `Failed to perform initial fetching`、退 local mode），节点照装照升，只影响 Manager 在线清单 |
| `pypi.org` / 清华 pypi 镜像 | 通（conda env 里有 `uv 0.12.5`） |
| `codeload.github.com` | ❌ zip 下载拿 `404: Not Found`（14 字节）；要代码就 `git clone --depth 1` |
| `gitee.com` / `hf-mirror.com` / `modelscope.cn` / `huggingface.co` | 通 |
| github 仓库不存在时 | 报 `could not read Username for 'https://github.com'`（404 页面）≠ 权限问题；先 `curl -o /dev/null -w '%{http_code}'` 验仓库是否真存在 |
