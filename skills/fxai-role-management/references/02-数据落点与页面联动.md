# 02 · 数据落点与页面联动

> **何时读**：确认写到哪里、页面看不到新角色、换用户账号、判断能否安全写入时。

## 一、数据落点

```
<数据目录>/sqlite/user_<用户ID>.db   →   表 ai_digital_human
```

- **数据目录来自全局配置**：`~/.workbuddy/fxai_global.json` 的 `software_data_dir`（取值形如 `<数据盘>/fxaitool`，随机器而异）。该文件由客户端「本机配置 → 技能运行环境」页生成，和 `software_install_dir` 一起写；脚本只认这一条，再兜底环境变量 `FXAI_DATA_DIR`，**不扫盘**。
- 装第二个盘才知道路径的机器也一样：用户在配置页选哪块盘，`software_data_dir` 就是哪块，脚本跟着走。
- 用户 ID 是客户端登录账号的 MyId，本机可能同时存在多个 `user_*.db`；每个账号一张角色表。
- 表由客户端建：`AiDigitalHuman` 实体，模块号 5，当前版本 2。**技能不建表**，表缺失时让用户先打开一次「AI伙伴」页面。

## 二、谁在读这张表

| 读取方 | 接口 | 用途 |
|---|---|---|
| 客户端适配层 | `getDigitalHumanList()` | 只取 id/title/nickname/avatar/gender/age/category/markerid，列表用 |
| 客户端适配层 | `getDigitalHumanInfo(id)` | 单角色全字段，编辑页用 |
| `tool/digitalhuman/index.js` | 上面两个 | 「AI伙伴」页面：角色卡、编辑、删除 |
| `tool/digitalhuman/pickrole.html` | `getDigitalHumanList()` | 选角色器 |
| `tool/tts/index.js` | 选角色器回传 | 多角色配音「选择角色」：带 title 与 voice、voicetext 进配音列表 |

写进这张表 = 客户端各页面都能读到，无需额外同步。页面不会主动轮询，**必须让用户切页或重进页面**才能看到新数据。

## 三、当前用户来源

`<安装目录>\userinfo.json` 的 `myid`（安装目录 = 全局配置的 `software_install_dir`）：

```json
{ "myid": "212", "account": "9000000000212", "nickname": "…", "usertoken": "…" }
```

**每次登录都会自动切换**，链路已核对客户端源码：

| 环节 | 位置 | 动作 |
|---|---|---|
| 登录成功回调 | `js/app.js` → `RssUser.Login` 里的 `top.onWeiXinLogin(data)` | `RssUser.Update(data)`，把新用户写进 `localStorage` 的 `ry-userdata` |
| 框架钩子 | `rsseasy.v3.min.js` 的 `RssUser.Update` | 覆盖完 `ry-userdata` 后调 `this.onUpdate()` |
| 业务钩子 | `js/app.js` 的 `RssUser.onUpdate` | `fxaitoolkit.updateUserInfo()` |
| 客户端 | `JsAdapter.updateUserInfo(json)` | `UserInfo.SetInstance(...)` → 整份重写 `Application.StartupPath\userinfo.json`，随后 `SQLiteTableManager.initTableStructure()` 建/补当前用户的表 |

所以：**换账号后 `userinfo.json` 的 `myid` 跟着变，`user_<myid>.db` 也由客户端在登录时建好**，技能每次调用重新读文件即可，不用问用户ID、也不该缓存。

- 只读 `myid` / `nickname` / `account`，**不读 `usertoken`**，不复制整份配置。
- 校验闭环：`myid` 对应的 `user_<myid>.db` 必须存在；不存在时报错，不自动换成别的账号库。
- 读不到 `userinfo.json` 时脚本直接指出是「全局配置没生成 / 没配 `software_install_dir` / 目录里没这个文件」中的哪一种，不靠猜。
- 目录来源、四步判定与缺失提示的统一口径见 `fxai-standard` 08 册（客户端与登录检测）。

## 四、用户库选择规则

| 场景 | 规则 |
|---|---|
| `userinfo.json` 有 myid，且 `user_<myid>.db` 存在 | 直接用该库 |
| `userinfo.json` 有 myid，但对应库不存在 | 报错并列出现有库，不自动换库 |
| 读不到 `userinfo.json`，只有一张库有角色 | 用该库 |
| 读不到 `userinfo.json`，多张库都有角色 · 读 | 取最近修改的那张，输出列出其它库 |
| 读不到 `userinfo.json`，多张库都有角色 · 写 | 拒绝执行，要求 `--uid` |

脚本按 `os.listdir` 扫 `sqlite/user_*.db`，跳过 0 字节文件与非数字后缀（`user_.db`、`*.bak_*` 不计入）。`--uid` 覆盖以上全部规则。

## 五、写入规则

- 新增行：`markerid = uuid4().hex`（与客户端 `Guid.NewGuid("N")` 同格式）、`addtime = 本机时间 yyyy-MM-dd HH:mm:ss`、`issync = 0`。
- 更新行：只写传入字段，不动 `markerid` / `addtime` / `issync`。
- 连接参数：`timeout=8`、`PRAGMA busy_timeout=8000`，客户端运行中可直接写；被长事务占用时等 8 秒后报 locked。
- 事务：单条 `INSERT` / `UPDATE` / `DELETE` 后立即 `commit`，不开跨语句事务。
- `journal_mode` 保持库文件原值，不 `VACUUM`、不建索引，连接参数只设超时。

## 六、写前备份

路径：`<技能>/data/backup/<yyyymmdd_HHMMSS>_<add|update|delete>_user<uid>.json`

```json
{ "action": "delete", "uid": "212", "time": "20261018_122300",
  "rows": [ { "id": 3, "title": "…", "markerid": "…", "voice": "…" } ] }
```

回滚办法见 01 册第四节。

## 七、边界

- 不写服务端角色表：本机角色是本地库，云端没有对应表。
- 不复制音色与图片：`voice` / `avatar` / `portrait` 只存路径，源文件移动后页面会失效。
- 不改客户端缓存：页面显示的是重新查询的结果，没有缓存可清。
- 不动 `fxai.db`：那是公共库，角色只在 `user_<uid>.db`。
