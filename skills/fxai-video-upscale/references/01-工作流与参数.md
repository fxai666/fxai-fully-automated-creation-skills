# 01 · 工作流与参数

> **何时读**：要把一整条视频超分并逐段修脸/换脸、走本机 ComfyUI 时；要改节点参数、查占位符、查产物从哪取时。

链路：**源视频 → 分段 → 自研超分 → 逐段修脸 / 换脸 → 逐段保存 → 合并成片**。

跑的是 `fxai-workflow/upscale-fvsr.json`（占位符版，来自工具箱 `视频超分人脸精修V1.json` 的 API 导出），注册表任务名 `upscale`、模型 slug `fvsr`。入口脚本 `scripts/video_upscale.py`。

## 一、节点结构（14 个节点）

```
108 视频分段器 ──┬─→ 111 生成控制器（宽度/高度、结束索引）
                 ├─→ 113 视频分段加载 ──→ 124 自研超分 ──→ 123 人脸精修 ──→ 5 保存成片
                 └─→ 114 视频合并（音频取 108 的音频输出）
125 公式节点（value=fxai_scale）──→ 124 与 123 的「放大倍数」
104 角色资源图片选择器 ────────────→ 123 的「参考图」
109 / 110 / 117 循环（计数，逐段推进）
114 视频合并 ──┬─→ 126 自动关机（默认不触发）
              └─→ 127 清理显存（跑完卸模型）
```

- **124 自研超分**：`放大倍数` 接 125 的 float 输出，支持 1.0~4.0，不写死 2 / 4；`分块边长 = 0` 且目标像素 > 0.98 Mpx 时自动改 384；`色彩校正` 开；`帧数对齐` 开（输出帧数 == 输入帧数）；`精度` bf16；`稀疏注意力` 开。
- **123 人脸精修**：`处理脸宽上限` / `换脸脸宽上限` 都是 120，按**原图像素**标定；接了 `放大倍数` 后实际门槛 = 120 × 倍数，改倍数时不必手算。
- **125 是倍数的唯一入口**：`value` 里填数字，输出 float 同时喂 124 与 123；手改倍数只改这里。
- **127 清理显存**接 110 的循环结束输出，保证卸载排在整条循环之后。

## 二、占位符（提交时注入）

| 占位符 | 落在哪个输入 | 传什么 |
|---|---|---|
| `fxai_videoinput` | 108 · 视频文件 | 源视频路径，**服务端可读的绝对路径**（相对路径按服务端根目录解析，报「找不到视频文件」） |
| `fxai_imageinput` | 104 · 图片列表 | **必填**：参考脸，逗号分隔的服务端相对路径（如 `avatar/000.png`）；脚本先校验非空与格式，缺了拒跑 |
| `fxai_outputdir` | 5 · 保存目录 | 服务端保存子目录，默认 `upscale` |
| `fxai_seed` | 123 · 随机种子 | 默认 42（固定，逐段更稳）；<1 即随机 |
| `fxai_width` / `fxai_height` | 111 · 宽度 / 高度 | **跟源视频一致**（占位符默认 960×544，竖屏素材会被拉横）；脚本 ffprobe 源尺寸 |
| `fxai_duration` | 108 · 平均分段时长 | 脚本按「单段帧数 ≤ 400」算，落在 2~10 秒；FLOAT，裸插数字 |
| `fxai_average_segment` | 108 · 是否平均分段 | 固定 `true` |
| `fxai_skip_initial` | 108 · 跳过初始段 | 固定 `true` |
| `fxai_include_tail` | 108 · 包含尾部段 | 固定 `false` |
| `fxai_segment_data` | 108 · 关键帧JSON | 固定 `"[]"` |
| `fxai_start_index` | 111 · 开始索引 | 固定 `0` |
| `fxai_end_index` | 111 · 结束索引 | **固定 `-1`**（＝跑完全部段）。传 `0` 只跑第一段 |
| `fxai_auto_shutdown` | 111 · 自动关机 | 默认 `false`；云端跑完想省机时费才 `--auto-shutdown` |
| `fxai_scale` | 125 · value | 放大倍数的**字符串**形态（如 `1.5`）。超分节点 124 与精修节点 123 的 `放大倍数` 都从 125 的 float 输出取，**全链路只认这一个数** |

`fxai_scale` 是字符串占位符（`value` 是 STRING 输入），由公式节点转成 float 后同时喂 124 与 123；两处倍数永远一致，改倍数只改这一个值。

## 三、分段口径

- 每段上限 10 秒；**单段帧数封顶 400 帧**（显存按帧数线性涨），高帧率素材自动缩短分段：`每段秒数 = min(10, max(2, 400 / fps))`。
- 最后一段不足 3 秒并进倒数第二段，不留碎尾。
- 段与段之间硬拼（无交叉淡化），段越多边界越可能看到跳变；人脸滞回的帧间判断也会在边界重置。
- 每段单独跑一次超分 + 精修，**耗时随片长线性增长**，不是一次推理跑完整片。

## 四、产物归属与取回

**交付物只认合并后的整片**（114 产出，落在服务端 `fxai/video/merged/`）。分段保存节点 5 写的是过程文件，多段任务下只是其中一段，不得当交付物。

下载令牌形如 `video/merged|fxai_<时间戳>.mp4`，由公共层 `submit_workflow` 按顺序取：`fxai:task_saved` 广播 → `/fxai/tasks/result` → `/history` 的 `outputs`。本链路末端是保存与合并节点，令牌走广播那条。

脚本落点默认 `<源文件名>_up<倍数>x.mp4`，下载后校验 MP4 `ftyp` 与体积，并核对成片时长 ≥ 源片 95%（不到即判「只拿到部分段」）。

## 五、改参数

| 要改什么 | 改哪里 |
|---|---|
| 放大倍数 | 脚本 `--scale`；手改工作流时只改 125 的 `value`（124 与 123 都从它取） |
| 换成谁的脸 | 脚本 `--ref`（必填，服务端相对路径，逗号分隔）；不接参考图就换不了脸 |
| 脸宽门槛 | 123 的 `处理脸宽上限` / `换脸脸宽上限`（默认 120，原图像素口径，不乘倍数） |
| 分块 | 124 的 `分块边长`（0 = 自动）与 `分块重叠`（64） |
| 分段长度 | 脚本按帧数上限自动算；手动改 108 的 `平均分段时长` 时同步确认单段帧数 ≤ 400 |
