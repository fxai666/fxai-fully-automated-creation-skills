# 01 · 工作流与参数

> **何时读**：要把一整条视频超分、走本机 ComfyUI 时；要改节点参数、查占位符、查产物从哪取时。

链路：**源视频 → 分段 → RelayVSR x2（原生节点，固定 2 倍）→ 逐段保存 → 合并成片**。

跑的是 `fxai-workflow/upscale-relayvsr.json`（占位符版），注册表任务名 `upscale`、模型 slug `relay`。入口脚本 `scripts/video_upscale.py`。

🔴 **2026-11-28 用户定**：与发布版工作流 `视频超分RelayVSR.json` 对齐，**链上没有人脸精修**（旧 `123 人脸精修` + `104 参考图选择器` 与 `fxai_imageinput` 占位符全部摘掉），倍率固定 2 倍。

## 一、节点结构（15 个节点）

```
108 视频分段器 ──┬─→ 111 生成控制器（宽度/高度、结束索引）
                 ├─→ 113 视频分段加载 ──┬─→ 132 RelayVSR 条件 ──→ 133 KSampler(1step) ──┐
                 │                      └─→ 134 VSR 解码 ←──────────────────────────────┘
                 │                              ↑ 131 Flash VAE x2      ↑ 130 UNET x2
                 │                              134 ──→ 5 保存成片
                 └─→ 114 视频合并（音频取 108 的音频输出）
109 / 110 / 117 循环（计数，逐段推进）
114 视频合并 ──┬─→ 126 自动关机（默认不触发）
              └─→ 127 清理显存（跑完卸模型）
```

- **130 UNETLoader**：`relayvsr_x2_lightx2v_int8_convrot.safetensors`（int8 repack，5.16 GB），`weight_dtype = default`。
- **131 VAELoader**：`relayvsr_flash_vae_x2_fp32.safetensors`。**x2 权重必须配 x2 VAE**，别的 VAE 不兼容。
- **132 RelayVSRConditioning**：`images` 与 `134.images` 是**同一份原分辨率低清帧**，都接 113 的「视频帧」；每 15 帧取一个关键帧。
- **133 KSampler**：固定 `1 step / cfg 1 / euler / simple / denoise 1`，`seed` 走 `fxai_seed`。加步数只会更慢，不会更清楚。
- **134 VSRDecode**：`detail = 1`（源片噪点大时可降到 0.6~0.8），把关键帧之间的中间帧补回来，输出帧数 == 输入帧数。
- **127 清理显存**接 110 的循环结束输出，保证卸载排在整条循环之后。

⚠️ RelayVSR 原生节点要 **ComfyUI ≥ v0.45.0**（本机 0.46.0 已验证）。

## 二、占位符（提交时注入）

| 占位符 | 落在哪个输入 | 传什么 |
|---|---|---|
| `fxai_videoinput` | 108 · 视频文件 | 源视频路径，**服务端可读的绝对路径**（相对路径按服务端根目录解析，报「找不到视频文件」） |
| `fxai_outputdir` | 5 · 保存目录 | 服务端保存子目录，默认 `upscale` |
| `fxai_seed` | 133 · seed | 默认 42；RelayVSR 是一步采样，种子影响很小 |
| `fxai_width` / `fxai_height` | 111 · 宽度 / 高度 | **跟源视频一致**（占位符默认 960×544，竖屏素材会被拉横）；节点最小 360，小于会被校验拒 |
| `fxai_duration` | 108 · 平均分段时长 | 脚本按「帧数 × 输出百万像素 ≤ 240」算；FLOAT，裸插数字 |
| `fxai_average_segment` | 108 · 是否平均分段 | 固定 `true` |
| `fxai_skip_initial` | 108 · 跳过初始段 | 固定 `true` |
| `fxai_include_tail` | 108 · 包含尾部段 | 固定 `false` |
| `fxai_segment_data` | 108 · 关键帧JSON | 固定 `"[]"` |
| `fxai_start_index` | 111 · 开始索引 | 固定 `0` |
| `fxai_end_index` | 111 · 结束索引 | **固定 `-1`**（＝跑完全部段）。传 `0` 只跑第一段 |
| `fxai_auto_shutdown` | 111 · 自动关机 | 默认 `false`；云端跑完想省机时费才 `--auto-shutdown` |

**没有倍数占位符**：倍率写在权重里，固定 2 倍。

## 三、分段口径

- 预算：**单段「帧数 × 输出百万像素」≤ 240**（16G 卡）。锚点是 11-12 实测——3648×2112（7.7 Mpx）每段 30 帧跑完不 OOM。
- 换算：8.3 Mpx（1080p 源 2×）约 28 帧/段；3.9 Mpx（720p 源 2×）约 61 帧/段；0.98 Mpx（480p 源 2×）约 240 帧/段，再被 10 秒上限截住。
- `VSRDecode` 一次解整段 `lq_images`，所以显存随**每段帧数**线性涨——切碎一点只多几次装载，不会更慢太多。
- 段与段之间硬拼（无交叉淡化），段越多边界越可能看到跳变。
- 每段单独跑一次超分，**耗时随片长线性增长**，不是一次推理跑完整片。

## 四、产物归属与取回

**交付物只认合并后的整片**（114 产出，落在服务端 `fxai/video/merged/`）。分段保存节点 5 写的是过程文件，多段任务下只是其中一段，不得当交付物。

下载令牌形如 `video/merged|fxai_<时间戳>.mp4`，由公共层 `submit_workflow` 按顺序取：`fxai:task_saved` 广播 → `/fxai/tasks/result` → `/history` 的 `outputs`。本链路末端是保存与合并节点，令牌走广播那条。

脚本落点默认 `<源文件名>_up2x.mp4`，下载后校验 MP4 `ftyp` 与体积，并核对成片时长 ≥ 源片 95%（不到即判「只拿到部分段」）。

## 五、改参数

| 要改什么 | 改哪里 |
|---|---|
| 倍率 | **改不了**，权重决定 2 倍；要别的倍率先改源片尺寸 |
| 解码细节 | 134 的 `detail`（1 = 全补；噪点大的源片降到 0.6~0.8） |
| 分段长度 | 脚本按显存预算自动算；手动改 108 的 `平均分段时长` 时同步确认单段帧数 × 输出 Mpx ≤ 240 |
| 修脸 / 换脸 | **不在本链**，跑完超分再走 `fxai-face-edit`（顺序永远是「先超分、后精修」） |
