# 视频超分

一条命令跑完：**源视频 → 分段 → RelayVSR x2 超分 → 合并成片**。
跑本机 ComfyUI（不计费），提交与下载全走公共层 `comfy_client`，工作流 `fxai-workflow/upscale-relayvsr.json`，任务名 `upscale`。

🔴 **2026-11-28 用户定**：链路换成 RelayVSR x2 原生节点（与发布版工作流一致），**只放大、不碰人脸**——人脸精修节点已摘掉，不传参考图；**倍率固定 2 倍**（由权重决定，没有倍数参数）。

## 直接开跑（最常用）

```bash
U=~/.workbuddy/skills/fxai-video-upscale/scripts/video_upscale.py

python "$U" 源视频.mp4 --out-dir .            # 固定 2×，返回成片路径
python "$U" 源视频.mp4 --out-dir . --dry-run  # 只打印注入参数，不提交
python "$U" 源视频.mp4 --width 1080 --height 1920  # ffprobe 读不到尺寸时才用
```

脚本自己 ffprobe 源尺寸与帧率，按「单段帧数 × 输出百万像素 ≤ 240」算分段，打印输出尺寸、段数与整片预估分钟数，
跑完校验 MP4 完整性、成片时长，并抽验成片尺寸是否为源片的 2 倍，返回本机成片绝对路径。
成片默认命名 `<源文件名>_up2x.mp4`，落在 `--out-dir`。

## 铁律速查（常驻）

1. 🔴 **交付物只认合并后的整片**（合并节点产出）；分段保存节点写的是过程文件，多段任务下只是其中一段。
2. 🔴 **倍率固定 2 倍**：由 `relayvsr_x2_lightx2v_int8_convrot` 权重决定，没有「放大倍数」参数；用户要 1.5× / 4× 就说明做不到，只能 2×（要别的倍率先降源片尺寸再跑）。
3. 🔴 **链路只有超分**：工作流里没有精修 / 换脸节点，也别自己加回去；要修脸换脸另跑 `fxai-face-edit`（顺序永远是「先超分、再精修」）。
4. 🔴 **源视频传服务端可读的绝对路径**，宽高必须跟源视频一致（占位符默认 960×544 会把竖屏拉横；节点宽高最小 360）。
5. 🔴 **单段预算「帧数 × 输出百万像素 ≤ 240」**（16G 卡）：4K 级（7.7 Mpx）约 30 帧/段，1080p 源（8.3 Mpx）约 28 帧/段，720p 源（3.9 Mpx）约 61 帧/段。脚本自动算，别手动放大。
6. 🔴 **开工先报时间**：耗时 ≈ 帧数 ×（0.05 × 输出百万像素）秒，首个任务再加 15~20 秒装模型；随片长线性增长，把预估分钟数说清楚再提交。
7. 🔴 **只按地址发 HTTP，启停权在人**：8188 探不通就提示用「凤希本地AI控制台」启动，不由 AI 自己起服务。
8. 🔴 **产物只落当前工作区**，交付前抽帧验几何（成片尺寸 == 源 × 2）、帧数（等于源片）、接缝（放大后整帧看）。
9. 🔴 **这是生成式重绘，不是锐化**：真实纹理能补出来，金属高光 / 磨砂条纹 / 浅景深背景会被改写；交片时说明是重绘细节，不承诺「原片修复」。
