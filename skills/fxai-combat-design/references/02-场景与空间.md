# 02 · 场景与空间

> 何时读：要定场景、设计空间锚点与人物路线时。

## 一、先判断用户有没有给「可执行场景」

- **可执行场景**：至少含明确地点或空间类型（如「雨夜窄巷」「云海浮岛」「废弃船坞」）。
- **不算场景**：只有题材（古代 / 赛博朋克 / 仙侠）——这类要往下补成具体空间。

**用户已有场景**：尊重，直接进入动作方案阶段，用户的场景原样保留，资料只用来补细节。
**没有场景**：检索 `scenes`，取排名第一的主场景；混合题材确有必要时最多再读一个辅助场景。

## 二、从场景资料里提取什么

拿到场景正文后，提取四件东西，再重新设计成适配当前剧情的空间（不照搬无关角色与情节）：

| 要素 | 作用 |
|---|---|
| **空间锚点** | 3 个彼此可区分、不会移动的位置，用于全片换位与镜头定位 |
| **路线限制** | 哪些地方走不通、哪里只容一人、哪里有高差或打滑 |
| **可交互物** | 能被踢、拉、砸、踩、炸的环境物，做受力反馈与地形改写 |
| **材质与光色** | 决定反馈质感（水花/火星/尘/雪）与画面色调 |

## 三、设计空间的三条准则

1. **锚点要能用方位词说清**：左/中/右，或前景/中景/后景。方位词说不清的位置只做描述，不登记为锚点。
2. **路线限制制造博弈**：窄口、断口、只容一人的回廊——这些是攻守易手的天然节点。
3. **环境是主动参与者**：好的场景会在关键时刻改变战局（立柱可蹬、雨棚可塌、楼板可穿），而不是纯背景。

## 四、零命中怎么办

明确写「**场景资料无关键词命中，将进行原创场景设计**」，再按人物能力、战斗方式与情绪设计一个**最小充分场景**：够用的锚点 + 一条限制 + 两个可交互物 + 一组光色即可，不必堆细节。

## 五、空间描述模板（可直接用）

```
【空间锚点】左…、中…、右…
【路线限制】…（哪里只能一人过 / 哪里是断口 / 哪里打滑）
【可交互物】…（踢得动的、砸得碎的、踩得塌的）
【材质与光色】…（主色 + 唯一强调色 + 光源方向）
【调度提示】…（这一场戏最该被利用的环境机制）
```

## 六、常见误用

- ❌ 把「古代」「仙侠」当场景直接开打（空间不明确，分镜必散）。
- ❌ 锚点选成会移动的东西（如「一辆行驶的车」当固定锚点）。
- ❌ 场景光色写了四五种（超过两色主调，画面会脏）。
