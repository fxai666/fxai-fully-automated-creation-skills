# 06 · 交付与验收

> 何时读：成稿前自检、确认连续性、准备交付时。

## 一、交付结构（用户未指定格式时）

1. **采用依据**：已确认方案、场景参考、招式来源、案例参考、原创部分。
2. **剧情设计**：目标、冲突、升级、转折、胜负因果、结尾。
3. **角色动作签名**：起手、距离、移动、主战、破招、受击、终结。
4. **动作设计**：动作目的 → 起势/轨迹 → 对手响应 → 接触/落空/格挡 → 受力反馈 → 位移/状态结果 → 下一动作条件。
5. **空间路线**：起点、转向点、终点、环境机制、观察轴。
6. **分镜表**：`时间段｜叙事目的｜景别与机位｜人物位置｜动作与攻防｜主运镜及终点｜接力状态｜环境反馈`。
7. **连续性约束**：见下节。

## 二、连续性约束（逐条自检）

- 角色与武器状态**稳定**（同一段里始终同一把兵器、单双手一致）。
- **无身体融合**（两人接触时肢体不得穿模或粘连）。
- **无回合制复位**（每次交锋后位移继续累积，交手完接着走，下一拍从上一拍的位置起）。
- **无随机越轴**（观察轴不无故跳到对面）。
- **特效不遮挡关键接触**（火花、光效不得盖住兵器相交点）。

## 三、成稿验收清单（全过才算合格）

- [ ] 开场快速进入有效动作，无热身/对视/摆 pose。
- [ ] 每个重要动作有因果与结果。
- [ ] 上一段末态是下一段起点（接力状态已写）。
- [ ] 一打多不排队，敌群有主动补位/变向。
- [ ] 终结来自前文破绽，不靠突然变强。
- [ ] 最后一帧仍有余波运动。
- [ ] 招式/技能过了对应门禁，且已写清身体路径与接触反馈。
- [ ] 已说明用了哪些资料、哪些是原创。
- [ ] 全程**没有写入任何提示词/生成参数/负面词/字幕声音指令**。
- [ ] **没有引用任何图片/动图样本**。

## 三之二 · 能力边界（每条对应一个正确动作）

| 边界 | 正确做法 |
|---|---|
| **提示词归属上层** | 任何模型/平台的提示词、生成参数、负面词、字幕声音指令都由上层技能写；本技能只出设计与分镜 |
| **锁定事实原样保留** | 人物、武器、动作顺序、胜负一旦用户给定，全部保持原样，资料只用来补细节 |
| **零命中如实回报** | 如实回「无命中」（`weak_fallback=true` 一并说明），招式名只取库里真实存在的条目 |
| **方案一次一个** | 展示推荐 + 备选后等用户确认，确认后再读该方案正文 |
| **招式写全链条** | 招式名 + 身体路径 + 接触 + 受力反馈 + 后续条件，缺一项不算写完 |
| **术语不当模板** | `glossary` 术语一段 2–4 个词嵌进动作描述，整段贴出或堆砌会让动作互相打架 |
| **案例只借机制** | 借可迁移的剧情机制，角色/场景/台词自己写，并在交付里告知用了案例参考 |
| **招式库优先** | 招式库已有或可收录的内容走招式库，技能库只补招式表达不了的独立机制 |
| **技能条件先匹配** | 二级条件（法器/部位/介质/状态）先匹配再采用，选中后把条件一并提示给用户 |
| **引用真实条目** | 条目以 `data/<域>.json` 为准，缺失内容按原创处理，不按文件名伪造 |
| **样本只走文字** | 交付只引用文字资料，图片/动图既不查找也不承诺推送 |
| **资料吸收是另一条流程** | 外部资料整理入库走独立流程，本技能只做设计 |

## 四、资料库自检（改过 JSON 后必跑）

```bash
PY="python -X utf8"
$PY "<技能目录>/scripts/combat_route.py" --validate
```

校验项：文件齐全、编号唯一、名称与关键词非空、正文非空、无占位符（TODO/待补/占位/xxx）。
不通过会列出问题条目并以非零码退出。

## 五、维护资料库

- 增删条目：直接编辑 `data/<域>.json` 的 `entries` 数组。
- 改检索词：改对应条目的 `keywords`（强词）或 `weak_keywords`（弱词）。
- 改完必跑 `--validate`，再抽查一次 `--query` 确认排序符合预期。
- 弱词（单字/高频词）放 `weak_keywords`，`keywords` 只放有区分度的强词，两处分开才不会污染召回。
