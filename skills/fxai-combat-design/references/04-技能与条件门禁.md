# 04 · 技能与条件门禁

> 何时读：角色需要**独立能力机制**，且招式库的身体路径/兵器技法/连续招式表达不了这套机制时。

## 一、先招式、后技能（顺序铁律）

**先完成招式库检索与合理性判断**。招式库已有、或可由现有招式表达的内容，**不得**改从技能库重复取用。
技能库只补「招式库表达不了的能力机制」。

## 二、技能检索（skills）：只按范围词召回

1. 根据能力作用目标，**只提炼一个范围词**：`单体` / `群体` / `buff`。
2. 用该范围词检索 `skills`。
3. **不得**把特殊法器、身体部位、介质、状态或发动动作加入检索查询。
4. 技能检索只做**宽松候选召回**：`primary` 不作数，也不因编号靠前就自动选中，**必须让用户选**。

## 三、条件门禁（选中后必须过）

选中某技能后，必须先展示并确认它的 `conditions`：

| 字段 | 含义 |
|---|---|
| `secondary_keywords` | 二级前置：需要的法器、身体部位、介质、状态或控制接口 |
| `condition_prompt` | 发动前**必须满足**的条件 |
| `condition_options` | 可创造条件 / 可行替代 / 放弃三选项 |
| `move_exclusions` | 与招式库的互斥边界 |

**处置规则**：
- 二级条件**已满足** → 才读技能正文并应用。
- 二级条件**未满足** → 让用户或智能体明确选择：**创造合理条件 / 采用允许的替代 / 不采纳该技能**。
- **不得静默补设**关键法器、身体结构、血契、介质或科技装备。

## 四、技能只补机制，动作仍归招式库

技能只补充「**前置 → 发动 → 作用 → 终止**」的能力机制。
具体的起势、身体路径、兵器接触、受力反馈与动作衔接，**仍从招式库获取或按同等完整度原创**。

## 五、全部不兼容怎么办

所有候选的条件都不兼容时，**放弃技能库**，不为使用资料而修改用户锁定事实。

## 六、技能的字段结构（读正文时重点看）

`data/skills.json` 每条技能：
- `keywords`：**只放范围词**（单体/群体/buff）；
- `conditions`：见上表；
- `body`：能力机制（前置→发动→作用→终止）、适用边界、招式库互斥。

## 七、常见误用

- ❌ 用「血祭」「尾巴」「灵环」这类二级词去检索技能（应只用范围词）。
- ❌ 选中技能后不提示条件就直接采用。
- ❌ 招式库能做的事，硬拆成技能库来写。
