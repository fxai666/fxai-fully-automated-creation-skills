# 01 · 创作卡与检索

> 何时读：**每次开工先读这册**。它决定后面查哪些资料、怎么查。

## 一、提炼创作卡（静默完成，不让用户填表）

从用户自然语言里提炼三块，缺的才追问：

### 1. 锁定事实（最高优先级，不得改）
人物、敌我关系、武器、能力、必备动作、动作顺序、胜负、对白、时长、画幅、媒介、结尾。

### 2. 设计关键词（用来检索）
题材、时代、场所、对战规模、战斗方式、武学/兵器、动作密度、写实程度、空间机制、镜头诉求、情绪、结局。

媒介只归一为三档：**真人写实 / 3D CG / 动漫漫画风**；用户没说就不加，**不把武侠、仙侠或高频出招当媒介**。

### 3. 缺口（只列会影响路线选择的）
只有会影响「选哪套方案 / 成稿可不可靠」的必要信息才追问。时长和画幅缺失且不影响设计时，可采用资料默认值并在交付里声明。

## 一之二 · 创作流程（八步）

```
0. 提炼创作卡   → 静默提取「锁定事实 + 设计关键词 + 缺口」，不让用户填表
1. 场景抽取     → 用户已有场景就尊重；没有才检索 scenes
2. 动作方案     → 检索 designs，给「推荐 + 备选 + 选择项」，必须等确认
3A. 招式检索    → 检索 moves，过合理性门禁
3A+. 术语取词   → 用 moves 的 terms 或 `--terms` 落到专业词汇（见 08 册）
3B. 技能检索    → 先招式后技能，按 单体/群体/buff 召回，过条件门禁
4. 剧情设计     → 检索 scripts，声明后仿结构
5. 编译成稿     → 采用依据 / 剧情 / 动作签名 / 动作设计 / 空间路线 / 分镜表 / 连续性约束
```

各步的展开写法与门禁细则见 02–06 册。

## 二、检索命令

```bash
PY="python -X utf8"
SK="<技能目录>"

# 语法：combat_route.py <域> --query "用户原文与提炼关键词"
$PY "$SK/scripts/combat_route.py" scenes  --query "..."
$PY "$SK/scripts/combat_route.py" designs --query "..."
$PY "$SK/scripts/combat_route.py" moves   --query "..."
$PY "$SK/scripts/combat_route.py" skills  --query "单体|群体|buff"
$PY "$SK/scripts/combat_route.py" scripts --query "..."
```

**一次把用户原文和提炼词一起塞进 `--query`**，命中越多排序越靠前。

## 三、结果怎么读

检索返回 JSON，字段含义：

| 字段 | 含义 |
|---|---|
| `weak_fallback` | `false` = 有强关键词命中；`true` = 全库无强命中，只能用弱词回退（结果可靠性低） |
| `primary` | 排名第一的候选（`null` = 零命中） |
| `eligible` | 全部命中候选，按分数排序 |
| `available` | 该域全部条目（用于列「其他可选方案」） |

单条候选里：`hit_count` 命中数、`matched_keywords` 命中了哪些词、`score` 综合分、`name_hit` 名字是否被直接点到。

## 三之二 · 六域资料库（字段与维护）

| 域（命令参数） | 显示名 | 条数 | 作用 |
|---|---|---|---|
| `scenes` | 场景库 | 10 | 空间锚点、路线限制、可交互物、材质光色 |
| `designs` | 动作方案库 | 10 | 整套「导演方案」：节奏、镜头、结构、时长 |
| `moves` | 招式库 | 13 | 具体武学/兵器的身体路径与接触链 |
| `skills` | 技能库 | 12 | 独立能力机制（单体 / 群体 / buff） |
| `scripts` | 案例库 | 8 | 镜头级案例，供「仿结构」参考 |
| `glossary` | 招式术语字典 | 138 | 单动作词表（16 类），带频次与档位，命中招式后取词用 |

资料**全部是明文 JSON**（`data/<域>.json`），每条含 `id / name / summary / keywords / weak_keywords / medium / avoid_when / body`；招式另有 `binding` 与 `terms`（推荐术语），技能另有 `conditions`，术语另有 `category / freq / tier / pinyin / en`。增删条目、改检索词直接编辑 JSON，改完跑 `--validate`，再抽查一次 `--query` 确认排序符合预期。强词放 `keywords`、弱词放 `weak_keywords`，两处分开才不会污染召回。

## 四、命中规则（务必理解，防止误判）

- **强关键词**：有区分度的词（如「窄巷」「剑气」「一打多」），单独命中即可构成候选。
- **弱关键词**：单字词（刀、剑）与高频通用词（连招、清场、战场、打斗），**不单独构成命中**；只有全库都没有强命中时才回退使用，此时 `weak_fallback=true`。
- **媒介标签**：只作筛选，不计入命中分。
- **零命中**：`primary` 为 `null` 且 `eligible` 为空——此时**必须明说「无关键词命中，将原创设计」**，匹配状态按实际结果如实报。

## 五、读正文

```bash
# scope 取检索结果顶层的 domain，id 取候选的 id
$PY "$SK/scripts/combat_route.py" --read moves/01
$PY "$SK/scripts/combat_route.py" --read designs/04
```

也可以直接读 `data/<域>.json` 里对应条目的 `body` 字段——两者内容一致，明文可查。

## 五之二 · 全量入口命令速查

```bash
PY="python -X utf8"   # Windows 中文环境建议加 -X utf8

# 检索（返回 JSON：primary / eligible / available / weak_fallback）
$PY "<技能目录>/scripts/combat_route.py" scenes  --query "雨夜 窄巷 双人 拼刀"
$PY "<技能目录>/scripts/combat_route.py" designs --query "一打多 清群"
$PY "<技能目录>/scripts/combat_route.py" moves   --query "单手长剑 剑气 外放"
$PY "<技能目录>/scripts/combat_route.py" skills  --query "群体"        # 只用 单体/群体/buff
$PY "<技能目录>/scripts/combat_route.py" scripts --query "雨夜 刀剑 错身"
$PY "<技能目录>/scripts/combat_route.py" glossary --query "腿法"        # 术语字典也走通用检索

# 读正文（scope 取检索结果的 domain，id 取候选 id）；读招式会自动带出推荐术语
$PY "<技能目录>/scripts/combat_route.py" --read moves/01

# 术语取词（glossary）
$PY "<技能目录>/scripts/combat_route.py" --terms                 # 列全部 16 类
$PY "<技能目录>/scripts/combat_route.py" --terms sword           # 列某类全部术语
$PY "<技能目录>/scripts/combat_route.py" --terms guard_footwork --tier high   # 只看高频
$PY "<技能目录>/scripts/combat_route.py" --terms "缠头"          # 按关键词模糊查

# 维护
$PY "<技能目录>/scripts/combat_route.py" --list scenes     # 列出某域条目
$PY "<技能目录>/scripts/combat_route.py" --validate        # 自检（编号唯一/正文非空/无占位符/类别已登记）
$PY "<技能目录>/scripts/combat_route.py" --about           # 技能信息
```

## 六、常见误用

- ❌ 把 `available` 里没命中的条目当命中结果读。
- ❌ 命中为零时直接套用某套通用方案（通用方案只有自己也命中关键词时才能自动推荐）。
- ❌ 用 `skills` 检索时把「法器/部位/介质」塞进查询（技能只按 单体/群体/buff 召回）。
- ❌ 预读五个域全部正文再挑——先路由、后读正文。
