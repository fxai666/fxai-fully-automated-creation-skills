# 03 · 动作方案与招式门禁

> 何时读：要选动作方案、检索招式、过合理性门禁时。

## 一、动作方案（designs）：怎么选、怎么确认

1. 用**用户原文 + 创作卡关键词 + 场景摘要**检索 `designs`。
2. 有命中时，向用户展示：
   - **推荐方案**：名称、命中词、推荐原因；
   - **其他方案**：从 `available` 列其名称与定位；
   - **选择项**：采用推荐 / 改用其他 / 用户自定义。
3. **必须等用户确认。确认前不读任何方案正文。**
4. 确认后**只读所选方案正文**，编译成当前项目的动作因果、空间路线、镜头结构与连续性约束——不照抄与当前剧情冲突的默认角色、镜头数、时长或结尾。
5. 零命中时给两项：**用户输入设计方案** / **智能体原创方案**。不得把某套通用方案当无条件回退（除非它也命中关键词）。

## 二、招式检索（moves）：只在需要时做

**仅当**用户要求具体招式、武学绑定、逐招拆解、兵器技法，或动作链需要专业技法支撑时执行：

1. 用**角色、身体条件、武器、主战距离、环境、对手、目标**检索 `moves`。
2. 只读有关键词命中的候选，通常 1 个主条目，必要时最多 2 个互补条目。

## 三、合理性门禁（逐条检查，不过就弃用）

对每个候选招式检查：

| 检查项 | 判据 |
|---|---|
| **角色能否使用** | 角色是否掌握或能合理使用该技法 |
| **武器/身体兼容** | 武器形制、肢体条件与主战距离是否匹配 |
| **姿态衔接** | 当前姿态能否进入，上一动作末态能否接上 |
| **场景支撑** | 场景是否提供所需空间、支点与落点 |
| **时长够不够** | 在目标时长内能否完成起势 → 接触 → 反馈 → 结果 |
| **不破坏锁定事实** | 是否破坏用户锁定的动作顺序、胜负或写实程度 |

**门禁不通过的处置**：弃用该招式，**不为命中资料强改剧情**；全部候选都不合理时，按**同等生物力学完整度原创**招式。

写实题材偏重可执行的身体路径与清晰接触；3D CG / 动漫漫画风可在能力与空间规则许可时采用高动态，但**媒介不自动授权无因乱出招**。

## 四、招式描述必须写全（缺一不可）

```
动作目的 → 起势/轨迹 → 对手响应 → 接触/落空/格挡 → 受力反馈 → 位移/状态结果 → 下一动作条件
```

只写招式名、不写身体路径与接触反馈的，一律判不合格。

## 五、招式的结构化绑定（读正文时重点看）

`data/moves.json` 每条招式带 `binding`：
`weapon`（武器绑定）、`capability`（能力前提）、`range`（主战距离）、`role`（战斗职责）、`forbidden`（禁用绑定）。
外加顶层 `avoid_when`（不适用条件）。**武器名字不改变绑定**，只有用户明确指定命名武器时才在角色卡保留名称。

## 六、常见误用

- ❌ 用户已确认方案 A，却顺手把方案 B 的镜头协议拼进来。
- ❌ 招式命中就硬用，无视「场景没支点」「时长不够」。
- ❌ 角色没剑却套用剑气招式（先看 `binding.forbidden` 与 `avoid_when`）。
