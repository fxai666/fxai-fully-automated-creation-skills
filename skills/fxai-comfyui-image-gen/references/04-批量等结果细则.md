# 批量生图两种等法与「界面没动静」判据

**何时读**：一次出多张图时查两种等法怎么选、以及看着没动静怎么判断时

单张 `generate_image()` 是**同步阻塞**的，调用方不用管等——但**一次生成多张时**（文章配图、
素材批产）有两种等法，**必须选后者**：

- ❌ **多张串成前台脚本干等**：批量出图每张要1~3 分钟，串行阻塞十几分钟，
  对话界面毫无进展，看着像卡死。
- ✅ **一次后台任务跑完全部图片**（一个脚本里顺序调N 次，每张 `try/except` 包住、
  失败打印 `FAIL` 继续下一张、全部跑完打印每张路径与成败），**用后台 Bash 提交，
  然后去干别的**。任务完成会**自动推 `<task-notification>`**，这是唯一正确的结果获取路径。
- 完整纪律见 `fxai-common`/SKILL.md「等任务纪律」。

## 「界面没动静」≠「任务卡住」

先分清三种情况再决定动作（「再等久一点」会掩盖判断缺失）：①任务本身慢（生图确实要几分钟）
→ 等通知；②自己阻塞在等待调用上 → 退出等待去干别的；③ id 传错/ 任务压根没起来 → 核对启动日志。

### 🔴 批量生图（一次出多张）怎么等

- 🔴 **收到「仍在运行 / 你会被自动通知 / do NOT poll」这类提示后，立刻停止查询。**
  `TaskOutput(block=true, timeout=600000)` 是**制造「卡死」的标准姿势**：十分钟零产出，
  还会吞掉本该即时到达的完成通知。`block=true` 只在预计剩余 ≤60 秒时用。
- **task_id 三态**：本机后台 Bash 用命令回显里的 **shell id**（形如 `iTJj7I`）；
  **子代理 id（`xxx@_auto_xxx`）不是 shell id**，喂给 `TaskOutput` 报 `No task found`。
  子代理要结果等 `<task-notification>`。
- **同一后台任务最多连查 1 次**；要看进度用 `progress.html` 面板（零token），反复轮询只会空耗。
