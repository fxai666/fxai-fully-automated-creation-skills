# 音频分段精确公式、入参与参数表

**何时读**：算分段数、备场景图数量、按段写提示词时

**一条音频内部会被 H3 自动切成多段**，所以「一条长音频」≠「一条视频」。要写几条逐段提示词、
备几张场景图，先算分段数：

```python
secs, bounds = av.h3_segments(120.0)   # → 13 段，每段 9.41667 s，bounds = [(0,9.42), (9.42,18.83), …]
n         = av.h3_segment_count(120.0) # → 13（最常用）
dur       = av.audio_duration("口播.wav")  # ffprobe 探测，先拿时长再算分段
```

H3 只接受满足「**17k+5 帧**」的时长（24fps）。工作流传「平均分段时长 = 10」时，
节点先**向下对齐**：`align_down(240) = 17*((240-5)//17)+5 = 226 帧 → 226/24 = 9.41667 s`
—— 这就是「传 10 秒、实际 9.4 秒多点」。尾段不足阈值（avg≤10 → 3s，>10 → 5s）会并回上一段。

**⚠️ 段数一律用 `av.h3_segment_count()` 算**——`ceil(时长/10)` 估算经常差 1 段（120s：公式 13 段，`ceil` 给 12），
会让场景数、时间窗、逐段提示词对位全错。

- `h3_align_down(frames)` / `h3_align_up(frames)`：17k+5 网格的向下 / 向上对齐。
- `h3_segments(duration, avg_seg=10.0)` → `(每段秒数, 每段 (start,end) 边界)`。
- `h3_segment_count(duration, avg_seg=10.0)` → 段数。
- `h3_actual_seconds(req_sec)` → 「请求 N 秒」实际生成多少秒（向上对齐）。
  **只用于事后按时间点定位第几镜**；回传给工作流的是 `h3_segments` 的段数与边界。

`gen_video` 的音频参数两种都认：本地文件自动经 `POST /fxai/audio/upload` 传上去；
已是服务端相对路径（形如 `音乐生成/051_audio.wav`）原样使用。

## 参数

`gen_video(mode, aud_rel, char_rel, scene_ref, size, tag, timeout, char_desc, scene_desc,
ref2va_prompts, seg_prompts, char_descs, subdir, prompt_out, start_index, end_index,
model, kind, prefix, audio_subdir, out_dir)`

- `kind`：`"sing"` | `"speak"`，只改提示词措辞。
- `prefix`：子目录与任务标签前缀（MV=`mv`、数字人=`dh`），决定服务端归档目录。
- `start_index=end_index=同一值`：multiref 只重渲该段（索引 0 起）。
- `prompt_out`：把实际提交的 `fxai_prompt` 存档落盘。
- 返回 `(本地路径, 服务端相对路径)`。

## 🔴 多镜控制器：跑法与服务端自动合并

工作流含「开始索引 / 结束索引」节点，按场景二选一：整片重做 `start_index=0` /
`end_index=-1` 一次提交跑完；某一镜返修 `start_index=end_index=N`（N 为 0 起索引）。
每次提交都要重跑前置，逐镜循环提交会按镜数成倍重跑。

服务端把「本次新段 + 已缓存的其他段」合并成一条完整视频返回，本地取到的即全长成片，
直接进烧字幕 / 后续环节。

- 服务端逐段产物：`<ComfyUI>/fxai/video/<prefix>_multiref/<序号>.mp4`（`000.mp4` 起，0 起编号）。
- 服务端合并产物：`fxai/video/merged/fxai_<时间戳>.mp4`，每次提交出一条完整成片。
- 服务端按项目缓存各段，同一时刻只有一个项目，重渲单段不影响其他段。
- **判据**：返回的成片时长 = 全长。时长等于单段说明走的是单段下载路径。

`gen_videos(auds, mode, name, out_dir, skip_existing=True, **kw)`：逐段串行提交，
产物 `<name>_01.mp4`…；`skip_existing` 默认跳过已有段，不重烧。

## 🔴 视频流必 ≥ 音频流（H3 生成 · 合成阶段强制补齐）

H3 帧数按 17k+5 网格向下对齐，**每段视频流必短于该段音频流**（0.03~0.19 s / 段，
累计可达 0.9 s 以上）。根因在生成阶段、无法改变；**合成阶段必须逐段补齐**。

1. 逐段取流时长判定（容器 `duration` 取 max(video, audio)，判定一律用流时长）：
   ```
   ffprobe -v error -select_streams v -show_entries stream=duration -of default=nw=1:nk=1 <mp4>
   ffprobe -v error -select_streams a -show_entries stream=duration -of default=nw=1:nk=1 <mp4>
   ```
2. 视频流 < 音频流的段，冻尾帧补足到 `音频 + 0.05s` 后进入 concat：
   ```
   ffmpeg -i seg.mp4 -vf "tpad=stop_mode=clone:stop_duration=<补足秒>" \
          -c:v libx264 -preset veryfast -crf 18 -c:a copy seg_pad.mp4
   ```
3. 验收判据：拼接后 `视频流时长 ≥ 音频流时长`，差 < 1 帧。
4. 同类触发条件：`-shortest` 提前截断；concat `-c copy` 后报 `Non-monotonic DTS`
   （改重编音频再拼）。
