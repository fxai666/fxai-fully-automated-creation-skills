# 分段与时长（算时长、判段位、决定重渲哪一镜时读）

## 生成速度经验
- **16G 显存显卡（如 RTX 5060 Ti）≈ 1 秒视频 / 1 分钟生成**。
- 总时长 N 秒 ≈ 预计 N 分钟。`estimate_minutes(N)` 直接返回 N。提交后按此估算等待，超时默认 90 分钟。
- 例：本集 7 镜头共 47 秒 → 约 47 分钟。多卡/更大显存会更快，按比例调整。

## H3 实际分段时间算法（fxai_screen_load.py · 仅用于后期验证/段定位）

MiniMax H3 **视频流**真正算每镜头帧数的公式在 ComfyUI 服务端插件 `fxai-toolkit` 的 `FxAiScreenLoad.get_scene_data`（fxai-toolkit 节点内，约第 74–75 行；安装位置随 ComfyUI 部署走，不写死）：

```python
x = max(5, round(时长 * 24)) # 秒→帧，24fps，最少 5 帧
frame = x + (5 - x) % 17 # 向上取整到最近的 17k+5 帧
```

即合法帧数 = `17*k + 5`（k≥0），**向上取整（ceil）**——与音频分段节点 `fxai_audio_segments_v2.py` 的 `align_down_h3`（向下取整）**方向相反，别混**。

向上多取那几百毫秒（最多 ~0.7s/镜）是设计目标（用户定），成片比请求时长略长属于正常。可复用函数：

```python
def h3_actual_seconds(req_sec, fps=24):
 """请求 req_sec 秒 → H3 实际生成秒数（向上对齐 17k+5 @24fps）。"""
 x = max(5, round(req_sec * fps))
 frame = x + (5 - x) % 17
 return frame / fps
```

**用途边界（用户定，重要）**：
- ❌ **不**改我们传给工作流的 `duration`（仍按提示词时间轴原样传，如 7/6/6/7/7/7/6/7/6/8）。
- ❌ **不**用来卡验收（验收用 ffprobe 核对时长）。
- ✅ **只**用于在**后期验证 / 判定某镜头是否重生成**时，精确算出"每一段实际落在成片的哪几秒 → 对应第几镜"。比抽帧猜段更准、更稳（抽帧本环境也做不了）。

**段定位用法**：把每镜 `h3_actual_seconds(d)` 逐级累加得 `[起,止)` 区间；成片里时间点 T 落在哪个区间，就对应第几镜，即可 `single_shot=N` 只重那一段，不盲猜。验收脚本里可调用 `build_seg_map(shots)` 打印/写出此表供参考（不用于 pass/fail 判定）。
