# 项目档案存储约定（建新项目/配资源/换服务器时读）

短剧技能是**可分享整合包**：任何人在任何项目空间安装后即可复用，技能内**不写死本项目/本机路径**（见「分享友好原则」）。所有产物按「项目档案」归档，资源在「ComfyUI 服务端生成 → HTTP 下载 → 本地备份 → 按需回传服务端」的闭环里流转。新空间只复制技能 + 在 `~/.workbuddy/fxai_global.json` 里填 `comfy_url` 即可复用整套规则与能力（技能包本身不带任何本机配置文件）。

## 〇、前置条件与配置

- ComfyUI 地址在 `~/.workbuddy/fxai_global.json` 的 `comfy_url`（本机）+ `comfy_cloud_url`（线上）；代码自动上线，无需手工启动、无需先探活（`require_comfyui()`）。
- 工作流模板：共享 `fxai-workflow/shortdrama-minimax-filmdrama-api.json`。
- **角色参考图一律四视图**：自有角色 = 全局头像库（`C.REF_WOMAN` = `avatar/000.png` 女主 / `C.REF_MAN` = `avatar/001.png` 男主），必须传 `ref="avatar/000.png"` 生成四视图；非自有角色/动物按提示词生成（`ref` 留空）。只有明确要三视图时才 `views=3`，正常短剧多参考链路不切三视图。`ref` 的格式与取值判据见 `fxai-standard/references/10-资源引用路径规范.md`（全技能唯一真相源，本技能不重复）。
- **自有形象直接用全局头像库当参考图**（服务端已有，重传会让锚脸锚错）。
- **技能包不带 `config.local.json`**，统一走全局配置；地址不读环境变量。

## 一、每集/每项目的目录结构（标准模板）

在项目空间下，每集一个文件夹，固定结构（文本产物用 **.md**，参考图/成片用 **assets/** 与 **.mp4**，映射用 **.json**）：

```
<项目根>/
├── project_def.json            # ★ 系列级项目定义（server_subdir + 角色/场景→server_index 映射，见「三、服务端目录」）
├── 剧集档案.md                 # 全剧设定/集数规划（长期项目维护，可选）
├── 角色库.md / 场景库.md        # 角色与场景清单（可选）
├── assets/                      # ★ 系列级规范资产副本（与服务器 shortdrama_<slug>/ 按 server_index 对齐，本地真值）
│   ├── 角色四视图/<key>.png
│   └── 场景图/<key>.png
├── 1、xxx/                      # 第 1 集文件夹
│   ├── 完整分镜脚本.md           # 本集剧本（文本用 MD 存，归档用）
│   ├── 镜头六段式提示词.md        # 六段式 H3 提示词（build_workflow 自动导出）
│   ├── run_xjzN_epN.py          # 生成脚本（组装 shots → 提交双采版 → 等合并）
│   ├── acceptance_burn_epN.py   # 验收 + 字幕烧录脚本
│   ├── scenes_manifest.json      # 资源 rel 路径映射表（characters/scenes → rel）
│   ├── assets_map.json           # rel 路径 + 本地备份路径（gen_assets 产出）
│   ├── assets/
│   │   ├── 角色四视图/<key>.png   # 人物/动物四视图本地备份
│   │   └── 场景图/<key>.png       # 场景图本地备份
│   ├── 成片_epN_xxx_sub.mp4      # 烧录字幕后的最终成片
│   └── subtitles_epN_word.srt    # 镜头锚定字幕
├── 2、xxx/ ...                   # 后续各集同构
```

精简骨架（每集一个文件夹即可开工）：

```
<项目根>/
├── project_def.json        # 系列级定义（server_subdir + 角色/场景→server_index 映射）
├── assets/角色四视图|场景图/  # 系列级资产本地真值
├── 1、xxx/                 # 每集一个文件夹（run_*.py / acceptance_burn_*.py / 成片 / srt）
└── 发布/_base/             # 平台交付底图缓存
```

> 新一集照抄上一集的 `run_xjzN_epN.py` / `acceptance_burn_epN.py` 模板即可，只改 shots 与文件名；本结构即分享时的标准产物布局。`project_def.json` 放在**系列根**（分集子文件夹向上查找即可），独立一次性短剧则放在自己的项目根。

**每集交付物里的 `镜头六段式提示词.md`**：`build_workflow` 组完 prompts 自动导出到集目录，不用手跑导出、也不用记得补。分镜脚本是**人读**的（画面/机位/台词，后期烧字幕用），六段式是**机器读**的（直接决定 H3 出什么画面和声音、可复现可改词重跑），两者同镜号一一对应。

## 二、资源闭环流程（服务端生成 → 本地备份 → 按需回传）
1. **服务端生成**：角色四视图/场景图在 ComfyUI 服务端跑（复用 `fxai-fourview-gen` / `fxai-scene-gen` / `fxai-comfyui-image-gen`），产物经 `comfy_client` 走 **HTTP `/fxai/down/file` 下载**到本地（缓存或直落）；取文件一律走这个接口，服务器可能装在别的机器，本机 `ls` 结果不作准。**生图必须显式传 `subdir=本系列 server_subdir`、`num=该资产 server_index`**（取自 project_def），让服务端文件精确落到 `shortdrama_<slug>/<server_index>.png`，与上传/引用同名对齐——详见「三、服务端目录」。
2. **本地备份**：下载到的图复制到本项目 `assets/角色四视图/` 与 `assets/场景图/`（见 `gen_assets_epN.py` 的 `backup()`）。**真值永远在本地 assets/，服务端只是临时工作区**。
3. **shots 引用 rel 路径**：每条镜头的 `images` 用相对服务端 `fxai/image/` 的 rel 路径（前缀=本系列 `server_subdir`，如 `shortdrama_xjz/000.png`、`shortdrama_xjz/001.png`），与 `scenes_manifest.json` 一致。生图/上传都落到本系列的 `shortdrama_<slug>/` 目录，正常流程无需回传。
4. **合并片取回**：`wait_for_merged(pid)` 拿到 merged 令牌 → 经 HTTP 下载到本地 → 写 `final_video` 回 manifest。**登记查不到但文件已在（尾节点未跑完）**：合并片按时间戳落在服务端 `fxai/video/merged/`，此时 `/fxai/tasks/result` 对该 pid 仍返回 `{}`，`acceptance_burn` 会直接抛 `未拿到 merged url`。此时**直接取服务端 merged 目录里最新那个文件**当 raw 用，`ffprobe` 验时长/分辨率/音轨三项对得上即可继续（抽音轨→对齐→烧录），不必死等登记。
5. **按需回传（仅恢复场景）**：当「重做旧项目 / 服务端资源被清、需从本地备份恢复」时，跑 `sync_project_to_comfyui(project_root, rels)` 或 `upload_project_assets(project_root)` 经 **HTTP `/fxai/image/v2/upload`（overwrite=true + filename=<server_index>.png）** 把本地 `assets/<rel>` 覆盖上传到服务端 `shortdrama_<slug>/` 对应 rel 路径。正常生图流程不需要此步。

## 三、服务端目录「每项目独立 shortdrama_<slug> + 覆盖、不累加」（重要 · 复用铁律）
- **每个短剧系列拥有自己独立的服务端目录 `shortdrama_<slug>`**（单层令牌，对应服务端 `fxai/image/shortdrama_<slug>/`）。`<slug>` 取自 project_def，如 小橘子升职记 → `shortdrama_xjz`。该系列所有角色/场景图都生成/上传到这里，按 `server_index` 命名（`000.png`、`001.png`…）。**不与其他短剧混用一个目录、不复用 MV 的 `views/`/`mv_scene/`/`charview/`/`boss_office/`**（MV 技能的目录，短剧只用自己的 `shortdrama_<slug>`）。
- **对齐基准 = project_def.json**（放在系列根）：记录 `server_subdir` 与 角色/场景 → `server_index` + 本地资产路径 的映射。本地 `assets/` 与服务器 `shortdrama_<slug>/` 通过这个映射对齐——**切项目只是换 `server_subdir`，不必把本地资源来回回传**（除非重做旧项目需从本地恢复）。
- **生图覆盖模式（生成即对齐）**：生图时 `gen_char_view(...)` / `gen_scene_image(...)` 显式传 `subdir=server_subdir`、`num=server_index`，配合工作流 `启用文件名覆盖: true` → 服务端精确写到 `shortdrama_<slug>/<server_index>.png`，**与上传/引用是同一个文件名，天然对齐、不靠递增乱序**。本系列所有生图调用统一用该资产的 `server_index`，勿改「不传 num / 关覆盖开关」（否则变递增命名持续堆积）。
- **上传覆盖模式（恢复用）**：`/fxai/image/v2/upload` 支持 `overwrite` + `filename` 参数；`comfy_client.upload_image(..., subdir=server_subdir, filename="<server_index>.png", overwrite=True)` 直接覆盖服务端 `shortdrama_<slug>/<server_index>.png`。`sync_project_to_comfyui` / `upload_project_assets` 走此路径（仅在「重做旧项目 / 服务端资源被清、从本地备份恢复」时用到）。
- **因此每个短剧系列在服务器端是独立、稳定、不累加的目录**；本地只在 `assets/` 保留自己那一份真值。换剧做另一部时，读新系列的 project_def 即可，互不干扰、无需回传。
- 🔴 **`characters[].prompt` 写成一句指认**：`保持参考图中的同一<身份词>。` 到句号收尾，句后不追加外观类目、"以参考图为准"的复述，也不追加 `不加 X` 这类反向澄清。判据见 `fxai-h3-video-prompt/references/04-通用技巧与自查.md`「白名单模式：指认到位就停」。

## 四、缺什么补什么

新项目/新角色/新场景首次按需生成并存入 `assets/`；已有（rel 一致）直接复用，不重复生成。`scenes_manifest.json` 记录 `characters`/`scenes` 的 rel 映射，新一集照抄即可。

## 五、换 ComfyUI 服务器（A 台生图 → B 台出视频）
- **镜头 `images` 引用的是「服务端 rel 路径」**（如 `shortdrama_xjz/014.png`），不是本地路径。所以**跑视频的那台服务器必须也有这些文件**；换服务器 ≠ 换个地址那么简单，参考图要跟着搬过去。
- **搬图一律用「覆盖上传」**：本地 `assets/` 里的图是已定稿真值，生图环节保持已有版本（重跑会让角色形象漂移、还白吃 GPU 时间）。做法是把本地 assets 按同一 rel 覆盖上传到新服务器（`comfy_client.upload_image(路径, subdir=<server_subdir>, filename="<server_index>.png", overwrite=True)`）。
- **提交前先核 rel 是否齐全**（列目标服务器 `shortdrama_<slug>/` 看缺不缺）。缺图不是静默降级：`FxAiMiniMaxImageToVideoV2` 的 `_validate_media_tags` 会在 `FxAiForLoopEnd` 抛 `ValueError: 提示词引用的素材不足`，整集重提。
- **指定服务器地址**（换服务器不用改配置）：`comfy_client.comfy_url(override=...)` 按单次调用覆盖（同一任务里 A 台生图、B 台出视频），或改全局配置的 `comfy_url` 长期生效。取值优先级 **调用方传入 > 全局配置 `comfy_url` > `http://127.0.0.1:8188`**。短剧侧 `drama_pipeline.COMFY` 同样只认全局配置，不读环境变量。
- **上传必须走 `comfy_client` 的 opener（关掉系统代理）**：手写 `urllib.request` 发 multipart 会被代理网关改包，服务端报 `Invalid HTTP header` 500。同理，boundary 用客户端默认的 `----fxaiup<hex>` 即可，别自造。

> 分享版一律 `project_root` + 向上查找的 `project_def.json`（server_subdir + server_index 映射）+ 服务端覆盖，本地与服务器经映射对齐、不来回折腾上传。
