# 字幕规范与对齐（做字幕时读）

## 核心决策：生成阶段抑制 + 后期烧录

MiniMax H3 有时会在画面里**自己画出字幕/文字**，且不准（同音错字、乱码）。因此采用与 MV 一致的稳定方案——**生成阶段不让它出字幕，字幕条全部后期叠加**。

## 一、对白/台词（语音 + 对口型）：用 `<d>[Chinese]台词</d>`
- 例：`<Subject 1> (S1) 开心地说：<d>[Chinese] 太好了，终于可以休息了！</d>`
- 作用：驱动「说话声音 + 口型同步」。画面字幕条由后期单独叠加。说话人用 `(S1)(S2)` 稳定 ID。

## 二、生成阶段抑制画面字幕（标准 negative_constraints 段）

`build_workflow` 默认开启 `suppress_subtitles=True`（**不传就等于开着，不是可选项**），会在**每条镜头提示词末尾自动追加**标准负面约束段 `NEGATIVE_CONSTRAINTS_BLOCK`。

🔴 **严格的三条，逐条照做**：
1. **`suppress_subtitles` 保持默认开着**。只有用户明确要 H3 自己在画面里生成可见字幕（极少数片尾 slogan 场景）才显式传 `False`。
2. **约束范围固定为「字幕」这一类**，字面就是「自动对白字幕条 + 乱码文字」两类。扩写成「任何文字 / 文本 / 标题」会把片尾 slogan、招牌、横幅、卷宗封面这些有意要生成的可见文字一起误杀。
3. **追加位置在六段之后**，是 `negative_constraints:` 独立小段（外加 `world_setting:`），不属于六段中的任何一段；由 `build_lines_data` 组装时自动加，不写回 `shots`，所以 run 脚本里也不手抄这段——抄了就会重复两遍。

```text
negative_constraints:
- 画面上不要出现叠加的字幕条、对白字幕，也不要出现乱码文字或扭曲不清的字形。 （# std:allow）
```

小标题 `negative_constraints:` 用英文，条目全中文、全口语，整段只一行。

### 本段条目范围（一件事，不扩写）

本段只收**画面里多出来的文字**：叠加的字幕条 / 对白字幕、乱码文字 / 扭曲不清的字形。
这两者是同一种失败——H3 的文字渲染能力不足，且后期字幕才是唯一真值。

片尾 slogan、招牌、横幅等**有意生成**的可见文字不进本段，走正文与后期。

**人物画质不进本段**。崩脸、多指、口型不同步靠正向锁死：主体定义只写「`<Subject N> 是 <Picture M> 中的<身份词>。`」，类目归延续分析
（极简口径，见 01 册；**不写类目清单、不写外貌句、不照抄生图 prompt** —— 文字越细越会覆盖参考图），
说话人一律写 `<Subject N> (Sx)` 稳定 ID（见 5.6 与 5.3 节）。「脸别变形 / 手指数量正确」这类否定句对画质类失败
没有约束力，等于把「变形」「多余手指」当概念喂进提示词。 <!-- std:allow -->

### 措辞口径

**用现代口语，不用文言单字**。条目写口语祈使句，与官方提示词的负面行同一口径：
「不要添加字幕」「无软溶解」「do not add extra text」都是官方原句。 <!-- std:allow -->
「勿」属低频单字，模型读得懂，遵从度不如常用词稳定，提示词正文按口语写。

**一条只说一件事，不换语言重复**。中英并列在自然语言通道里属重复指令，不构成双保险：
H3 铁律「同一件事只写一次」按同镜内 ≥5 字相同片段判定重复，重复会摊薄权重、被当成第二个任务；
混入英文还会多引入一种语言信号。字幕这条只写一次。

### 时代感与画风：正向锁定

时代感、画风、道具、构图一律写进六段正文，用正向锁定表达——写「只有什么 / 是什么」：
古装锁定单一材质与器物清单，现代锁定金属、玻璃、嵌入件这类可见特征。
正向锁定的判据：正文里能指认画面中每一样东西，不依赖任何否定句。

### 机制口径

H3 为 guidance-distilled 检查点，无独立 `negative_prompt` 参数；`1155` 节点（FxAiMiniMaxImageToVideoV2）
未暴露负向输入框。本段按**普通文本**参与生成，条目按上面三类最小化。

`build_workflow(negative_prompt=...)` 只在模板暴露负向字段时注入（`_inject_negative_prompt` 探测），
探测不到则以上述段落为准；`no_humans=True` 的宠物版另追加 `NO_HUMANS_BLOCK`。

> 片尾/标题类短句若确实想让 H3 直接生成可见字幕，可用双引号写法 `画面定格，弹出字幕："每一次羡慕，都是前进的动力~"`（字要大、高对比），但大段对白一律走后期。

## 三、内心戏写法

`<d>[Chinese]…</d>` 只放角色真说出口的话（TTS 会念出来 + 驱动口型）。内心活动用动作 / 表情 / 神态描写：
`At 00:03.000, <Subject 1> 低下头陷入沉思，若有所思地搓了搓爪子。`
画外音 / 旁白 / 思考都不包 `<d>`，要旁白走后期配音。

`drama_pipeline.build_lines_data` 会做轻量校验：提示词里 `内心` / `独白` / `OS` 与 `<d>` 同时出现时打印 ⚠️ 警告（不阻断）。

## 三之一、全动物阵容（宠物版）专属约束：画面与场景不得出现人类

**硬规则**：宠物/动物版短剧是**全动物阵容**（橘猫/德牧/仓鼠等），场景图与每一帧画面只出现拟人化动物，不出现人类、真人、人物剪影、人群。

**两道落实（调用 `build_workflow(..., no_humans=True)` 时自动生效）**：
1. **场景图生成阶段**（生图时）：提示词必须显式写无人约束「画面中绝对没有任何人类人物，只呈现空旷的动物活动场地 / 空无一人的动物办公室」。纯场景用 `fxai-comfyui-image-gen` 的 `generate_image(prompt, role=None)`（role=None=不带人物参考），提示词末尾带上面的无人约束。
2. **视频生成阶段**：每条镜头提示词末尾自动追加 `NO_HUMANS_BLOCK`（`negative_constraints` 段）：
 ```text
 negative_constraints:
 - 本片为全动物阵容（宠物卡通角色），画面中只有拟人化动物角色（橘猫、德国牧羊犬、仓鼠等），人类、真人、人物、人物剪影、人群、路人、人类角色都不进画面。 （# std:allow）
 - No humans, no real people, no human silhouettes, no crowds in the frame; animals only.
 ```
 同时 `DEFAULT_NEGATIVE_PROMPT` 也加了 `人类,真人,人物,人群,路人,human,people,person` 作为双保险（若模板 1155 节点暴露负面字段则注入）。

**`build_lines_data(..., no_humans=True)` 还会做轻量 lint**：若提示词（你写的原始部分）里出现 `人类/真人/人物/人群/路人/人类角色/男人/女人/人员` 等词，打印 ⚠️ 提醒你确认。

> UI 截图类场景（凤希AI主界面/活动策划界面）是软件界面，天然无真人风险，可跳过重生成；但环境类场景（团建场地、办公室）**必须**带无人约束重生成。

**职场场景三件套（写进镜头提示词正文）**：
1. 背景直接写"一群动物在办公/活动"：`办公室里是一群动物在办公` / `场地里一群动物在活动——有的搭帐篷、有的烤肉、有的追逐`；职业词用动物身份，不用"同事/员工/职员"这类带人类职场联想的词。
2. 详细描述声明风格：`目标视频是 3D 卡通动画风格的动物办公室场景`。
3. 延续分析用"明亮整洁"这类词，不用"忙碌/人流"类词。

**每次出片都抽帧验收**（不按上一集的结果推定这集干净）：`ffmpeg -ss <秒> -i 成片.mp4 -frames:v 1 帧.png`，每镜抽 1 帧（t 取镜头中点）逐镜全查。

**疑似时的验证流程**：改强提示词 → `single_shot=N` 只重该镜预览（约 6 分钟）→ 抽帧确认干净 → 再整集重提（约 40 分钟）。

## 三之二、场景里的参与者/动物必须"动起来"（动态描述）

**问题**：场景中的动物几乎全静止——只有主角按时间轴动，背景动物像贴图。H3 **不会自动给"背景演员"编动作**：提示词只描述静态场景 + 单一角色动作时，其余动物就是死的。

**写法（写进每条镜头提示词的「摘要」+「详细描述」）**：在摘要和详细描述里，**显式写出场景里其他动物正在做什么动态事**（多动作、有位移/互动），例如：
- 办公室：`办公室里一群动物在办公——有的敲键盘、有的端着咖啡走动、有的凑在一起交头接耳`
- 团建场地：`场地里一群动物在活动——有的搭帐篷、有的生火烤肉、有的在草地上追逐打闹`
- 围观：`周围的动物们有的烤肉、有的举着相机拍照、有的围坐聊天`
- 游戏：`大家围成一圈做游戏，周围的动物们有的拍手大笑、有的蹦跳欢呼、有的加油助威`
- 夕阳：`周围的动物们有的在收拾帐篷、有的举着手机拍照留念、有的相拥道别`

要点：
- **动态动词优先**：走/跑/敲/端/搭/烤/追/扔/拍手/蹦跳/晒太阳/野餐/散步/收帐篷/拍照/交头接耳/追逐/打闹……让画面"有事发生"。
- **摘要 + 详细描述都要写**，不只写在时间轴里（时间轴只覆盖主角，背景动物靠场景描述驱动）。
- 与「三之一」配合：动物身份（"一群动物"）写在场景描述里，动态动作也写在场景描述里，H3 才会让整帧都活。
- 这一条对**场景丰富的项目（团建/聚会/街道/办公室）尤其关键**；纯特写镜头可酌情弱化。

**`build_lines_data(..., dynamic_action_check=True)` 轻量 lint（默认开）**：若某镜头提示词的「摘要」与「详细描述」里都检测不到动态动词（走/跑/敲/搭/烤/追/扔/拍/蹦/跳/晒/野/散/收/游/玩/聊/笑/闹…），打印 `⚠️ [动态]` 提醒你补动态描述。**组装阶段就拦住，不等出片才发现动物是死的。**

## 三之三、画面里无故生成的乱码字幕 / 对白字幕条归后期

**分工**：画面里**无故生成的乱码字幕 / 对白字幕条**（不该出现却出现的字幕条、乱码文字）由 `suppress_subtitles` 压掉 + 后期字幕规范收口（见上）。

**验收**：抽帧只盯**乱码字幕 / 对白字幕条**这类无端内容是否被压掉。

**能写出干净画面的替代构图（按此搭镜头）**
- 需要传达数据/产出/进度：用**木桌上一排纯色分镜卡片**（白纸上只有蓝/橙/灰色块或圆环），画面里只有木桌与色块卡片，显示器、投影幕布、白板、软件界面面板都不入画；提示词同时写死这一点。
- 需要传达配色/选版：用**桌面摊开的空白纯色卡**（天蓝、橙、浅灰三块圆角/圆形色块），写死「色卡是完空白纸，没有任何文字、汉字、字母、数字、符号与图案」。

## 四、后期字幕烧录（推荐 · 复用 fxai-lyric-subtitle 技能）

成片合并完成后，用 `burn_subtitles()` 把字幕条叠加上去（MV 同款，最稳）：
```python
from drama_pipeline import burn_subtitles, wait_for_merged
# merged 是服务端资源令牌（wait_for_merged 从接口取回、含 "merged" 目录名），走 HTTP 接口取，本机 ComfyUI 目录不参与
# 路径写占位符（<某ComfyUI本机路径>/... 之类）——服务端可能部署在另一台机器
merged = wait_for_merged("<prompt_id>")
out = burn_subtitles(merged, "项目目录/台词.txt", out_name="ep4_sub", out_dir="项目目录")
```
或直接命令行：
```bash
python drama_pipeline.py --burn --merged "<合并成片.mp4>" --lyrics "<台词.txt>" [--karaoke] [--no-burn]
```
流程（委托 `fxai-lyric-subtitle` 技能）：抽音轨 → whisper 提**时间戳** → 与我们的台词做强制对齐 → 生成 SRT/ASS → 带 libass 的 ffmpeg 烧录。

**为什么稳 + 如何改错别字**：
- 显示的字幕文字 **一律以「我们的台词」为准**，whisper 只提供时间点（即使 H3 念错/咬字不清，字幕仍显示正确词）。
- 同时输出 `_alignment_record.json`：每行 `{start,end,lyric:我们的词, whisper:模型听到的}`，**逐句对照就能挑出 ASR/模型念错的错别字**，人工复核极方便。
- 依赖：已安装 `fxai-lyric-subtitle` 技能 + 凤希AI伴侣的 whisper / 带 libass 的 ffmpeg（见其 `config.json`）；可用环境变量 `LYRIC_SUBTITLE_SCRIPT` 指定脚本路径。

**方式 B：确定性时间轴（推荐 · 对白剧更准，不依赖 ASR）**——镜头时长和台词都是已知的，直接从 shots 解析 `<d>` 生成 SRT：
1. 解析每条 shot 的 prompt：用 `drama_pipeline.timeline_marks(prompt, duration)` 取每档 `(起, 止, 行)`（首档自动补 0 起点），再从行里抓 `<d>[Chinese](.*?)</d>` 得台词。
2. 绝对时间 = 前序镜头 duration 累加 + 镜头内相对时间（若提示词时间轴超出 duration，按 `duration/max_rel` 等比缩放）。忽略转场帧误差（<0.5s/间隙，肉眼无感）。
3. 生成 SRT → 烧录。参考实现：`小橘子升职记/4、团建活动/gen_subtitle_ep4.py`（通用，换 shots 即可复用）。
> whisper 对 H3 **合成卡通音**的识别很不稳（易出乱码错别字），对白剧直接用台词真值生成 SRT 反而无错别字；whisper 对齐（方式 A）更适合真人录音/歌曲。

**⚠️ 确定性时间轴的漂移陷阱**：H3 **系统生成语音**实际起音/句间停顿，和提示词里写的切点时刻**并不一致**——模型常在句间加停顿、起音偏晚，越往后累积延迟越大，字幕就越「提前」。**修法：改用 whisper 真实时间轴对齐**——
1. 抽音轨：`ffmpeg -i 成片.mp4 -ar 16000 -ac 1 -c:a pcm_s16le audio.wav`
2. 提时间戳（**推荐词级 `words=True`，比句级更准**）：走 whisper 服务接口，`whisper_client.write_transcript(audio, out, words=True, vad=True)`，**不起本地进程**（地址读全局配置 `whisper` 段，本机 8185 / 线上均可）。
- **为什么用词级**：句级的分段边界包含句间停顿/静音；当两句之间有明显静音（H3 系统音常有）时，前一句区间被拉长、后一句字幕"提前"冒出。词级把每句字幕的 **起=该句第一个词的开始、止=最后一个词的结束**，直接卡到"开口"时刻。
- 句级也可用，但句间有长静音时字幕会明显提前；故**优先词级**。
3. 得到 N 段 `[start->end]`（词级产物也是每行一句的 `[start->end]`，已自动取首词/末词边界），**按句序**与我们的正确台词一一映射（文字以台词真值为准，whisper 只借它的时间）
4. 生成 SRT 烧录。

**⚠️ whisper 词级尾部「零时长幽灵词」坑**：faster-whisper 开启 `word_timestamps` 后，在音频**尾部静音/音乐段**会吐出一批 `start==end` 的零时长词，集中在时间轴**末端**，会污染"按字数比例切分"的映射——把最后几句台词挤压成零/极短时长。**修法**：`load_words()` 加载词表时**直接剔除 `end<=start` 的零时长词**（`gen_subtitle_aligned.py` 已内置）。若仍出现末句极短，再在 `distribute_by_char` 给末句做"不足 0.5s 则延到下个词/补 0.5s"的兜底。此坑与"段数≠台词数"无关，是词级时间轴的独立陷阱。

**⚠️ 全局比例切分的「尾部漂移/滞后」坑**：即使剔除幽灵词，"按字数比例把全部词时间轴切成 N 句"仍会在**后段系统性滞后**——它假设 TTS 匀速，但 H3 系统音实际节奏有波动，越往后累计偏移越大。**修法：镜头锚定对齐 `align_subtitles_shotwise(shots, words_path, out)`**（`gen_subtitle_aligned.py` 已内置）：用 H3 公式（见 04 册）算每镜 [起,止) 窗口 → 取落在该窗口内的 whisper 词作本镜真实语音区间 → 按字数切分本镜台词（某镜无词则退化为按窗口均分，仍锚在镜位）。把每句锚到所属镜头，彻底消除全局漂移。**注意**：中文 ASR 丢字严重（识别字数常少于真值 30%+），**勿**用"识别文字↔台词字符级 difflib 对齐"——映射会越界/错乱；镜头锚定只借 whisper 的**时间**，文字一律用 `<d>` 台词真值。
> 取舍：**文字**仍靠「台词真值」保证准确，**时间轴**改用「whisper 时间戳」保证对齐。对白剧默认用方式 B 起步，一旦发现「字幕越往后越提前/滞后」，立刻切到本流程（且用词级）。

## 字幕对齐标准动作（SOP）

把上面所有经验收敛成**一条标准流水线**，新增一集直接复用，参数全部固定：

**标准入口（一句话走完）**：`gen_subtitle_aligned.py` 的 `align_standard(shots, out, audio)` —— 自动跑词级 whisper → 剔除零时长幽灵词 → **镜头锚定对齐**。也支持 CLI：

```bash
# 标准动作：给镜头定义 + 音轨，一步出 SRT（推荐）
python gen_subtitle_aligned.py --shots run_xjzN_epN.py --audio audio_epN.wav --out subtitles_epN_word.srt
# 已有 whisper 词级文件则跳过跑 whisper：
python gen_subtitle_aligned.py --shots run_xjzN_epN.py --transcript subtitles_epN_word.srt.whisper_wl.txt --out subtitles_epN_word.srt
```

**SOP 五条铁律**：
1. **whisper 只借时间，文字用正确文本替换**——H3 合成卡通音 ASR 错字/漏字多（"凤希AI"→"凤夕AI"），字幕文字一律取台词真值。
 - **短剧的正确文字来源 = 剧本里的 `<d>` 台词真值**（本技能）；**MV 的正确文字来源 = 歌词真值**（`fxai-mv-pipeline` 技能）。
 - 二者**唯一区别就是"正确文字的来路不同"**，对齐机制（whisper 取时间 + 镜头锚定 + 剔幽灵词 + 相对路径烧录）完全通用、共用 `gen_subtitle_aligned.py`。本 SOP 只管短剧这条（剧本台词），MV 那边的歌词替换由 fxai-mv-pipeline 各自负责，互不干扰。
2. **用词级时间戳（`--word-level`）**——句级 `--ts` 的分段含句间静音，会让字幕"提前"；词级把每句卡到真实开口时刻。
3. **剔除零时长幽灵词**——`load_words()` 已内置剔除 `end<=start` 的尾部幽灵词（否则末几句被压成 0 秒）。
4. **镜头锚定对齐（非全局比例）**——`align_subtitles_shotwise` 用 H3 公式算每镜窗口，把每句锚到所属镜头，消除"后段系统性滞后"（全局比例会在尾部累计偏移 ~2s）。
5. **SRT 路径用相对 basename + `cwd`**——ffmpeg `subtitles=` 只收文件名（Windows 绝对路径的盘符冒号/`\` 会被误当滤镜选项分隔符，报错 `original_size`）。

**烧录**：libass ffmpeg，`force_style='FontName=Microsoft YaHei,...'`（白字黑边）；`burn()` 内部已统一 `os.path.basename` + `cwd` 规避第 5 条坑。

**段定位（判定某镜是否要重生成）**：用 `h3_actual_seconds` 累加每镜真实 `[起,止)` 区间；成片时间点 T 落在第几镜 → `single_shot=N` 只重那一段。H3 向上取整是刻意为之（让镜头更充实），属正常值。

**⚠️ 拿 `h3_actual_seconds` 直接当字幕窗口会让整条时间轴偏长**：该值是逐镜估长、误差同向累积，
实测比成片实拍长 4~5%（30 镜：计划 223.7s vs 实拍 213.8s），照它切字幕会越往后越提前、
尾部漂十几秒。**修法：先按「实拍总长 / 计划总长」把全部窗口等比缩放一次，再逐镜锚定 whisper 词级时间**；
两者同时做，缺一个都会漂移。实拍总长用 `ffprobe -show_entries format=duration` 读成片。


> 中文 ASR 丢字严重（识别字数常少于真值 30%+），对齐只借 whisper 的**时间**、按镜头锚定，字符级对齐交给台词真值。

**✅ 推荐脚本（标准动作的自动化实现）**：技能自带 `gen_subtitle_aligned.py`，封装了上面全部逻辑——`align_standard`（标准入口）/ `align_subtitles_shotwise`（镜头锚定）/ `h3_actual_seconds`（段定位）/ `load_words`（已剔幽灵词）。词级 whisper 自动调 fxai-whisper-transcribe 环境的 faster-whisper。新一集照抄 `run_xjzN_epN.py` + `acceptance_burn_epN.py` 模板即可，SOP 已写死在脚本里。
```bash
# 已有 whisper 时间轴时（最快）：直接喂正确台词 + transcript
python gen_subtitle_aligned.py --lyrics lyrics.txt --transcript ts.txt --out out.srt
# 没有时间轴时：自动调 fxai-whisper-transcribe 技能跑 whisper 取时间（句级）
python gen_subtitle_aligned.py --lyrics lyrics.txt --audio audio.wav --out out.srt
# 推荐：词级对齐（每句=首词开始/末词结束，消除句间静音带来的提前）
python gen_subtitle_aligned.py --lyrics lyrics.txt --audio audio.wav --word-level --out out.srt
```
- `--lyrics`：正确台词**纯文本，每行一句**（无时间戳）。来源就是 shots 里 `<d>` 的台词真值（可先用 `gen_subtitle_ep4.build_srt` 抽文字行写文件）。
- `--transcript`：whisper 输出（`[start->end]` 格式，句级/词级都行），**只取起止时间，文字丢弃**。
- `--word-level`：词级时间戳（推荐）。自动调 fxai-whisper-transcribe 环境的 faster-whisper 跑 `word_timestamps`，**同时写出两份**——① 每段的 `[start->end]`（段数恰好=台词数时直接用，最准）；② **每个词的独立 `[start->end] 词` 时间戳文件**（`.words`）。需 `fxai-whisper-transcribe` 技能在线（其专用 python + 模型由 DEFAULT_WHISPER_PY 指定，可用参数覆盖）。
- **段数处理**（关键）：
 - 若词级段数 == 台词数 → 逐段直接映射。
 - 若词级段数 **≠** 台词数（连续 TTS 音频常被 whisper 切成比台词少的段）→**自动改用「词级时间轴 + 按每句字数占比切分」**：把全部词的真实时间戳按台词字符权重（实义字权1、标点权0.3）切开，每句锚在真实词起止上、互不重叠。TTS 按我们的台词匀速朗读，字数占比≈时长占比，结果很准。
 - 句级 `--ts` 若段数≠台词数仍会**直接报错**（不退化），需用词级才有退化兜底。
- 现成封装：`某项目/某集/gen_subtitle_aligned_epN.py` 已封装"抽正确台词 → 调本脚本（默认词级）→ 出 `subtitles_epN_word.srt`"，新一集照抄即可。

**ffmpeg libass 大坑（Windows）**：
- conda 自带的 ffmpeg（默认安装位置）**没有编译 libass**（无 `subtitles` 滤镜），烧录必失败。
- 本机**带 libass 的 ffmpeg（full_build）**：以软件安装目录为准——`{software_install_dir}\ffmpeg\ffmpeg.exe`（即你用凤希AI伴侣指定的软件安装目录下的 ffmpeg）。`drama_pipeline._resolve_bin` 已按此自动定位，无需手动指定。自查：`ffmpeg -filters | grep -w subtitles`。⚠️ 环境变量 `FFMPEG_PATH` 若指向**目录**而非 exe，会让 subprocess 报 WinError 5；`_resolve_bin` 已忽略指向目录的 env 覆盖。
- **SRT 路径必须用相对 basename**：ffmpeg 的 `subtitles` 滤镜语法里 `:` 是选项分隔符、`\` 是转义符，Windows 绝对路径（形如 `<某盘符>:\项目目录\...`）里的盘符冒号和反斜杠会被误解析（报错 `Unable to parse option value ... as image size` / `Error applying option 'original_size'`）。**正确做法**：`subprocess.run(..., cwd=SRT所在目录)`，滤镜里只写 `subtitles=文件名.srt`（os.path.basename）。输入视频 `-i` 可给绝对路径（那是普通参数，不受影响）。

🔴 **字号与样式一律走 ASS，禁用 `force_style='...,FontSize=NN,...'` 定字号**：SRT 无 PlayRes，
libass 按 288 基准放大 ×(视频高/288)，竖屏 1280 就是 ×4.44——`FontSize=28` 实际烧成 124px em
（汉字 91px），画面被字占满。`drama_pipeline.SUBTITLE_STYLE` 的 `FontSize=18` 同属此列，已作废。

标准做法：SRT 先转 ASS，`PlayResX/Y` = 视频真实分辨率，字号取 `fxai-lyric-subtitle/SKILL.md`
「单条字幕的上限（按画面方向分档）」表——**竖屏 32 / 横屏 38，固定两档，不按比例**：

```bash
python ~/.workbuddy/skills/fxai-lyric-subtitle/scripts/srt2ass.py subtitles.srt subtitles.ass --size 768x1280
# [srt2ass] PlayRes 768x1280 | 字号 32（竖屏档）
```

样式：微软雅黑加粗、白字 `&H00FFFFFF`、描边 `&H00181A1C`、描边 2.5、投影 1.2、字距 0.8、
`MarginV = 画高 × 0.078`（1280 → 100）。字号变了行宽跟着变：竖屏 32 号一行约 20 字，
**单条上限 16 字 / 4.0 秒**，单行不折（`gen_srt.py` 侧 `MAXC=16`、`PERLINE=20`）。
