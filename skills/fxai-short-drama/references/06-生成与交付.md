# 生成与交付（提交渲染 / 单镜重生成 / 平台发布 / 验收时读）

## 交付铁律（SKILL.md 铁律 14 的判据）

1. **尺寸**：横屏 `1280×768`、竖屏 `768×1280`。
2. **音频模式**：宠物 / 卡通 = `系统生成`；真人 = `音色参考` 或 `原音频`。
3. **服务端目录**：每个系列独立目录 `shortdrama_<slug>`，覆盖不累加；生图显式传 `subdir=` + `num=`（详见 05 册）。
4. **路径占位**：机器路径走 `~/.workbuddy/fxai_global.json`，项目路径用 `project_root` + 相对路径。
5. **打斗镜先取词**：写提示词前跑 `fxai-combat-design` 的 `combat_route.py`（`moves --query …` → `--read moves/<id>` 或 `--terms <类别>`），术语 **2–4 词/段**；触发词由 `build_lines_data` 挂到「详细描述」首行（01 册 §4.5）。
6. **封面模板路由**：按 `project_def.cover_style` 选模板——`guwu` 古装权谋（缺省，男女主同框 + 宫殿宫灯，`_cover_prompt_guwu` + `_series_role_refs` 双图）；`niandai` 农村年代（主角捧发光外挂物件 + 土坯房老槐树煤油灯，`_cover_prompt_niandai` + 主角单图）。`_series_cover_prompt` 与 `_series_cover_role` 同步按 `cover_style` 选；新增题材在 `platform_publish` 加 `_cover_prompt_<主题>` 并登记路由。
7. **按集落盘**：每集的 pid、抽音轨、字幕、中间版本成片、最终成片全部放该集目录（`N、集名/`）；系列根只留共享文件（`project_def.json` / `scenes_manifest.json` / `发布/_base/` / 资产库 / 各集目录）。

## 长任务等待规范（提交渲染后必读）

**首选：用全局广播监听等，别自己 sleep 轮询。**

```bash
# 提交渲染拿到 prompt_id（照旧写进 epNN_pid.txt）后，立刻起这个等：
python <技能目录>/scripts/comfy_watch.py wait <prompt_id> --timeout 5400
```
- 它连 ComfyUI 的 `/ws` 收 fxai-toolkit 自己广播的事件：**「开始渲染第 N/M 个场景」「第 N 个场景已生成」「完成：video/merged → xxx.mp4」**，逐条落进 `~/.workbuddy/runtime/comfy_ws/` 台账；出终态时自己退出（退出码 0=success）并触发通知，随后直接跑 `acceptance_burn` 烧字幕。
- 顺带能拿到**成片文件名**（`merged`），省掉再去 `POST /fxai/tasks/result` 查一次。
- 查看进度：`comfy_watch.py status <prompt_id前缀>`；看全服务器在跑什么：`comfy_watch.py top`。
- 细节与通道原理见技能 `fxai-comfyui-watcher`。

**没有监听器可用时**（例如运行环境不给起进程）的退路：
- **本机工具默认超时 120 秒，后台模式同样受此约束**：超时后服务端任务仍在正常生成，先查 ComfyUI `queue_running` 再判断。
- 按规模选节奏：单镜头重生成（5-6 分钟）60 秒查一次 `/history/<pid>`；整集渲染（40 分钟量级）切 9 分钟窗口前台分段跑。
- **兜底走前台分段跑**（本机 `schtasks.exe` 被安全策略拦截，常驻计划任务这条路走不通）。
- 等待过程只查结果，同一 `prompt_id` 只提交一次。

## 已封装通用能力（drama_pipeline.py，所有短剧共用 · 勿每集复制）
- **`render_episode(project_root, ep, shots, **kw)`**：提交骨架。组装+提交+等合并+写 `ep{N}_pid.txt`+写回 manifest。`world_constraint` 自动从本系列 `project_def.json` 的 `world_constraint` 字段取（全动物世界观句，无需手写 `% WORLD_OFFICE`），也可在 kw 里显式覆盖。内部同样是先过单集时长下限（≥60s）再组装提交。每集 run 脚本只需：组装 shots → 调它 → 完事。
- **`acceptance_burn(project_root, ep, shots, title_hint="集名", denoise=False)`**：验收+烧录 SOP 一体化。读 `ep{N}_pid.txt` → 查 merged 令牌（`query_task_result_raw`/`_find_merged`）→ HTTP 下载 → ffprobe 验收（时长/音轨）→ 段映射 → 抽音轨 → **镜头锚定词级对齐**（`gen_subtitle_aligned.align_standard`，**不依赖 MV 的三段式补齐**）→ libass 烧录 → 写回 manifest（`final_video`/`subtitle`）。`denoise=True` 时烧录叠加轻度去噪（视频 `hqdn3d` + 音频 `afftdn`，需软件目录 ffmpeg 的 full_build 滤镜）。ffmpeg/ffprobe 路径以**软件安装目录**为准（`fxai_global.json` 的 `software_install_dir` + `/ffmpeg/`），`_resolve_bin` 候选顺序：全局配置显式 `ffmpeg_path`/`ffprobe_path`（真实文件才采用）> env `FFMPEG_PATH`/`FFPROBE_PATH`（**仅当是真实文件，目录直接忽略**，规避指向目录的 `FFMPEG_PATH` 令 subprocess 报 WinError 5）> `software_install_dir`/ffmpeg（你用凤希AI伴侣指定的软件安装目录）。**不写死本机绝对路径**。
- **字幕对齐已封装，不重复造**：短剧用 `fxai-short-drama/gen_subtitle_aligned.py`（`align_subtitles_shotwise`/`align_standard` 镜头锚定，文字一律取 shots 的 `<d>` 真值、whisper 只借时间）；MV 用 `fxai-lyric-subtitle`（`align_subtitles`+`distribute_by_char` 三段式补齐）。各取所需。
- **whisper 子进程坑（共享 `gen_subtitle_aligned.run_whisper`）**：词级对齐会把临时脚本写到 `tempfile.gettempdir()`。**若该系统临时目录（Windows 的 `%TEMP%`）里残留 `enum.py` 之类包，会作为 `sys.path[0]` 影子标准库，令 venv 的 `import re` 报 `enum.global_enum` 缺失**。现在写进 `tempfile.mkdtemp()` 的干净空子目录；若其他机器复现此错，清掉临时目录里的影子模块即可。
- 其余：`gen_project_assets`/`upload_project_assets`/`sync_project_to_comfyui`/`load_project_def`/`server_subdir_of`/`build_workflow`/`build_lines_data`（含 `no_humans`/`suppress_subtitles`/`dynamic_action_check`/`world_constraint` 注入）/ `gen_episode` / `wait_for_merged` 均已在此文件，未来任何短剧项目直接 `from drama_pipeline import ...`。

### 断了接着跑（一条命令，推荐）

不小心中断 / 被 SIGTERM / 服务器挂了 → **不用重新准备 shots**，一条命令从第 N+1 镜接着跑：

```bash
python <技能目录>/scripts/comfy_watch.py resume <prompt_id>            # 查断点 → 自动重投，返回新 pid
python <技能目录>/scripts/comfy_watch.py resume <pid> --dry-run        # 先看它会从第几镜开始
python <技能目录>/scripts/comfy_watch.py resume <pid> --wait           # 提交后就地等终态
```

⚠️ **`/history` 是内存态**：实测本机只留最近 10 条、全在 0.4 天内，而输出目录里存着 23 天前的分镜——**ComfyUI 一重启，老任务的工作流就查不回来了**。
所以 `submit_workflow` 在提交成功时会自动落一份快照到 `~/.workbuddy/runtime/comfy_ws/snapshots/<pid>.json`（日志里会打 `[快照] 已存工作流快照`）；resume 取工作流顺序：`/history` → `--wf <文件>` → 本地快照。换电脑/快照也丢了时，用 `--wf` 指定工作流 json，或按原脚本重投并显式给 `start_index`。

## 断点续跑：先查「已生成到第几镜」（生成视频通用）

整集 / 多段循环生成中途断了（超时被 SIGTERM、关机、报错、换机器）时，**先查再续，别整集重投**：

```bash
python <技能目录>/scripts/comfy_watch.py shots <prompt_id> --dir <保存目录> --total <总镜数>
# 例：shots 1c8d942e --dir sucai --total 30 --files
```

- **判定口径（全技能统一）**：视频文件**只要不在合并目录（`merged`）里**，文件名上的文件号**就是分镜序号**（`000.mp4` = 第 1 镜、`007.mp4` = 第 8 镜）；`video/merged/xxx.mp4` 是成片，不算分镜。
- 输出：`已生成 N 镜` / `缺失第 X 镜` / `下一镜 第 N 镜` / `续跑参数 start_index=N`。
- 续跑：`build_workflow(shots, start_index=r["next_index"])`；库里 `comfy_client.shot_progress(pid)` 返回同一份字典（`--json` 给脚本读）。
- 单镜返修仍是另一套：`build_workflow(shots, single_shot=N)`（1-based），见下节。
- 实现与更多参数见 `fxai-workflow/shot_query.py`（短剧 / MV / 数字人都走这一套）。

## 单镜头重生成（只重某一镜）

只重生成某一个镜头（开始索引=结束索引=同一值），比整集重提省时间——适合"只有一个镜头出问题、其余都好"的情况。

**用法**
- API：`build_workflow(shots, single_shot=N)`，`N` 是 **1-based 第 N 个镜头**（如第1个镜头传 `1`）。内部自动设为 `开始索引=结束索引=N-1`（0-based）。
- CLI：`python drama_pipeline.py --lines-data shots.json --single-shot 1`（只重第1个镜头）。

**产物即整集成品**
提交 `single_shot=N` 后返回的 `merged` **仍然是完整成片**（如 ep11 单镜重渲的 merged 时长 72.94s，与整集一致），因为其余镜头命中 ComfyUI 节点缓存被原样复用，只有第 N 镜重新生成，merger 照旧合并全部镜头。
🔴 **这是所有视频生成环节的统一模式**（短剧 / MV / 数字人 / 幻灯片视频一致，见
`fxai-standard/references/01-产出铁律.md`「视频生成的两种跑法」）：完整生成与单镜重渲都一样，
服务端把「本次新段 + 已缓存的其他段」合并成一条完整视频返回，本地取到的即全长成片，
直接进后续环节。
（单镜产物被拆成独立文件时的拼接走法见下方「需要手动拼接 ffmpeg 的场景（罕见）」。）

因此返修单个镜头**走这套即可，整集沿用上一次提交**：
1. 改好 `run_xxx.py` 里那一个镜头的提示词 / `images`；
2. `python submit_epNN.py N`（`submit` 脚本会把 pid 写进 `ep{N}_pid_single_shot={N}.txt`，**注意文件名里的 N 会变**，`ep{N}_pid.txt` 是 acceptance 读的那个）；
3. `comfy_watch.py wait <pid> --timeout 1800` 等它出终态（单镜约 5-6 分钟，整集才 40 分钟量级）；

**SIGTERM 不等于提交失败（必须先核实再重投）**
`run_xxx.py <镜号>` 这类入口在提交后会接着调 `wait_for_merged()` **阻塞等待**，单镜渲染 6-10 分钟会超过 Bash 命令默认超时，进程被 SIGTERM 掐掉、连日志都丢。**此时 pid 已写进 `ep{N}_pid_single_shot={N}.txt`、任务也已进 `/queue`，提交是成功的**——先核对这两处再决定是否重投，盲目重投会重复占 GPU 并浪费一次渲染。exit=1/SIGTERM 一律先核对再决定动作。

**取消已在跑的任务**：先比对 `ep{N}_pid.txt` 与 `GET /queue` 的 `queue_running` 确认是自己那一条（本机 ComfyUI 队列常混有别处的活），再 `POST /interrupt`（空 JSON body）中断队首running。中断后显存会明显回落。渲染已完成、只是尾节点空转占着 GPU 时同样适用。

**whisper 对齐要传绝对路径**
`gen_subtitle_aligned.align_standard` 会把临时脚本写到系统临时目录下的 `wl_align_*` 并以那里为 cwd 执行，`audio`/`srt` 传相对路径必报 `FileNotFoundError`。srt 与 audio 都传 `os.path.join(集目录, ...)` 绝对路径。
4. 把最终 pid 写进 `ep{N}_pid.txt`，直接跑 `acceptance_burn` 重新下载 raw + 重烧字幕，用这个 merged 当整集成片。

**需要手动拼接 ffmpeg 的场景（罕见）**
只有单镜产物被拆成独立短视频文件（如 `FxAiVideoMerger` 只输出那一段）时才用：
 ```bash
 # new_shot1.mp4 = 新镜头，old_full.mp4 = 原成片
 ffmpeg -y -i old_full.mp4 -ss 6 -c copy old_rest.mp4
 ffmpeg -y -f concat -safe 0 -i <(echo "file 'new_shot1.mp4'; file 'old_rest.mp4') -c copy patched.mp4
 ```

**只看单镜头预览**：只想验证某个镜头的提示词修改效果（如调了镜头 1 的措辞），直接看单镜头产物即可，不必拼回完整片。

## 多平台发布交付套件（platform_publish.py · 渲好一集、为那一集跑一次）

短剧要发到红果短剧/番茄短剧/快手/火龙漫剧(腾讯)时，**每个平台要的图、尺寸、投稿字段都不一样**。本脚本把这些规格固化进技能，跑一次直接产出可上传的物料。

**交付物按集落盘、每集自包含**：渲好一集就为那一集跑一次，产物全部落在**该集目录**里，系列根只放总览清单。

**规格真相源 = `platform_publish_specs.json`**：通用视频规格 + 每个平台 `required_images`(key/label/role/w/h/ratio/note/`per_episode`) + `required_fields` + `special` + `ai_declare`。**改尺寸/加平台/调需要的图只动 JSON**。

**出图规则（按平台真实投稿表单需要的图片数量出图，不重复、不漏）**：
- 每平台按其 `required_images` 逐项出图：`role=poster` 盖大号中文标题的封面（如 剧集封面 1200×1600）；`role=avatar` 中心裁切海报作头像/剧照（如 账号头像 750×750、角色剧照 240×240），无文字；`role=clean` 只缩放底图、不加任何文字（用于榜单封面等禁带文字的场景）。
- 每图可按 `per_episode` 决定"是否逐集各出一份"：`role=poster` 且 `per_episode=true` 的图，为该系列每个分集各出一张（如 剧集封面 1200×1600 逐集一份）；`per_episode=false`/非 poster 的图只出系列级一张（如 横版封面、榜单、角色剧照）。
- 当前平台（4 个）：红果短剧(字节系,3:4 1200×1600)、番茄短剧(字节系,3:4 1200×1600)、快手(9:16 1080×1920+账号头像750)、火龙漫剧(腾讯视频创作平台 mp.v.qq.com：竖版770×1080/横版1920×1080/榜单2450×800禁字/角色剧照240×240，须勾AI声明)。红果即抖音旗下，故只列红果；公众号不出。
**封面生成执行规范（写入每集分镜流程的必做环节）**
- 封面是短剧的**必交付物**：① 一张**全剧共用作品封面**（平台上传作品必传，由 `gen_hero_poster` 从 project_def 派生提示词、走生图技能生成）；② **每集各一张专属封面**（贴合该集剧情）。
- 全部走生图技能 `fxai-comfyui-image-gen` 生成，**禁用用成片抽帧当封面底图**（抽帧仅作生图失败时的兜底）。
- **每集封面提示词（COVER_PROMPT）必须在写分镜【之前】设计好**，作为模块级常量写进该集 `run_qsl1_epN.py` 顶部。发布时 `platform_publish` 用 AST 安全读取（不执行脚本），自动喂给生图技能生成该集封面；**脚本里没有 `COVER_PROMPT` 不得生成该集**（三轮自检第 1 轮硬门禁会卡）。
- COVER_PROMPT 口径：**海报式构图 + 角色锚定**，不是空镜氛围图。
  - 构图必须写死「画面下方三分之一是人物主体 / 画面上方三分之二留出深色朦胧负空间压标题」——这是海报与剧照的分界线，也是 PIL 文字层能读清的前提。
- 人物外貌**从 `project_def.characters[].prompt` 逐字派生**（不另编、不加重）；用 `COVER_ROLE` 指定角色锚定：
  `shortdrama_qsl/000.png`(女主凤希) / `shortdrama_qsl/001.png`(男主谢云澜) / `shortdrama_qsl/002.png`(沈砚之) / 逗号分隔双人(男主在前) / `None`(纯场景，仅用于该角色无形象图时)。
  🔴 **必须用短剧自己的角色形象图**（`server_subdir` + `characters[].server_index` 派生，即渲染管线同一套四视图）；**禁用用全局头像库 `avatar/000、001`**——那是凤希AI 品牌头像（女主/用户本人证件照），与剧中人物对不上，模型会直接忽略参考图（2026-10-12 双人封面事故根因之一）。
- 有角色就必须写全**穿搭 + 发型**（`check_outfit` 硬校验，参考图是裸肩头像，衣服靠提示词补）。
- 🔴🔴 **多参考图必须写引用标签 `<imageN>`（缺一个都不行）**：`COVER_ROLE` 传 N 张图，`COVER_PROMPT` 里必须逐个含 `<image1>`…`<imageN>`，把每张图显式绑到画面里的具体人物（如「`<image1>` 是画面右侧的男子…`<image2>` 是画面左侧的女子…」）。标签编号 = 图片列表顺序（双人时男主在前 → `<image1>`=男、`<image2>`=女）。这是 Qwen-Image-2.1 edit 的图片绑定机制，**不写标签模型不知道哪张脸是谁、参考图被直接忽略**；`check_image_refs()` 硬拦（N>1 缺标签 ValueError，单图缺标签告警，`None` 免检）。
- 统一尾缀：冷青灰调为底 + 宫灯/烛火暖黄唯一暖光源、强明暗对比、体积光、浅景深、电影级调色、**画面里没有任何文字/字幕/可读汉字/现代物**。
- `COVER_HOOK`（可选）：该集封面底部的一句钩子文案，取自该集已确认剧情，**不演绎不编台词**。
- 全剧作品封面提示词由 project_def 的 `title` + 男女主外貌自动派生（`_series_cover_prompt`），角色图由 `_series_role_refs(pd)` 派生（server_index 0=女主 / 1=男主，男主在前），不贴任一集。

**封面文字层（全部由生图模型画入，2026-10-12 用户定，PIL 只裁切不叠字）**：
- 🔴 **所有中文（剧名/集数/集名/印章/钩子句/标签）都由生图模型一次画入**：排版指令（位置+字体+颜色+「所有中文必须清晰可读、笔画完整、无错字无乱码」）全部写进 `COVER_PROMPT`；`poster_cover`/`composite_cover`（PIL 盖字）已删除，PIL 层只做裁切/缩放。
- 🔴 **竖版不加任何黑色蒙版**：生图提示词已要求「画面上方留深色朦胧负空间」，底图自带明暗结构。
- 提示词里的固定排版：剧名 → 「第N集」章 → 集名大字（魏碑书法体、金色渐变、墨色描边）→ 朱红印章 → 钩子句 → 标签行；标签行写「画面底部往上约百分之十五处」，避开火龙竖版封面底部 16% 安全禁区。
- 全剧封面：顶部分类标签 → 剧名大字 → 一句话卖点（用 `cover_hook`，≤24 字；长句模型会自行编乱字）→ 规格行「第一季 · N集」。
- 🔴 **单版口径（用户 2026-10-12 定）**：每张封面只生【一版】最大竖版主图（1080×1920），其余平台尺寸全部本地 `_center_crop_resize` 等比裁切（竖裁横时窗口偏上 30%，保住标题文字与人物上半身），**每个尺寸只做本地裁切**。火龙榜单图 2450×800 规格禁任何文字 → 无文字专用底图 `gen_rank_base` 单独生一版（全系列共用，缓存 `cover_rank_base_WxH.png`）。头像/剧照小图裁女主角色参考图头肩区（`crop_ref_face`）。
- 兜底链路不变：生图失败 → 主海报 → 抽帧。


- 全剧作品封面底图（图片层）→ 走生图技能 `fxai-comfyui-image-gen` 生成（`role` 由 `_series_role_refs(pd)` 派生男女主同框，提示词 `_series_cover_prompt` 从 project_def 派生，图近黑（亮度<15）才退回系列最亮场景/角色图）；每集封面底图 → 优先该集脚本 `COVER_PROMPT` + `COVER_ROLE` 走生图技能生成（见上方执行规范）。**所有文字层也由模型画入，本地不叠任何字**。
- **封面/交付文案只写剧集规格**：project_def 的 `status`（如「剧本档案已完成…开拍第1集（资产生成中）」）是内部制作状态，交付文案/封面只写「第一季 · 20集」这类对外规格。季与集数由 `season`(默认 1)/`season_label`/`total_episodes` 决定，改季名或换季只动 project_def。每集封面只有「第N集·集名」一行大标题，副标题「第一季 · 20集」只画在整剧主封面（`<平台>/图片_cover_*.jpg`）上。
- **集号一律取集目录名开头的数字**（`_ep_index()`：「2、假意庇护」→ 2）；本次列表的序号不作集号——只跑一集时列表只有 1 项、序号恒为 1，会把 ep2 的封面写成「封面_ep1_*」、文案写成「第N集」错号。目录名没数字才退回排序位。
- **每集独立封面**：`per_episode=true` 的 poster 图为该集出一张（底图**优先用该集分镜脚本里的 `COVER_PROMPT` + `COVER_ROLE` 走生图技能生成，只生一版最大竖版主图 1080×1920**，各平台尺寸本地裁切）；无提示词或生图失败才退回主海报 / 抽帧，存 `<集目录>/发布/<平台>/封面_epN_WxH.jpg`。横版/榜单/剧照等 `per_episode=false` 的图在该集目录下各出一张（同一批底图派生）。

**产物落点（每集一套，随集走）**：
- `<集目录>/发布/<平台>/`：`图片_<key>_WxH.jpg`（该平台所需各图）+ `封面_epN_WxH.jpg`（本集封面）+ `<平台>_展示页.md`（投稿表单字段预填，可直接复制粘贴）。**整目录可直接上传。**
- `<集目录>/发布/剧情介绍.md`：该集投稿共用的剧名/简介/角色/标签/AI声明。
- `<集目录>/发布/本集交付清单.md`：该集各平台要传什么，逐条对照。
- `<系列根>/发布/_base/`：共享底图与抽帧缓存（主海报全系列只生一次，`cover_main_base.png` 存在即复用，不重跑 ComfyUI）。
- `<系列根>/发布/总览_交付清单.md`：跨集总览。

## 产物落点 & 完成判据
- ComfyUI 分段/合并片默认存 `sucai/`；最终合并片在 `merged/`（`fxai_时间戳.mp4`）。
- 产物查询：fxai-toolkit 节点不写 /history → `POST /fxai/tasks/result {"prompt_ids":prompt_id}`；提交时记 prompt_id。
- **完成判据**：接口返回结果里包含 `merged` 目录名 = 全部生成+合并完毕；返回空对象 `{}` = 未生成完，继续轮询。
- 🔴 **资源存在性确认（如 `shortdrama_xjz/005.png` 参考图）只走接口**：ComfyUI 是服务器端模式、可能装在另一台机器，本机 `find`/`ls` 扫到的结果不作准。直接提交工作流被 `queued` 即证明服务端已读到；或 `GET /fxai/down/file?url=<category/subdir|file>` 探测。通用铁律见 `fxai-workflow` 技能。
