# 08 · 步骤类型与回执

流程 JSON 里每一步的 `do` 取值、通用字段，以及每次执行留下的运行记录与回执口径。

## 步骤类型速查

| `do` | 作用 | 关键字段 |
|---|---|---|
| `open` / `goto` | 从站点配置读地址并**粘贴**打开 | `url`（留空读 `upload_url`）、`wait_ms` |
| `click` / `dblclick` / `rightclick` | 点区域（或相对坐标） | `region` 或 `at` |
| `type` / `paste` / `fill` | **默认都走剪贴板粘贴**（`fill` 会先点输入框） | `text`、`clear`、`literal`、`wpm` |
| `select` | 在框内拖选文本（**替代 Ctrl+A**） | `region` 或 `at`+`w`+`h`、`multi`、`to_end` |
| `drag` | 鼠标拖选 / 拖拽 | `region` 或 `from`+`to`（相对客户区） |
| `modal` | 点掉 Chrome 独立确认窗（离开此网站 / 重新加载） | — |
| `key` / `combo` | 按键 / 组合键 | `key`、`keys` |
| `scroll` | 滚动 | `clicks`（负下正上）、`region` |
| `file` | 等系统文件对话框并**粘贴**路径 | `path` |
| `probe` | 局部截图校验 / 学模板，不点击 | `region`、`learn`、`color`、`text`、`on_miss` |
| `preflight` | 开工诊断：锁屏 / 原点 / 吞点击确认窗（默认自动点掉） | `strict`、`dismiss` |
| `wait` / `wait_stable` / `wait_change` | 定长等 / 等画面静止 / 等画面变化 | `ms`、`region`、`timeout_ms` |
| `pause` | 真人停顿（只在真需要想 / 看的地方放） | `kind`（`read` / `hesitate` / `think` / 自动） |
| `login_gate` | 判断是否在登录页，需要人时停住 | `expect`、`bad`、`block` |
| `gate` | 任意人工节点 | `prompt`、`block` |
| `shot` / `note` | 截图存档 / 写日志 | `name`、`text` |

### 表单录入（铁律 30）

```json
{"do": "fill", "region": "title_box", "text": "{title}"},
{"do": "fill", "region": "desc_box", "text": "{desc}", "clear": true}
```

`fill` = 点框 →（可选 `clear`：**框内拖选 + Shift+End + Delete**）→ 剪贴板 + Ctrl+V → 恢复原剪贴板。
`type` 默认也改成粘贴，只有 `"literal": true` 才逐字敲。
**禁止用 Ctrl+A 清空**：焦点不在框里时 Chrome 会选中整页（2026-11-11 抖音事故）。
要「先选整行再替换」用 `{"do":"select","region":"title_box"}` 再 `paste`；
多行框加 `"multi": true`。老步骤只给 `clear` 不给框时，会自动改用整页选中检测兜底。

### 点击前局部校验（铁律 29）

```json
{"do": "click", "region": "publish_btn", "probe": true, "terminal": true}
```

`probe` 可为 `true` 或 `{"on_miss": "abort"}`；`on_miss` 取 `relocate`（默认）/ `abort` / `warn`。
不带 `probe` 的步骤行为与旧版完全一致。

### 相对底边的临时坐标

```json
{"do": "click", "anchor": "bottom", "at": [424, 182], "w": 96, "h": 36}
```

`at = [x, 距视口底边像素]`。正式流程优先用台账 `region`（带 `anchor: bottom`），
临时探路才用 `anchor` 内联。

## 通用字段

| 字段 | 作用 |
|---|---|
| `chain` | 同值相邻步骤视为一条连续动作，几乎不停 |
| `glued` | 只粘住这一步 |
| `no_pause` | 这一步之后完全不停 |
| `optional` | 失败跳过不中断 |
| `terminal` | 本站最后一个动作；点完不截 final 图 |
| `probe` | 点击前只截该区域 ROI 校验，命中才点 |
| `on_miss` | 校验未命中时：`relocate` / `abort` / `warn` |

`block=false`（默认）时人工节点**不阻塞**，直接返回 `need_user` 交上层去问人；`block=true` 才在控制台等 `F9`。人工验证要用 `gate` 明确「叫人 + 等人」，不静默卡住。

## 输出与回执

每次执行在 `<hub>/runs/<时间戳>/` 下留 `log.jsonl` 与 `shots/`：每步耗时、停顿次数与累计时长、失败时的现场截图。发布结果按 `fxai-browser-publish` 的项目回执规范写回项目目录。

## 命令速查（`publish_cli.py` 全量）

```bash
S="$HOME/.workbuddy/skills/fxai-physical-publish/scripts"

python -B $S/publish_cli.py env                          # 环境与通道自检
python -B $S/publish_cli.py selftest                     # 安全自检：轨迹 / 点击 / 输入真实生效
python -B $S/publish_cli.py snap --out x.png             # 截客户区，供定位
python -B $S/locate.py --color blue --y0 600 --y1 900    # 按颜色定位控件矩形
python -B $S/publish_cli.py regions --site <站点>         # 查看已录区域
python -B $S/publish_cli.py preflight --site <站点>        # 锁屏 / 原点 / 吞点击确认窗
python -B $S/publish_cli.py mark --site X --name publish_btn --anchor bottom --color ksred --text 发布
python -B $S/publish_cli.py probe --site X --name publish_btn            # 只截局部校验
python -B $S/publish_cli.py probe --site X --name publish_btn --relocate  # 未命中才全屏重定位
python -B $S/publish_cli.py reanchor --site X --names publish_btn --anchor bottom  # 存量迁移
python -B $S/publish_cli.py run --site <站点> --inline '[{"do":"open"}]' --fast   # 干跑
```

实例目录里的 `publish_cli.py` 是可选的转发壳，转发到本包引擎。
