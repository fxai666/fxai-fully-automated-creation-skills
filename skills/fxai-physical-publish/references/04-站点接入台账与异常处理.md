# 04 · 站点接入台账与异常处理

接入单位是「**站点 × 内容类型**」。每接一格按下列顺序走，跑通即回写区域与流程。

## 一、接入九步

1. **开窗**：`launch --fit 1500x900`，把客户区固定。之后所有录制与执行都在这个尺寸下。
2. **登录**：`open` 打开站点，若跳到登录页，流程里放 `login_gate` 停住，由用户亲手登录。
   `login_gate` 只读**窗口标题**判断是否还在登录页，不读页面内容、不读 cookie。
3. **找地址**：从站点后台或导航进到发布页，把**最终落地地址**写进台账 `upload_url`
   （不含会话令牌、一次性参数、账号标识）。之后 `open` 只读配置，不重复分析。
4. **截屏**：`snap` 或流程里的 `shot`，看清页面上有哪些控件。
5. **定位**：纯色按钮用 `locate.py`；其它用 `record`/`mark` 人工框选。
6. **录区域**：按从上到下、从外到内的顺序录，命名用「动词_对象」：`upload_entry`、`title_input`、
   `desc_input`、`submit_btn`。一屏放不下就分滚动状态录，并在 `note` 里写清是哪个滚动位置。
7. **写流程**：`flows.video` 按步骤表写，顺序 = `open` →（`login_gate`）→ `click` → `file`
   → `wait_change` → 填字段 → `hesitation` → `click submit` → `wait_change` → `shot`。
8. **干跑**：`--fast` 跑一遍看每一步是否落在预期控件上，失败就看 `shots/error.png`。
9. **正式跑**：`scale=1.0`，`log.jsonl` 留档，结果写回项目回执。

## 二、通用流程骨架（视频发布）

```json
[
  {"do":"focus"},
  {"do":"open","wait_ms":6000},
  {"do":"login_gate","expect":["<登录后标题关键字>"]},
  {"do":"pause","kind":"read"},
  {"do":"click","region":"upload_entry"},
  {"do":"file","path":"{video}"},
  {"do":"wait_change","timeout_ms":60000},
  {"do":"pause","kind":"read"},
  {"do":"click","region":"title_input"},
  {"do":"type","text":"{title}","clear":true},
  {"do":"click","region":"desc_input"},
  {"do":"paste","text":"{desc}"},
  {"do":"hesitation"},
  {"do":"click","region":"submit_btn"},
  {"do":"wait_change","timeout_ms":60000},
  {"do":"shot","name":"submitted"}
]
```

变量用 `--var video=... --var title=...` 传入，或由上层从项目 `发布材料.json` 读取后注入。

## 三、实测踩过的坑（务必先看，省几小时）

1. **输入法吞键**：真实键位输入的 ASCII 被中文 IME 合成成汉字。
   → 可见字符一律 `KEYEVENTF_UNICODE`；回车/退格仍走键位。
2. **系统文件对话框在独立进程**：Chrome 的「打开」对话框 pid 与浏览器主窗口不同，
   按 pid 匹配永远抓不到。→ 按「程序名 + 窗口类 `#32770`」匹配。
3. **权限气泡是小 Chrome 窗口**：通知/下载气泡也是 `Chrome_WidgetWin_1`，客户区只有几百像素宽，
   枚举时会抢到它，导致截图对不上、点击错位。→ 按客户区宽度 ≥600 过滤，并排除 `Chrome_WidgetWin_0`。
4. **最小化的窗口客户区被压到几十像素**：会被「宽度过滤」误判成"没有窗口"。
   → 最小化窗口要单独识别并先 `SW_RESTORE`。
5. **截图前必须激活**：窗口被遮挡时截到的是遮挡物，表现为"整页找不到目标颜色"。
6. **预览图上的像素不是坐标**：截图若被缩放显示（如 1500×910 显示成 1092×642），
   换算比约 1.374，直接拿预览坐标去点会整体偏小。
7. **用户同时操作会抢焦点**：人在对话窗口打字时，前台窗口切走，此后的点击会落到对话窗口上。
   → 关键点击前校验 `GetForegroundWindow() == 目标`，不等则重新激活，仍不等则报错停下。
8. **下拉列表从"当前选中项"开始展开**：想选它上面的项要往回滚，往下滚永远是反方向。
9. **弹窗会挡住后续控件**：发布页常见"上传完成通知"引导弹窗和通知权限气泡，
   先关掉再操作，否则截图判断全被盖住。
10. **粘贴打开地址比逐字敲稳**：地址栏逐字敲中文域名会被 IME 干扰，统一 `Ctrl+L` → 写剪贴板 → `Ctrl+V`。
11. **合集入口点空白处不响应**：小红书「加入合集」整行只有文字可点，点行内左侧空白不弹面板。
    → 对准文字坐标（该行文字起点附近）点，或直接用行右侧的「创建合集」链接。
12. **没有合集时点「加入合集」直接弹创建框**：不是"列表为空"，而是省掉了列表这一步。
    看到创建框不要以为点错了，那正是"该账号零合集"的信号。
13. **跨站跳转被「离开此网站？」卡住**：上一个页面有未保存表单时，Chrome 会弹模态确认框，
    标题一直不变，此后所有截图/点击都落在旧页面上。批量核查时会表现为
    「后面几个站点都显示未登录」，实际是**根本没跳过去**。
    → 导航后轮询窗口标题确认到达；卡住就 **Tab → Enter**（默认焦点在「取消」，Tab 一次到「离开」）。
    **绝对不要按坐标点这个框**：它是浏览器自绘的，位置随窗口尺寸变，实测点偏过一次，
    点到了页面上的链接，直接跳到垃圾站。
14. **锁屏后物理通道全废**：工作站锁定后输入桌面交给 Winlogon，
    `SendInput` 返回错误码 5（拒绝访问），`BitBlt` 直接失败，`SetForegroundWindow` 返回 0。
    现象是「窗口激活不了」「点了完全没反应」「截图报 BitBlt 失败」。
    → 动手前先 `api.is_locked()` / `api.assert_ready()`；锁了就停下告诉人，不要重试空转。

## 三之二、合集对齐（跨平台统一）

合集**不是每个平台各起一个名字**，唯一来源是 `<hub>/config/collections.json`：

```json
{ "canonical": [{ "key": "ai_music_mv", "name": "AI原创音乐MV",
                  "desc": "凤希AI 原创音乐 MV 合集",
                  "sites": { "bilibili": {"state":"existing"},
                             "xiaohongshu": {"state":"existing"} } }] }
```

执行顺序：

1. 查 `sites/<站点>.json` 的 `collection` 字段。`state=existing` → 页面里选中同名项即可。
2. 台账没有或 `state=created` 但站点已重登/清空 → 打开「加入合集」，**先看列表里有没有同名项**。
3. 列表里有 → 选它，回写 `state=existing`。
4. 列表里没有（直接弹创建框）→ 按 `canonical.name` **原样**填名称、填 `canonical.desc` 简介，创建。
5. 创建后立刻回写站点台账 `collection` 与清单里该站 `state`。

**禁止**：平台化改名（`AI原创音乐MV-小红书版`）、临时替代名（`音乐MV合集`）、
为了"先发出去"跳过合集。名称不一致会让各平台合集割裂，用户侧检索不到同一条内容线。
