# 09 · 底部锚定、局部校验与粘贴录入

> 2026-11-11 用户口径固化：**「滚动到底部过后，记距离底部多高不就完事了吗」**
> 「第二次就按已有的坐标范围截取那一部分，看一看有没有，没有的情况下再去全屏重新获取」
> 「标题、内容直接用复制粘贴发送数据，不用挨个输」

这一册解决一个反复出现的问题：**发布按钮点不中**。

## 一、根因复盘（快手，2026-11-11 06:38~07:22）

页面底部「发布时间」下面会动态插入一条橙色提示：「你的粉丝在 20:00 到 21:00 点活跃，
在该时间发布可提升流量～ 一键设置」。这条一出现，下面的红色「发布」按钮整体下移。

| 记录 | 坐标 | 结果 |
|---|---|---|
| 11-09 `publish_btn` | `[424,700,2,2]`（中心点） | 当时滚到底后有效 |
| 11-11 06:43 `publish_btn_2026` | `[378,573,92,32]` | 流量提示条出现后按钮下移，按 y=573 **连点落空** |
| 07:4x 从 `ks_34_publish.png` 像素扫描 | `[376,682,96,36]`，中心 `(424,700)` | 真实位置，**距视口底边 182px** |

差 109px。用户手动点一下立刻发布成功 —— 说明按钮一直是好的，是我们的坐标错了。

**同一轮还有两个叠加干扰**，不可只怪坐标：

1. Chrome「离开此网站？」是**独立顶层窗口**（`Chrome_WidgetWin_1`），窗口截图 BitBlt 看不见，
   但吃掉所有鼠标点击，表现为「键盘/滚轮有效、点击全失效、截图零变化」；
2. 客户区原点会变：`launch` 新窗口 `(48,40)`，`reveal --w 1440 --h 900` 后 `(8,0)`；
   截图是客户区坐标、点击按屏幕坐标换算，原点一变按旧图点就整体偏 40px。

三者叠加时，「按老坐标反复点、页面毫无变化」看起来就像平台静默拒绝，其实是根本没点在按钮上。

## 二、四条机制

### 1. 发布控件锚定到视口底边（铁律 28）

滚到滚动条底部后，视口显示文档末尾；上方增删行只让滚动条多滚一点，
**按钮到视口底边的距离不变**。所以发布 / 提交 / 发表按钮记：

```
bottom_offset = 录制时客户区高度 - (rect.y + rect.h)
解析时 y = 当前视口底边 - bottom_offset - h
```

- 控件是固定像素，`h` 不按视口高度缩放（缩放会让 y 偏 3px，故不缩放）；
- 底部锚定只校验客户区**宽度**偏差，视口高度变化不误报「请重录区域」；
- 执行前必须滚到底，区域带 `scroll_state: "bottom"` 作提醒；
- 弹窗内部按钮、不贴底的控件保持 `top`（如小红书 `collection_submit`）。

```bash
publish_cli.py mark --site X --name publish_btn --anchor bottom --color ksred --text 发布
publish_cli.py reanchor --site X --names publish_btn --anchor bottom   # 存量迁移
```

迁移是**零回归**的：同尺寸下 `resolve` 的 y 与旧 rect 完全一致（脚本已逐站复核 13 站，0 处不一致）。

### 2. 只截那一小块校验（铁律 29）

记过坐标之后，第二次不整屏截图。按已有 rect 外扩 12px 抓 ROI，与模板比对：

- 灰度网格指纹（20×8）平均绝对差 ≤ `tolerance`（默认 0.12）；
- 按钮主色占比 ≥ `min_ratio`（默认 0.20，快手 0.25）；
- 命中 → 直接点；未命中 → 才全屏扫主色重定位 → 回写台账 → 重学模板 → 复验 → 通过才点；
- 找不到候选或复验仍失败 → 停下报错，**绝不盲点**。

主色用 `locate.py` 的 `PRESETS`（`ksred` 是快手品牌红 `#F83060`）。
模板 PNG 存 `<hub>/shots/probes/`，台账只存指纹数组与路径，不含页面数据。
截图前把鼠标挪到 ROI 外，防止 hover 变色干扰（实测 hover 差异 0.0092，远低于阈值 0.12）。

```bash
publish_cli.py probe --site X --name publish_btn                 # 只截局部 + 判定，返回 rc=2 表示未命中
publish_cli.py probe --site X --name publish_btn --learn         # 重学模板
publish_cli.py probe --site X --name publish_btn --relocate      # 未命中才全屏重扫并回写
```

流程里：`{"do":"click","region":"publish_btn","probe":true,"terminal":true}`。
`on_miss` 默认 `relocate`；发布按钮建议 `{"probe":{"on_miss":"abort"}}`，宁可停下也不乱点。

### 3. 表单文本一律粘贴（铁律 30）

```json
{"do": "fill", "region": "title_box", "text": "{title}"},
{"do": "fill", "region": "desc_box", "text": "{desc}", "clear": true}
```

`fill` = 点框 →（可选清空）→ 剪贴板 + Ctrl+V → 恢复原剪贴板。
`type` 默认也改成粘贴，只有 `"literal": true` 才逐字；`file` 对话框路径同样改粘贴。
理由：中文逐字 `KEYEVENTF_UNICODE` 会被 IME 吞、长文本慢且掉字；粘贴是真人动作且一次到位。

⚠️ 抖音复合编辑框**空表单不得 `clear`**（Ctrl+A 会整页全选，整段描述塞进 30 字标题框）。

### 4. 开工前置诊断（铁律 31）

`run` 开头自动跑，也可单独跑 `publish_cli.py preflight --site X`：

```json
{"locked": false, "origin": [8,0], "client": [8,0,1440,900],
 "foreground": 196864, "windows": 8, "blockers": [], "client_deviation": 0.0}
```

- `locked` 为真 → 别空转，先解锁；
- `origin` 与上次不同 → 现场重录坐标或 `reveal --w 1440 --h 900` 固定回 `(8,0)`；
- `blockers` 非空 → 独立确认窗在吞点击，按铁律 19 **只用 Tab → Enter**，不按坐标点；
  `{"do":"preflight","strict":true}` 会直接阻断流程。

## 三、推荐动线（写流程 JSON 时）

```json
[
  {"do": "preflight"},
  {"do": "focus"},
  {"do": "open"},
  {"do": "file", "path": "{video}"},
  {"do": "wait_stable", "required": false},
  {"do": "fill", "region": "title_box", "text": "{title}"},
  {"do": "fill", "region": "desc_box", "text": "{desc}"},
  {"do": "scroll", "clicks": -20, "region": "desc_box"},
  {"do": "wait_stable", "required": false},
  {"do": "probe", "region": "publish_btn", "on_miss": "abort"},
  {"do": "click", "region": "publish_btn", "probe": true, "terminal": true}
]
```

`probe` 步骤是**发布前的门**，不是发布后的验收：按铁律 27，点完发布只看有无错误提示，
没有就立刻收工，不截图、不开作品、不复核。

## 四、排查顺序（点不中时照这个走）

1. `preflight` —— 锁屏？确认窗？客户区原点？
2. `probe --site X --name publish_btn` —— 只截那块，看还是不是发布按钮；
3. 未命中 → `probe --relocate`，或现场 `snap` 后 `locate.py --color ...` 重扫；
4. 用 `mark --anchor bottom --color ... --text ...` 重录；
5. 命中但仍无反应 → 才怀疑按钮 disabled（颜色变浅）或需要回车补提交（快手旧版曾如此）。

**不得做的事**：按截图目测比例反推 y；复用上一次的旧 rect；同一坐标连点三次以上；
把「点击全失效」直接归因为平台静默拒绝。

## 五、Ctrl+A 会把整页选中（2026-11-11 抖音事故）

**现象**：点完标题框按 `Ctrl+A`，左侧导航、右侧预览、整页文字全变蓝；随后一粘贴
就把整页内容覆盖，标题框被塞进截断的乱码（`30/30` 满格）。

**根因**：`Ctrl+A` 是**浏览器级快捷键**。只有焦点确实落在可编辑元素里，页面才会把它
拦下来当「全选本框」；焦点一旦在 `body` 或非可编辑容器上，Chrome 就执行「选中整页」。
前一步 `click` 没点进输入框（点在字段留白/图标上、字段是复合编辑器）就会这样。
`type`/`fill` 的 `clear:true` 走的就是 `Ctrl+A` + Delete，所以直接踩中。

**规则**：

1. 表单清空**只用框内拖选**：`clear` 带 `region`/`at` 时改走 `drag` 右→左 + `Shift+End` + `Delete`，
   全程不发 `Ctrl+A`；焦点跑偏也只是选区落空，不会波及整页。
2. 要「先选整行再粘贴替换」用 `select` 步骤（`region` / `at`+`w`+`h` / `multi` / `to_end`）。
3. 老步骤没带框、只能退回 `Ctrl+A` 时，按完立刻用 `selection_ratio()` 验：整屏「选中蓝」
   占比 > 0.22 判为误选整页，点一下空白取消选区并改走拖选兜底，日志记
   `page_select_detected`，绝不带着整页选区继续粘贴。
4. 单行字段（如抖音标题 30 字上限）粘贴内容超长会被截断并弹错，**必须先选中整行**。

## 六、确认窗当普通弹窗点掉（用户口径）

「离开此网站？」「要重新加载吗？」是 Chrome 的**独立顶层窗口**，不在页面截图里，
但会吞掉所有点击。**它不是阻塞**：`preflight` 默认直接点右下角主按钮（离开 / 重新加载 / 确定），
点不掉再退 `Enter` → `Tab+Enter` → `Shift+Tab+Enter`，日志记 `modal_dismissed`。
`open` 步骤在跳转后也会自动处理一次。只有 `dismiss:false` / `preflight --no-dismiss` 才只看不动。
