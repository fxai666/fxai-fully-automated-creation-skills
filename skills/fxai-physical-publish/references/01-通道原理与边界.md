# 01 · 通道原理与边界

## 一、这条通道到底做了什么

程序通过 `user32.SendInput` 向系统输入队列投递**真实的输入事件**，与物理鼠标键盘发出的事件
在系统层面同源：前台窗口收到的是 `WM_MOUSEMOVE` / `WM_LBUTTONDOWN` / `WM_CHAR`，
页面里触发的也是同样的 `mousedown` → `mouseup` → `click` → `input` → `keydown` 事件序列。

因此它与自动化通道（CDP / Playwright）的本质区别：

| 维度 | 自动化通道 | 本通道 |
|---|---|---|
| 控制点 | 浏览器调试协议，直接操作渲染层节点 | 操作系统输入队列，只能作用于前台窗口 |
| 页面可感知 | `navigator.webdriver` 等痕迹、事件 `isTrusted` 语义差异 | 与真人按键无差别（事件全部为系统派发） |
| 能否读页面 | 能（DOM / 网络 / cookie） | **无法**，只能看屏幕像素、只能读窗口标题 |
| 稳定性 | 依赖选择器，改版即失效 | 依赖坐标与画布尺寸，改版需重录区域 |
| 速度 | 快 | 慢（含真人停顿，一条发布流程通常 3~10 分钟） |

## 二、能力边界（做不到的事，不得承诺）

- **读不到页面内容**：无法取标题、取错误文案、判断某字段是否必填。只能靠截图 + 人眼/模型看。
- **拿不到登录态**：不读 cookie，因此「上次登录过」这件事只由浏览器自己记得。
- **无法并行**：系统鼠标只有一个，同一时刻只能操作一个窗口。
- **无法后台运行**：目标窗口必须在前台；用户此时无法同时用鼠标。
- **受遮挡影响**：任何窗口盖住目标区域，截屏和点击都会落到遮挡物上。

## 三、坐标体系

三层坐标，转换必须显式：

1. **屏幕坐标**：`SendInput` 的绝对坐标，按虚拟桌面归一化到 0..65535。
2. **客户区坐标**：相对窗口客户区左上角，**这是区域台账唯一存储的形态**。
3. **截图坐标**：截图就是客户区，尺寸 = 客户区尺寸；若截图被缩放显示（例如按比例预览），
   换算回客户区必须乘回缩放比，**不得直接拿预览图上的像素当坐标**。

换算公式：

```
屏幕点 = 客户区原点(ClientToScreen) + 客户区坐标
```

## 四、多显示器与 DPI

- 进程启动即置 DPI 感知（`SetProcessDpiAwareness(2)`），否则 125%/150% 缩放下坐标会整体偏移。
- 绝对坐标按**虚拟桌面**范围归一化（`SM_XVIRTUALSCREEN` 等），跨屏也能落到正确位置。
- 客户区原点可能为负（副屏在左/上），一律通过 `ClientToScreen` 求，不得假设从 0 开始。

## 五、安全与止损

- **长按 ESC 中止**：看门狗线程轮询 `GetAsyncKeyState(VK_ESCAPE)`，连续命中即抛出中止，
  正在等待的步骤立即返回。
- **失败即留现场**：任何步骤异常都截一张 `shots/error.png`，便于人眼核对。
- **不猜不凑**：找不到窗口、找不到对话框、画布尺寸不符，一律报错停下，不做「差不多就行」的兜底。

## 六、窗口生命周期：只有一个，一直用下去

窗口策略是「复用优先」，不是「每次开一个新的」。理由很实在：多出来的窗口、堆满的标签页，
比鼠标轨迹更容易被人一眼看出来——真人干活就那么一个窗口，跳来跳去都在里面。

### 挑选顺序（`browser.ensure_window`）

1. **上次用过的那个**：`config/window.json` 里记着 hwnd，窗口还在就直接用。
2. **现有主窗口**：上次那个被关了，就在当前打开的窗口里挑客户区最大的主窗口
   （`main_windows()` 已排除权限气泡、下载气泡、`Chrome_WidgetWin_0`）。
3. **一个都没有**：才 `launch()` 启动浏览器。启动时不带任何自动化开关。

### 运行期约定

| 场景 | 正确做法 | 错误做法 |
|---|---|---|
| 换站点 | 同标签 `Ctrl+L` → 粘贴 → 回车 | `Ctrl+T` 新开标签、开新窗口 |
| 流程结束 | 保持原样退出 | 关闭窗口、最小化、改尺寸 |
| 需要人操作 | `reveal`：**取消置顶** + 靠左缩窗 → 人做完 → `release` 还原 | `HWND_TOPMOST` 置顶，把对话窗口压在下面 |
| 要跟人说话 | `minimize` 最小化，屏幕整个让给对话 | 让窗口留在前台挡着 |
| 客户区尺寸漂移 | `focus()` 自动 resize 回录制尺寸 | 按新尺寸硬点（坐标全错） |

### 记录与失效

`remember(hwnd)` 在每次 `focus` / `resolve_window` / `launch` 后写 `config/window.json`：

```json
{ "browser": { "hwnd": 1443388, "title": "小红书创作服务平台 - Google Chrome",
               "client": [1500, 910], "at": "2026-11-08 09:56:12" } }
```

hwnd 在窗口未关闭期间稳定；**系统重启或窗口被关后失效**，此时自动退化为「选最大主窗口」，
不需要人工清理配置。文件缺失也不报错，按无记录处理。

### 为什么不用标签页编号

标签没有稳定的窗口句柄，按标签标题匹配又会随页面标题变化而失效。用「窗口 + 当前标签」
这一层最稳：窗口有 hwnd，标签则由 `Ctrl+L` 直接接管地址栏，不依赖任何页面内部结构。

## 七、什么时候走本通道

| 场景 | 选哪条 |
|---|---|
| 要求完全像真人手动操作、不希望被识别为自动化 | **本通道** |
| 站点有强行为风控、需要随机节奏与真实轨迹 | **本通道** |
| 站点页面结构频繁改版、选择器维护成本高 | **本通道**（改坐标不改代码，或重录区域） |
| 只要快、要批量、要稳定重放 | 走 `fxai-browser-publish` |

两条通道**共用同一个实例目录**（站点台账、运行记录、发布物料都在实例侧），互不覆盖：
自动化通道写 `config/sites/<站点>.json`，本通道写 `sites/<站点>.json`。
