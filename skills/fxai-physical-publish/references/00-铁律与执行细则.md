# 00 · 铁律与执行细则

`SKILL.md` 只列每条铁律的判据一句话；本册给全文、例外与处置。执行前逐条对照，冲突时以本册为准。

## 一、31 条铁律（28~31 为 2026-11-11 新增，详见 `09-底部锚定与局部校验.md`）

### 1. 零注入

不用无头浏览器、不接 CDP、不 `evaluate` 页面脚本、不改页面 DOM。浏览器必须以用户日常使用的方式启动，不带任何自动化开关。

### 2. 零凭据

不读不写 cookie、不存 storage_state、不保存登录态。需要登录时**停下来等人**亲手登录，程序只做「判断是否还在登录页」。

需要**人工验证**（短信码 / 人脸 / 扫码 / 密码 / 滑块）时不适用「静默停下」，按第 17 条主动点发送验证码、在对话里叫人、人配合完继续做，**不许没反应**。

### 3. 坐标可固定，行为必须随机

区域坐标录一次固定下来；鼠标轨迹、按键节奏、动作间隙每次重新抽样。禁用固定延时——固定延时会形成可统计的节律。

### 4. 停顿跟着动作走，不跟着步骤走

连贯动作用 `gap`（0.04~1.8s，手挪过去就行），只有「要看、要找、要想」才用 `pause`（长尾 0.5~120s）。**禁用每步之后都停一次**：把点框、打字、再点下一个框切成一段段，比机器还假。

### 5. 拍摄前先激活

窗口被遮挡时截到的是遮挡物，表现为「整页找不到目标」。任何截图 / 点击前必须确认目标窗口在前台。

### 6. 区域存相对客户区

坐标相对窗口客户区原点，并记录录制时的客户区尺寸；偏差超过 4% 拒绝执行并提示重录。绝对屏幕坐标一律不存。

### 7. 只按区域点，不按像素猜

区域要用工具定位后录入（像素扫描 / 人工框选），不允许手写估算坐标。

### 8. 让人动手就别置顶，要跟人说话就最小化

人工环节先 `reveal`：**取消置顶**、靠左缩窗，用户点一下对话窗口就能把它盖住。一旦要把控制权交回对话（汇报、提问、抛 `NeedUser`），立刻 `minimize` 把屏幕整个让出来；人做完用 `release` 还原录制尺寸。

**任何时候都不得 `HWND_TOPMOST`**——置顶会把对话窗口压在下面，用户连「我该干什么」都看不见。

### 9. 随时可中止

长按 `ESC` 立即停止；程序不得吞掉用户的按键。

### 10. 一次只操作一个窗口

目标窗口不唯一时先 `windows` 确认，禁用盲点。

### 11. 人工闸门不可跳过

登录、投稿提交等外发动作，必须有明确的人工确认节点。人工验证按第 17 条走「主动点发送验证码 + 叫人 + 继续」，不是静默闸门。

### 12. 流程必须能一条命令重放

不许边跑边由模型现算坐标：模型思考的卡顿会混进节奏里，下次也没法复现。

### 13. 窗口只有一个，一直用下去

能复用就绝不开新的——先复用上次那个（`config/window.json` 记着），没有再退到现有主窗口，一个都没有才启动。

**流程结束不关窗口、不新开窗口、不 `Ctrl+T` 堆标签**，换站点就在同一个标签里粘贴地址跳过去。多出来的窗口和标签本身就是最容易看出来的破绽。

### 14. 合集以 B 站为唯一标准，且 B 站必须第一个发

合集名与简介由 B 站在先创建，后面所有平台照抄。站上已有同名合集 → 直接选；没有但界面能建 → 按原名建，不加后缀、不改字；**界面不提供创建功能 → 停下来告诉用户，由用户手工建，之后我再选**，绝不用近似名凑、也绝不跳过。站点没有合集概念 → 记 `collection: "n/a"`。

清单见 `<hub>/config/collections.json`，细则见 `06-流程迭代与合集文案规范.md`。

### 15. 动态项一律现场读，绝不写死

推荐话题、现有合集、分区、可见范围这些内容每次执行都可能变，必须当场看当场选。**写死的只在台账里的坐标**，可选项永远从当前页面取。

### 16. 文案分两层，不得一套通发

**B 站走技术向**（制作链路、模型、参数、制作细节，技术人群要信息密度），**其余平台走娱乐向**（情绪、氛围、第一行钩子、流量标签）。技术细节在娱乐向里只留一句，不展开。品牌标记「凤希AI」所有平台都要出现。唯一来源是项目的 `平台文案.json`，靠 `platforms.<站点>.tier` 区分。

### 17. 遇到人工验证：主动点「发送验证码」，把人叫过来配合，然后接着做

**任何平台**（抖音 / 快手 / 视频号 / B 站 / YouTube / TikTok…）、**任何验证类型**（短信码、人脸、扫码、登录密码、滑块、邮箱码）都适用。

1. 不停住、不静默、不存草稿走人——**立刻现场定位并点「发送验证码 / 获取验证码 / 发送短信」**（坐标按第 7 条现场扫描，不许估算）；
2. 按第 8 条 `reveal` 让位（不置顶），**在对话里明确说一句**：「需要你输入验证码，我在这儿等你，填完告诉我 / 你点『验证』我接着做」——人就在旁边配合，等一下即可；
3. 用户填完码（或完成人脸 / 扫码）后，程序只点「验证 / 确定」这个提交动作，**然后立刻按第 27 条收工，不追加任何流程**。

🔴 **绝不代收、代填、代看验证码，绝不绕过验证**；验证码只由账号本人经手。不得以「找免验证入口」「存草稿交用户」「记 `blocked_verify`」替代本流程。

### 18. 动手前先自检锁屏

`api.assert_ready()` / `is_locked()`。工作站锁定后系统把输入桌面交给 Winlogon，`SendInput` 直接返回错误码 5，`BitBlt` 直接失败——表现是「点了没反应」「截图全黑」「窗口激活不了」。**先查锁屏，再怀疑代码**。人也睡了、屏锁了，就老实停下并说明，不空转重试。

### 19. 跨站跳转先确认真的跳过去了

上一个页面有未保存内容时，Chrome 会弹「离开此网站？」把跳转卡住，此后所有截图和点击都落在旧页面上，看起来像「后面几个站点都没登录」。导航后必须轮询窗口标题确认到达，卡住就处理确认框——**只用键盘（Tab → Enter），不用坐标点**：那是浏览器自绘的框，位置随窗口尺寸变，按坐标点会落到页面链接上。

### 20. AI 生成标记是硬合规项，一票否决

内容只要有一项由 AI 生成（音乐、画面、文案任一），**每个平台都必须勾选对应声明**，一个都不得漏。各站入口名称不同（作品声明 / 内容创作声明 / 创作声明 / AI 生成的内容 / Altered content），逐站对照 `05-发布前合规清单.md`。

**找不到入口不等于可以跳过**：先滚到底、展开「显示更多 / 更多设置」，全找过确实没有，才在台账记 `declare_ai: "none"` 并写明「已全页搜索未找到」。

### 21. 原创声明有就必勾

凡是提供「原创 / 自制 / 声明原创」选项的平台，必须勾上。原创声明与 AI 标记**不冲突**——作品是我们原创的，只是生成手段用了 AI，两个都要勾。漏勾原创 = 放弃权重与维权依据，事后极难补。

### 22. 审核中就是发出去了，点完发布即收工

出现「审核中 / 处理中 / 内容审查中 / 仍在检查」即视为发布完成，**立刻结束该站：不回头等结果、不打开播放页、不比对作品数、不做可播放验收**。YouTube 尤其如此：提示「我们仍在检查你的内容」时直接点发布，别点「返回」保留私享。

**点了发布按钮，只要页面没出现错误提示，就是成功**，后面所有验收 / 复查流程一律不做，别把流程跑长。

### 23. 外发前跑一遍合规清单

`05-发布前合规清单.md` 里的勾选项逐条过，特别是「AI 标记、原创声明、封面、合集、可见范围、默认勾选项」六项——这六项是反复出问题的位置。**这是提交前的门，不是提交后的验收**。

### 24. 流程按三次迭代收敛，不许一次就想写死

第 1 次是 `v0-init` 探路（页面上全是引导弹窗、恢复气泡、首用教学，坐标会被顶偏，**此时的坐标不可全信**）；第 2 次是 `v1-observed` 提炼（干扰消失，删绕路、补坐标、压等待）；连续两次动作序列无需临时改坐标 / 绕路才升 `v2-stable`（人工验证是正常环节，不算异常介入）。

第 2 次提炼必须同时**提速**：删发布后步骤与 final 截图、固定等待改 `wait_stable`（原值只作超时上限）、填表动作串 `chain`、显式 `pause` 全删交回 `bridge` 语义、说明性 `note` 搬进台账；正式执行 `scale` 恒为 1.0，**不许用 `--fast` 冒充真人速度**。

每次跑完都要把动线写回站点台账的 `flows`，把缺的坐标记进 `flow_meta.missing`，把前后节奏预算写进 `flow_meta.speed_profile`。细则见 `06-流程迭代与合集文案规范.md` 第 2 次提炼。

### 25. 封面尺寸只准引用 key，规范归封面设计技能

站点台账只写 `"cover": {"key": "horiz_16x9"}`，项目配置只列 key 清单，任何地方都不许再写像素。尺寸、比例、各站规格、版式与验收全部归 `fxai-poster`（`references/11` + `cover_sizes.json`），本包只留指针，见 `07-封面尺寸与版式规范.md`。竖版标题一律竖排贴空余最多的一边，禁用横排压脸。

### 26. 上传没到 100% 就提交 = 造一个空壳作品

必须等「进度 100% + 封面帧出现 + 能点开预览」三样齐了再填表提交。**这三样是提交前的门，不是提交后的验收**；点完发布、没有错误提示就收工（第 22 / 27 条），不回去点开验证能否播放。

### 27. 「点发布」是本站最后一个动作

任何站点，发布提交按钮点下去之后，只做一件事——看有没有错误提示。**没有 → 立刻结束该站**，不许再截图、不许点开作品、不许跑验收清单、不许回列表数条数、不许复查审核状态。

**唯一例外**是第 17 条的验证弹窗（那属于「要人配合」，不算「后面的流程」）：点发送验证码 → 叫人 → 点「验证」→ 同样立刻收工。

### 28. 发布控件只记「距视口底边」

发布 / 提交 / 发表这类按钮，坐标一律用 `anchor: "bottom"` 记 `bottom_offset`＝录制时「元素底边 → 视口底边」的像素距离，执行时用当前客户区高度反推 y。

理由：滚到滚动条底部后，视口显示的是文档末尾；页面上方增删一行（流量提示、协议、推荐条、AI 声明）只让滚动条多滚一点，**按钮到视口底边的距离不变**。而「距窗口顶部 y」会随每一条新增提示整体平移。2026-11-11 快手实测：橙色「你的粉丝在20:00到21:00点活跃」提示条出现后，发布按钮从 y=573 落到 y=682，差 109px，按旧坐标连点全部落空。

- 录制：`mark --anchor bottom`（或 `record --anchor bottom`），区域带 `scroll_state: "bottom"`，执行前**必须先滚到底**。
- 存量迁移：`reanchor --site X --names publish_btn --anchor bottom`；同尺寸下 resolve 结果与旧坐标完全一致，零回归。
- 例外：弹窗内部按钮（如创建合集弹窗）、随文档流滚动但不在底部的控件，保持 `top`。
- 只有 `at` 临时坐标时也可以写 `{"anchor":"bottom","at":[x, 距底边像素]}`。

### 29. 点之前只截那一小块校验

记过坐标之后，第二次**不得再整屏截图**：按已有区域范围（外扩 12px）只截那一小块 ROI，与录制时学的模板比对（灰度网格指纹 + 按钮主色占比），确认它还是不是目标控件（那两个字 / 那个按钮）。

- 命中 → 直接按坐标点；
- 没命中 → 才做全屏（客户区）主色扫描重新定位，把新 rect 与新的 `bottom_offset` 回写台账、重学模板、复验通过才允许点；
- 找不到候选 / 复验仍失败 → **停下报错，绝不盲点**，把局部图交给上层判断。

流程里给关键点击加 `"probe": true`；不带该字段的步骤行为与旧版完全一致。独立命令 `probe --learn / --relocate`。
模板存 `<hub>/shots/probes/<站点>_<区域>.png`，台账 `probe.learned` 存指纹，不含任何页面数据。

### 30. 表单文本一律复制粘贴

标题、描述、话题、标签、系统文件对话框里的路径，一律走剪贴板 + `Ctrl+V`（步骤 `fill` / `paste`），不逐字敲。中文逐字 `KEYEVENTF_UNICODE` 会被输入法吞、长文本慢且容易掉字，`fill` 一步完成「点框 → 可选清空 → 粘贴」。

`type` 默认也已改为粘贴；只有显式 `"literal": true` 才逐字（留给需要触发逐键联想的搜索框）。

**清空输入框绝不用 `Ctrl+A`**：`Ctrl+A` 是浏览器级快捷键，只有焦点真在可编辑元素里页面才会拦成「全选本框」；焦点在 `body` 或复合编辑器容器上时，Chrome 执行「选中整页」——2026-11-11 抖音就是这么把左导航 / 右预览全选蓝、再把整页覆盖进标题框的。`clear` 带 `region` / `at` 时改走**框内拖选 + `Shift+End` + `Delete`**，要「先选整行再替换」用 `select` 步骤。老步骤没带框时仍可退回 `Ctrl+A`，但按完立刻用 `selection_ratio()` 验整屏「选中蓝」占比，> 0.22 判为误选整页、取消选区并改走拖选兜底。

### 31. 开工先跑前置诊断

`run` 开头自动跑 `preflight`，单独跑用 `publish_cli.py preflight --site X`。三项先查：

1. 锁屏（`is_locked`）——锁屏下 `SendInput` 报错码 5、`BitBlt` 失败；
2. 客户区原点与尺寸——`launch` 新窗口是 `(48,40)`，`reveal --w 1440 --h 900` 后是 `(8,0)`；截图是客户区坐标、点击 `at` 会被换算，原点一变按旧图点就整体偏；
3. 会吞点击的独立顶层确认窗——Chrome「离开此网站？」是独立 `Chrome_WidgetWin_1` 窗口，窗口截图 BitBlt 看不见，但吃掉所有鼠标点击，表现为「键盘/滚轮有效、点击全失效、截图零变化」。

确认窗**不当阻塞**（用户 2026-11-11 口径）：它就是个普通弹窗，点右下角主按钮（离开 / 重新加载 / 确定）继续，点不掉再退 `Enter` → `Tab+Enter` → `Shift+Tab+Enter`。`preflight` 默认自动处理，`open` 跳转后也自动处理一次；只有 `--no-dismiss` / `"dismiss": false` 才只看不动。

## 二、窗口复用规范

| 情况 | 做法 |
|---|---|
| 上次用过的窗口还在 | 直接复用，连标签都不换 |
| 上次那个没了，但有别的浏览器窗口 | 复用客户区最大的那个主窗口 |
| 一个浏览器窗口都没有 | 才 `launch` 新开一个 |
| 流程跑完 | **保持原样**，不关、不最小化、不改尺寸 |
| 换站点 | 同一标签 `Ctrl+L` → 粘贴地址 → 回车，**不 `Ctrl+T`** |
| 需要人操作 | `reveal` **不置顶**缩左让位；人做完 `release` 还原到录制尺寸 |
| 要跟人说话 | `minimize` 最小化，把屏幕让给对话 |
| 需要人工验证 | 先点发送验证码 → `reveal` → 对话里明确叫人 → 人填完点「验证」→ 收工（第 17 条） |

判定结果写进 `config/window.json`（hwnd / 标题 / 客户区 / 时间），下次据此复用。hwnd 在窗口未关闭期间稳定；系统重启后失效，自动退化为「选最大主窗口」，不需要人工干预。

## 三、目录归属（四层不混放）

| 层 | 位置 | 放什么 |
|---|---|---|
| L0 能力 | 本包 `scripts/` | 引擎与 CLI：`human/*`、`publish_cli.py`、`locate.py` |
| L1 指针 | `~/.workbuddy/fxai_global.json` 的 `publish_hub.hub_dir` | 只放实例目录路径 |
| L2 实例 | `<hub>/sites/<站点>.json`、`config/human.json`、`runs/`、`shots/` | 站点区域台账、节奏参数、运行记录 |
| L3 项目 | 项目目录 | 成片、封面、`发布材料.json`、发布回执 |

引擎代码只有一份（本包），实例目录只放数据；换机器改一个字段即可，代码不用搬。
