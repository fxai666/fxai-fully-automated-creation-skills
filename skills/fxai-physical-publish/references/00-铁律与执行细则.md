# 00 · 铁律与执行细则

`SKILL.md` 只列每条铁律的判据一句话；本册给全文、例外与处置。执行前逐条对照，冲突时以本册为准。

## 一、40 条铁律（28~31 为 2026-11-11 新增，32~36 为 2026-11-16 新增，37~40 为 2026-11-17 新增）

### 1. 零注入

不用无头浏览器、不接 CDP、不 `evaluate` 页面脚本、不改页面 DOM。浏览器必须以用户日常使用的方式启动，不带任何自动化开关。

### 2. 零凭据

不读不写 cookie、不存 storage_state、不保存登录态。需要登录时**停下来等人**亲手登录，程序只做「判断是否还在登录页」。

需要**人工验证**（短信码 / 人脸 / 扫码 / 密码 / 滑块）时不适用「静默停下」，按第 17 条主动点发送验证码、在对话里叫人、人配合完继续做，**不许没反应**。

### 3. 坐标可固定，行为必须随机

区域坐标录一次固定下来；鼠标轨迹、按键节奏、动作间隙每次重新抽样。禁用固定延时——固定延时会形成可统计的节律。

### 4. 停顿跟着动作走，不跟着步骤走

连贯动作用 `gap`（0.04~1.8s，手挪过去就行），只有「要看、要找、要想」才用 `pause`（长尾 0.5~120s）。**禁用每步之后都停一次**：把点框、打字、再点下一个框切成一段段，比机器还假。

### 5. 拍摄前先激活

窗口被遮挡时截到的是遮挡物，表现为「整页找不到目标」。任何截图 / 点击前必须确认目标窗口在前台。

### 6. 区域存相对客户区

坐标相对窗口客户区原点，并记录录制时的客户区尺寸；偏差超过 4% 拒绝执行并提示重录。绝对屏幕坐标一律不存。

### 7. 只按区域点，不按像素猜

区域要用工具定位后录入（像素扫描 / 人工框选），不允许手写估算坐标。

### 8. 让人动手就别置顶，要跟人说话就最小化

人工环节先 `reveal`：**取消置顶**、靠左缩窗，用户点一下对话窗口就能把它盖住。一旦要把控制权交回对话（汇报、提问、抛 `NeedUser`），立刻 `minimize` 把屏幕整个让出来；人做完用 `release` 还原录制尺寸。

**任何时候都不得 `HWND_TOPMOST`**——置顶会把对话窗口压在下面，用户连「我该干什么」都看不见。

### 9. 随时可中止

长按 `ESC` 立即停止；程序不得吞掉用户的按键。

### 10. 一次只操作一个窗口

目标窗口不唯一时先 `windows` 确认，禁用盲点。

### 11. 人工闸门不可跳过

登录、投稿提交等外发动作，必须有明确的人工确认节点。人工验证按第 17 条走「主动点发送验证码 + 叫人 + 继续」，不是静默闸门。

### 12. 流程必须能一条命令重放

不许边跑边由模型现算坐标：模型思考的卡顿会混进节奏里，下次也没法复现。

### 13. 窗口只有一个，一直用下去

能复用就绝不开新的——先复用上次那个（`config/window.json` 记着），没有再退到现有主窗口，一个都没有才启动。

**流程结束不关窗口、不新开窗口、不 `Ctrl+T` 堆标签**，换站点就在同一个标签里粘贴地址跳过去。多出来的窗口和标签本身就是最容易看出来的破绽。

### 14. 合集：有同名就选，界面能建就建，连创建入口都没有就跳过（2026-11-17 用户改口径）

合集名以 B 站为唯一标准，B 站第一个发（这条不变）。之后每站按四段判据走：

| 现场情形 | 动作 |
|---|---|
| 站上已有同名合集（下拉 / 列表里能选到） | **直接选**，不新建 |
| 没有同名，但**当前发布界面里**就有「创建合集 / 新建合集 / 新建播放列表」入口，且能按原名建成功 | **按 canonical 原名建**，不加后缀、不改字；建完必须校验控件已显示该名 |
| **当前界面没有创建入口**（下拉只有「不选择合集」/ 弹窗写「暂无合集，请先去添加」却没有新建按钮 / 要离开发布页去内容管理另开模块才能建 / 播放列表属于账号侧资产） | 🔴 **跳过**，台账记 `collection.state = "skipped_no_entry"` 并写明核查过程。**不追问用户、不等人工补、不用截断名或近似名凑、不事后自动建** |
| 站点根本没有合集概念 | 记 `collection: "n/a"` |

判据一句话：**入口就在当前发布界面里 → 建；要另开模块 / 换页面 / 走账号侧才能建 → 算没有入口，跳过。**

> 🔴 旧口径「界面不提供创建功能 → 停下来告诉用户由用户手工建」**已废止**（用户 2026-11-17 明确：连创建入口都没有就跳过，不要因此中断发布，也不许自动绕去别处建）。

清单见 `<hub>/config/collections.json`，细则见 `06-流程迭代与合集文案规范.md` 合集标准一节。

### 15. 动态项一律现场读，绝不写死

推荐话题、现有合集、分区、可见范围这些内容每次执行都可能变，必须当场看当场选。**写死的只在台账里的坐标**，可选项永远从当前页面取。

### 16. 文案先看作品性质，教程类实事求是（2026-11-16 用户顶级口径）

**先判作品是「教人做」还是「给人看」**，再决定写法——这条优先于下面的站点分档：

| 作品性质 | 写法 |
|---|---|
| **教程类 / 操作演示 / 工作流教学** | 🔴 **实事求是，按实际教程名称与内容写**：标题用真实作品名 / 工作流名，详情讲这条教程教什么。禁用娱乐钩子、煽情标题、「你最想…」互动句。**B 站以外的全部大众站也不许写娱乐向**——教程类任何平台都实事求是 |
| **创作 / 发挥类成品**（短剧、MV 成品等） | 才按站点分档：B 站技术向，其余娱乐向 |

判据：这条片子是教人做还是给人看？教人做 → 实事求是；给人看 → 可娱乐化。教程类哪怕题材是短剧 / MV，只要片子本身是操作演示，就实事求是，别因题材写成娱乐向。

**违反实例（2026-11-16）**：《MiniMaxH3影视剧场双采版-操作演示教程》是教程类，却给 9 个大众站写了「一个人分饰几角，写段对白就成了一部短剧」的娱乐钩子标题，已纠正。

创作/发挥类的站点分档：**B 站走技术向**（制作链路、模型、参数、制作细节，技术人群要信息密度），**其余平台走娱乐向**（情绪、氛围、第一行钩子、流量标签）。技术细节在娱乐向里只留一句，不展开。品牌标记「凤希AI」所有平台都要出现。唯一来源是项目的 `平台文案.json`：顶层 `内容性质`（tutorial/creative）先定走哪套，`platforms.<站点>.tier` 再分站点档。细则见 `06` 册文案分层。

### 17. 遇到人工验证：主动点「发送验证码」，把人叫过来配合，然后接着做

**任何平台**（抖音 / 快手 / 视频号 / B 站 / YouTube / TikTok…）、**任何验证类型**（短信码、人脸、扫码、登录密码、滑块、邮箱码）都适用。

1. 不停住、不静默、不存草稿走人——**立刻现场定位并点「发送验证码 / 获取验证码 / 发送短信」**（坐标按第 7 条现场扫描，不许估算）；
2. 按第 8 条 `reveal` 让位（不置顶），**在对话里明确说一句**：「需要你输入验证码，我在这儿等你，填完告诉我 / 你点『验证』我接着做」——人就在旁边配合，等一下即可；
3. 用户填完码（或完成人脸 / 扫码）后，程序只点「验证 / 确定」这个提交动作，**然后立刻按第 27 条收工，不追加任何流程**。

🔴 **绝不代收、代填、代看验证码，绝不绕过验证**；验证码只由账号本人经手。不得以「找免验证入口」「存草稿交用户」「记 `blocked_verify`」替代本流程。

### 18. 动手前先自检锁屏

`api.assert_ready()` / `is_locked()`。工作站锁定后系统把输入桌面交给 Winlogon，`SendInput` 直接返回错误码 5，`BitBlt` 直接失败——表现是「点了没反应」「截图全黑」「窗口激活不了」。**先查锁屏，再怀疑代码**。人也睡了、屏锁了，就老实停下并说明，不空转重试。

### 19. 跨站跳转先确认真的跳过去了

上一个页面有未保存内容时，Chrome 会弹「离开此网站？」把跳转卡住，此后所有截图和点击都落在旧页面上，看起来像「后面几个站点都没登录」。导航后必须轮询窗口标题确认到达，卡住就处理确认框——**只用键盘（Tab → Enter），不用坐标点**：那是浏览器自绘的框，位置随窗口尺寸变，按坐标点会落到页面链接上。

### 20. AI 生成标记是硬合规项，一票否决

内容只要有一项由 AI 生成（音乐、画面、文案任一），**每个平台都必须勾选对应声明**，一个都不得漏。各站入口名称不同（作品声明 / 内容创作声明 / 创作声明 / AI 生成的内容 / Altered content），逐站对照 `05-发布前合规清单.md`。

**找不到入口不等于可以跳过**：先滚到底、展开「显示更多 / 更多设置」，全找过确实没有，才在台账记 `declare_ai: "none"` 并写明「已全页搜索未找到」。

### 21. 原创声明有就必勾，且必须校验勾上

凡是提供「原创 / 自制 / 声明原创」选项的平台，必须勾上。原创声明与 AI 标记**不冲突**——作品是我们原创的，只是生成手段用了 AI，两个都要勾。漏勾原创 = 放弃权重与维权依据，事后极难补。

**「点了」不等于「勾上了」（用户 2026-11-17 立规）**：日志 `step_ok` 只说明鼠标落在了某个像素上，不说明勾选框变了状态。勾完必须局部校验（`probe` 或截图）确认框已变勾选态 / 弹出「原创权益」弹窗并走完（同意条款 → 声明原创按钮）；没变就是点空了，重定位再点，仍不过就 abort 停住报人。

**禁止用 `optional: true` 兜住这一步**。台账缺坐标就现场标定补录，不许让 `region` 指向空气——`optional` 遇到不存在的 region 会静默跳过，日志看起来全绿，作品却没有原创声明。

现状体检（2026-11-17 核查）：快手 / 头条 / 百家号的原创步骤指向 `region: "original"`，台账里**根本没有这个坐标**且标了 `optional`，长期空转；抖音的原创与合集坐标齐备但**流程从未调用**；视频号的原创与合集坐标存在但点击偏移、点空静默放行。以上全部已按本节补齐。

### 22. 审核中就是发出去了，点完发布即收工

出现「审核中 / 处理中 / 内容审查中 / 仍在检查」即视为发布完成，**立刻结束该站：不回头等结果、不打开播放页、不比对作品数、不做可播放验收**。YouTube 尤其如此：提示「我们仍在检查你的内容」时直接点发布，别点「返回」保留私享。

**点了发布按钮，只要页面没出现错误提示，就是成功**，后面所有验收 / 复查流程一律不做，别把流程跑长。

### 23. 外发前跑一遍合规清单

`05-发布前合规清单.md` 里的勾选项逐条过，特别是「AI 标记、原创声明、封面、合集、可见范围、默认勾选项」六项——这六项是反复出问题的位置。**这是提交前的门，不是提交后的验收**。

### 24. 流程按三次迭代收敛，不许一次就想写死

第 1 次是 `v0-init` 探路（页面上全是引导弹窗、恢复气泡、首用教学，坐标会被顶偏，**此时的坐标不可全信**）；第 2 次是 `v1-observed` 提炼（干扰消失，删绕路、补坐标、压等待）；连续两次动作序列无需临时改坐标 / 绕路才升 `v2-stable`（人工验证是正常环节，不算异常介入）。

第 2 次提炼必须同时**提速**：删发布后步骤与 final 截图、固定等待改 `wait_stable`（原值只作超时上限）、填表动作串 `chain`、显式 `pause` 全删交回 `bridge` 语义、说明性 `note` 搬进台账；正式执行 `scale` 恒为 1.0，**不许用 `--fast` 冒充真人速度**。

每次跑完都要把动线写回站点台账的 `flows`，把缺的坐标记进 `flow_meta.missing`，把前后节奏预算写进 `flow_meta.speed_profile`。细则见 `06-流程迭代与合集文案规范.md` 第 2 次提炼。

### 25. 封面尺寸只准引用 key，规范归封面设计技能

站点台账只写 `"cover": {"key": "horiz_16x9"}`，项目配置只列 key 清单，任何地方都不许再写像素。尺寸、比例、各站规格、版式与验收全部归 `fxai-poster`（`references/11` + `cover_sizes.json`），本包只留指针，见 `07-封面尺寸与版式规范.md`。竖版标题一律竖排贴空余最多的一边，禁用横排压脸。

### 26. 上传没到 100% 就提交 = 造一个空壳作品

必须等「进度 100% + 封面帧出现 + 能点开预览」三样齐了再填表提交。**这三样是提交前的门，不是提交后的验收**；点完发布、没有错误提示就收工（第 22 / 27 条），不回去点开验证能否播放。

### 27. 「点发布」是本站最后一个动作

任何站点，发布提交按钮点下去之后，只做一件事——看有没有错误提示。**没有 → 立刻结束该站**，不许再截图、不许点开作品、不许跑验收清单、不许回列表数条数、不许复查审核状态。

**唯一例外**是第 17 条的验证弹窗（那属于「要人配合」，不算「后面的流程」）：点发送验证码 → 叫人 → 点「验证」→ 同样立刻收工。

### 28. 发布控件只记「距视口底边」

发布 / 提交 / 发表这类按钮，坐标一律用 `anchor: "bottom"` 记 `bottom_offset`＝录制时「元素底边 → 视口底边」的像素距离，执行时用当前客户区高度反推 y。

理由：滚到滚动条底部后，视口显示的是文档末尾；页面上方增删一行（流量提示、协议、推荐条、AI 声明）只让滚动条多滚一点，**按钮到视口底边的距离不变**。而「距窗口顶部 y」会随每一条新增提示整体平移。2026-11-11 快手实测：橙色「你的粉丝在20:00到21:00点活跃」提示条出现后，发布按钮从 y=573 落到 y=682，差 109px，按旧坐标连点全部落空。

- 录制：`mark --anchor bottom`（或 `record --anchor bottom`），区域带 `scroll_state: "bottom"`，执行前**必须先滚到底**。
- 存量迁移：`reanchor --site X --names publish_btn --anchor bottom`；同尺寸下 resolve 结果与旧坐标完全一致，零回归。
- 例外：弹窗内部按钮（如创建合集弹窗）、随文档流滚动但不在底部的控件，保持 `top`。
- 只有 `at` 临时坐标时也可以写 `{"anchor":"bottom","at":[x, 距底边像素]}`。

### 29. 点之前只截那一小块校验

记过坐标之后，第二次**不得再整屏截图**：按已有区域范围（外扩 12px）只截那一小块 ROI，与录制时学的模板比对（灰度网格指纹 + 按钮主色占比），确认它还是不是目标控件（那两个字 / 那个按钮）。

- 命中 → 直接按坐标点；
- 没命中 → 才做全屏（客户区）主色扫描重新定位，把新 rect 与新的 `bottom_offset` 回写台账、重学模板、复验通过才允许点；
- 找不到候选 / 复验仍失败 → **停下报错，绝不盲点**，把局部图交给上层判断。

流程里给关键点击加 `"probe": true`；不带该字段的步骤行为与旧版完全一致。独立命令 `probe --learn / --relocate`。
模板存 `<hub>/shots/probes/<站点>_<区域>.png`，台账 `probe.learned` 存指纹，不含任何页面数据。

### 30. 表单文本一律复制粘贴

标题、描述、话题、标签、系统文件对话框里的路径，一律走剪贴板 + `Ctrl+V`（步骤 `fill` / `paste`），不逐字敲。中文逐字 `KEYEVENTF_UNICODE` 会被输入法吞、长文本慢且容易掉字，`fill` 一步完成「点框 → 可选清空 → 粘贴」。

`type` 默认也已改为粘贴；只有显式 `"literal": true` 才逐字（留给需要触发逐键联想的搜索框）。

**清空输入框绝不用 `Ctrl+A`**：`Ctrl+A` 是浏览器级快捷键，只有焦点真在可编辑元素里页面才会拦成「全选本框」；焦点在 `body` 或复合编辑器容器上时，Chrome 执行「选中整页」——2026-11-11 抖音就是这么把左导航 / 右预览全选蓝、再把整页覆盖进标题框的。`clear` 带 `region` / `at` 时改走**框内拖选 + `Shift+End` + `Delete`**，要「先选整行再替换」用 `select` 步骤。老步骤没带框时仍可退回 `Ctrl+A`，但按完立刻用 `selection_ratio()` 验整屏「选中蓝」占比，> 0.22 判为误选整页、取消选区并改走拖选兜底。

### 31. 开工先跑前置诊断

`run` 开头自动跑 `preflight`，单独跑用 `publish_cli.py preflight --site X`。三项先查：

1. 锁屏（`is_locked`）——锁屏下 `SendInput` 报错码 5、`BitBlt` 失败；
2. 客户区原点与尺寸——`launch` 新窗口是 `(48,40)`，`reveal --w 1440 --h 900` 后是 `(8,0)`；截图是客户区坐标、点击 `at` 会被换算，原点一变按旧图点就整体偏；
3. 会吞点击的独立顶层确认窗——Chrome「离开此网站？」是独立 `Chrome_WidgetWin_1` 窗口，窗口截图 BitBlt 看不见，但吃掉所有鼠标点击，表现为「键盘/滚轮有效、点击全失效、截图零变化」。

确认窗**不当阻塞**（用户 2026-11-11 口径）：它就是个普通弹窗，点右下角主按钮（离开 / 重新加载 / 确定）继续，点不掉再退 `Enter` → `Tab+Enter` → `Shift+Tab+Enter`。`preflight` 默认自动处理，`open` 跳转后也自动处理一次；只有 `--no-dismiss` / `"dismiss": false` 才只看不动。

### 32. 整条流程一次跑完，异常才回头找原因

已记录 `flows.<类型>` 与 `regions` 的站点，**一次 `run --site X --flow video` 连跑到底**。禁用把一条 40 步的流程拆成 3~6 步的小段，每段之间截图、看图、重新算坐标——那样每一步都要人再判断一次，时间全花在段间而不是动作上。

只有三种情况才升级：

1. 步骤抛错，或 `probe` 局部校验未命中；
2. `required: true` 的 `wait_stable` / `wait_change` 超时；
3. 画面出现台账里没有的弹窗、跳转或登录页。

升级时按顺序做，不许跳步：先看 `runs/<时间戳>/log.jsonl` 的失败步号 → 再 `probe --site X --name <区域>` 只截那一小块 → 仍未命中才 `snap` 全屏重扫 → 改台账 → `--from-step N` 续跑。

跑完用 `run --audit` 看逐步耗时表；**表里没有异常行就不许打开任何截图**。

判据（2026-11-15 实测）：引擎连跑 6 步只用 9 秒（`pauses: 0`），而整站收尾花了 72 分钟，其中真正的鼠标键盘动作不到 30 秒，其余全是段间截图与人工判断。慢的从来不是引擎。

### 33. 开工先清残留草稿

上次没发完的站，进投稿页会弹「继续编辑 / 是否恢复上次编辑 / 继续未完成的发布」。**先放弃并删掉那一条，再走本次全新发布流程**。

站点配 `draft_guard`：

```json
"draft_guard": {
  "probe_region": "resume_dialog",
  "discard_region": "resume_discard",
  "confirm_region": "resume_confirm",
  "wait_ms": 900
}
```

流程第 3~4 步放 `{"do": "dismiss_resume"}`。没配 `draft_guard` 的站点记 `draft_guard_skip` 并继续，不报错。

不清理的后果很隐蔽：上一条的标题、简介、封面、合集被带进新作品，而字数计数器显示正常、日志也看不出来，只有发出去才发现发错。

### 34. 封面裁剪框必须让文案全显示

平台裁剪框比例 ≠ 出图比例（抖音竖 3:4 / 横 4:3、公众号 2.35:1 等）。上传后若出现可拖动 / 缩放的裁剪框，用 `crop_fit` 把图拖到设计稿的重要文案全部落在框内：

```json
"cover": {
  "key": "vert_9x16",
  "crop_adjust": {"box": "crop_box", "drag": [0, -80], "zoom": null}
}
```

流程里放 `{"do": "crop_fit"}`，偏移优先取步骤内联 `dx` / `dy`，其次取站点 `cover.crop_adjust`。

**更优先的是出图时就防止被裁**：横屏作品发竖版站，竖版封面用「横图完整居中 + 模糊铺底」，文案零裁切（见 `fxai-poster/references/11`）。拖裁剪框是补救，不是主路径。

判据：裁剪框内能完整看到主标题与副标题。看不全就拖；拖到底还看不全，说明这张图不该硬塞，换竖版。

### 35. 发布成功之前不许关浏览器

**用户 2026-11-16 口径**：「整个任务没有完毕之前勿关闭浏览器，就是没有发布成功之前不允许关闭浏览器。就算你现在只是做一个路径测试，也按正常的流程走好，你勿关闭浏览器。」

这条管的是**执行纪律**，不是窗口管理偏好。中途关窗的代价是双向的：

| 关得早，坏在哪 | 后果 |
|---|---|
| 平台侧 | 投稿页留一条「上次没发完」的草稿，下次进页面必弹「继续编辑 / 恢复草稿」，又把上一轮的问题抛回来 |
| 本地侧 | 重开就得重新上传一遍成片、重新填一遍表，几十 MB 的同一个文件反复推上去 |
| 平台侧再看 | 短时间内同一账号反复上传同一文件，看起来就是异常流量 / 浪费服务器资源 |

#### 必须做

1. **一次执行 = 一站从上传到发布，一条命令跑到底**。不许把流程拆成「先探到第 N 步、看看截图、再跑后半段」两三条命令——那等于中途关了一次窗。
2. **路径测试也按正常流程走**：标题、简介、标签、封面、声明、合集该填什么填什么，不在测试时填占位内容。测出来的结果要能直接当发布结果用。
3. **测试中发现问题就地记录，然后继续往后跑**：把发现的坐标 / 文案 / 缺项写进该站台账（`sites/<站点>.json`）或 `notes`，下一步接着走，不回头重来。
4. **需要人帮忙时等，不关窗**：`reveal` 让位 → 对话里明确叫人做什么 → 人做完 → 接着跑。等待期间脚本停手，窗口留着。
5. **关窗只走 `close` 子命令**，由它核对「这一站这次是否跑到最后一步且 ok」。没跑完会拒绝并给出续跑命令。
6. **一站发完才关，关完再开下一站**：每站「发布成功 → `close` → 下一站 `launch`」，不并行开多个窗口、不提前为下一站开窗。

#### 环境事实：为什么必须一条命令跑完

agent 侧的每条 shell 命令都是独立进程会话，**命令一结束，本次启动的浏览器进程就被回收**。
`DETACHED_PROCESS`、`CREATE_BREAKAWAY_FROM_JOB`、`ShellExecuteW` 三条路都试过，都留不住
（实测：命令内 `chrome.exe` 有 12 个进程、窗口客户区正常，下一条命令 `count=0`）。

所以「把流程拆成几条命令、中间保持窗口」在本环境里物理上做不到；能做到且唯一正确的做法，
就是**一站一条命令，从 `launch` 到点发布一次跑完**，中途不退出、不拆段。
`--from-step` 是给「命令还在跑、某一步抛错后在同一会话里重试」用的兜底，不是跨命令续跑的许可证。

| 命令被打断 / 超时 | 后果 | 处理 |
|---|---|---|
| 浏览器随命令消失 | 平台侧留下未完成草稿 | 重开后**先清残留草稿**（第 33 条），再从第 1 步整条跑 |
| 已经上传过成片 | 会再上传一次 | 无法防止，属于异常路径；正常路径不该走到这里 |

给命令留足超时：一站全流程（上传 + 填表 + 发布）按 10 分钟上限申请，勿用默认短超时把流程腰斩。

```bash
python -B publish_cli.py launch --fit 1500x900
python -B publish_cli.py run --site <站点> --flow video      # 一条命令跑完整条
python -B publish_cli.py close --site <站点>                 # 跑完才允许
python -B publish_cli.py launch --fit 1500x900               # 下一站才开新窗
```

#### 断在中间怎么办

| 情况 | 做法 |
|---|---|
| 某一步反馈不对 | **不关窗**。改台账 / 改步骤 → `run --from-step N` 从失败步续跑，前面已填的不重来 |
| 流程真的跑不下去了 | 窗口留着，把现状告诉用户，等指示；不许用 `close --force` 悄悄放弃 |
| 用户要求放弃本次 | 只有用户明确说放弃，才 `close --force`，并在回执里写明「平台侧留了草稿待清理」 |
| 系统 / 浏览器自己崩了 | 属于异常，重开一次可以接受；重开后**先清残留草稿**（第 33 条）再走 |

**判据**：一个站点的执行记录里，`run` 出现两次以上且第二次是从第 1 步开始的，就是违反了本条——正常只该有一次全量跑加若干次 `--from-step` 续跑。

### 36. 有上次草稿就继续编辑，防止重复上传；发布没确认成功不许关窗

**用户 2026-11-16 口径**：「如果说检测到你上次需要继续编辑了，赶紧继续编辑了，你现在这样都上传了多少个呀。以后遇到站点把它记录下来，B 站就是一个例子。你进入页面去判断有没有上次编辑的，有的话继续。这样每一次都去传传传的，传了多少了呀。还有没有上传成功的情况下，禁用关闭浏览器；必须在点击发布过后，当前页面或者他转到新页面里面去确认已经上传成功，才关闭浏览器进行下一个操作。」

这条有两半，都是硬要求。

#### 36.1 进页面先判草稿，有就「继续编辑」

投稿页加载完先探一次顶部提示条（`draft_guard.probe_region`，只截那一小块）：

| 探测结果 | 动作 |
|---|---|
| 命中（有「上次没发完」的提示条） | 点 `draft_guard.continue_region`＝**「继续编辑」**，恢复原稿，后面带 `skip_if_resumed` 的上传步骤全部跳过 |
| 未命中 | 什么都不做，走全新上传 |

- **禁用**为了「干净」去点「不用了」把草稿丢掉再重传——那是把已经花掉的带宽和时间再花一遍。
- 「不用了」只在**用户明确要求清理**时用（`dismiss_resume`），不作为默认路径。
- 每接入一个站点就把这两个区域记进该站台账：`draft_guard.probe_region` / `continue_region`，`wait_ms` 给草稿恢复留时间（含视频重新加载）。
- 提示条会把下方表单整体下推约 50px，**必须先处理提示条再填表**，否则后面所有按 y 定位的点击全偏。

```json
"draft_guard": {
  "probe_region": "resume_banner",
  "continue_region": "resume_continue",
  "on_miss": "learn",
  "first_run_assume": true,
  "wait_ms": 2800
}
```

流程写法：`resume_gate` 之后，上传入口与选文件两步都挂 `skip_if_resumed: true`。

#### 36.2 发布必须在页面上确认成功，才允许关窗

点「发布」只是发出动作，**不是发布事实**。要拿页面上的证据：

| 判据 | 做法 |
|---|---|
| 页面发生变化 | 点完立刻 `wait_change`（`required: true`）：没变化＝没点中，当场报错，不许静默通过 |
| 出现成功标志 | `confirm_success` 对 `success_check.region`（成功提示条 / 稿件管理页特征元素）做局部模板校验 |
| 站点还没配模板 | 退化为「页面已变」并把本次标记 `publish_unverified`；`close` 会拒绝关窗，直到人工看过 `after_submit.png` 并加 `--accept-unverified` |

**关窗闸门（`close`）三道全过才放行**：跑到最后一步 → `publish_ok` 为真 → 不是 unverified（或人工已确认）。

| 情形 | `close` |
|---|---|
| 跑完 + 确认成功 | 关窗，清窗口记录，可以为下一站 `launch` |
| 跑完 + 未确认成功 | 拒绝，窗口留着 |
| 只跑到一半 | 拒绝，给 `--from-step` 续跑命令 |
| 站点对不上 | 拒绝——上一站没收尾，无法拿它的记录给下一站放行 |

**为什么这条无法省**：2026-11-16 B 站实测，发布按钮区域记错 30px，点在了按钮下方的空白，页面毫无反应，本地却记成「44 步全过、无异常」。没有 `wait_change` 这一道，这种失败会一路静默到「已提交」。

### 37. 开工与换站先验输入通道，探针不过就停，不许硬跑

`preflight` 只能证明「窗口在、客户区对、没锁屏」，**证明不了鼠标键盘真的能投递**。会话被切走（远程桌面断开、物理控制台另有人登录、屏保接管）时，窗口还在、截图还正常、`preflight` 全绿，但每一下点击都掉进虚空。

**三针探针**（任一不过即停）：

| 探针 | 通过判据 | 失败含义 |
|---|---|---|
| 光标移动 | `SetCursorPos(x,y)` 后 `GetCursorPos` **必须真的变成 (x,y)** | 光标位置恒为 `(0,0)` 或原地不动＝输入桌面不接收 |
| 单发输入 | `SendInput` 发一条鼠标移动，返回值 `n == 1` | 返回 `0` 且 `GetLastError()==5`（ACCESS_DENIED）＝输入被拒 |
| 前台窗口 | `GetForegroundWindow() != 0`，且能被 `activate_window` 切到目标 hwnd | 恒为 `0` 且怎么 `SetForegroundWindow` 都回不来＝没有活动输入会话 |

诊断补充：`OpenInputDesktop` 能成功、桌面名 `Default`、`WTSQuerySessionInformation(WTSConnectState)==0` 都**无法**说明可用——2026-11-16 实测这三项全绿，光标照样移不动。唯一可信的是上面三针。

处置：**立刻停手**，勿在失败态里连试（`activate_window` 重试 6 次、`run` 反复重跑都只是空转），把现象原样告诉用户，请他把桌面会话恢复（重连远程桌面 / 回到物理机当前会话）后再继续。已完成的站点照常回写台账，不受影响。

**为什么这条无法省**：2026-11-16 百家号实测，`run` 在第 1 步 `focus` 就报「无法把浏览器窗口切到前台」，此时如果当成偶发重试，后面每一步都会「执行成功」但页面毫无变化，最后又是一次静默假发布。

### 38. 点击坐标只认 1:1 实测，不认看图软件里的像素

`shot` / `print_window_bgra` 截的是**客户区原尺寸**（如 1500×910），但对话里看图工具会把图缩到约 1092 宽显示。直接读显示图上的像素当客户区坐标，会整体偏 `1500/1092 ≈ 1.374` 倍（1440 宽时约 `1.319`），点下去全落在目标上方或左侧。

| 做法 | 结果 |
|---|---|
| 拿 `crop_zoom.py <hwnd> <x0> <y0> <w> <h> <scale>` 截 1:1 或整数倍放大的局部图读坐标 | 准 |
| 拿 `grid_shot2.py <hwnd> <out>` 叠 50/100px 网格读坐标 | 准 |
| 直接读看图工具里的显示像素 | 必偏，禁用 |

换算公式（仅在没有 1:1 图时应急）：`客户区坐标 = 显示坐标 × (客户区宽 / 显示图宽)`。算完必须再用 `crop_zoom` 复核一次才能点。

**为什么这条无法省**：2026-11-16 B 站标题框连续三次填不进去，根因就是把显示图坐标当客户区坐标用，点击落在输入框上方 100 多像素的空白处；换成 1:1 截图后一次点中。

### 39. 必勾项（原创 / 合集）点完必须校验，点空不许放行

用户 2026-11-17 立规：**有原创声明就必须声明原创，能进合集的必须进合集**；这两项与 AI 标记同级，是提交前的硬门，不是「尽量做」。

写流程的硬约束：

| 约束 | 说明 |
|---|---|
| 不许 `optional: true` | 原创 / 合集步骤一律非可选；缺坐标先标定，不许留空 region 空转 |
| 点后必校验 | 勾原创后 `probe` 该区域确认已是勾选态；选合集后 `probe` 确认控件已显示合集名而非「添加到合集 / 请选择」占位 |
| 校验不过就重定位 | `on_miss: relocate` 重找一次；仍不过 `abort` 停住报人，绝不带着未勾项点发布 |
| 有二级弹窗要走完 | 原创常带「原创权益」弹窗（先勾同意条款，再点「声明原创」按钮，按钮灰色说明条款没勾上） |
| 无此概念才记 n/a | 平台确实没有原创 / 合集概念，台账记 `original: "none"` / `collection: "n/a"` 并写明核查过程 |

**踩过的三个坑**（2026-11-17 全平台核查）：
1. `region` 指向不存在的键 + `optional: true` → 引擎静默跳过，日志全绿、作品无声明（快手 / 头条 / 百家号）。
2. 坐标齐备但流程没调那几步 → 有坐标等于没有（抖音）。
3. 坐标存在但点击偏了 `40~60px`，页面滚动状态变了而台账没更新 → 点空仍 `step_ok`（视频号）。
   共同结论：**日志 `step_ok` 只证明鼠标动了，不证明按钮生效**。必勾项只认状态截图。

### 40. 三项硬门对所有站点一律适用：AI 声明 / 原创声明 / 合集（2026-11-17 用户立规，最高层）

**用户口径原文意指**：不要说「这条只管某几个站」，声明类规则是**整个发布程序的最上层要求**，每一站、每一条作品都要走一遍。

| 硬门 | 有入口 | 产品形态确实没有 |
|---|---|---|
| **AI 声明** | 必勾 / 必开，勾完校验状态（第 20 条） | 把 AI 标识写进**标题开头 + 简介正文**，台账记 `declare_ai: "none"` 并写明「已全页搜索/展开/滚到底核查」 |
| **原创声明** | 必勾，含二级「原创权益」弹窗要走完（第 21 条） | 台账记 `original: "none"` + 核查过程 |
| **合集** | 按第 14 条四段判据：有同名选、界面能建就建 | 无创建入口 → `skipped_no_entry`；无合集概念 → `n/a` |

三条约束：

1. **不豁免**：不因「这站风控严 / 页面特殊 / 上次没勾也没事」跳过任何一项；站点差异只影响「入口在哪」，不影响「要不要做」。
2. **不留 `unknown`**：台账 `compliance` 与 `collection` 在点发布前必须有确定结论；`unknown` 等于没核查，下一次发布前必须先核实。
3. **不许 `optional` 兜过**：三项步骤一律非可选；缺坐标就现场标定补录（第 7 / 29 条），不许让 region 指向空气（第 39 条踩坑 1）。

## 二、窗口复用规范

| 情况 | 做法 |
|---|---|
| 上次用过的窗口还在 | 直接复用，连标签都不换 |
| 上次那个没了，但有别的浏览器窗口 | 复用客户区最大的那个主窗口 |
| 一个浏览器窗口都没有 | 才 `launch` 新开一个 |
| 流程跑到一半 | **保持原样**，不关、不最小化、不改尺寸；用 `--from-step` 续跑（第 35 条） |
| 该站发布走完 | `close --site <站点>` 正常关窗，然后才为下一站 `launch` |
| 换站点（同一窗口内） | 同一标签 `Ctrl+L` → 粘贴地址 → 回车，**不 `Ctrl+T`** |
| 需要人操作 | `reveal` **不置顶**缩左让位；人做完 `release` 还原到录制尺寸 |
| 要跟人说话 | `minimize` 最小化，把屏幕让给对话 |
| 需要人工验证 | 先点发送验证码 → `reveal` → 对话里明确叫人 → 人填完点「验证」→ 收工（第 17 条） |

判定结果写进 `config/window.json`（hwnd / 标题 / 客户区 / 时间），下次据此复用。hwnd 在窗口未关闭期间稳定；系统重启后失效，自动退化为「选最大主窗口」，不需要人工干预。

## 三、目录归属（四层不混放）

| 层 | 位置 | 放什么 |
|---|---|---|
| L0 能力 | 本包 `scripts/` | 引擎与 CLI：`human/*`、`publish_cli.py`、`locate.py` |
| L1 指针 | `~/.workbuddy/fxai_global.json` 的 `publish_hub.hub_dir` | 只放实例目录路径 |
| L2 实例 | `<hub>/sites/<站点>.json`、`config/human.json`、`runs/`、`shots/` | 站点区域台账、节奏参数、运行记录 |
| L3 项目 | 项目目录 | 成片、封面、`发布材料.json`、发布回执 |

引擎代码只有一份（本包），实例目录只放数据；换机器改一个字段即可，代码不用搬。
