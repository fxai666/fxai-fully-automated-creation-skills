# 03 · 真人节奏与行为仿真

坐标可以固定，**行为不能固定**。固定延时会形成可统计的节律，比坐标更容易被识别。

## 一、鼠标轨迹

`mouse.plan_path` 每次调用都重新抽样：

- **路径形状**：三次贝塞尔，控制点沿位移法向随机偏移（弧高 6%~26% 位移，方向随机），
  短距离退化为二次曲线。
- **速度曲线**：先加速后减速（`ease`），距离越短时长越短；总时长 0.16~0.95 秒，再乘 0.85~1.22 随机因子。
- **微抖动**：每步叠加高斯抖动，幅度随接近终点而衰减（人对准目标时会收敛）。
- **步数**：按距离除以 9~15 像素，夹在 8~64 步，每步间隔再乘 0.62~1.5 的随机因子。
- **过冲回拉**：22% 概率先落到目标外 2~6 像素再回拉。
- **落点**：区域中心 56% 范围内随机取点，不在正中。
- **按下时长**：42~96ms 随机；抬起后再停 60~180ms 才做下一件事。

## 二、停顿由语义决定，不由步骤序号决定

最容易写错的地方：**每执行完一步就随机停一下**。那是最不像人的做法——
真人填表单时，点开标题框、打字、点简介框、粘贴，是一条连贯的动作，
中间只有手指移动的零点几秒；他不会每填一格就发一次呆。

所以时间被拆成两层：

| 层 | 方法 | 量级 | 受 min_s 约束 | 用途 |
|---|---|---|---|---|
| 动作间隙 | `gap()` | 0.04~1.8s | 否 | 手从一处挪到下一处的连贯性 |
| 真停顿 | `wait()` / `delay()` | 0.5~120s 长尾 | 是 | 要看、要找、要想 |

### 桥接规则（`bridge(cur, nxt)`）

每个步骤先归到一种**动作语义**，再按「上一步语义 → 下一步语义」决定间隙：

| 语义 | 步骤类型 | 含义 |
|---|---|---|
| `window` | focus | 只是把窗口切到前台，画面没变 |
| `nav` | open / goto | 换页面，画面会整个变 |
| `target` | click / dblclick / scroll / file | 要先找到并指向某个位置 |
| `input` | type / paste / key / combo | 作用于当前焦点，手已在键盘上 |
| `settle` | wait / wait_stable / wait_change | 等画面自己变 |
| `meta` | pause / gate / login_gate / shot / note | 自己的时间自己管 |

| 从 → 到 | 间隙 | 为什么 |
|---|---|---|
| `window` → nav/settle | 0.15~0.5s | 马上要导航，时间它自己会花 |
| `window` → 其他 | 抬眼 0.12~0.62s | 切过来确认一下 |
| `nav` → settle | 0.15~0.6s | 下一步就是等加载，不必人再读 |
| `nav` → 其他 | **读页面 0.9~6.5s**（15% 到 6.5~18s） | 新页面出来，得看清再动 |
| `input` → `input` | **0.06~0.4s**（8% 概率停 1.4~6.5s 想一下） | 手还在键盘上，只是换框 |
| `target` → `input` | 0.15~0.55s | 刚点中框，光标就位 |
| `input` → `target` | 0.22~0.85s | 打完字，手从键盘移到鼠标 |
| `target` → `target` | 0.35~1.8s（8% 概率 2.2~9s） | 点完等界面反应，再找下一个 |
| `settle` → 其他 | 0.15~0.9s | 等完了确认一眼 |
| 任何 → `meta` | 0 | 闸门/暂停自己会等，不重复加 |
| `meta` → 其他 | 0.2~0.9s | 人回来了，手放回鼠标 |

**首次点击额外加时**：某区域在本次流程里第一次被点 → `search()` 0.5~2.4s
（18% 到 2.4~9s），因为视线要在页面上扫一遍；之后再点是熟路，只 `glance()`。

实测一条 20 步的发布流程（400 次采样）：

| | 全程中位 | p10~p90 | 真停顿占比 |
|---|---|---|---|
| 老做法（每步都停） | 15.0s | 13.5~16.5s | 0%（全是均摊的假停） |
| 语义桥接 | 11.0s | 9.0~17.5s | 22% |

**关键是分布形状变了**：老做法的 p10~p90 只有 3 秒宽，规律得像节拍器；
新做法大部分间隙在 0.1~0.4 秒，偶尔一次 3~9 秒，这才是人。

### 显式声明连贯性

流程 JSON 里可以用 `chain` / `glued` 手工兜底：

```json
{"do": "click", "region": "title",  "chain": "form"},
{"do": "type",  "text": "潮汐来信", "chain": "form"},
{"do": "click", "region": "desc",   "chain": "form"},
{"do": "paste", "text": "简介…",    "chain": "form"}
```

同 `chain` 的相邻步骤只留 0.05~0.28s 手指间隙。`glued: true` 效果类似（0.04~0.2s），
用于只想粘住一步的情况。反过来 `no_pause: true` 让这一步之后完全不停。

### 长尾停顿（只在真正的决策点用）

`config/human.json`：

```json
{ "enabled": true, "min_s": 0.5, "max_s": 120,
  "weights": [0.86, 0.105, 0.03, 0.005], "scale": 1.0 }
```

| 桶 | 权重 | 区间 | 含义 |
|---|---|---|---|
| 短 | 0.86 | 对数正态，峰≈1.1s，夹 ≥0.5s | 连续操作 |
| 中 | 0.105 | 4~25s | 看一眼页面、想一下 |
| 长 | 0.03 | 25~60s | 被别的事打断 |
| 离开 | 0.005 | 60~120s | 短暂离开 |

2 万次采样实测：中位 1.23s、均值 4.35s、p95 22.4s、最长 120s，
`0.5~2s` 占 75%，`60~120s` 占 0.47%。**没有任何固定区间**。

**这个长尾分布不要摊到每一步上**，只在三种地方调：

- `pause` 步骤，`kind` 可选：
  - `read` → `reading_pause()` 读页面（0.9~6.5s，15% 到 18s）
  - `hesitate` → `hesitation()` 提交前犹豫（2.5~18s）
  - `think` → `think()` 中途想到什么（1.4~6.5s）
  - `auto`/其他 → `delay()` 混合分布（0.5~120s），用于换大环节、被叫走
- 动作流之间的交界（由 `bridge` 自动判定）
- 人工闸门前后的自然过渡

**长等待期间的微动作**：超过 6 秒的等待会拆段，并以 45% 概率做 1~2 次 ±2 像素的鼠标微动——
人不会像机器一样完全静止。

## 三、键盘节奏

- 基础间隔按 WPM 反推（28~62 词/分），每字再乘 0.55~1.9 随机因子。
- 词/句边界（空格、逗号、句号、换行后）额外加 45~190ms。
- 2% 概率出现 220~620ms 的「手停」（看屏幕）。
- `typo_rate` 可选打错再退格，**正式发布保持 0**，不建议开启。

## 四、输入法陷阱（必读）

中文输入法处于激活态时，走**真实键位**的 ASCII 会被 IME 合成成汉字：
实测 `human input ok` 变成「胡曼小尾草羊」，整段内容报废。

**结论**：可见字符一律用 `KEYEVENTF_UNICODE` 直送，等同于键盘发出的字符、绕过 IME 合成；
回车/退格/Tab 仍走真实键位（这些必须触发真实按键语义）。
`keyboard.tap(ch, real_keys=True)` 仅在确认输入法已关闭时才可用。

## 五、调试加速

`--fast` 把 `scale` 压到 0.08，`--scale 0.3` 用三成节奏。
**调试可以加速，正式执行必须 scale=1.0**，否则等于自废随机性。

## 六、不要做的事

- 不要给步骤写死 `sleep(2)` / `wait ms`。等界面反应改用 `wait_stable`：
  短界面 `stable_ms=400`、上传类 `stable_ms=1500`（进度条还在动就不算稳定），
  **原毫秒数只作 `timeout_ms` 上限兜底**；画面稳定即走，既不等满也不冒进。
  这是第 2 次提炼（06 册第 7 条）最主要的提速来源。
- **不要每步之后都停一次**——把连贯动作切成一段段，是最容易被看出来的破绽。
- **不要把长尾分布摊到动作间隙上**——打完标题去点简介框，中间塞个 30 秒停顿，比机器还假。
- 不要在循环里用同一组随机种子。
- 不要把所有停顿都改成同一个量级（长尾才是关键）。
- 不要在人工环节用程序代点（登录、验证码、提交确认）。
- 不要一边写流程一边让模型现算坐标——模型思考造成的卡顿会混进节奏里，
  流程必须能被一条命令完整重放。
