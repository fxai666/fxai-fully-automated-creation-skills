# 06 · 发布流程的迭代规范（初始化 → 提炼 → 稳定）

> 一支作品第一次发，和第十次发，做法不一样。
> 第一次是**探路**：页面有引导弹窗、有未读公告、有首次使用的教学浮层，坐标也会被这些干扰顶偏。
> 第二次开始才是**提炼**：干扰消失，页面干净，此时记录的动作才可信。
> 这份文件规定三个阶段各自做什么、什么条件下才允许把动作写进站点台账。
> 🔴 2026-11-09 起：**点完发布就收工**，流程里不许再挂发布后的验收步骤。

---

## 阶段划分

| 阶段 | 名称 | 触发条件 | 目标 | 产物 |
|---|---|---|---|---|
| 第 1 次 | `v0-init` 初始化 | 站点从未跑过 | 把整条路走通一次，哪怕绕远、哪怕中途要人介入 | `flows` 骨架 + `flow_meta.missing` 清单 + 异常笔记 |
| 第 2 次 | `v1-observed` 提炼 | 用同一账号第二次发 | 把第一次的绕路删掉，动作顺序压到最短，补录缺失区域 | `flows` 可重放 + 区域坐标补齐 |
| 第 3 次起 | `v2-stable` 稳定 | 连续两次动作序列无需临时改坐标 / 绕路 | 只维护，不改结构 | `flow_meta.stage = v2-stable` |

**判定标准**：`v0` 允许 `optional` 步骤满页跑；`v1` 要求每一个必做项都有确定坐标；`v2` 要求去掉所有 `optional`。
🔴 **人工验证（短信码 / 人脸 / 扫码）属于正常环节，不算「异常介入」**，不影响升 `v2`——
用户会配合完成，见第六节。

---

## 第 1 次（初始化）要记什么

第一次跑，页面一定会有这些东西，全部是干扰，必须在 `flows` 里用 `note` 记下来并给出处理动作：

| 干扰类型 | 表现 | 处理 |
|---|---|---|
| 引导弹窗 | 「开启自动内容检查？」「全新编辑功能已上线」 | 点取消/知道了，**不得点开启**（会引入额外处理流程） |
| 恢复气泡 | Chrome「要恢复页面吗」 | 点右上角 ×，**不得点恢复**（会恢复一堆旧标签） |
| 离开确认 | 「离开此网站？」 | 键盘 Tab → Enter，**不得按坐标点**（是浏览器自绘框） |
| 首用教学浮层 | 半透明蒙层 + 高亮某个按钮 | 点蒙层空白处或按 Esc |
| 未发布草稿提示 | 「你还有上次未发布的视频，是否继续编辑」 | 点继续编辑，**不得重传** |
| 默认预填 | 标题/描述被填成文件名 | 一律 `Ctrl+A` → `Delete` → 重填 |
| 默认勾选 | 头条「视频生成图文」 | 一律取消 |
| 验证弹窗 | 「接收短信验证码」「请完成身份验证」 | **主动点发送验证码 + 叫人配合**，见第六节；不许静默停住 |

**第一次的坐标不可全信**：引导层会把按钮顶偏，录完要在第二次核对。

## 第 2 次（提炼）要做什么

1. 用第一次的 `flow_meta.missing` 清单逐个补录区域（用 `mark` 或 `locate`）
2. 把 `optional` 步骤中已经确认存在的，去掉 `optional`
3. 把第一次绕的路删掉（比如为了找按钮而多点的那几下、多余的滚动）
4. 记录**真实耗时**，把 `wait` 的定长等待压到实际需要（上传 36MB ≈ 3 分钟，别写 5 分钟）
5. 跑通后把 `flow_meta.stage` 改成 `v1-observed`，写 `verified` 时间与结果
6. 🔴 **把发布按钮之后的所有 `shot` / `wait` / 「验收」步骤删光**：点发布即终点，
   发布按钮标 `terminal`，其后只留一次确认回车（`glued` + `no_pause`）与一句验证协作 `note`。
   引擎 `run()` 见到 `terminal` 不拍 final 截图。
7. 🔴 **提速靠「删等待、改判据、串动作」，不许调 `scale`**：正式执行 `scale` 恒为 1.0，
   `--fast` / `--scale` 只用于调试，用它们冒充真人速度等于自废随机性（03 册第五节）。
   - 写死的 `wait ms` 一律改 `wait_stable`：短界面 `stable_ms=400`、上传类 `stable_ms=1500`
     （进度条还在动就不算稳定），**原毫秒数改作 `timeout_ms` 上限兜底**；小成片稳定即走，
     无论多快都不等满 25s / 60s。
   - 「点框 → 全选 → 删 → 输入」加同一个 `chain`，只留 0.05~0.28s 手指间隙；
     弹窗点击不串（页面要渲染）。
   - 删掉所有显式 `pause`：`open` 之后 `bridge` 自带 `reading_pause`，
     8% 长尾自带真停顿，再手写一遍就是节拍器。
   - 说明性 `note` 搬进 `flow_meta.notes`（人读），流程里只留动作，不制造 `meta` 间隙。
   - 命中过坐标的 `optional` 改必做；真缺坐标的保留 `optional` 并留在 `missing`。
8. 每次优化写 `flow_meta.speed_profile`（前后步数、固定等待预算、chain 数、搬走的说明），
   便于下一轮对比。批量优化脚本落实例层 `tools/`，技能包只留规范。
9. 🔴 **滚动状态是路径的一部分**：长表单里所有坐标都是「某个滚动位置下」的坐标。只把坐标记进
   `regions`、却没把 `scroll` 动作写进 `flows`，等于没记路径——流程跑完仍停在编辑页，发布按钮根本没点到。
   第 2 次提炼必须逐段固化「滚几格、鼠标落在哪个 `region`」；`scroll` 一律带 `region` 把鼠标放进表单列，
   不指定 `region` 时鼠标常停在预览面板，页面不滚。到底格数宁可多给（到顶/到底会自然停），不得不足。
10. 🔴 **区域用覆盖控件整体的矩形，别用 `2,2` 点**：点的随机抖动很容易落在控件边框外，表现为
    「明明点对方向却没反应」。弹窗项、下拉框、按钮都录成实际矩形；只有确实很小的图标才用 2x2 并配像素扫描校准。
11. 🔴 **任何会改变窗口客户区尺寸的步骤不得进自动流程**：`gate` / `reveal` 之类的需要人配合动作会把窗口
    resize，直接让全站按固定视口录制的坐标失效（`regions.resolve` 偏差 >4% 就拒绝执行）。需要人工核对时，
    让上层驱动停下、留判读图、由人决定，不得把 `gate` 塞进 `flows`。
12. 🔴 **`run_done ok` 只代表「步骤跑完」，不代表「发布成功」**：批量驱动必须每站留一张
    **即时判读图**，用来判断有没有错误提示 / 人工验证弹窗 / 是否已离开编辑页；这张图是即时判错，
    不是可播放验收，不违反铁律 22。上层确认后再进下一站；一次连跑多站时，前一站失败的表单会被
    后一站的 `open` 导航覆盖，补发要重新上传，反而更慢。
13. 🔴 **草稿恢复是独立分支**：重开上传页时平台可能提示「继续编辑未保存草稿」，恢复后视频与封面
    通常都在，但描述、AI 开关等状态会**重置**，不得沿用上一次的结论。把恢复链路单独写成
    `flows.video_from_draft`，不得和空白页上传链路混成一条；「继续」与「放弃」常只隔几十像素，
    必须叠网格取准，点错就丢草稿。有无提示横幅还会让同一套按钮整体平移，坐标要按布局状态分别录。
14. 🔴 **合规声明常藏在「展开／显示更多」后面，且不止一层**：AI 披露／原创声明／视频标注这类
    字段往往要「滚到底 → 点展开 → 再滚 → 才出现」；多层弹窗（如原创权益弹窗）还要先勾同意
    条款才能激活确认按钮。找不到入口不许记 `none`，必须把「滚几格 + 点哪个展开控件」都写进流程；
    点灰色说明文字无效，要点真正的按钮（用 `md5sum` 比对截图确认点击有没有生效）。
15. 🔴 **向导弹窗内部也有滚动状态**：多步上传向导是弹窗时，内部滚动与页面滚动是两回事；
    「继续」按钮坐标可能固定，表单项坐标却随内部滚动变化。`scroll` 的 `region` 必须落在弹窗内容区；
    步骤之间返回／前进会让滚动位置复位，回写台账按**标准顺序**记路径，不得把探路时的绕路写成流程。

**判断「跑通」的标准**：点完发布、页面没有错误提示。
不回列表核对、不看播放页、不比对作品数（铁律 22 / 27）。

## 合集标准（唯一来源）

**B 站是合集标准的唯一定义方，且 B 站必须第一个发。**

理由：B 站有成熟的合集体系，命名与简介由我们控制；后面所有平台都照着它抄，不各起各的名。

| 情形 | 动作 |
|---|---|
| B 站第一次发，还没有这个合集 | **在 B 站创建**，名称与简介由我们定，写进 `config/collections.json` 的 canonical |
| 其他站点已有同名合集 | 直接选，不新建 |
| 其他站点没有，但界面提供「新建合集/新建播放列表」 | 按 canonical 名称原样建，不加后缀、不改字 |
| 其他站点界面**不提供**创建功能 | 🔴 **停下来告诉用户，由用户手工建**，之后我再选。不得用近似的名字凑，也不得跳过 |
| 站点根本没有合集概念（快手/百家号/头条） | 记 `collection: "n/a"`，不得硬塞 |

YouTube / TikTok 的「合集」是播放列表（Playlist），属于账号侧资产，与发布页分离，发完再建。

## 文案分层

| 层 | 站点 | 写法 |
|---|---|---|
| `technical` 技术向 | **B 站** | 讲链路、模型、参数与制作细节。技术人群要信息密度，不得抒情 |
| `entertainment` 娱乐向 | 抖音 / 快手 / 视频号 / 小红书 / 百家号 / 头条 / YouTube / TikTok | 讲情绪、氛围、共鸣。第一行是钩子，短句，标签走流量词 |

🔴 **大众向（mass）标题零技术名词，详情只讲作品本身**：不写怎么做／怎么实现／制作过程／参数／
资源链接，按正常作品发布。两档都**必须保留 AI 显式标识**（合规红线）。
（2026-11-08 用户定，取代旧口径「娱乐向详情也要带一句技术标记」；旧写法已废止。）

品牌标记「凤希AI」所有平台都要出现，位置：描述末尾或标签里。

文案唯一来源是项目目录的 `平台文案.json`，`platforms.<站点>.tier` 标明归属。

## 六、人工验证协作（2026-11-09 用户强制口径）

🔴 **遇到需要人工验证，就主动点「发送验证码」，然后叫我来配合，我弄完你接着干。**

用户明确说过多次：「操作过程中需要我帮助的，我辅助你」「你直接点发送验证码，我给你把验证码输进去」
「我在旁边呢」。所以**不许停下来干等、不许静默无反应、不许存草稿走人**。

标准动作序列（写进站点 `flows` 时用 `gate` 明确节点）：

1. 弹出验证 → **现场定位并点「发送验证码 / 获取验证码 / 发送短信」**（坐标按铁律 7 扫描录入）
2. `reveal` 让位（不置顶），**在对话里明确说一句**：需要你输入验证码，我在这儿等你，
   填完告诉我 / 你点「验证」我接着做
3. 用户本人填码 / 人脸 / 扫码完成后，程序只点「验证 / 确定」提交
4. **立刻收工**，不追加任何后续流程

适用范围：**所有平台、所有验证类型**（短信码、刷脸、扫码、登录密码、滑块、邮箱码），不只抖音。

🔴 边界：**绝不代收、代填、代看验证码，绝不绕过验证**；验证码只经账号本人之手。
程序可做的只有「点发送」「点验证」这两个提交动作。

🔴 **旧口径已废止**：「不主动走验证路径 → 先找免验证入口 / 关弹窗看按钮是否可用 →
确认被硬拦才存草稿交用户 → 记 `blocked_verify`」。不得再执行，也不得再劝用户绕路。

## 站点台账字段约定

```json
{
  "flows": { "video": [ ...步骤，publish_btn 是最后一步... ] },
  "flow_meta": {
    "stage": "v0-init | v1-observed | v2-stable",
    "missing": ["还没录到坐标的必做项"],
    "verified": "最近一次跑通的时间与结果"
  },
  "compliance": {
    "declare_ai": {"state": "done | unknown | n/a", "note": "..."},
    "original":   {"state": "done | unknown | n/a", "note": "..."}
  },
  "collection": {"name": "AI原创音乐MV", "state": "existing | created | n/a"}
}
```

`compliance` 里 `unknown` 表示**未核实**，下次发布前必须先核实再改 `done`，不许照抄上一次的结论。
`flows` 里 `publish_btn` 之后**不许**出现 `shot` / 长 `wait` / 验收 `note`；
唯一允许写的是「若弹验证 → 按第六节协作」的一句 `note`。
