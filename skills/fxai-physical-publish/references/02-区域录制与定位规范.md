# 02 · 区域录制与定位规范

区域（region）是这条通道的核心资产：**录一次，长期复用**。录错一次，后面每次点都错。

## 一、区域台账格式

`<hub>/sites/<站点>.json`：

```json
{
  "site": "<站点标识>",
  "window": { "exe": "chrome.exe", "title_contains": "" },
  "client": [1500, 910],
  "upload_url": "站点发布页地址（首次确认后记录，之后只读不猜）",
  "humanize": { "scale": 1.0 },
  "regions": {
    "upload_entry": { "rect": [698, 642, 304, 48], "note": "投稿页·上传视频按钮",
                      "recorded_at": "...", "client": [1500, 910], "hits": 1, "fails": 0 }
  },
  "flows": { "video": [ { "do": "open" }, { "do": "click", "region": "upload_entry" } ] }
}
```

- `rect` = `[x, y, w, h]`，相对客户区。
- `client` = 录制时的客户区尺寸，用于尺寸漂移校验。
- `hits` / `fails` 由执行时回写，用于判断某区域是否已经不可靠。

## 二、录制方式（两种，都要求先锁定画布）

**前置：把客户区固定下来**，例如 `launch --fit 1500x900`。录制与执行必须是同一尺寸，
否则坐标全部偏移。执行时若发现尺寸变了，`focus()` 会自动调回录制尺寸。

### 方式 A · 人工框选（最可靠）

```bash
python -B <包>/scripts/publish_cli.py record --site <站点> --plan plan.json
```

`plan.json` 里按顺序列区域名与说明；每项提示：把鼠标移到目标**左上角按 F7**，再**右下角按 F8**。
`ESC` 跳过该项。录完自动截一张该区域局部图，便于事后核对。

只有一个区域时用 `mark --site X --name Y`，效果相同。

### 方式 B · 像素定位（适合按钮类纯色控件）

```bash
python -B <包>/scripts/locate.py --color blue --y0 600 --y1 900 --min-area 1500
# rect=[698, 642, 304, 48]  304x48  area=14592  中心=(850,666)
```

按颜色扫描客户区，输出候选矩形的 `[x,y,w,h]` 与面积。适合主色明确的按钮；
多候选时按面积/纵向区间收窄。确认后：

```bash
python -B <包>/scripts/publish_cli.py mark --site X --name upload_entry --rect 698,642,304,48 --note "上传视频"
```

`locate.py` 内置预设：`blue / deepblue / red / orange / green / white / dark`。
自定义颜色需求改 `PRESETS` 即可。

## 三、录制要点

1. **区域要包住整个可点元素**，但不要外扩到相邻控件；点选时取区域中心 56% 内的随机点，边缘不触发。
2. **小目标（≤16px 的关闭按钮）** 先放大截屏确认中心，再录；点偏一点就无效。
3. **同一页面不同滚动位置 = 不同坐标**。表单类页面要么先滚到固定位置（`Ctrl+Home` 后固定次数滚动），
   要么给每个滚动状态分别记区域名。
4. **弹窗/气泡是独立窗口**，坐标相对主窗口客户区会算错；这类元素单独按窗口处理。
5. 录完立刻看 `shots/<站点>_<区域>.png`，确认框住的是不是那块。

## 四、尺寸漂移

执行时若当前客户区与 `client` 偏差 > 4%，直接拒绝执行：

```
窗口客户区尺寸已变化（录制 1500x910，当前 1180x860，偏差 21%）。
区域坐标不可靠，请重新录制该站区域，或把窗口调回原尺寸。
```

**不要**用拉伸缩放硬套（`regions.resolve` 虽按比例换算，但那只兜住 1~3% 的抖动）。
给人让位而缩小窗口后，必须 `release` 还原，`focus()` 也会自愈调回。

## 五、变更与失效

- 站点改版后先 `snap` 截图比对；位置变了就重录该区域，其余不动。
- `fails` 连续增长即判定该区域失效，优先重录。
- 区域名一旦被流程引用就不要改名；改名等于流程失效。

## 六、🔴 视口底部按钮：必须像素扫描，不能按截图比例换算

2026-11-08 发知乎时踩过：`shot` 出的图是 1440×900，但人眼看图（或被缩放到 1080×675）后
按 0.75 比例反推坐标，算出「发布视频」按钮在 y≈821，**连点 5 次全部落空**。
真实可点位置在 y≈862，差 41px。CSDN 同样，算出 y≈823，实际 y≈850，差 27px。

原因：贴在视口底边或做了 sticky 定位的按钮，截图与点击坐标系之间存在原点偏移；
页面滚动位置在截图与点击之间也可能有 1~2px 抖动，但这解释不了几十像素的差。
结论是**不要相信任何"看图数比例"得来的 y 值**。

**凡符合以下任一条，一律先扫描再点：**
- 按钮在页面最底部 / 贴着窗口下沿
- 按钮是 `position: sticky` / `fixed`（滚动时位置不变）
- 同一坐标点了 2 次页面毫无变化

扫描写法（找按钮主色，换算回客户区）：

```python
import sys; sys.path.insert(0, '.')
from human import api
# grab 用屏幕坐标；客户区原点用 api.client_rect(hwnd) 取，通常是 (48, 40)
x0, y0, w, h = 940, 790, 240, 110
cw, ch, buf = api.grab(x0, y0, w, h)
xs, ys = [], []
for y in range(ch):
    for x in range(cw):
        i = (y * cw + x) * 4
        b, g, r = buf[i], buf[i + 1], buf[i + 2]
        if r > 200 and 40 < g < 130 and b < 100:   # 橙色；蓝色用 b>200 and r<90 and 100<g<180
            xs.append(x + x0); ys.append(y + y0)
print((min(xs) + max(xs)) // 2 - 48, (min(ys) + max(ys)) // 2 - 40)   # → 客户区坐标
```

**坐标系对应关系（务必记住）：**

| 接口 | 坐标系 |
|---|---|
| `shot` 截图 | 客户区，左上角为 (0,0)，尺寸 = 客户区尺寸 |
| `click at=[x,y]` | 客户区 |
| `api.grab(x,y,w,h)` | **屏幕**（要减客户区原点才是截图坐标） |
| `api.client_rect(hwnd)` | 返回 `(origin_x, origin_y, w, h)`，屏幕坐标下的客户区左上角 |

另有一条：**按钮点两次没反应，先怀疑坐标，再怀疑按钮 disabled**。
判断 disabled 的办法是看颜色是否变浅（禁用态通常是低饱和灰）；
颜色正常却不响应，几乎一定是点在按钮外面。
