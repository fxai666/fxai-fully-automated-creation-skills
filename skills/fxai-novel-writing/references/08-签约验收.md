## 一、何时做

`check_novel.py` 与模型终检（`references/06`）均通过后、投稿番茄前，由大模型按本册对正文与档案做一次内容验收，结论落 `<书名>/签约验收报告.md`。

## 二、平台流程门槛

这一节是**发布与申请的前置条件**，不满足时内容再好也递不上去。

| 项 | 平台口径 |
|---|---|
| 签约模式 | 连载签约 / 完本签约，二选一 |
| 审核链 | 连载：安全审核 → 质量评估；完本：**完结审核** → 安全审核 → 质量评估 |
| 申请机会 | 各模式共 **3 次**，用完即无法再签。连载模式在 **2 万 / 5 万 / 8 万字**时各有 1 次；完本模式须用**非默认书名与封面**、并达到对应主分类的最低完本字数 |
| 重报间隔 | 完结审核不通过：改后间隔 **3 天**再报；安全审核不通过：间隔 **7 天**；质量评估不通过：**总共只有 2 次**修改重报机会 |
| 评估时长 | 完结 / 安全 / 质量三环节各 **1–5 个工作日**，双休与法定节假日顺延 |
| 结果通知 | 无论通过与否都发站内信；不通过时提示「审核不通过」或「不符合平台签约质量要求」 |
| 单章字数 | 每章 **≥1000 汉字**（不足则点不了「下一步」，无法发布）、**≤50000 汉字**；常见 2000–6000 字 |
| 未签约后果 | 无平台推荐、无打赏入口、无稿费 |

- 单章字数由 `check_signing.py` 的「单章字数」项查，不足 1000 字报 ERROR。
- **短篇按发布方式判断**：整篇作一章发布，则 1000 字门槛对全篇生效（8 千字以上无压力）；若把篇内小节拆成独立章节发布，则**每一节**都须 ≥1000 字，不足的须合并或重新切分。脚本按小节计数，拆章发布时其 ERROR 即为真问题，整篇发布时可忽略该项。
- 走**完本模式**的书，投稿前多一道完结审核，须先写到该主分类的最低完本字数。写一半就申请会被卡在完结审核。
- 账号等级是否限制可选模式（如 Lv.0 / Lv.1 只能选完本），平台现行帮助文档未写，**以创建作品页实际展示的按钮为准**，报告按后台实际状态记录。

### 3.2 质量评估的「低质」项（原文五项：粗制滥造 / 逻辑混乱 / 结构失常 / 内容空洞 / 刻意注水）

| 低质表现 | 判定口径 | 查证范围 |
|---|---|---|

| 无关环境描写 | 大量与剧情毫无关联的环境描写 | 全文 |
| 空洞升华 | 大量空洞无意义的升华文本 | 全文 |
| 人物塌陷 | 人物形象单薄、出场突兀，或**前后主角不一致** | 02-人物画像 与正文对照 |
| 连续低质 | 非正常手段连续发布低质、逻辑不连贯内容 | 全文 + `check_signing.py` 重复段落与相邻重复句项 |
| 机械扩写 | 重复堆砌、大段无效铺陈拉长篇幅 | `check_signing.py` 重复段落与相邻重复句项 |

- **本书的高危项是「空洞升华」**：现实章以白描抒情收束，容易滑向"大量空洞无意义的升华文本"。逐章查一句：这段抒情有没有落在具体物件或动作上；落不到，就是升华文本。
- 「前后主角不一致」要按人物画像核对动机与行为，不只看名字对不对。

## 四、B 类：内容评估（自建量表）

平台原文只给四条**定性**标准，不给分值、不给分项权重。下面的五项 0–5 分与 ≥18 线是本技能自建的操作量表，用于内部排序与定位短板，**不是平台评分口径**，报告里不得表述为"达到平台分数线"。

### 4.1 平台四条 → 本技能五项

| 平台原文（质量评估·优质内容标准） | 对应项 |

## 五、本技能投稿体例

**这一节全部是本技能自建的规矩，平台没有对应条款。** 违反它不算平台否决，但投稿前必须清干净；报告里不得把本节任何一条写成「平台不通过」。

| 项 | 平台依据 | 本技能口径 |
|---|---|---|
| 必须分段 | 章节排版问题：**一个章节只有几个大段落的，会因内容排版有误而无法通过审核**；须用换行键分段，空格键分段无效 | 段落目标 40–80 汉字，单段上限 300 字 |
| 场景分隔符 | 平台无此条款 | 不用 `---`、不用 `＊　＊　＊`，场景切换只靠段落间隔 |
| 章标题 | 平台不解析 Markdown | 标题独立成行、不带 `#` |
| Markdown 标记 | 平台不解析 Markdown | 不用 `**`、`*`、反引号；`【】` 是内容，保留 |
| 引号 | 平台无此条款 | 只用中文弯引号 `“”`；`『』` 按层级降为 `‘’` |
| 中英混排间距 | 平台自动排版会吞掉段内空格 | 不留间距（`鸡 3 只` → `鸡3只`、`VR 记忆` → `VR记忆`）；英文词间空格与标题行间隔空格保留 |
| 第一人称禁区 | 平台无此条款，且**不对叙事人称设要求** | 主角以「我」自称时不写主角父母的生病与死亡，见 `references/07` 第九节 |

- 叙事人称（第一 / 第三）不列入否决项：现行《签约评估》只列四条优质标准，未涉及人称。第一人称题材禁区是本书的创作规则，与人称合规无关，**不得据此判定人称不合规**。
- 场景分隔符与 Markdown 标记属体例项，归本节，不入 A 类。

## 七、与脚本的分工

- `scripts/check_signing.py` 查可量化的内容信号：单章字数（1000–50000）、段落长度、重复段落、相邻重复句、短章占比、套话词频、对话占比、标点混用、Markdown 标记与中英混排间距残留、章名重复。全书均值会被长章拉高、掩盖碎片章，故段落密度项**先判全书均值、再逐章判**。
- 本册查内容质量：题材、立意、创新、代入感、潜力，由大模型完成。
- 脚本报 ERROR 时，先按 ERROR 项修正文，再回到本册做打分。

## 八、格式整改

段落类格式缺陷（单句成段、节拍级场景分隔符）用 `scripts/reflow_paragraphs.py` 修，**只动分段、不动文字**：

```
python scripts/reflow_paragraphs.py <书名目录> --scene auto --target 60 --merge-dialog 0 --apply
```

- `--scene auto`：逐章判**分隔符的平均间隔**（章内汉字数 ÷ 分隔符数）。间隔 < `--scene-gap`（默认 100）判为分段符，按 `soft` 处理（跨分隔符合并、输出无分隔符）；间隔达标判为真场景分隔，按 `keep` 保留。
  - 判间隔而非判个数：同是 2000 字的章，9 个分隔符（间隔 230 字）是换场，40 个（间隔 50 字）是每段一条。
  - 一部书里两种写法并存时，只有判间隔才能把同一批章整批分开，不出现同批章一半被判分段符、一半被判场景符。
- `--merge-dialog 0`：对话行一律独立成段。
- `--target 60`：叙述段目标长度（汉字），达到即断段。
- 不加 `--apply` 时输出到 `<书名目录>/重排预览/`，原文不动。
- 该脚本对已完成章幂等，可在现正文上重复跑。

标点与标记体例用 `scripts/normalize_punct.py` 统一，**只动标点、标记与空格、不动文字**：

```
python scripts/normalize_punct.py <书名目录> --apply [--scene mark|none|keep] [--md strip|keep] [--heading strip|keep] [--space strip|keep]
```

- `--scene mark`：场景分隔行统一为 `＊　＊　＊`（全角星号 + 全角空格）。
- `--scene none`（投稿稿用这个）：场景分隔行整行删除，场景切换只靠段落间隔。
- `--scene keep`：分隔行不动。
- 识别对象含 `---` 与已有的 `＊　＊　＊` 两种写法。平台编辑器不解析 Markdown，`---` 会原样显示为三条横线，故 `keep` 不用于投稿稿。
- 走 `mark` 前先用 `reflow_paragraphs.py --scene auto` 把节拍级分隔符合并掉，否则满屏标记。
- `--md strip`（默认）：去掉 `**粗**`、`*斜*`、`` `代码` `` 的标记符、保留其中文字。系统面板写法 `**【提示】**` 去标记后成 `【提示】`，方括号 `【】` 是内容的一部分，保留。
- `--heading strip`（默认）：去掉行首 `#{1,6}` 及其后空白，保留标题文字（`# 第001章 章名` → `第001章 章名`）。正文体例不带标题标记，见 `references/01` 三、`references/02` 六。
- `--space strip`（默认）：去掉中英混排间距（`鸡 3 只` → `鸡3只`、`VR 记忆` → `VR记忆`、`存档 / 读档` → `存档/读档`）。英文词间空格（`GAME OVER`）与汉字之间的空格一律保留，标题行 `第NNN章 章名` 整体不动。
- 引号：直引号 `"..."` → `“...”`；直角引号 `「」` → `“”`；`『』` 按层级处理（一级 `“”`，嵌在 `「」` 内降为二级 `‘’`）。
- 直引号须同行成对，存在落单直引号时报错退出且不写任何文件。
- `--only scene|quote|md|heading|space` 可只处理其中一项。
- 不加 `--apply` 时输出到 `<书名目录>/标点预览/`，原文不动。

整改前先整体备份原文；整改后跑 `check_signing.py` 复验，密度项与标点项须为 OK。
