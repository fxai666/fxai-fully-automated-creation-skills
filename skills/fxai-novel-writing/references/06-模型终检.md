# 06 模型终检

## 一、何时做

正文与档案全部写完、`check_novel.py` 通过后，交付前由**大模型通读一遍**。

## 二、检测项

| 项 | 查什么 |
|---|---|
| 错别字 | 同音字 / 形近字误用（的得地 / 在再 / 做作 / 即既 / 其他其它 / 账帐 / 需须） |
| 标点 | 中英文标点混用、成对标点缺失（引号 / 括号 / 书名号）、省略号与破折号用法 |
| 语病 | 成分残缺、搭配不当、语序混乱、重复啰嗦 |
| 逻辑 | 时间线、因果关系、前后矛盾 |
| 设定一致性 | 人名 / 地名 / 称谓 / 年龄 / 能力设定全书统一，且与人物画像一致 |
| 章节结构 | 章号连续、章名与目录及梗概一致 |
| AI 味 | 模板化句式、过度排比、口号式结尾 |

## 三、签约质量维度终检（每本必查，短篇长篇通用）

`08-签约验收.md` 的四条优质标准与五项低质红线是**每一本小说的核心质量检测**，不是投稿前才看的一次性门禁。脚本查不出「内容空洞」「立意不深」「结构失常」，这一节由大模型在交付前逐项过。

### 3.1 五项低质红线（命中任一即须改，不等到投稿）

| 红线 | 通读时查什么 |
|---|---|
| 粗制滥造 | 有无批量重复、大段无效铺陈、拼接痕迹；重复段落由脚本查，语感重复由本册查 |
| 逻辑混乱 | 时间线、因果、人物动机能否串起来；前后矛盾逐条列 |
| 结构失常 | 卷/幕是否分段清晰；有无某卷突然换写法、某章游离主线；长篇每 20 章抽查一次节奏 |
| 内容空洞 | 每段抒情是否落在具体物件或动作上；落不到就是空洞升华。拎出所有升华段逐句审 |
| 刻意注水 | 有无为凑字数的同义反复、环境描写堆砌、对话灌水；字数达标但信息量未增加的章 |

### 3.2 四条优质标准（逐条给结论，写进终检记录）

| 平台标准 | 终检问题 |
|---|---|
| 题材切入、开篇事件或人物设定有创新性，能快速激发好奇 | 第一章第一句是不是动作或对话？前 1000 字有没有具体冲突？前三章是否说清了这本书的看点？ |
| 三观正向，立意深刻，自然融入故事 | 主题句有没有落在具体人物经历上？有没有说教段？主角的行为是否由立意驱动而非作者硬塞？ |
| 文笔清晰流畅，准确生动地讲好故事 | 有无病句、AI 味、口号式结尾；描写是否落在感官细节上 |
| 结构完整、主线清晰、节奏稳定，长期发展潜力大 | 主线一句能否说清；伏笔是否都有回收；节奏是否前紧后松；短篇看收束，长篇看是否可持续写下去 |

判定：五项红线全清 + 四条标准均有「是」的结论，终检通过；任一项答不上来，退回对应阶段改写，不等到投稿验收。

## 四、做法

- 通读范围：正文全文 + 全部档案。
- 问题逐条列出：位置 + 原文 + 建议改法。
- 改完复读改动处，确认无新增问题。
- 终检通过才交付；3.1 与 3.2 的结论一并写进终检记录。

## 五、与脚本的分工

- `check_novel.py` 查硬指标：字数、章节标签、档案齐备。
- `check_signing.py`（投稿前）查可量化信号：单章字数、段落密度、重复、标点、体例残留。
- 本册查软指标与签约质量维度：语言、逻辑、一致性、低质红线、优质标准，由大模型完成。
- 脚本全绿不等于质量合格；内容空洞、立意不深、结构失常只有人工能判。
