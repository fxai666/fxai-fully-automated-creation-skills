# 04 · 声音与节拍

> **何时读**：选音色、出配音、算口播时间码、混 BGM、核成片时长时。

## 两条声音路线

| 路线 | 声音从哪来 | 适用 |
|---|---|---|
| 系统生成音 | H3 镜内自带口播与音效（`audio_mode="系统生成"`） | A 类产品演示片，人物在画内说话 |
| 后期配音 | 先出 wav，再按时间码贴到无声画面上 | B / C / D 类，旁白不在画内 |

- A 类用系统生成音时，**画面里的人在说什么由提示词决定**，后期只补 BGM 或整段不加。
- B / C / D 类一律后期配音：一条一条出 wav，一条对应一个语义单元（一句话或一段）。

## 配音

- 引擎：CosyVoice3（`POST /synthesize`，端口 8086），走 `fxai-voiceover` 的封装，不自拼请求。
- 音色：定一次就写进 `delivery.json`，后续各条沿用同一 `speaker_id` + `ref_audio`，
  同片多条音频换音色会听起来像两个人。
- `instruct_text` 给口语语气、`speed` 恒为 1.0、变速交给 `speed_mode="server"`；
  稿子超长靠压字解决，不靠拉 `speed`（拉过 1.1 会吞字）。
- 每条音频落项目根，命名 `<用途><序号>.wav`（`广告口播01.wav`），序号即口播稿行号。
- 出完立刻核时长：`字数 ÷ 5` 与实测秒数差在 10% 内为正常；差得多说明稿子被 TTS 吃字，回查标点。

## 时间码

口播按绝对时间贴到成片，不用「跟着画面走」的相对偏移——成片剪一次，绝对时间改一处即可。

- 时间码表按段落累计：第 n 段起点 = 前 n-1 段时长之和；首段从 0.3–0.5s 起，
  留一点入画余量。
- 混音：各条 `adelay=<毫秒>:all=1` + `amix=inputs=N:normalize=0`。
  `normalize=0` 必须显式给，默认会把各路音量均分，口播被压掉一半。
- 单声道源先转立体声：`aformat=sample_fmts=fltp:channel_layouts=stereo`。
- 时长不等长时按最长轨收，或 `-t <成片时长>` 裁齐。

## 音量

| 轨 | 取值 |
|---|---|
| 口播 | 1.0（基准） |
| BGM | 0.20（低于口播约 14dB），`atrim` 到成片时长 |
| 混后峰值 | ≤ -1 dBFS，超出即整体降一档 |

BGM 只在段间留白处抬到 0.28，口播段压回 0.18–0.20；整片一条直线的 BGM 会跟口播抢中频。

BGM 原样铺满，画面从第一帧起就有 BGM，片尾自然收；不得加 `afade`。

## 成片音轨验收

- 成片必须含音轨流（`ffprobe` 见 `h264` + `aac`）；合成主链不得无条件 `-an`。
- 混音后峰值 ≤ -1 dBFS；口播 1.0 基准不降，BGM 0.18–0.20 垫底。

## 节拍表

`timeline.json` 是标题卡与章节的共用真值：

```json
{"total": 50.84, "beats": [{"i": 1, "start": 0.0, "end": 6.22, "title": "", "sub": "", "foot": ""}]}
```

- `beats` 的 `start` / `end` 与口播段落起点一致，差在 0.3s 内；标题卡按它切换。
- `total` 填实测成片时长（`ffprobe` 取得），不填计划时长。
- 段数控制在 7–9 条；超出就把两条并一条，标题卡每 3 秒换一次会盖住画面。

## 时长核对

1. `ffprobe` 取成片时长，与 `sum(各段时长)` 差 ≤ 0.2s；
2. 各条口播的起点与对应段落起点差 ≤ 0.3s；
3. 末句说完距片尾 ≥ 0.5s，留收口气；
4. 时长与 `delivery.json`、交付清单、文案里的「N 秒广告」三者一致。
