# 02 · 标题卡模板库

> **何时读**：用户说「套个模板 / 又要加推广卡 / 上次那个侧栏字条再来一条」，或想少想一遍排版时。
> 模板 = 已经验过的「文案骨架 + 时间分配 + 排版参数 + 生成命令」四件套，直接换字就能出片。
> 照抄模板不等于跳过验收：叠完必须抽帧看一遍（见第五节）。

## T-01 · 侧栏三步引导（`side-rail-3step`）

**一句话**：横版片左侧钉死一条竖排三拍卡，从头到尾不断，三拍讲清「东西在哪 → 怎么找到 → 选哪个」。

模板文件：`templates/side-rail-3step.json`（可直接 `--timeline` 用，改字即可）。

### 一、什么时候用

| 条件 | 说明 |
|---|---|
| ✅ 横版（16:9 / 4:3 / 非竖屏） | 竖排版式的前提，竖屏别用（竖屏走顶部横排） |
| ✅ 全片常驻 | 模板假设三拍首尾相接、覆盖 0 → 片尾，中途不留空 |
| ✅ 有明确的"去哪找东西"诉求 | 引导观众到平台/店铺/镜像广场，或分三步讲操作 |
| ✅ 人物基本居中或偏一侧 | 侧栏占画面宽约 21%，主体偏另一侧才不打架 |
| ⛔ 竖屏片 / 人物长期贴在预定侧栏侧 | 换 `right` 或改用顶部横排 |
| ⛔ 客户要干净画面 / 要投放到不接受角标的站点 | 这种片**单独出纯净版**，卡只叠到"发群/发朋友圈"的那一版上 |

### 二、文案骨架（三步，别乱序）

顺序就是观众的行动链，**先说在哪，再说怎么找，最后说选哪个**：

| 拍 | 主标（≤5 字最佳） | 副标（≤8 字最佳） | 作用 |
|---|---|---|---|
| ① | 平台 / 地点名 | 这东西叫什么 | 点明「在哪」 |
| ② | 入口名（广场 / 商店 / 频道） | 搜什么关键词 | 告诉「怎么找」 |
| ③ | 具体产物名 | 一个动作（一键部署 / 立即使用） | 落到「选哪个」 |

T-01 的现成版式（仙宫云推广）：

```
① 仙宫云      凤希AI角色替换
② 镜像广场    搜凤希AI
③ 全自动镜像  一键部署
```

换成别的推广只需替换词位，**不要改动拍数与结构**。

### 三、时间分配

- 三拍按片长**三等分**，尽量落在镜头切换点上（换字卡在切镜处最不扎眼）。
- 首拍从 `0.0` 起，末拍 `end` = 片长（可略超 0.05s，脚本按帧裁）。
- 每拍不短于 2 秒，短于 2 秒字还没读完就换了。
- 硬切无淡入（`overlay_cards` 用 `enable=between`），**换字点避开人脸特写**。

### 四、排版参数（固定，别在项目里另调）

| 项 | 值 | 为什么 |
|---|---|---|
| `--position` | `left`（或 `right`，看人物偏哪边） | 人物居中时，交替会有一拍压人；钉死一侧最稳 |
| 锚点 | 顶对齐，`left=96`、`top=80`（**单屏 960×704** 实测） | 按短边 0.12 / 0.10 估算，与 cardkit 小档一致；**叠加在对比片上时锚点另算，见下一节** |
| 主标 | **≤5 字**（704 高时） | 竖排安全区 = 704 − 80×2 = 544px，主标 64px/字，7 字就顶破边框 |
| 块宽 | 约占画面宽 21% | 再宽就压到人物了 |

**必须做顶对齐**：`gen_cards.py` 的竖排是「块整体垂直居中」，三拍文字长短不一会让主标在换字时上下跳几十像素。用 `scripts/align_titles.py` 统一裁边 + 钉同一锚点。

### 四之二、叠在「上下对比片」上：先拼后贴，别先贴后拼

对比片（上原片 / 下成片，或左右并排）叠字时，**顺序决定字号和可控性**，先想清楚：

| 顺序 | 结果 | 评价 |
|---|---|---|
| 先贴成片 → 再上下拼 | 画布只有半屏高（如 960×704），字号被压在小档 64；字只能落在半屏内 | ❌ 字小，且改字要重拼整片 |
| **先上下拼 → 再在整张画布上贴** | 画布变 960×1408，短边 960 → 字号**自动升到中档 96**（大 50%）；落位可自由选 | ✅ 默认走这条 |

拼接后画布的**锚点换算**（以 960×704 单屏 → 960×1408 上下堆叠为例）：

| 想要的效果 | `--left` / `--top` | 说明 |
|---|---|---|
| **只落在下半（推荐）** | `144 / 772` | 下半区 704 高，块高约 567，留上下各 68 余量。字全在成片侧，背景统一 |
| 骑在中线上（跨缝） | `144 / 620` | 主标起点压在中线上方 84px，主标跨缝、副标落下半 |
| 整块垂直居中于全片 | `144 / 420` | 块中心≈中线，跨缝最多 |

🔴 **跨中线不是默认选项**。它只在「上下两半亮度接近」时成立（同一个镜头两种处理、光照没变）。
本片实测：上半原片偏亮（米黄沙地）、下半成片偏暗，字条跨过中缝时底色从米黄跳到深褐，
字被中缝"切成两段"，反而比只放半屏更难读。**判据：抽一帧看中缝两侧亮度差，目测明显就别跨。**

左右并排片同理：画布变 1920×704 或类似，锚点按左半/右半区算；此时短边仍是 704，字号不升档，
但可以把三拍卡分别钉在中间过渡带两侧。

### 五、生成命令（四步）

```bash
SK="${HOME}/.workbuddy/skills/fxai-title-card/scripts"
TPL="${HOME}/.workbuddy/skills/fxai-title-card/templates/side-rail-3step.json"

# ① 复制模板改字
cp "$TPL" ./timeline.json
#（编辑 title / sub / start / end）

# ② 出卡（尺寸 = 目标视频尺寸）
python "$SK/gen_cards.py" --timeline timeline.json --size 960x704 --position left --out titles_raw

# ③ 顶对齐（关键，缺这步换字会跳）
python "$SK/align_titles.py" --src titles_raw --out titles --size 960x704 --left 96 --top 80

# ④ 叠卡
python "$SK/overlay_cards.py" --video 母版_无卡.mp4 --titles-dir titles \
       --timeline timeline.json --out 带卡.mp4 --crf 21
```

`--crf 21` 收口：`overlay_cards` 默认 crf 16 是从**已压缩源**重编，体积会翻倍而画质不涨。

### 六、三个必须防的坑

1. 🔴 **卡烧进画面后不可逆**。叠之前必须先另存一份 `母版_无标题卡.mp4`，改一个字都从母版重来。
   模板假设"卡是最后一道工序"——卡压完之后只剩混音/封装。
2. 🔴 **别用同一份文件既当纯净版又当带卡版**。要投放到其他站点的那一版，**画面必须零贴片**；
   带卡的只给"发群 / 发朋友圈 / 内部演示"用。两条片子并行出，别串。
3. 🔴 **换字点不要在正脸特写上**。硬切会像闪一下；挪到切镜处或人物背对/远景时。

### 七、验收（叠完必做）

```bash
ffmpeg -y -v error -i 带卡.mp4 -vf "select='eq(n,60)+eq(n,250)+eq(n,420)+eq(n,700)',scale=470:-2,tile=2x2" \
       -frames:v 1 check.jpg
```

看图确认四件事：① 三拍文字内容与设计一致；② 每拍主标起始高度相同（不跳）；③ 文字没压人脸/没被背景吞掉；
④ 既有的右下角标还在、没被挤掉。
