# 02 · 标题卡模板库

> **何时读**：用户说「套个模板 / 又要加推广卡 / 上次那个侧栏字条再来一条」，或想少想一遍排版时。
> 模板 = 已经验过的「文案骨架 + 时间分配 + 排版参数 + 生成命令」四件套，直接换字就能出片。
> 照抄模板不等于跳过验收：叠完必须抽帧看一遍（见第五节）。

`T-<序号> <中文名>`，序号按入库顺序，不复用。新增模板追加到本册末尾，并在本节加一行索引。

|---|---|---|---|

> 曾用名「侧栏三步引导 / `side-rail-3step`」（V2.0 起）。改名原因：它的本质是**多段循环**的引导文字卡，

## T-01 · 多段循环引导卡（`guide-loop-card`）

**一句话**：横版片贴一组竖排引导卡，讲清「东西在哪 → 怎么找到 → 选哪个」；短片一次排完，长片整组循环，
相邻拍左右交替换边、一拍显示几秒就撤。

模板文件：`templates/guide-loop-card.json`（可直接 `--timeline` 用，改字即可）。

### 一、什么时候用

| 条件 | 说明 |
|---|---|
| ✅ 横版（16:9 / 4:3 / 非竖屏） | 竖排版式的前提，竖屏别用（竖屏走顶部横排） |
| ✅ 引导信息需全片可见 | 片 ≤30s 几步首尾相接一次排完；片 >30s 走**循环排法**（见第三节）——一拍挂十几二十秒等于没贴 |
| ✅ 有明确的"去哪找东西"诉求 | 引导观众到平台/店铺/镜像广场，或分几步讲操作 |
| ✅ 人物基本居中或左右轮换 | 卡占画面宽约 21%；左右交替时**每一拍的落点都要抽帧确认不压人**，人物长期钉死在一侧才回去钉另一侧 |
| ⛔ 竖屏片 | 改用顶部横排 |
| ⛔ 客户要干净画面 / 要投放到不接受角标的站点 | 这种片**单独出纯净版**，卡只叠到"发群/发朋友圈"的那一版上 |

### 二、文案骨架（行动链，别乱序）

顺序就是观众的行动链，**先说在哪，再说怎么找，最后说选哪个**。默认三步，也允许 2/4 步——
只要顺序保持行动链、每拍一句即可（`make_loop_timeline.py` 吃任意步数）：

| 拍 | 主标（≤5 字最佳） | 副标（≤8 字最佳） | 作用 |
|---|---|---|---|
| ① | 平台 / 地点名 | 这东西叫什么 | 点明「在哪」 |
| ② | 入口名（广场 / 商店 / 频道） | 搜什么关键词 | 告诉「怎么找」 |
| ③ | 具体产物名 | 一个动作（一键部署 / 立即使用） | 落到「选哪个」 |

T-01 的现成版式（仙宫云推广）：

```
① 仙宫云      全自动化体系创作
② 镜像广场    搜凤希AI
③ 全自动镜像  按详情教程部署
```

换成别的推广只需替换词位，**不得打乱行动链顺序**。

### 三、时间分配：短片一次排完，长片整组循环

**判据一句话：单拍挂字超过 10 秒等于没贴。** 片长除以 3 超过 10s（即片 >30s），就别三等分，改走循环。

#### 长片循环口径（固定值，不在项目里调）

| 参数 | 值 | 为什么 |
|---|---|---|
| `--on`（一拍显示时长） | **7.0s** | 竖排 8 字副标读完约 2–3s，7s 在可读前提下从容不赶，又不到挂住变背景的程度 |
| `--off`（拍间/组间留白） | **1.5s** | 换字那一下要有缓冲，这 1.5s 也让画面喘气 |
| 换边 | **相邻拍左右交替**（`side` 按拍序自动写，跨循环连续） | 一拍只挂几秒、进出频繁，同位置硬切会闪跳扎眼；左右轮换后相邻两拍落点不同，切感自然 |
| 循环周期 | 步数 × (ON+OFF)，三步组 = **25.5s** | 观众约 25 秒看到一遍完整引导链，记忆点反复敲 |
| 收尾规则 | 剩余 < ON 不起新拍；残拍 < 2s 直接不放 | 尾巴挂半截卡很难看 |

引导文案顺序**每轮不变**（在哪 → 怎么找 → 选哪个），只整组重复，不打乱、不跳拍。

> 实测参考：60–120s 的推广/教程片，这套 25.5s 周期能循环 3–6 组，观众任意时刻回头都能看到卡在场，
> 但任何一拍都不会变成"挂着不动的背景"。
> 口径演进（ep2 实测定档）：ON=3.5 太赶→ 5s 仍偏快干扰观感 → **定为 7s**；整片同侧进出扎眼 → 改相邻拍左右交替。

#### 短片（≤30s）一次排完

- 几拍按片长**等分**，尽量落在镜头切换点上（换字卡在切镜处最不扎眼）。
- 首拍从 `0.0` 起，末拍 `end` = 片长（可略超 0.05s，脚本按帧裁）。
- 每拍不短于 2 秒，短于 2 秒字还没读完就换了。

#### 通用

- 硬切无淡入（`overlay_cards` 用 `enable=between`），**换字点避开人脸特写**。
- 循环排法进出密（每 8.5s 一次），不可能全落切镜——靠左右换边 + `--off` 留白双重缓冲，
  不强求逐点对齐切镜；但**首拍起点仍从 0.0 起**。
- 人物**长期钉死在画面一侧**时不要交替（另一侧每一拍都会压人）：
  `make_loop_timeline.py --no-alternate` 钉死空着那一侧，整片抽帧确认不压主体。

### 四、排版参数（固定，别在项目里另调）

| 项 | 值 | 为什么 |
|---|---|---|
| 落边 | timeline 每拍 `side` 字段逐拍定（默认左右交替） | 人物居中的片子左右都能落；长期压人一侧才 `--no-alternate` 钉死 |
| 锚点 | 顶对齐，左锚 `left=96`、`top=80`（**单屏 960×704** 实测）；右锚镜像 = 内容右缘贴 `W−96` | 按短边 0.12 / 0.10 估算，与 cardkit 小档一致；**叠加在对比片上时锚点另算，见下一节** |
| 主标 | **≤5 字**（704 高时） | 竖排安全区 = 704 − 80×2 = 544px，主标 64px/字，7 字就顶破边框 |
| 块宽 | 约占画面宽 21% | 再宽就压到人物了 |

**必须做顶对齐**：`gen_cards.py` 的竖排是「块整体垂直居中」，各拍文字长短不一会让主标在换卡时上下跳几十像素。用 `scripts/align_titles.py` 统一裁边 + 钉同一锚点；左右交替时必须带 `--timeline`（按拍的 `side` 分边，右缘镜像等距）。

### 四之二、叠在「上下对比片」上：先拼后贴，别先贴后拼

对比片（上原片 / 下成片，或左右并排）叠字时，**顺序决定字号和可控性**，先想清楚：

| 顺序 | 结果 | 评价 |
|---|---|---|
| 先贴成片 → 再上下拼 | 画布只有半屏高（如 960×704），字号被压在小档 64；字只能落在半屏内 | ❌ 字小，且改字要重拼整片 |
| **先上下拼 → 再在整张画布上贴** | 画布变 960×1408，短边 960 → 字号**自动升到中档 96**（大 50%）；落位可自由选 | ✅ 默认走这条 |

拼接后画布的**锚点换算**（以 960×704 单屏 → 960×1408 上下堆叠为例）：

| 想要的效果 | `--left` / `--top` | 说明 |
|---|---|---|
| **只落在下半（推荐）** | `144 / 772` | 下半区 704 高，块高约 567，留上下各 68 余量。字全在成片侧，背景统一 |
| 骑在中线上（跨缝） | `144 / 620` | 主标起点压在中线上方 84px，主标跨缝、副标落下半 |
| 整块垂直居中于全片 | `144 / 420` | 块中心≈中线，跨缝最多 |

🔴 **跨中线不是默认选项**。它只在「上下两半亮度接近」时成立（同一个镜头两种处理、光照没变）。
本片实测：上半原片偏亮（米黄沙地）、下半成片偏暗，字条跨过中缝时底色从米黄跳到深褐，
字被中缝"切成两段"，反而比只放半屏更难读。**判据：抽一帧看中缝两侧亮度差，目测明显就别跨。**

左右并排片同理：画布变 1920×704 或类似，锚点按左半/右半区算；此时短边仍是 704，字号不升档，
但可以把三拍卡分别钉在中间过渡带两侧。

### 五、生成命令（四步）

```bash
SK="${HOME}/.workbuddy/skills/fxai-title-card/scripts"
TPL="${HOME}/.workbuddy/skills/fxai-title-card/templates/guide-loop-card.json"

# ① 排 timeline
# 短片（≤30s）：复制模板改字，几拍等分（side 已逐拍写好）
cp "$TPL" ./timeline.json
#（编辑 title / sub / start / end / side）
# 长片（>30s）：引导文案 × 循环（默认 ON=7s OFF=1.5s、相邻拍左右交替，别在单项目里调）
# 先把定稿文案（只取 title/sub/foot）放一个 json，再：
python "$SK/make_loop_timeline.py" --steps <引导文案.json> --total <片长秒> --out ./timeline.json

# ② 出卡（timeline 里每拍有 side 就按 side 落边；--position 只是无 side 拍的兜底）
python "$SK/gen_cards.py" --timeline timeline.json --size 960x704 --position left --out titles_raw

# ③ 顶对齐 + 按 side 分边（关键，缺 --timeline 左右拍会被摞到同一边）
python "$SK/align_titles.py" --src titles_raw --out titles --size 960x704 --left 96 --top 80 --timeline timeline.json

# ④ 叠卡
python "$SK/overlay_cards.py" --video 母版_无卡.mp4 --titles-dir titles \
       --timeline timeline.json --out 带卡.mp4 --crf 21
```

`--crf 21` 收口：`overlay_cards` 默认 crf 16 是从**已压缩源**重编，体积会翻倍而画质不涨。

### 六、三个必须防的坑

1. 🔴 **卡烧进画面后不可逆**。叠之前必须先另存一份 `母版_无标题卡.mp4`，改一个字都从母版重来。
   模板假设"卡是最后一道工序"——卡压完之后只剩混音/封装。
2. 🔴 **别用同一份文件既当纯净版又当带卡版**。要投放到其他站点的那一版，**画面必须零贴片**；
   带卡的只给"发群 / 发朋友圈 / 内部演示"用。两条片子并行出，别串。
3. 🔴 **换字点不得在正脸特写上**。硬切会像闪一下；挪到切镜处或人物背对/远景时。

### 七、验收（叠完必做）

```bash
ffmpeg -y -v error -i 带卡.mp4 -vf "select='eq(n,60)+eq(n,250)+eq(n,420)+eq(n,700)',scale=470:-2,tile=2x2" \
       -frames:v 1 check.jpg
```

看图确认五件事：① 各拍文字内容与设计一致；② 同侧各拍主标起始高度相同（不跳）；③ 文字没压人脸/没被背景吞掉；
④ 左右交替的落边与 timeline 的 `side` 一致，且**换到另一侧的那一拍同样不压人物**（左右两侧都要各抽帧看过）；
⑤ 既有的字幕行/右下角标还在、没被挤掉。
