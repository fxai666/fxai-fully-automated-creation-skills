# 09 · 分镜设计与验收

> **分镜由模型设计，不由脚本写死。**
> 本册给两样东西：① 设计规范（模型按它出分镜）② 验收清单（智能体按它自检）。

## 为什么分镜交给模型

固定动作库（抬手 / 摊掌 / 前倾）配固定运镜轮换，是把创意决策写死在代码里：
12 段永远那 8 个动作循环，跟这段讲什么无关，画面必然是「站着念稿」。

镜头怎么设计，取决于**这一段在讲什么 + 场景里有什么**。这是模型的活，不是 if-else 的活。

代码只负责三件事：把分镜拼成提示词、调模型、把结果拼起来。

## 设计分镜时手里有什么

| 输入 | 从哪来 |
|---|---|
| 逐段文案 | `口播文案.md`（空行分段） |
| 每段时长与时间码 | `music/dh-voNN.wav` 累加，或 `_beat_times.json` |
| 场景图与场景描述 | `image/scene_NN.png` + `scenes.txt` |
| 镜头语言规范 | `08-镜头语言.md`（景别 / 机位 / 运镜 / 构图 / 光线 / 技术边界） |

## 设计规范（模型按这个出分镜）

### 每一镜回答七个问题

1. **这段在讲什么**——内容决定镜头，不是轮换决定镜头
2. **人物此刻在做什么**——动作从这段话里长出来
3. 🔴 **主体的运动轨迹**——从哪走到哪、什么姿态、多快（08 册 4.2）
4. 🔴 **场景物件在怎么变**——屏幕滚不滚、键盘按不按、纸翻不翻（08 册 4.3）
5. **镜头怎么动**——一个镜头一种运动
6. **画面停在哪**——结束状态；不写这条，结尾容易飘
7. **观众要看到什么**——是否需要 B-roll 补证据

第 3、4 两条决定画面活不活。漏掉第 3 条，人物就是原地比划；漏掉第 4 条，空镜就是静图。

### 硬约束（技术边界，越界会出废片）

- **机位分两层**：`camera`（生成层）只走固定 / 极缓推近；拉远、横移、摇、手持写进
  `move` 字段，由后期 `camera_move.py` 执行（08 册 4.4）。混着写会让背景逐段重算 → 闪烁跳跃
- **主体位移**可以写，但**慢、短、有明确终点**：「走到桌前停下」安全，
  「在房间里来回走」「横穿画面」会把位移放大成画面晃动（08 册 4.2 位移边界表）
- 🔴 **每一镜都要写 `motion`**；写「站在原地讲解」等于没写
- 🔴 **空镜 / B-roll 必须写 `dynamics`**；没有动态描述，出图就是一张静照
- 🔴 **空镜 / B-roll 用中景或中远景**，特写与近景会让画面失去场景上下文
- 🔴 **`size` 只填六档标准景别词之一**（远景 / 全景 / 中全景 / 中景 / 近景 / 特写）。
  代码拿它去查 `av.SHOT_SPEC` 换成标准描述；写成自由文本或夹英文
  （`中全景，头顶到大腿以上入画，…，headroom above hairline`）会**查表落空**，
  退化成原样拼接，景别约束等于没写——实测第 1 镜就是这个原因渲成了远景。
  判据见 `preflight` ★13。
- **场景里没有的东西不写**：场景图里没有白板，就别写「转身指白板」
- 🔴 **头部与眼神一律不写**：分镜里没有 `head` 字段，也不写点头节拍、仰头低头、
  转头回看、目光与镜头交流（08 册 4.5）。头交给模型自己处理，只留身体朝向。
- 每段动作**各不相同**，同一段里只做**一种**主要动作

### 字段分工：同一件事只写一次

一镜的 `entry` / `motion` / `action` / `dynamics` 会被拼成**同一条动作链**，
所以同一件事在两个字段里各写一遍**不是强调**：权重被摊薄到两句上，
第二句还被模型当成另一个独立动作，出来是动作折返或语义打架。

| 字段 | 只写什么 |
|---|---|
| `entry` | **入场**：从哪进画、边走边讲（只第 1 镜用） |
| `motion` | **身体轨迹**：脚 / 腿 / 重心 / 朝向。手势镜只写落脚与重心 |
| `action` | **手部动作**：手势的类型与落点。`kind=move` 时留空 |
| `dynamics` | **场景物件**在怎么变 |

🔴 手势镜最容易犯的错：同一个手势同时写进 `motion` 和 `action`
（★11 首跑 6 镜里 5 镜是这个）。按上表，手势只归 `action`。

⛔ 要强调就**换说法**（`讲` / `开口` / `嘴部开合` / `口型跟随` 任选其一），不是抄一遍。
提示词层的完整判据与反例见 `fxai-h3-video-prompt/references/01` 册「同一件事只写一次」。

### `text` 归谁：台词挂人物主体，不挂场景

分镜表只负责**提供** `text`（这段文案原文），**挂到哪个主体由代码决定**：
`dh_video.build_seg_prompts()` 走 `av.build_ref2va_prompt(..., lines=…)`，
把它写进 `<Subject 1>`（人物）的定义句。

🔴 **不得**为了「让模型知道这段在讲什么」而把台词塞进场景相关字段
（`why` / `dynamics` / 场景描述）。台词进场景主体 = 模型读成「场景在说话」，
与动作链里的口型同步指令打架，实测 15 段全程闭嘴。

这条是 MiniMax H3 的全局规矩（MV 与口播共用同一条工作流、都传原始音频
`fully_copy`），正文与反例见 `fxai-h3-video-prompt/references/02` 册 3.3；
门禁是 `preflight` ★12（走 `av.audit_subject_binding()`，对所有段生效）。

### 动作怎么选（按判据选，不给现成句子）

三条判据同时满足才算合格：

| 判据 | 查什么 |
|---|---|
| **从内容动词长出来** | 这段话里有「数 / 装 / 比 / 指 / 递 / 翻」这类动作动词时，用它当动作来源；没有就是纯陈述，改用重心或位移 |
| **落点是场景实物** | 动作指向的对象必须在场景图里真实存在 |
| **手在动、身稳住** | 手部承担表达，躯干只做重心与位移；一镜只做一种主要动作类型 |

动作类型只在这些里选，具体怎么落由该段内容定：

| 类型 | 部位 | 适用内容 |
|---|---|---|
| 计数 | 手 / 指 | 报数量、列清单、数步骤 |
| 指向 | 手 / 臂 | 讲身侧物件、讲某个位置 |
| 摊开 | 掌 / 臂 | 讲无奈、讲差异、递出结论 |
| 开合 | 双手 / 臂 | 讲规模、讲前后对比 |
| 位移 | 脚 / 腿 | 换景深、换落点 |
| 收拢 | 手 | 收尾、下结论 |

相邻两镜的类型须不同；同一镜只做一种，位移镜不叠手部动作。

### 表情怎么写（expression 字段）

`expression` 只写**面部肌肉的静态状态**。三条判据缺一条就退回：

| 判据 | 命中 | 不命中 |
|---|---|---|
| 部位限定在眉 / 唇 / 下颌 / 眼 / 面部 | 出现其中任一部分 | 出现头、颈、肩 |
| 状态是静态量 | 抬起、收紧、放松、上扬、下垂、抿紧、看向某处 | 位移类动词搭配头或颈 |
| 不做持续节拍 | 单一状态，或一次状态转换 | 出现「随时变化 / 不断 / 切换」类持续词 |

⛔ **词级禁写**（`preflight` 第 14 项 + `dh_video._AUDIT_BAD`）：点头 / 抬头 / 低头 / 转头 /
回头 / 歪头 / 仰头 / 摇头 / 探头 / 扭头 / 侧头 / 颔首 / 表情灵动 / 随内容变化 / 眼神闪烁。

眼珠的静态落点可以写（`FACE_OK`：`眼睛看向` / `目光落在`）；**头部动作一个字都不写**。

### 身体姿态怎么写（口播铁律：朝向锁死，只写位置与位移）

口播是对着观众讲话，朝向只有一个：正面朝镜头。`motion` 只写**位置与位移**，
转向过程与躯干倾斜都不写。

| 维度 | 判据 |
|---|---|
| 位移 | 沿纵深（走近 / 走远）或沿左右（横移），须有**明确终点**，范围 ≤ 一个身位 |
| 速度 | 全程匀速从容；离散量（两步 / 快步 / 来回 / 横穿）会被模型放大成晃动 |
| 躯干 | 只写重心落在哪只脚、双脚是否踩稳 |
| 朝向 | 不写。默认正面朝镜头，写出来会被执行成侧身 |

⛔ **词级禁写**（`preflight` 第 25 / 26 / 28 项 + `dh_video._strip_turn`）：
侧身 / 侧转 / 转身 / 转体 / 背对 / 背朝 / 面向屏幕 / 朝向屏幕；
肩线 / 肩头 / 上身前压 / 上身后仰 / 前倾 / 后仰 / 停住不动 / 定住 / 僵住。

表现人物与场景物件的关系，用**手**到物件。眼睛可以给静态落点
（`眼睛看向` / `目光落在` 属允许项），眼球转一下是安全的，身体转过去会毁掉整段。

### 背景人物怎么写（讲台 / 露天 / 会议室场景）

三条判据：

| 判据 | 命中 |
|---|---|
| 不给正面五官 | 只出现后脑勺 / 侧脸 / 剪影 / 模糊 |
| 每人一个具体小动作 | 具体到单个动作（记录、抱臂、举设备） |
| 全部虚化 | 出现大幅虚化 / 失焦 / 景深外 |

⛔ 禁写：群体性情绪与整齐划一的动作（鼓掌、欢呼、围观），以及只有数量没有动作的写法 ——
后者会被画成一排木头人。

### 什么时候要 B-roll

讲**具体操作、具体界面、具体数字**时，观众想看的不是脸，是那个东西：

| 内容 | 姿态 | 必写的动态要素 |
|---|---|---|
| 装环境、跑脚本、报错 | 中景 · 手在键盘上 | 按键的按下与弹起、屏幕上逐行滚动的内容 |
| 翻规范、数手册 | 中景 · 双手持册 | 纸页翻起落下、页角抖动 |
| 接设备、调机器 | 中景 · 手在操作台 | 插接动作、指示灯亮起 |
| 讲结构、讲流程 | 中远景 · 手持笔在板前 | 线条逐段延伸 |

🔴 `what` 里必须出现「动词 + 幅度 + 随时间的变化」。只有物件名词的写法出来是静图。

🔴 **B-roll 用中景或中远景**。手部特写丢掉场景上下文，观众看不出这是在干什么，
也和人物镜头的景别接不上。

B-roll 段 3~6 秒，落在段落边界。

## 输出：storyboard.json

字段值是**格式占位**——括号里写的是该填什么类型、按哪条判据填，不含可直接照抄的成句。
每一镜的具体内容按本册判据结合该段文案与场景自己写。

```json
{
  "total": "<总时长，秒>",
  "shots": [
    {
      "i": "<镜号，1 起>",
      "start": "<起，秒>",
      "end": "<止，秒>",
      "text": "<该段文案原文>",
      "scene": "image/scene_NN.png",
      "kind": "move | gesture",
      "size": "<SHOT_SPEC 六档之一；kind=move 时须中全景或全景>",
      "angle": "<08 册机位表可用项>",
      "camera": "<固定 或 极缓推近>",
      "move": "<后期运镜，无则空>",
      "motion": "<位移或重心；部位限脚/腿/重心/手/臂/掌/指>",
      "dynamics": "<场景物件的动态；空镜必填>",
      "action": "<手部动作类型；kind=move 时留空>",
      "expression": "<部位 + 静态状态>",
      "why": "<这一镜的设计依据：内容依据 + 场景依据>",
      "broll": "null，或 {what: 动作过程, size: 景别, start: 秒, dur: 秒}"
    }
  ]
}
```

## 验收清单（智能体逐条自查，不过就改）

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 段数与音频段数一致 | 补/删 |
| 2 | 时间码首尾相接、无空洞无重叠 | 重算 |
| 3 | 每段动作不同，重复不超过 2 次 | 重写重复段 |
| 4 | 动作与场景实物对应（场景没屏幕就不写指屏幕） | 改动作或改场景 |
| 5 | 位移在技术边界内（慢、短、有明确终点） | 改写 |
| 6 | `camera` 只有固定 / 极缓推近，机位运动写在 `move` | 改写 |
| 7 | 没有场景里不存在的物件 | 删掉 |
| 8 | B-roll 标了内容与时长，且落在段落边界 | 调整 |
| 9 | 每段 `why` 能说清「这段在讲什么 → 为什么这么拍」 | 重想这一镜 |
| 🔴 10 | **每镜都写了 `motion`**，且是轨迹不是状态 | 补写 |
| 🔴 11 | **空镜 / B-roll 写了 `dynamics`**，画面里有东西在持续变化 | 补写 |
| 🔴 12 | **空镜 / B-roll 景别是中景或中远景**，没有特写 | 改景别 |
| 🔴 13 | 全程有运动的镜头占多数，静止镜头是少数 | 给静止镜头补运动 |
| 🔴 14 | **没有任何头部动作与面部节拍**（点头/抬头/低头/转头/歪头/仰头/摇头、肩颈起伏、表情随内容变化）。**表情与眼神的静态描写要写**（面带微笑／眼睛看向镜头） | 删头部动作，补静态表情 |
| 🔴 15 | **第 1 镜有入场**（位移或朝向变化），不是站定念稿 | 补 `entry` |
| 🔴 16 | **每镜至少一次明显抬手动作，相邻镜手势类型不同**（走位镜不写手势，不计入） | 换类型 |
| 🔴 17 | **每镜有 `expression` 字段**，写**静态**表情与视线方向即可（「面带微笑，眼睛看向镜头」）。不限定只写眉/唇/下颌 | 补写 |
| 🔴 18 | **互动用手部表达**（手到物件的落点上），朝向不写、默认正面朝镜头；视线只写静态落点 | 改写 |
| 🔴 19 | **讲台/露天/会议室场景写了背景人物**，且是剪影+具体小动作（记笔记/抱臂/举手机），不是笼统的"很多观众" | 补写或具体化 |
| 🔴 20 | **`size` 是六档标准景别词之一**（不写自由文本、不夹 token）；构图 token（`waist-up framing` / `headroom above hairline` / `center-framed` / `rule of thirds`）与 35mm look 都写在 **`camera`** 字段 | `size` 改标准词、token 挪到 `camera` |
| 🔴 21 | **走位镜（`kind:"move"`）景别必须是中全景及以上** | 中景看不见腿，走位白写 |
| 🔴 22 | **走位不写离散量**（两步/走过去/来回/横穿），写成连续漂移 + 一个身位 | 按 02 册「走位三件套」改写 |
| 🔴 23 | **景别至少 2 种**，全片一个构图必然呆板 | 在中景 / 中全景之间轮换 |
| 🔴 24 | **走位镜不叠开放手势**（`action` 留空），一镜只做一种主动作 | 删掉 action，只留 motion |
| 🔴 26 | **`motion` 不写躯干倾斜 / 肩线**（上身前压、上身后仰、肩线高低错开、肩头略收）。腰以上构图里，"上身前压一点"模型就是渲成点头 | 改成「重心落到前脚，双脚踩稳」 |
| 🔴 27 | **不写冻结词**（停住不动 / 定住 / 僵住）。人会连嘴一起定住 → 出片像"根本不开口" | 改成「脚步站定」 |
| 🔴 28 | **部位白名单**：`motion` 只准出现「脚 / 腿 / 重心 / 手 / 臂 / 掌 / 指」。肩 / 胸 / 背 / 腰 / 颈 / 脖 / 上身 / 躯干 一律不许出现 | 头颈动作只能借这些部位表达，堵住即根治 |
| 🔴 ★9 | **每段提示词都有「持续讲话」强指令**（持续讲话 + 嘴部全程保持明显开合 + 口型逐字跟随）。只写「嘴唇同步开合」或「开口讲述」强度不够，配上面带微笑会锁嘴 | 走位镜尤其容易漏（`_tune_prompt` 会换掉整段 action_core） |

### 门禁：机械项与语义项都交给程序

`scripts/preflight.py` 是**本清单的可执行版本**，1~24 条里能机械判的全部覆盖，
另加一条场景图底部空地判据。它**真跑一遍 `build_seg_prompts`**，
拿「实际会提交给模型的提示词」来查（★5/★6），而不是只查分镜表 ——
分镜写得再对，只要代码没把它拼进提示词，出片照样呆板。

```bash
python scripts/preflight.py --project <项目> --char-desc "<人物穿搭>"
```

`check_delivery.py`（S5 交付门禁）已把 preflight 挂成硬项：
**分镜或提示词不过，交付自检直接非零退出**，出不了片。

### 白名单还是黑名单？

**两层各用各的判据，缺一不可：**

- **结构用白名单**（枚举 + 必填）：`kind ∈ {move, gesture}`、`size ∈ SHOT_SPEC 六档`、
  `camera` 必须落在「固定 / 极缓推近」、时间码必须首尾相接、`motion` 必填。
  白名单能挡住「新编出来一个没见过的值」——黑名单永远列不全。
- **语言用黑名单**（禁写词）：头部动作、面部节拍这类是**开放自然语言**，
  白名单列不出「所有可能的点头写法」，只能靠禁写词表。
  表情/眼神是允许项，白名单不用于反向限制表达。

对应到代码：`preflight.py` 里 `HEAD_ACT` / `FACE_BEAT` 是黑名单，
`MOVE_SIZES` / `CAM_BAD` / `SHOT_SPEC` 枚举是白名单，两边都跑。

## 验收发现问题 → 返修闭环（S4.5，**这一章是流程，不许跳**）

验收不过的时候，**唯一正确的下一步是「定位到镜 → 单段返修 → 重跑验收」**。
不是整片重跑，也不是「先记下来以后再说」。

### 1. 先定位镜号，不靠感觉

| 怎么发现问题 | 定位方式 |
|---|---|
| 说得出秒数（「62 秒那里侧脸」） | `rework.shot_no_of(62)` → 第 7 镜 |
| 预检 / 交付门禁报未过项 | `doc/_preflight.json` 里的 `rework_shots` |
| 只说得出「第几镜」 | 直接用，再用 `rework.shot_timecode(n)` 核对时间码 |

`preflight.py` 会把未过项**自动落成返修清单**并打印现成命令（不用人拼）：

```
需要返修：第 3、7 镜
  第 3 镜  18.83~28.25 s   未过项 14
  第 7 镜  56.50~65.92 s   未过项 ★2
python scripts/refix.py --project <项目> --shots 3,7
```

`check_delivery.py`（S5）跑不过时，也会把上面这两行抄进门禁输出里。

### 2. 几镜有问题，就一次提交几镜（串行排队）

验收报出 3 镜 → `--shots 3,7,9` 一条命令提交 3 段，
**这三段全部渲完才做后面的事**（字幕 / 封面 / 交付自检）。

`refix.py` 的行为就是这条：一镜渲完才提交下一镜，全部返回 0 才退出 0。
中途任一镜失败 → 立刻停，打印「已完成 / 未完成」，绝不带着半成品往下走。

### 3. 服务端合并规则（**理解返修的前提**）

H3 每渲完一段，服务端都会**拿其它段的缓存拼回一条完整成片**。所以：

- **多段返修必须串行**。并行提交会互相覆盖对方刚生成的段，成片里总有几镜是旧的。
- **中途那几次成片都是半成品**，只有**最后一段渲完**的那一次是终版。
- **全部渲完之前不许烧字幕 / 做封面 / 交付** —— 烧在半成品上等于白烧一遍。
- 「真合并了」的判据：成片 mtime 晚于开始时间（`refix.py` 自动核对并打印）。

### 4. 返修之后的收尾顺序（固定三步，缺一步都不算完）

1. 重跑 `preflight.py`，必须全绿。分镜没改对就重渲等于白烧 GPU ——
   所以 `refix.py` 会在渲染前先逐镜体检，带硬伤直接拦截（`--allow-bad` 才强渲）。
2. 看 `_tmp/refix_shotN/` 抽出来的 4 帧，确认问题真的消失。
3. 才做字幕 / 封面 / S5 交付自检。

### 判据：返修流程走对了吗

| 该看到 | 不该看到 |
|---|---|
| `[dh] 返修模式：只重渲第 N 段` | 一路「完整音频一次性生成」渲到底 |
| `[dh] 角色四视图复用缓存` | 每次都重新出四视图 |
| 成片 mtime 晚于本次开始时间 | 成片 mtime 没变（参数被跳过逻辑吃掉） |

三行缺任一行，就说明这次不是单段返修。两处程序拦截：`rework.is_rework()` +
「只改 1~3 镜自动降级为逐镜返修」，入口统一在 `refix.py`。

## 跑法

```bash
# 1. 设计完先自检（分镜结构 + 提示词双层）
python scripts/preflight.py --project <项目> --char-desc "<人物穿搭>"

# 2. 按分镜渲染（不给 storyboard 才退回通用轮换）
python dh_video.py --project <项目> --audio-dir <项目>/music \
       --storyboard <项目>/image/storyboard.json ...

# 3. 验收发现问题 → 单镜 / 多镜返修（多镜串行，全部渲完才继续）
python scripts/refix.py --project <项目> --shot 7
python scripts/refix.py --project <项目> --shots 3,7,9

# 4. 返修完重跑预检，全绿才进字幕 / 封面 / S5
python scripts/preflight.py --project <项目>
```
