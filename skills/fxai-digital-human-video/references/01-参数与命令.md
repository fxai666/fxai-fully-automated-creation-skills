# 参数与命令

## 完整跑法命令

**整套任务**：
```bash
python dh_pipeline.py --project <项目名> --script <项目名>/口播文案.md \
       --tag-file <项目名>/口播标签.txt \
       --char-desc "年轻女子，米色针织衫配利落短发，淡妆，神态亲切自信" --role woman
```

**只做视频这一步**（音频已有）：
```bash
# 单音频 → 一条视频
python dh_video.py --project <项目名> --audio <项目名>/口播音频.wav \
       --scene-desc "现代开放式书房，暖黄台灯，窗外午后阳光"

# 多音频（口播逐段）→ 逐段各一条，再拼成一条完整口播
python dh_video.py --project <项目名> --script <项目名>/口播文案_标签.md \
       --scene-desc "书房，暖光" --concat

# 多参考（四视图人物图 + 场景图，质量最好，默认模式）
python dh_video.py --project <项目名> --audio-dir <项目名> --mode multiref \
       --char-desc "年轻女子，米色针织衫，利落短发，自然淡妆"

# 🔴 出片后发现某几镜不对 —— 只返修这几镜（最常用，别整片重来）
python scripts/refix.py --project <项目目录> --shots 3,7,9
#    多镜一次提交、**串行**排队：一镜渲完才交下一镜，全部渲完才退出 0
#    服务端每渲完一段都会拿其它段缓存合并回完整成片 → 并行会互相覆盖
#    中途那几次成片是半成品，只认最后一段渲完那次；全部渲完才能烧字幕/封面/交付

# 单镜
python scripts/refix.py --project <项目目录> --shot 7
#    等同于：--start-index 6 --end-index 6（镜号 1 起，索引 0 起）
#    整片 88 s ≈ 70 min；单镜 9.42 s ≈ 8~10 min，四视图命中缓存后约 2~3 min

# 只看要跑什么，不执行
python scripts/refix.py --project <项目目录> --shots 3,7,9 --dry-run

# 手动写法（等价，refix.py 就是逐镜拼这条）
python dh_video.py --project <项目名> --audio <a.wav> --mode multiref \
       --scene-desc "<原样照抄>" --storyboard <项目>/image/storyboard.json \
       --start-index 6 --end-index 6

# 整片重做：一次提交跑完全部镜（**只在分镜整体推倒重来时用**）
python dh_video.py --project <项目名> --audio-dir <项目名>/music --mode multiref \
       --start-index 0 --end-index -1
```

🔴 **返修模式的生效判据（三行日志，缺一行就是没生效）**：

| 该看到 | 说明 |
|---|---|
| `[dh] 返修模式：只重渲第 N 段` | 显式索引且非 `(0,-1)` 即进返修模式，强制重渲 |
| `[dh] 角色四视图复用缓存` | 命中 `~/.workbuddy/fxai_cache/<项目>_口播_char.png` 时直接上传复用 |
| 成片 mtime 晚于本次开始 | 服务端确实合并回完整成片 |

只出现「完整口播已有产物，跳过」= 索引被跳过逻辑吃掉，成片不会变。
只出现「合并模式：完整音频一次性生成」+ 一路渲到底 = 整片重跑，同样不是返修。

## 🔴 跑法与服务端合并（多镜控制器）

工作流含「开始索引 / 结束索引」节点，按场景三选一：

| 场景 | 索引 |
|---|---|
| 整片重做 | `start_index=0`、`end_index=-1`（每次提交都要重跑角色四视图，逐镜循环提交会按镜数成倍重跑） |
| 某一镜返修 | `start_index=end_index=N`（N 为 0 起索引） |
| 从第 N 段跑到结尾（断点续跑） | `start_index=N`、`end_index=-1`（N 为 0 起索引；`is_rework` 判为返修，前面段命中缓存不动） |

断点位置由 `scripts/comfy_watch.py shots <pid> --dir <保存目录> --total <总镜数>` 给（`--json` 取 `next_index`），
或 `comfy_client.shot_progress(pid)`；续跑即 `--start-index <next_index> --end-index -1`。

服务端把「本次新段 + 已缓存的其他段」合并成一条完整视频返回，本地取到的即全长成片，
直接进烧字幕 / 后续环节。

- 服务端逐段产物：`<ComfyUI>/fxai/video/dh_multiref/<序号>.mp4`（`000.mp4` 起，0 起编号）。
- 服务端合并产物：`<ComfyUI>/fxai/video/merged/fxai_<时间戳>.mp4`，每次提交出一条完整成片。
- 服务端按项目缓存各段，同一时刻只有一个项目，重渲单段不影响其他段。
- **判据**：返回的 `合并_<W>x<H>.mp4` 时长 = 全长。时长等于单段说明走的是单段下载路径。
- 🔴 **每张场景图配一段自己的文字描述**：`--scene-ref` 传 N 张时，`--scene-desc` 用 `|`
  分隔传 N 段与之对应，各段提示词才带上自己的场景描述、各镜按时段切到自己的场景。

## 参数表

| 参数 | 作用 |
|---|---|
| `--project` | 项目名：成片落 `video/`，清单落 `doc/` |
| `--audio` | 口播音频（本地路径或服务端相对路径），**可给多条 = 多段** |
| `--audio-dir` | 音频目录，按序号排序逐段生成 |
| `--script` | 口播文案：按同名序号去 `music/` 找各段音频（多音频模式最省事） |
| `--mode` | `single` 单场景 / `multi` 多场景 / `multiref` 多参考（**默认 multiref**） |
| `--role` | 人物参考 `woman`/`man`/自定义相对路径（single/multi 把人物画进场景） |
| `--char-desc` | 人物穿搭外貌（写进 multiref 提示词） |
| `--scene-desc` | 场景描述，多场景用 `\|` 分隔（`"书房，暖光\|阳台，晨光"`）。**按整篇文案的意境定**，不必逐段对齐口播内容 |
| `--scene-ref` | 用现成场景图（相对路径，逗号分隔），给了就不生成 |
| `--scene-count` | 一般不用给（默认 0 = 按时间规则自动算）。显式给值也会被下限 2 / 上限=段数夹住 |
| `--avg-seg` | H3「平均分段时长」入参（默认 10，实际每段 9.41667 秒；一般不用改） |
| `--seg-prompts` | 逐段运镜提示词文件（空行分段），给了就按段精确命中；不给则按文案自动生成 |
| `--size` | 仅 single/multi 模式生效：`portrait_9x16` 竖屏 1080×1920（默认）/ `portrait_3x4` / `landscape_3x4`；**multiref 不取此值** |
| `--multiref-landscape` | multiref 输出**横屏** 1280×768。默认是**竖屏 768×1280**（口播一般是竖版，要横版才加这个开关） |
| `--name` | 任务/场景图标签前缀（成片本身用固定名 `合并_`/`成片_`，不受此影响） |
| `--concat` | 多段按顺序拼成一条完整口播 |
| `--seam` / `--no-seam` | **接缝色彩对齐，默认开**：把每段首帧贴到上一段末帧，消掉段间跳色。分段生成必然跳色（模型没有跨段记忆，实测接缝处掉 1.6~2.0 灰阶，是正常帧间变化的近 3 倍）。段间差超 30 灰阶会自动判定换场、不接 |
| `--tone` | 拼接时**额外**做影调对齐（乘法增益，把每段背景拉回参考色阶，修「发闷」）。默认关 |
| `--tone-ref` | 影调参考片（源片）；不给就以第一段为锚 |
| `--tone-strength` / `--seam-offset` | 影调强度 0-1（默认 1）／ 接缝单通道最大偏移灰阶（默认 12） |
| `--burn` | 合并成片后自动烧录字幕：`video/字幕.ass` → `video/成片_{W}x{H}.mp4`（`fxai-lyric-subtitle`） |
| `--start-index` / `--end-index` | **单段返修**（索引 0 起，两者相同 = 只重该段；镜号 N → 索引 N-1）。服务端自动把新段与已缓存的其他段合并成完整片返回，**本地勿再 concat**。⚠️ 只要显式给了索引且不是 `(0, -1)`，主流程一律按返修处理并强制重渲（旧的「已有产物→跳过」已被修掉） |
| `--timeout` | 单段视频渲染超时秒（默认 7200） |
| `--scene-timeout` | 单张场景图超时秒（默认 3600；GPU 排队时别调小） |
| `--force` | 已有该段视频、该张场景图也重跑（默认复用，不重复烧 GPU） |
| `--json` | 末尾吐 JSON 给其它技能解析 |

`dh_pipeline.py` 额外常用：`--speaker --landscape --no-burn --no-charview --dry-run --lyrics`
（`--dry-run` 只打印将要执行的命令，不实际运行）。
