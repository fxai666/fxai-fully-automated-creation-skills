# 单音频 / 多音频

音频来源三条：`--audio`（可多条）/ `--audio-dir`（按序号排序）/ `--script`（按同名序号去 `music/` 找）。

- **合并模式（默认，单人单口播）**：把多条音频合成一条完整音频，再一次性生成视频 →
  `合并_{W}x{H}.mp4`。H3 截断公式不会在段边界错位，**单人单口播一律走这条**。
- **多音频模式**（`--multi-audio`）：每条音频各出一条视频，`--concat` 按顺序拼成
  `合并_{W}x{H}.mp4`。适合多人物/多场景。逐段单独生成会让 H3 截断公式在段边界错位，
  非必要不用。
- 音频顺序按**文件名里的序号**排（`口播01` / `口播_01` / `口播-1` 都认），第 i 段对第 i 条。

# ★「一条音频」不等于「一条视频」——H3 内部还要再切段

MiniMax 只接受满足「**17k+5 帧**」的时长（24fps）。工作流传「平均分段时长 = 10」时，
节点先**向下对齐**：`align_down(240) = 17*((240-5)//17)+5 = 226 帧 → 226/24 = 9.41667 s/段`。
所以**每条音频内部还会被切成 9.41667 秒一段**，尾段不足 3 秒会并回上一段。

本技能启动时用 ffprobe 读每条音频时长、按精确公式算段数（日志逐条打印
「第 N 条音频 X.XX 秒 → H3 切 M 段」），再据此决定写几条逐段提示词。
`--scene-count 0` 时场景图数量也按这个段数自动定。

**⚠️ 别用 `ceil(时长/10)` 估段数**——经常差 1 段（120 秒：公式算 13 段，`ceil` 给 12），
段数不对齐会让后面几段复用第一条提示词/场景。

公式本体在公共件 `fxai-audio-video`（MV / 短剧共用同一份）：

```python
av.h3_segments(120.0)        # → (13 段秒数, 13 组 (start, end) 边界)
av.h3_segment_count(120.0)   # → 13
av.audio_duration("口播.wav") # ffprobe 探测时长，分段计算的唯一输入
av.h3_actual_seconds(9.4)    # 请求 9.4 秒 → 实际生成 9.41667 秒（只用于事后定位第几镜）
```

# 提示词自动契合文案

给了 `--script`（或同目录有口播文案）而**没给** `--seg-prompts` 时，本技能会
**按文案自动逐段生成提示词**，第 i 段 ↔ 第 i 段文案：

- `multiref` → Ref2VA 六段式；`single` / `multi` → FL2VA 三段式（格式硬约束见
  `fxai-h3-video-prompt` 的第 FL2VA / Ref2VA 两册）。
- 场景描述 = `--scene-desc` + 该段文案要点，写进 `subject_definitions`（六段式）或
  `integrated_multimodal_description`（三段式）。**逐段提示词可以带该段文案**（对镜讲述什么），
  但**场景图本身**按整篇意境出即可、不必逐段对齐（见 02 册「场景图数量规则」）。
- **道具要写出来**：H3 不会自己加道具，`--scene-desc` 里给了什么就有什么
  （「画面两侧靠后放着马克杯与笔记本」会进提示词；写成「桌上有…」会把镜头拉成俯拍桌面，
  见 02 册黑名单）。场景按内容定：讲职场沟通→办公区，
  讲育儿→客厅，讲代码→屏幕。找不到依据的道具不硬塞。
- 没给 `--scene-desc` 会打醒目提醒并带出文案摘要，**不会静默拿一个无关场景糊过去**。

格式规范统一在 `fxai-h3-video-prompt`（MV 与口播共用同一套），本技能只负责把文案喂进去。

# ★ 提示词怎么写才不死板

数字人「呆板」几乎不是模型的问题，是提示词把动作空间写没了。四条硬规矩：

## 一、手势写「一直在动 + 大致方向」，不写动作清单

早先按 Ekman & Friesen 的手势分类逐条写死「数数时逐一点数、对比时双手分开」，
结果模型像在背动作表：**手只在被点到的那两三秒动，其余时间垂着**，一段下来还是呆板。

现在的写法是给「什么时候开始动 + 往哪个方向动」，**具体姿势交给模型自己发挥**：

```
从第一句话起，双手就跟着说话内容自然地动起来：强调时抬手、铺陈时摊开、
说到身边的东西时伸手示意，具体姿势由话语自己带出来，幅度与快慢跟着语气走，
像人在面前聊天；身体随着讲解自然换重心，整个人是松的；
```

已写进 `_NARR["speak"]["action"]`。三个要点：

1. **「从第一句话起」**——不写这句，模型会把动作排到中段才开始（实测）。
2. **只给方向，不给动作**——强调 / 铺陈 / 指向三类足够，写清单反而把动作锁死。
3. **「像人在面前聊天」**——这句把「表演」拉回「日常说话」，模型给的手势更碎、更连续，
   而不是一次一次的大动作。

唯一要挡掉的是 Ekman 的第 4 类（摸脸、挠头、玩笔）：那是紧张信号，写进提示词会被放大。

`SPEAK_ACTS` 只留一条中性规范；具体动作写在分镜 `motion` / `action`，代码里不放动作库。

## 二、头部与眼神都不写

提示词里**不出现**任何头部动作与眼神描写。点头节拍、仰头思索、低头看一眼、「眼神看向镜头 /
短暂移开再回来 / 目光与镜头交流」一律不写——写出来就是一边说一边点头、眼球来回扫，
观感很假（实测）。动作库里也不放仰头、低头、抬头、点头。

只保留一句朝向：「面向镜头」。朝向是身体朝向，不是头部动作。

头如果真的在乱点，查两处：人物幅度是不是被「幅度克制 / 原地不动」压死了（`08` 册 4.5），
这段是不是没有任何身体动作可做（模型能动的只剩头，用点头填空）。

## 三、只有第 0 段写入场，其余段落人已经在场景里

第 0 段由 `ENTRY_ACTS` 自动给（从画面外侧走入 / 从画面深处走近），并替换该镜的 `pre`。
**只给第 0 段**——每段都写入场，每次硬切都像重新进一次门，很傻。

第 1 段起，人物**本来就在场景里**，动作要从场景里长出来：
走向身侧的屏幕、走到台面前俯身、走近镜头半步、朝画面右侧横移一个身位。
这些是「场景内动作」，不是「从画外进来」；全部保持正面朝镜头。

`dh_video.py` 已经按 `i == 0` 分配 `ENTRY_ACTS`，其余段落 `entry=None`；
分镜里显式写 `entry` 才会覆盖。

⚠️ **「起幅全身→落幅腰以上」一镜写不完**（实测 V2 失败：模型把「走近」理解成无限推近，
10s 段从「膝盖以上」一路推到「脸特写」）。要做远近变化的节奏感，得**分两段拼接**——
先一段 5s 全景+走位+停住，再切到中景续讲。详细对比见 `08` 册 4.2.1「三种运动方式怎么选」。

## 四、机位运动别写进提示词

生成层只写「固定 / 极缓推近」。拉远、横移、摇、手持走后期
`scripts/camera_move.py`（`08-镜头语言.md` 4.4）。写进提示词会触发背景重算 → 闪烁跳跃。

## 自检

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 每段有一次**明显**的抬手动作，不是全程手放身前 | 补一个 illustrator 手势 |
| 2 | 相邻段手势**类型不同** | 换类型 |
| 3 | 提示词与动作库里**没有**头部动作、也没有眼神描写 | 删掉，改成身体动作 |
| 4 | 第 0 段有入场位移或朝向变化 | 补 `entry` |
| 5 | 位移有明确终点，不是「来回走」 | 改写 |
| 6 | 提示词里没有平移 / 摇 / 环绕 / 手持 | 删掉，改走后期 |
