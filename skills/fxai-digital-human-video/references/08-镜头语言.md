# 08 · 镜头语言（专业术语 → 本技能怎么落地）

> 口播视频在行业里属于 **talking head / piece to camera**（对镜头讲述）。
> 本册把影视与剪辑的标准术语对齐到我们的产线，并标明**技术上能做到哪一档**。

## 一、五个基本要素

任何镜头都由这五样决定：**景别、机位角度、运镜、构图、光线**。
写场景提示词时，五样都要落到具体描述，画面才可控。

## 二、景别（shot size）

景别只有六档，`av.SHOT_SPEC` 就是这张表（第五节有展开参数，改表即改全局）：

| `shot_size` | H3 官方术语 | 画面范围 | 占画高（仅设计参考） | 口播里用来做什么 |
|---|---|---|---|---|
| 远景 | wide shot | 环境为主，人很小 | 1/3 | 交代地点、开场、过渡（B 段空镜） |
| 全景 | full shot | 全身入画，头脚各留白 | ~4/5 | 展示人物与环境的关系、入场起幅 |
| 中全景 | medium-wide shot | 头顶到大腿以上 | 3/4 | 想要「人稍远、背景多一点」时用 |
| **中景** | medium shot | **头顶到腰部以上** | **3/5** | **口播主力**：能看动作也能看表情 |
| 近景 | close-up | 头顶到胸口 | 4/5 | 强调表情与语气（⚠️ 背景只剩虚影，口播少用） |
| 特写 | extreme close-up | 面部 / 局部充满画面 | — | 细节强调（M 段素材镜头） |

🔴 **「占画高」那一列只是给人做设计参考的，不许写进提示词**。
H3 官方提示词指南里，与构图有关的量化只有运镜的 `small/large amplitude`，
**「人物占画面高度几分之几」没有任何官方依据**（2026-10-22 查证）。
`av.SHOT_SPEC` 因此只写「中文名 + 官方术语 + 身体部位范围」。
构图要精确，官方给的正道是**用参考图锚定**
（`position and framing established by <Picture N>`），不是写百分比。

🔴 **口播默认中景，不用近景**。近景人物占满画面、背景全虚，人显得僵、环境也交代不出来；
中景到腰部以上，身后墙面与上半部空间都露出来，人物有地方可动。

**一条片子里景别要换**：中景讲、全景开场、特写给证据，才有剪辑感。
⚠️ 只换景别不换机位角度是安全的；**换机位角度会触发背景重算**（见 4.1）。

## 三、机位角度（camera angle）

| 角度 | 英文 | 本技能 |
|---|---|---|
| 平视（眼高） | eye level | ✅ **默认**：相机与人物落位区视线齐平 |
| 斜侧 45° | 45-degree angle | ✅ 可用：比正对镜头自然，脸型更好看，适合口播主力 |
| 俯拍 | high angle | ❌ 人物会被画成沉进桌面/家具里 |
| 仰拍 / 虫视 | low angle / worm's eye | ❌ 同上，且人物必然落在桌后 |
| 过肩 | over-the-shoulder | ❌ 场景图里没有人却写过肩，等于暗示前景有人形遮挡 |

> 这条是硬约束，`_SCENE_GUARD` 会把「相机与落位区视线齐平、身前无前景遮挡」自动追加到每条场景提示词。

## 四、镜头与画面里的运动

一条片子「看起来活不活」，取决于**三类运动**。设计分镜时这三类都要写，缺任何一类画面就会僵。

### 4.1 镜头运动（camera move）—— 机位怎么动

运镜分两层做，**别把两层混在一起写进提示词**：

| 运镜 | 英文 | 生成层（提示词） | 后期层（`camera_move.py`） |
|---|---|---|---|
| 固定 | static | ✅ 首选 | — |
| 推近 | push in | ✅ 极缓（改焦段，不改机位角度） | ✅ 任意幅度 |
| 拉远 | pull out | ⚠️ 易触发背景重算 | ✅ **推荐**：开场拉开交代环境 |
| 横移 | truck / pan | ❌ | ✅ |
| 摇 | pan / tilt | ❌ | ✅ |
| 升降 | crane | ❌ | ✅（垂直方向等价于 tilt） |
| 跟 / 环绕 | follow / arc | ❌ | ⚠️ 只能近似，做不出真环绕 |
| 手持呼吸感 | handheld | ❌（会写成晃动） | ✅ 轻微叠加 |

**为什么分两层**：multiref 把背景**逐段重算**，生成层任何改变机位角度或高低的要求都会让背景被反复重算，
表现为背景闪烁跳跃。而后期是在成片像素上做亚像素变换，**背景一次都不用重算**——
所以**生成层锁机位、机位运动交给后期**，这是唯一既能动又不穿帮的做法（见 4.4）。

🔴 **机位锁死 ≠ 画面里没有运动**。机位不动时，**主体照样可以在画面里走、转身、走近走远、坐下站起**——
主体在画面内位移不会触发背景重算，是生成层最有效的运动来源（见 4.2）。

### 4.1.1 运镜的标准写法（H3 官方三维度，**英文**写进镜头内）

H3 官方提示词规范（`fxai-h3-video-prompt/references/base-modes-en.txt` §4.3）把运镜拆成
**三个维度**，并强调「写成自然的英文动作句，勿堆标签」：

| 维度 | 可用表达 | 含义 |
|---|---|---|
| **运动类型** | `Zoom In/Out`（变焦）· `Push In/Pull Out`（机位前进/后退）· `Pan L/R`（原地转镜头）· `Truck L/R`（机位横移）· `Tilt Up/Down` · `Pedestal Up/Down` · `Arc Shot`（环绕）· `Tracking Shot`（跟拍）· `Static Shot` · `Shake Slightly/Strongly` · `POV` · `Roll` | 镜头怎么动 |
| **幅度** | `with small amplitude` / `with large amplitude` | 画面变化范围 |
| **速度** | `at slow speed` / `at fast speed` | 运动的快慢 |

官方参数写法（`at slow speed` + `with small amplitude`）：

```
The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.
The camera trucks right with small amplitude at slow speed, revealing the open doorway.
```

🔴 **关键**：慢 = `at slow speed`、小幅度 = `with small amplitude`，**这两句必须显式写**；
只写「缓慢」「慢推」中文词，H3 不一定当速度约束——它吃的是英文 `at slow speed`。
我们的 `06` 册运镜 LoRA 词表（`slow push-in` 等）也是同一套英文。

⚠️ **但数字人口播的生成层机位是锁死的**（动机位 → 背景逐段重算闪烁，见上）。
所以「镜头慢慢移」在生成层写不出来——要么走**后期** `camera_move.py`（任意幅度/速度的
推拉移摇），要么把「动」落在**人物自身**（走动 / 横移），人物在画面内位移不触发重算。
**「让画面慢下来」的杠杆，在口播里是「人物慢走」+「后期慢运镜」，不是生成层运镜。**

### 4.1.2 社区实证写法（别人怎么写）与我们的对齐

查了一圈社区（CSDN《MiniMax-H3 进阶实战 · 运镜提示词》、知乎《Awesome MiniMax H3 提示词仓库》、
Wondershare Hailuo 公式指南），别人的写法与我们 4.1.1 的官方三维度**完全对齐**，互相印证，不用另起一套：

**① 提示词结构 —— 与我们同构**
- CSDN「黄金四段式」：`(主体与环境) + (动作与细节) + (运镜与镜头语言) + (画质与氛围风格)`。
  我们的 `detailed_description` 就是这套（谁 + 在哪 + 做什么 + 镜头 + 光线 + 风格），只是拆得更细。
- 知乎仓库把提示词拆成 **7 层**：视频类型 / 主体与目标 / 时间轴 / 镜头语言 / 物理互动 / 声音对白 / 硬约束；
  核心忠告是「**写空间路径，不堆形容词**」——把镜头怎么追、怎么穿、怎么转、最后怎么揭示写清楚，
  模型才给连续镜头。我们 4.2「写轨迹不写状态」、4.3「物件动态」正是这层。
- Wondershare 公式：`[Camera Shot + Motion] + [Subject] + [Action] + [Scene] + [Lighting] + [Style/Mood]`，
  镜头运动常放最前定视角——与我们「生成层只写固定 / 极缓推近」一致。

**② 慢运镜的真实用例（英文原句，社区都在用）**
- `slow panning right`
- `the camera slowly pans from left to right at a 30-degree angle`
- `(slow push in:1.2)` —— 括号权重强化推进的速度与幅度（ComfyUI 侧写法）
- 避坑：出现「画面拉伸 / 肢体扭曲 / 模糊」时，把 `Fast zoom in` 改成 `Slow push in`，或降低 CFG。

**③ 防畸变负面词（社区通用 Negative Prompt）**
> `deformed, distorted camera movement, sudden jitter, blurry, bad anatomy, morphing artifacts, flickering light`

🔴 **对齐后的关键告诫（口播务必记住）**：上面所有 `slow push in / slow pan / tracking` 都是**生成层机位运动**，
对自由镜头（无 multiref 背景重算）有效；但**数字人口播的生成层机位是锁死的**（动机位 → 背景逐段重算闪烁，见 4.1）。
所以：
- 口播提示词里**勿写生成层运镜**（push in / pan / tracking 这类），写了也不会动，反而可能触发背景重算；
- 「让画面慢下来」在口播里的等价做法是 **人物缓慢横移（4.2.2）+ 后期 `camera_move.py` 慢推 / 慢移（4.4）**；
- 想要「纪实手持感」别在提示词写 `handheld`（会变成晃动），用后期 `--handheld 0.5~1`（4.4）补轻微呼吸；
- 括号权重 `(slow push in:1.2)` 是否对 H3 文本提示词生效**未实测**，且口播镜头锁死，暂不作为默认写法。

### 4.2 主体运动轨迹（motion path）—— 谁在画面里怎么走

这是**人物镜头最主要的运动来源**。写清「从哪 → 到哪 → 什么姿态 → 速度」：

| 写法 | 参考写法 |
|---|---|
| 入画出画 | 从画面右侧走入，走到中央停下继续讲 |
| 走近走远 | 边讲边朝镜头走近，走到中景距离停住 |
| 横向位移 | 从书桌一侧走到白板一侧，身体始终朝镜头 |
| 转向 | 不写。口播只允许走近 / 走远 / 左右横移（02 册「朝向锁死」） |
| 俯身起身 | 俯身翻桌上的手册，找到后直起身继续讲 |
| 坐下站起 | 拉出椅子坐下，把手放桌面开始讲 |

**判据**：一段里主体至少有一次**看得见的位移或朝向变化**。只有手势和表情，
躯干和脚全程不动，就是没写 motion path。

⚠️ **要写轨迹，不写状态**。「站在桌前讲解」是状态，模型只会给你一个站着的人；
「从右侧走到桌前，边走边讲，走到桌前停住」才是轨迹。

#### 4.2.1 三种运动方式怎么选（实战 3 组对比的结论）

口播段最常用的运动只有三种，对应 `ENTRY_ACTS` / `SPEAK_ACTS` 的不同位：

| 方式 | 写法 | 实测（10s 段，同 seed 20261026~28，skin 掩膜量化） | 何时用 |
|---|---|---|---|
| **A. 人在场景里**（默认） | 不写入场或 `ENTRY_ACTS[0/1/2]` | **V1 头宽 210 px / 脸底 33% / 脸顶 0 px / 皮肤横心 209 px** —— 构图稳、头不点、手真动 | **首选**——绝大多数口播段 |
| **B. 场景内走动** | `SPEAK_ACTS[12]`「缓慢走动两步，从画面一侧走到另一侧」 | **V3 头宽 181 px / 脸底 33% / 脸顶 2 px / 皮肤横心 80 px** —— 9~10s 段里「走动」被模型稀释成小幅横移（10% 画宽），没有真走过去；横心反而比 A 模式小（手被走位「抢」了动作空间） | 留给 **>15s** 的长段，让走动有时间展开；9~10s 段用 B 反而比 A 横心范围小 |
| **C. 全身→半身**（看似美好） | `ENTRY_ACTS[3]`「从画面深处朝镜头走来，起幅全身，走近到腰部以上停住」 | **V2 头宽 9~224 px / 脸底 34%→72%** —— 开篇 0.4s 已经是中景（膝以上），结尾一路推到脸特写，**10s 内从「全身」推到「脸特写」** | ❌ **不可行**；要远近变化得分两段拼接：先 全景 5s 走位+停住，**再切**到中景续讲 |

**为什么 C 不可行**：`shot_size` 决定整段的主导构图（在 `av.SHOT_SPEC` 展开后是 prompt 里最显眼的视觉描述），
模型拿它当锚定值；「走近 / 走近到腰部以上」会与锚定值打架——

- 锚定值是「中景」时，人物根本无从近起（构图已经收在中景了）；
- 锚定值是「全景」时，模型默认按全景给一段远景，但描述里又有「走近」就把镜头也一起推，
  结果从「膝盖以上」一路推到「脸特写」（V2 实测）。

**B 模式在 9~10s 段不出彩的根因**：开放手势（`action` 主句）与走动（`act_extra`）同时存在时，
模型只能在「自由手势」「定向位移」里二选一——两者都是动作空间；同时给两个就给「小幅站位偏移」
这种最安全的中间解。要让 B 真出效果，**得让段够长**（>15s 让走动有时间展开），
或者把 `act_mode` 从 `extra` 改成 `replace`，把主动作换成「走向屏幕侧、停住、抬手讲解」这种
**位移 + 停顿**复合形态（勿再叠开放手势）。

**判据三选一**：这一段需不需要「入场感」？需要就用 A 的 `ENTRY_ACTS[0/1/2]`
（注意**只给第 0 段**，其余段落人已经在场景里）；这一段会不会讲超过 15s？会的话中间插一段 B
（用 `replace` 模式）；想用「远近变化」制造节奏？**别试图一段写完**，
分两段：先 C'（全景+走位+停住）再切 A（中景+续讲）。

#### 4.2.2 运动速度：怎么让走位 / 运镜「慢下来」

用户实测反馈：V3 的「走动两步」出来是**快步**——这不是模型不听话，是描述把「慢」写丢了。
H3 对速度的控制有官方写法（见 4.1.1）：**慢 = `at slow speed`、小幅度 = `with small amplitude`，
且必须用英文写进镜头内**。中文「缓慢」「慢走」H3 不保证当速度约束。

落到我们的中文 `detailed_description` 里，两条经验：

1. **删掉「两步 / 走过去」这类离散短位移**——模型会把它们当一次快速小动作执行。
   改成**连续的、横贯整个镜头的漂移**：「从画面一侧**缓缓**移到另一侧，脚步从容、匀速、
   **不急不缓**、身体始终朝向镜头，**全程持续移动**」。其中「全程持续移动」来自 `fxai-h3-video-prompt`
   04 册的铁律——远处/小主体不写这句会卡住不动；
2. **幅度写死**：「横向移动范围很小（约一个身位）」，别让模型自由发挥成大横穿。

> 为什么中文里还要渗一点英文？`06` 册的运镜 LoRA 词（`slow push-in` 等）和 4.1.1 的
> `at slow speed` 都是 H3 训练集里的英文速度词。口播里镜头是锁死的，**慢的杠杆是人物**——
> 把「慢」用 `at slow speed` 的语义译成中文等价描述（从容 / 匀速 / 全程持续 / 不急不缓）并
> 去掉离散步数，人物就会真的慢下来。

**后期运镜的「慢」**：真要镜头慢慢移，走 `camera_move.py`——`--amount 0.08~0.12` + 默认
`smoothstep` 缓动（起步慢、中间快、收尾慢）就是天然的「慢推 / 慢移」；`--handheld 0.5~1`
给轻微呼吸感。生成层做不到的慢运镜，后期一条命令补上。

### 4.3 场景物体动态（object dynamics）—— 画面里的东西在怎么变

空镜和操作镜头**必须**写这一项，否则出图就是一张静止照片。

| 场景有什么 | 动态怎么写 |
|---|---|
| 显示器 / 屏幕 | 内容随讲解滚动，光标移动，进度条推进，报错行一条条刷出来 |
| 键盘 | 手指逐键按下并弹起，键帽起伏 |
| 手册 / 纸张 | 纸页被翻起、翻面、落下，页角抖动 |
| 指示灯 / 设备 | 指示灯闪烁，风扇转动，读条推进 |
| 手写 / 白板 | 笔尖移动留下字迹，线条逐段画出 |
| 环境 | 窗外光斑移动，窗帘轻摆，咖啡冒热气 |

**判据**：空镜里至少有一个物件在**持续变化**。全场只有镜头缓推、物件纹丝不动，
观众一眼就看出是静图。

### 4.4 后期运镜 —— 生成层做不到的机位运动

人物镜头的机位运动**不在提示词里写**，在成片上做。`scripts/camera_move.py` 对任意视频
做亚像素变换，背景不重算、不闪烁，而且幅度、缓动、速度全都可控。

```bash
# 开场：从人物拉远，交代环境（最常用的一条）
python scripts/camera_move.py --video video/成片_768x1280.mp4 --move pull-out \
       --amount 0.12 --out video/成片_move.mp4

# 讲到某个点时横移一点，画面「让开」给旁边的东西
python scripts/camera_move.py --video a.mp4 --move pan-right --amount 0.10 --out b.mp4

# 推近 + 轻微手持，画面有呼吸感，不像三脚架死拍
python scripts/camera_move.py --video a.mp4 --move push-in --amount 0.10 \
       --handheld 1.2 --out c.mp4

# 只给开头 4 秒加拉远，后面原样保留（运镜当标点用）
python scripts/camera_move.py --video a.mp4 --move pull-out --start 0 --dur 4 --out d.mp4
```

| `--move` | 效果 | 用在哪 |
|---|---|---|
| `still` | 极轻微呼吸推 | 全片兜底，让静止镜头不是死帧 |
| `push-in` | 缓推近 | 讲重点、情绪收紧、收尾 |
| `pull-out` | 缓拉远 | **开场**、讲完一个段落「放开」 |
| `pan-left` / `pan-right` | 缓横移 | 人物偏一侧、要给另一侧环境让位 |
| `tilt-up` / `tilt-down` | 缓摇 | 从人物摇到屏幕/桌面，或反之 |
| `drift-tl` / `drift-br` | 斜向漂移 | 长段落防呆板，方向比横移更柔和 |
| `handheld` | 只加手持晃动 | 纪实感、vlog 感 |

- **`--amount` 幅度**：推拉 0.08~0.15（12% 已经很够，超过 0.2 会看出是数码变焦）；
  横移/摇 0.06~0.12（占比越大越容易露出画质下降）。
- **缓动默认开**：`smoothstep`（起步慢、中间快、收尾慢）。关掉是匀速，看着像机器臂。
- **`--handheld` 0~2**：1 = 轻微呼吸，2 = 明显手持。纪实向用 1~1.5，知识口播 0.5~1。
- 一次只做**一种**运动。要在一段里换运动，用 `--start` / `--dur` 分段处理，或切段后 concat。
- `--start` / `--dur` 只给那一段加运镜，**其余原样保留**——开场拉远、结尾推近就用它，
  不用把整片都推一遍。
- 后期运镜是**重编码**，`--crf 18` 起步；成片最后一步做，别在中间反复转码。
- **`z=1.0` 就是原片视野**：脚本先按 `pad=1.3` 超采样再 zoompan，z=1 时按 cover 填满输出，
  同帧像素差 0.6/255。所以 `--amount 0.10` 的推近就是 10%，别自己再乘 pad。
- **`handheld` 不改构图**：z 固定 1.0，只做亚像素平移（同帧差 1.5/255），
  想「有呼吸感但别动景别」就用它，适合已经站定的中景口播。
- 🔴 **后期拉不远**：z 最小就是 1.0（= 原片视野），`pull-out` 只能从「放大 12%」拉回原样，
  没法让画面比原片更松。生成时构图偏近（竖屏常见），只能把 `shot_size` 降一档重跑，
  后期补不回来。

**排布原则**：运镜按段落分配，不是每段都给。开场拉远一次、中段横移一两次、结尾推近一次，
其余段落保持固定——**运镜是标点，不是背景音乐**。

### 4.5 头部动作不写，表情和眼神要写

> 🔴 **2026-10-21 用户口径，覆盖本节旧版「头眼都不写」的结论。**
> 用户原话：「删除所有头部描写的动作」「写表情就可以了，面部表情就可以了」
> 「也可以写眼神，也可以写眼睛看向哪里」。本节已按这个口径改。

**禁写**（等于给模型下发动作指令，出来就是一边说一边点头、眼球来回扫）：

- 头部**动作**：点头 / 抬头 / 低头 / 转头 / 歪头 / 仰头 / 摇头 / 探头 / 扭头
- 面部**持续节拍**：「表情灵动随内容变化」「随内容自然切换」「随呼吸有轻微起伏」
  「肩颈放松」——这几句会让脸和颈肩全程做小动作，是「头部机械」的直接来源。

**要写**（静态描述，不写动作节拍）：

- 静态表情：面带微笑 / 表情认真 / 表情凝重 / 带一点自嘲的笑
- 视线方向：眼睛看向镜头 / 眼睛朝屏幕方向看一眼再回到镜头
- 身体朝向：不写。默认正面朝镜头，写出来会被执行成侧身（02 册「朝向锁死」）

三张词表在 `scripts/preflight.py`（`HEAD_ACT` / `FACE_BEAT` / `FACE_OK`），
分镜和**提示词**两层都会查（★5 查的是实际提交给模型的文本，不是分镜表）。

**「人物一直没规律点头」的真正成因**在别处：提示词里写了「动作幅度克制 / 原地不动 / 不摇摆」，
模型能动的只剩头，于是用连续点头填满画面。约束把动作空间压没了，不是模型不听话。

三条改法，从根上治：

1. **把身体动作给足**（4.2 的位移 + 4.3 的物件互动），人有事可做，头自然不需要填空。
2. **约束只写给镜头**：「镜头不摇晃、不做快速推拉」，人物幅度那半句删掉——
   「幅度克制」是死板的第一来源。
3. **景别要放得下动作**：中景只有腰以上，走位看不见（02 册「走位三件套」）。

## 五、构图（framing）

| 构图 | 本技能 |
|---|---|
| 三分法 / 中心构图 | ✅ 人物略偏中心或落在三分线上 |
| 负空间 / 留白 | ✅ **人物落位区**就是留白，身前保持开阔 |
| 背景纵深 | ✅ 用浅景深虚化背景制造层次 |
| 前景遮挡 / 框架式构图 | ❌ 镜头与落位区之间放家具，人物会被画进家具里 |
| 物件特写塞人物 | ❌ 特写就拍空镜，人物镜头与物件特写分开 |

### 竖屏安全区（9:16）

- 主体**居中或偏上三分之一**。
- **顶部留出标题卡空间**（标题卡基线：小档 768×1280 为 y=80，中档 1080×1920 为 y=120，
  四档全表见 `fxai-title-card/SKILL.md`「排版规范」）。
- **底部约 15% 是平台互动区**（点赞、评论、购物车按钮），关键内容与字幕避开这一带，
  否则会被平台界面盖住。

### 横屏安全区（16:9 / 4:3）

- 主体**居中**（横版人像居中才稳），**左右两侧各留约 20% 空区**给标题卡竖排。
- 🔴 横版**不得在画面顶部给标题卡留位**：顶部一行横字正好压在额头/眉眼上。
  横版标题卡走侧边竖排（`--position auto` 已默认，横版逐张左右交替），构图时按"侧边留白、顶部照常"来写场景提示词。
- 详细参数（贴边距、列宽上限、一列几字）见 `fxai-title-card/references/01-排版与时间码.md`
  第二节之二「竖排」。

### 景别只写两个字，模型会自己收成胸像

实测：提示词里只写「中景镜头」，H3 给的是**胸像近景**——人物占满画面、手势出画、背景全虚；
把景别**展开成身体部位范围**（「人物从头顶到腰部以上进入画面，身后的环境、墙面与上半部空间
清楚可辨」），才落成真正的中景。

🔴 **展开时只写身体部位，不写量化比例**。旧版还带「约占画面高度五分之三、头顶距上沿留出
六分之一」——H3 官方提示词指南里与构图有关的量化只有运镜的 `small/large amplitude`，
**「人物占画面高度几分之几」没有任何官方依据**（2026-10-22 查证）。实测里真正起作用的
是「从头顶到腰部以上」这段部位描述，比例是陪衬，删掉不影响效果。

`av.SHOT_SPEC` 内置六档，`build_ref2va_prompt(shot_size=...)` 自动展开；
要调构图就改那张表，别在每个提示词里手写（下表「占画高」只做设计参考，不进提示词）：

| `shot_size` | 落幅（写进提示词） | 占画高（仅参考） | 头顶留白（仅参考） |
|---|---|---|---|
| 远景 | 环境是主体，人物全身在画面中且较小 | 1/3 | 大 |
| 全景 | 人物全身完整进入画面，头脚各留白 | ~4/5 | 1/10 |
| 中全景 | 人物从头顶到大腿以上进入画面，环境完整可见 | 3/4 | 1/10 |
| **中景** | **人物从头顶到腰部以上进入画面，身后环境清楚可辨** | **3/5** | **1/6** |
| 近景 | 人物从头顶到胸口进入画面，面部清晰 | 4/5 | 小 |
| 特写 | 面部充满画面，以头顶到下巴为主 | — | — |

🔴 **口播默认走「中景」，别用近景**。近景（头顶到胸口）人物占满画面、背景只剩一条虚影，
观众看不出他在什么环境里，人也显得僵。中景到腰部以上，身后墙面与上半部空间都露出来，
人物有地方可动。

### 2.1 构图 token（写进分镜提示词，让模型不瞎构图）

只写景别范围不够，模型还会自由决定人物居中还是偏左、头顶留多少。
补上这些构图 token，模型就不会裁人头、不会把背景拍得清清楚楚。

🔴 **token 写进 `camera` 字段，不写进 `size`**。`size` 必须是六档标准景别词之一
（代码要拿它查 `av.SHOT_SPEC`，写成 `中景，头顶到腰部以上入画，waist-up framing`
会**查表落空**，标准描述根本进不了提示词——2026-10-22 实测第 1 镜就这样渲成了远景）。
门禁两条：`preflight` ★13 查 `size` 是标准词，★20 查 `camera` 带 token。

| Token | 什么时候写 | 效果 |
|---|---|---|
| `center-framed` | 人物居中正对镜头时 | 人物在画面正中心 |
| `rule of thirds, subject on left third` | 人物偏左、右侧留桌面/产品时 | 人物落在左三分线，右侧给环境 |
| `headroom above hairline` | 所有景别都写 | 头顶有适当留白，不顶到画框上沿 |
| `waist-up framing` | 中景时写 | 腰部以上入画，明确裁切位置 |
| `chest-up framing` | 中近景/产品展示时写 | 胸口以上入画，稍近一点 |
| `35mm lens look, shallow depth of field` | 风格开头统一写 | 标准焦段+浅景深，人物清晰背景虚 |

🔴 **焦段选择**（写在风格句里，不写具体mm数也行）：
- 说话、讲观点：`35mm look`（自然透视，不畸变，人脸好看）
- 环境交代、B-roll空镜：`24mm look`（广角，多收环境）
- 产品特写、近景：`50mm look`（中长焦，背景虚化更强，产品突出）

竖屏（9:16）里模型**天生偏近**：同一段描述，横屏给中景，竖屏常再收紧半档。
所以竖屏默认按表写、看片再定，偏近就降一档（中景 → 中全景），
**后期补不回来**（`camera_move.py` 的 z 最小是原片视野）。

🔴 **入场措辞会决定整段景别**：写「从画面近处后退半步」，模型把「近处」当成整段的基准，
10 秒全是近景；写「从画面外侧缓步走入」才拿到中景。入场只写「从哪进来、走到哪停」，
**不写「离镜头多远」**。

## 六、光线（lighting）

| 光线 | 本技能 |
|---|---|
| 三点光 | ✅ 主光在前侧约 45°、补光柔化阴影、轮廓光把主体从背景分离 |
| 自然窗光、侧光、柔和顶光 | ✅ 实景常用，写清方向与软硬 |
| 逆光、硬光 | ⚠️ 人脸易黑，慎用 |
| 霓虹、彩色光效、数据流光带 | ❌ 那是特效空间，不是实拍 |

**实景口播的光**：优先用环境里本来就有的光（窗光、顶灯、台灯），在场景描述里写清
「从哪侧来、硬还是软、什么色温」，比堆氛围形容词有效。

### 6.1 光线三要素写法（写场景图提示词时按这三行写）

勿只写"柔和光线"——模型不知道画什么。
按 **主光 + 补光 + 轮廓光** 三行写，每行都写清楚：**什么实物光源 + 从哪侧来 + 什么色温**。

| 要素 | 写什么 | 短语 | 反例短语 |
|---|---|---|---|
| **主光 key** | 场景里最亮的实物光源，从人物哪侧打来 | "桌上台灯从左前方打来暖黄色光" | "温暖的光线" |
| **补光 fill** | 从另一侧补光、柔化阴影的来源 | "身后显示器冷蓝光柔化右侧阴影" | "柔和补光" |
| **轮廓光 backlight** | 从人物后方打来、分离人与背景的光 | "右侧窗光在肩膀边缘形成轮廓" | "电影感打光" |

🔴 **禁用写**："电影感光线""氛围感打光""炫酷光影""高级色调"——这些词模型不知道画什么。
🔴 **必须写**：具体光源实物 + 方向 + 色温（暖黄/冷白/自然阳光）。

**不同场景的光线配方速查**：

| 场景 | 主光 | 补光 | 轮廓光 |
|---|---|---|---|
| 办公桌 | 桌上台灯左前方暖黄 | 身后屏幕冷蓝 | 右侧窗光 |
| 讲台 | 头顶会议室顶灯中性白 | 投影幕布冷白从前方补 | 讲台两侧射灯后方打 |
| 露天户外 | 自然阳光右侧45度暖金 | 天空散射光柔化阴影 | 阳光在头发边缘打亮 |
| 会议室 | 头顶平板灯均匀中性 | 桌面文件反光从下补 | 玻璃墙走廊光侧面打 |
| 产品展示 | 柔光箱正面偏左 | 展示台下方补光灯 | 后方两侧轮廓灯 |
| 居家客厅 | 落地灯左前方暖黄 | 电视微光从身后补 | 窗帘透进傍晚天光 |

完整场景配方见 `10-典型场景配方库.md`。

## 七、素材层级：A-roll / B-roll / insert / cutaway

这是剪辑的基本分层，比「模板」更接近实际工作方式：

| 层级 | 定义 | 本技能对应 |
|---|---|---|
| **A-roll** | 主叙述素材：人物对镜头讲，构成故事骨架 | S / L / W（人物镜头） |
| **B-roll** | 辅助镜头：补充、渲染氛围、遮剪辑点 | E（演示空镜）、B（环境） |
| **insert** | 插入特写：把某个物件/界面放大给观众看 | M（素材贴图） |
| **cutaway** | 切走再切回：从人物切到别处，再切回人物 | B-roll 的一种用法，用来遮跳切 |

**口播的典型结构**：A-roll 讲主线 → 说到具体东西切 insert（M）→ 换地点切 B-roll（B）→ 回 A-roll。

## 八、剪辑点与转场

| 手法 | 英文 | 本技能 |
|---|---|---|
| 硬切 | hard cut | ✅ 默认，段与段之间直接切 |
| 跳切 | jump cut | ⚠️ 同机位同景别硬接会有跳跃感；换场景/换景别再切更顺 |
| 叠化 | dissolve | ✅ 素材段之间可用 |
| 淡入淡出 | fade in / out | ✅ 开场与收尾 |
| 匹配剪辑 | match cut | ✅ 用相似构图或相似动作衔接两段 |
| 声音先入 | J-cut | ⚠️ 需要音画分离，成片音轨连续时做不了 |
| 画面先走 | L-cut | ⚠️ 同上 |

**切点落在语义转折处**，不落在句子中间。一段话讲完一件事再切，观众才不晕。

## 九、一个镜头要说清六件事

写进提示词时，六样都要落字（提示词层面的完整公式见
`fxai-h3-video-prompt/references/06-运镜LoRA与运镜写法.md`）：

1. **主体在做什么**——具体动作，不是「一个人站着」，而是「她抬手指向屏幕」
2. 🔴 **主体的运动轨迹**——从哪到哪、什么姿态、什么速度（见 4.2）；写状态等于没写
3. 🔴 **场景物件的动态**——屏幕、键盘、纸张、指示灯在怎么变（见 4.3）；空镜缺这条就是静图
4. **镜头怎么动**——生成层只写「固定 / 极缓推近」；拉远、横移、摇交给后期（见 4.4）
5. **光线与氛围**——主光方向、软硬、色温
6. **结束状态**——镜头结束时画面停在哪；不写这一条，结尾容易飘

头部、眼神都不在这六条里——一律不写（见 4.5）。

第 2、3 两条是「画面活不活」的分水岭。只写 1、4、5、6 而漏掉它们，
出来的就是人物原地比划 + 静物背景。

### 主体在做什么：动作要从场景里长出来

口播最常见的失败是**场景摆了东西、人物却空比划**：身后是双屏、旁边是白板、身侧是操作台，
人物站在画面中间对着镜头念——观众看到的就是念稿，场景成了背景板。

| 场景里有什么 | 动作类型（部位 · 落点） |
|---|---|
| 显示器 / 屏幕 / 笔电 | 指向类：手 / 臂，落点在屏幕，可带虚点 |
| 白板 | 指向 + 划动类：手 / 臂，落点在板面 |
| 操作台 / 主机 / 机柜 / 指示灯 | 拾取 + 指向类：手，落点在台面与指示灯 |
| 手册 / 书架 | 翻动 + 指向类：双手，落点在册页与书脊 |
| 便签墙 / 留言板 | 指向类：手，落点在单张便签 |
| 窗 / 城市 / 绿植 | 指向类：手 / 臂，落点在窗外方向 |

动作落点用**手**表达，身体朝向始终正面朝镜头 —— 转身到物件前面会变成侧脸口播。

**代码已实现**：`dh_video.pick_act()` 按该段场景描述里**最先出现的实物词**选动作
（谁写在最前面，谁就是这段的主体），匹配不到才退回通用比划（`SPEAK_ACTS`）。

**关键是「替换」而不是「追加」**：`build_ref2va_prompt(act_mode="extra")` 会用互动动作
**替换**默认那句「手随话语自然比划讲解（抬手强调、摊掌、轻点）」，只保留稳定站位与表情部分。
只追加不替换时，那句泛化的空比划会把「指向屏幕」稀释掉，人物照样站着念稿——
追加以外的动作句会被前半句压制，替换才生效。

**位移边界**：位移可以写，但要**慢、短、有明确终点**——「从右侧走到桌前停下」安全，
「横穿整个画面来回走」会把位移放大成画面晃动。写清终点让模型知道运动在哪收住。

| 写法 | 结果 |
|---|---|
| 从画面右侧走入，走到中央停下继续讲 | ✅ 安全，位移是这段最主要的运动 |
| 边讲边朝镜头走近两步，停在中景距离 | ✅ 安全，景别自然变化 |
| 走到白板前停下，抬手指向板面 | ✅ 安全，走 + 指两段动作（不转向） |
| 在房间里来回走动 / 横穿画面 | ⚠️ 位移过长，易晃 |
| 走位同时镜头环绕跟随 | ⚠️ 主体与机位同时动，背景会重算 |

## 十、视频类型决定结构

类型定下来，分镜结构和镜头配比才定得住。

| 类型 | 结构 | 要出镜人 |
|---|---|---|
| 开箱 | 揭示 → 第一眼 → 关键特征 → 使用中 | 不用（手 + 物即可） |
| 测评 | 优点 → 缺点 → 结论 | 要 |
| 教程 | 一步步演示怎么做 | 不用 |
| 对比 | before/after 或 我方 vs 别方 | 不用 |
| 叙事 | 情境 → 问题 → 转折 → 结果 | 要 |

口播多数落在「测评 / 教程 / 叙事」三类；带货类走「开箱 / 对比」。

## 十一、按内容选镜头（口播配方）

| 这段在讲什么 | 用什么镜头 |
|---|---|
| 抛观点、开场、立人设 | W 走近半步 / S 中景 |
| 讲步骤、讲界面、讲怎么操作 | S 中景 + E 演示空镜 + M 界面截图 |
| 给数据、给对比、给证据 | M 素材镜头（图表 / 对比图 / 参数表） |
| 讲行业、讲现场、交代地点 | B 环境镜头 |
| 讲结构、指着东西说明 | L 静立 / 倚靠，指向白板或设备 |
| 收尾、CTA | S 中景（可切近景） |

## 十二、B 段与 M 段怎么落地

人物镜头由 `dh_video.py` 生成；环境空镜与素材贴图不走人物链路，由
`scripts/make_material_seg.py` 把一张静图做成一段带运镜的视频。

```bash
python scripts/make_material_seg.py \
  --image image/mat_01.png --dur 4.5 \
  --motion zoom-in --fit contain \
  --size 768x1280 --fps 24 --out video/seg_M01.mp4
```

| 运镜 | 用在哪 |
|---|---|
| `still` | 文字密集的界面、表格，画面动起来反而看不清 |
| `zoom-in` | 强调某个数字、某个按钮、某处细节 |
| `zoom-out` | 从局部拉到全貌，用来交代「这是什么」 |
| `pan-left` / `pan-right` | 长截图、宽表格、横向对比图 |

**`--fit` 的取舍**：`cover` 满屏裁切，适合纯界面截图；`contain` 完整显示并留边，
适合图表、参数表、带标注的对比图——数据类画面被裁掉一部分等于证据缺失。

**B 段（环境空镜）**：用同一套场景描述能力生成**空场景**（不加人物），
再交给 `make_material_seg.py` 加 `zoom-out` 或 `pan-left`，就有呼吸感。
机场、体育馆、车间、街口都能当 B 段，地点由内容决定。

**操作特写（最贴「在做事」的一类 B-roll）**：口播镜头里人物只能正面讲，做不出「真的在干活」，
补的就是这一类——**只有手入画**，敲键盘、翻手册、插线缆、在白板上画线：

| 这段在讲什么 | 补什么特写 |
|---|---|
| 装环境、报错、跑脚本 | 双手在键盘上敲击，身后屏幕虚化 |
| 数家底、翻规范 | 双手翻开一本厚手册，纸页边缘清晰 |
| 接设备、调机器 | 双手在操作台上插接一根线缆 |
| 拆结构、讲流程 | 手持记号笔在白板上画连线 |

### 插入方式是「覆盖」，不是「拼接」

口播音频是一条**连续音轨**，往中间塞片段会让后面全部音画错位。
`scripts/insert_broll.py` 把指定时间段的**画面顶掉**，音轨原样保留、总时长不变：

```bash
python scripts/insert_broll.py --video 成片_768x1280.mp4 --out 成片_b.mp4 --spec broll.json
```

```json
[{"video": "_tmp/broll_01.mp4", "start": 20.0, "dur": 5.0},
 {"video": "_tmp/broll_02.mp4", "start": 62.0, "dur": 6.0}]
```

**插入点落在段落边界**，落在句子中间会把一句话劈成两半。每段 B-roll 3~6 秒：
短了看不清，长了观众以为卡了。**B-roll 段没有字幕是对的**——空镜配着人声，这是标准用法。

## 十三、一句话总结

**镜头语言不是让人物一直对着镜头念，而是让画面替内容干活**：
该人物出场时人物讲（A-roll），该给证据时切素材（insert），该换气时给环境（B-roll），
每一刀都落在内容转折上。
