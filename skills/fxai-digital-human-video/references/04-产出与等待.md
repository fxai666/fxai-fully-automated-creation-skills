# 产出（扁平结构 · 交付物都在项目根）

⚠️ **落盘位置铁律**：所有产物落在**工作区** `<工作区>/<项目名>/` 下（工作区由
当前工作区决定（在哪个工作区跑就建在哪））。
**产物只落工作区** `<工作区>/<项目名>/`；用户个人目录只作为素材来源，引用别处的素材 ≠ 把产物写到别处。

**目录扁平**：交付物一律放**项目根目录**，不建 `video/` `music/` `doc/` 分层（方便一眼看全）；
只有图片多，单独放 `image/`。

```
<项目名>/
├─ image/                     四视图、场景图、标题卡、封面（全部要落本地，见下）
│   ├─ scene_NN.png           场景图（程序自动取回本地；封面背景、E 段空镜、留档都用它）
│   ├─ cards.json             标题卡文字清单（一节拍一条：title/sub/foot）**可选，不做就没有**
│   ├─ title_NN.png           标题卡叠加层（独立技能 fxai-title-card 出，与节拍序一一对应）
│   ├─ infocards.json         信息贴片清单（文字+形状+位置+时间）**可选，不做就没有**
│   ├─ cover_bg.png           封面写实背景（生图，缓存不重生）
│   └─ cover.png              成品封面（PIL 叠字，拼在成片前）
├─ _tmp/                      临时中间产物
├─ 口播文案.md                 ① 正文（无标签）—— 字幕就用它
├─ 口播文案_标签.md            ② 加情感/格式标签版（喂 TTS）
├─ 口播标签.txt                标签配置（一行一个，按句套用）
├─ <项目名>01.wav…NN.wav       ③ 逐段音频（编号从 01 起）
├─ 口播音频.wav                ④ 合并音频（分段无损直连）
├─ 合并_{W}x{H}.mp4            ⑤ 合并成片（无字幕，带分辨率后缀）
├─ 字幕.ass / 字幕.srt         ⑥ 字幕（**不带**分辨率后缀，可跨尺寸复用）
├─ 成片_{W}x{H}.mp4            ⑦ 加字幕成片（`-c:a copy` 保留原音频）⚠️ **中间成片，不是交付物**
├─ _beat_times.json           ⑧ 节拍时间码（finalize.py 从逐段音频时长算，标题卡靠它定位）
├─ 成片_最终_{W}x{H}.mp4       ⑨ ★**交付物**：叠好标题卡 + 前拼写实封面
├─ 口播提交提示词.json         实际提交给 ComfyUI 的 fxai_prompt
└─ 交付清单.md / 视频清单.md    清单
```

## 🔴 ⑦ 不是交付物，⑨ 才是

| | 文件名 | 里面有什么 | 可否直接发 |
|---|---|---|---|
| 中间成片 | `成片_{W}x{H}.mp4` | 只有数字人画面 + 字幕 | ❌ 暂不交付：缺封面 |
| **交付物** | `成片_最终_{W}x{H}.mp4` | 数字人画面 + 字幕 + **封面**（+ 标题卡 / 信息贴片，若本片要叠） | ✅ 这个才是发出去的 |

- 🔴 **正常链路默认全套都有**（画面 + 字幕 + 封面 + 标题卡 + 信息贴片），但**每一项都能单独关**：
  封面 `--no-cover`、标题卡 `--no-titles`、信息贴片 `--no-infocards`。**默认全开，关掉是例外，不是常态。**
- 🔴 **封面缺背景图不报错**：先拿 `image/scene_01.png` 当背景，再没有就走兜底渐变
  （`gen_cover.fallback_bg()`）。默认链路必须能一路跑完，不因为缺一张图卡死。
- 🔴 只交到 `成片_{W}x{H}.mp4` = **半成品**，等于没做完（观众首屏看到的是人脸特写，
  不是设计过的封面）。
- 🔴 标题卡实现**不在本技能**：已抽成独立技能 `fxai-title-card`（能给任何视频叠字）。
  本技能只在 `image/cards.json` 存在时调它叠卡。
- 🔴 信息贴片同理走独立技能 `fxai-infocard`，只在 `image/infocards.json` 存在时才叠。
  两层的时间 `t` 都按**口播起点**算（不含封面）；封面最后拼，拼完全体后移封面段时长，
  三层仍同步。封面段占几帧见 `fxai-poster/references/05-封面模板库.md`「封面段时长」。
- 🔴 落盘后必须跑 `python scripts/check_delivery.py --project <项目>` 过门禁，
  它逐项校验 `成片_最终` / `title_NN.png` 张数 / `cover.png` / `cards.json` /
  `_beat_times.json` / `image/scene_NN.png`，缺一项就报错退出。
- 场景图取回本地由 `dh_video._sync_scene_to_project()` 自动完成：本地没有就拷、
  已有就跳过、`--force` 覆盖。项目 `image/scene_NN.png` 是唯一交付位置。


- 全部文本类交付物用 **Markdown**（`.md`）；仅机器清单用 `.json`。
- `{W}x{H}` 取视频真实输出尺寸：竖屏 `768x1280`（默认）/ 横屏 `1280x768`，代码按 `out_size()` 自动拼，
  **不用** single/multi 的 `size` 拼（会写成 1080x1920）。
- 收尾清 `_` 前缀临时件（whisper 转录/抽轨/字幕正文等）。

## 硬规则（代码已强制）

| 规则 | 强制方式 |
|---|---|
| **字幕只显示正文**，`用…的语气说<\|endofprompt\|>` 标签在烧录前剥掉 | 烧录后校验 `.srt/.ass`，发现标签/MARK 直接报错、不落盘 |
| 场景图/四视图缓存 tag 必须带项目名 | `_project_tag()`；否则同 tag 会跨项目复用错图 |
| 音频编号从 01 起 | `enumerate(start=1)` 直接用序号，不二次 +1 |
| 脚本本来就在项目根时不做同文件复制 | 路径相同就跳过（否则 `WinError 32`） |
| 合并音频已存在时不重复合并 | 单音频且源==目标直接复用 |
| multiref 至少 2 个不同场景、上限=段数 | `scene_count_for()`；`--scene-count` 给 1 也会被抬到 2 |
| 烧字幕必须用带 libass 的 ffmpeg | `av.ffmpeg_libass()`（conda 自带的没有 `subtitles` 滤镜） |
| **一句字幕 = 一个完整时间窗口** | `align_lyrics_spans()`：whisper 把一句切成多个 phrase 时，窗口取首 phrase 的 start → 末 phrase 的 end，不逐 phrase 显示 |
| **单条字幕按方向分档** | 竖屏 4.0 秒/16 字、横屏 6.0 秒/24 字（`sub_limits()` 按分辨率自动选） |
| **字幕不显示标点** | 标点只参与断句，上屏前剥掉 |
| **字幕对齐用逐字时间戳** | `--asr-mode char`（默认）；口播纯朗读识别率高，**不做 MV 那套多次识别** |
| **时间轴写盘前自检** | `check_subtitle_timing()`：单条 ≥0.6 秒 / ≤上限 / 递增不重叠 / 覆盖到音轨末尾，不合格报错不落盘 |

## 等任务

`gen_video` 内部等 `fxai:task_saved`（＝**合并/保存完毕**）才返回，返回即已过终态门。

| 阶段 | 规则 |
|---|---|
| 等待期·**正常** | ✅ 只查健康（服务器/进程还活着吗）<br>❌ 不做数据交互：不查 `/history`、不拉文件列表、不取结果、不下载、不反复 curl `/queue` |
| 等待期·**报错** | ✅ **这时才做数据交互**：取错误详情与日志，分析原因并解决。异常里带 `prompt_id`，用 `comfy_watch.py status <pid>` 查详情 |
| **终态门** | 日志出现 `✅ 合并成功，已保存：<url>` 之后，才做后续：烧字幕（`--burn`）→ 归档 → 写清单 → 交付 |

- 要在对话里只在完成时播报一句 → `$WATCH next <pid>`（只出终态，不刷过程）。
- 要全程看进度 → 双击 `fxai-comfyui-watcher/progress.html`（直连 WS，绕过对话，不耗 token）。

已有段视频、已有场景图都默认复用（`--force` 才重烧），所以中断后重跑不会重复花钱。

**场景图比成片新时，成片自动作废重渲**（`_scenes_newer_than()`）：换了场景描述重出图，
再跑一次就会重新渲染，不会拿旧画面配新场景。要保住旧成片就先挪走再出图。
同一台 ComfyUI 还有别人在跑时排队会很久（视频默认 7200s、场景图默认 1200s）。

### 场景图先单独出，确认了再渲染

`--scene-only` 只出场景图、不渲染视频，返工不浪费 GPU：

```bash
python dh_video.py --project <项目> --audio-dir <项目>/music --scene-only --force
```

图对了，去掉 `--scene-only` 再跑一遍，12 张图直接复用缓存。**改场景描述时先走这一步**——
画面不对只需重出图，不用等完整渲染。

### 队列卡住：running 却不出活

现象：`/queue` 里有一个 running 任务，但 `nvidia-smi` 显示 GPU 利用率接近 0、显存只占 2GB 左右，
后面的任务全部 pending。这是服务端残留的僵尸任务占着队列，等它自然超时要一小时。

```bash
curl -s -X POST http://127.0.0.1:8188/interrupt -H "Content-Type: application/json" -d '{}'
```

中断后 pending 里的下一个任务立刻转 running，GPU 利用率回到 100%。**场景图逐张提交**时，
一张卡住只影响那一张（`make_scenes` 记下失败序号继续往下），重跑补缺即可。
