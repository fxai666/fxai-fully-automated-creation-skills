# 02 · 模板库

> **何时读**：按模板名做一套（`--preset <模板名>`）、照抄某个版式的 `fields`、做封面、出横版时。
> 动画怎么进场、怎么录制 → **`03-动画与录制.md`**。

> 本册 = **参考模板库**。把爆款风格拆成可复用的**配方**，起名登记，说「按 <模板名> 做一套」即可
> `sv_pipeline.py --preset <模板名>` 开跑。

## 模板体系（三层积木）

| 层 | 是什么 | 在哪配 | 例 |
|---|---|---|---|
| **① 模板（Template）** | 一整套配方：结构 + 版式组合 + 动画 + 音频 + 封面 + 正文配图 | `sv_pipeline.py --preset <模板名>` | 快嘴爆款 / 穿搭展示 / 写真 |
| **② 版式（Layout）** | 单页怎么画 | `segments.json` 每段 `template` | marketing / outfit / product / showcase / stats / chat / pricing / frame / trio / steps / list / compare / points / quote / code |
| **③ 动画（Animation）** | 页内元素怎么进场 | `segments.json` 每段 `anim` | 分层弹入 / 左滑入 / 缩放弹入 …（见 **`03-动画与录制.md`**）|

一个模板 = 挑一组版式 + 每段配一个动画 + 定一组音频参数。版式和动画是共享积木。

## 模板登记表

| 模板名 | 一句话 | 适用 |
|---|---|---|
| **快嘴爆款** | 深色底大花字 + 页内弹入 + 黑场换页 + 快嘴口播 | 营销 / 运营 / 工具推广 / 干货口播 |
| 教程讲解 | 浅色步骤卡 + 逐步展开，平速讲解 | 安装教程 / 操作步骤 / 知识科普 |
| **穿搭展示** | 人物图满屏 + 底部暗卡列单品 | 穿搭 / 服饰 / 好物 / 商品种草 |
| **商品展示** | 商品图完整不裁切（contain）+ 底部暗卡列规格 | 食品 / 实物商品 |
| **写真人像** | 人像大图 + 少量文案 | 写真 / 形象片 |
| 对比测评 | 并排对比卡（A vs B） | 测评 / 竞品对比 |
| 清单合集 | 清单逐项点亮 | 「必备 N 件」 |
| **数据说话** | 大数字 + 涨跌柱图打头，结果前置 | 战绩复盘 / 效果展示 / 案例汇报 |
| **成交逼单** | 聊天反馈拉信任 + 三档套餐报价收尾 | 课程 / 服务 / 代运营成交 |
| **上中下分栏**（`frame`，旧名栏目图文）| 竖屏 9:16 固定节目壳（上下黑带不动）+ 中区全宽 16:9 换素材，图/视频/海报混排 | 栏目化连载 / 知识口播 / 认知故事片 / 静态背景板式 |
| **左中右分栏**（`trio`）| 左栏竖排标题 + 中槽 + 右栏竖排落款；**竖素材 = 满高贴边**（上下零边距、宽度可调），横素材 = 16:9 横带居中 | 素材是竖屏/人像、要顶天立地占满高度；或横素材要做「文字左右」那一版 |

各模板的预设参数见 `sv_pipeline.py` 的 `PRESETS`。
新增模板：按「配方六件套」拆解 → 表里加一行 → 在 `sv_pipeline.py` 的 `PRESETS` 注册同名预设。

## 配方六件套

| # | 维度 | 看什么 |
|---|---|---|
| 1 | 结构 | 段落顺序与功能（钩子→正片→总结→人群→CTA） |
| 2 | 版式 | 底色、字号、高亮色、胶囊/徽章/流程/UI |
| 3 | 动画 | 换页方式 + 页内元素进场（→ 动画库点名） |
| 4 | 音频 | 语速、句子长短、停顿、重读词 |
| 5 | 封面 | 首帧形态（纯文字海报 or 图片封面） |
| 6 | 正文配图 | 有无插图点缀、位置、风格 |

## 模板：快嘴爆款（★ 主推）

### 1) 结构骨架（6 段式，可扩到 10~14 段）

```
① 钩子/成果前置 → ② 引导互动 → ③ 正片 ①②③④ → ④ 价值总结 → ⑤ 人群覆盖 → ⑥ CTA
```

### 2) 版式（`template:"marketing"`）

深色渐变底 + 大花字。`fields` 速查：

| 字段 | 作用 |
|---|---|
| `brand` | 顶部品牌胶囊（橙点）|
| `tag` | 右上高亮标签 |
| `chapter` | 左上章节胶囊，写内容属性（痛点 / 观点 / 难点 / 问题 …）|
| `badge` | 标题上方编号徽章 |
| `title` | 大标题，支持 `<span class="hl">橙</span>` / `hl2` 绿 / `hl3` 蓝 |
| `title_size` | 标题字号（默认 58；封面 52~64）|
| `hook` | 副标（金色小字）|
| `chips` | 胶囊标签 |
| `steps` | 序列步骤条 `[[编号,标题,说明], ...]`（见 `03-动画与录制.md` §5）|
| `flow` | 图标流程 `[[图标, 文字], ...]`，自动加橙箭头 |
| `mock` | UI 模拟面板 `{title, rows}` |
| `hint` | 封面提示文字（如「点关注·不迷路」）|
| `frame` / `frame_top` | 纯文字封面：文字套半透明圆角框（默认居中，`frame_top` 上移）|
| `cover_image` | 图片型封面 |
| `media` | 正文点缀图 |
| `site_bar` | 底部引导条（默认不开）|

🔴 **横版的字号是固定 px，不跟 `vh` 缩放**（2026-10-27 定）。
横版用 vh 时，1366×768 下标题 `5.4vh` 只有 **41.5px**，看着像正文；而横版左栏可用宽
560px、竖版 656px，是同一量级，所以直接沿用竖版那套 px 观感才一致：

| 元素 | 竖版 | 横版（固定值）|
|---|---|---|
| 大标题 `.mk-title` | 58 | **58** |
| 副标 `.mk-hook` | 36 | **34** |
| 小字 `.mk-sub` | 32 | **30** |
| 胶囊 `.mk-chip` / 提示 `.mk-hint` | 28 | **26** |
| 章节 `.mk-chapter` | 24 | **24** |
| 品牌 / 标签 | 24 | **22** |

盒子宽高、内距仍走 `vh`，版式照样自适应。**选 58 的依据**：实测 48 偏小（标题和副标挤在一起、
层次分不开）、66 偏大（10 字标题几乎顶满栏宽，稍长就换行难看），56~60 最稳，取 58 与竖版同一个数。

⚠️ 固定值是按 1366×768 定的：`横屏小` 1280×720 会略大一点（可接受），
`横屏高清` 1920×1080 会偏小 —— 高清档单段用 `title_size` 覆盖即可。
横版穿搭 / 商品（`landscape_outfit_slide`）同理：`ot-title 40 / ot-price 32 / ot-sub 26 / 条目 26 / 胶囊 24`。

### 3) 动画

- 换页：`--fade 0.3`（黑场过渡，只淡视频不淡音频）。
- 页内：`--anim` 元素分层弹入；首段 `"anim": false`（静态），首帧即完整封面。

### 4) 音频

- 快嘴 `--speed 1.12`（≈18 字/秒）；短句密集；数字前置；关键词重读与高亮词对应。
- 写多长、拆多少段都行。

### 5) 正文配图（`media`）

```json
{ "text": "第二个，AI数字人：文字进去，真人出镜口播。",
  "template": "marketing",
  "fields": { "chapter": "② 数字人", "title": "出镜口播 <span class='hl'>全自动</span>",
              "media": "./media/m_dh.png" } }
```

- 用生图工具（`fxai-comfyui-image-gen`）出横构图 768×512，落项目内（如 `配图/`），`fields.media` 给绝对路径。

## 模板：穿搭展示（`outfit`）

人物图**满屏裸露**，顶部品牌/章节/标签，右侧竖排亮点标签，底部一张暗卡列单品。

| 字段 | 作用 |
|---|---|
| `image` | 人物/商品图绝对路径（满屏 cover）|
| `title` / `price` | 卡片主标题 / 右侧价格或亮点 |
| `sub` | 副标 |
| `items` | 单品列表 `[[分类, 单品名], ...]` |
| `chips` | 胶囊标签 |
| `tagside` | 右侧竖排标签 |
| `chapter` / `tag` / `brand` / `hint` | 同 marketing |

```json
{ "text": "今天这套通勤风，三件就够，低饱和还显白。",
  "template": "outfit", "slug": "穿搭",
  "fields": { "brand": "凤希AI · 穿搭局", "chapter": "今日穿搭", "tag": "通勤 · 三件套",
              "image": "./cover/coverA.png",
              "title": "米白针织 · 通勤风", "price": "3件套",
              "sub": "低饱和高级感 · 通勤约会都稳",
              "items": [["上衣","米白针织开衫"],["内搭","白色衬衫"],
                        ["下装","燕麦直筒裤"],["配饰","细金耳环"]],
              "chips": ["显瘦","百搭","不挑肤色"], "tagside": ["柔和","高级","显白"] } }
```

🔴 `image` 若直接引用自有角色底图生成，提示词必须写【穿搭/服装】+【头型/发型】。

## 模板：商品展示（`product`）

与 outfit 的区别：outfit 人物图满屏 `cover`（会裁切）；`product` 商品图 `contain` **完整放进图卡，不裁切**。

**横竖两套布局，按画布方向自动切**（也可写 `"layout": "landscape"` 强制）：

| 画布 | 布局 |
|---|---|
| 竖屏（768×1280）| 居中图卡（`shot_top`/`shot_bottom` 定上下边界）+ **底部**暗卡列规格 |
| 横屏（1366×768）| **左半屏 contain 商品图**（`.pd-l`，四周留呼吸位）+ **右卡**列规格（`.ot-cover-r`）|

| 字段 | 作用 |
|---|---|
| `image` | 商品图绝对路径（contain 完整显示）|
| `title` / `price` | 商品名 / 右侧规格或价格 |
| `sub` | 副标 |
| `items` | 规格条目 `[[标签, 值], ...]` |
| `cols` | `2` → 规格双列 |
| `tagside` | 竖版：图卡右上竖排标签；**横版：右卡顶部一行胶囊**（图占左半屏，浮上去会压商品）|
| `shot_top` / `shot_bottom` | 微调图卡上下边界（px，默认 212 / 508）—— **仅竖版有效** |
| 其余 | 同 marketing |

🔴 实物商品用**真实实拍照片**。

🔴 横屏一律不套 outfit 那套 `cover`：`product` 的意义就是「包装/标签须完整」，横版同样走 contain。

## 新版式三件套（`stats` / `chat` / `pricing`）

三种专职形态，深色底、顶部胶囊/标签/章节、`foot`/`hint`/`site_bar` 与 marketing 完全同款。
正文中「讲结果」「讲反馈」「讲报价」的三类段落，分别点名这三个版式。

### `stats` · 数据战绩

大数字 + 涨跌幅 + 上升柱状图，讲「结果」的一屏。

| 字段 | 作用 |
|---|---|
| `value` / `unit` | 主数字 / 单位（如 `"12.8"` / `"万"`）|
| `delta` | 涨跌幅（如 `"+236%"`；`"-"` 开头自动转红=下降）|
| `label` | 数字下方说明 |
| `title` | 数字上方小标题（可选）|
| `bars` | 柱状图 `[[底部标签, 柱顶数值, 高度值0~100], ...]`，最高一根自动橙高亮；`hot_bar:<索引>` 手动指定 |
| `rows` | 数据行 `[[名称, 值], ...]`（bars 未给时改用两列排布）|
| 其余 | 同 marketing |

```json
{ "text": "一个月，播放从一万二涨到十二万八。",
  "template": "stats", "slug": "战绩",
  "fields": { "brand": "凤希AI · 数据局", "chapter": "战绩", "tag": "30 天",
              "value": "12.8", "unit": "万", "delta": "+236%",
              "label": "单月播放增量",
              "bars": [["第1周","1.2万",18],["第2周","3.6万",42],
                       ["第3周","7.1万",70],["第4周","12.8万",100]],
              "foot": "四条视频，没花一分钱投流" } }
```

### `chat` · 聊天对话

浅色 IM 卡内仿微信气泡，**逐条弹出**（`--rec` 录制模式按 `data-seq` 一条条出现；定格模式分层错峰）。

| 字段 | 作用 |
|---|---|
| `title` | 对话对象（如 `"客户 · 某餐饮连锁 王总"`），显示在卡顶 |
| `msgs` | 消息 `[["you"\|"me", 文本], ...]`；you=左白泡，me=右橙泡。**建议 4~6 条** |
| `avatars` | `[对方头像字, 我方头像字]`，默认 `["客","我"]` |
| 其余 | 同 marketing |

```json
{ "text": "客户第一句话就问我，一个月能出多少篇。",
  "template": "chat", "slug": "反馈",
  "fields": { "brand": "凤希AI", "chapter": "真实反馈",
              "title": "客户 · 某餐饮连锁 王总", "avatars": ["王","凤"],
              "msgs": [["you","你们这个 AI 代运营，一个月能出多少篇？"],
                       ["me","按你的品类定，一般是 20 到 30 篇原创。"],
                       ["you","那我得配几个人审核？"],
                       ["me","不用配人。选题到成稿全自动，你只看终稿。"]],
              "foot": "从咨询到成交，只用了 12 分钟" } }
```

### `pricing` · 三档套餐

并排价格卡，高亮档自动带橙框 + 徽章（引导到想卖的那一档）。

## 模板：上中下分栏（固定节目壳 / 静态背景）

**这个版式的正式叫法是「上中下分栏」**：上面一条带、下面一条带、中间是展示区。
`template` 写 `"上中下分栏"` / `"frame"` / `"栏目图文"` 三者等价（同一份实现）。

一款「节目壳」式版式：**上下两条黑带全片一个字都不改**（栏目包装，这就是「静态背景」）——
带子是固定的，全片只有中间那条横构图媒体区按 3~5 秒换素材。适合做成**栏目化连载**：
壳一次做好，后面每一集复用。

🔴 与 `thirds`（左右分栏 / 上下分栏）的区别：那个是**两段并排**（文字区 + 媒体槽），
文字随旁白逐段变、没有固定壳；这个是**三段叠起来**，上下带是资产、不随段变。别混。

素材三种混排，按段指定：`图片`（本地生图）/ `视频片段`（视频生成产出）/ `海报`（`fxai-poster` 产物）。

```bash
python sv_pipeline.py --project <项目名> --spec segments.json --preset 上中下分栏
```

### 1) 结构骨架

钩子（结论前置）→ 抛观点 → 逐条讲（每条一张素材）→ 收口。每段 3~5 秒。

### 1b) 画布：竖屏 9:16 是规范，横屏只在例外时用

🔴 **这个版式默认就是竖屏 9:16（1080×1920）**，不是「横竖都能」：
上下两条带压住画面、中间一条横构图素材带，竖着拿在手里才成立。文档、模板、预设一律按竖屏写。

比例按画布自动算，同一份规格不用改字段：

| 画布 | 上带 | 中区（媒体槽） | 下带 | 说明 |
|---|---|---|---|---|
| **竖屏 9:16 · 1080×1920**（规范）| 36.0% | **1080×608，全宽 16:9** | 32.3% | 素材按 16:9 出，进框零裁切 |
| 竖屏 3:5 · 768×1280（默认档）| 34.9% | 768×432 | 31.3% | 同上，只是画布窄一点 |
| 横屏 · **1366×768**（`--size 横屏`）| 15% | 956×538（左右各让 15%）| 15% | 仅当素材本身是横屏片、要整条嵌进中区 |
| 横屏 · 1280×720（`--size 横屏小`）| 15% | 896×504（左右各让 15%）| 15% | 同上，720p 档 |

🔴 **横屏是借来的用法，不是这个版式的第二种形态**。只有「一条现成的横屏片要整体嵌进中区」
（如川西那条旅游片）才用横屏；借完勿把它当默认。竖屏那套比例套到横屏会把中区压成
扁条、16:9 片源裁掉三成高度，所以横屏单列一套：中区宽高各 70%，16:9 一点不裁，
代价是左右各让 15% 给壳底（观感是「画框装在栏目包装里」）。

槽位坐标只从 `ml_frame.frame_box(w, h)` 取（壳 CSS、广告 `slots`、幻灯 `sv_media` 三处共用），
别处一律不按比例再算一遍。风格（配色、字号、换图节奏、验收）见
`../fxai-mixed-layout/references/04-风格-上中下分栏.md`。横屏下带的品牌字段转横排（`tagline` 走 `horizontal-tb`）、字号另给一档，
免得 1280 宽的画面里品牌小到看不清。

### 2) 版式（`template:"frame"`）

🔴 **壳写在 `segments.json` 顶层 `frame`，勿每段重复**。`load_specs()` 自动合并进每一段；
段内同名字段可以覆盖（某一段想临时换标题时才写）。

顶层 `frame`（壳，全片共用）：

| 字段 | 作用 |
|---|---|
| `title1` | 顶部第一行（白字 + 黑描边）|
| `title2` | 顶部第二行（黄字 + 黑边 + 红投影）|
| `logo` | 底部主 logo 文字（金色）；要书法字/正式 logo 就传 `logo_img` |
| `logo_img` | logo 图片路径（优先于 `logo`）|
| `logo_en` | logo 下方拉丁小字（可选）|
| `tagline` | 竖排栏目名（可选）|
| `slogan` | 底部右侧一句（可选）|

🔴 **这五个品牌字段不填就用本品牌默认壳**（`slides.py` 的 `FRAME_BRAND`）：
`logo=凤希` / `logo_en=FENGXI AI` / `tagline=自动创作论` / `slogan=一个人干一个团队的活`。
换品牌、换口号只改 `FRAME_BRAND` 一处，勿每集重填。某一集想临时留空，显式传 `""`
（`dict.get` 的默认值只在 key 缺失时生效，传空串就是真的空）。
顶部 `title1/title2` 是**选题标题**，随片变，没有默认值。

每段 `fields`（换的是这一条）：

| 字段 | 作用 |
|---|---|
| `media` | 中区素材：**一张**（路径字符串）/ **一叠**（list，段内做成幻灯片轮播）/ **网页槽**（`{"page":{…}}`，见 2.61）。图片 / 视频 / 网页都行。相对路径按 `segments.json` 所在目录解析 |
| `media_fit` | `cover`（默认，撑满裁切）/ `blur`（**竖版海报首选**：原图完整居中 + 同图虚化铺底，无黑边）/ `contain`（完整不裁切 + 两侧黑边）。list 里可逐张覆盖：`{"src":"x.png","fit":"blur"}` |
| `trans` | 段内多图的转场（仅 list 有意义）：`push_left` 左右推移（默认）/ `push_up` 上下切换 / `fade` / `cut` / `mix`；也可给 list 按张轮换 |
| `trans_dur` | 转场时长秒（默认 0.55；0.3 更利落）|
| `overlay` | 中区成语花字（白色大字 + 黑粗描边）|
| `overlay_pos` | `bottom`（默认）/ `mid` / `top` |
| `slug` | 建议给，否则文件名都是 `S01_slide.png` 不好认 |

🔴 **视频段不需要特殊处理**：`media` 指到 `.mp4` 时，渲染端只出「壳遮罩」（媒体区透明），
素材由 `sv_media` 垫进去 —— 遮罩不动、素材动。图片段走同一条路，所以推近（`zoom`）对两者都生效。

### 2.5) 视频素材从哪来（本地现生成，纯画面无台词）

用 `fxai-audio-video`（MiniMax H3）把一张已生成的横图做成 4 秒动态，走本机 ComfyUI、零云消耗：

```python
import comfy_client as C, audio_video as av
C.prefer_local()                                   # 本机优先，探不通才回云
rel = C.upload_image("<素材图.png>", subdir="sv_frame")   # 参考图先上传
av.gen_video("single", "<室内底噪>.wav", char_rel=rel,
             seg_prompts=[FL2VA提示词], kind="speak",
             tag="...", out_dir="<素材目录>", prefix="sv", allow_no_outfit=True)
```

🔴 **三个工作流都带音频参考，音频是驱动源、不可省**——这是「铁律：音频=原音频，提示词不另设计音轨」
（`fxai-h3-video-prompt` 第 1 节）。要「纯画面无人声」时这样办：

1. **音轨用合成的室内底噪顶**，勿用 TTS 配音：
   `ffmpeg -f lavfi -i anoisesrc=color=brown:duration=4:amplitude=0.06 -af lowpass=f=1100 ...`
2. **提示词不写口型**：明确写「嘴部始终闭合，不做任何讲话动作」，别照抄口播那套「持续讲话」的写法。
3. `overall_soundscape` 写「沿用原音频：室内底噪、键盘声，全程无人声、无对白」。
4. 按 FL2VA 三段式写（首行对齐指令 + `integrated_multimodal_description` + `overall_soundscape` + `non_diegetic_music: 无`），
   描述顺序是「首帧状态 → 中间变化 → 末帧状态」，运镜只写一条主线。

参考图是完整场景图（不是裸肩底图）时传 `allow_no_outfit=True`，否则会被穿搭校验拦下。

### 2.6) 段内多图轮播（这才是「幻灯片效果」）

🔴 **参考片的中区不是一张死图**：一段里 2~3 张图轮着换，换的过程是**推移**（左右移动）或
**上下切换**，不是硬切黑场。这一段效果全靠 `media` 给 list：

```json
{ "slug": "pain", "text": "上一条我光找图就耗了两个多小时……", "template": "frame",
  "fields": {
    "media": ["素材/翻页.png", "素材/咖啡杯.png", "素材/疲惫特写.png"],
    "trans": "push_left",
    "trans_dur": 0.55,
    "overlay": "两小时没了"
  } }
```

转场对照：

| `trans` | 效果 | 适合 |
|---|---|---|
| `push_left` / `左右推移` | 新图从右边推进来，旧图往左让位 | 默认，讲「接着往下」的事最顺 |
| `push_right` | 反向推移 | 回看 / 对照 |
| `push_up` / `上下切换` | 新图从下往上顶上来 | 分段递进、条目式内容 |
| `push_down` | 新图从上往下压 | 收束 / 落回主题 |
| `fade` | 叠化 | 时间跳跃、情绪转折 |
| `cut` | 硬切（半帧） | 强调「就是这儿」、节奏要狠 |
| `mix` | 按张轮换上面三种 | 不想逐段定，图省事 |

实现是在合成端做一条**中区轮播片**（`sv_media.build_reel`）：几张图先各自归一化到媒体区尺寸
、各带缓慢推近，再用 `xfade` 串起来（`slideleft` / `slideup` / `fade` / 半帧硬切），
然后当普通视频素材垫到壳下面。所以：

- **张数和时长自动分配**：整段音频时长 N 等分，转场重叠会自动补进每张的时长（`L=(total+Σ转场)/n`），
  不需要你算时间点。素材太短时转场会自动收，不会出现负时长。
- **每张图各自的 `fit`**：list 里可以写 `{"src": "海报.png", "fit": "contain"}`，混排也不会变形。
- **`zoom` 仍然生效**：推近做在轮播片里，每张图从 1.0 缓慢推到 1+zoom。

### 2.61) 中区网页槽（文字卡 / 长图滚动 / 真网页）

🔴 **中区那一格不只能放图**。上中下分栏的差别只在「展示形式」——上下壳固定、中间是展示区；
中间放什么，跟整页幻灯**用的是同一套能力**：造 HTML → Chrome 真实录屏 → 得到一条媒体区尺寸的
无声 mp4 → 垫进壳里。图片 / 图片轮播 / 视频 / 网页，在合成端都是同一条视频流。

**三种填法的完整规格（写法、字段表、转场、`fit`、四条坑）只有一处**：
`../fxai-mixed-layout/references/01-素材槽规格.md`。本册只留上中下分栏这一层的差异：

```json
{ "slug": "list", "text": "三条都是我自己踩出来的，别重复踩。", "template": "frame",
  "fields": {
    "media": [ { "page": {
        "type": "text",
        "kicker": "三件别干的事",
        "title": "这三件事<em>别再干</em>",
        "items": ["一次只放一张图，别堆", "转场不超过 0.6 秒", "长段别慢慢推近"],
        "note": "都是我自己翻过的车"
    } } ]
  } }
```

上中下分栏特有的三条：

- ⚠️ **网页段默认不出花字**：页面里本来就是字，再压一层 `overlay` 必然打架。要压就显式写
  `"overlay_show": true` 并自己挑 `overlay_pos`，否则 `overlay` 会被自动忽略（不报错）。
- ⚠️ **时长自动对齐**：录屏片段按「画面静止」收工，和配音时长对不上，合成前按该段音频
  补齐（`tpad` 定格补尾）或裁齐，所以拼接不会越拼越偏。
- 🔴 **勿为了动效造网页**：只是想让图动，用 `zoom` / 轮播就够了；网页槽留给「图放不下的
  信息」（清单、结构、参数、真网页演示）。中区只有 768×440，字多必然滚动，一段别塞超过 5 条。
- 🔴 **壳上的字别与画面里的字撞**：中区嵌的片子若自带地名卡、落版金句，上下带就写
  栏目包装（栏目名 + 期数），否则同一句会在上带和画面里各说一遍。


### 2.65) 竖版素材怎么放（海报 / 竖屏截图）

`fit` 三档，实拍对比过：

| `fit` | 画面 | 什么时候用 |
|---|---|---|
| `cover` | 撑满裁切，竖图两侧内容会被切掉 | 横图、无所谓裁切 |
| `blur` | **原图完整居中，左右用同一张图的虚化放大垫底** | **竖版海报、竖屏截图（推荐）** |
| `contain` | 原图完整居中，左右是真的黑边 | 需要干净留白 / 素材本身就是设计稿 |

🔴 **别用 `contain` 演示竖版海报**：媒体区 768×440，9:16 的海报只占 247 宽，两边各 260 的黑边，
在成片里像「这块缺图」。`blur` 铺底后视觉是满的，内容一点不裁。

`blur` 同时会关掉推近（推近会把虚化层一起放大，边缘露出）。

### 2.66) 推近速度有下限（长段必看）

推近在超采样空间里每帧至少要走 2.2 像素，否则取整误差占比过大，长段会出现 12Hz 的轻微闪烁。
换算下来 768 宽 + 5% ≈ 70 帧 ≈ 3 秒，所以代码里**推近固定在 3 秒内走完，之后保持静止**
（`ZOOM_MIN_STEP`）。一段 7 秒的收尾镜头不会一直慢慢挪，前 3 秒推到位就停——比「永远在挪但挪得发抖」好。

要更长的推近就调大 `zoom`（0.08 能撑到 ~4.5 秒），勿靠缩小 `zoom` 拉长。

### 2.7) 画面抖动专项（踩过，别再踩）

🔴 **推近不得用「按目标尺寸直接 zoompan」**。`zoompan` 的裁剪窗口只认整数像素，
768 宽的媒体区做 5% 推近时单帧位移只有 0.4 像素，结果就是「有的帧完全不动、有的帧跳一整像素」，
24fps 下肉眼就是抖动。实测逐帧差异在 `0.02 ↔ 2.5` 之间来回跳（0.02 = 那一帧没动）。

现行做法：**放大 4 倍进 zoompan、输出 2 倍、再 lanczos 降回目标尺寸**（`FRAME_SS=4` / `FRAME_ZOUT=2`），
单帧位移落到亚像素级，逐帧差异收在 `0.7 ↔ 1.3`（没有冻结帧）。改这段代码时勿图省事把倍数调回 1。

**光靠超采样还不够**：一段 7 秒的镜头，5% 推近摊到 168 帧，每帧只走 0.2 像素，取整后还是会跳。
所以再加一条**推近速度下限**（`ZOOM_MIN_STEP=2.2`）：推近固定在 3 秒内走完、之后保持静止，
见 2.66。两条一起才彻底干净。

另外几条：
- 静图输入一律带 `-framerate <fps>`，别让图片解复用器默认 25fps 跟输出 24fps 打架。
- 段内多图时，转场帧是整幅移动（差异值 20~40），别把它当成抖动——**看静止段的逐帧差异**才准。
- 自检命令（差异值应稳定在 0.7~1.5，出现 0.0x 就是还有冻结帧）：
  ```bash
  ffmpeg -hide_banner -ss 3.0 -t 2 -i 成片.mp4 \
    -vf "crop=768:440:0:420,tblend=all_mode=difference,signalstats,\
  metadata=print:key=lavfi.signalstats.YAVG" -f null - 2>&1 | grep -o "YAVG=[0-9.]*"
  ```

### 3) 动画与换页

- **硬切**：`fade` 给 0.1~0.15。参考片绝大多数是硬切，长淡入反而像 PPT。
- **中区缓慢推近**：`--zoom 0.05`（5%），全片有呼吸感；`contain` 模式自动关闭推近（会把补边一起放大）。
  推近走「4 倍超采样 + lanczos 回降」，直接按目标尺寸 zoompan 会抖，见 2.7。
- **壳不动 → 不需要页内动画**，`anim` 保持 false。

### 4) 音频

平速 `speed: 1.05`，讲解口吻（勿快嘴 1.12，塞不进 3~5 秒的换图节奏）。

### 5) 字幕（这个模板专属参数，preset 已带）

```bash
--sub-bottom 455 --sub-size 46 --sub-color "#FFD84D"
```

| 参数 | 为什么 |
|---|---|
| `455` | 字幕压进**媒体区内侧下沿**，不是贴画面底部（贴底会掉进底部黑带里）|
| `46` | 媒体区只有 440 高，默认 36 太小 |
| `#FFD84D` | 黄字 + 黑描边，压在写实图上比默认暖白更醒目 |

🔴 **花字与字幕的间距**：`.fr-ov` 固定在中区底部往内 112px，字幕在媒体区底部往内约 35px。
改花字位置时别往下压，两层会叠在一起（踩过）。

### 6) 封面

第 1 段仍是封面：`"anim": false` + `overlay` 放大字，或直接给一张满屏封面图当 `media`。
封面素材建议单独做（参考片的封面是二次元插画、正文是写实剧照，两者风格不必统一）。

## 模板：左中右分栏（`trio`）

> **和上中下分栏是同一族**：壳元素完全一样（两行标题 / 品牌落款 / 中区花字），
> 换的只是**槽的形状**。写 `segments.json` 时字段可以照抄，只改 `template`。

| | 上中下分栏（`frame`）| 左中右分栏（`trio`）|
|---|---|---|
| 中间那格 | **全宽 16:9 一条横带**（9:16 画布下 1080×608）| **槽形只看槽里素材的方向**：竖素材 = **满高竖条**（y=0、高=画布高）<br>横素材 = **16:9 横带居中** |
| 上下边距 | 有（上带 + 下带）| 竖素材：**零**（视频贴住画布上下边）<br>横素材：有（居中留白，放花字）|
| 左右 | 占满全宽 | 让出两栏，**宽度可调**（`media_w`）|
| 文字放哪 | 上带标题 / 下带品牌 | 左栏竖排标题 / 右栏竖排落款 |
| 素材怎么填 | `cover`（铺满横带）| 竖素材 `height`（按高对齐、左右裁）/ 横素材 `cover`（槽已是 16:9，零裁切）|
| 适合 | 横构图素材、要露出上下包装 | 竖素材 / 人像顶天立地；**横素材时做「文字左右」那一版** |

🔴 **槽形只认「槽里素材的方向」，跟画布横竖无关**：
- 素材**竖构图**（`h > w`）→ 槽 = **满高竖条** `(x, 0, mw, h)`，配 `fit:"height"`。
  画布本身是横屏也照样满高 —— 竖素材按**画布高度**缩放，上下贴边、左右裁，
  这就是「视频上下百分之百显示」那版。
- 素材**横构图**（`w > h`）→ 槽 = **16:9 横带水平垂直居中** `(x, y, mw, mh)`，配 `fit:"cover"`，
  上下自然留出空间（可放花字，也可以纯留白）。
- 探不到素材尺寸时，才按画布方向兜底（竖画布→竖条、横画布→横带）。

最常踩的一条：**横屏画布（1366×768）+ 竖屏素材**。它不是「横带」，是 **432×768 的满高竖条**
（宽 = 画布高 × 9/16、水平居中），左右两栏各 466px 放竖排文字 —— 素材高度就**等于画布高度 768**，
一个像素都不裁。分辨率仍是 1366×768，没变。

四种组合的实际槽框（都可以直接对表核）：

| 画布 | 素材 | 槽框 | 两翼各 |
|---|---|---|---|
| 768×1280（竖屏）| 竖 | `(146, 0, 476, 1280)` 满高竖条 | 146 |
| 768×1280（竖屏）| 横 | `(146, 506, 476, 268)` 16:9 横带 | 146 |
| **1366×768（横屏）**| **竖** | **`(466, 0, 432, 768)` 满高竖条** | **466** |
| 1366×768（横屏）| 横 | `(204, 114, 956, 538)` 16:9 横带 | 204 |

所以同一份 `segments.json` 换 `--size 横屏` 字段一个不改，槽形按素材自己走。

🔴 **横屏素材有两种布局，按内容挑**：

| 想要 | `template` | 结构 |
|---|---|---|
| 文字**上下** | `frame` | 上带标题 + 16:9 中区 + 下带品牌 |
| 文字**左右** | `trio` | 16:9 中槽居中 + 左右两栏竖排文字 |

不想每次挑就写 `template: "auto"`：管线读第一个素材的方向，竖→`trio`、横→`frame`。

### 1) 版式字段

```json
{ "template": "trio",
  "fields": {
    "media": "素材/人像.png",
    "media_w": 0.62,
    "overlay": "满高贴边",
    "overlay_pos": "bottom"
  } }
```

| 字段 | 说明 |
|---|---|
| `media` | 中槽素材：单张 / 一叠 list（段内轮播）/ `{"page":…}` 网页槽 / 视频片段 |
| `media_w` | **中槽宽占比** 0.30~0.92（认 `0.62` / `"62%"` / `62`）。越大中槽越宽、两栏越窄。默认值按「画布 × 素材」四档：竖画布 `0.62` / 横画布+横素材 `0.70` / **横画布+竖素材 = `画布高×9/16÷画布宽`**（1366×768 下 0.3163 → 槽宽 432）|
| `media_fit` | **竖素材默认 `height`**（满高居中，上下零边距）；**横素材默认 `cover`**（铺满 16:9 槽）。显式写就按写的来 |
| `media_portrait` | **手动指定槽里素材的方向**，覆盖自动探测：`true` / `"竖"` / `"portrait"`，或 `false` / `"横"` / `"landscape"`。素材是合成图、探不到真实构图时用 |
| `overlay` / `overlay_pos` | 中槽花字；`bottom`（默认）/ `mid` / `top` |
| `title1` / `title2` | 左栏两行竖排大字（白 / 黄，粗描边）—— 写顶层 `trio` 里可全片复用 |
| `logo` / `logo_img` / `tagline` / `slogan` | 右栏竖排落款，缺省取本品牌固定值 |

壳参数（title / logo / tagline / slogan）和上中下分栏一样写**规格顶层**，管线自动合并进每段：

```json
{
  "theme": "深夜蓝金",
  "trio": { "title1": "一个人", "title2": "干一个团队" },
  "segments": [
    { "slug": "cover", "text": "……", "template": "trio", "anim": false,
      "fields": { "media": "素材/人像.png", "overlay": "满高贴边" } },
    { "slug": "wide", "text": "……", "template": "trio",
      "fields": { "media": "素材/工作台.png", "media_w": 0.72 } }
  ]
}
```

### 2) 槽宽怎么选（`media_w`）

两栏宽度 = `(1 − media_w) / 2`。竖排标题是两列，所以栏宽必须够放两列字。

**A. 竖素材（满高竖条）** —— 槽高恒等于画布高，`media_w` 只决定**槽宽**：

| 画布 | 默认 `media_w` | 中槽 / 两翼各 | 说明 |
|---|---|---|---|
| 768×1280 | `0.62` | 476×1280 / 146 | 竖屏标准档，两翼够放两列标题 + 三列落款 |
| **1366×768** | **`0.3163`**（自动）| **432×768 / 466** | 槽宽 = `画布高×9/16 ÷ 画布宽`，正好等于 9:16 素材在 768 高下的原生宽度，**零露边、零裁切** |
| 1366×768 | 手调 `0.45` | 615×768 / 375 | 槽比素材宽 → 素材居中、两侧露底色。想让画面更大就把 `media_w` 往默认值靠 |

🔴 竖素材下 `media_w` 超过「素材原生宽 ÷ 画布宽」只会加宽槽、不会放大画面
（`fit:"height"` 按高度锁死，宽度由素材比例定），多出来的部分是底色，不是画面。

**B. 横素材（16:9 横带）** —— `media_w` 决定槽宽，槽高由 16:9 反推（`mh = mw × 9/16`）：

| `media_w` | 768 画布下中槽 / 单栏 | 1366×768 下中槽 / 单栏 | 适合 |
|---|---|---|---|
| `0.50` | 384×216 / 192 | 683×384 / 341 | 文字为主、中槽只做点缀 |
| `0.62`（竖画布默认）| 476×268 / 146 | 847×476 / 259 | 竖排两列标题 + 三列落款，最稳的一档 |
| **`0.70`（横画布默认）** | 538×303 / 115 | **956×538 / 205** | 横屏标准档，中槽正好 16:9 且与上中下分栏同宽 |
| `0.72` | 552×311 / 108 | 983×553 / 191 | 画面为主，标题要短（≤5 字） |
| `0.80`+ | 614×345 / ≤77 | 1093×614 / ≤136 | 极限档，两栏只够放一列字 |

🔴 字号会随栏宽自动缩（`clamp` 兜住上下限），不用手调；但栏太窄时两列标题会挤，
所以 `0.75` 以上建议 `title1` / `title2` 各控制在 4~5 字。

🔴 横素材给到 `0.92` 这种极限值时槽高会超出画布，代码会反过来按高度收宽度，比例始终不破。

### 3) 动画 / 音频 / 字幕

- **动画**：`anim: false`（壳是静态包装，跟 `frame` 一样不进动画）。
- **音频**：`--preset 左中右分栏`（或 `左中右`）自动带 `--speed 1.05 --fade 0.15`。
- **字幕**：竖屏 `sub_bottom 96`（中槽满高、贴底留 7.5%）；**横屏自动改算** ——
  位置交回 `sv_media` 按中槽下沿 + 16 算（横素材 1366×768 → 132），字号按画布高度等比缩（44 → 26），
  因为竖屏那套值在 768 高的画布上会掉出中槽。
  **横屏 + 竖素材**时中槽满高、没有下边距可借，字幕贴画布底 7.5%（768 下 = 58）。
- 🔴 **`--zoom` 必须 0**：中槽满高时推近会裁掉上下，直接毁掉「视频上下百分之百显示」。

### 4) 三条硬规矩

1. **「上下零边距」只属于竖素材**，不是整个版式的可选项 —— 竖素材一律走 `fit:"height"`，
   写成 `cover` 只在「槽比素材窄」时等价，槽一调宽就会裁上下。
   横素材反过来：槽本身就是 16:9，默认 `cover` 铺满才对。
2. **中槽宽度只改 `media_w`**，勿改 CSS 里的 `--tr-mw`；槽位坐标只从 `trio_box()` 取。
3. **槽形跟着槽里素材走，勿手写坐标**：竖素材满高、横素材 16:9 居中，都由
   `trio_box(w, h, media_w, portrait_media)` 按素材方向算 —— 换 `--size` 不用改任何字段。

## 封面（首帧即封面，二选一）

🔴 **第 1 段一律加 `"anim": false`**（静态渲染、不生成帧序列），保证第一帧就是一张设计好的完整封面。

🔴 **封面胶囊（`chapter`）写内容属性**：按第 1 句钩子定一个内容属性词，如
「观点 / 问题 / 见解 / 痛点 / 结论 / 干货 / 避坑」（可带主题，如「观点 · AI时代」）。

- **模式 A（默认）· 首帧当封面**：用 `marketing` 模板把第 1 段设计成完整封面海报——
  品牌胶囊 + 右上标签(`tag`) + 章节胶囊 + 大标题(`title`/`title_size`) + 副标(`hook`) + chips + 提示(`hint`)。
  **纯文字也够冲击力**（不人物、不背景图）；想更"框住"可选 `frame:true` 把文字套一层半透明圆角框
  （默认居中，`frame_top:"20%"` 可上移；`wrap_top:360` 调整文字块上边界）。
- **模式 B · 单独生成封面图**：用生图工具（`fxai-comfyui-image-gen`）先出一张漂亮、抓眼球、戳痛点的封面图，
  第 1 段 `fields` 给 `cover_image:<图绝对路径>`（图满屏裸露 + 底部暗卡放文案，遵守 `01-配图与文案.md` 的 showcase 规则）。

两种封面都要**好好设计、拿捏亮点/痛点**（数字前置、结果承诺、身份标签、紧迫感）。
动态作用于「页内元素」（分层弹入 / 高亮 / 逐条出现）；后续镜头照常动画。

## 横版（landscape）

**触发**：`slides.set_canvas(w, h)` 设成宽 > 高，或 `fields.layout="landscape"` 强制。

🔴 **分辨率规则**（`--size` 预设，别每次手算）：

| `--size` | 尺寸 | 比例 | 什么时候用 |
|---|---|---|---|
| `竖屏`（默认）| 768×1280 | 3:5（1.667）| 不写就是它。**全项目历史基准，勿改** |
| `竖屏1366` | 768×1366 | 9:16（1.7778，差 0.02%）| 想要「768 边 + 精确竖屏比例」时用这档 |
| `竖屏高清` | 1080×1920 | 9:16 精确 | 要平台原生竖屏、要上大屏 |
| `横屏`（横屏默认）| **1366×768** | 1.7786 | 横屏成片的标准档：高度正好 768 |
| `横屏小` | 1280×720 | 16:9 精确 | 720p 标准档，兼容性最稳 |
| `横屏高清` | 1920×1080 | 16:9 精确 | 1080p 交付 |

也可以直写 `--size 1600x900`，或 `--w`/`--h` 单独覆盖（只给一边时另一边按预设比例补齐）。
同一份 `segments.json` 任意画布通用，换尺寸不用改字段。

🔴 **768 高凑不出精确 16:9**：`768 × 16 ÷ 9 = 1365.33`，没有整数解。取 **1366×768** 是因为
它高度正好 768、宽高皆偶数，比例与 16:9 只差 0.05%（16:9 素材铺进去上下各裁 0.4px，等于零裁切）。
竖屏同理：**768 宽凑不出精确 9:16**（`768 × 16 ÷ 9 = 1365.33`），取 **768×1366** 当 `竖屏1366` 档。

🔴 **`1344×768` 不是 16:9**，是 **7:4**（1344 宽若按 16:9，高应是 756）。那是 SDXL 出图的
常用横版尺寸，**别拿来当视频标准** —— 16:9 素材进去左右各被裁 0.8%。

| 模板 | 横版布局 |
|---|---|
| `marketing` | 左右分栏：左栏=品牌/章节/标题/副标/胶囊/提示，右栏=流程/UI/步骤/配图 |
| `outfit` | 左图右文（图 `cover` 满屏裸露 47% + 暗卡列单品 53%）|
| `product` | 左图右文，但图走 **`contain`**（55% 左半屏、四周留呼吸位）+ 右卡列规格（45%）—— 包装/标签不裁 |
| `frame` / `trio` | 见上文「左中右分栏」章：槽形看素材方向，不看画布 |

横版页面按实际 w/h 出图，宽度用 `%` / `vw`，不写固定像素 max-width；
**盒子**宽高/内距用 vh/vw 随视口缩放，固定元素用注入的 `--s` 缩放因子定位；
但**字号是固定 px**（见上文「横版的字号是固定 px」那一节），不跟 vh 缩。
