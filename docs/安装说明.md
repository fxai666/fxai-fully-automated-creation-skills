### 为什么必须先读

- **这些技能不是靠记命令用，是靠说触发词用。**手册每张卡片都写了「你张口该怎么说」，照抄就行，不用背参数。
- **每个技能都有明确的边界**（它不干什么、该转给谁）。不读就会拿错技能，然后在错误的地方调半天。
- **手册第 10 节是「15 个真实的坑」**：`image/` 里放中文名图片会被安全策略拒、正文 HTML 的图片必须写绝对路径、whisper 要设 `KMP_DUPLICATE_LIB_OK`、ffmpeg 的 `fade` 必须在 `scale` 之前、整片换人的源视频不得放进分段目录……**每一条都是真踩过的**，提前看能省几个小时。

## 〇、先读这一节：本包技能是「缩影 + 按需」结构

安装者（人或 AI）请先记住一件事，否则用起来会以为技能"写漏了"：

> **每个技能目录下 `SKILL.md` 只是缩影（入口 + 铁律 + 命令速查），细节在同级 `references/` 里，用到才读。**

三层加载，别一次性全读：

| 层 | 在哪 | 何时加载 | 体积 |
|---|---|---|---|
| L1 | `SKILL.md` 顶部 `description` | 常驻，只决定这次该不该命中 | 几十字 |
| L2 | `SKILL.md` 正文 | 命中后才读 | 目标 ≤6 KB |
| L3 | `references/*.md`、`scripts/*.py` | **用到哪一册才读哪一册** | 不限 |

- **路由不依赖你的记忆或任何外部配置**：每个技能的 `SKILL.md` **顶部自带「本技能文件清单」**（列出同级有哪些文件、各自什么时候读）。流程是：命中 → 读清单 → 判断这次要读哪几册 → 只读那几册。初次安装、没有任何历史记忆也能照着走。
- L2 里的每条索引都写了**触发条件**（"要发图集时 → 读 `references/newspic.md`"）。看到这种指针就去读对应文件，细节以被指的那一册为准。
- 带 🚨/🔴 的硬约束**永远在 L2 里**，不会被拆走，必须照做。
- ⚠️ **复制技能时必须整个目录一起复制**（含 `references/`、`scripts/`）。只拷 `SKILL.md` 会让技能"看着能跑、实际缺细节"。

**样板：`fxai-mv-pipeline`**（原 93 KB 单文件，已拆成 `SKILL.md` 7.5 KB + 6 册 `references/`）。
照着它的结构看一遍就懂这套机制：L2 顶部是「铁律速查 + 文件清单」，底下按「什么时候读」分册，
18 条历史经验按主题并进各册（每条经验只落在一个册里，不单设经验册，防止内容双写）。

## 一、通用安装步骤（所有智能体通用）

1. **准备一个智能体宿主**（如尚未安装）：任何支持技能目录的智能体都行；推荐用 WorkBuddy，通过下方推广链接下载安装（含专属推广码，双方均可获得权益）👉
   <https://www.workbuddy.cn/events/invite?inviteCode=q8j94equzsvuskb>
2. **解压本压缩包**：顶层是若干「技能文件夹」（每个含 `SKILL.md`，部分还带 `references/` 细节册）加两个公共目录 `fxai-workflow`、`fxai-common`（**不是技能，但必须和各技能同级**）。读法见第〇节。
3. **复制技能文件夹**到你的智能体技能目录，二选一：
   - **用户级（推荐，对所有项目生效）**：WorkBuddy 为 `<你的用户名>/.workbuddy/skills/`；其它宿主用该宿主文档里写的用户级技能目录
   - **项目级（仅当前项目生效）**：WorkBuddy 为 `<你的项目>/.workbuddy/skills/`；其它宿主同理
   - ⚠️ 复制时**整个目录连名字一起复制**，`fxai-workflow` 和 `fxai-common` 必须与各 `fxai-*` 技能在同一层（代码按 `../fxai-workflow`、`../fxai-common` 相对路径找它们）。
   - ⚠️ **`fxai-common` 漏了会直接崩**：所有走 ComfyUI 的技能都 `import fxai_common`，缺了就是 `ImportError`，一调就报错。
4. **重启 / 刷新智能体**，让技能被加载（WorkBuddy 看左侧「技能」里有没有；其它宿主看它自己的技能列表，或直接问它「你装了哪些技能」）。
5. 按「二 ~ 四」装好环境即可：安装时由安装者告诉你装在哪个盘 + 数据目录名固定为 `fxaitool`，技能照配置里的实际值自动命中（详见下方「三、目录约定」），无需任何手动配置。
6. **按开头「装完第一件事」的路由表读对应文档，再开始操作。**手册与 `合规使用边界.md` 是第一次动手前必读的两份，**这一条是硬要求**；合规细则按路由表去对应文档查，本文件不展开。

### 目录约定（数据目录名固定，安装目录是默认名）

| 目录 | 名称 | 装在哪 | 里面有什么 |
|---|---|---|---|
| 软件安装目录 | 默认 **`fxai`**，**用户可改名** | 某个盘的根目录下，如 `<盘>:\fxai` | ffmpeg（带 libass / arnndn）、`model.rnnn`、conda 环境 |
| 数据目录 | **`fxaitool`**，**固定不改** | **某一个盘**的根目录下，如 `<盘>:\fxaitool` | 模型缓存、其它数据与缓存 |

- 数据目录这个**名字是死的**（写错就找不着），按它逐盘扫；软件安装目录是**装的时候选的默认名，用户可能改过**，以配置里 `software_install_dir` 那条实际值为准，别去猜默认名。

- ⚠️ 两个目录**可以提供不同的盘**（例如软件装在其中一个盘、数据在另一个盘），不强制同盘，所以代码是各盘分别扫。

### 安装时采集本机数据，写进全局配置

## 五、关键参数约定

1. **视频最大边长封顶 1300**（出片最长边 1280）；生图 1080×1920 / 1440×1920；生图与视频尺寸独立。
2. **音频分段**用精确公式（默认每段约 9.41667s）；音乐节点 `seconds` 必须保持对上游输出的链接，写死会报
   `YuE2 latent duration must match the seconds output of YuE2 Text Encode`。
3. **多参考模式场景图必须是空镜不含人物**，人物靠四视图参考图在 MV 阶段注入；`img` 只写环境，人物动作写 `act`。
4. 工作流里的占位符是 `fxai_audioinput`（输入音频）/ `fxai_outputdir`（输出目录），改错名提交会被拦下。
5. 服务端保存的人声文件名是 `<序号>_audio.wav` 而不是 `人声.wav`，必须按返回的令牌下载再改名，硬拼会 404。
6. ffmpeg 必须带 libass（conda 自带的不带，中文会烧成豆腐块）；换字幕样式只改 ASS 头，whisper 保持上次结果直接复用。
7. 场景图数量：时间规则只是**下限**，场景素材里规划了几张就出几张。

完整字段含义见 `环境配置.md` 第三节。

## 六、配置完毕，先跑一次「一分钟验证」

环境配好之后**别急着做完整作品**——先用一小段素材把整条链路跑一遍，确认 ComfyUI、音乐、出图、出片、字幕每一环都通，
再投入正式创作。一次验证的全部素材就是「**一首一分钟的歌 + 一支一分钟的片**」，代价最小、覆盖面最广。

### 验证 1：一首一分钟的歌（跑通音乐链路）

- **歌词写 5～6 句**：一段主歌 + 一段副歌，用 `[Verse]` / `[Chorus]` 分区。**就这五六句，出来差不多就是一分钟**。
- **不用设时长**：时长交给歌词，五六句歌词自然就是一分钟上下，别去改最大时长参数。
- **风格（Style）写一句人话**：如「温暖的流行中文歌，女声，钢琴铺底，节奏舒缓」。
- **通过标准**：拿到 `.wav`，能播放、唱的是你写的那几句、结尾没有被截断。

### 验证 2：用这首歌出一支一分钟的片（跑通出图 → 出片 → 拼接）

- 直接把上面那首歌喂进去。**有人物参考图就走多参考（默认，一致性最稳）；没有就走单场景**，先别碰多场景。
- 一分钟音频按 MiniMax H3 的精确公式切成 **7 段**（每段约 9.42 秒），对应 7 张场景图——段数由工具自己算，不用你数。
- **通过标准**：产出 `成片_768x1280.mp4`，能播放、人物在画面里、段数对得上。
  🔴 **必须抽帧目看一眼**（每段中点一帧），日志报 success 不算通过。

### 验证 3（可选）：一分钟数字人口播

- 口播文案 150～200 字（约 60 秒）即可，先选一个现成模板（走动式 / 坐姿式）跑一遍。
- **通过标准**：数字人出镜、口型对得上、字幕**不是豆腐块**（出现豆腐块 = ffmpeg 缺 libass，见第五节第 6 条）。

### 三轮都过，再上正式作品

- 之后再做完整歌词、多场景、长视频；**短剧链路更重**（剧本 → 分镜 → 多角色），建议放在上面都通过之后。
- 卡住了先看是不是 ComfyUI 没起来（本机 8188 探不通就走云端，或先把控制台/启动器开起来），
  再把**报错原文 + 卡在第几个环节**发到 QQ 群；想省时间也可以联系凤希AI做有偿部署。

## 八、以后怎么升级（一句话搞定）

包里带了 `fxai-auto-update`（技能包自动更新器）。装好之后 **不用再去官网重新下载安装包、也不用口令激活**，
在你的智能体里直接说一句话就触发：

> **「检测有没有新版本」** ／ **「更新新版本」** ／ 「更新技能包」 ／ 「升级技能」 ／ 「有没有新版本」 ／ 「拉最新版」

就这几句，说哪句都行。它会先告诉你「官网版本 vs 你本机版本」，你点头才更新。

它去官网读 `https://www.fxai.site/upgrade/skill.json`（里面就两项：版本号 + 压缩包的相对路径），
把官网最新那个 zip 拉下来、解压后逐文件比对落盘。整个过程是：

1. **先报版本**：告诉你「官网 `1.3` vs 本机 `1.2`」，由你决定升不升，不会自作主张；
2. **只动有变化的文件**：内容一致的直接跳过；
3. **你自己改过的文件不会被覆盖**：这类文件会单列出来，由智能体读「基线 / 本地 / 上游」三份做合并，合并完才落盘；
4. **可回滚**：落盘前自动备份旧文件，一句「回滚技能」退回备份版本；
5. **不留垃圾**：只在你用户目录下留三处记录（版本状态 / 基线副本 / 备份），不往技能目录写任何运行产物。
6. **专家一起管**：整包附带的「凤希AI技能包管家」是专家、不是技能，会装进宿主的专家市场而不是技能目录。更新时如果没装、版本旧了或市场清单没登记，会自动补齐；也可以直接说「检查专家装没装」「把专家也装上」。

**从 1.6 首次升到 1.7 的特别说明**：那一次执行更新的是旧版更新器，它不认识包里的 `专家包/`，
所以**专家不会被自动装上**。更新完成后补一句「把专家也装上」，或跑：

```bash
python skills/fxai-auto-update/scripts/update.py expert --install
```

再用 `python skills/fxai-auto-update/scripts/update.py expert --check` 判定，输出「判定 ok」即通过。
旧版脚本可能把 `专家包/` 平铺进技能根，那只是残留文件、不是安装位置（专家中心看不到），不必删。
这次补完之后，再升级都由新版更新器自动补齐。手动安装细则见包内《智能体安装规程》§3，
版本变更与全局配置采集见包内《更新日志》V1.7「升级到 V1.7 必读」。

> 官网域名默认取品牌官网 `www.fxai.site`；若要换，在 `~/.workbuddy/fxai_global.json` 里加 `update.site` 即可。
> 同一版本号若做了文档补包，`skill.json` 的 `sha256` 会变，更新器会按「同版本内容有更新」重新拉一次，不用等下个版本号。
