## V1.8 · 2026-11-08（同版本补包）

> 版本号仍是 `1.8`，只补内容。客户端按包的 sha256 变化判定「需要重新下载」，覆盖同名包即可。

**本次相对 2026-11-07 版的新增 / 变更：**

- **`fxai-auto-publish` 新增 12 册「文章类型发布链路」**：文章类（`article`）从建任务到回执的完整口径——文章确认后**直接发布**，只有公众号进草稿箱；正文注入四种方式的取舍（导入 `.md` / 剪贴板粘贴 / `execCommand insertHTML` / 直接填），并写明 Draft.js、ProseMirror、Lexical 这类**受控编辑器只改 DOM 不进内部状态**，必须走 paste 事件；封面两种结构（页内 file input、弹窗式上传）；CSDN / 百家号 / 知乎 / B 站四站实测手法、坑与动作台账回写做法；跑完必核的四件事（公开链接、封面是否生效、审核态、重复发布核对）。
- **`fxai-auto-publish` 新增 13 册「标题与详情生成规范」**：标题与详情分 `tech` 技术向 / `mass` 大众向两档。`tech` 技术名词前置、可写实现；`mass` 走娱乐化钩子，标题与详情**不得出现技术名词、制作过程、参数与资源链接**，按正常作品发布。档位取实例目录站点条目 `copy_profile`（类型层可覆盖），**未标注一律按 `mass`**。两档都保留 AI 生成显式标识——这是合规红线，不属于「技术描述」，不得借「不写技术」删掉。册内含三写 / 四不写、公共文案块按档位收口（`footer_in_desc` / `common_block`）、出单前逐站自检清单、违规处理与改写对照。
- **文案档位前置到发布物料与执行 SOP**（05 / 08 / 09 / 10、`SKILL.md`、`templates/发布单.md`、`scripts/init_hub.py`）：标题 / 简介先定档再落笔再自检，未过自检不出单、不建任务；发布单模板加「文案档位」行与自检勾选项；成熟阶段清单逐站记实际档位，便于回执与复盘核对口径。10 册补两条判据：凭导航菜单 / 内容列表的类型名建键会造出地址恒空的虚格，只有真的打开过该类型投稿页并看到对应媒体上传控件才算「确实支持」；「不建键」的两种理由（找不到入口 vs 业务当下不需要）要分开写进 `notes`，不得把业务决策写成平台不支持的事实断言。`init_hub.py` 生成的接入清单同步加档位与建键判据。
- **`fxai-standard` 新增「成片品牌标识」通则**：所有成片画面右下角常驻一枚半透明圆角角标，文案取全局配置 `brand.ai_mark_text`（当前 `凤希AI生成`）。这是**品牌植入位**，不得改写成「AI 生成」「AI」等通用文案，不得省略，也不得只写进简介而不上画面；位置、尺寸、交付清单写法与「配置读失败兜底同值」一并写入 01 册。`fxai-face-edit/references/07` 补本机实现（PIL 现生成、合成与帧率规整同一次 ffmpeg）。
- **`check_standard.py` 放行系统目录子路径**：`C:/Windows/...`（字体目录等 OS 定义路径）不再判为「本机绝对路径」；此前只放行 `C:/Windows` 根目录本身，写到具体字体文件即报 ERROR。
- **手册母版补 `fxai-auto-publish` 卡片**：第六摊「规范与复盘」补该技能卡与摊头计数，第五摊计数按实际修正；`make_manual.py` 修掉「表格 + 卡片混排的摊只按表格计数」导致摊头与首屏技能数少 1 的问题（第五摊）。
- **`fxai-auto-publish` 更名为 `fxai-browser-publish`**：两条发布通道要能一眼分开——`fxai-browser-publish` 走选择器 / 无头通道，`fxai-physical-publish` 走系统级鼠标键盘。同步改名：包内 `SKILL.md`、`references/02`、`scripts/init_hub.py`、`scripts/resolve_hub.py` 的 `SKILL_NAME`、`~/.workbuddy/fxai_global.json` 的 `publish_hub.skill`、`skills/SKILL.md`、`安装说明.md`、`环境配置.md`、`README.md`。既有实例目录里 `hub.json` 的 `skill` 字段若仍是旧名**不影响使用**（只作标注），想统一就手改。
- **新增 `fxai-physical-publish`（物理仿真发布）**：用 `SendInput` 真实驱动鼠标键盘操作浏览器窗口，零注入、零 CDP、零 cookie、零登录态；区域坐标录一次固定，轨迹与停顿每次重抽。节奏按「动作语义」调度——连贯动作用 0.04~1.8s 的间隙，只有「要看 / 要找 / 要想」才用 0.5~120s 长尾停顿，**不做每步必停**。手册第六摊补该技能卡、附录速查表补一行，首屏与正文技能数 40 → 41。

### 升级到本补包必读

## V1.8 · 2026-11-07

**本次相对 V1.7 的新增 / 变更：**

- **新增技能 `fxai-auto-publish`（自动发布）**：把项目目录里的最终成片配上封面 / 标题 / 简介 / 标签与 AI 标识，出发布单、人工确认后发到各内容平台，发布回执写回项目目录。技能内是**实现规范**（11 册 + 3 模板 + 初始化与寻址脚本）：发布通道选型、实例目录初始化、接入未配置站点、多账号与凭据隔离、发布物料与发布单、回执规范、站点操作路径台账、确认后执行 SOP、内容类型路由与登录兜底。包内零站点名称、零域名、零选择器、零账号、零凭据。
- **`fxai-face-edit` 补三条工作流**：① **全场景替换**（保留原片动作 / 机位 / 事件，换场景与画面内容）；② **主体替换**（只换主体，动物与物体同口径）；③ **指定人物删除**（抹掉画面中某一位人物）。同步补主体替换 / 全场景替换提示词素材、纯器乐配乐 caption 素材，以及交付对比片脚本 `make_compare.py`。

- **合规文档成体系**（`fxai-share-skill-package`）：新增 03 合规分发规范（打包器侧门禁与放行判据）、合规使用边界、字体与素材授权台账、已知合规缺口清单。

- **旧版本机发布能力并入 `fxai-auto-publish`**：早期本机发布技能停用留档，不进公开包（目录名不带 `fxai-` 前缀，出包器不扫）。

- **安装文档表述通用化**：`安装说明.md` / `环境配置.md` 的安装步骤不再把本包写成某一家的专属技能，改为「所有智能体通用」——技能按通用技能规范组织（目录 + `SKILL.md` + 按需加载的 `references/`），任何能读技能目录、能执行本机命令、能读写文件的宿主都能装；原有 WorkBuddy 路径作为示例保留，换宿主只需替换技能目录。

### 升级到 V1.7 必读（尤其是从 1.6 升上来的用户）

1. **第一次从 1.6 升上来，专家不会自动装好**。那次执行更新的是旧版更新器，它不认识包里的 `专家包/`。
   更新完成后补一句「**把专家也装上**」，或直接跑：

   ```bash
   python skills/fxai-auto-update/scripts/update.py expert --install
   ```

   判定装好没装好：

   ```bash
   python skills/fxai-auto-update/scripts/update.py expert --check
   ```

   输出「已安装 V1.1.0、市场登记 True、判定 ok」即通过。旧版脚本可能把 `专家包/` 平铺进技能根，
   那只是残留文件、**不是安装位置**（专家中心里看不到），不必删，也别当成已经装好。
   这次补完之后，再升级都由新版更新器自动补齐，不用再管。手动安装细则见包内《智能体安装规程》§3。

2. **本机数据写进全局配置**：本版起技能里不再写死解释器、Logo / 图标、字体目录等本机路径，
   统一读 `~/.workbuddy/fxai_global.json`。新装或首次升到本版，按《安装说明》「安装时采集本机数据」
   一节把 `python_exe` 与 `brand` 段采一遍（一键 `global_config.py --init`）；不填也能跑，
   技能会回退到系统通用值，只是品牌素材可能取不到。真实路径只存你本机，**包里只有空模板**。

3. **已经装了 1.7 的用户**：本版若做同版本文档补包，官网 `skill.json` 的 `sha256` 会变，
   更新器识别为「同版本内容有更新」，说一句「更新技能包」就会重新拉一次，不用等下一个版本号。

4. **边界**：更新器不覆盖你自己改过的文件（这类文件走三方合并）；专家不进备份、也不参与「回滚」。

**本版包内包含（39 个技能 / 公共目录 + 1 个专家包 + 5 份文档，含技能操作手册，可独立使用）**
