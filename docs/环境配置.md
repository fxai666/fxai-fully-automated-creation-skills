## 三、通用环境配置（所有技能共用）



### 1) 全局部署配置 `fxai_global.json`



放到用户级：`~/.workbuddy/fxai_global.json`。本文件记录机器级的「软件安装目录」与「数据目录」两个根（**由安装者在安装过程中确定，写在装机的那台机器上，不随技能包分发**）。关键字段如下（两个根通常照下面给出的默认值落位，一般不用手写）：



- `software_install_dir`：**软件安装目录**，默认目录名 **`fxai`**，在某个盘的根目录下（如 `<盘>:\fxai`），里面是 ffmpeg / `model.rnnn` / 第三方工具。**这是安装时选的默认名，用户可能改**，以这里写的值为准，别去猜。

- `software_data_dir`：**软件数据目录**，目录名 **一定叫 `fxaitool`**，用户改不了，在某个盘的根目录下（如 `<盘>:\fxaitool`），里面是数据 / 缓存 / conda 环境的根。两者**不必同盘**；取不到数据时按这个固定名逐盘扫，数据盘的位置以扫描结果为准，不按安装目录去猜。

- `comfy_url`：ComfyUI 服务地址，**默认值** `http://127.0.0.1:8188`。真正生效的是**任务里传的那台**——`comfy_client` 的接口都能收 `url=` 参数，传了就打那台；不传才回落这份配置。**不读环境变量**（`COMFY_URL` / `SHORT_DRAMA_WORKFLOW` 已废弃，写了不生效）。同一条任务 A 台生图、B 台出视频时，就靠参数分别指定。

- `whisper`：语音转写服务一组字段——`local_url`（本机服务地址，默认 `http://127.0.0.1:8185`）、`cloud_url`（线上服务地址）、`prefer_local`（是否优先本机）、`idle_timeout`（空闲多少秒卸载模型）、`timeout`。地址解析顺序：函数参数 > `prefer_local` 命中 > `cloud_url` > `local_url`。

- `rnnn_model`（可选）：人声去噪模型 `model.rnnn` 的绝对路径；缺省取 ffmpeg 同目录，无需手写。

- `workflow_dir`（可选）：自定义工作流目录，缺省用包内置 `fxai-workflow/` 的工作流 JSON。

- `workflow_models`（可选）：按任务覆盖默认模型，如 `{"vocalsep": "uvr"}`。

- `vocal_separation`（可选）：人声分离开关，默认 `true`（设 `false` 则直接用原音频做识别）。

- `ollama_url`（可选）：`http://127.0.0.1:11434`，本地大模型服务地址。

- `xgy_instance_id`（可选）：仙宫云实例 ID，**一般不用手写**——地址域名能反解出来、令牌下只有一台时也会自动选；只有多实例且要固定某台时才填（见本节 5)）。



> **读取优先级**：`FXAI_GLOBAL_CONFIG` 环境变量 → 否则 `fxai_global.json` → 否则代码默认值。

> ffmpeg / 模型 / 去噪模型的具体路径，全部由脚本按这两个根目录自动推导，**写在配置里、不写死盘符**。



### 2) 凤希AI伴侣（整合包，必装）



提供带 libass 的 ffmpeg（字幕烧录必需）。整合包装好后，按 `software_install_dir` 自动找到 ffmpeg，无需手动指定。

自查：`ffmpeg -filters | grep -w subtitles` 应能看到 `subtitles` 滤镜。



> 带 **arnndn** 的 ffmpeg 与人声去噪模型 `model.rnnn` 同样来自这个安装目录（通常在 `ffmpeg/` 下），人声分离后的二次去噪就靠它。



### 3) 语音转写 whisper（走接口 · 无需独立安装）



字幕识别所依赖的 whisper 统一走 HTTP 接口，本机服务与线上服务二选一：



- **本机服务**：在全局 `fxai_global.json` 的 `whisper.local_url` 填本机服务地址（默认 `http://127.0.0.1:8185`）。

- **线上服务**：填 `whisper.cloud_url`（如仙宫云容器地址）。

- **优先级**：`whisper.prefer_local` 为真时优先探本机服务，探不通再走 `cloud_url`。

- 本机服务是**懒加载**：首次请求才载模型，空闲 `idle_timeout` 秒（默认 30）自动卸载释放显存。



> 想自己起本机 whisper 服务，看凤希AI的相关部署视频即可；用线上服务则只需填地址，不装任何东西。



### 4) ComfyUI 服务



整合包里已带 ComfyUI 与 `fxai-toolkit` 自定义节点（提供 `/fxai/down/file`、`/fxai/tasks/result` 等 HTTP 接口）。启动整合包的 ComfyUI 即可；工作流 JSON 已随 `fxai-workflow` 内置，无需另行准备。把 `comfy_url` 指向它。



### 5) 仙宫云（可选 · 远端 GPU 自动开关机）



`comfy_url` 指向仙宫云容器（`*.container.x-gpu.com`）时，实例通常是**关机**的（关机释放 GPU 才停计费）。`fxai-workflow/xgy_guard.py` 统一管两头，所有走 ComfyUI 的技能自动生效，**你不用自己写开关机**：



- **开工前自动开机**：`require_comfyui()` 里已挂——探 `/fxai/health`，不通就解析实例 ID → `/instance/boot` → 等 `running` → 再回探一次端口（云上报 running ≠ 容器端口已通）。

- **收工前问一句关不关**：整套流程做完、准备交付那一步，`comfy_client.finish()` 会问用户两档，**由用户选**（技能自己默默关是错的做法）：

  | 选项 | 后果 |

  |---|---|

  | 释放 GPU（**默认推荐**） | 停计费、数据保留，下次要重分配 GPU + 加载镜像，**启动明显变慢** |

  | 普通关机（保留 GPU） | GPU 留着、**照常计费**，下次基本秒起（只有明确说马上接着用才选它） |

- **本机地址（`127.0.0.1`）不触发这一整套**，其它非仙宫云地址同理，一律不管不问。



**初次配置**（令牌到位之后）：



```bash

python xgy_guard.py list                 # 列令牌下「已有」的实例（ID/状态/名/容器地址），只查已有的、不新建

python xgy_guard.py use <实例ID>         # 选中的写进 ~/.workbuddy/fxai_global.json，之后固定用它

```



- 令牌在「凤希 AI → 仙宫云管理台 → 访问令牌」页生成（**不是 SSH 密码**），存本机 `sysconfig/xgy_*.json`。没令牌时自动开机那一步会停下来提示，不硬闯。

- 实例 ID 依次取：配置 `xgy_instance_id` > 地址域名反解（`abc-8188.container.x-gpu.com` → `abc`）> 令牌下已有机器的唯一那台；多台或查不到会列出来让你选，**不盲猜**。

- 技能侧**只有开关机能力，没有销毁能力**；「关机并销毁 / 销毁实例 / 储存镜像并销毁 / 销毁镜像」别自己拼 HTTP，去控制台点。

- 仙宫云凭据**只认全局** `~/.workbuddy/fxai_global.json`，技能包内不存任何凭据。

## 四、各技能要点与用法



### 0) 人物形象图（参考图）：第一次用必看



- **它是什么**：角色的「脸」。MV 里这个人长什么样，完全由参考图决定；**长相由图锁死、穿搭每首歌单独写**（穿搭写在歌曲的文本里），所以配置里不需要、也不该用文字描述五官脸型——写了会污染其它歌。

- **放哪**：服务端的 `fxai/image/avatar/` 目录下（默认女主 `fxai/image/avatar/000.png`、男主 `001.png`）。

  - ⚠️ 这个目录在**服务端**，不一定是你本机硬盘上的某个文件夹。**ComfyUI 通常装在另一台机器 / 云端 GPU 上**，本机没有、也翻不到是正常的。

- **形象图不用你自己传**：直接跟 AI 助手说一句「准备人物形象」，它会先去服务端查一眼缺不缺，**缺了会先问你要女主图 / 男主图**——你发图给它就行（正脸、胸口以上、光线均匀、不戴墨镜口罩帽子遮脸的清晰人像；用你自己创作的角色形象，**禁用他人肖像**）。图到手后它负责传上去并登记好配置，然后你再开始做 MV。

  - 想自己传也行：图片传到服务端的 `fxai/image/avatar/`，名字用 `000.png`（女主）/ `001.png`（男主），纯数字三位数补零、`.png`；然后在**音乐工作区根目录的 `config.json`** 的 `characters` 里登记 `"女主": { "ref_image": "avatar/000.png", "type": "face" }`。

- **⚠️ 图没传好不会报错**：参考图漏传时**不会停、不会报错**，只表现为「生成出来的人长相漂移」。所以助手开工前会先查一眼再问你要，不会拿默认图或别处的图顶替。

- **换人 / 换形象**：跟助手说「换个女主形象」，把新图发它即可，它自己会换掉配置里的 `ref_image`。**全程不用改任何代码**。



### fxai-vocal-separate（🆕 人声分离 + 神经网络去噪）

- 调用：`separate_vocals(audio_rel, out_dir, model=None)`；CLI：`python separate_vocals.py <音频> <输出目录>`（分离+去噪）、`--denoise <音频> [输出] [mix]`（只去噪）。

- 流程：服务端 `Mel-Band RoFormer` 工作流分出人声 → 下载到本地 → 本地 ffmpeg `arnndn`（RNNoise 神经网络）二次去噪。

- 模型与位置：节点 `ComfyUI-MelBandRoformer`、模型 `MelBandRoformer_fp32.safetensors`；去噪模型 `model.rnnn` 取 ffmpeg 同目录（可用 `rnnn_model` 覆盖）。`arnndn` 只吃 48kHz，代码已前置 `aresample=48000`。

- ⚠️ 产物命名：服务端保存名恒为 `<序号>_audio.wav`，**不叫** `人声.wav`；下载后落地再改名。下载一律用 `/fxai/tasks/result` 返回的令牌，勿按文件名硬拼令牌。  <!-- std:allow -->

- 输入两种都吃：本地音频先上传服务端再分离；服务端相对路径直接用。**本地已有人声则跳过分离、只走去噪**。

- 被 `fxai-mv-pipeline` 在歌词识别前自动调用（1.4/6 步），开关 `vocal_separation`；也可单独对任意音频用。



### fxai-mv-pipeline（MV 主管线）

- `produce_song.py`：两段式——`--phase music`（出音乐 + 歌词对齐 + 分镜剧本草稿）、`--phase render`（读分镜 → 出图 → MV → 烧字幕）。

- `lyrics_align.py`：三版硬切 + 行级多数簇表决的对齐引擎；`mv_pipeline.py`：各 `gen_*` 函数与 ComfyUI 状态检测；`setup_env.py`：环境配置。

- 依赖 `fxai-workflow` 工作流与 ComfyUI。



### fxai-yue2（歌曲）

- `gen_song.py`：风格(Style) + 歌词(Lyrics) → 中文歌；支持 Full / Melody / Off 规划模式。



### fxai-comfyui-image-gen / fourview-gen / scene-gen（绘图）

- 一律用**自有角色参考图**，禁用他人肖像（IP 保护）。四视图建形象、场景图搭环境。

### fxai-h3-video-prompt

### fxai-poster（海报与图片设计 · 🆕）

- 三种模式：**web**（HTML/CSS 排版 → 浏览器截图，文字精确）、**image**（委托 `fxai-scene-gen` 生图，画面质感）、**hybrid**（生图做底图 + 网页叠字，既要质感又要中文）。判定：要中文排版就离不开网页层，要真实质感就离不开生图层。

- 用途：视频封面（口播/短剧/MV 首帧）、海报、广告图、图文卡片。产物 PNG 既可进交付清单，也可直接铺到视频首帧（见 `references/04-接入视频首帧.md`）。

- 依赖（本技能不写死任何路径）：浏览器走 `fxai-slide-video` 的 `gpu.chrome_exe()`、ffmpeg 走 `fxai-audio-video` 的 `av.ffmpeg_libass()`、ComfyUI 寻址走 `fxai-workflow`、生图委托 `fxai-scene-gen`。

- 硬规则：尺寸一律引用 `fxai-poster/cover_sizes.json` 的 key，默认只出 `vert_9x16` (1080×1920) + `horiz_16x9` (1920×1080) 两张（旧 `768x1280` / `1280x768` 已废止）；截图/ffmpeg 临时文件落系统临时目录下的 `fxai_burn/poster/`（中文路径会让 `file://` 与 ffmpeg 滤镜解析失败）；配色只改 `themes/*.css` 的 CSS 变量，HTML 内不硬写颜色。



### fxai-content-review（内容复盘与经验库）

- 把复盘从"输出报告"变成"往台账记一笔"：SQLite 是唯一真相源，经验库_领域.md 是其只读投影。

- 命令：`python db.py exp add --领域 文章 --分类 钩子 --关键词 开头利益 --结论 "…" --证据 "…" --动作 "…"` 记一笔（同类问题按 `领域|分类|关键词` 指纹累加次数，≥2 即顽疾）；`exp export` 按领域生成 经验库_领域.md；`exp promote --id N` 把反复命中的经验晋升为规则写入 已沉淀规则.md。

- 领域即岗位（通用/文章/口播/视频/素材/复盘），受控；标签也必须先 `tag add` 登记。库目录按 `fxai_global.json` 的 `data_dir` 定位（缺省落工作区 `_fxai_data`），不进技能目录。



### fxai-standard（通用标准规范 · 写 / 改技能用）

- 纯文本规范 + 一个体检脚本：不碰 GPU、不改用户内容，装完即用。其他技能里只留一行指针（如「通用法则见 fxai-standard 硬规则 6」），规则全文都在这册。

### fxai-face-edit（人脸替换 / 修复 / 增强 / 整片换人 · 🆕）

- **三条链路，先按「做什么」分派**（判断口诀：脸对、衣服别动 → 精修链；整个人换成另一个人 → 角色替换链；单张图 / 几十秒短片 → 云端）：

  | 要做什么 | 入口 | 跑在哪 | 分段 |
  |---|---|---|---|
  | 换脸 / 对嘴 / 老照片 / 单张图增强 / 抠像 | `scripts/face_edit.py` | 云端 FaceFusion REST | 不分段 |
  | 整片精修（只修脸，身份与服装不动） | `scripts/face_restore.py` | 本机 ComfyUI | 10 秒 |
  | **整片换人 / 换装 / 换角色**（脸 + 发型 + 肤色 + 服装 + 配饰一起换） | `scripts/char_swap.py` | 本机 ComfyUI | 4 秒 |

- **云端链路**：先 `health` 探活（队列 / 显卡 / 磁盘）、`profiles` 看有哪几台可切，再 `run --target-file … --source-file …` 提交，本机不跑模型。地址按云商分档存在 `face.profiles.<档>`（`cloud_url` / `ui_cloud_url` / `instance_id` / `provider`），`face.active` 指当前档；**换云只加一档，不覆盖老档**。素材位：换脸 / 深度换脸必给 `--source`，唇形同步必给 `--audio` 且目标必须是视频，多人画面先 `faces` 再 `--face-pos` 指定。
- **本机精修链**：`fxai-workflow/face-restore-lite.json`（任务名 `facerestore`、模型 `lite`），核心节点 `FxAiFaceRestoreLiteV2`，超分引擎是自研 VOSR2。分段时长**固定 10 秒、全片统一口径**，结束索引在工作流里写死 `-1`。
- **本机角色替换链**：`fxai-workflow/h3-char-swap-api.json`（任务名 `charswap`、模型 `h3`），30 节点。参考角色图进 `<Picture 1>`、提示词走内置三段式模板（752 字，靠 `<Picture 1>` / `<Video 1>` 指代，**换参考图不用改提示词**），分段 4 秒。
  - 三条 LoRA（节点 2，一个 `lora_data` JSON）：`minimax_h3_ref2v_turbo_8step_768p_bf16` 1.0（8 步出片，必带）、`h3_character_swap` 1.0（**换人核心**）、`Motion_Repair` 0.45（修换人后动作发飘，纠错性质）。底座 / CLIP / VAE 复用短剧那套 MiniMax H3。`h3-人脸去油` 已从默认链路移除（属修饰不属纠错，会把皮肤抹成另一种质感）。
  - 三道后处理顺序不可颠倒：26 裁回真实帧数 → 39 `FxAiToneMatch` 影调（乘法增益）→ 28 `FxAiSeamColorMatch` 接缝（加法平移）→ 21 存盘。**影调默认 `不启用`（2026-11-01）**——背景明暗不均时增益会乱跳，段间亮度改由接缝做，只动亮度不动对比度；需要时 `--tone 增益` 打开。
  - 段间不闪的第一道保险是 11 → 14 的 `接缝首帧`（`value1`）守针，**这条线不得删**；21 的「保存后释放」恒为 true（每段存完卸模型，压显存）。
- **节点包版本**：≥ **1.1.3**（合并节点只认纯数字命名的分段，修「成片慢放 / 尾段丢失」）；≥ 1.1.1 才有影调 `[0.7,1.4]` 范围检查。
- **三个高频坑**：
  1. 源视频**别放进分段输出目录**，放 `<子目录>_src`。否则合并节点会把它当一段拼进去，`concat -c copy` 的 DTS 回退 → 成片慢放、尾段丢失（只在多段时炸，单段正好躲过）。
  2. `--end-index 0` 只跑第一段，成片只剩 4 秒；整片跑要用 `-1`。脚本有兜底：成片短于源片 95% 直接抛错。
  3. 两条本机链吃的是**服务端可读路径**（ComfyUI 那台机器上的绝对路径），不是本机客户端路径；路径错表现为 `queued` 后卡住不动。`--ref` 给本机图片会自动上传，比手写服务端相对路径稳。
- **耗时口径（整片两条链都随时长线性增长，开工前先说清）**：换人链单段采样约 10 分钟，含编解码 / 合并按 10~13 分钟算 → 20 秒片约 5 段 ≈ 1 小时，1 分钟片约 3 小时。所以**先 `--start-index 0 --end-index 1` 跑两段试片**，确认换人效果和衣服对了再整片；`--max-side 720` 能明显提速（像素数约少 55%），代价是脸和布料细节变软。**分辨率默认按显存档位**：本机 ≤16G 卡长边 960、本机 ≥24G 卡 1280、线上实例 1280；`char_swap.py` 不传 `--max-side` 即自动取档，显式传数字才覆盖。

### fxai-voiceover / fxai-voiceover-script（口播文案与配音）

- 流程：`fxai-voiceover-script` 把文案转成「用…的语气说<|endofprompt|>。<正文>」格式（每段正文 ≤ 80 字）→ `fxai-voiceover` 合成口播音频（CosyVoice3）。

- 状态码和地址写在全局 `fxai_global.json` 的 tts 一组字段里；**本机 8182 优先，没起走线上**。

- **多人同时用不用改配置**。CosyVoice 按显存开多份模型真并行（本机 3 份），千问一份模型攒批（几条合一次推理，显存不涨），whisper 一份权重开多 worker；人满进队列、任务不丢、排队时不会断连接。`/health` 的 `workers` / `free` / `queue` 能看出当前忙不忙。换声（`fxai-svc`）是刻意串行的（并发实测更慢且串音色），多人提交即排队。

- 产物落项目目录的 `music/*.wav`，并写交付清单。配音音色靠参考音频，参考音频别放技能目录（是用户素材）。



### fxai-audio-video / fxai-digital-human-video（音频驱动视频 / 数字人口播）

- `fxai-audio-video` 是公共件：音频 + 参考图 + 提示词，按 MiniMax H3 出视频，三种模式（single 单场景 / multi 多场景 / multiref 多参考），工作流用 `fxai-workflow/mv-minimax-*.json`。

- `fxai-digital-human-video` 站在它上面：拿 `fxai-voiceover` 产出的 `music/*.wav` 当口播音频，出数字人出镜讲话的视频。

- 音频是唱歌还是说话**与流程无关**，只有提示词措辞不同（`kind=sing` 演唱 / `kind=speak` 口播）。

- 多段音频会逐段各出一条视频再拼接，段数多时耗时长，建议先用单条跑通再上多段。



### fxai-slide-video（幻灯片口播视频 / 配图视频 · 🆕）

- 把口播文案做成「幻灯片式讲解」视频：画面一张张切换（步骤逐步展开、清单逐项点亮、对比表、流程图），声音是配音、**不是数字人出镜**。

- 链路：文案（手写或 `fxai-voiceover-script`）→ 配音（`fxai-voiceover`）→ **HTML/CSS 绘制配图 → Chrome headless 截图** → ffmpeg 拼接 → 按各段音频**精确时长**排字幕 → libass 烧录成片。

- 与 `fxai-digital-human-video` 的区别：那个是数字人出镜、吃 GPU（ComfyUI + MiniMax H3）；这个是幻灯片配图、**纯 CPU、不依赖 ComfyUI**，几分钟出片、画面里中文零错字。

- ⚠️ 依赖**本机 Chrome** 做 headless 截图；ffmpeg 与各路径均从全局 `fxai_global.json` 读（`software_install_dir` → ffmpeg、`chrome_path` → 浏览器），**不写死盘符、不扫盘**。画面统一 768×1280 竖屏 / 24fps。



### fxai-ad-video（广告片制作 · 🆕）

- 管**广告专属规范与全流程编排**：立项（片型 / 时长 / 卖点 / 渠道）→ 创意方向 → 口播稿与分镜 → 素材 → 配音与节拍 → 包装（标题卡 / 贴片 / 片尾卡 / 字幕 / 封面）→ 组装交付。画面、配音、字幕、贴片各调下游技能，本技能只规定该怎么定、怎么卡、怎么验。

- 四条路线选一条：A 产品演示（走短剧管线两镜跑法）、B 品牌蒙太奇（自家成片切片重剪，`ad_assemble.py concat` + `mix`）、C 静图运镜旅拍、D 氛围片。

- 组装与交付用 `ad_assemble.py`（拼装体检）、`ad_delivery.py`（交付清单）；混排段走 `fxai-mixed-layout`，所以那个公共目录必须与各技能同级。

### fxai-rvc-convert（音色转换 / 换声 · 🆕）

- 前置：本机常驻服务监听 `0.0.0.0:8187`，地址读全局 `fxai_global.json` 的 `rvc.local_url`（`rvc.cloud_url` 兜底）；技能只按地址发 HTTP，**不启停服务、不占显存**，服务没起时 `health` 会直接告诉你。

- 常用子命令：`health` 探活（显存 / 队列）、`voices` 列音色、`convert` 换声（上传 → 等 → 下载）、`job` / `jobs` 查任务、`unload` 释放显存、`train` 练音色。

- 链路：上传原曲 → 人声分离 → 换音色 → 等响混音 → 下载成品；分离后端由 `rvc.sep_backend` 指定（默认 Mel-Band）。参数与听感调法见 `references/03`，训练见 `references/04`。

### fxai-video-upscale（视频超分与精修 · 🆕）

- 跑**本机 ComfyUI**：工作流 `fxai-workflow/upscale-fvsr.json`，任务名 `upscale`、模型 slug `fvsr`；依赖自研超分与人脸精修节点 / 权重，部署清单见 `fxai-xiangongyun-deploy` / `fxai-onethingai-deploy` 的模型表。

- 一条命令：`video_upscale.py <源视频> --ref <参考图> [--scale 1.5]`；脚本自己 ffprobe 源尺寸与帧率、按「单段帧数 ≤ 400」自动分段，跑完校验 MP4 完整性与成片时长，返回本机成片路径。

- 倍数额度 1.0~4.0 走公式节点（占位符 `fxai_scale`），超分与修脸共用这一个数；**精修恒在链路里，没有开关**。多人各换各的用 `--ref a.png,b.png`，只打印不动手加 `--dry-run`。
