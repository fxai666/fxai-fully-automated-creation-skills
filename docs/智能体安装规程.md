# 智能体安装规程（本文件由智能体执行，不是给人读的说明书）

> 收包方是**智能体**：请按本文件顺序执行，每步都有「判定」与「失败处置」。
> 不要凭印象改路径、不要臆造包内不存在的文件。全部命令在本包解压目录下执行。

---

## 0. 先认「宿主配置根」（后面所有路径都由它派生）

不同宿主（智能体客户端）有各自的配置根，本包**不写死任何产品目录名**。按顺序认定：

| 顺序 | 依据 | 怎么拿 |
|---|---|---|
| 1 | 宿主环境变量 `WORKBUDDY_CONFIG_DIR` | `echo "$WORKBUDDY_CONFIG_DIR"` |
| 2 | 你**自己**的技能目录反推 | 你的 `fxai-*` 技能装在哪，`.../skills/<技能名>/SKILL.md` 往上退两级就是配置根 |
| 3 | 结构探测 | 家目录下一层里含 `plugins/marketplaces` 的那个目录（能装专家的宿主才有这个特征） |

```bash
# 1) 宿主自己告诉我们
CFG="${WORKBUDDY_CONFIG_DIR:-}"
# 2) 拿不到 → 用你自己技能目录反推（把下面换成你实际装的 SKILL.md 路径）
#    /…/<配置根>/skills/<技能名>/SKILL.md  →  /…/<配置根>
[ -z "$CFG" ] && CFG="$(dirname "$(dirname "$(dirname "$SKILL_MD_PATH")")")"
# 3) 都拿不到 → 停。把「家目录下哪些目录有 plugins/marketplaces」列给用户，让他指一个。
#    严禁自己猜一个 .xxx 目录装进去。
```

之后两条落点都从 `$CFG` 派生：

```
技能根   $CFG/skills/<技能名>
专家市场 $CFG/plugins/marketplaces/my-experts/plugins/<专家ID>
```

**判定**：`echo "$CFG"` 非空且该目录存在。
**失败处置**：认定不到就停下来问用户，不要退回到某个写死的产品目录。

## 1. 先判包形态（一条命令定分支）

## 2. 装技能

### A. 整包 → 平铺复制（不得嵌套）

把**每个** `fxai-*` 目录整个复制到**当前宿主的技能根**（`$CFG/skills`），**不要**把整包再套一层目录：

```bash
SKILL_ROOT="$CFG/skills"
mkdir -p "$SKILL_ROOT"
for d in fxai-*; do [ -d "$d" ] && cp -r "$d" "$SKILL_ROOT/"; done
```

```powershell
$root = Join-Path $env:CFG "skills"
New-Item -ItemType Directory -Force $root | Out-Null
Get-ChildItem -Directory -Filter fxai-* | ForEach-Object {
  Copy-Item $_.FullName -Destination $root -Recurse -Force
}
```

**判定**：`ls "$SKILL_ROOT" | grep -c '^fxai-'` ≥ 包内 `fxai-*` 目录数（以包根实际目录数为准，不写死数字）。
**失败处置**：数量不足 → 逐目录核对缺哪个，重拷该目录；出现 `skills/<包名>/fxai-*` 说明套了一层，删掉重来。

### B. 市场壳 → 一键安装

```bash
python install.py                 # 平铺解到技能根
python install.py --target <路径>  # 换目标（指向 $CFG/skills）
python install.py --force         # 整体重装（会覆盖本机改过的文件）
```

**判定**：脚本退出码 0 且打印装到技能根的目录数。
**失败处置**：同名目录默认跳过不覆盖，属正常；要覆盖加 `--force`。

## 3. 装专家（本包附带，只有整包有）

`专家包/` 是一个 **Agent 型专家**（凤希AI技能包管家），**不装进技能根**，走专家市场。

```bash
cd 专家包
python install_expert.py                        # 自动认定宿主配置根并注册
python install_expert.py --check                # 只查现状，不改动
python install_expert.py --config-root "$CFG"   # 指定宿主配置根
python install_expert.py --upgrade              # 本机版本低于包内版本时覆盖
python install_expert.py --force                # 无条件覆盖同名文件
python install_expert.py --share-only           # 只做多账号共享体检/修复
python install_expert.py --share-only --check  # 只报共享状态，不改动
```

脚本以包内 `.codebuddy-plugin/plugin.json` 的 `name` / `version` 为唯一依据，做五件事：
复制到 `$CFG/plugins/marketplaces/my-experts/plugins/<专家ID>/` → 合并 `marketplace.json` 条目 →
登记 `known_marketplaces.json` → 清理账号私有登记、保持多账号共享态 → 校验 `avatars/expert.png`。
覆盖只写包内同名文件，**不删目标目录里的独有文件**。
认宿主根的顺序：`--config-root` / `--market` → `WORKBUDDY_CONFIG_DIR` → 家目录下含 `plugins/marketplaces` 的根（结构探测）。
**认不到会直接报错退出（返回码 2），不会乱装**——这时用 `--config-root "$CFG"` 指定。

**手动等价步骤**（脚本跑不了时才用）：

1. 复制 `专家包/` → `$CFG/plugins/marketplaces/my-experts/plugins/fxai-suite-manager/`
2. 在该市场根的 `my-experts/.codebuddy-plugin/marketplace.json` 的 `plugins` 数组加：
   ```json
   { "name": "fxai-suite-manager", "source": "./plugins/fxai-suite-manager", "description": "FXAI suite orchestrator", "version": "1.1.0" }
   ```
3. 确认 `avatars/expert.png` 存在（512×512）

**判定**（四条全绿才算装好，第四条管多账号）：

```bash
EXPERT_DIR="$CFG/plugins/marketplaces/my-experts/plugins/fxai-suite-manager"
ls "$EXPERT_DIR/avatars/expert.png"
python -c "import json;d=json.load(open(r'$CFG/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json',encoding='utf-8'));print([p['name'] for p in d['plugins']])"
python "$EXPERT_DIR/install_expert.py" --check
python "$EXPERT_DIR/install_expert.py" --share-only --check   # 输出「共享态」即通过
```

**失败处置**：`marketplace.json` 不存在 → 先建 `{"name":"my-experts","description":"my-experts marketplace (auto-generated)","plugins":[]}` 再跑脚本。

## 3.5 自动更新场景（V1.7 起）

整包经 `fxai-auto-update` 更新时，更新器会自动管专家，**不需要再手动跑第 3 节**：

- 包内 `专家包/` **不落进技能根**，只作专家安装源；
- 读包内 `plugin.json` 与本机专家市场比对：未安装 / 版本落后 / 市场清单未登记 → 执行包内 `install_expert.py --config-root <配置根>`（版本落后时加 `--upgrade`）；已就绪不动；
- 已装但本机改过的同名文件不会被删，覆盖只写包内同名文件；专家安装失败只告警，不阻断技能落盘。

**判定**（更新完成后在技能目录下执行）：

```bash
python skills/fxai-auto-update/scripts/update.py expert --check
```

输出「已安装 V1.1.0、市场登记 True、判定 ok」即通过；显示 `need-install` / `need-upgrade` / `need-register` 时跑：

```bash
python skills/fxai-auto-update/scripts/update.py expert --install
```

**失败处置**：从更早版本首次升级时，执行更新的是旧版脚本，不会自动装专家，按第 3 节手动装一次即可。
旧版脚本可能把 `专家包/` 平铺进技能根，那只是残留文件、**不是安装位置**（专家中心看不到），按「仅本机有保留不删」处理，不要当成装好了。

## 5. 禁止事项（违反会装坏）

- ❌ 不要把 `专家包/` 放进技能根——它是专家不是技能，放错位置专家中心永远看不到。
- ❌ 不要把 `fxai-suite-navigator` 单独抠出来装——它跟着专家包走，脱离专家包没有意义。
- ❌ **不要写死任何宿主的配置目录名**，也不要拿别的机器的路径套过来；一律从 `$CFG` 派生。
- ❌ **不要给专家目录挂软连接**：宿主加载前会 `resolve()` 再校验是否在 `…/plugins/marketplaces/my-experts/plugins` 下，连接一解析就报「专家不在专家目录下」。每个宿主根下必须是实体文件。
- ❌ **不要把本专家设成某个账号的私有专家**：不得把 `fxai-suite-manager` 写进 `experts/custom/<账号>/experts.json`，也不要用「分享 → 导入」给别的账号复制一份。任何账号私有登记后，其它账号立刻看不到，这就是「换账号专家不见了」。详见第 6 节。
- ❌ 不要改 `avatars/expert.png` 为生成人像——品牌标识只用官方 Logo。
- ❌ 不要动 `plugin.json` 的 `name` / `version`（版本号随专家发布递增），改了市场条目就对不上。
- ❌ 不要跳过「重启」直接判断失败。

## 6. 共享口径（多账号共用一个专家 + 别再挂软链接）

### 6.1 多账号共享：一份实体，所有账号可见

**专家包实体和市场清单在配置根内共享，本来就不按账号隔离**；按账号隔离的是
「我的专家」私有注册表：

```
<宿主配置根>/experts/custom/<账号ID>/experts.json   # 字符串数组，如 ["fxai-suite-manager"]
```

宿主扫描 `my-experts` 市场清单时的判定：某专家 ID **没有出现在任何账号的私有注册表**里，
就被当作「本地共享专家」下发给**所有登录账号**（含以后新登录的账号）；
一旦某个账号把它登记进去，这个 ID 就从共享集合里被剔除，其它账号立即看不到——
这就是「切换账号后专家又不在了」的成因，不是文件丢了，也不需要重装一遍。

因此本专家的分发口径是 **「只装一份实体 + 只登记市场清单 + 谁都不私有登记」**：

| 做 | 不做 |
|---|---|
| 市场清单 `marketplace.json` 登记一次 | 把 ID 写进任何账号的 `experts.json` |
| `known_marketplaces.json` 登记市场 | 用「分享 → 导入」把专家复制成某账号的副本 |
| 换账号看不到时跑一次共享体检 | 为每个账号各装一份 / 各建一个目录 |

**判定**（在专家目录执行）：

```bash
python install_expert.py --share-only --check
```

输出 `账号共享 : 共享态（N 个账号目录，0 个私有登记）` 即通过。
显示「⚠ N 个账号私有登记本专家」时跑一次修复（只删本专家 ID，其它专家条目原样保留，写前自动备份 `.bak-share-*`）：

```bash
python install_expert.py --share-only
```

新登录的账号由宿主共享通道自动覆盖，**不需要为新账号重复安装**；重启宿主后生效。
`install_expert.py` 在正常安装、升级、`--check` 时都带这一步体检，装完即共享态。

> 跨机器 / 跨团队成员共享：专家是本机文件，换机器要在那台机器上按第 2、3 节装一次
> （整包或专家市场上架包均可）；云端账号之间不自动同步本机专家。

### 6.2 多宿主根：别再挂软链接

同一台机器有多个宿主配置根时，**给专家插件目录挂 Junction / 软链接是最常见的翻车点**：宿主加载专家会 `resolve()` 真实路径，再校验专家必须位于**自己根**的 `plugins/marketplaces/my-experts/plugins` 下；市场目录一挂链接，解析后落到别人的根，直接报「专家不在专家目录下，将无法被检测到」——专家中心里就凭空消失。

正确口径是 **「单一权威源 + 多份实体副本 + 一条命令同步」**：

- 权威源（唯一改这里）：`$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/fxai-suite-manager`
- `平台上传-专家zip/源/fxai-suite-manager` 是指向权威源的**目录连接**，仅供打包读取，不存第二份副本。
- 技能根下 `_专家包/` 也是指向权威源的**目录连接**，仅供本地仓库做版本留痕；它是源码镜像，**不是安装位置**，不得当成专家装进技能根。
- 每个宿主根下必须是实体目录，不能有 Junction。

更新流程：

```bash
cd 平台上传-专家zip
python 同步专家包.py --check    # 先看差异（不改动）
python 同步专家包.py            # 同步到所有宿主根 + 账号共享体检
python 重出专家包.py            # 要出上架 zip 时再跑
# 最后重启宿主
```

`同步专家包.py` 一次做完：断开目标市场的 Junction 并改实体 → 镜像权威源文件（覆盖 + 清理多余）→ 合并 `marketplace.json` 条目 → 登记 `known_marketplaces.json` 的 `my-experts` → 调用权威源安装器做账号共享体检 → 同步前把旧目录备份到 `打包线/_归档/专家同步备份/`。版本号只读权威源 `plugin.json`，不在脚本里写死。校验用 `--check`，不改市场登记用 `--no-known`，跳过共享体检用 `--no-share`。

判定：脚本输出每个根的「市场目录: 实体 OK」+「账号共享: …共享态」且差异为 0，重启后**所有账号**的专家中心都可见。
